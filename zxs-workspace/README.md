# ZIP Workspace

把目录签出到本机，用普通工具编辑，手动提交时才保存整棵目录的新版本。每份 `.zxs` 快照都是未加密、Store 模式的标准 ZIP，大归档使用 ZIP64。要取出文件和空目录，可把副本改名为 `.zip` 后用普通解压工具打开；需要签出或查看历史时保留原 `.zxs`。

客户端管理工作树、分支和历史。归档只在标准 ZIP 注释内保存仓库标记，没有隐藏元数据目录。普通 ZIP 用独立入口打开；只改后缀不能创建仓库。STORE 是普通目录；系统已挂载的共享也可作只读来源。无须安装 Workspace 服务端。[归档格式与准入规则](docs/design.md)。

## 先试用

在项目目录用 Python 3.12+ 运行，CLI 只依赖标准库。用新的 `demo` 目录：

```sh
mkdir -p demo/work/empty demo/store demo/states
printf 'hello\n' > demo/work/hello.txt
python3 -m zipworkspace init demo/work demo/store demo/states/first
ARCHIVE=$(
  python3 -m zipworkspace commit demo/states/first --writers-stopped |
    python3 -c 'import json, sys; print(json.load(sys.stdin)["committed_archive"])'
)
```

在同一个终端使用提交返回的 `$ARCHIVE`：

```sh
python3 -m zipworkspace inspect "$ARCHIVE"
python3 -m zipworkspace browse "$ARCHIVE" --limit 40
python3 -m zipworkspace checkout "$ARCHIVE" demo/second demo/store demo/states/second
python3 -m zipworkspace history "$ARCHIVE" demo/store
python3 -m zipworkspace branches "$ARCHIVE" demo/store
python3 -m zipworkspace status demo/states/second
# 可选：提交整个工作树到新分支
python3 -m zipworkspace commit demo/states/second --fork --writers-stopped
```

### 命令和操作约束

- **登记与签出。** `init` 登记已有目录，不提交。`checkout` 还原所选版本，不覆盖现有目录。WORK、STORE 和本机私有 STATE 必须互不包含，每棵工作树使用自己的 STATE。签出和恢复期间，目标父须由操作者控制，勿移动、替换或同步。`checkout-auto ARCHIVE PARENT STORE STATE Project` 依次试 `Project`、`Project (2)` 等，最多 256 个新名称。
- **按版本签出。** `checkout-branch ARCHIVE STORE WORKTREE STATE BRANCH_ID` 使用本次核验的完整分支头；需要固定节点时用 `checkout-node ARCHIVE STORE WORKTREE STATE NODE_ID`。缺祖先时，`history` 列出缺失的父操作，`branches` 分列已观察的最高代与祖先完整的分支头。
- **私处签出。** 四个签出命令可加 `--private-stage`，让解包中的目录只出现在 STATE 的私处。STATE 父须本人独占（0700），与新工作目录的父在同一实际 Linux ext4/XFS 挂载；目标父不可是符号链接，STORE 不可经别名与本机目录交叠。操作及恢复期间保持父目录不被搬动、同步或修改。条件不满足会拒绝，不改用复制或在目标处解包。两种方式的新签出都需要 Python SQLite 的 `serialize()`。
- **签出中断。** 先 `checkout-status STATE`，再按原号 `resume-checkout STATE OPERATION`。只采用 STATE 中已核验的原包或已登记暂存，不从 STORE 补包，也不接管同名目录。没有已受理回执时，可能只留下私有准备材料；保留现场，不另发或按名字清理。
- **提交。** 停止所有编辑器、同步和其他写入者，再用 `commit STATE --writers-stopped`；`--fork` 同样提交整棵树。保持 WORK 父和本人独占的本机 STATE 稳定。新冻结只接能核验的整个 Linux ext4/XFS 挂载和不可链接匿名临时文件，无具名后备。私有候选 `STATE/<原操作>.zxs` 可能在登记前失败并留下半件。发布要求 STORE 支持原生不可覆盖改名和目录同步；同代竞争保留原候选，不覆盖、不自动分叉。不要改动他人的上传暂存，也不要按名删除遗留候选或 `.partial`。[冻结与发布设计](ARCHITECTURE.md#4-提交竞争与断线)。
- **提交中断或冲突。** `status STATE` 查原 `pending_operation`；操作者先确认 STORE 仍是原存储，再用 `resume STATE OPERATION` 核认已发布的准确槽，或从原候选续作。找不到原证据就保留待决，不用当前工作树重建。原候选有父节点时，`fork-pending STATE OPERATION` 核验原 STORE 的同代竞争槽，再用已冻结的候选另建分支，不含后来编辑。已受理后继仍按原号续作。
- **查看改动和状态。** `changes STATE` 核验原工作目录和登记基线，报告新增、修改和删除；`status STATE` 只查登记、可见状态和原操作。两者使用 SQLite 只读事务，缺库或需要回滚热日志时停止，不创建空库或改为写权限。回滚日志模式下，读事务可能暂时阻塞提交。扫描时仍可有外部文件写入；[被另行改成 WAL 的数据库可能需要现成辅助文件](https://sqlite.org/wal.html#read_only_databases)。
- **收起与恢复。** `hide STATE --writers-stopped`、`restore STATE --writers-stopped` 只移动干净且已提交的原目录，不动归档、不覆盖占名。操作前关编辑器并停同步，[改名后已有句柄仍可写](https://man7.org/linux/man-pages/man2/rename.2.html)。父目录保持稳定；失答时按原 STATE 和原号用 `resume-visibility STATE OPERATION --writers-stopped` 核对或继续。只有仍持有原会话的 Linux 桌面提供保留修改的恢复入口。
- **只读浏览和普通 ZIP。** `browse "$ARCHIVE" "目录/名称"` 返回直接子项、字节数及 SHA-256；从同一快照和目录用 `--cursor` 传回 `next_cursor`。普通未加密 Store ZIP 用 `import-zip archive.zip --preview` 核验；可附一个目标路径查看是否占用，但不创建目录。压缩或加密成员、链接、特殊文件、重复项、穿越及跨平台别名均拒绝。


### 空间估算

下表按 **CLI 路径、每代普通文件正文 100 GiB** 估算：直接从 STORE 已有的规范基线包签出，工作目录与 STATE 同卷，不另外留一份散包；两次提交大小均不变且成功。表内是整个例子同时占用的约数，不是额外空闲空间要求或实测值。

| 时点 | 三处同卷 | STATE＋工作目录同卷、STORE 单独一卷 |
| --- | --- | --- |
| 首次签出完成 | 300 GiB | 200 GiB／100 GiB |
| 第一次提交 | 峰值及完成后约 500 GiB | 本机峰值 400、完成后 300 GiB；STORE 从 100 到 200 GiB |
| 第二次提交 | 峰值及完成后约 700 GiB | 本机峰值 500、完成后 400 GiB；STORE 从 200 到 300 GiB |

起步的三份是 STORE 原基线、STATE 的 `original.zxs` 和已解包工作目录。每次冻结时多出匿名正文和一份新命名候选；匿名正文关闭后才向 STORE 上传，上传的 `.partial` 在成功改名时不会再复制一份。**完成后的私有候选仍保留**。分卷时两边峰值不在同一阶段。另留的散包、之前的候选、失败遗留的 `.partial`、ZIP 结构、SQLite 和文件系统开销均另计。实际分配、配额和并发占用仍须按卷核对；不要按表中数值把磁盘填满。

Linux 桌面普通提交直接冻结一份新 ZIP；在上述例子中，捕获阶段比 CLI 少约 100 GiB。本机 STATE 候选和 STORE 暂存上传时仍各占一份。

Linux 桌面签出确认页显示一份 STATE 原包加一份解包所需的逻辑字节，以及目标卷当时报出的可用量；低于需求会提醒，无法读取则显示未知。工作目录与 STATE 在同一挂载，正式改名不多占一份。

提交确认页分列 STATE、STORE 当时的可用量；同卷不能相加。普通提交捕获前大小未知；按报告提交显示已审正文量，ZIP 结构另计。续作需要上传时按原冻结包大小算一份 STORE 暂存；只核认已有原槽不增加副本。空间提示不预留容量，另查配额与 inode。

容量错误按发生位置和阶段报出：`ENOSPC` 是空间或目录资源不足，`EDQUOT` 是配额用尽，`SQLITE_FULL` 是数据库或其临时存储无法扩展。CLI 默认签出的逐成员解包保留原始读写错误。

中断后先查原回执：签出用 `checkout-status STATE`，提交用 `status STATE` 或本窗口「查询该次操作的原回执」。只按已受理的原操作号续作；没有回执时保留现场，不另发或按名字清理。

## 桌面窗口

以下是源码中的操作，桌面尚未实机验收。用独立的 Python 3.12+ 环境，从本项目目录安装 `python -m pip install '.[desktop]'`，然后运行 `zip-workspace-desktop` 或 `python -m zipworkspace.desktop`。CLI 无需 Qt。待验项目见[交付清单](TASKS.md)。

### 打开与浏览

- **打开快照。** 点「打开 .zxs 快照」选择文件，或拖入单个 `.zxs`，也可把带引号的绝对路径作为启动命令的唯一参数。拖放或命令参数进入独立确认窗口，核对路径后点「只读打开并核验」。入口只接收单个本机路径形式的 `.zxs`，不移动原件、不设置默认应用、不挂载。macOS 打包配方还声明 Finder「打开方式」入口，文档请求也需要在新窗口确认。
- **从 STORE 开始。** 先选归档存储，再点「从存储目录选择快照」。初始列表是规范文件名里的仓库、分支和代数；点选才完整核验该包。要查祖先或分支头，另点「读取分支与历史」。缺祖先时显示具体缺失项。可单独打开某个历史节点或已核分支头；原文件被替换则停止。挂载另走 [Linux 可选入口](#linux把一个固定快照挂为只读目录)。
- **查看内容与摘要。** 打开时核验全部成员，显示整树摘要、文件大小和 SHA-256，双击目录进入，支持分页和空目录。要单独核对原 ZIP 的完整字节（含头及注释），点「核验并显示整包 SHA-256」并确认读取量；历史节点还须匹配已登记的整包摘要。可取消核验或读取历史；当前系统调用返回后停，不显示半份或迟到结果。更换或关闭快照会清掉旧摘要。
- **窗口。** 「文件 → 新窗口」打开空窗口；「在新窗口浏览当前原快照」复制只读视图，不重读正文。两种方式都不转移 STORE、工作树、原操作或挂载。「文件 → 关闭当前快照」只释放本窗口浏览和对照；操作在途须等它结束，工作树会话和挂载另行关闭。
- **查找或定位。** 在「文件」或「核验普通 ZIP」点「查找条目或定位路径」。可用名称片段查找后点「定位所选条目」，也可粘贴如 `设计/图纸.txt` 的完整相对路径并回车。保留原拼写和大小写，不加首尾斜杠，不用 `..`、系统路径或网址。定位只选中原父目录的页和行，不自动打开；路径无效保留原页。
- **预览一个纯文本成员。** 在文件页点「预览选中的纯文本」，核对原条目和完整读取量。严格 UTF-8 的 256 KiB 以内文件可看全文；大项默认只看开头，也可选「完整核验大文本后跳页」。全文通过核验后，跳页只从原归档复核所需块。无效编码、孤立回车或禁用字符拒绝显示；取消、换选或关页清除正文。不启动外部应用或写文件。

### 只读对照

- **同一库的版本。** 先打开左侧快照并读出历史或分支，选另一正式版本，点「与当前快照比较所选版本」。左侧用已核目录，右侧核验选定的规范归档；不追随后续 HEAD。分支没有已核头、选同一节点或右侧换件时不出结果；换快照、换存储或重读列表会清除旧对照。
- **两份独立 `.zxs`。** 在「只读对比」点「选择另一份 .zxs 并比较」。不需要 STORE，可选不同仓库的文件；按相对路径、类型、大小和内容摘要找差异，不按时间猜增删或改名。
- **与本机文件夹比较。** 打开快照并选已有目录。比较文件实际字节和空目录，列新增、修改、缺少。期间如果原路径、文件或目录变化，或遇到符号链接等无法核实的条目，则停止；普通文件的硬链接按各自可见名称参与列表。此操作不登记工作树。macOS 的文件夹比较仅接本机卷；应用从系统选档返回后，在绑定及比较时禁用线程自动下载，遇到占位文件即停止。可先在系统中下载后再选。只比正文、名称和空目录，不比资源分叉、扩展属性或 ACL。
- **筛选与复制路径。** 历史、独立快照、文件夹或普通 ZIP 对照完成后，输入字面的路径片段，或选「仅对照对象 / 内容或类型不同 / 仅当前快照」，再点「筛选本次对照」。大小写敏感，层级用 `/`，无通配或正则。原总计与匹配数分列；选中差异，在表格下方的完整相对路径栏全选复制。取消筛选保留原结果，清除则恢复全部，新对照不继承条件。
- **看逐行差异。** 在「不同」中选两端均为普通文件的一行，再确认读取这一对成员。每侧最多 64 KiB、1,024 行，严格 UTF-8；CRLF 与 LF 在显示中同样处理，原字节有差异而显示相同会标明。关闭或换选清掉旧正文，「关闭本次对照」释放右侧，保留左侧浏览。本机文件夹的逐行比较只对有原件凭据的修改行开放；文件更换或变化后须重新比较。

可取消对照；正在进行的系统调用返回后停止，不显示部分结果。

本机文件夹逐行比较的准入：

- **Linux**：本机 ext4/XFS 上的原目录及同挂载的普通单链接文件；需要原生 x86-64 或 AArch64、内核 procfs 与 `openat2`。
- **Windows**：归档和文件夹分别位于可核的固定本机 NTFS，可不同卷；只读有准确长名和文件 ID 的普通单链接文件的默认数据流。拒绝别名、重解析点和占位内容，不读写 `Zone.Identifier`（MOTW）。
- **macOS**：归档与文件夹分别位于可核的本机 APFS，可不同卷；须是原名、单链接、已驻留的普通文件，按原目录相对名读。绑定、扫描及逐行读取用 [Apple 禁止线程物化的策略](https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files)，系统选择器和初次打开归档不在其中。

### 另存、提取与库副本

**Linux：另存完整快照为 ZIP。** 打开并核验所选 `.zxs`，在「快照与历史」顶部点「另存完整快照为 ZIP」，指定已准入的本机 ext4/XFS 父目录和全新 `.zip` 文件名。逐字节另存，保留 Store/ZIP64、原目录，以及包内版本标识等标准 ZIP 注释，不改原包、不解包或创建工作树。复制所用原句柄、整树与匿名副本全部检查成功后才无覆盖公开名称；父目录同步失败会说明完整副本可能已出现。发布前可通过主窗口取消复制；若已开始唯一正式发布，界面会等待并核对结果。长复制分阶段显示实际读写、核验、同步和发布进度。一般 ZIP 工具可按常规取出内容；在 Workspace 里登记/查看历史仍用 `.zxs` 名称。这不是信任来源认证，不会复制外部元数据或自动打开结果。

**Linux：从已核验快照另存一个普通文件。** 在「文件」页选中一行，点「另存选中的文件」，选择已有目录和新文件名。确认前可核对原节点、成员的完整相对路径、SHA-256、正文大小和目的位置。同名、目录或链接都不覆盖。不需要 STORE、工作树或虚拟盘，只写这一份正文，单项上限沿用归档的 128 GiB；可用空间和配额不作保证。

目前源码适用 x86-64 或 AArch64 原生 64 位 Linux，要求实际可用的 [openat2](https://man7.org/linux/man-pages/man2/openat2.2.html)（Linux 5.6 起）、进程自己的内核 procfs 和普通用户，不需提权或装驱动。仅写入已核本机 ext4/XFS；目标目录须属于本人，上级目录须属于本人或 root，均不能让组或其他人写入，不经符号链接。操作期间请保持所选位置不被移动、同步或另行修改。程序保留浏览时的原归档句柄，只重新读取受限 ZIP 索引（尾窗口可能覆盖正文末端）和所选成员，不追分支头。完整 CRC、原 SHA-256、实际 0600 副本读回及文件同步通过，才用 [Linux 匿名临时文件和本进程 procfs](https://man7.org/linux/man-pages/man2/open.2.html#O_TMPFILE) 的原生无覆盖链接生成正式名，再同步并检查原父目录。确认后可在正式发布前请求取消；不能打断正在进行的系统调用，未发布的匿名副本随原句柄关闭释放。若已开始正式发布，不能用取消撤回。条件不符时没有具名暂存或其他写法；最终确认失败时原目录可能已有完整副本，不自动重试或删除。只保存文件字节，不带原执行权限或来源元数据，不打开结果，也不验证文件可信。

**Linux：另存选中的文件夹。** 在同一「文件」页点一行文件夹，再点「另存选中的文件夹」。为它指定目的父目录和一个新名称，并另选同一实际 ext4/XFS 挂载上的已有独占 0700 暂存目录。两处必须互不包含；沿原路径不跟随符号链接，支持范围和普通用户要求与单文件另存相同。确认前显示原节点、完整子目录、新路径、暂存路径和选中范围的字节数。只保存这项及其后代，不提取兄弟目录、不建工作树、不复制原执行权限或来源元数据。

程序先在原独占暂存中构建并读回完整子树，包括隐式和空目录。继续使用原归档句柄，一次重读受限 ZIP 目录并核所选成员的 CRC 和原 SHA-256；不遍历其他成员正文。全部文件及子目录已同步、真实暂存与所选树相符后，才用一次原生 [RENAME_NOREPLACE](https://man7.org/linux/man-pages/man2/rename.2.html) 公布完整目录，两父同步并核原名才报完成。可在正式改名前从主窗口请求取消；须等当前系统调用退出，现场私处可能留材料。期间请勿移动源或目标，不允许其他程序更改或同步专用暂存。中断可能留私有准备材料；晚失败时目标可能已有完整副本，不自动清理、换名或重试。

**macOS：另存完整归档或标准 ZIP。** 在「快照与历史」打开并核验要保留的版本，点「另存同名完整归档」或「另存完整快照为 ZIP」，选同一本机 APFS 卷上本人独用、无同步的现有目录。看清新路径、节点及原 ZIP 的 SHA-256 后再确认。两项都逐字保留整个原包；ZIP 只把新副本的后缀换成 `.zip`，仍保留归档注释中的版本标识，可由兼容 Store/ZIP64 的普通 ZIP 工具读取。读取和克隆都借本窗口初次验证的同一归档句柄，不按路径重开正文。它不打开或提取副本，不更改原文件、分支或工作树；已有目标一律不动。目的目录须为本人所有、权限 0700、没有扩展 ACL，卷必须启用所有权。不能满足条件时没有备用写法。

只接受本人所有、0600、无扩展 ACL 的普通原包，且 macOS 须能从它读到明确的[系统隔离来源](https://developer.apple.com/documentation/foundation/urlresourcevalues/quarantineproperties)。在确认时，原件不能含资源叉或未知的可见属性。本人须确认原包、目的目录都不会被其他人、程序或同步服务改动，并同意系统先将**整个原件及其当时的元数据**复制到该目录的隐藏文件；其中可能有私有下载地址。程序不显示、发送、移除或补写标记。即使最后拒绝发布，这一份完整的私有暂存也可能留下。

从下文的「从现有目录生成全新 .zxs」得到的本机无标记快照可以打开和浏览，但当前这两个保留原隔离来源的另存入口不会接受它，新文件和暂存都不会建立。程序不会为通过另存检查补写隔离标记。这不影响 `.zxs` 本身采用的标准 Store ZIP 格式。

[APFS 原生整文件克隆](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/clonefile.2)只在原卷上独占创建一个新文件，初期与原包共享数据块，**不是独立介质备份**。副本必须仍是本人所有的 0600 单链接新文件，无扩展 ACL，且完整字节、原可见元数据与系统隔离来源均核对一致，才会[同目录不可覆盖改名](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/rename.2)。正式名确认失败时可能已出现，不自动重试或删除。不支持从 SMB、另一外盘直接另存；不保证隐藏系统记录、Gatekeeper 放行、防病毒或介质级断电安全。

Windows 文件夹比较仅接有盘符的固定本机 NTFS；拒绝网络盘、重解析点、脱机文件和无法核实的原件。Windows 桌面未开放导出；内部实现及待验条件见[交付清单](TASKS.md)。

**核验并浏览普通 ZIP。** 在三个桌面的「核验普通 ZIP」页选择一个 Store `.zip`，完整只读核验后可查看原包与整树 SHA-256、条目数和文件字节数。双击进入目录，空目录可见，也可按名称查找，或输入完整相对路径直接选中原页上的条目。翻页、查找不重开归档或读取正文；保留的 ZIP 注释也不赋予版本、分支或工作树身份。不需要选择目的地。命令行 `import-zip --preview` 仍仅显示核验摘要；只有 Linux 桌面可按下述独立动作提取。新增桌面浏览源码未运行。若本窗口同时打开了已核验的 `.zxs`，还可点「与当前已核验 .zxs 快照比较」。比较只读取这两个先前核验的目录结果，分页区分仅 ZIP、仅快照和不同，含空目录、类型变化及同长度异内容；不重开两包、不改文件，也不追分支头。任一视图换选即清除旧对照。

**看普通 ZIP 与快照中同一小文件改了哪些行。** 在这份对照中选中同一相对路径、两侧均为普通文件的「不同」行，再点「查看所选文件的逐行差异」。确认后，只从仍持有的两份原归档句柄复核这一个成员的 Store 布局、CRC 和原已核验 SHA-256；每侧完整读取上限 64 KiB、1,024 行，只有可显示的严格 UTF-8 才呈为纯文本。Windows 额外确认两个原句柄是本机 NTFS 的非占位文件；macOS 检查实际本地卷及驻留状态，在一次性读取线程禁用自动物化。不能核对即拒绝，不按路径重开或读取同名替件，也不重算整包摘要或从普通 ZIP 注释取得版本身份。取消、切页、改选差异行或换档使迟到结果失效，不提取、同步或启动外部应用。未在桌面平台运行验收。

**普通 ZIP 的纯文本预览**使用同一份已核验 ZIP 的原只读句柄。点一条文件并确认完整读取量，原本地头、CRC、长度和首次核验的单项 SHA-256 相符才显示；不读取另一个同名条目。小文本、明确只显示前部或大文件全文核验后跳页，与 `.zxs` 的纯文本界面一样有界。没有外部打开、写入或从 ZIP 注释取得仓库身份。换页、换档或「关闭此 ZIP」会关闭旧预览；关闭或更换归档释放原浏览句柄，不关闭本窗口的 `.zxs` 或工作树会话。

**Linux：仅另存普通 ZIP 里的一个文件。** 在已核验 ZIP 的目录里点一行普通文件，再点「另存选中的文件」。确认显示完整成员路径、首次核验的原 ZIP 摘要、所选成员 SHA-256 和全新的目的名称。与 `.zxs` 的单文件另存采用同一原句柄、只读布局复核和 CRC/SHA 门，在符合条件的本机 ext4/XFS 目录中通过 0600 匿名文件读回后才无覆盖发布。不额外提取其他文件或目录，不从 ZIP 注释采用仓库身份，不带原权限或来源元数据，不自动打开。正式发布前可请求取消；晚失败不自动重试或清理。

**Linux：提取已核验的普通 ZIP。** 从同一预览另点「提取到新的本机目录」。选择一个不存在的新目的名称，另选同一实际 ext4/XFS 挂载中本人独用、无同步的现有 0700 暂存目录；两处不能交叠。确认显示原包、整树摘要、正式与私处路径、成员总字节数。只读本次预览持有的原句柄并核原名、挂载、完整成员和各自的 CRC/SHA；空目录也完整保存。只在私处逐项写入、同步并完成读回，最后在两个原父之间一次无覆盖改名并同步父目录。确认前取消不启动，确认后可在正式改名前请求取消。冲突不覆盖；取消或失败可能在私处保留材料，发布后确认失败只提示结果未知，不删除或另发。只保留普通字节和目录结构，不复制执行权限、其他元数据，不打开结果，不登记工作树。

**从刚提取的目录另行新建仓库（Linux）。** 只有提取、两个原父同步和终名核验都已完成，且当前窗口仍持有这一次真正的原目录，才可点「用刚提取的原目录新建仓库」。无需按路径重新选择工作目录；另选 STORE、专用 STATE 父及全新 STATE 名称，并单独确认登记。不接受原件或挂载被替换，不从 ZIP 注释接续仓库、节点或分支。提取后的本机编辑仍在，登记时不扫描或改动工作文件，也不上传。想生成第 1 代，还须停止写入并执行普通的手动提交。换选或关闭原普通 ZIP、关闭窗口即释放交接，不删除已提取目录。若已发起但登记结果未知，先核对这次原 STATE，不凭路径接管或自动重试。

**Linux：把本次原版本及其祖先复制到新本机 STORE。** 打开原 STORE 里的规范快照、读取分支与历史并确认祖先完整后，在「历史」点「将当前版本及祖先复制到新本机库」。确认页列固定末代、新库的位置、私处与新增完整归档字节数。来源可为系统已挂载的共享；源目录及各槽只读，末代用首次持有的原 FD，其他祖先在同一个原 STORE 下用各自的规范相对名、原实际文件观察和整包 SHA-256 复核。不追分支头、不复制旁支或缺祖先的链，也不从散包推断原槽。

若需要本机保留多条分支，另点「复制本次已核的所有分支到新本机库」。必须是同一原仓库中已列且均能追到正式起点的版本；确认列分支数、版本数和原包总字节。不加入后来出现的版本，不扫其他仓库或补配缺祖先；原名称对应的文件丢失或被替换就不发布，不替换原 STORE 或同步回写。

两个本机父和专用 0700 同挂载暂存要求与整目录另存相同。复制与提取的确认页也会读取原持有暂存卷报告的可用量；只计这次输出，不重复计算源归档或正式改名，未知或低于字节需求仅提示，不能断言配额、目录资源或成功。操作者须确认两个本机位置均不是原共享的服务端目录、别名或写回同步位置。只在私处写原样 ZIP；完整读回及同步后将新库一次无覆盖移动到所选空名。原 STORE、当前工作树和已选择路径都不改；可在之后明确选新 STORE、打开本机末代并按原流程签出。这个时点副本保留原分支号，**不是双向同步**；在两库用同一分支独立提交，可能产生同一代同名但不同内容的归档。要离线独立开发，签出后先用「从签出时的原节点创建新分支」，保留新分支名下的提交，不把两边文件相互覆盖。不自动登记或写共享。正式移动前可请求停止，取消或失败保留可能已有的私处材料；发出正式移动后不可撤销，确认失败只报结果未知。大历史会读完所列原 ZIP，且在本机读回逐字校验；成本和 SMB 行为均未实测。

**Linux：把原样下一代并入已有本机 STORE。** 打开仍在外部的那份 `.zxs`，选择本人独用、无共享或同步的已有 `0700` 本机 STORE，读取分支与历史，再在「历史」点「将当前下一代原样并入所选本机库」。只有本仓已核的目录完整、所选包恰好接在同一分支的最高已核规范上一代，并且下一代名称完全空着，才能继续。确认列出两节点的确切原始 ZIP 摘要、规范父路径、新路径和实际字节数。拒绝首代、旁支、补中间空洞、缺失或替换的父和任何占位，甚至已有字节相同的目标也不认作本次成功。

只从选中的原归档句柄复制，不重开同名源或改资料头及版本注释。原 STORE 必须在能从真实句柄确认的本机 ext4/XFS；已挂载的共享只作为只读来源。复核真实上一代的完整 ZIP、整树、原始 SHA-256 和原槽，并在发布前后检查同一目录里的既有同仓槽。先完整核验及读回本机匿名文件，再无覆盖链接到唯一新规范名，同步原父后才报完成。正式链接前可请求停止；若链接已发出而后验失败，只报该原位置的结果未知，不重发、换名、删除或自动同步。只增加这一份归档，不打开结果、不接管/改工作树或 STATE，不复制文件权限、时间或来源元数据。本机库静止是操作条件，不是跨进程锁。需要看新目录时另行读取历史。

### Linux 工作树与仓库

**从已有工作目录新建仓库**。不用先打开快照。在「工作树」页点「从已有工作目录新建仓库」，选择已有工作目录、后续存放快照的 STORE、本人独占且无同步的现有 CLI 状态父目录，再输入一个未使用的新 STATE 名称。三处须互不包含；工作目录与状态父须在同一个实际本机 ext4/XFS 挂载，STORE 也须是已核的本机 ext4/XFS。先核对完整路径、实例、仓库和分支。确认后只在新 STATE 建立 CLI 登记，不扫描文件正文、不改动原工作目录、不写 STORE。同步或身份不能确认时不接管，也不清理留在所选私有父目录中的原 STATE。

登记成功后仍显示「尚无已提交快照」。首代前没有可比较的基线，但可以先点「查看首次提交的内容」。本窗口原工作树须仍可见、保持原零代登记且无待决。窗口读取实际目录的文件正文、复核名字，分页显示观察到的相对路径、文件大小和目录（含空目录），并显示逻辑正文总量。可取消；如果观察期间发现原登记变化或树无法完整核实，不显示部分清单。清单本身不访问 STORE，不冻结或预留正式槽。

如果要提交清单里刚审阅的内容，点「提交本次审阅的第 1 代」。程序先核对当前窗口刚创建的零代登记与原本机 STORE 的空首槽，再列出整树 SHA-256 和已审正文量。另行停止所有写入者并确认后，才从原工作目录重新冻结。只有路径、种类和文件正文与清单全匹配才继续；同长度的正文变化也会拒绝，不建立具名候选、不登记待决或写入 STORE。首代仍没有父快照。清单关闭或拒绝确认不会提交。

也可以不经清单点「提交本次工作目录」，冻结时读取当时的内容，不与之前的清单绑定。两种方式都要求停止所有写入者，并确认原工作目录、原 STORE、操作号和首次正式槽，才发布整个目录的第 1 代标准 Store ZIP/ZIP64。第 1 代没有父节点；不会选已有 HEAD、覆盖原文件或自动提交。失答先只读查询原操作，确知待决且没有已知冲突才能另行续作同一份冻结归档；若已看到精确原槽，只核回执。首次正式槽冲突不在窗口另造第二个起点。会话持有的是本窗口刚登记的原件，关闭后用 CLI `status STATE`，窗口不凭路径接管。首次提交完成后使用正常的基线对照。

**Linux：只从一个现有目录生成首份 `.zxs`**。如果只想拿到快照、不想登记工作树，从「文件」菜单选择「从现有目录生成全新 .zxs」。选择原目录、其外的现有本机父目录与未占用的 `.zxs` 名称。核对准确路径及新节点，暂停编辑与同步，再单独确认。目的地须支持现有本机 ext4/XFS 匿名文件和无覆盖发布合同；原目录只是持原句柄的只读来源，可以与目的地不在同一挂载，但不会进入嵌套挂载、链接或特殊文件。已挂载的远端来源由系统访问。窗口边读原文件边写一份匿名 Store ZIP，复核目录清单，保留同名异父文件及空目录，写入独立仓库的第 1 代注释；再同步并完整核验同一匿名实体后才公开。不是现有分支提交，不写 STATE、不登记或切换工作树，不复刻来源权限或额外元数据。这是一次观察，不是对原目录未来内容的保证。正式发布前可取消；若名称出现后父同步不能确认，先查原位置，不重发或删除。

**macOS：同一 APFS 卷上由现有目录制作独立首份 `.zxs`**。也用「文件」菜单的同名入口，但选择的是当前同一可核本机 APFS 卷上的原目录及其外的既有目的目录，不接 SMB、跨卷、带系统卷级隔离或来源未知的位置。目的目录须本人独占、0700、无 ACL 且无同步。源及所有成员须实际驻留、本人所有且路径仍和原句柄一致；不接嵌套挂载、链接、特殊标志、扩展 ACL、可见扩展属性或资源叉。用每个原句柄和 [Apple 的系统隔离属性](https://developer.apple.com/documentation/corefoundation/kcfurlquarantinepropertieskey)复核两遍目录；看到标记或查询出错便整次拒绝，不剥除或跳过。普通 POSIX 权限和时间不作为快照数据；没有可见属性不是来源认证或 Gatekeeper 放行。

确认后只在这个私有目的目录独占打开一个 0600 暂存文件，写 Store ZIP、同步并完整读回后才用原卷明确支持的 [RENAME_EXCL](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/rename.2) 发布正式名，不覆盖。暂停编辑、后台写入和同步。改名前可请求取消，私有暂存可能留下；改名后目录同步或核验失败可能已有完整文件，程序不自动清理、换名或重试。不建 STATE、不登记或切换工作树、不签出、不挂载。

**Linux：从当前快照新建 CLI 工作树**。在「工作树」页选「签出此快照到新目录」。要使用历史节点或分支头，先在列表打开它；签出不会重新选择更新的分支头。依次选择归档存储（STORE）、新工作目录的父目录、本人独占且无同步的 CLI 状态父目录。三处互不包含；后两者必须在同一个已准入的本机 ext4/XFS 挂载中，不只是同一种文件系统。输入一个新名称，例如 `设计稿`；工作目录和 STATE 在各自父目录下使用这个名称，任一已存在都停止。

核对原节点、两个完整新路径、STORE 和本次操作号，明确确认独占条件才开始写。成功后工作目录里是快照的真实普通文件，STATE 仍使用命令行格式；只有本窗口保留原交接凭据时才会临时持有这棵工作树，不接管已有登记。若中断，只有核到原 STATE 的受理回执，才按它显示的操作号用 `checkout-status` / `resume-checkout`；若尚未安装 STATE，则没有可续作的回执，可能只留下私有准备目录；无法核证的保留现场，不另发请求或删除。交接使用与命令行 `--private-stage` 相同的原操作和两父目录同步，没有后台自动恢复。

桌面签出显示写入私有原包、原包回读、解包及工作树读回的实际阶段。子阶段字节数不是签出成功。安装新 STATE 前可从窗口请求停止；正在等待的磁盘或 SMB 调用须返回后才能响应。停止后不安装本次 STATE 或正式工作目录，不自动删除可能留下的私有准备目录。开始安装后不能撤销或放弃原回执，只继续这一笔；此时不能靠关闭窗口取消操作。

如果原 STATE 和准备树已经完整同步、但签出较晚失败，仍显示原快照的同一个窗口可点「核对并继续本窗口的原签出」。先只读核对原 STATE、实际准备树和原号：原树仍在私处且目标为空，才可另行确认一次无覆盖移动；原树已到了正式名称，则只可确认核验、同步和补全原回执，不会再改名。位置在确认后改变时不会切换做法。继续前停止所有编辑器、同步及并行 CLI 操作；它不重新读 SMB 归档或创建另一棵树。新工作树登记出现或原完成行已可见时，这个入口不凭路径接管。确认原完成回执及 STATE 最后一次目录同步后才交出新工作树。换快照或关窗口即释放原恢复能力，仍可用原 CLI 回执核实，不接管冷状态。

已挂载的 SMB 归档可以作为只读源，但新工作目录和 STATE 仍在本机。正文只用窗口第一次核验时实际保留的 Linux 只读 FD，经独立偏移顺序读取，不为签出按同名路径重新打开正文；还会核原名、原观测和实际挂载。短读导致 EOF 过早、报错或原件不能核对就拒绝，不改用同名源。历史选择仍要求原 ZIP SHA-256 相符；散包首次查看未计算原 ZIP 摘要，签出按原节点、整树及原 FD 的观测核对。客户端可能透明重连；SMB 尚未实机验收，窗口不写共享。源包在 SMB 与后续 STORE 是否也在 SMB 是两件事：签出对两处都只读，后续窗口提交仍只接已准入的本机 STORE。

签出确认页会提示所选 STORE 里的原分支基线槽：没有这个名称或它不是普通文件，仍可从当前快照签出，STORE 不会被自动补写。若要提交，仍须核验该基线槽的原节点及整包 SHA-256。

在本窗口实际创建且保留原目录和原库凭据时，可用**刷新本窗口工作树的状态**只读查看原实例、分支、基线节点和待决操作，不检查 STORE 是否可用。要查看文件是否修改，另开改动对照。浏览其他快照、历史或选择其他浏览存储，都不改变已持有的工作树、原 STORE 或原操作回执。签出页把浏览候选与本窗口实际操作的工作目录分开显示；不把浏览版本换到工作树里。

**查看已登记的提交（Linux）**：原会话可见、无待决且状态显示已有版本时，可点「核验登记基线并在新窗口浏览」。不重新扫描历史、查最新分支头或读取工作文件。只从原 STORE 的规范位置核对状态所列版本的实际文件、完整内容和整包 SHA-256；前后短暂只读核对同一原登记，期间变更或失去原件就不开窗。耗时核验可取消。新窗口只收到核验完成的归档视图与原只读句柄，不带原 STORE 选择、工作树、待决操作或挂载；旧窗口和原分支操作权限不变。这不是切换编辑目录、判定未提交修改或认领已有 STATE；未实机运行。

**临时收起／恢复原工作目录（Linux）**：只用本窗口仍持有的原工作树及原 STATE、STORE。先刷新状态；已有提交且无待决的可见工作树可点「临时收起工作目录」，只允许收起与原基线一致的内容。收起后可另点「恢复原路径并保留改动」：只有仍能核实同一个原目录才会移动；实际已保存到其中的内容一起回原名，仍是未提交改动，不会回滚或自动提交。每次单独确认两条实际路径；先关闭编辑器，暂停同步和其他后台写入直到操作结束。改名不会撤销既有写入句柄，点号名称也不是权限隔离。

两种操作仍需普通 Linux x86-64/AArch64 原生 64 位环境及可核的 procfs/`openat2`；WORK 与 STATE 须在同一已核 ext4/XFS 挂载，STORE 须是已核本机 ext4/XFS 且能核验登记的原基线，STATE 须使用现有 SQLite DELETE 回滚日志模式，工作目录父须本人所有，父链不得含链接或让其他账户写入。核对原目录、读取并核验其当前内容后，先同步原 STATE 意图，再在原父内无覆盖改名及同步父目录，最后同步这笔完成回执。不会删除、打包、改写文件、改变权限或释放占用，不能取消已确认的动作，也不自动重试。

结果不明时先点「只读查本次收起／恢复回执」。仅在原窗口确认原意图已同步、原号仍待决时，可单独选择「继续本窗口这笔待决改名」。复核后会明确区分继续一次无覆盖改名，或原目录已经移动、只需核对并同步原回执；确认后不能自动切换两种授权。只核这笔实际接受的原内容，不重新挑基线，不覆盖后来保存的文件。尚未证实原意图同步或只见未证耐久的完成行时，不在窗口续作。只有尚可证明原件、两名和这次核验内容未变时，才按原 STATE 和原号手动 `resume-visibility STATE OPERATION --writers-stopped`（会写入），不是重开旧工作树。若目标已占用，只在仍能核实原隐藏目录时指出该路径；如急需保住文件，先停写，把所需文件另存到独立的新目录，绝不覆盖、手动改登记树的名称或改 STATE。原件、名称或回执无法核实时保留现场，不按路径认领。窗口关闭不会移动目录或重开旧 STATE。

**关闭工作树会话（Linux）**：每个窗口只持有一棵工作树。要从另一个快照再签出，先点「关闭本窗口的工作树会话」，记录显示的原目录、STATE、STORE、原登记实例或签出操作与最近提交、分支或收起／恢复操作（如果有）。只有确认仍是同一会话且没有正在处理的窗口任务才关闭。关闭会话或退出窗口都只释放当前凭据，不删除、隐藏、提交或取消已受理的操作；继续时用原 CLI STATE 的 `status` 或 `checkout-status` 核对。窗口不会按路径重新接管已有工作树。

**查看工作目录相对基线的改动（Linux）**：不必重新选择目录或归档。在本窗口持有的原工作树可见且无待决操作时，点「查看工作目录相对基线的改动」。它从原 STATE 读取这棵工作树当前记录的基线，从原 STORE 核验该代的原节点、完整 ZIP 和整包 SHA-256，再扫描原工作目录。即使窗口仍在浏览首次签出的版本，也对照实际登记的基线，不改选分支头。报告列出新增、修改（含同尺寸不同正文和类型变化）、缺少及空目录。缺原归档、不支持的成员或观察期间发现原目录、基线、待决发生变化时不显示部分结果。

如果原 STATE 仍指向本窗口**首次签出的确切基线**，还可选「离线对照首次签出版本」。它只读本机原登记和工作目录，跟签出时已核验的名称和摘要比较；不重开原归档，也不连接 STORE 或验证 STORE 中的副本仍可用。这个索引仅保留在当前会话，即使浏览已经换档也不换基线；提交或分叉推进基线后不能用它替代当前版本。离线报告不授予提交、写共享或重开旧会话的权限。

在当前基线对照、离线对照或首次提交内容清单中，选中一行后，在表格下方的完整相对路径栏用系统快捷键全选、复制（Linux 上为 Ctrl+A、Ctrl+C）。该栏保留原拼写；翻页、取消选择或关闭报告后不保留旧行。可将复制的路径粘贴到已核验归档的定位栏；未提交的新增项可能不在该归档中。

两种对照都可从主窗取消。从 STORE 做对照时分别显示真正的基线成员与整包读取量；工作文件显示一次读取中实际处理的正文，不预扫总量，之后另行复核目录。取消须等正在进行的系统调用返回，不显示半份差异。报告是一次只读观察，不冻结、复制或提交工作树，也不保留到下一次写操作。普通读取可能更新访问时间；SQLite 沿用原库的逻辑只读方式。扫描与登记读取分开；提交前仍须停止外部写入。

**从这次改动对照提交所审阅的完整内容（Linux）。** 本窗口核完原 STORE 中的登记基线与工作目录后，可点「提交本次审阅的整棵工作树」。它从对照交接同一原基线句柄，先只读复核原登记，随后仍须另行确认、停止编辑器和所有其他写入者；只关闭报告不提交。确认页列出原 WORK／STATE／STORE、基线、此次操作号与已审整树摘要。实际冻结仍读本机原工作目录；只有整棵树的路径、种类及正文与报告完全一致，才可具名、登记待决并走通常的无覆盖发布。若捕获内容不同，连候选名也不建立，请重新查看改动。这不锁住外部编辑器，不比较 ACL、时间戳等主机属性，也不是容量保证。本段入口只适用于已有已提交基线且实际合格的本机 STORE；零代使用首次内容清单的独立按钮，离线对照、冷重开和远端写入不提供审阅提交。

**看工作文件具体改了哪些行（Linux）**。在从原 STORE 核对的对照中，选同一相对路径的「修改」普通文件，点「核验所选小文本的逐行差异」。每侧完整读取最多 64 KiB、1,024 行。只重读原 ZIP 中这一成员及原工作目录里的这一文件：沿原持有的 STORE／WORK、核精确相对名和两侧原长度与 SHA-256，当前登记在起止仍须与该次对照相符；稍后同尺寸的不同编辑也不混入旧报告。两侧为严格可显示 UTF‑8 才显示纯文本，不透传控制字符，不编辑文件或打开外部应用。关闭、切页或换行选择时丢弃旧结果，取消可在对照窗口操作。

**离线对照也可核验一对小文本（Linux）**。仍在首次签出的原登记、原 STATE 和工作树时，选中同路径的「修改」普通文件并确认。归档一侧用签出时实际创建、读回并交接的本机 `STATE/original.zxs` 只读句柄；只查原名的元数据，不重开归档正文。工作文件用本报告保存的原文件实体、大小和摘要，只读取该相对路径的一项。仍按每侧 64 KiB／1,024 行和严格 UTF-8 判定，核完 ZIP 布局、该项 CRC 及两侧摘要才显示。不对原包重新做完整读取或访问 STORE，不改文件、不提供恢复或提交。若私有原包无法核到，普通差异清单仍可用，但不提供文本对；选定后发现同字替件、原登记推进、取消或关闭，也不会显示旧正文。

**补回一个缺失的已提交文件（Linux）**。在从原 STORE 核对的对照里选择「缺少」的普通文件，点「从登记基线补回所选缺失文件」，核对原基线、完整相对路径和将写入的唯一原名。父目录须已存在，位于同一已准入的本机工作树挂载。先关闭编辑器、暂停同步及其他写入（包括 CLI），再单独确认。只从该次对照仍持有的原 ZIP 核对、复制选定文件；不重新打开同名归档，不重读其他成员。原登记仍须可见、无待决且基线不变。文件以 0600 生成原字节，完整读回后无覆盖发布；不创建目录、不覆盖晚到的文件，不改登记、STORE 或历史，也不自动打开。正式发布前可取消；若父同步或身份核对失败，文件可能已经完整出现，先确认原位置，不自动重试。离线对照不提供此动作。

**补回一个整个缺失的已提交子目录（Linux）**。在同一对照中明确选「缺少」的目录；已有目录不合并，缺上级时选缺失的上级本身，不顺手重建其他路径。另选工作树所在的同一实际挂载上、与 WORK／STATE／STORE 互不包含的现有 0700 本人独占暂存目录；确认页列出原基线、子树范围、原位置和暂存位置。停止编辑器、同步、CLI 等其他写入后才开始。只复用该次对照仍持有的同一 ZIP 句柄，核验所选子树的正文和空目录、同步并读回后再一次无覆盖放回原路径。登记及基线仍须相同且无待决。不存在公开的半成品，不改旁路文件、原登记或版本历史；不复刻原权限、时间或来源元数据，不打开结果。正式改名前可取消；失败时暂存可能保留，改名后同步错误则不能确认完成，两种情况都不自动删除或重试。

**提交本窗口刚创建的工作树（Linux）**：编辑普通工作目录后，关闭编辑器并停止所有写入者。在同一窗口点「提交本次工作目录」，先只读核对登记和 STORE 中原分支基线的完整节点及整包摘要。STORE 若只有一份任意命名的散包、缺少该基线的规范代际槽，不能直接延续此分支，不会替你补发。核对分支、基线、下一代、三个位置和本次操作号，再确认停写及本次上传暂存名称不会被同步、移动或改写，才开始冻结和保存整树。这个入口只尝试能核实为本机 ext4/XFS 的原 STORE；缺空间、基线已变、同代被占或其他拒绝都不覆盖、不自动分叉。

普通提交直接把读到的工作树写成一份未命名的私有 Store ZIP，第二遍核对目录和成员。只从同一个生成句柄完整读回 ZIP／整树和原始摘要、同步实际文件后，才用已核本机 procfs 和原状态父句柄无覆盖链接为本次候选。在实际候选和父目录都同步且写句柄已关后才登记待决。需要普通 Linux x86-64／AArch64、可用 `openat2`、`O_TMPFILE` 和实际无覆盖相对链接；不能证明就拒绝，不改用命名临时文件。旧 CLI/续作资格不变。

只读基线核对、确认后的捕获和私有读回都可请求停止。这些阶段显示实际处理的字节，不额外预扫总量。取消须等正在进行的系统调用返回；在本次待决登记前停止就不登记或上传，可保留已出现的私有候选，但不能当作回执或自动重试。开始登记后不能撤销，后续只处理原号。这个停止入口不改变分支、冲突续作或命令行流程。

返回不确定时，点「查询该次操作的原回执」只读该 STATE 中同一操作号。待决时不会自动续作；本地完成回执可按原号查询。窗口不会自动重新上传，退出窗口后仍按原 STATE 和操作号查询。

窗口的提交、分支及其续作沿用原库的 SQLite DELETE 回滚日志模式，不替用户改模式。重新核到同一原待决后，先同步实际持有的原 STATE 目录，再尝试上传或核认 STORE 正式槽。原 STATE 屏障失败时，本次不尝试发布，保留原冻结包和操作号；同号续作重新核对并尝试该同步，不重新冻结。

STORE 确认后，窗口还会在 SQLite 写入原完成回执并成功返回之后，再同步同一个本机 STATE 实体，才显示本次正常成功。若只剩这道本机目录同步失败，先只读查原完成行，再另行确认「只同步本机原完成回执」；它核对同号、原标记和摘要，只同步原 STATE，不读取 STORE 或重新发布。SQLite 写回未确认时，不开放此操作。

**从签出时的原节点创建独立分支（Linux）**：在本窗口签出后，如果仍连续显示那次选定的确切归档，可点「从签出时的原节点创建新分支」。离开这个浏览快照后，该会话不再从它发起新分支，即使重新打开同名归档；已待决的原操作仍可查询和按原候选核对。核对父节点、新分支号、第 1 代正式槽和 STORE，再单独确认「创建、发布并切换」。它复制的是签出时选定的完整归档，**不读取当前工作目录**，不会把尚未提交的编辑带入新分支。原分支后来前进也不会改选 HEAD。只有新包无覆盖发布、原回执完成后，这个工作树才以新分支为基线；原分支归档和磁盘上的编辑不变。新私有候选和正式包仍各占一份空间。

窗口所选的原归档、STORE 规范原件和工作树登记基线必须一致。若基线已被另一次提交推进、第一代名称被占、源被替换或原结果未知，不覆盖、不自动换号建分支。先查询本次操作；只有确有匹配待决才另行确认续作。此入口不同于 CLI 的 `commit --fork`（提交整个当前工作目录），也不替代已有冲突候选的 `fork-pending`。

**从当前登记基线创建新分支（Linux）**：已有后续提交，或已离开首次签出的浏览页，也可以从本窗口状态中确切显示的已发布基线另建分支。仅限仍持原会话、原目录可见且无待决操作；重新核验原 STORE 规范归档的原名称、实际挂载、完整快照及已登记 SHA-256。状态在核验或确认时变化便停止，不改选另一代或分支头。确认框会列出准确父节点、目标分支、操作号及新文件位置。保留原分支及工作文件；当前未提交编辑不进入新包。新分支仍沿用原有私有候选、无覆盖发布和原号续作，成功回执才切换本工作树的基线。原首次签出分叉、冲突分叉及本机写入限制不因该入口改变。

**续作同一笔原提交（Linux）**：先点「查询该次操作的原回执」。仅当本窗口查到本机原登记仍有这笔待决、没有已知同代冲突时，才能点「核对并续作原待决操作」。核对的是私有 STATE 里已经冻结的同一操作号和整包摘要，不会读取、冻结或发布你后来对工作目录的编辑。核验时若正式槽空缺，另行确认才尝试不可覆盖上传；若已有相同归档，只核认原文件、不上传；文件消失或被替换不会改为上传。登记完成才更新本工作树基线。如果续作的是新分支操作，确认时会再次显示当前和目标分支；登记完成才切分支，工作目录文件不改。取消、冲突或结果未知不会自动续作，也不会另建分支。窗口关闭后不按路径重新认领工作树；CLI 的 `status STATE` 与 `resume STATE OPERATION` 是独立的显式操作。

**同代竞争后，用已冻结的原提交另建分支（Linux）**：仅适用于本窗口刚发起的普通提交仍待决，且窗口报告原槽不符。先查询该次原回执，再点「核对同代冲突，用原冻结归档另建分支」。原 STORE 的同一代必须确有合法、不同节点且基于同一父节点的完整归档；空槽、损坏包、错父或换件不会放行。确认框列出旧操作、竞争节点、冻结包 SHA-256、指定新分支及其第 1 代槽，只在确认后复制原私有冻结包。不会重扫工作树、更改当前文件、追随分支头或覆盖原槽。新包仍以旧待决的父节点为父，发布且完成回执才切换该工作树的基线。只允许已有本机 ext4/XFS、原独占 STATE 与协作式 STORE；不是从浏览页里的旧版本创建分支。

丢失应答时仍查询这一笔，界面保留旧操作号和当时确认的后继号。如果该后继仍待决，窗口不上传，可在原 CLI STATE 用该后继号执行 `resume`。不会改选别人的后继、另发或清理遗留文件；没有接管已关闭工作树的权限。

窗口沿用 CLI 格式的 STATE，只操作本窗口创建、仍能核验的工作树。关闭后继续用原 STATE 的 CLI；桌面从既有 STATE 重开尚未提供。macOS、Windows 与未能核验的挂载不开此签出入口。

## Linux：把一个固定快照挂为只读目录

**在 Linux 桌面操作：** 在同一独立 Python 环境安装本项目的 `desktop,mount` 两个可选组；程序不会替你安装软件或取得权限。打开一个快照（或先点开历史中的特定节点），进入「只读虚拟盘」，选择已有的私有空目录。预览列出原节点、整树摘要和挂载点。勾选确认后，独立助手使用窗口在首次核验时保留的只读归档句柄，以及所选目录的原始父链，不会重新按归档路径选择文件。完整核验和建立块索引期间可用窗口下方的取消键；普通后台操作不会禁用它，其他操作或模态对话框未结束时也不会越过核验进入挂载。此时换选或退出也不发起挂载。从「正在请求系统挂载」开始不再按取消键强制终止。

只有在内核挂载表中核到本次的唯一来源标签、原父挂载、只读标志及确切位置时，窗口才显示观察到的挂载 ID。操作页给出核对来源和 ID 的 `findmnt` 指令；匹配后才正常卸载，不匹配或查不到时保留现场。已发出挂载请求后，另行确认只关闭窗口不会结束助手。助手从本项目当前安装的绝对位置启动，要求可信的 Python 环境及其已安装依赖（含启动配置）；隔离启动不是操作系统沙箱。它不通过 shell 执行命令，不安装组件、不自动卸载，也不用于可编辑工作树。

正常手动卸载并等助手退出后，可从原窗口点「只读核对原挂载／卸载状态」。此操作只适用于本窗口曾核到 ID 的原挂载；通过原目录句柄和已核的本机 procfs 比对状态，不运行卸载程序。若本命名空间仍有原挂载，保留核验指引；只有 ID 与来源均不在表内、原目录在原父挂载下重新可见且复查一致，才报告已离开本命名空间。ID 重用、路径被替换或证据不全均显示未知。需要 Linux x86-64 或 AArch64 原生接口。

也可以使用独立的前台命令，不必先签出或解压：

```sh
zip-workspace-mount-ro "/path/to/原版本.zxs" "$HOME/快照查看"
```

两个路径都由你选择。挂载点须是已存在、本人独占的 **0700 空目录**，位于可核验的本机 ext4/XFS 上，不是另一个挂载点；用没有符号链接的绝对路径。各级父目录须属于本人或 root，不可由组/其他人写入。保持这个目录与祖先不被改名、同步或挪作他用，直到卸载。程序不会创建目录、改权限、更新系统设置或随应用启动挂载。需要普通非提权 Linux 账户已获准使用 FUSE3；独立 `mount` extra 使用 [pyfuse3](https://pyfuse3.readthedocs.io/en/stable/install.html) 与 Trio，不是普通 CLI/Qt 的依赖。

挂载前会检查全部成员、内容及整树标记。成功后可列目录、看大小、按偏移读取，包括空目录和空文件；不提供写、执行、共享给其他账户、提交或跟随分支头。本机同一用户仍能访问挂载内容。读取一直来自最初选中的文件句柄，不按归档名再开。每次只取涉及的 1 MiB 块，核对挂载时记录的 SHA-256 后才交付；小范围随机读也会读完涉及的块。原件变化、读不满或校验失败时，当前 FUSE 请求报错。不复制一份归档到临时盘。按当前归档预算，挂载索引留存的块摘要净数据最多约 12.6 MiB，不含准入时的 ZIP 元数据、临时分配、名称、目录索引和在途请求缓冲。每个请求最多 16 MiB，最多同时处理 4 个请求；跨块的 4 KiB 读取最多需核两块。这些是源码边界，不是性能实测。

每次前台挂载请求会先打印本次的 `SOURCE=zip-workspace-ro-…`；这只是识别标签，不表示已经挂载。只有在同一挂载命名空间的表中核到唯一位置、原父挂载、只读 FUSE 及本次标签，才另外打印当时的 `ID`。同一个归档再挂到同一路径也有不同标签；内核 ID 可能复用，不能单独用来核认。

结束时先关闭占用该目录的程序，再在同一挂载命名空间的另一终端只读核对：

```sh
findmnt --kernel --nocanonicalize --mountpoint "$HOME/快照查看" --output ID,TARGET,FSTYPE,SOURCE,OPTIONS
```

仅有一项，且目标路径、只读 FUSE 类型、`SOURCE` 和前台观察到的 `ID` 都匹配时，才由操作者正常卸载。ID 未核到、结果不明或不匹配时不要按路径卸载：

```sh
fusermount3 -u -- "$HOME/快照查看"
```

正常卸载后前台命令可退出；命令中断后用上面的方式核对原挂载。核对与手动卸载期间保持挂载点及其祖先稳定。程序不自行或强制卸载，不清理目录。该 Linux 入口为只读，未做实机验收。

macOS 的[虚拟盘只读回调源码](docs/macos-snapshot-volume.md)可从一份已选快照列目录、查属性和按偏移读取；没有 macOS 挂载命令或桌面按钮，未安装驱动或做实机验证。

Windows 的[只读虚拟盘数据面源码](winfsp/README.md)已连接原归档和 WinFsp SDK 的目录、属性、偏移读回调。目前不能从桌面或命令行挂成盘符，也没有编译、安装或驱动验收。

## 平台与发行状态

- **本轮原生验收只安排 Linux。** 历史验证覆盖 Linux / Python 3.12 CLI 和 65,536 条目的 ZIP64；迁入本仓后未重测，单成员 4 GiB 未验。

- **其他平台源码：** macOS、Windows 有桌面入口，尚未实机验收。[Android 15+](android/README.md) 与 [iOS 16+](ios/README.md) 有独立只读预览、单项校验与显式整包核验源码。当前没有签名桌面/移动发行包或已发行的虚拟盘。
