# ZIP Workspace

把一棵目录签出到本机，用普通工具编辑，明确提交时才发布整个目录的新版本。主机或 SMB 共享只需保存普通文件：每个已提交目录快照都是一个 **未加密、Store 模式的标准 ZIP**，扩展名为 `.zxs`，大归档使用 ZIP64。要用普通解压工具取回文件和空目录，可将归档复制为 `.zip`；保留原来的 `.zxs`，之后仍可用命令行签出或查看历史。保存归档的主机或共享目录不需要安装 ZIP Workspace 服务端。

本仓库是独立实现。目录仓库、分支、历史和本机工作树由客户端管理；归档内没有逐文件节点、文件容器、专用文件头或隐藏元数据目录。仓库标记位于 ZIP 规范已有的 archive comment。普通 ZIP 和仓库包有独立的打开入口，不能只靠后缀冒充仓库。

## 先试用

本次源码验证环境：Linux、Python 3.12。项目运行时只用标准库。从已经签出的本仓库运行，无需安装依赖：

```sh
mkdir -p demo/work/empty demo/store demo/states
printf 'hello\n' > demo/work/hello.txt
python3 -m zipworkspace init demo/work demo/store demo/states/first
ARCHIVE=$(
  python3 -m zipworkspace commit demo/states/first --writers-stopped |
    python3 -c 'import json, sys; print(json.load(sys.stdin)["committed_archive"])'
)
```

在同一个终端继续。`$ARCHIVE` 是刚才那次提交返回的归档路径，不用猜文件名或寻找“最新”的包：

```sh
python3 -m zipworkspace inspect "$ARCHIVE"
python3 -m zipworkspace browse "$ARCHIVE" --limit 40
python3 -m zipworkspace checkout "$ARCHIVE" demo/second demo/store demo/states/second
python3 -m zipworkspace history "$ARCHIVE" demo/store
python3 -m zipworkspace branches "$ARCHIVE" demo/store
python3 -m zipworkspace status demo/states/second
# 可选：从选中的目录快照明确分叉，仍是提交整个工作树
python3 -m zipworkspace commit demo/states/second --fork --writers-stopped
```

- `init` 只登记已有目录。工作目录、归档存储和本机私有状态必须互不包含。
- `checkout` 只还原指定快照，不换成较新的包，也不会覆盖现有目录。不同工作树和私有状态相互独立。
- 让工具选一个不冲突的目录名：`checkout-auto ARCHIVE PARENT STORE STATE Project`。它从 `Project`、`Project (2)` 起尝试，已存在的目录一律保留；256 个名字都被占用时停止。
- 签出中断时，运行 `checkout-status STATE` 查看原操作，再运行 `resume-checkout STATE OPERATION`。恢复只接认本机已验证的原快照和原目录；不会重新选择更新的分支或仅因字节相同就采用别人的同名目录。无须联网重新下载已经保存的原包。
- **新的 `commit`（包括 `--fork`）**：停止工作目录的所有写入者。将 `STATE` 放在本人独占、稳定且持久的本机目录中；工作树父目录和 `STATE` 都不能被同步、搬移或重新挂载。其他合作客户端可以竞争归档槽位，但不能动别人的临时上传文件。模式 0700 和 `--writers-stopped` 不是对其他进程的锁。
- 新提交的冻结阶段仅接纳能证明原挂载的 Linux ext4/XFS（当前未接纳子目录挂载），并要求所选 `STATE` 文件系统实际提供不可链接的匿名临时文件。工作内容只写入一个无名称文件，再从同一句柄核验并打包；正常退出、失败或进程结束都无需按名字递归清理。峰值仍需一份未压缩工作内容加一份本地归档的空间，关闭句柄不是安全擦除。单独创建的具名候选 `STATE/<原操作>.zxs` 如在登记前失败，可能只写了一部分；出错时会尽可能给出该名称，不会自动删除、认领或重试。已有 `freeze-*` 目录也不会被扫描或清理。无法证明这些条件时，在打开 SQLite 前拒绝不支持的 `STATE`；不退回具名暂存目录。不影响只读浏览或原提交的 `resume`。这项改动未运行，macOS / Windows 未提供等效的新提交冻结实现。
- 先在本地生成、关闭并验证完整 ZIP，记录原操作，再上传临时同级文件，关闭、复读并验证。只有底层支持 **原生不可覆盖 rename** 和目录同步时才发表。分支同一代只能有一个提交；冲突保留原包和私有候选，不自动覆盖或分叉。失败后的 `.partial` 不当成提交，也不自动清理。
- `status STATE` 在同一个 SQLite 只读事务里查看已登记的基线、可见状态和待决操作，不申请预留写锁；在回滚日志模式下，短暂的读锁仍可能让提交等待。若库缺失、读取遇到损坏或需要回滚热日志，直接报错，不创建空库，也不改以写权限重试。这是对原库的逻辑只读查询；若另外将库改成 WAL 模式，[SQLite 仍可能需要 WAL 辅助文件](https://sqlite.org/wal.html#read_only_databases)，不等于对任意介质零写入的取证工具。
- 断线后用 `status` 查看原 `pending_operation`，再执行 `python3 -m zipworkspace resume STATE OPERATION`。客户端从本次已打开的原存储目录读取准确的代际槽位，在同一归档句柄核验整包 SHA-256、节点和全部成员。文件及目录同步后须仍是刚核验的文件和目录，才能确认成功；否则不清除待决操作。若本次改名明确成功，还须是刚上传的文件实体。重新打开时只凭已登记的原标记和整包摘要核对，不把同名存储认作先前持有的目录：必须先由操作者确认仍是原存储。找不到原证据不凭当前工作树重新签发。
- `branches ARCHIVE STORE` 区分观察到的最高代与祖先完整的分支头。`checkout-branch ARCHIVE STORE WORKTREE STATE BRANCH_ID` 使用本次签出命令核验到的完整分支头，不锁定上一次列表。要签出之前看到的特定快照，使用 `checkout-node ARCHIVE STORE WORKTREE STATE NODE_ID`。本次选定后，即使字节相同，名称、文件身份、大小或时间戳不符也会拒绝。签出前在独占创建的私有副本上核验完整成员、节点和整包 SHA-256，目录同步后再次核对副本仍是原文件。失败可能留下尚未登记的准备目录，不自动删除。操作者仍须提供稳定的私有 STATE 位置；这不是桌面受管签出。
- 仅新签出需要 Python 所带 SQLite 支持 `serialize()`：原操作的初始记录只在内存中生成一次，再排他写入新 `opening.sqlite`。默认准备目录仅含它和原包；`--private-stage` 另含一份已核验的签出目录。按所选方式核对全部对象并同步后，才交给常规 SQLite。已有签出的原操作查询、恢复和锁协议不变，不复制或替换活动数据库。
- 默认首次签出已记录暂存目录后，命令在原目标父目录内做不可覆盖改名、同步和读回；若父目录或目标被替换，不登记替件。应答丢失只查原操作。暂存名称及早期解包仍要求该父目录由操作者控制，期间不要让同步工具或其他写入者改动它；目标不可覆盖不等于源名不能被换。

**如果不希望目标位置出现解包中的目录：** Linux 的四个签出命令都可加 `--private-stage`，例如 `zip-workspace checkout design.zxs worktrees/design archives private-states/design --private-stage`。先准备互不包含的 `worktrees`、`archives`、`private-states` 三个目录；后者须由当前用户独占（0700），在整个操作及恢复期间不允许其他程序同步、搬动或修改。私有父与目标父必须是同一实际 Linux ext4/XFS 挂载，目标父不能是符号链接。恢复前也按当前实际 STORE 复查隔离；同一设备经另一挂载暴露的 STORE 别名不予接纳。这不是对远端存储历史身份的登记。条件不满足就拒绝，不改在目标目录解包，也不改用复制。

新目录在私处逐级按已持有的目录句柄创建；全部内容核验、同步后，才与原包和唯一的签出记录一起安装为 STATE。此时目标仍未出现；接着只用跨父目录不可覆盖改名发布，并同步两个原父目录。STATE 已安装而确认中断时仍用 `resume-checkout STATE OPERATION`；更早中断可能在 `private-states/.zip-opening-…` 留下原包、部分或完整解包内容，尚无可自动续的回执，不扫描认领或清除。此选项不改变旧操作，不提供普通 ZIP 导入、桌面托管登记或 Windows 写入能力；源码未经实机验收。
- `changes STATE` 对照原提交显示真实新增、修改和删除的普通路径。工作树只能由其登记的原目录继续提交；同名同内容的新目录不能冒充。
- `hide STATE --writers-stopped` 只移动已提交且干净的原工作树，归档不变。恢复用 `restore STATE --writers-stopped`；原名已被占用时拒绝覆盖，也不删除任何一方。这里的“隐藏”不是权限隔离。断电中断后用 `status` 显示的原操作执行 `resume-visibility STATE OPERATION --writers-stopped`。
- 同代竞争留下的未发布候选可用 `fork-pending STATE OPERATION` 明确另起分支。按已登记的完整 SHA-256 和节点核验原候选；从同一打开的文件复制，在独占创建的新 ZIP 句柄中改写节点标记，不重新按路径打开文件修改。冲突后的工作树编辑不包含在内，原件保留。若原件或新名称变化，拒绝把新包登记为成功；保留可能未登记的候选，不自动删除。已有分叉的重试仍只核对原后继操作。此保护不代替稳定的原归档存储与私有状态目录。
- 只读核验普通未加密 Store ZIP：`python3 -m zipworkspace import-zip archive.zip --preview`。只选 ZIP，输出原包 SHA-256、整树摘要、条目数和正文总字节数。可选地给出一个目标路径以额外查看该名称当前是否被占用（`target_observation`）；不预留、更不创建该目录。命令不带 `--preview` 会明确拒绝写入。拒绝压缩或加密成员、链接、设备、重复路径、路径穿越和跨平台别名。
- 一份归档足以恢复其完整目录，**不等于**拥有所有历史。祖先档案不在当前存储位置时，`history` 明确返回缺失父操作。
- 只看目录不必签出：`browse "$ARCHIVE" "选中的文件夹"` 返回直接子项、文件字节数和 SHA-256，空文件夹也会显示。用上一页的 `next_cursor` 继续同一快照和目录；新快照不会接用旧游标。[只读应用接口](docs/design.md#read-only-archive-browser)同样先核验整个归档，不创建工作树。

运行本项目测试：

```sh
python3 -m unittest discover -s tests -v
```

### 空间估算

下面按**每代普通文件正文 100 GiB**估算：直接从 STORE 已有的规范基线包签出，工作目录与 STATE 同卷，不另外留一份散包；两次提交大小均不变且成功。表内是整个例子同时占用的约数，不是额外空闲空间要求或实测值。

| 时点 | 三处同卷 | STATE＋工作目录同卷、STORE 单独一卷 |
| --- | --- | --- |
| 首次签出完成 | 300 GiB | 200 GiB／100 GiB |
| 第一次提交 | 峰值及完成后约 500 GiB | 本机峰值 400、完成后 300 GiB；STORE 从 100 到 200 GiB |
| 第二次提交 | 峰值及完成后约 700 GiB | 本机峰值 500、完成后 400 GiB；STORE 从 200 到 300 GiB |

起步的三份是 STORE 原基线、STATE 的 `original.zxs` 和已解包工作目录。每次冻结时多出匿名正文和一份新命名候选；匿名正文关闭后才向 STORE 上传，上传的 `.partial` 在成功改名时不会再复制一份。**完成后的私有候选仍保留**。分卷时两边峰值不在同一阶段。另留的散包、之前的候选、失败遗留的 `.partial`、ZIP 结构、SQLite 和文件系统开销均另计。实际分配、配额和并发占用仍须按卷核对；不要按表中数值把磁盘填满。

Linux 桌面首次签出会在确认前显示这一笔新增的逻辑字节：一份 STATE 原包副本，加上已校验各成员的正文总量。工作目录与 STATE 同挂载，最后只改名，不重复算一次解包。窗口读所选私有父目录所在挂载当时报告的普通用户可用字节；若低于上述数值会提醒，查不到则显示未知。这不是预留，不能判断配额、剩余 inode 或元数据开销，后续提交及 STORE 上传没有自动容量预检。

签出或提交中真的遇到容量错误时，CLI 和桌面错误详情会标出当时正在写入的位置和阶段：例如 STATE 冻结正文、写私有候选、同步工作目录的正式名称，或 STORE 上传、同步正式归档。只有系统返回 `ENOSPC` 才报空间/目录资源不足，`EDQUOT` 才报配额用尽；`SQLITE_FULL` 单独表示数据库或临时存储不能扩展，不一定是卷满。其他读写错误不按文字猜成容量问题。旧式 CLI 签出（未选 `--private-stage`）的逐成员解包尚未逐处标注，保留其原始读写错误，不把读源错误推定为目的盘满。

不要按临时文件名删除、也不要另发一次提交。若已分配操作号，先核对原 STATE：签出用 `checkout-status STATE`，提交用 `status STATE` 或本窗口“查询该次操作的原回执”。只有查到匹配的原待决，才考虑显式续作。创建回执前可能只留下准备材料；目录或正式包已可见也不等于回执已完成。

## 桌面窗口（源码，尚未打包或验证）

当前可用和待验的操作见[本项目交付清单](TASKS.md)。

在单独的 Python 3.12+ 环境中，从本项目目录安装可选依赖 `python -m pip install '.[desktop]'`，再以 `zip-workspace-desktop` 或 `python -m zipworkspace.desktop` 打开窗口。命令行不依赖 Qt。依赖来自 [Qt for Python 的 Essentials 组件](https://doc.qt.io/qtforpython-6/package_details.html)。

选择 **打开 .zxs 快照** 可查看大小、SHA-256 和空目录，双击目录进入、按页前后浏览。选择 **归档存储目录 → 读取分支与历史** 才扫描对应仓库；历史节点和已核验的分支头可以单独打开。缺少祖先时显示缺失的原操作，不把该分支当作完整头。文件选择后被替换会拒绝，不用当前同名文件代替原节点。这个窗口不是虚拟磁盘。

首次浏览会读取并核验全部成员，再显示整树摘要和文件摘要；不会为了第一屏再顺序读取整个 ZIP 计算原包 SHA-256。显式读取分支历史、核对一个已绑定的原节点时仍需原包字节证据。归档很大时完整成员核验仍可能耗时。

**与本机文件夹比较**：打开快照后，选择一个已有文件夹。窗口按相对路径列出本机新增、修改（含文件与目录互换）、缺少的条目，保留空目录；同大小的文件也按实际内容摘要比较。结果是两次目录核查取得的一次观察，不是原子快照或已登记工作树的状态。若发现来源被替换、成员改变、符号链接或无法核验的条目，不显示部分结果。普通文件的硬链接按各自可见名称比较。应用不登记、不解压、不写入所选内容；读取可能由文件系统自动更新访问时间。不具备所需目录句柄能力的平台不提供比较。

macOS 的「选择文件夹并比较」复用上面的逐项比较，只接受从归档和目录的实际句柄都能核实为本地卷的组合。应用接到所选路径后，在绑定目录及后台比较期间按 [Apple TN3150](https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files) 禁止当前线程自动下载占位内容；遇到未下载的目录或文件便停止，不把它算作空或缺失。可先在系统中下载所需内容，再重新选择。只比较数据内容、可移植名称和空目录，不比较资源分叉、扩展属性或 ACL。此限制不覆盖系统文件选择器、先前打开归档的其他操作，也不是全机无网络保证。此比较器未在 macOS 实机运行，只读，不提供签出或挂载。

**macOS：另存同名完整归档（源码，未实机验收）。** 在「快照与历史」打开并核验要保留的版本，点「另存同名完整归档」，选同一本机 APFS 卷上本人独用、无同步的现有目录。看清新路径、节点及原 ZIP 的 SHA-256 后再确认。它复制整个原 `.zxs` 的字节，不解包、不改名、不移动分支，也不创建工作树；已有同名文件一律不动。目的目录须为本人所有、权限 0700、没有扩展 ACL，卷必须启用所有权。不能满足条件时没有备用写法。

只接受本人所有、0600、无扩展 ACL 的普通原包，且 macOS 须能从它读到明确的[系统隔离来源](https://developer.apple.com/documentation/foundation/urlresourcevalues/quarantineproperties)。在确认时，原件不能含资源叉或未知的可见属性。本人须确认原包、目的目录都不会被其他人、程序或同步服务改动，并同意系统先将**整个原件及其当时的元数据**复制到该目录的隐藏文件；其中可能有私有下载地址。程序不显示、发送、移除或补写标记。即使最后拒绝发布，这一份完整的私有暂存也可能留下。

[APFS 原生整文件克隆](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/clonefile.2)只在原卷上独占创建一个新文件，初期与原包共享数据块，**不是独立介质备份**。副本必须仍是本人所有的 0600 单链接新文件，无扩展 ACL，且完整字节、原可见元数据与系统隔离来源均核对一致，才会[同目录不可覆盖改名](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/rename.2)。正式名确认失败时可能已出现，不自动重试或删除。不支持从 SMB、另一外盘直接另存；不保证隐藏系统记录、Gatekeeper 放行、防病毒或介质级断电安全。

Windows 比较器已写入源码，未在 Windows 实机验证。只尝试带盘符、可核验为固定本地 NTFS 卷的目录。它持有所选目录和逐级打开的成员，比较普通文件的默认数据流；不比较 NTFS 附加流、ACL 或其他系统元数据。重解析点、脱机或需召回的文件、网络盘、占用冲突和无法证明的身份均停止，不改用路径拼接扫描。它没有写入、签出或挂载能力。

Windows 另有内部的**单文件导出原语**：从已核验 `.zxs` 的指定普通成员生成一个新文件。调用方须明确指定同一本机 NTFS 卷上两个不同的现有目录：一个容许留下未完成文件，另一个接收正式文件。仅供同一普通账户在专用、无同步的合成目录验证。只有本人拥有、两个目录的简单可继承权限一致，且新文件实际只授本人及可选的 SYSTEM、内置管理员完整权限时，才写入来源标记和正文；不依赖移名后继承目的权限。读取不到权限、有显式完整性标签或 EFS 均拒绝，不提权、不修改 ACL。它核对的是当时的描述，不会排除持有旧句柄或同一账户的其他程序。正式目标叶不会提前显示暂存；同名（含大小写差异）不覆盖。它不处理整目录、工作树或普通 ZIP，**没有接入图形界面或命令行**。

该原语仅传递原包上标准两行的 Internet（3）或受限制（4）`Zone.Identifier`：先在暂存文件上写入、同步和复读原字节，才写成员正文。无标记、带网址等附加字段、其他区或其他数据流均拒绝，不删改标记，也不联网查询。这是容器来源证据，不是子文件信誉或病毒扫描。尚未在 Windows 执行；开放前还需验证实际权限、同步、竞争及 Windows 附件策略。

另有一个**只评估私有暂存、绝不发布**的 Windows 附件服务试验。普通操作不会调用它。只对授权的合成文件，按原成员完整文件名在专用私处写入并核验，关闭写句柄，再把实际路径和所持原包路径交给 [Windows 附件服务](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iattachmentexecute-save)。机器配置的服务可能检查、传输、改写或隔离合成内容，亦会获知路径；这需要独立同意。系统要求询问、拒绝，或原文件、正文、权限、来源标记不能复核时不报通过，不补写、不重试。试验不启动文件，也不改变系统设置。拟用终名仅单独做[策略询问](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iattachmentexecute-checkpolicy)，不是对终点文件的实际检查。即使私处结果可核，也不产生发布许可。

**核验普通 ZIP** 是独立只读入口。只需选择普通 Store `.zip`，即可查看完整原包与整树 SHA-256、条目数和文件字节数，无需选择目标。当前所有目的地都不开放提取：不可覆盖改名能保护目标名称，却不能证明被改名的仍是应用创建的暂存目录。仅凭目录权限也不能排除其他程序替换暂存条目。应用不创建文件，不清理既有目录或失败留下的材料。

**Linux：从当前快照新建 CLI 工作树**。在「签出工作树」页选「签出此快照到新目录」。要使用历史节点或分支头，先在列表打开它；签出不会重新选择更新的分支头。依次选择归档存储（STORE）、新工作目录的父目录、本人独占且无同步的 CLI 状态父目录。三处互不包含；后两者必须在同一个已准入的本机 ext4/XFS 挂载中，不只是同一种文件系统。输入一个新名称，例如 `设计稿`；工作目录和 STATE 在各自父目录下使用这个名称，任一已存在都停止。

核对原节点、两个完整新路径、STORE 和本次操作号，明确确认独占条件才开始写。成功后工作目录里是快照的真实普通文件，STATE 由命令行管理；窗口不会接管它。若中断，只有核到原 STATE 的受理回执，才按它显示的操作号用 `checkout-status` / `resume-checkout`；若尚未安装 STATE，则没有可续作的回执，可能只留下私有准备目录；无法核证的保留现场，不另发请求或删除。交接使用与命令行 `--private-stage` 相同的原操作和两父目录同步，没有后台自动恢复。

签出确认页会提示所选 STORE 里的原分支基线槽：没有这个名称或它不是普通文件，仍可从当前快照签出，STORE 不会被自动补写。同名普通文件也仅表示看到了名称，不证明与快照相同；真正提交时仍要核原节点和整包 SHA-256。

在本窗口实际创建且保留原目录和原库凭据时，可用**刷新本窗口工作树的状态**读取原实例、分支、基线节点和待决操作。这里不遍历文件，也不把“无待决操作”解释成目录未修改。切换到其他快照或关闭窗口会释放本次凭据，不删除工作树；以后仍可用原 CLI STATE 查询。本窗口不会从结果路径或已有库补领凭据。

**提交本窗口刚创建的工作树（Linux 源码）**：编辑普通工作目录后，关闭编辑器并停止所有写入者。在同一窗口点「提交本次工作目录」，先只读核对登记和 STORE 中原分支基线的完整节点及整包摘要。STORE 若只有一份任意命名的散包、缺少该基线的规范代际槽，不能直接延续此分支，不会替你补发。核对分支、基线、下一代、三个位置和本次操作号，再确认停写及本次上传暂存名称不会被同步、移动或改写，才开始冻结和保存整树。这个入口只尝试能核实为本机 ext4/XFS 的原 STORE；缺空间、基线已变、同代被占或其他拒绝都不覆盖、不自动分叉。

返回不确定时，点「查询该次操作的原回执」只读该 STATE 中同一操作号。显示待决不是发布成功，也不自动续作；已完成说明本地原回执存在，不保证共享位置以后仍保留该文件。窗口不会自动重新上传，退出窗口后仍按原 STATE 和操作号查询。此批没有执行程序、测试或真实卷验收。

**从所选原节点创建独立分支（Linux 源码）**：打开要分叉的确切节点并在本窗口签出后，点「从所选原节点创建新分支」。核对父节点、新分支号、第 1 代正式槽和 STORE，再单独确认「创建、发布并切换」。它复制的是刚才选定的完整归档，**不读取当前工作目录**，不会把尚未提交的编辑带入新分支。原分支后来前进也不会改选 HEAD。只有新包无覆盖发布、原回执完成后，这个工作树才以新分支为基线；原分支归档和磁盘上的编辑不变。新私有候选和正式包仍各占一份空间。

窗口所选的原归档、STORE 规范原件和工作树登记基线必须一致。若基线已被另一次提交推进、第一代名称被占、源被替换或原结果未知，不覆盖、不自动换号建分支。先查询本次操作；只有确有匹配待决才另行确认续作。此入口不同于 CLI 的 `commit --fork`（提交整个当前工作目录），也不替代已有冲突候选的 `fork-pending`。

**续作同一笔原提交（Linux 源码）**：先点「查询该次操作的原回执」。仅当本窗口查到本机原登记仍有这笔待决、没有已知同代冲突时，才能点「核对并续作原待决操作」。核对的是私有 STATE 里已经冻结的同一操作号和整包摘要，不会读取、冻结或发布你后来对工作目录的编辑。核验时若正式槽空缺，另行确认才尝试不可覆盖上传；若已有相同归档，只核认原文件、不上传；文件消失或被替换不会改为上传。登记完成才更新本工作树基线。如果续作的是新分支操作，确认时会再次显示当前和目标分支；登记完成才切分支，工作目录文件不改。取消、冲突或结果未知不会自动续作，也不会另建分支。窗口关闭后不按路径重新认领工作树；CLI 的 `status STATE` 与 `resume STATE OPERATION` 是独立的显式操作。

上述入口都使用显式 CLI 格式工作树。**桌面应用托管**的登记、重开、提交/分叉和隐藏/恢复尚未提供；macOS、Windows 与未能核验的挂载不开放这个签出入口。未实机运行、未验收真实 SMB。

## Linux：把一个固定快照挂为只读目录

如需让文件管理器或其他程序直接访问一个历史版本，可显式运行独立的前台命令，不必先签出或解压：

```sh
zip-workspace-mount-ro "/path/to/原版本.zxs" "$HOME/快照查看"
```

两个路径都由你选择。挂载点须是已存在、本人独占的 **0700 空目录**，位于可核验的本机 ext4/XFS 上，不是另一个挂载点；用没有符号链接的绝对路径。各级父目录须属于本人或 root，不可由组/其他人写入。保持这个目录与祖先不被改名、同步或挪作他用，直到卸载。程序不会创建目录、改权限、更新系统设置或随应用启动挂载。需要普通非提权 Linux 账户已获准使用 FUSE3；独立 `mount` extra 使用 [pyfuse3](https://pyfuse3.readthedocs.io/en/stable/install.html) 与 Trio，不是普通 CLI/Qt 的依赖。

挂载前会检查全部成员、内容及整树标记。成功后可列目录、看大小、按偏移读取，包括空目录和空文件；不提供写、执行、共享给其他账户、提交或跟随分支头。本机同一用户仍能访问挂载内容。读取一直来自最初选中的文件句柄，不按归档名再开。每次只取涉及的 1 MiB 块，核对挂载时记录的 SHA-256 后才交付；小范围随机读也会读完涉及的块。原件变化、读不满或校验不符时，当前 FUSE 请求报错，不把这个请求的半段内容当作成功；不能撤销应用在更早请求中已读到的字节。摘要用于一致性，不是发布者签名。不复制一份归档到临时盘。按当前归档预算，挂载索引留存的块摘要净数据最多约 12.6 MiB，不含准入时的 ZIP 元数据、临时分配、名称、目录索引和在途请求缓冲。每个请求最多 16 MiB，最多同时处理 4 个请求；跨块的 4 KiB 读取最多需核两块。这些是源码边界，不是性能实测。

结束时先关闭占用该目录的程序，再在另一终端明确卸载原挂载点：

```sh
fusermount3 -u -- "$HOME/快照查看"
```

命令会在正常卸载后退出。进程被中断可能留下已断连的挂载；先核对仍是这一挂载，再正常卸载，不强制卸载、不清理目录。这里是 **Linux 只读快照挂载源码**，不是可编辑的工作树挂载；尚未执行挂载或实机验收。macOS、Windows 不提供此入口。

## 平台与发行状态

- **已验证：** Linux 上的 Python 3.12 源码命令行。`checkout` 写入普通本机目录，不会创建挂载点。ZIP64 已用包含 65,536 个条目的归档验证，单个 4 GiB 文件不在这项验证范围内。
- **尚未发行：** 已有可选的桌面图形界面源码，未在 Linux、macOS、Windows 实际启动验收、签名或打包；均无虚拟磁盘挂载发行版。[Android 15+ 目录预览](android/README.md)已有独立源码：从系统选择主存储中的单个 `.zxs` 或 Store ZIP，按目录查看声明的文件大小，也可点选一个普通文件，从本次原句柄逐块核验该项 CRC-32；不超过 32 KiB 的内容可在核验相符后按严格 UTF-8 纯文本查看。不解包，不认证快照或分支；未构建、实机验证或发行。[iOS 16+ 目录预览](ios/README.md)已有独立的 iPhone/iPad 源码，也能在浏览目录后明确核验一个普通成员的 CRC-32，或在核验相符后查看不超过 32 KiB 的 UTF-8 纯文本，不把结果当作整包认证。通过系统文件选择器原地读取；外部提供方可能为选择或读取自行下载。未构建、签名或发行。
- **网络存储：** 真实 SMB 共享的不可覆盖发布和断线恢复尚待验证，不能将本机测试当作共享设备的保证。详见[归档校验和平台范围](docs/design.md)。
