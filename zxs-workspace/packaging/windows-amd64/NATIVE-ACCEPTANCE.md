# Windows 原生磁盘最终冻结包验收

实现或 CI 的通过不能替代本清单。只在不存放实际业务文件的 Windows 11 x64 普通用户测试桌面操作。这里的工具不安装 WinFsp、不签名、不部署或配置服务、不提供通用写客户端。无可信已签组件/原生资格记录时，不填假散列，也不能用旁置模块或环境变量解锁。仓库当前没有已准入的发布记录。

1. **准备独立输入。** 归档原源码提交、原始 SDK/构建工具收据、签名权限、依赖许可，和已签应用 PYD/原厂 DLL/SYS 的逐字节散列。对相同字节完成 WinFsp 回调、原盘正常/异常关闭和私有文件/回执资格。获权审核后将记录固定在应用构建内。普通 GUI 原始候选生成时保留原未签 EXE 及完整 onedir、candidate.json 和从独立渠道获得的 SHA-256。
2. **只签副本。** 单独签最终 EXE，不在原候选上覆盖。运行 `verify-signed.py --unsigned-candidate <原候选> --expected-unsigned-receipt-sha256 <原收据散列> --signed-bundle <最终 onedir> --new-receipt <另一个新文件> --attested-build-commit <独立构建证明中的完整提交> --app-signer-cert-sha256 <独立 EXE 身份> --provider-signer-cert-sha256 <独立 PYD 身份>`。工具重新验证全部文件，比较原 EXE 包括整个嵌入的 PYZ；只允许 [PE 校验和/证书目录与末尾规范签名块](https://learn.microsoft.com/windows/win32/debug/pe-format#the-attribute-certificate-table-image-only)发生变化，并核对[固定版启动器](https://github.com/pyinstaller/pyinstaller/blob/v6.22.3/bootloader/src/pyi_archive.c)从文件末尾选择的原归档位置不变；在同一成功的 Windows 信任验证中按[明确的主签名序号](https://learn.microsoft.com/windows/win32/api/wintrust/ns-wintrust-wintrust_signature_settings)核对签署者叶证书（不是时间戳签署者）。它核验而不授予签名权；源提交来自独立构建证明，不从最终二进制推断。由有权发布者复核签署人、完整最终库存收据及其散列，另行传给验收者。
3. **最终产品本身。** 最终包、脚本和独立清单由验收者保持不变，使用测试账户不能写入的受控交付位置；若不能保证包外完整性，不启动。不要把入口 EXE 的签名当作所有旁置 Python/Qt 组件都已获签。在干净普通账户使用系统 PowerShell `-NoProfile` 运行 `qualify-native-release.ps1`，提供最终 SignedBundle、SignedInventory、独立 ExpectedInventorySha256、两个签名证书的独立 SHA-256、隔离空 ScratchDirectory，以及显式开关 `-LaunchIsolatedNativeCampaign`。这不是会自动关闭窗口的普通启动烟测。测试者自行通过原窗口输入一次性测试账号；不要把口令放在命令行、报告或日志中。首次准入须已安装对应的原厂 2.1 SxS 且服务原先停止，不主动停止机器上其他会话/驱动。切勿加入测试 CA 旁路或跳过 HTTPS/2；准备受正常客户端信任的独立 TLS 服务和独占测试容器。
4. **受控原位编辑。** 预先记录测试容器确切名称（可使用需要 Windows 本地别名的 `CON.txt`）、容器 ID、分支、原节点/修订、原字节 SHA-256；独立准备与之不同的目标完整内容、长度和散列（不大于 16 MiB）。在全新的独立私有 STATE 通过最终 GUI 打开实际目录磁盘，核对路径、别名、原字节及适用的只读 Zone.Identifier。从普通 Windows 数据句柄以 OPEN_EXISTING、GENERIC_READ|GENERIC_WRITE 原位写入并设 EOF、刷回；既有读写/映射引用时正常停止必须仍等待。关闭编辑器与相关资源管理器引用，但保持 Workspace 的原审阅窗口打开。确认正常停止、原目录已消失，审阅的大小/散列与预期一致；服务器此时不能出现新节点。在**同一未关闭窗口**明确准备并提交同一完整正文；记录本地四段原号与服务器监听侧同号的元数据 GET、至多一个这次 POST、实际长度及新节点回执。不获取或记录正文/口令报文。
5. **独立结果验证。** GUI 自行关闭后，在同一普通登录/原 STATE 的独立验证工具环境（可在产品免 Python 启动验收之后准备）运行 `tests/qualification/windows_gui_saved_result.py --help` 所示命令，显式 `--consent-read-isolated-server-and-original-state`。提供四段原号、原 HTTPS/账号与独立预期值。客户端先按原方式登录并读取列表；工具随后要求既有本地 .zrr 和两项已归档原记录，再通过已有网络适配器只读取同号服务器回执、实际分支元数据和新节点正文完整散列。它不补写回执、重试、退役或发布任何对象；无合格证据即失败。输出是这个正例的观察，不等于整个产品合格。
6. **负例另开原会话。** 独立负例中编辑后正常停止，直接关闭尚未准备的审阅窗口，确认服务器仍无新节点、不会自动准备或上传，不再使用已关闭窗口的草稿权限。另开会话在同号查询时模拟真实测试服务中断或请求后断线，核对原意图仍保留、未知时无新身份/盲重发；仅服务器明确缺席才允许同号显式恢复，已经见过的匹配回执不能被后来的缺席推翻。用独立私有目录和测试容器验证强制/外部停止不能产生可提交证明；保留私有原件。核对只读来源流、不能执行/改 ACL、无法创建未授权名字、目录/安装替换、服务原本运行、错误 DLL/PYD/SYS/签名/账号/目的地必须拒绝。不要为了完整走完流程而关闭系统安全功能、继续使用错名目录或强杀持卷进程。

最终记录应列出**实际**系统构建、原始/最终库存散列、应用和原厂三个二进制摘要、身份/ACL/来源、正负例结果、失败阶段和残留原件。原包启动、源码夹具、人工勾选和一次 HTTP 200 都不能单独充当发布资格。没有执行时写「未执行」。

### 外部前提与未满足时的处理

- 代码签名不是个人必须已经拥有的东西。由实际拥有分发权的发布者决定是否提供 Windows 信任的代码签名证书和受控签名服务/硬件；独立提供公共证书 SHA-256。**不向对话、源码、验收机或脚本交付 PFX、令牌、私钥或 PIN**。本工具不申请、购买、配置或代替签名。没有授权签名者时保留未发布源码或只读候选，不降低信任要求。
- 需要能处理可信时间戳/证书链/吊销缓存的签名流程、合法使用 WinFsp API 的分发权及应履行的开源/商业条款判断（由发布者确认），还有 Qt/Python/启动器的现有分发许可。应用只签自有 EXE/PYD；厂商的 WinFsp 原件与驱动签名不由本项目替换。不要将签名、密钥、安装授权或验收结论视为已经具备。
- 需要真实 Windows 11 **原生 x64**（非 Windows Server、非 ARM 仿真），本机固定 NTFS，普通非管理员中完整性桌面，以及管理员事先独立准备的相符 WinFsp 2.1 SxS。程序本身不提权、不安装、不帮忙停止别人的服务。可用满足该配置的专用机器或隔离的 x64 Windows 客户机，须实际运行原生驱动和本地 NTFS 路径，不能用模拟挂载代替。私有测试账号/容器和已授权签名交付不会因合并源码而自动具备。
