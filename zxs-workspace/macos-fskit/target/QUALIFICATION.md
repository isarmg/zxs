# macOS FSKit：SDK 合约与正式发行分开核验

**当前没有获准发行的签名可写卷。** 下面三个关口相互独立，第一项通过并不允许挂载、提交或加入发行表。

1. **SDK/ABI。** 只有维护者以后另行手动触发 [Workspace macOS FSKit SDK contract](../../../.github/workflows/workspace-macos-fskit-sdk.yml) 才运行；推送不会触发这一任务。用 GitHub 的 [xcode-27 arm64 镜像](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md)、Xcode 27.0（27A266a）和 macOS 27.0 SDK，分别以扩展限制和宿主配置编译实际 C 与 Swift 模块。将 Swift 生成的 C 符号及声明与手维护的前台宿主头文件交叉核对，再对跨层断言做类型检查。它不链接应用、运行测试、申请证书、签名、安装、启用扩展、挂盘或连接 R3。镜像缺少该固定版本时应报错，不使用另一个默认工具链补跑。现有 macOS 26 Qt/ad-hoc 流水线不变。
2. **发行组件和资格。** 发布者提供独立、可信的 Apple Silicon macOS 27 发布环境。须实际获得前台宿主的 `com.apple.developer.fskit.mount`、扩展的 `com.apple.developer.fskit.fsmodule` 及同一真实团队配置的 App Group。申请用的 plist、Xcode 构建或 bundle ID 本身均不授予 entitlement。按[真实目标](README.md)生成并保留精确的宿主静态库和 ExtensionKit 产品，将宿主库链接进应用窗口所在的真正主可执行文件，嵌入指定的 `Contents/Extensions/ZxsRemoteFS.appex`。当前 [PyInstaller 的 windowed bootloader](https://pyinstaller.org/en/v6.22.3/bootloader-building.html) 没链接该组件；不得拿现有 macOS 26 包、普通 SDK 库、旁置 dylib 或辅助进程冒充。检查最终 Mach-O 的导出表和整个签名分发包，不能只看静态库上的 `nm`。按 [Apple 正式签名说明](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac) 从内到外签正本，按发行渠道完成公证或相应审核；本仓库没有凭据、真实团队/配置或代签/代启用流程。
3. **独立参考机。** 保存最终签名包的字节指纹、所有组件库存、源码提交、唯一 `CFBundleVersion`、已签嵌入扩展的 Security 代码标识、系统构建、独立验收记录号。用这一份未分发候选，通过普通窗口/真实凭据和一次性测试目录验证用户亲自启用、真实内核卷标志与权限、大小写两种 APFS、同时打开的读者/截断/EOF、已支持的原位编辑，以及未支持的编辑器原子替换必须拒绝且不改正文。验证忙时不强制、断连与崩溃不冒充正常、终态发布/设备刷盘失败、正常后整件哈希、未改不建版本、明确提交与原回执/同号恢复。不得以模拟 HTTP、进程内 FSItem 或编译成功代替。未经这些核验不公布可写功能，不向现有发布表写入猜测身份。编辑器临时替换目前并未实现，不能宣称 WPS／Office 保存已通过。
