# 远程容器：原号回执与冷重开

[仅静态] 本页针对现有 Workspace 的故障恢复。已通过[隔离客机的原号查询阶段](https://github.com/isarmg/zxs/actions/runs/45322511258/job/138204176887)；整套桌面关窗、恢复与同号重试尚未实机验收。

## 结果未知时

- 保留原服务器、实际账号、容器、原操作号和私有原件；不要另建计划、改目标、另行上传或根据列表消失认定成功。
- 先选「查询原回执」或当前篇章所述恢复入口。只有原操作的精确未找到才表示缺少回执；空 503、冲突、不一致或网络失答都不授权发送。
- 已有完整匹配回执时先登记原结果，不能因为后续查询不明再次提交。正文缺失不妨碍查询，但不能重发。

各项提交须核对容器、原操作与其效果；保存还核分支、父节点、新节点及完整长度和摘要。追加的序列可跳过同容器另一次已确认变更；回收回执是终态，不虚造一个活动修订号。

同一容器只处理一项原操作；不同容器各自保存原号与结果。另存后若提示发布结果未知，先看原选位置。已有同名不能当作本次成功，也不要覆盖。

## 回收失答

连接或点「读取列表」时，本机仍能核对的原操作可出现在「原回收待查」。它不是活动容器，也不说明已经回收。选该项点「查询原回执」，不重新发删除；有准确回执才显示结果。

## Linux 冷重开

关窗前从待查容器或新文件行点「复制原传输信息」。内容是原 STATE、容器号、本机提交号和原操作号，不含登录凭据。

重新用原账号连接同一 HTTPS 地址，点击「按原号恢复传输…」，粘贴或填写四项。先只查；只有精确缺席且原材料仍在，才可在另一次确认后发送同一笔，发送前再查原号。

恢复只接受同一已登记 STATE 和已准备票据，不需要原 WORK、STORE 或原挂载，不补造票据或换目标。没有原证据就保留现场。有关正常停写，见[Linux 操作](../guides/linux-remote-edit.md)。

开发入口由 [`ContainerClient`](../../zipworkspace/desktop/container_client.py) 按已确认的原计划执行；[冷重开入口](../../zipworkspace/desktop/container_cold_transfer.py)与原会话编辑分开。[旧说明的原恢复章节](https://github.com/isarmg/zxs/blob/85a8988c386baad1305f4f81ce2c57786df6e436/zxs-workspace/docs/container-management.md#重启后按原号恢复传输linux)保留。
