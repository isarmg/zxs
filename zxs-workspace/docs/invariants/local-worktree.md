# 本机工作树：位置、空间和原号恢复

[仅静态] 本页记录 Linux 本机工作树的安全边界与空间估算。异常路径待实机验收；远程文件容器另有规则。

## 三个位置

- WORK 是普通编辑目录，STORE 保存正式快照，STATE 是本机私有状态；三处不能互相包含，每棵工作树有自己的 STATE。
- 新签出不覆盖、也不接管同名目录。操作与恢复期间保持选定父目录和原存储不被改名、替换或同步。
- 提交前关闭编辑器并停止所有写入者。新冻结使用合格本机 ext4/XFS；STORE 还须支持原生无覆盖发布和父目录同步。成功前不把普通读回、暂存或同名文件当作确认。

## 分卷空间

以 CLI、每代正文 100 GiB、已有基线且不另留散包为例。数字是同时占用量，不是所需额外空闲量。

| 时点 | 三处同卷 | WORK 和 STATE 同卷、STORE 独立 |
| --- | --- | --- |
| 首次签出完成 | 约 300 GiB | 本机 200 GiB；STORE 100 GiB |
| 第一次等大小提交 | 峰值和完成后约 500 GiB | 本机峰值 400、完成后 300 GiB；STORE 从 100 增至 200 GiB |
| 第二次等大小提交 | 峰值和完成后约 700 GiB | 本机峰值 500、完成后 400 GiB；STORE 从 200 增至 300 GiB |

起步已有原基线、STATE 原包和工作目录。完成后的私有候选仍保留。分卷的峰值不同时出现；散包、旧候选、失败暂存、文件系统和数据库开销另计。界面提示不预留容量，须另查各卷可用量、配额和 inode。

## 中断先查原号

- 签出用 `checkout-status STATE` 查询；确有待决才用 `resume-checkout STATE OPERATION`。
- 提交用 `status STATE` 查询同一待决，确认仍是原 STORE 后才用 `resume STATE OPERATION`。它不会把之后的编辑重做成原候选。
- 结果未知或原件对不上时保留现场。不按名称清理候选或 `.partial`，不替换正式槽，也不自动另开分支。
