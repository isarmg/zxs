# Windows：旧远程工作文件的安全边界

[仅静态] 给维护 WinFsp 和桌面收尾的人。本页涉及单个远程节点，不是已签名发行的编辑盘。只读快照、单节点另存、普通本机文件首提和可写卷各有资格。

## 从原节点到私有工作文件

- 保存实际账号、HTTPS 信任、容器/版本、原分支与明确节点。确认前不写文件；确认后复核同一详情，只取原节点，不追最新头。
- 在持有的私用 NTFS 父内独占创建内部名称，不拿远程显示名作本机名。系统要求标记时，首个正文前先写、同步、读回真实 `Zone.Identifier`。
- 偏移读写、追加和调整长度只操作默认数据流；限制按本次逻辑字节数，不是空间预留。短写或原件不明后保留文件，不再审阅。
- 停写拒绝新上下文，等已有写入、同步和原句柄真实关闭，再完整读回。工作文件审阅不是 WinFsp 的实际缓存排空或提交授权。

## 有资格的桌面流程

1. 登录原账号，选分支头或历史 `main` 节点，点「将所选节点作为本机磁盘打开」。选现有私用 NTFS 目录、本机别名与字节上限；缺合格签名组件不能挂载。
2. 关闭编辑器和占用的资源管理器引用，点「正常停止并核对修改」。须实际看到同一卷正常消失并核原正文；强制或外部停止没有提交证明。
3. 有修改才点「准备完整文件提交」。先落原号再封存完整新正文及计划；另审原服务器、账号、节点、长度和 SHA-256，点「提交完整文件」才有这一次发送资格。
4. 只查原号，不自动重发。仅精确缺席且原冻件完整时，可显式确认同号全量发送；第一字节前读回“可能已发送”记录。先前已核回执不能被后续缺席推翻。
5. 匹配回执经本机确认后，凭原件把意图和恢复键分别不可覆盖归档。半完成只补本地归档；不删工作文件、冻结正文或回执。

重启后以同一账号点「核对待处理的原提交」，选原私处及原容器／已有四段原号。没正文仍可查同一回执，不需要原卷；缺正式意图只能保留。新历史分支与原操作已绑定，不换号或二次分叉。

## 可选：一次同目录临时文件替换

默认为原位编辑。签名候选若含高级选项，用户明确选择后只允许一个同目录临时件；私下保留新旧两个 FileId 与实际来源流。磁盘内别名限定 1–120 个 ASCII 字母、数字及 `._~-`，拒绝设备名、尾点和原名大小写变体。

- 用 `CREATE_NEW` 独占新建、写完并刷新。普通路线先关写，再用不写正文的句柄；独占同步的 `GENERIC_READ | GENERIC_WRITE | DELETE` 路线只能用同一原创建句柄。
- 等其他正文和来源流上下文 Close；用经典 `FileRenameInfo` 指向本次同目录别名。若独占旧句柄改名后又写入或改长，关闭前须再次刷新。
- 源和替件都不删除或覆盖。正常停止时用真实卷重新打开原别名，看到正确的新 FileId 且临时别名消失，再排空、卸载和审阅；无法核实则保留两份、拒绝提交。
- 不支持先删除再改名、备份、直接写回退、`CREATE_ALWAYS`、任意交换或扩展/POSIX 改名。没有经实机验证的 Office/WPS 或 Qt 保存组合。

`tests/qualification/windows_winfsp_live_draft.py --consent-live-winfsp-qt-save-and-retain-both-private-files` 另接独立本机私用 NTFS 合成目录，只用于 Qt 保存和取消的原生候选，未执行。不以 Qt 源码路线相符当作应用或驱动通过。

## 独立的普通本机文件首提

已准入候选登录后点「提交新的本机文件」，无需选容器或挂载。选固定本机 NTFS 普通文件与私用暂存；禁止链接、同步占位、加密和附加流。服务器名字单选，保留原拼写。

第一次确认只封存原号和完整正文；第二次才按原号查、发。成功建立 `main` 首节点；失败不覆盖原件、不改名。尚未进列表也可在原账号下核对原容器或四段原号，不重选源。

两份独立源码用例分别为 `tests/qualification/windows_draft_qualification.py` 和 `tests/qualification/windows_save_qualification.py`，不代替最终签名包装及端到端读写。
