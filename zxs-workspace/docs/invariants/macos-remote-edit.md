# macOS：旧远程编辑、留存与另存

[仅静态] 给维护桌面和 FSKit 的人员。以下为已接通的源码路线，不是公开可用的签名卷。远程单文件提交不改本地 ZIP 的格式或状态。

## FSKit 正常收尾到原文件提交

1. 核同一服务器、实际账号、容器、分支和节点。在 App Group 私有 APFS 先独占登记卷 UUID、原目录及原磁盘号，再下载、挂载；同名替件不获得资格。
2. 正常卸载先停接新打开，排空原引用、同步原件、关闭可写句柄并核完整摘要。宿主的原卷已正常消失和扩展完成卸载须分别作证，且绑定同一原停写记录。
3. 接收方用原只读工作文件、父目录和票据 FD 复核 APFS 身份与时间代次，保留原租约。未改变不生成请求；有改变才独占封存全量正文（0400）、原计划、目标节点及原操作号。
4. 「只查原回执」不发正文。「提交完整文件」先核实际账号、目的地、原基准及完整长度/SHA；仅精确缺席才可按原号发，并在发送前持久记一次尝试。
5. 同一已认证账号可凭已知容器和原磁盘号读回原材料。仅原精确结果释放活动位，改动的原键和磁盘指针做两次无覆盖归档；半完成只补本机，不删除或重发。

已经进入的活动编辑必须有两边正常卸载证据，否则不能猜测崩溃后可提交。缺根、票据、原文件或终态时保留现场；不扫描认领、再下载、换号或重分叉。[FSKit SDK 与签名资格](../../macos-fskit/target/QUALIFICATION.md)另验。

`macos_edit_file.selected_edit_file` 是进程内匿名 APFS 原语。独占、核身份、去名、同步并确认零链接后才收正文；停写核全量后才能交接。它不等于真实系统卷；移交前退出会丢编辑。

## 两条独立另存路线

- **严格公开下载。** 真的系统隔离类型与 Launch Services DataURL 均须从原文件读回。[macOS 26 证据](https://github.com/isarmg/zxs/actions/runs/45298114940/job/138123553971)未得到原 URL。成功设置、Finder 文本或应用属性都不替代。此路线仍关闭。
- **单次明确另存。** 独立源码也默认关闭，不算系统 URL 证明。AppKit 对话框默认取消，显示完整连接地址、账号、节点、长度、SHA 和当前原目标；明示同意只作用于一次。
- **共同保护。** 先真实读回隔离类型。系统有 URL 则须精确；严格路线缺 URL 就拒绝，独立显式路线才可如实说明缺失。零字节先核空 GET。提交给系统的 URL 可能被留存，含私有地址/ID，不含口令。
- **发布不覆盖。** 保留原父目录、实际新名、精确正文与读回；原授信和目录在改名前后复核，并同步。普通同步不证明实际断电仍耐久。

还需在前台签名应用验证完整文本可读、仅实际点击肯定才批准，Return、Escape、关闭和取消均不批准。见[托管范围](../guides/hosted-desktop-qualification.md#macos-原节点另存)。

## 独立的普通本机文件首提

已准入候选在容器页点「提交新的本机文件」，不选原容器、不挂载。选择本人所有的本机 APFS 普通文件；拒绝符号链接、占位、资源叉和系统隔离来源。远程名称单独选择，不改原文件。

第一次确认只本机封存，第二次才按原号查询和全量发送。成功创建 `main` 首版；冲突不换名或覆盖。关窗后在原服务器/账号点「核对首次提交」，用原容器号继续，无需该容器已进列表。只凭原 APFS 证据，不补造。
