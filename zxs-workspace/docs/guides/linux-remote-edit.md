# Linux：旧容器页的本机编辑和全量提交

只适用于现有 Linux Workspace 容器页；不适用于新版 Rust 普通目录客户端，也不改变本地 `.zxs` 工作区。[仅静态] 真实 FUSE 编辑和卸载尚未验收，见[交付状态](../../TASKS.md)。

## 接入和选择一个原件

确认当前窗口持有本次原工作树并已连接正确服务器。按[打包说明](../../packaging/ubuntu-26.10/README.md)使用相应 FUSE3 组件。

1. 点「接入本机编辑…」，选择已经存在、本人独占的 0700 本机 ext4/XFS 空挂载点。它与原 WORK、STATE、STORE 独立。
2. 明确选「使用原登记」或「首次创建本机登记」。这一步不建目录、不联网、也不挂载；原登记不符保留只读连接。
3. 选要编辑的节点，使用核验相同的原文件，或取回到原 WORK 的空名。程序不覆盖占名。只在原卷证据通过并显示可编辑位置后，用普通编辑器在此工作。

首次向新空池提交时，在确实读到空列表并且本窗口新登记的 WORK 为空的前提下，可选「从本机空目录开始…」。不收养已有文件。首次提交在原正常卸载后逐项明确确认。

## 停写、准备与提交

1. 点「停写并准备提交」或「仅停写」。关闭占用原卷的文件、目录和终端。
2. 对同一原卷明确正常卸载。待全部原句柄退出并完成封存、原队列登记；准备并不上传。
3. 选实际要提交的那一项并确认。只发送完整新正文；只读打开、普通保存、退出、准备或卸载都不提交。

从历史 `main` 选定节点保存时，一次操作创建新分支及首个新节点，`main` 不动。原卷或答复不明时不自动重挂、清理、换号或重发；见[按原回执恢复](../invariants/remote-recovery.md)。

## 不上传的本机文件

默认忽略 `.DS_Store`、`~$*`、`*.tmp` 和 `*.swp`，文件仍在本机。旧远程编辑卷的下列规则与新版 Rust 打包、旧本地 ZIP 均独立。

- 在编辑卷根目录建立 `.zxsignore`，原有规则就编辑原文件。首次空 WORK 先挂载再创建。UTF-8，至多 16 KiB 和 128 条；空行、`#` 注释忽略，行首尾空白忽略。
- 规则区分大小写。不带斜线，如 `cache`，匹配任意层；带斜线，如 `reports/*.bak`，从根匹配。匹配目录排除后代。仅支持不跨斜线的 `*` 和 `?`；不支持绝对路径、反选、字符组或 `**`。
- 只读取停写原 WORK 中本人所有的普通单链接规则；它本身不上传。规则无效或在准备中改变会停止；已准备的原票据不重算。

编辑器把临时名原子换成未忽略的正式名时，以实测最终路径为准。已有容器的最终路径若被忽略，不改远端名称、标签或节点；删掉被忽略的本机路径不会删除远端。无其他改动时不生成队列。
