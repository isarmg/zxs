# macOS：完整文件编辑、留存与原号提交

[普通容器窗口与 FSKit](../macos-fskit/README.md)按原节点编辑一个文件，既不是直接操作远端文件名，也不写入普通 ZIP。源码包含从原节点到明确提交的路径；当前没有通过真实 macOS 验收的发行版本，不能将源码接线视为可用磁盘。

## FSKit 正常收尾到原文件提交

1. 用户选择实际账号、目的地和容器分支头／历史 main 节点，确认后才下载。桌面在应用专用 App Group 首次独占登记原私有 STATE 的 APFS 卷 UUID、inode、创建时刻；不同目录不能接管。以目的地、实际账号、容器在 STATE 预留本次原磁盘号，先于正文 GET。准备完整后记录原登记摘要及选择，再调用系统挂载。若中断，只查已知原号，不扫描、重新下载或另发新号。
2. 正常卸载时先停接新打开，等全部原引用及在途回调结束，先同步全部工作件，再关闭每个可写句柄、计算全部完整摘要。提供方停写记录的发布与系统卸载通知串行。宿主的原系统卷已正常消失，以及扩展的正常资源卸载，分别通过独占改名前已核、已同步、已关闭的原终态文件记录；两者必须绑定同一物理停写记录。消费者还须独立核原件，同步文件与目录、复读、核对原实体，才可接收。可见文件名、系统同步或单方关闭都不够。
3. 原票据租约独立于正文写 FD，跨越整个卸载。系统宿主只借三个真实只读原 FD：工作文件、私有父目录、原票据。工作者核同一凭据所属账号和目的地、原 APFS 身份与时间代次；再整份读回核摘要。**未改不建版本**。已改才生成同一份 `Plan/SaveNode`、新节点和操作号。分支头以原头为基准；历史 main 只在**一次保存**中分出新枝，不动 main。桌面保存返回的确切留存键，不把相同路径、选择或摘要当作相同操作。
4. 已认证的同一账号可通过已知容器及原磁盘号重读已完成原件／留存。完整正文为 0400，连同原意图保存在独占创建的私有 APFS 子目录。各元数据绑定原卷、实体、创建时刻、原版次和完整 SHA；在最终无覆盖改名前同步并确认原键。根、键、正文、意图或终态缺失／被替换均不重新造号。尚未取得双边正常卸载的活动编辑不属于可提交的崩溃恢复。私有状态不应被同步软件、其他同用户程序或 File Provider 改动；这并非抵抗恶意同用户的沙箱或系统备份承诺。
5. 「只查原回执」不发送正文。「提交完整文件」让用户先核原分支、目标分支、基础修订、完整长度与 SHA、原提交／操作号，再复查已认证服务器。只有原号确切 404 才按现有 R3 HTTP/2 协议 POST 同一份完整正文；第一字节发出前持久记录本次尝试。结果未知、冲突或先前已有回执不盲重发。明确查无先前尝试的原号，才可手动选择同号重发，发送前再次确认缺席；不会重分叉、换号或覆盖新头。已匹配的原回执绑定操作、基准、分支、新节点、完整内容与修订，先在本机读回并刷盘再报告。
6. 只有未改的已核原件或持久原回执能释放活动位。按同一个目的地／账号／容器锁，以两次本机独占改名归档改动的原键和原磁盘指针，保留正文与审计记录。每次都在原 FD 上核原物、内容和目标身份，部分完成只按同一笔核对，不删除或重新发送。旧原号可只查，后来重新编辑同一历史节点不是旧操作的续传。

### 独立的匿名编辑与公开另存

`macos_edit_file.selected_edit_file` 是进程内的匿名 APFS 编辑原语，不是卷或恢复票据。独占建立 0600 空暂存，开真正独立的读写与只读句柄，核实体、[移去名字](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/unlink.2)、同步原私有父目录并确认链接数为零后才接收正文。停写后等本会话内全部句柄结束，显式封存整份；未移交前退出进程会丢失编辑。它与真正的 FSKit 正常后移交共享原整文件留存、计划和回执代码，不假装共用 OS 挂载或进程内锁。

公开 Finder「另存」仍须读回真正系统隔离标记与确切 [Launch Services DataURL](https://developer.apple.com/documentation/coreservices/klsquarantinedataurlkey)。已观察到隔离类型正确但系统未返回实际 URL；不以成功 setter、Finder 来源文本或应用私写属性替代，公开另存继续关闭。挂载限制也不替代独立下载的来源证明。以上源码和[资格断言](../tests/qualification/)未在 macOS 执行，特别不能据普通 fsync 声称[设备断电持久性](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/fsync.2)。


## 首次提交一个本机文件

已准入的 macOS 客户端可在「存储容器」里选择「提交新的本机文件」。不用先选服务器容器，不挂载磁盘。选择本人所有的本机 APFS 普通文件，不接受符号链接、占位、资源叉或系统隔离来源。服务器文件名单独确认，按原拼写提交，不改本机原件。

应用只持同一文件句柄核对完整长度和摘要。首次确认只把完整文件和原号封存在本机私有 APFS 状态中；再次确认才查原回执并按原号发送，全量成功后才产生 `main` 首版。同名冲突不覆盖或自动改名；丢回复后不新开一笔。

如果关闭窗口，保持同一服务器和账号，点「核对首次提交」并输入原容器编号。即使新容器尚不在列表，也能核对同一份保留记录，不重开原文件。没有原件或只剩部分记录时不接管或补造。本功能沿用签名客户端准入，不启动 FSKit。新增首次全量发送、晚到回执和原件变更的资格源例，还没有运行真实平台验收。
