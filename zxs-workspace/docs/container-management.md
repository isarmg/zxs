# Workspace 容器管理页

Workspace 桌面窗口的「存储容器」页使用已有的 Qt Widgets。详情由窗口中的 [QTextBrowser](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QTextBrowser.html) 渲染本地 HTML；列表、分支/节点选择和操作确认用原生控件。详情只绘制已转义的文本，关闭链接及资源加载。不打开单独浏览器，不提供 Web 地址，不载入脚本或新增依赖。既有本机归档功能继续使用原入口。

## 操作

读取可访问容器的实际列表，选择后再打开元数据；打开不加载文件正文或启动挂载。所选容器可以重命名、整组替换标签，或经再次确认移入专用回收盘。回收确认来自原操作的真实回执，不以容器从列表消失为依据。界面没有永久删除、清理或远程管理入口。

保存要求原生客户端已冻结**单个所选文件容器**的完整新正文。既有分支头追加一个新节点；首次保存产生 `main` 的第一节点。从精确的历史 `main` 节点编辑后，同一次明确保存携带原节点、已在原计划中保留的新分支和节点标识与正文，原子创建分支并写入首个新节点。不会预先创建分支，不移动 `main`；不推断其他历史分支的写入方式。查看、普通编辑与关闭窗口不提交。

不同容器各有自己的原号与状态，可在有界工作池中独立进行；同一容器只有一项在途，不以另一容器的结果覆盖它。失答显示「结果未知」，先查询同一原号。只有服务器明确返回原回执不存在时，才可另行确认重试同一笔；发送前会再查原号。确认要求回执符合原容器、原操作、原序列和所选内容；保存另外核对分支、父节点、新节点、长度与完整摘要。保存回执序列可跳过同容器其他已确认变更；回收回执为终态，不会填造新的活动修订号。回执明示清理待完成时，仍单独显示原盘清理状态。

已接入写入权限时，也可以在分支历史里选定节点，点「从所选节点新建分支…」，核对原节点和新分支标识后确认。这是单独的元数据操作，新分支继承该节点，不上传正文或生成新节点。取得原回执才显示新分支及其继承节点；原分支保持不变。从历史 main 编辑后直接保存的原子分叉流程不变。

## 连接所选服务器

在「存储容器」中点「连接…」，填写 HTTPS 地址、账号与口令，再点「连接并读取列表」。只有收到该地址已通过鉴权的完整列表才接入；没有启动自动连接、浏览器跳转或换址。口令从窗口原生输入，当前连接仅在进程内使用，不写设置或交给页面。HTTPS 要求正常证书核验，并在 TLS 中协商 HTTP/2（ALPN `h2`）后才发送鉴权和请求正文。仅支持 HTTP/1.1 或不协商 `h2` 的端点不能连接。连接使用[已钉住的网络组件](../packaging/network-r3/README.md)。

普通连接可列出容器并查看实际分支和节点，不写入服务器。打开容器本身不下载正文。断开时清除本窗口的凭据、列表和选择，旧请求的迟到结果不会恢复界面；已开始的请求不能撤销。

## 另存所选节点（Linux）

读取并打开容器后，选定具体分支和节点，点「另存所选节点…」。选择本人所有的现有本机 ext4/XFS 目录与新文件名，核对服务器、原节点、长度和 SHA-256 后再下载。只读取这个原节点，包括历史节点；不会换成后来出现的分支头。普通只读连接即可使用，不需要原 WORK、STATE 或挂载；窗口正在处理原编辑卷时，请先结束该次编辑。

正文直接写入目标卷的无名称 0600 文件；完整接收、摘要、文件同步和本机读回相符，才以不可覆盖方式公开新名称并同步父目录。发布前可请求取消，当前网络或系统调用返回后停止；发布后若确认失败，原位置可能已有完整副本，先检查原位置。程序不会打开结果，不另发提交。Linux 桌面实机尚未验收。

## 回收结果失答

如果原容器已不在这次已认证的活动列表，重新连接或点「读取列表」会同时显示本机仍可核对的「原回收待查」记录。这类记录来自既有准备票据和原操作日志，不是活动容器，也不证明远端已经回收。选中后点同一个「查询原回执」；只按原容器和原操作号查询，不会重新发起删除。没有取得准确回执时仍待查；取得专用回收盘的真实回执后显示原操作号，不补造新的活动修订号。

## 重启后按原号恢复传输（Linux）

关闭窗口前，可从待查容器或本机新文件行点「复制原传输信息」。它包括原私有 STATE、容器号、本机提交号、原操作号，不含账号凭据。重启后用原账号只读连接同一 HTTPS 地址，再点「按原号恢复传输…」。粘贴或填入这四项，先查原回执。只有本次明确查到原回执不存在，才可另行确认重试；发送前仍会再次核对同一原号。

只接受已登记的原 STATE 和已准备的票据。这个入口不用原 WORK 或 STORE，不恢复挂载，也不会另外建票或选目标。原件不匹配时保留现场。

## 原生接线

`Window(container_operations=...)` 可接同一连接的原生 `ContainerClient`。它以原计划、原本机封存副本及已确认前缀定位唯一操作，调用现有 R3 适配器，先查原号；仅显式操作、获得精确未找到且本机未确认过时才发送，一次只处理该容器的这一步。查询只读原号，认证目的地改变即停止。

Linux 的写入配置要求本窗口仍持有原工作树和私有 STATE。它只接给这次已认证连接的目的地和账号，不从 STORE 找记录。发送及查询前须在原容器租约内核对本机原票据；确认后先登记再显示。非 Linux、原件或锁机制不符时保持只读。新窗口不继承账号口令。

### 本机编辑卷

同一个 Linux 窗口已有原工作树、并成功读取所选 HTTPS 服务器后，点「接入本机编辑…」。只选择已经存在、本人独用并且空的 0700 挂载点；它必须独立于原 WORK、STATE 与 STORE，位于符合条件的本机 ext4/XFS 上。选「使用原登记」或明确「首次创建本机登记」。这一步使用已认证的连接和原列表，只核对本机，不再次联网、创建挂载点或挂载。已有登记不符时停在原连接。断开会撤销本次接入权。

选中要编辑的节点，再用原文件或取回到原 WORK 中的空名。程序复核所选容器、修订、分支头和正文；用已有文件时逐字比较，取回时不覆盖占名。原卷获证后才显示本机可编辑位置。普通保存只写本机。原生所有者也可交给 `Window.offer_container_edit(choice)` 一次性原编辑资格。

首次写入时，若已认证的容器列表确曾返回空列表，而且本窗口已新登记一个实际为空的 WORK，可点「从本机空目录开始…」。无需远端节点；现有文件不会被收养。正常卸载并完成原队列登记后，窗口显示从本机原记录查到的新文件。选一个明确提交，才发送该完整文件并创建它的第一个 `main` 节点。原票据已存在时先查原回执。只有明确查不到、容器也尚未出现在列表时，才可再确认重试这笔原提交。列表已经出现同一容器时仍可查原号；取得原回执才显示已创建。

编辑结束后，选择「停写并准备提交」或「仅停写」，关闭文件、目录和终端占用，再明确正常卸载这块原卷。只有正常卸载、原卷句柄退出并完成本机封存及给原队列登记后，才显示已准备的提交号；这一步没有发送。原卷收尾不明确时，保留原件与已知原号，暂停本窗口旧工作树操作，不自动重挂、清理或提交。

### 不上传的本机文件（Linux）

停写准备远程容器提交时，默认忽略 `.DS_Store`、`~$*`、`*.tmp` 和 `*.swp`。文件仍留在本机。这不影响单独的 ZIP 快照工作区。

可以在编辑卷根目录创建 `.zxsignore`；首次从空目录开始时，先挂载再创建。已有规则文件请直接编辑。使用 UTF-8，最多 16 KiB、128 条规则。一行一条，空行和以 `#` 开头的行跳过，行首尾空白忽略。名称区分大小写；不带斜杠的规则匹配任何一层名称，如 `cache`；带斜杠的规则从根开始匹配，如 `reports/*.bak`。匹配目录也排除其下文件。`*` 和 `?` 不跨斜杠；不支持绝对路径、反选、字符组或 `**`。程序只在已停写的原 WORK 根目录读取本人所有的普通单链接规则文件；规则文件本身始终不上传。规则无效或准备期间改变时，这次不生成提交队列。

以完整的本机改名记录确定最终文件：编辑器先写 `x.tmp`、再替换成未忽略的正式文件时，仍准备这个正式文件。已签出的容器若最终路径被忽略，保留服务器的原名、标签和节点；从被忽略的路径删除本机文件也不触发远端删除。没有其他可提交改动时不会产生上传队列。已准备的原票据不会按新规则重算。首次会话如果只留下忽略项，再次使用「从本机空目录开始」仍需选择实际为空的新 WORK。容器页上明确执行的重命名、标签、分支与回收仍是独立远端操作。

以上是源码流程。实际使用还需符合条件的本机原工作树、空挂载点和 FUSE3 组件，尚未做实机验收。

## 分页容器列表

桌面端在现有已验证的 HTTP/2 连接上，用 `GET /zxs/v1/containers` 和请求头
`Zxs-View: compact` 读取目录。每页最多 256 个容器，只返回 `container_id`、
`sequence` 和 `name`。下一页将响应中的 `next_after` 原样放入
`Zxs-After` 请求头；`null` 表示结束。满页可能接一个空的末页。
客户端核验所有页后才更新目录或恢复列表；标签、分支与节点仍由具体详情读取。
各页反映查询时的状态，并非同一时刻的快照。提交和回执仍走原来的精确核验。

## 分页分支历史

桌面端读取容器详情后，在同一已验证的 HTTP/2 连接上读取
`GET /zxs/v1/containers/{id}/branches/{branch}/nodes`，每页都发送
`Zxs-History-Head`，其值为最初选定的分支头。续页另发 `Zxs-History-Next`，
其值为上一页末节点的父节点。本页从该父节点开始，不重复上一页末节点。

响应含 `head`、`nodes` 和 `next`。每页最多 256 个节点，`next: null` 表示链已到根。
服务端每页都确认分支头未变，并从该头沿父链重新走到续页起点；不会把其他分支的节点
当成续页起点。单页大小有上限，越靠后的页可能需要走过越多的历史元数据。
只有整条父链核验完成、容器详情再次读回一致后，客户端才展示此次结果。
分页请求要求原先看到的分支头是节点 ID。原有无分页请求（包括空分支）行为不变；
桌面端不在分页失败后回退。

## 分页容器详情

桌面端用 `GET /zxs/v1/containers/<id>` 和 `Zxs-Detail: paged` 读取所选容器。
每页保留容器 ID、版本、名称和标签，最多返回 256 个按分支名排序的分支头。
后续页带原版本 `Zxs-Detail-Sequence` 和上页的 `Zxs-Detail-After`；
满页可能接一个空的末页。版本不一致，或任一页不完整时，本次详情不会显示。
所有分支历史读取完成后，客户端按原版本再核对第一页；提交和回执继续使用各自的精确校验。
