# Authority, archive profile, and validation boundaries

## Independent directory repository

The directory workspace owns the repository ID, branch ID, explicit commit, parent operation and history. The server is generic storage, not a dependency or a source of membership/version facts. No custom server endpoint, source import, workspace dependency, submodule, package schema, file-container map or per-member move/copy protocol is used. Each immutable branch-generation slot contains one complete standard ZIP; no server-side database or accompanying user-visible history file is mandatory. The standard ZIP comment contains a bounded canonical directory-level marker. Its tree digest detects accidental mismatch; it is **not** a signature or an authorization scheme. Directory names and full file bytes remain ordinary members without metadata path collisions.

Portable behavior implemented here: checkout from a specified historical node, multiple isolated ordinary working directories, complete tree capture (including binary data and empty directories), explicit same-branch advance or explicit fork, independent local edits, original-operation retry, and immutable no-clobber branch publication. A concurrent stale commit cannot silently win or fork; its exact candidate stays in the private spool. No file-level source-node mapping, inner repository traversal, cross-repository member-container routing or old-format migration.

The private SQLite database is local to a single working directory and not part of the ZIP. A write transaction saves the candidate operation, marker and completed archive SHA-256 before the first remote write. A separate transaction records completion only after readback. In-process and cooperating clients cannot claim the same generation by overwriting it. This is not a distributed lock against arbitrary writers with share-admin permissions; backups/access controls remain necessary. Listings currently read whole archives and are intentionally bounded. Verified stopping points are not blanket claims about filesystem durability on all network appliances.

## Checkout and validation boundaries

Every managed checkout first persists the selected standard archive and original directory-level IDs in a private, exclusively named local registration. It reads and hashes the bounded source through one open descriptor, rejects a disappearing, changed or rebound selection, and verifies the complete closed local copy. A verified extracted directory is fsynced (files and child directories first); its original device/inode is committed before a no-replace rename can make the chosen worktree visible. If a call loses its reply after the rename, the original registration can recognize the exact named inode and attach it without fetching a newer archive or moving anything again. Automatic names advance through a bounded series under the selected parent. Collisions preserve both sets of data. Failure before the first state record can leave an unregistered private stage but never a visible managed checkout. Incomplete ambiguous stages are deliberately not deleted or adopted; finished checkout receipts are historical even after a later hide. Private originals take extra local space. The private state and checkout parent must not be concurrently altered by users/tools that can replace or delete their entries.

## Implemented and outstanding validation

- The CLI resolves branch heads and exact historical nodes from strictly verified directory slots. A loose archive can restore its own tree but cannot fill a missing published branch slot. Conflicting genesis, broken ancestry, duplicate identities, bad slot names or changing catalog observations do not create a head. Selection carries the complete archive digest into checkout. No member-level references are involved.
- The CLI now supports verified clean-only local hide/restore, working-directory inode identity, exact visibility-operation retries, change reporting, and explicit fork of a retained conflicting candidate. Visibility moves the original local directory with no-replace rename before recording completion. A newly occupied destination, dirty tree or third inode is preserved and rejected. Historical receipts never move the checkout again. These are client-local operations, never archive-member or server mutations.
- Directory-level real races, lost replies, post-freeze external edits, dirty hide refusal, original-dir replacement, non-overwriting restore and a real 65,536-member ZIP64 are exercised on Linux. 4 GiB single-member ZIP64, real SMB backends, automatic mount-handle draining, packaged clients, and private spool/orphan inspection and cleanup remain unverified or unfinished. The local checkout catalog is development state; pre-lifecycle catalogs without an original inode record are not automatically rebound. Keep any dirty data and use a freshly registered checkout. Archive format is unchanged.
- A writable virtual disk must expose **local checkout I/O**, not rewrite archives on every save. End write admission, drain every active writable handle, freeze a generation, then explicitly submit it. Linux is the first mount validation target using [FUSE](https://docs.kernel.org/filesystems/fuse/fuse.html); macOS should validate a native [FSKit](https://developer.apple.com/documentation/fskit) extension with the applicable resource/OS entitlements; Windows should validate the [WinFsp user-mode framework](https://winfsp.dev/doc/WinFsp-Design/) and its licensing, installer and signing constraints. None is currently mounted or shipped.
- iOS: use [the document picker and security-scoped user locations](https://developer.apple.com/documentation/uikit/providing-access-to-directories); Android: use [Storage Access Framework document/tree grants](https://developer.android.com/training/data-storage/shared/documents-files). The shared pure archive core can be embedded using [CPython on iOS](https://docs.python.org/3/using/ios.html) and [Android](https://docs.python.org/3/using/android.html), with native transport and workspace adapters. A picker or document provider that lacks exact no-replace/flush/readback cannot silently claim safe commit; permit read/import/export and disable that publish path. No mobile distribution, association, signing, release or mount claim until verified on the corresponding OS.
- System-mounted SMB is an ordinary provider, not a server plugin. Verify a real SMB server's no-replace and disconnect/reopen semantics before advertising support. The [SMB2 rename information class](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/52aa0b70-8094-4971-862d-79793f41e6a8) supports requesting refusal on existing names; this does not establish what an arbitrary provider actually implements.
- Archive validation compares local headers, central-directory declarations, CRCs, ZIP64 fields and streamed data descriptors. A contradictory Store/encryption declaration is not accepted as a portable archive. The underlying native writer must exist before checkout/registration can make files. Archive format: [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) and [Python zipfile](https://docs.python.org/3/library/zipfile.html). Repository opening requires both .zxs and the typed marker; an ordinary ZIP importer deliberately does not create or infer repository authority. No custom magic before the normal archive and no proprietary member projection.
