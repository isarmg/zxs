# Windows：一个远程分支头的本机工作文件（内部源码）

这不是已交付的编辑盘。没有盘符、驱动调用、可用的桌面按钮或远端写入口。本阶段把一次已认证的、明确选择的远程版本变成可按偏移编辑的一份本机正文。原先的固定 ZIP 只读视图和单节点另存均不因此获得写权限。

- **确定原件。** 选择记录 HTTPS 来源及信任策略、账号、容器 ID/原名/版本、分支和选中的头节点（包含长度和 SHA-256）。准备时仅持续持有已选私用 NTFS 父目录；确认前不创建文件、不重新请求数据。确认后在同一认证读取器重查所选详情，版本、名称或分支头已变就停止，绝不改选最新。只 GET 原节点。选择时还须明确这份本机工作文件的逻辑字节上限，至少容纳所选正文；这不是磁盘预留或配额保证。
- **保存正文。** 初始文件用无覆盖 FILE_CREATE 以独占的数据句柄创建在该父目录，只用新生成的内部名称；远端的 `CON` 等名称不会被用作 NTFS 文件名，也不会因本机选择改名。遵从系统对该 HTTPS URL 的实际来源区域和保存标记策略：需要标记时，先在这个文件写入、同步及核验 `Zone.Identifier`，再收正文。用相同的原句柄同步、读回全文、核实原名/文件 ID/权限、父目录和来源流。此标记不是查毒或运行许可。
- **编辑与停写。** 只对默认数据流提供有限长度的偏移读写和修改文件长度，未交付真实用户/内核/编辑器文件句柄。同步 HANDLE 上的定位、读写、改长与审阅串行；使用 [FilePositionInformation / FileEndOfFileInformation](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntsetinformationfile)，不使用会暴露旧介质数据的 valid-data-length 特权操作。追加在同一把锁内采用当前 EOF，受限的延迟写只覆盖仍在当前长度内的部分，不会在刚缩短后把文件重新撑大。依据 [WinFsp 2.1 Write 和 Flush 契约](https://github.com/winfsp/winfsp/blob/v2.1/inc/winfsp/winfsp.h#L439-L487)，单文件刷新仅同步这份原文件，不当作全卷刷新、停写或提交。短写或其他本机 I/O 不明后保留原文件，拒绝审阅，不重试或隐去已经生效的局部写入。
- **审阅与退出。** 开始停写后拒绝新的上下文，既有上下文仍能完成最终写入；每个都显式释放后，才可另行确认，同步并按原句柄重新读完整正文得出长度、SHA-256 和是否改变。此阶段不访问网络；不是持久化提交意图，也不是原生 WinFsp 缓存、映射或卷排空的依据。关闭、取消、断线和出错都不会上传或按路径清理失答/已编辑的私有文件。应保留确认时显示的生成路径；当前不能重开认领或自动恢复这份工作文件。

**与真正可提交的编辑盘之间还差什么：** 在受信的 WinFsp 会话中实现并核验虚拟条目的调用者、命名与本机别名、写回缓存/映射、来源/执行策略（含编辑器用无标记临时文件替换原正文）和真实关闭/卸载；将实际排空后的完整正文及相同目标、账号和操作号持久化，并实现只在明确提交时发送、失答后按原号查回执。在这些条件具备前，不能把本页的内存状态当成对外能力。

独立原生资格源例在 `tests/qualification/windows_draft_qualification.py`。需要实际 Windows 11 普通用户、现有固定本机私用 NTFS 合成目录及有效的系统来源标记策略；不改 ACL、不访问真实服务器、不加载 WinFsp、不自动清理合成目录。源例覆盖并发追加、受限写截断、单文件刷新、容量上限及稀疏偏移零填充、缩短再扩展、空正文、未确认/撤销、停接新句柄后的最终写入、半写失败不可审阅及断线保留原文件。本次只检查源码，没有编译、执行或实机验收。

## 单容器整文件准备、原号和冷重开（内部源码）

对已有远程分支头，只有原工作文件本次的完整审阅结果确实改变，再单独确认，才生成一个普通全量正文和一份原有 R3 `Plan`。计划只含一个 `save_node`，保留原容器 ID、版本、分支、预期原头、新节点、操作号、正文长度和 SHA-256；不发送改名，远程原名和生成的本机文件名彼此独立。此步需要额外一份完整正文的本机空间，不预留容量。

在原来选定的私用 NTFS 目录内，先独占创建正文及计划的内部文件，确定各自的真实 FileId。**写正文或发布待决槽前**，先无覆盖发布并同步一份单独的原号凭据；其中的容器、提交号、操作号、计划记录摘要也可以另行保管。正文的来源流先按系统策略写入，同步正文、读回核 SHA 及原实物，再将小计划不可覆盖地改名为该私处、账号、服务器信任配置和容器的待决槽。读回原号不等于已生成完整计划或已向服务器提交。

应用退出后，可用原认证读取器、原目录和明确的容器 ID 核对原号凭据，再用该原号重开已发布计划和完整正文。两次本机操作都不发网络请求；重开会同步原父目录以补确认最后的改名屏障。核对实际目录与各自文件身份、原账号/来源、原节点及标记、全量正文摘要，不寻找其他同名文件、临时文件或后来编辑的工作文件。原号已落盘但缺正式计划时，拒绝收养或重发，请保留现场。原号和正文另存于同一个受本人控制的私处，不防该账号或管理员恶意伪造整个私处；若有另存的原号和完整记录摘要，则可作独立核对。该槽约束该私处，不是跨磁盘的全局锁。

当前只提供持久本机材料以及供原 R3 上传器使用的、限时的已核只读正文；没有接入远端写请求、旧槽退役或 UI，第二笔不会覆盖第一笔。完整服务器确认、真实 WinFsp 停写、断电持久性和系统盘符都没有验收。独立 `tests/qualification/windows_save_qualification.py` 为同一普通用户条件下的合成源例，覆盖关闭后重开、同字节换件、竞争、原号先行、晚到改名应答及失效的只读游标；未执行。

**只查询原远程回执。** 内部入口可单独确认查询这份原计划：必须由同一目标、原账号的认证供应者证实实际登录名，只请求一次原操作号的 R3 GET。它不需要重新读取草稿或已冻结的大文件，也不能 POST。服务端报告未找到、冲突或结果未知都不会重发；只有完整的容器、操作、分支、父子节点、长度、摘要及返回版本与原票据相符，才将规范回执在本机无覆盖发布、同步和复核。服务器已确认而本机留证失答时，报告原操作号和服务器版本，仅可重新查询同一回执；不会因之前已确认的回执后来查不到就重新开放提交。这不是待决槽退役或 GUI 资格。独立源例另覆盖正文不可用仍查回执、错误目标/摘要、无回执、错账号、重复查询和本机改名应答丢失；未运行。
