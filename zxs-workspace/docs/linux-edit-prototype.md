# Linux 本机可编辑卷：原型源码

这段原型为一个持有的本机工作目录提供 FUSE3 文件系统操作，不是块设备。私有挂载交接已接入本机代理源码，尚无公开挂载命令、桌面按钮、包入口或后台服务；[固定快照只读挂载](../README.md#linux把一个固定快照挂为只读目录)不变。打开、读写和刷新都不联网、不自动提交，也不会生成整棵工作树的 ZIP。

- **原工作目录。** 只接原窗口的 `LiveCheckout` 与其确切可见登记。WORK 须在准入的 ext4/XFS 上，是本人独占的现有 0700 目录。核对原根、原名和祖先；相对访问不跨挂载、不跟随链接、不接受非普通文件或多链接文件；核对内核记录的原名字，不把底盘折叠写法当成实存名字。不读 STORE。实际 WORK 持有协作式独占锁来拒绝第二个编辑提供者；该锁不拦同 UID 绕过虚拟卷直接写入，操作者必须停止其他写入者。
- **原生编辑。** `zipworkspace/_fuse3_edit.py` 分开实现普通用户的既有目录遍历、普通文件只读与原位编辑、独占新建、追加和调整长度。已退场句柄不会指向下一份文件。另可显式删除已关闭的普通文件，或将其改名/移到同一工作根中的既有目录，目标须空闲。没有目录改名、建/删目录、任意覆盖、任意交换、属性/ACL 或扩展流。下述编辑器原子保存只接受一个确切已有目标。文件归属 ID、历史分支、标签和回收站不归挂载层管理。
- **每文件交接。** `bind_file(ino)` 在同一提供者的已核普通文件上保留本机观察身份；成功的新建、写入、截短记录实际受影响原件，保留原 inode 不受内核忘记目录索引影响。它不是服务器容器 ID。调用 `stop_writes()` 停止新写柄和命名操作，现有写柄可完成写入、同步及真实关闭。还有写柄、同步失败、已观察的原名失配或延迟关闭错误时，不交编辑结果。获准后用 `with owner.freeze() as cut:` 取得本次 `cut.changed_files`，再用 `with cut.open_file(bound) as image:` 得到同一原件的只读 FD、准确长度及 `image.check_file()`。调用方只能从这个只读 FD 在私处封存并复核完整副本；原文件借用和外层切点都成功退出后，明确提交才可传封存副本，不能直接发送 WORK FD。每次只接受本次切点中实际改过的那一项；只绑定未修改的数据不交出。复核实际长度、权限、变更时间与原 inode，拒绝观察到的外写。相同观察值不等于系统强制隔离，也不代替独占保管；退出不自动恢复编辑。该交接不从路径消失或正文相同推断改名、删除。同一容器的顺序及不同容器的并行由计划和传输层处理。
- **命名操作回执。** 相同的写入闸门接受真实改名/删除请求：从原父句柄核对确切旧名与已持有的原文件，普通改名只用原子不覆盖；删除后要求原 inode 的链接计数确实归零。同步受影响的原父目录，复核实际旧/新目录项和同一文件，目录描述符成功关闭后才追加内存事件。操作后失败可能已改动本机名称，不自动回滚或重试，阻止交接。接收方从同一次活切点读取按完成顺序固定的 `cut.namespace_events`，包括本机 `(dev, ino)`、操作前相对路径及改名的新路径（删除没有新路径）。重新签出或重启没有可信事件日志；删除的 inode 借原句柄保留到会话退出，不因同名新建而变成另一个文件。改名不算正文修改；另有正文修改的文件仅按最后实际名称交付，已删文件不交正文。只有在整个切点正常结束后，接收方才可按先前独立绑定的容器身份和原版本规划命名操作；没绑定的本机文件不产生远端删除。该证明依赖原目录本来就无人绕过提供者修改，Linux 不提供这里所需的按 inode 原子比较后 unlink。
- **私有原卷交接。** `EditMountChoice.review()` 留住原窗口 WORK 和既有 0700 空挂载点全链；必须在同一挂载命名空间，原目标位于无传播的 ext4/XFS，与 WORK、STATE、原 STORE 分开。明确授权并独占保管后才可调用已安装的系统 FUSE3 助手；未设置权限或安装任何组件。只承认已审阅的 pyfuse3 3.5.0 / 实际 libfuse 及 fusermount3 3.18.3 组合。固定 `rw,nodev,nosuid,noexec,default_permissions`、本人访问、直接 I/O，禁用写回和共享映射能力；确认实际内核来源、原父与挂载 ID 后，才把原设备 FD 交给回调服务。不能把这个协作锁当成禁止同 UID 绕过程序的强制隔离；不支持移动挂载点、直接改 WORK、同时运行旧式写项或共享传播。
- **停止、正常卸载与准备提交。** 仅停止不准备提交；另有显式准备提交动作。两者都关闭新写入，原文件须自行完成同步和关闭。随后另行确认同一回执的正常卸载；先排空实际文件/目录句柄并冻结新打开，检查原持有父链和活卷，调用同一已核系统助手只走正常卸载，不发延迟、强制或自动卸载。必须收到这个原助手成功退出、原卷内核项消失、原私有空目录恢复、FUSE 循环和处理任务全部归还，才允许本次提交在同一工作线程借一次只读切点；缺一项留 RUNNING。没有根据表项消失猜正常卸载，不会重放或切换到另一卷；没有自动网络提交。
- **持久隔离。** 在已核对的原同挂载 STATE 中独占建立 RUNNING 目录，落原实例和 WORK、STATE 身份，同步原记录和目录后，才允许挂载写入。残留 RUNNING（包括不完整记录或任何未知同名项）阻断重挂；不自动删除、重新绑定、从路径差猜改名/删除或重放。仅确认已正常停止、没有实际编辑或替换记录时，非覆盖移动本次空 RUNNING 为保留的结束回执；有改动须先由原切点完整封存并重新核对同一 STATE 内的确切待决计划与每个原正文凭据、逐容器在原 outbox 租约下读回实际 READY 队列与原计划摘要，再持久写本机结清回执并移动本次 RUNNING；保留原件、计划和回执，不删除、不代表服务端完成。结果阻断、现场不完整、意外离开或未提交的编辑保留 RUNNING；不按名字重开或接管未知状态。旧 ZIP 路径及其他平台不使用这个闸门。
- **正常编辑器的原子替换。** 在同一原父下，只有本会话真实独占新建、未绑定容器的普通临时文件，才可替换已由控制器绑定的确切原文件；两个原文件均已关闭。同步临时正文，决策先写入持久本地意图，再原子交换两原件，并把旧件移入同挂载的本次私处，不覆盖、不删旧件。同步原父和私处、确证真实前后名字、保留两原 inode 后才交事件。日志及原件不完备只报未知、阻断交接；不根据文件名后缀猜测。事件上的原目标本机身份映射到原容器及原版本，新的本机身份交付整份新正文，目标路径不变；不提交临时名，不产生远端删除/改名。没有先删后改、跨父替换、通用交换、自动恢复或清理。控制器必须在编辑前绑定真实原容器及原版本；本机换 inode 不会凭自己产生新服务器身份。
- **其他平台。** macOS 后续需独立准入的 FSKit 本机目录扩展；Windows 需真实 WinFsp 同登录会话盘符和本机 NTFS 读写权及原句柄收尾。它们未接入本原型。

`tests/test_linux_edit.py` 是尚未执行的普通本机源例，不需要 FUSE 驱动或网络。
