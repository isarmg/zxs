# 本机文件与原回执边界

[仅静态] 说明 Linux 第一条普通文件路径依赖的保持条件；不是新增服务端协议。真实 HTTPS 丢回复和跨进程发布仍需[单独验收](../../TASKS.md#还要证明什么)。

## 绑定原对象

- 状态目录须私用 0700，与编辑或另存目录分开。`workspace.sqlite` 仅存原授权配置摘要、普通路径绑定、服务端基线、原操作/回执及本机包清单，不存口令或本机历史。
- 先持有并验证 inode，再读普通文件或打开已有私用租约；类型、所有权、链接数、权限或路径换件不成立就拒绝。首建租约必须独占创建；另存是匿名文件读回后不覆盖插入。
- 普通源文件可由编辑器原子替换。核对选定的版本在封存前变动就重新核对；封存后用户继续编辑也不会被拿来重做旧待决正文。

## 租约不是安全账户边界

私用目录中的客户端按容器协同持锁。租约在原名、文件及父目录验证后保持打开；发布、状态更新和 H2 就绪后的真正发送前再核。发现原名被替换时停止。若此前已写入“已准备尝试”，该记录保留供同号查询；已明确的本机发送前拒绝不再写成未知的服务器答复。

本机核对能保护协同客户端与检测到的意外换件，不对恶意同 UID 进程作隔离承诺。远端重复提交保护仍依赖同一原操作 ID 和精确回执。

## 只确认原号

1. 本机核对并明确封存只记原 ID、长度、摘要、去向和原基线；无网络正文提交。
2. 离线打开不请求服务器。明确重新认证后按原 ID 查回执；原正文丢失也可以查，不可以重送。
3. 只有原回执明确不存在、原基线和原封存仍符合，且用户另行确认，才尝试发同一原操作。未知结果、账号/来源不符或假回执不重试，不把新编辑当旧正文。
4. 已记录的冲突会阻止原操作再发送。后来查询显示不存在、无法核验或仍冲突，都不会解除这个状态；只有逐项匹配的原回执能确认该操作。未收到有效回执的查询不会抹掉原尝试记录。
5. 逐项核对已提交回执后，事务内推进原基线，再清理精确原封存。清理中断可本机再核对；不是重发理由。新编辑内容仍在原普通文件里。

## 只取消未尝试的本机封存

离线执行 `zxs-client /绝对/私用目录 cancel-prepared 操作ID`。核对原号和封存，另行确认才丢弃。保留当前普通编辑文件与旧确认基线，不改映射，不生成新操作，不连接服务；无需编辑文件还与旧封存完全相同。

只接受状态明确从未登记发送尝试的 `prepared`。编辑文件缺失、换件，或原记录曾尝试、不确定、冲突、已确认，均拒绝。早期只留下“不存在”或“不确定”的记录不能还原成从未尝试。

确认后、开始丢弃前会再次核对原工作文件。两个路径的操作不是一个原子动作；不保证阻止同一账号在最后核对之后另行删除工作文件。

如果中断发生在封存副本删除之后、本机记录取消以前，原记录还在。用同一原号重新核对并另行确认才完成取消；不以此授权重发或替换编辑文件。
