# 归档冲突，按当前分支头重新开始

[仅静态] 只处理已记录的冲突。不把断线、超时或查询不到回执视为冲突，也不确认远端取消或传输成功。

1. 先对原操作号查回执。若精确回执已确认，无需归档。
2. 离线执行 `zxs-client /绝对/私用目录 archive-conflict 原操作号`。核对原意图后，按提示输入 `archive 原操作号`。仅释放该笔本机待决占位。
3. 要继续原容器，签出所选分支的当前头，填写**全新的普通路径**。从旧文件挑出需要的改动，手动合并到新文件，再走正常的核对、封存、确认提交。
4. 若冲突出在首次新建，先查原回执和远端清单；已有目标时从现有分支签出。若确需另建，使用新本机路径并明确选择新名字。不会自动新建或分叉。

归档保留旧普通文件、旧映射、原封存及同一操作号。旧路径和归档前同容器的旧签出不能当作新写入基线。工具不自动把旧内容并入新头，也不改服务器。

用 `zxs-client /绝对/私用目录 archived-conflicts` 离线查看原号。继续用带地址的 `status 原操作号` 或回执专用会话逐笔重查；后来出现的精确回执只补进归档，不推进新的本机基线。

第一次归档会原子升级本机私用状态格式。旧程序不能再打开升级后的私用目录；普通工作文件不是版本库，不受影响。详见[本机回执边界](../invariants/receipt-recovery.md)。
