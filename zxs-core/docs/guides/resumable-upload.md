# 显式断点上传一个普通文件

Linux CLI 在[安装后的隔离 Ubuntu/ext4 客机验收](../../../zxs/docs/guides/resumable-upload-installed-qualification.md#已核对的-cli-客机验收)通过：8 MiB 后断线或首块确认答复丢失，重开只查询，确认继续只发送最后 137 字节。
需使用已启用匹配分块入口的服务；默认整文件上传与只查回执的入口不变。

[仅静态] Linux 窗口可直接选择普通文件和远端名称，点「Review resumable upload」并确认。重开后在原待决行核对或继续；[窗口操作](desktop-shell.md)。桌面断点续传未纳入上述验收。

1. 先在现有私用工作区用 `prepare` 封存原件，记下操作号。首版、已有文件和原基线沿用[普通工作区流程](../../README.md)。
2. 选择分块模式后运行以下命令。核对账号、路径、原目标、整长与 SHA，再输入提示的 `send 操作号`。一次确认覆盖剩余分块和发布，不逐块询问。
3. 命令输出服务器已确认的字节数。只有原 `save_node` 回执才算发布。编辑器里后续修改不会替换原封存。

```text
zxs-client --upload-session HTTPS地址 账号 /绝对/私用目录 send 操作号
zxs-client --upload-session HTTPS地址 账号 /绝对/私用目录 status 操作号
```

## 断线、重开或结果不确定

- 先用第二条命令查原号。已发布就确认原回执；未发布才查暂存。只有匹配服务返回的专属不存在证明才可开始；没有该入口的旧版返回普通 404 时不发文件。首次响应丢失时按原容器和操作号查；已知上传号时只查该号。查看状态不会补发正文，不会重新开始或发布。
- 确认继续才再次运行第一条命令。客户端不自行重登、切回整文件、改用新操作号或从编辑文件重做正文；只发送服务器确认偏移后的完整分块。会话到期也需要明确续作。
- 原封存缺失仍可查回执；已知上传号消失、进度倒退、意图或资格不符、服务端无法核定时保留原记录。若开始时服务端中断在准备阶段、查询持续不确定，此版不尝试强制修复。
- 低版本客户端不认识已切到分块模式的待决记录。保留原私用目录，使用本版或更新版核对该原号；不要用其它版本或操作号绕过。

分块线规以[服务端唯一规格](../../../zxs/docs/specs/resumable-uploads.md)为准，回执归属见[本机回执边界](../invariants/receipt-recovery.md)。
