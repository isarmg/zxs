# zxs-core

统一 Rust 客户端内核的第一份 Linux 源码候选。保留现有 R3 API：普通文件下载、在任意本机编辑器修改、确认封存、明确提交完整正文、按原号冷查回执。无需旧客户端、虚拟盘、本机 `.zxs` 仓库或 `STORE`。

## 首条使用路径

需普通 Linux 用户、真实 ext4/XFS、`openat2`、正常 HTTPS/2 和原工作区所信的系统证书。私用目录须是应用单独选择的空 0700 目录，与编辑内容分开。口令只从不回显的终端输入。

命令原型：认证路径 `zxs-client HTTPS地址 账号 /绝对/私用目录 <操作>`；离线路径 `zxs-client /绝对/私用目录 <操作>`。

- `init` 核对远端列表并登记独立本机状态。之后 `list`、`detail 容器ID` 可浏览。
- `checkout 容器ID 分支ID /绝对/本地新文件` 把原分支头另存为一个新普通文件。用任意本机编辑器修改；它的保存不会触发服务器操作。
- `prepare /绝对/本地文件` 核对并只在本机封存；新容器加 `first 显示名`。正文未变化不生成新操作。
- `send 操作ID` 另需确认，先只查原回执，只有原号明确缺席才可能发送同一完整正文。离线 `open` 不连网；重新认证或 `reconcile` 后自动查原号，不自动重发。确认回执只更新原基线，不覆盖用户编辑。
- `bundle-diff /绝对/目录` 与 `bundle-pack /绝对/目录 /绝对/新文件.zip` 核对目录变化和确定性标准 Deflate ZIP，支持根 `.zxsignore`。当前只打包到本机，不假装已有服务端 ZIP 类型或 Range 接口。

历史分叉模型已在 R3 原始结构中表达，首条 CLI 暂只选择当前分支头。会话 Bearer、Range、分块续传、ZIP 远端差异和其他壳的接入待实际契约冻结。旧数据和旧程序未删除。

**验证状态：** 已用官方锁完成格式检查、Linux CLI/库类型检查和 4 个纯内存单测；未运行独立安装后的客户端或端到端验收，未发布。参见 [架构](ARCHITECTURE.md) 和 [验收](TASKS.md)。
