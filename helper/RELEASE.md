## H07：获准后，怎样验证一次独立构建

从干净的本项目单独源码目录开始。不继承上级 Cargo 配置，不用相邻工程或来源不明的二进制。以下是**未来的记录步骤，本次未执行**。

1. 记录原始源码提交及目录树、工作区是否干净、实际工具链和目标三元组。源码要求 Linux x86_64、64 位指针；清单是 Rust 2024 edition、最低 Rust 1.100，[工具链文件](rust-toolchain.toml)钉住 1.100.0（minimal）。下面仅以 GNU/Linux 的 `x86_64-unknown-linux-gnu` 举例，不据此宣称已支持其他 ABI 或发行版。
2. 使用已准备好的准确工具链、目标和完整可信缓存；记录 Cargo/Rust、链接器、系统运行库及影响构建的配置或环境。缺包、缺目标或锁文件需变化，停止并记录原因，不临时解除锁定或改用其他版本。[依赖来源核对](DEPENDENCIES.md)不是 Cargo 解析或构建结果。
3. 在该源码目录分别记录命令、退出码、完整日志和实际输出。示例仅供将来获准使用：

   ```sh
   cargo +1.100.0 build --locked --offline --release --target x86_64-unknown-linux-gnu --bin helper
   cargo +1.100.0 test --workspace --locked --offline --target x86_64-unknown-linux-gnu
   ```

   测试与发行构建是两项证据。正向文件用例需要允许的文件系统、私有专用测试目录和相应只读权限；`HELPER_TEST_DATA_PARENT` 只供测试，不能指向真实业务数据。记录实际用例数、失败、跳过及原因。以下是旧 MAINT‑1 原型的测试条件，不是通用新池的发行资格：旧原生身份与互斥用例需支持 O_TMPFILE、FS UUID / 文件句柄及指定的首次具名权限。全组锁的正向用例另需 `HELPER_TEST_RECYCLE_PARENT` 明确指定另一独立的本地专用测试区域，dev 和真实文件系统 UUID 都须与数据测试区不同；没有这个区域时不能把两目录伪装成两盘。完整祖先阳性要求所选根到当前维护进程的根目录可逐级核对、支持读固定卷标签、各所用挂载露出完整本地文件系统根，实际命名空间根行须 self-parent。即使普通宿主，也不能把缺失的 initramfs 父行当作终点正证。子树 bind 反例另需预置私有 HELPER_TEST_SUBTREE_BIND_PARENT，用例不创建挂载，也不读取测试区其他数据。缺少前提不是通过；没有用同一配置复建比对，不声称可复现。[Cargo 参数说明](https://doc.rust-lang.org/cargo/commands/cargo-build.html#manifest-options)

   通用格式另需双方在真实、明确授权的隔离挂载验证普通文件认领、真实锁竞争、文件和父目录同步、断点与冷读；准备阶段的纯向量或旧原型均不替代这些证据。不需要格式化或改造现有盘。

## H08：在交付文件之前，需要什么证据

| 要证明的事 | 留存的证据；缺失时不作该结论 |
| --- | --- |
| 哪个文件来自哪次构建 | 从上面的准确源码、锁和工具链追到同次构建输出；记录目标、构建配置、文件名、字节数、SHA-256 和构建日志。在最终打包及传输后重新核对实际交付文件，不用相同版本号代替。 |
| 该带哪些许可和署名 | 按真实目标区分随包代码/运行库、仅测试工具和其他平台依赖。以每个实际组件的准确版本和原始材料为依据，保留适用的许可原文、版权、例外与通知。若分发额外运行库，也单独记录。将最终材料目录与制品摘要一起归档。 |
| 站点管理员如何核准制品 | 从独立可信的完整构建记录或来源取得绑定源码、版本、目标与最终文件的预期 SHA-256。可以是自己在可信环境从锁定源码构建的产物。先留预期值，再核即将安装的字节；不从待验文件或它附送的摘要现算现批。本项目不要求单独的发布者签名；已有签名可作为来源证据，不能代替本地核准。 |
| 如确需安装，能否安全退出或升级 | 另行明确安装目标、权限与文件清单；不启动服务，不扫描或更改其他程序。只有已核发布物和明确目标才可安装。首次安装只写入确认的新目标，不覆盖已有文件；升级只认经核实的本工具原安装，未知、被替换或指向符号链接的目标一律停止。须在获准的独立试验位置验证中断后的原件、残留和恢复，再写实际安装或卸载说明。当前没有安装器。 |

线上 SMB、离线建域及离线 SMB 账户使用三个既有、彼此独立的 root 本地审批文件：[在线角色](docs/smb-host.md#安装材料)、[建域三摘要](packaging/debian13-amd64/README.md#专用-samba-供给运行时)、[两账户的站点策略](docs/samba-domain.md#独立发行与站点策略)。构建器和安装包不写这些批准，也不代替本机前台、池或实例级确认。管理 HTTP 的可选单元仍按[原 ELF 摘要](docs/management-http.md#可选准备一份-systemd-单元)核对。Debian 上游 `InRelease`/.dsc 认证与 SMB 会话签名均不变。

构建、制品核准、安装和运行分别记结果；证据不足就标为未验证。项目待办见[任务清单](TASKS.md)。
