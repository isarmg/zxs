# helper

目前的宿主只读诊断包括：目录关系、文件比较、选定存储根的容量/挂载、Linux 块设备清单与被动 I/O 速率，文件系统检查工具清单，以及隔离调用 FAT32、exFAT、ext4、XFS、NTFS 或 Btrfs 的上游工具。目标平台为 Linux x86_64。不接管设备或服务，没有后台服务；只有显式启动 `helper disk-web` 才开临时本机面板。无参数只显示用法。

ZXS 的业务管理页由 [ZXS 原生 HTTP](docs/management-http.md) 直接提供，默认监听 0.0.0.0:8443，无需域名、证书、nginx 或套接字激活。可选的非 root systemd 单元只作为不启用的候选；如需 HTTPS，使用站点的外部软件。本包不会启动或改网络。

[专用 SMB](docs/smb-host.md) 在配套验签发行下由本机前台启动。首装已选的数据目录无需再进 Web 开启，只访问唯一共享。原监听证明与独立客户登录、读写验收分开。

```sh
helper inspect-dirs /home/alice/downloads /home/alice/downloads/week-01 /mnt/incoming
helper compare-files /home/alice/reference.bin /mnt/incoming/candidate.bin
```

**目录观察。** `inspect-dirs` 接受 1–16 个现存绝对目录，包括 `/`。每行用输入序号标识目录；每对位置分别报告是否同一实体、内核返回的设备号是否相同，以及从原始路径实际看见的两个祖先方向。同一目录可以选两次，正常的父子关系不是错误。内容不被枚举，名称不回显。最多输出 120 对关系、32 KiB；同时保留的目录操作描述符不超过 18 个，不计进程原有描述符。不同设备号不证明独立物理盘，路径中看不见共同祖先也不是跨 bind 挂载的全局不相交证明。

**文件比较。** `compare-files` 要求本次选择的是两个不同、各只有一个硬链接且不超过 256 MiB 的普通文件。两端先以不读取内容的描述符核验身份和实际文件系统，再尝试打开任何一端读取。只受理 ext2/3/4、XFS、Btrfs 和 F2FS；未知文件系统、procfs/sysfs、tmpfs、网络、FUSE、overlay 等不支持，被拒绝的输入不会被探读。需要真实的本进程 procfs 和使用 `O_NOATIME` 的权限（通常为文件所有者）；不能满足即失败，不按名称回退重开。

比较按两块 64 KiB 缓冲区流式读取，即使首字节或长度不同，也要确认两端的完整长度和终点。输出前重核原位置及关键文件属性。返回码 `0` 表示文件相同（或目录观察完成），`1` 表示两份合格文件的内容确实不同，`2` 表示参数、权限、支持范围、变化或 I/O 错误使观察不能完成。结论只针对本次读取；它既不是原子快照，也不说明参照文件可信。

两个通用命令都要求未经缩写的绝对路径，最多 4096 字节、128 个分量；拒绝符号链接和空、点、父级分量。没有默认扫描、修复、写入、覆盖或上传行为。更多边界及未来范围见[架构](ARCHITECTURE.md)。

## 本机磁盘面板

`helper disk-web` 在明确启动后才监听本机临时端口。从终端取得一次性配对码，网页可查看设备与挂载、被动 I/O 速率及七类工具的固定安装位置。普通启动不会执行检查。终端用 `--fat32-copy`、`--exfat-copy`、`--ext4-copy`、`--xfs-copy`、`--ntfs-copy` 或 `--btrfs-copy` 加 `IMAGE --sha256 HEX` 只选定一份卷镜像，配对后预览并确认一次。两种 FAT 在启动时封存，ext4/XFS/NTFS/Btrfs 只在确认后持只读租约并比对整份摘要，不复制。网页不收路径、上传、工具参数或修复请求。见[用法和访问边界](docs/disk-web.md)。配对后还可打开[首次安装向导](docs/disk-web.md#首次安装向导本机命令与原回执)：比较固定模板并提供可复制的本机命令；真正建池、域供给、口令和启停确认仍只在终端。

## 查看选定的存储根

```sh
helper storage-status --system /mnt/control/pool --recycle /mnt/recycle/pool --data /mnt/photos/pool --data /mnt/video/pool
```

明确给一个 SYSTEM 候选、一个回收站候选和 1–62 个普通数据候选；顺序不限。当前存储根参数的原始路径边界为：最多 4096 字节、1–256 个分量，不接受 `/`。不做 UTF‑8 转换；与通用命令一样不跟随链接，不允许空、点或父级分量。报告开头是采样的 Unix 毫秒时间窗，随后按角色和数据盘序号列出结果，不回显路径。**这里的角色是你的选择，不是已登记身份或布局检查。** 这是主机观察，不打开业务文件、枚举设备、访问服务或获取维护锁。

每个目录以自身持有的描述符取 Linux 挂载 ID、内核是否将它标为该挂载的根（可能不报告），再用该目录的文件系统统计取只读标志、总字节、全部空闲字节和非特权进程可用字节。挂载 ID 只在本机当次命名空间与该挂载的生命周期内使用，不是设备/文件系统 UUID。只读标志未设置不证明当前账户有写权限；可用量不是可保证的预留空间，也不能跨行相加当作独立磁盘容量。

报告前重新解析原路径，核对全部可见祖先、目录实体与挂载 ID；身份不匹配不发布那一行的旧数据。若路径不存在、权限不足、挂载 ID 不可取或容量统计不可用，将保留其他行和仍可核的字段，返回 `2`。各行挂载与容量都采到时返回 `0`，并非“可初始化”或“盘健康”。数据不是全机原子快照，观察期间可发生重挂载或空间变化；没有温度、速率、业务可用性或已登记卷的验证。

## 查看块设备、分区与 I/O 速率

```sh
helper disks
helper disks --device 259:1 --rates
```

只有显式调用 `disks` 或点击本机面板的相应按钮才读取本机的内核块设备索引。每行对应一个 `主设备号:次设备号`，给出内核名称、整盘或分区、块层容量。分区另列实际父设备、分区号和起始扇区。名称不是固定的盘身份。“整盘”也可能是 loop、dm 或其他虚拟块设备。不会将父盘、分区和底层设备加总。对超过 256 个条目的系统，改用 `--device` 精确选择一项。

`direct_mount_ids` 只列本线程挂载表中超级块设备号直接匹配的挂载 ID；同一文件系统的 bind 挂载可能有多个。无直接匹配不表示未挂载或未被 swap、阵列、其他命名空间使用。`fs_uuid_udev_alias`、`partuuid_udev_alias` 来自受保护 devtmpfs 上当前分别指向该设备号的 udev 别名；它们是可陈旧的宿主缓存，不是现读介质、硬件序列号、登记 ID 或挂载 ID。无法安全归属的别名和无已知缓存型号的设备显示未知，不启动识别程序。只对设备节点取路径元数据，不打开设备读取扇区。

`--rates` 多取一帧内核累计计数，中间等约一秒；按**每个设备两次读计数完成时的单调时间间隔**输出读、写 B/s。Linux 在这里的一个扇区恒为 512 B，即使设备采用 4 KiB 扇区。设备生命周期、分区原件或几何变化、可见计数回退、缺少同一盘世代时不能给速率；只有该方向的计数增量为零才报告 0；有实际传输但平均不足 1 B/s 显示为 `<1`。不是写入测试、性能上限、文件系统可用量或健康证明。基本资料/挂载或所请求速率不完整时保留其余行、退出 2；仅缺型号或 UUID 不影响基本清单。当前还没有 SMART、自检或修复命令。来源：[Linux 块层计数](https://docs.kernel.org/block/stat.html)、[内核设备世代](https://docs.kernel.org/admin-guide/abi-stable.html#sys-block-disk-diskseq)、[挂载命名空间字段](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html)。

## 查看检查工具是否在位

`helper fs-tools` 显示 ext4、NTFS、ZFS、XFS、Btrfs、exFAT、FAT32 各自的只读检查方案、对象和固定程序位置：FAT32/exFAT/ext4/XFS/NTFS/Btrfs 查私有发行工具槽，其他仅观察宿主槽，不能据此调用。可用 `helper fs-tools xfs` 只看一种，或对单个工具加 `--sha256` 与独立发行材料的摘要比较。**不会打开设备、调用检查器或修盘**，版本与签名仍为未核。详情见[七格式能力表、检测限制和返回码](docs/filesystem-tools.md)。

## 检查一份 FAT32 或 exFAT 镜像（只读）

`helper check-fat32-copy /绝对路径/volume.img --sha256 完整镜像的可信SHA256`。只接受已保存、最多 128 MiB 的普通 FAT32 卷镜像，不接受设备、分区表或任意工具参数。检查器只看到已核摘要的独立副本，在独立的 Linux 命名空间中运行 `fsck.fat -n`；不会修复或改写原镜像。[Debian 13 amd64 的发行配方](packaging/debian13-amd64/README.md)将上游工具与其运行库放在 helper 私有目录；不借用宿主同名程序，不自动安装。缺件或隔离不成立就拒绝。详见[配置、结果和限制](docs/fat32-copy-check.md)。本批只写源码，尚无实跑证据。

exFAT 使用 `helper check-exfat-copy /绝对路径/volume.img --sha256 完整镜像的可信SHA256`。它只对 1–128 MiB、符合单卷边界的封存副本运行包内 `fsck.exfat -n`。返回 0 只表示此次检查未报告问题；1 表示明确报告问题或卷状态位须注意；2 表示未能确认。不会修盘，也不检查普通文件正文。[范围、结果与上游依据](docs/exfat-copy-check.md)。也可在终端按上述方式预选 exFAT，由配对页面确认同一项检查。

另有本机确认的 [`repair-exfat-copy`](docs/exfat-copy-check.md#只修新建的工作副本)：仅对新工作文件固定 `fsck.exfat -p`，再次只读检查后无覆盖发布。自动修复可能截短或删除工作副本里的损坏项，不改变输入、原盘或现有输出，不提供网页登录修复。

## 检查一份 ext4 保存副本（只读）

`helper check-ext4-copy /绝对路径/volume.img --sha256 完整副本的独立SHA256`。从用户明确选择的本地普通镜像检查，不打开原盘，也不把镜像拷入内存或限制为 128 MiB。需保持实际只读租约及原件；用隔离的 Debian 原版 `e2fsck -fn`。外部日志、需要恢复、截短或未完整检查都不报正常。也可用上面的配对面板确认同次只读检查；更长任务用终端命令。[完整边界与返回码](docs/ext4-copy-check.md)见专页。

另有分开的本机前台 [`repair-ext4-copy`](docs/ext4-copy-check.md#只修新建的工作副本)：可用 `web` 先请求原终端确认，但网页不运行修复、也不选输入或输出。只对新的工作副本固定用 `e2fsck -fp`，独立 `-fn` 复查后才发布新文件，不改输入或磁盘。

## 检查一份 XFS 保存副本（只读）

`helper check-xfs-copy /绝对路径/volume.img --sha256 可信SHA256`。只对独立单卷副本运行固定 `xfs_repair -n -f`，可在本机配对网页确认一次。没有外部日志、实时卷或修复选项；脏日志、额外诊断和工具不完整均不报正常。[实际边界](docs/xfs-copy-check.md)。

## 查看一份 NTFS 保存副本（有限只读）

`helper check-ntfs-copy /绝对路径/volume.img --sha256 可信SHA256`。包内 `ntfsfix -n` 仅观察独立单卷副本的有限 MFT/镜像记录和备用启动扇区；配对网页也可确认一次。未验证日志/Windows 休眠或正文完整性，不是 chkdsk，不修复、不打开原盘。[用法与结果](docs/ntfs-copy-check.md)。

## 检查一份 Btrfs 保存副本（只读、单设备）

`helper check-btrfs-copy /绝对路径/volume.img --sha256 可信SHA256`。固定上游 `btrfs check --readonly` 只对自包含的单设备完整原始副本做结构检查；也可通过配对面板确认。不会查宿主其他设备，不支持多设备、恢复或修复，也不证明普通文件或每份镜像无误。[用法与边界](docs/btrfs-copy-check.md)。

## 本机部署与离线维护（设计）

**首次建池：** 这是独立于只读诊断的离线写操作。[本机 `install-pool new|resume`](docs/sqlite-first-install.md) 只处理预先挂载、受保护且明确交付的 SYSTEM、独立回收卷和普通卷。不同的前台确认分别用于新建空池和续同一原单；不格式化、不清盘，不把未知残留作为可续状态。唯一 SYSTEM.sqlite3、各卷准确标记和最后活动回执需分别确认。建池不是设置两个账户、启用服务或保证登录。若只需检查原结果，用同样的原参数运行 `install-pool receipt`。它只读核原 SYSTEM，即使外卷暂不在也不会补标或同步。源代码尚未运行，更未进行真实设备验收。

**首次设置账户：** [本机 `setup-pair` 的前提、语法与返回值](docs/samba-domain.md#本机首设入口)。`provision --create-layout` 可明确只建立一个新的受保护实例目录与正式模板，不接管旧路径；随后另批 `provision` 为全新专实例生成并确认本地域；`enroll` 在同一原池一次建立唯一 Web 管理员和唯一 SMB 用户（使用不同口令）。Web 校验值只留 v11 SQLite，SMB 凭据只在专用原生账号库；两角色可分别在停机时重置。加 `--receipt-only` 只查原回执；明确的 `--resume` 只在原件与原阶段可核的适用情形继续，不询问已落盘目标的密码。当前没有已打包安装物、帐号登录或真实 Samba 访问的验收结果。

当前 Web 向导仅引导已有本机流程，不提供实际磁盘选择、服务配置应用或实时状态。后续完善 CLI，并按独立授权分批增加环境核对、卷设置和服务排错。磁盘初始化/加入、非空普通盘显式导入、永久退登记（不擦盘）均在 ZXS 停止后由 helper 自己完成，不调用 ZXS 程序或服务。它依赖双方一致的公开磁盘与账户契约，以及原 SYSTEM 上的真实排他租约，而不信任“服务已停”的字样。正常主动下线和故障离线仍由 ZXS 处理。两端均应显示系统及磁盘状态；helper 的运维视图还将列出候选盘与型号、容量/挂载、可取得的温度和设备错误、被动观测的速率，以及实际服务配置和有界脱敏日志；不测速，不用“服务在运行”或历史登记推断在线业务健康。无法核实则明确标出。

计划中的停机维护 CLI 还将按明确选择核查原池、卷和 FILE 容器，按原操作 ID 查询，只在另经授权并能核实原件时续作受支持的原维护操作。查询不自动修复；拿不到独占租约或认不出公开格式，不凭同名目录或旧命令输出猜测。日常 FILE 操作不放在维护 CLI：业务 Web 只管理，不收发文件正文；正文访问走 SMB。helper 自己的 Web 向导也不收发业务文件正文。

这些是[架构与交付门槛](ARCHITECTURE.md)，不属于上述已接命令的部分尚未交付。以上观察命令都不授予离线写权；目前的[本机面板](docs/disk-web.md)只读观察，并可引导终端安装；它没有安装执行器、systemctl 或 Web 修复操作。

## 独立开发

本目录有独立 Cargo 工程、Rust 工具链和[依赖来源记录](DEPENDENCIES.md)。允许验证时，入口为 `cargo build --locked` 和 `cargo test --locked`。后者的正向文件用例须在上述受支持文件系统上的专用临时位置创建自己的测试文件；如系统临时目录不满足，可由操作者设置 `HELPER_TEST_DATA_PARENT` 指向合格的专用目录。该变量仅供测试使用；先决条件缺失是测试失败，不算验证通过。

当前未执行 CLI、依赖解析、构建、测试或 CI，也未安装或操作实际介质。块设备 CLI 验收源码另需显式提供稳定试验设备号 `HELPER_TEST_BLOCK_DEV`，没有实际测试结果。独立构建和发行需要哪些输入与证据，见[交付核对表](RELEASE.md)；待办见[项目任务清单](TASKS.md)。
