# 离线跨 DATA 移动一个容器

[设计中] 供 Helper 和 ZXS 维护者审查。基线：`b471bfb2319fcd73adf35694604967c6b2eb8d08`。
开始或续作未完成的移动要求业务服务停机，且两块 DATA 都已登记和初始化。当前没有可用入口，也没有实盘验收。

## 请求与权限

拟用 `helper disk move CID OP_ID SOURCE_DATA TARGET_DATA SYSTEM RECYCLE DATA [DATA ...]`。
`CID` 和 `OP_ID` 各为非零的 32 位小写十六进制标识。续作时使用同一操作号和原操作参数。每次末尾都按登记顺序给出当前完整名册。

- 一次只移动一个活动容器。容器号、顺序、已存正文、分支、名称、标签及原业务回执不变。移动操作号不成为容器的新账本条目。
- 复用[原停机租约和原件约束](../invariants/offline-authority.md)。Helper 固定启动原受保护的 ZXS；双方核对同一配置、角色目录和活动挂载。复用原 EX、带凭据的本地顺序包和密封请求，不传可供任意打开的路径或正文 FD。
- 未完成操作只允许将两个操作路径映射到本次原名册中的不同 DATA 令牌。ZXS 持有 SYSTEM、RECYCLE 和这两块 DATA 的原目录及所需既有所有者锁；不接管替代盘、不初始化空盘。

## 开始前必须排除

- 原 SYSTEM 路由须恰好指向指定源 DATA。目标最终位置、候选路由和本次专用暂存必须正面证明可用；不接管仅凭名称或相同字节碰巧匹配的旧目标。
- 两个 DATA 令牌都不得有 `SYSTEM/retired-data/<token>` 或 `SYSTEM/retired-data/.<token>.incoming`。仍列在名册中不代表没有开始退盘；错型或不可读也不是缺失。
- 同一 `CID` 不得存在 `SYSTEM/upload-intents/<CID>`，也不能有 `.<CID>-0h.incoming` 的任何一个同容器待选槽（`h` 为 `0` 至 `f`，共 16 个）。准备态、旧口令纪元或无法证明缺失均拒绝，不迁移上传。见 [UR1](../../../zxs/docs/specs/resumable-uploads.md)，它在本基线尚无 HTTP 入口。
- 拒绝同一 `CID` 的 SYSTEM 已选回收记录、RECYCLE 到达信封（即使尚未选中）和未完成回收。仅在原命名空间遍历名字、读取受限的 `selector` / `ready` 元数据，不读回收正文。
- 回收暂存非空而无法证明归属、不合法或不可读时，不能推定与此操作无关。保留所有暂存，不完成别的操作；不需要搜索其他路径或物理盘。

移动不改写 [RC1/RC2 回收记录](../../../zxs/docs/specs/recycle-record.md)，不改登记目录、盘令牌或 `server.conf`。

## 单一路由、期望证据与互锁

`SYSTEM/container-routes/<CID>` 始终是唯一权威，其记录仍是 CR1。移动不增加第二套路由，也不改动[首次保存的选盘规则](../../../zxs/docs/specs/data-placement.md)。

- SYSTEM 侧 `data-relocations/<CID>-<OP_ID>/` 存放不可变的意图、就绪、已切换和完成记录，以下称 INTENT、READY、SWITCHED、DONE。它们只用于同号恢复和原件证明，不能为网络读写提供另一处选择。
- INTENT 绑定原池、原请求、源和目标稳定令牌、原 CR1 精确字节及原生身份、源容器与历史见证。写入意图前要在持有的父目录确认相关旧位置为空，按需同步这些原父目录后，再确认同样的缺失。
- 在停机 EX 内，于原状态目录独占发布 `.server-stage-move-<CID>-<OP_ID>`。确认私有原标记、内容及原生命名，先同步标记文件，再同步持有的状态父目录并复核。
- 互锁的有效出生须先于任何 DATA 暂存写入或路由替换。若中断时只有意图而尚无互锁，不得已有这些写入。不可只凭同名接管未证实的标记。

该池有待完成互锁时，现有其他离线入口及普通 ZXS 启动必须拒绝，且早于常规 Store 打开时的共享路由同步或暂存清理。
只允许明确的同号离线续作；不影响其他池，不加在线恢复、逐容器写入例外或后台清理。

## 复制、切换与重试

先完整核对源账本和原件形状。每项需有精确的序号和操作号；保存项只含所需 `receipt` 和 `payload`，纯元数据项只有 `receipt`。
遇到未知后代、别名、错误挂载、缺项、越界历史或不能确认的原件，必须在任何路由切换之前拒绝。

- 目标使用既有 `staging/` 内本操作专用的位置，避开普通清理识别的 16 位十六进制暂存名。只复制原容器的正文和账本，保留未能确认的暂存。
- 每份正文在正常复制时从原件读一次，边写边核对长度、EOF 和 SHA-256。同步已写文件和相关原目录，并严格复核目标整树与原历史相符。此路径不声称做了独立的物理介质读回。
- 保存原历史和每项原件的稳定证明，做法参考 RC2。源、目标与系统路由均需在每个切点复核当前持有的实际挂载；不把临时 `st_dev` 或挂载号写入持久证明。
- READY 绑定完整目标、原 CR1、新 CR1 的精确字节及其原生身份。新文件先在本操作的私有原件中写全并同步；记录已同步后，才可将这个已证实的原件无覆盖地放入原路由目录下的 `.<CID>.incoming`。同步持有的两个 SYSTEM 父目录，并复核候选仍为该原件。
- 目标树在目标 DATA 自身挂载内发布到 `data/<CID>`，不覆盖现存目录；同步原暂存父目录和目标父目录，核对到达的是同一完整原件。只用正常文件读写、目录同步和受控发布，不依赖 reflink 或 DATA 交换操作。
- 所有较慢的复核或交接完成后，再立即重钉 CR1 旧名与候选名，然后用 `renameat` 在同个持有的 SYSTEM 路由目录内原子替换。只有这一处改变路由；不要求 `RENAME_EXCHANGE`，没有复用其他路径的后备动作。
- 冷重开须用持久的 SYSTEM 原生原件证据（例如有效的 inode 和创建时刻），不能把重命名前的 ctime 当作改名后身份。证据不支持、同步有误、任何写入不确认时保留原件。

| 中断后所见 | 同一操作号允许的下一步 |
| --- | --- |
| 确认无有效互锁，尚未写入 DATA | 只能从确切原意图核对后建立互锁。目标或候选来源不明，保留并拒绝。 |
| 互锁有效，目标专用草稿尚未就绪；原 CR1 仍选源 | 只续可证明为本操作的准确前缀；不截断、不重用陌生材料。源仍保持完整。 |
| READY 已持久；目标仍在准确暂存或已到达原计划位置；原 CR1 仍选源 | 辨认真正到达的目标。冷续作失去活复制证据时，对恢复采用的目标正文作一次全量 SHA/EOF 核验；不自动重算全源或换目的盘。 |
| 旧 CR1 正是原记录，已证候选仍在 | 重证原件与发布前提，才可尝试同一替换。 |
| CR1 正是记录中的新目标原件，候选名确切缺失 | 核对目标和原意图，确认原路由目录同步，再重新证明原名和缺失，然后持久发布 SWITCHED。先前替换可见不等于可清理。 |
| 已持久 SWITCHED，源仍完整或已部分退休 | 只有目标被选中。冷续作若还需要清理原源，先对同一个已核目标作一次全量 SHA/EOF 核验，再逐项核对幸存源原件。 |
| 路由、候选、目标、互锁或证明混合、不符或未知 | 不补写或猜测选择，不回拨，不删除任何仍存源或未知目标。 |

同次调用已经建立的整份目标正文证明不因进入下一切点而重复全量哈希。来源不明的零散目标不会变成可恢复副本；没有撤销、强制清除、自动重新选盘或迁移其他操作的入口。

## 退休原件与完成回执

只有已持久 SWITCHED、原名册和原锁仍可证明、选中目标仍完整，才可开始退休源。使用已核目标的准确账本与保存的源证明，先检查**所有**仍存在的源项。
每个存活项仍须匹配原挂载、原目录和原文件。匹配之前不做任何删除；只有已切换确认后才允许先前正常清理造成的缺失。

- 每项按 `payload`、`receipt`、空项目录顺序删除，确认准确缺失并同步其原父目录。只删准确的原空容器目录，再同步其原 `data/` 父目录，不做递归清扫。
- 已证明源准确缺失且同步、目标路由和所选原件仍在后，才写并同步不可变 DONE，绑定这次已证互锁的原生身份和指纹；持久确认原目录及新建的相关父层。
- 有了已持久的 DONE，才可确认并删除这个操作原互锁，随后同步**原状态父目录**并重证准确缺失。不可先删互锁再写 DONE。
- 若互锁已删除但目录同步未确认，掉电可能使旧标记重现。之后同号凭准确 DONE 只删除匹配的原标记；若已缺失则重证缺失。两种情况均同步原状态父目录，不查旧源或哈希正文。

同号重放 DONE 是历史查询，不证明容器此刻仍在原目标。只用**当前**原名册和锁、同一原池以及确切保存的操作参数；旧源无需仍登记、挂载或可访问。
已保存的源/目标操作路径只作原输入比较，不据此打开旧路径。准确 DONE 不会触发再复制、再切路或再删源；同号参数不符不重新开始。

完整成功只能在匹配的本机工序回执、原子进程正常退出、无多余包且 Helper 重验原租约和原件后报告。只有准备或路由状态可见时，分开报告未确认的步骤。

## 待验

- 在隔离介质逐点中断：原互锁出生、目标数据或父目录同步、候选发布、原 CR1 替换、原路由目录同步、SWITCHED、每次源退休、DONE、互锁删除及父目录同步。
- 覆盖真实掉盘后同一原介质重挂、同字节不同 inode/出生时刻、错盘、已有目标、UR1、待退休 DT1、未选回收、外来后代及输出断开。
- 验证分支、所有历史版本和原回执不变、只改这一条 CR1；源退盘后同号仍只报告历史 DONE。只使用获准的隔离原件，不操作现有盘。

当前单容器[只读核验](../guides/offline-verify.md)不执行这些写入，也不确认移动是否曾持久完成。
