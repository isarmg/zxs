# 用 xfs_repair 只读检查 XFS 副本

准备一个**独立保存、未挂载、未用作 loop 后端且从 XFS 卷起点开始的普通文件**，另从可信记录取得全文件 SHA-256。不接受整物理盘、分区表、设备节点、容器镜像、其他日志/实时设备文件，或任何自定义上游选项。仅支持完整、单一数据卷并带内部日志的输入。

```sh
helper check-xfs-copy /绝对路径/volume.img --sha256 可信SHA256
helper disk-web --xfs-copy /绝对路径/volume.img --sha256 可信SHA256
```

第一条直接在非 root 的本机终端检查。第二条只预选，按[本机配对面板](disk-web.md#可选在网页上检查一个已保存的卷镜像)预览终端给出的摘要并确认一次；等待期间不打开镜像读取或取得租约。网页不给文件路径、格式或工具参数。配对后的十分钟限时包含剩余的指纹读取与工具检查；大镜像可能要用独立终端，后者在摘要核验后才开始上游工具自己的时限。

检查进程只持一个具名原件的普通只读 FD 和 Linux 读租约，全量顺序读取一次做 SHA-256，不复制或设 128 MiB 镜像上限。有写端、原件/原挂载变化、租约失效或不能核证则停止。保持租约至上游退出并回收、复核原件与 EOF；有写者请求时可能短暂阻挡它打开这份副本用于写，仅选明知闲置的副本。镜像的额外尾部只纳入摘要，不算 XFS 结构已检查。主超级块只用于核单卷范围及日志边界；所有元数据检查仍交给上游。

实际工具为 [Debian 13 amd64 xfsprogs 6.13.0-2+deb13u1](https://packages.debian.org/trixie/amd64/xfsprogs)，固定 `xfs_repair -n -f -P -t 0 -o phase2_threads=1 /image`：只读普通镜像、不预取、不输出定时进度、不接受外部日志或实时设备。没有 `-L`、强制、日志重放、挂载、修复或宿主同名工具兜底。隔离内的镜像与发行文件硬只读，不映射宿主设备、进程表、挂载表或系统配置。上游可能用匿名临时文件存放诊断元数据，限制在客体自己新建的 512 MiB tmpfs；不把宿主临时目录当后备，这也不是总进程内存或宿主禁换页的承诺。

上游实际尝试提高任何有限的文件大小软限额，因而只接受已继承无限该限额的普通进程，不替用户抬高限额。子进程实际使用一个已获原 CPU 遮罩允许的逻辑 CPU，仅需同进程线程路径，禁止产生新进程、离开组或回退无界 memfd。上游阶段预算是至多 10 分钟、300 秒 CPU、2 GiB 地址空间、64 KiB 全输出；较低继承限额仍有效，耗尽时未完成。不以 I/O 卡顿时的进程状态证明已收尾。

- **退出 0**：上游无修改检查的实际状态为 0，顺序、分配组报告、终行和真正 EOF 全符，未报告问题。阶段 5 是上游按设计不运行的写路径，不据此称全部检查或整个磁盘健康；不验证文件正文。
- **退出 2**：未完成或不能确认。包括外部日志、实时分区、脏或不可读日志、早退、缺包、环境或 I/O 失败、额外诊断、任何其它退出。上游 1 可能是结构问题也可能是运行错误；`-n` 有时会警告并越过脏日志，不能假定只有返回 2 才涉及日志。若得到实际回执，保留上游数值及镜像/文件系统字节数，不显示原始诊断或卷内文件名。

只交付源码，未构建、组包或运行。参见[准确 Debian 上游手册](https://manpages.debian.org/trixie/xfsprogs/xfs_repair.8.en.html)及[发行源码包](https://packages.debian.org/source/trixie/xfsprogs)中的 `repair/{init,xfs_repair,phase2}.c`、`libxfs/{init,xfile}.c`。
