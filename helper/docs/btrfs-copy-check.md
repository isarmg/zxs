# 已保存的 Btrfs 单设备卷：只读结构检查

在获准的非 root 本机终端，给一个独立、未挂载且未用作 loop 后端的普通本地文件及其独立可信的完整 SHA-256。这里的文件应是**实际只有一个存储设备的完整 Btrfs 卷的原始副本**，从该卷的零字节开始，不是整盘/分区表，不是单张多设备成员，不是 `btrfs-image` 元数据转储，也不是服务或虚拟机正在使用的文件。

```sh
helper check-btrfs-copy /绝对路径/volume.img --sha256 可信SHA256
helper disk-web --btrfs-copy /绝对路径/volume.img --sha256 可信SHA256
```

后一项只在[本机配对面板](disk-web.md#可选在网页上检查一个已保存的卷镜像)预览并确认本次选择。等待网页时只固定本机原文件、路径和挂载，不读内容或取租约；确认后从同一原件取读租约，验证一次完整 SHA-256 和真正的 EOF。检查后仍重核原名、挂载和元数据。不要用摘要替代副本来源核实；无法取得租约或正证则停止，不复制整卷或回退到宿主程序，不套用 FAT 的 128 MiB 封存上限。

本命令只调用 Debian 13 amd64 固定 **`btrfs check --readonly`**（btrfs-progs `6.14-1`）。主超级块须声明一个设备，整个声明范围应在副本内；原生检查还独立核对 chunk tree 中的设备数量。不改用备用超级块、不读取其他镜像文件，也不修复或恢复为可挂载。独立组和其他同 FSID 设备不暴露给程序：它只得到所选普通文件的硬只读投射 `/image` 与已核私有运行库，没有宿主设备、sysfs、procfs、udev 服务、网络或宿主配置。工具所读 `/proc/self/mounts` 是新客体中预先创建的只读空**普通文件**，只描述其中没有从这个镜像挂出的卷，不是宿主挂载表或空闲证明。检查不需要、也不注册 loop，不挂载所选 Btrfs 卷。

多设备组、seed/依赖 seed 的卷、元数据转储和需要真实设备分区带（zoned）几何的副本不是本命令支持的目标。标准 Btrfs 命令只接一个设备参数，寻找其余同 FSID 成员依赖系统块设备扫描；仅把几张普通文件放进隔离视图不会让它们成为已核实完整的一组。不提供多盘降级检查，不碰宿主的同 FSID 原件。不限制普通单设备的设备编号、DUP 或已完成变更的 metadata UUID；明确仍在变更 UUID、块组树或校验格式的副本不会报告成功。

| Helper 退出码 | 实际含义 |
| --- | --- |
| 0 | 原工具确实以 0 退出，所选副本的 UUID、预期的八个阶段和终场统计均对应，且没有其他诊断。只表示此次结构检查未报告问题。 |
| 2 | 未能确认检查完整：有其他诊断、缺阶段或终场、工具退出异常、权限/资源/租约与摘要或副本资格未满足。不据此断言原盘坏或正常。 |

Btrfs 可选用健康的元数据镜像，结果不能证明每份镜像都无误。此命令不验证文件正文，不重放日志，结构报告不等于完整文件校验或物理健康。`image_bytes` 是整份摘要范围，`device_bytes` 是原主超级块的声明范围；可能存在的尾部只计入摘要。不会回显原路径、FSID、卷内名称、工具原文或数据。网页的配对后十分钟也包含整份校验；时间更长请用终端，终端的上游阶段仍有十分钟、300 秒 CPU 和有界输出，不能保证阻塞的宿主 I/O 立即结束。

参见 [Debian btrfs-check(8)](https://manpages.debian.org/trixie/btrfs-progs/btrfs-check.8.en.html) 和 [上游 btrfs-check](https://btrfs.readthedocs.io/en/latest/btrfs-check.html)。发行依赖[独立核准确切 SHA-256 的私有材料](../packaging/debian13-amd64/README.md)；当前只完成源码和上游静态对读，未运行、组包或做设备验收。
