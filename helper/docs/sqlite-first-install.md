# 本机首次建池和续同一个 INIT

`helper install-pool` 是**有写入的离线工具**，不是只读磁盘面板的按钮。当前源码针对外部预先挂载、受保护且独立选定的本地卷。它不分区、格式化、挂载、擦盘、迁移既有目录或启动服务。只建立与同版业务端一致的唯一[已冻结数据库结构](../src/sqlite_install/schema.sql)，不识别、升级或双写此前的格式。建池完成后**仍没有账户或可登录的服务**。尚未构建、运行或做真机断电验收；请勿把本页当成实盘验证报告。

```text
helper install-pool new    --op ID --approval ID --system DIR --recycle DIR --data DIR [--data DIR ...]
helper install-pool resume --op ID --approval ID --system DIR --recycle DIR --data DIR [--data DIR ...]
```

- **new：只新建。** 本机管理员先独立确定全新的 SYSTEM、回收 R 和 1–62 个普通卷，包括 R 确实来自与 S 和所有普通卷独立的文件系统；路径或挂载 ID 本身不证明物理盘独立。每个目录是受保护宿主上的专用普通目录，由预定非 root 存储账号拥有，权限 0700；父链需可核，来源不明就拒绝。实际目录、祖先、名称容量、挂载、只读标志、已有旧属性或未知现物均核查。无法核查既有目录的旧标记不接手；不读旧值，不用 xattr 存新格式。不自动发现或占用非空卷。
- **resume：绝不建库。** 保存两个非秘密 ID（均为 32 位小写非零十六进制），使用**同一维护主体、审批参考、存储 UID、明确的原 S/R/F 与原操作**。必须独立核实当前接入的确是上次交付的原介质；整套卷与库被复制时，单靠 SQL/卷标不能证明哪套是原件。观察到已提交的准确原单只返历史回执，不重建已丢的标记，不证明当前健康。如有未归属或需恢复的 `-journal`、WAL、SHM、空/半库、损坏/外来标记或签发来源不明，不删、不代修、不重发新号。
- **谁能确认。** 需可信宿主上的本机 root 管理终端。固定的、受保护且 root 所有、无链接别名的 0600 普通 `/etc/local-ops-helper/installer.identity` 含一行 ASCII：`HOST-INSTALL-1 <32位小写非零十六进制维护ID> <十进制非root存储UID> <十进制非root存储GID>\n`。该文件应由可信宿主管理员预先设置；helper 不创建它，不保存口令或审批票。使用 [Linux 初始 PID、USER nsfs 身份](https://github.com/torvalds/linux/blob/v6.12/include/linux/proc_ns.h) 与真实 PID1 的挂载命名空间及根。三个标准流必须是该操作者同一前台控制终端，不接受其他继承描述符或后台/网页调用。完整列表及原申请摘要显示后，new 需输入 `INIT 摘要`，resume 须另输 `RESUME 摘要`；两个 ID、路径或服务停止都不是授权。随后永久降到已核的非 root 存储身份、清补充组及能力，才允许建库/写卷标。
- **互斥及结果。** 以独立打开的原目录描述符按固定次序取齐全部非阻塞 EX，S 的那一把贯穿所有 SQLite 连接与操作末端；不同进程不能借同一 OFD。锁要求所有参与者遵守，不能抵抗能任意替换整个受保护宿主的第三方。SQLite 始终使用固定 Unix VFS，核实际引擎/禁 WAL/扩展，S 路径必须无损 UTF‑8 且数据库和回滚日志名能容纳；R/F 保留原路径字节。仅 OS 可独占预留 0600 新空库，文件和父目录同步并关闭 raw FD 后，SQLite 才只用精确原名开户，**不用 CREATE**。不在打开 SQLite 的同时裸开关其数据库 inode。
- **先库后标，再确认。** 第一笔短事务保存原待认领结果及整组卷行；先由真正的只读连接按完整[规范 DDL](../src/sqlite_install/schema.sql)、原请求与各行核实，再关库做磁盘标记。先核 *全部* 指定根；已有正确标记只重同步，没有的用固定名称独占创建。逐个核实际 101 字节、EOF、原 inode、文件与原父同步、独立具名读回。只有整组已核才重开既有库，以短事务再取同一原单和全表后条件提交 0→1，最终再次只读查证。每次补标前再核原 DB 与 S 清单；最后 UPDATE 紧前从原描述符完整枚举 S/R/F，COMMIT 前再次完整枚举 R/F 并核 S 两件原物及意外名称。只有原进程的 SQLite 在其短事务内管理自己的临时回滚日志；不按日志名字授予归属，不打开或手动删除。关库后 S 必须重新仅有数据库及原标。失败或 COMMIT 结果不明保留现场，不能用新号代原单；若 SQL 已提交而末端检测报错，不能承诺它仍然待办。

| 中断位置 | 当前严格的续作语义（不是实测） |
|---|---|
| 空库预留，尚无已提交完整 INIT | 资料不足；两种命令均不接管这个现有空库。 |
| 待办已提交，零个或只有连续前几项准确卷标 | resume 重新核原 S/全组，重同步准确标，然后只补缺失项。 |
| 只有半个标、标有空洞或意外日志 | 保留失败现场，不覆盖、不删除、不猜。 |
| 全部标可见，最后 SQL 未提交或回执丢失 | 原 INIT 仍待决则全组重同步/复读才完成。若原 SQL 已提交，仅返回历史，不补标、不启动服务。 |

两个真实登录需要独立授权的 Web 管理员/专用 SMB 账户首设和各自网络适配；这两个动作均不属于本命令。

Web 侧另有内部凭据准备源码：仅接受 1–1024 个有效 UTF-8 字节，调用 [RustCrypto Argon2](https://docs.rs/argon2/0.5.3/argon2/) 按 Argon2id v19、64 MiB、3 次、4 lanes、16 字节新随机盐生成 32 字节验证值。它不处理 SMB 口令、不写账号，也不是会话证明。已知输入、显式工作区和结果按作用期清除；尚无公开账户命令或真实口令采集；受管 Samba 原域和专用首设审批不能由账号名、裸 SID、哈希或操作号代替。没有在本次编写中调用算法或采集密码。

内部的前台输入适配只读取既有的同一前台控制终端，不收网页、路径、参数、环境或管道中的口令。先在同一宿主任务降权前仅查询固定 Linux [AUDIT_TTY_GET](https://github.com/torvalds/linux/blob/v6.12/kernel/audit.c#L1408-L1416)；不能证实本任务的 TTY 审计及记录口令两项均未开启即拒绝，不更改审计策略。该结果只在同一 PID/线程内短时有效，不覆盖管理员、终端主端或外部录屏。随后要求独立的已降权单线程进程，禁进程转储、拒已被追踪的进程、以 Linux `mlockall(CURRENT|FUTURE)` 锁本进程内存；锁页失败不放行；这不替后续 KDF 预留 64 MiB，实际受控发行须在询问前保证其预算。四次提示共用一次经回读的无回显设置；每项丢弃提前输入，再通过初选前台原终端的独立非阻塞写描述符发送固定提示，不改变宿主标准流的模式。选定的是实际从端或虚拟控制台，不认泛指当前终端的 /dev/tty 别名。分别输入并核对两遍不同的 Web/SMB 口令。每次最多 1024 个 UTF-8 字节，两分钟期限包含发送提示；退格编辑，不截断、去空格或做 Unicode 归一化。ASCII 控制字符不能作为此交互通道的口令内容。中止、超时、终端改变或普通取消信号时先清队列和还原设置；失去终端、SIGKILL、SIGSTOP、异常崩溃或内核停机不能保证恢复。要求受信且未录制的本地控制台及无泄露的审核、休眠/内核转储策略；只检查回显和进程锁页不证明宿主满足这些条件。未来接线必须**先核授权及原回执，已提交时绝不再问密码**，也不借用带读前缓存的非秘密确认输入。未在本轮读任何真实输入或操作终端。
