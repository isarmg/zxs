# 停机首次建池：目前只写到数据库待认领

这不是现成安装命令。当前所写的内部链从一次本机前台确认开始，止于 SQLite 已提交且复读的待认领 INIT。此时没有活动存储池、磁盘卷标、可登录的 Web 管理员或 SMB 用户，亦没有可从 Web 或 CLI 调用的建池入口。打包配对的诊断 Web 不能授这种权。

一次可信的宿主本机管理会话先持有明确选定的原目录，显示 S、专用回收 R、排序后的普通卷、原操作/审批参考和完整申请摘要。要求本机管理员实际使用同一前台控制终端确认原单；路径按字节转义。固定的、由 root 管理的 `/etc/local-ops-helper/installer.identity` 只含已登记的维护主体和专用非 root 的存储 UID/GID，格式为一行 ASCII：`HOST-INSTALL-1 <32位小写非零十六进制维护ID> <十进制UID> <十进制GID>\n`。文件须普通、无链接别名、0600；它不保存密码、每操作投票、状态或卷标。普通存储账号、操作ID、服务状态、复制的审批参考或 Web 会话不能替代操作者现场确认。现在不在系统上创建这个文件。

开始时以真正 nsfs 上的 Linux [初始 PID/USER 命名空间号](https://github.com/torvalds/linux/blob/v6.12/include/linux/proc_ns.h)识别宿主，再核与宿主 PID 1 同一挂载命名空间及根；两个同属隔离环境的进程自相匹配不够。采用受信任的本机安装文件。请求只针对妥善安装、预先挂载、受权限保护的全新空目录；操作者必须另外确认独立 R 的真实部署及可靠本机锁/同步。仅见另一设备号不是物理拓扑证明。诊断员不自动发现/挂载/格式化，不能把未知旧件说成空。privileged 阶段只持有 O_PATH 原物；新 CLI 在受限检查后永久放弃本机 root 和补充组，以受保护 profile 的非 root 身份继续。两个参与者独立 open 原 S；此动作只锁自己的原 S 一次，连同其他根按固定次序一起非阻塞 EX 至关库。目录被替换、含其他物料或回收不足以独立均拒绝。对这些既有空目录及其真实祖先，若读到旧 `user.zxs.volume` 存在（包括零长度），或不能检查，绝不认领。这个否决不读取、写入或迁移旧值，不是新格式的身份或数据库需求；不能观察既有目录来历时，当前首次准入暂不支持。

- **原生开户：** 实际 SQLite 3.54.1 源 ID、OMIT_WAL、OMIT_LOAD_EXTENSION 和实际标准 Unix VFS 上限先核。规范 S 路径必须无损 UTF-8 且 DB 与回滚日志含 NUL 均可表达；R/F 保留原始 Unix 字节。所有根真实保护、原实体/挂载和名称预算均需核；未知不能降级。
- **第一个持久物：** 只有 OS 可 O_EXCL 建立固定 0600 空 `SYSTEM.sqlite3`。同步这个文件和原 S 目录，关闭原 DB 描述符，SQLite 才按唯一路径显式 READWRITE/NOFOLLOW/非 CREATE 开户。连接存活期间只对具名 DB 作不打开文件的 statx 和 SQLite 自身 HAS_MOVED 检查。不会用额外 raw FD 或 SQLite 数据库 inode 的 flock 代替原 S 生命周期锁。
- **第一笔事务：** 固定规范 DDL、原待办和所有初始卷行一次提交，保存一次性的池/卷 ID 与卷认领标识。只在新的短事务完整复读原字段、确认真状态为 0、SQLite 已关闭后，才能给“数据库待认领”内部回执。失败/提交不明不删库或侧件，不回滚外部目录、不用新 ID 重来。
- **下一步：** 同单冷开、每个卷标的无覆盖同步/完整复核与最后 SQL 活动回执另交付。完成 INIT 后，仍须一笔独立授权的两账户首设。一个 Web 管理员和一个专用 SMB 用户分角色、分凭据；不使用两档权限或多账号兼容，不开放 guest/匿名。其真实登录、密码重置、断电及跨实现验收均未完成。

[本工程内固定的公开 DDL](../src/sqlite_install/schema.sql)、[原 INIT 读视图](../src/sqlite_install/initial-catalog.sql)保持逐字节相同的已审接口，不引用兄弟源码/构建目录，不自创表。源码用例标出真实原 S 的独立 SH/EX、原空库不覆盖、异物、限定文件系统测试父，以及待办不产生卷标/账户；本轮没有运行这些用例或组件。
