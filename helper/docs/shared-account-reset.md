# 共用账户：离线重置及原单回执

默认构建不接受此命令。私有 `private-fresh-install` 候选只接受确切 v20 的原部署，不迁移或修复旧格式，不更改用户名或业务记录，不启动或停止服务。ZXS 必须已经完全退出：Helper 要独立拿到原 SYSTEM 和实例的排他租约，再核原 INIT、原库、卷标、站点及实际原凭据版本。只由 `/zxs/state/deployment.v1` 定位原受保护实例，使用它保存的单 ELF 路径与完整 SHA-256；没有旧路径回退，也没有新的路径或摘要覆盖参数。

```text
helper reset-account new --op ID --approval ID --previous ID --previous-generation N --helper-sha256 HEX --gcrypt-sha256 HEX --gpgerror-sha256 HEX
helper reset-account receipt --op ID --approval ID --previous ID --previous-generation N --helper-sha256 HEX
```

- **new：只发新原单。** 信任实际宿主与前台终端，核同一原账号/用户名、当前共用代次、完整旧 vault 和受保护的原件；如果有影响旧代次的未闭合文件或目录出生，或无法在界限内确认，停止。一次批准同时确认 Web 和 SMB 的同一个后继；仅输入一次新口令并复输。同一个降权写者派生独立验证材料。未取得原件、工作进程与受保护内存的确证时不询问口令、不分配暂存。
- **PENDING 和完成。** 原低权写者先退出并由父进程核同一暂存、文件及父目录同步。原 SQLite 事务只为这一个账号记录单一待决后继；这时两个入口都不回退到旧代次。只有同一个暂存真正成为原 `credential.v2` 且核回，同一个低权 SQL 作业才可提交共用新代次；完成后另读回原 S 与原具名文件。本机 root 只核 vault 的公开前缀和描述符，不读密钥；Web 不接触 SMB 密钥，口令不经参数、日志、数据库、普通文件或进程间消息。
- **receipt：只查原单。** 查询同一操作、批准和前序，不询问口令、不打开 vault 或凭据提供者、也不写数据库或凭据。可能返回曾确认、尚未确认或未能确定；不判断当前口令，也不为重试背书。SQLite 与文件系统仍可能有正常读取时间记账。
- **中断或回执丢失。** 保留原 ID、原名和所有未知暂存；只查询同一原单，不自动继续、删除、回退或重发。若待决前已经留下未知暂存，不能保证旧代次仍可启动。若待决已持久化，新旧客户端都不能绕过同一共用门。本候选未提供中断恢复或实地验收。
