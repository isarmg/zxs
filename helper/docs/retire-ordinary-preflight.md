# H04：普通数据卷永久退登记的只读预检

这是 Native v16 的本机只读预检，不是退登记命令、Web 按钮或实际可物理移除的证明。它不撤权、不迁移、不擦盘、不移走数据、不卸载、不启动或停止服务，也不写 SYSTEM。只认正式 Native v16 的确切库格式，不接未定 ADD、新版或旧格式，历史 INIT 不是退盘凭据。源码尚未运行或进行实际卷验收。

## 入口与结果

`helper check-ordinary-retirement --system DIR --pool ID --init INIT_OP --volume VOLUME_ID --data DIR`。两个目录均为明确的绝对原名，三个 ID 均为 32 位非零小写十六进制。只在本机受信管理员前台、现有受保护维护配置与同一已安装 Helper 原件下使用；若在线参与者仍持原 S，检查无法凭 systemd 或终端文字绕过排他。无 `--apply`、`--force`、继续、查询退盘回执或浏览器模式。

退出码 0 表示「本次未见阻挡」，1 表示有已核挡项或保护角色，2 表示核验未确认（例如忙、读不完整或原件不匹配）。这些结果都没有实际退登记、写入、清除或卸载。不能把 0 当作取走磁盘的条件。前台只持原 S 的实际独占描述符，既有只读工人永久降权后才看数据库及明确选择的 F，并在仍持同一原 F 时发有界的本次事实。前台以真实子进程正常退出及确切 EOF 为条件收取该结果，不读库、不看账户、不取回数据卷描述符；结果显示时已经是快照，不再持锁。

## 可核的事实

- 已认证低权维护参与者持原 SYSTEM 非阻塞 EX 与被动实体链；占有另一个模式的锁或看见服务已停不算。只开现有 Unix VFS 只读连接：同一原库/原 SYSTEM 标、应用与格式号和逐项 schema、已确认 INIT 原申请摘要完整复核。操作范围必须明确给出同一个池、原 INIT、原普通 VolumeId、S 路径和 F 精确原始路径。SYSTEM 与唯一回收卷直接拒绝为目标，其他路径无法从 SQL 自动变为打开许可。
- v16 的实际卷引用来自发布、当前 FILE 位置、FILE 出生、普通目录出生（含其原生命名链）、FILE 改名、跨卷操作的源和目标。另报告正在排队的转移、已确认但仍待清的移交源、以及标记为不可证明的清理。只有在有界切面读全规范表、无断开的外键及缺原业务锚时，才接受负面结论；超出每张表 2048 行或资料不确定均不放行。此门不是数据库一致性或整盘健康诊断。
- 仅明确选的普通 F 可打开数据根目录 FD。被动查其他已登记的名称与同物/祖先别名，不读其内容、卷标或加锁；无法核实或与唯一 R 当前挂载归属无法区分时保守拒绝，不自动挂载。F 真正同挂载/目录身份、祖先、已登记分量上限及 101 字节原标在两次检查一致，S 的原只读锚和真实锁一直持有。空的窄定义是只见固定原标并独立读到真目录末尾；任何额外名字（包括容器、空目录、暂存或未知项）都是阻挡，不读取或输出其正文或名称。
- 只返回该次检查所见状态，不签发旧单或新单、没有可重用的许可。连最后一个普通根也不能呈为无阻碍候选。原标与命名证据不是硬件序号，不能识别复制了完整原物后首次冷呈现的副本。

## 目前不能证明的事

正式 v16 没有取消已发布共享或退登记状态；Disabled、盘离线、历史位置已移动、屏幕显示空、旧清理状态为完成，都不能证明已无登记责任。第一切片故意只对**从未发布且没有已知业务历史或残留**的原普通根，以不超界的完整核对报告「本次未见阻挡」。有历史即单列事实，不标成活动写，也不推断数据一定仍在。实际何时可按已核历史解除责任、如何保全原 ID、位置和历史而撤销有效名册、独立授权与掉电回执、以及如何安全覆盖大池，须另定两端契约。没有新增库格式、配置、写入入口或 ADD 能力；未执行源码例或接触真实介质。
