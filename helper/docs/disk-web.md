# 本机磁盘面板

获准运行时，普通 Linux 用户可在自己的前台终端输入 `helper disk-web`。打开终端给出的 **`http://127.0.0.1:随机端口/`**，在页面中输入一次性配对码。没有默认端口、后台安装、启动时扫描或局域网地址；不把码放在链接、命令行、环境或日志里。当前只有源码；没有启动面板或做浏览器验收。

| 面板按钮 | 实际会做什么 |
| --- | --- |
| 查看设备与挂载 | 和 `disks` 使用同一宿主读取。显示块层容量、整盘/分区和父盘、可核型号、内核设备号、缓存 FS UUID/PARTUUID、当前直接匹配的挂载 ID。它们是不同的标识，不是健康或归属证明。 |
| 读取本次 I/O 速率 | 只在点击后对同一实例采两次内核计数。显示实际间隔、读和写 B/s；不产生测试流量。实例更换/计数下降/样本缺失为未知，不把整盘和分区相加。 |
| 核对工具安装位置 | 从 `fs-tools` 的七项类型化清单读取每个固定槽的安装元数据。区分随包配方和宿主观察，不因位置存在而认定版本匹配、验签或开始检查。OpenZFS 不加载模块、不调用 `zpool`。 |

### 首次安装向导：本机命令与原回执

配对后点“打开首次安装向导”。它一次只核固定包内的 **5 份公共材料**（初始 Samba 配置、SMB 预检脚本及模板、原生管理 HTTP 的可选单元及其生成脚本），比较已选普通文件的完整字节与这份正在运行的 helper 内置版本。只比较模板，不验发行签名，不扫描块设备，不读取池、真实站点配置、凭据、证书私钥、服务日志或现场安装状态；未能核对或不一致分别显示。没有外部请求、后台刷新或自动推进。

按照页面按段复制命令，使用**另外一个本机终端**。变量须先以真实非秘密值设定，缺值则不会执行。别把恢复号、秘密或终端回执输入页面。需要 root 前台的阶段须分别获得真实宿主授权：

1. 普通用户先做存储根观察；新根真正符合条件后，另在 root 前台 [建原 INIT](sqlite-first-install.md)。保留原池 ID、原 INIT 和原请求；重复或中断都不换号重建。
2. 在合格布局尚未存在时可单独批准新布局，再单独批准 [专用域供给](samba-domain.md)，保存 `domain-binding=confirmed` 回执的 `bound_sha256=`。只有真正完成持久同步与读回才打印该摘要，不读取替代的同名文件。
3. 同一原池和同一原实例 [首次设置两账户](samba-domain.md#本机首设入口)。在真正前台无回显输入两种不同口令，首次设置不在浏览器中完成。加 `--receipt-only` 只在终端核原单，区分确认、缺失/待办和未能确认。
4. 只用来源独立验签、与本池数据库及唯一 SMB 计划配套的在线发行物。初装的原回执同时确认各已选普通目录的初始许可，不需在 Web 再开；配置已准备、程序在监听、客户可登录分别验明。管理员可用 [`/usr/bin/helper start-smb`](smb-host.md) 启动原配套实例，只接受本机前台明确确认；不使用旧回环模板或预检结果替代。
5. 用登记的普通存储身份在独立终端[启动验签的原生管理 HTTP 版 ZXS](management-http.md)，或生成单一可选 systemd 候选、另行复核安装。业务管理监听所有 IPv4 的 8443，无需域名或证书；只在可信网络直连明文，HTTPS 可由外部软件提供。真正管理页与本机配对页是两个入口。

浏览器既不提交参数、写入、回执或状态，也不调用终端、磁盘工具、生成器、systemd 或启动服务来完成这五步。页面的“与内置模板一致”和“未能核对”只针对观察当下，不用于推断原池持久状态。源码未部署或运行。

### 可选：由同机浏览器发起原 INIT 前台确认

不同于上面的只读向导，可在可信本机 root 前台选择已了解的普通根，以 `/usr/bin/helper install-pool web new` 或 `/usr/bin/helper install-pool web resume` 加上原 [INIT 的同样参数](sqlite-first-install.md) 启动这一页。先选择相同的 SYSTEM、独立回收和本次数据根；没有设备扫描，也不会让网页拿到原路径。`resume` 须仍为准确原单、原选择与原审批。

1. 打开此前台打印的独立 `http://127.0.0.1:随机端口/`，在两分钟内用一次性代码配对。页面只显示新建或原单续作、SYSTEM/回收存在于所选范围及所选数据根数，不读原库、内容、设备或管理员口令。原句柄仅用来守住终端选择，等待阶段不领卷锁。
2. “请求在原终端确认”仅提交这次配对的 90 秒预览票，不可重放；关闭、超时、会话不符或未知都不写入。网页的“已交回”只是请求。全页最长八分钟，从开启此页算，不延长。
3. 原程序先关监听、确认自己的原隔离非 root 工人正常退出、结果通道收完，再在同一已核本机前台展示全部准确原件与原申请摘要，清除已排队输入并当场发出一次性确认码。只有终端批准且真正原件仍相同，才走与原 CLI 一样的降权、原锁、实际初始写入、同步及 SQL 确认。若没有终端确认，不会写；若实际写阶段丢回执，按原单查询，不要换新号。文件、批准、回执与口令不经过浏览器。

当前这条真实 Web 路径只到原 INIT，不是全流程 Web 安装。域供给、两账户设置和启动仍单独处理；不自动启任何服务或共享，不使用普通磁盘面板授权写。网页工人不持卷描述符，并由原 Linux 文件/网络隔离限制为已开的一只 loopback listener；不支持该隔离时可继续使用原终端流程。只有源码，未运行或做任何磁盘/浏览器验收。

### 可选：在网页上检查一个已保存的卷镜像

只从本机终端选一种格式、一份普通单卷镜像和来自其他可信来源的完整 SHA-256：

```sh
helper disk-web --fat32-copy /绝对路径/fat32.img --sha256 可信SHA256
helper disk-web --exfat-copy /绝对路径/exfat.img --sha256 可信SHA256
helper disk-web --ext4-copy /绝对路径/ext4.img --sha256 可信SHA256
helper disk-web --xfs-copy /绝对路径/xfs.img --sha256 可信SHA256
helper disk-web --ntfs-copy /绝对路径/ntfs.img --sha256 可信SHA256
helper disk-web --btrfs-copy /绝对路径/btrfs.img --sha256 可信SHA256
```

这是操作者**只授权本次面板检查这一份副本**的选择。IMAGE 和 SHA 是操作者本机命令行参数，可能出现在 shell 历史或按宿主策略可读的进程参数中；不用它们代替会话票。默认 `disk-web` 不读取镜像，普通配对也不能补发此授权。

[FAT32](fat32-copy-check.md) 和 [exFAT](exfat-copy-check.md) 启动时读取这份普通文件，制作不可执行、不可写的独立内存副本并核完整摘要。对于 [ext4（ext2/3/4 家族）](ext4-copy-check.md)、[XFS](xfs-copy-check.md)、[NTFS](ntfs-copy-check.md) 和 [Btrfs 单设备](btrfs-copy-check.md)，启动时只确认选中的普通镜像文件、原挂载和元数据，不读镜像内容、不取读租约、不复制；这个引用可能暂时阻止正常卸载该挂载。预览中的这些摘要是终端给出的**预期值**，不是验证结论。

1. 配对后点“预览终端已选镜像”，核对所选格式、预期 SHA-256 与字节数。两种 FAT 副本另显示各自的扇区和簇/表信息；ext4/XFS/NTFS/Btrfs 尚未读内容，不猜扇区。确认票 90 秒有效；网页不接收格式选择、文件路径、上传、设备号或工具参数。
2. 点“确认：只读检查这份副本”。服务端先认领本票。独立工作进程重新核两种 FAT 的封印和摘要，运行固定的 `fsck.fat -n` 或 `fsck.exfat -n`。ext4/XFS/NTFS/Btrfs 在认领后才打开终端原件的只读 FD，由子进程持读租约、只核一次全 SHA-256，并运行同版固定 `e2fsck -fn`、`xfs_repair -n -f`、`ntfsfix -n` 或 `btrfs check --readonly`。这些检查不封存整镜像；配对后的十分钟包含剩余的摘要核验与工具检查，不延长，长任务请用各自终端命令。原件变化、其他写入者或租约失败时拒绝，不能切换副本或强制继续。重复确认不会启动第二次。
3. 点“查看同次结果”。只显示类别和数值，不显示卷内文件名、工具原文或文件内容。ext4 区分本次未报告问题、报告未修复问题但不能确认全程、未能确认完整检查；XFS 不把上游 1 或日志警告当已完成。NTFS 仅观察部分 MFT/镜像及备用启动扇区，无法证明日志、Windows 休眠或完整性。Btrfs 只核单设备的结构，可观察已写的日志树，不重放日志，也不验证文件内容或所有元数据镜像。租约检查都区分镜像大小与卷范围。ext4 或 XFS 的外部日志和已知待恢复状态、工具不可用、额外诊断或回执残缺均不能得到相应的正面结论。任何成功陈述都不是实盘健康或文件正文验证。浏览器提交后断线时，可在同一仍配对页面查询；刷新或启动新进程不能找回旧结果。

工作进程必须是受保护 `/usr/bin/helper` 中与本次运行相同的原 ELF；没有 PATH 或不同安装回退。子进程只继承此副本描述符和专用结果/错误管道，不接收镜像路径、配对凭据或监听套接字。上游工具的隔离不含宿主设备或其他目录；两种 FAT 工具看到封存副本，e2fsck、xfs_repair、ntfsfix 和 btrfs check 只收到该保存副本的只读投射；XFS 另有自己的有界临时区，不给宿主目录。父进程接完原结果并确认子进程实际退出后，仍要复核 ext4/XFS/NTFS/Btrfs 原名、挂载和文件元数据。关闭应答只表示不再接受请求；关闭监听后，若仍有工作进程则发送 TERM 并等它收尾。不以浏览器回复、强杀或内核 I/O 停顿时的进程状态作完整回收证据。升级时先关闭面板并等检查收尾。不会启动 ZXS、加载模块、检查原设备或修盘；本操作未构建、运行或做实机验收。

配对仅一用，2 分钟有效；失败六次关闭。已配对会话最多 10 分钟、程序全程最多 512 次本机连接。刷新页面、关页不会找回凭据；“结束会话”关闭监听，或直接从终端结束进程。网页不写 cookie、本地存储或请求日志。凭据仅留在本标签页内存；每次观察都校验同一回环地址/端口、精确 Origin、会话授权和单独的 CSRF 值。不接反向代理、不提供 CORS 或可嵌入框架。

配对码只发到进程已有的标准错误终端：接受已核定的 Linux 虚拟控制台、devpts 从终端或当前 TTY 设备；需与操作者同会话、同前台进程组。后台、重定向、其它会话、伪终端主端或不能确认的终端拒绝，无其他输出回退。必须是有控制终端的受限本机普通单线程进程（非 root，实际 UID/GID 一致，没有额外宿主组、可继承或有效能力，禁止取得新特权）。账户不符合时拒绝，**不要用 sudo 运行**。信任操作者终端、本机内核和当前浏览器；不防已控制同一账户/终端的进程。HTTP 只用于本机回环，不构成对外公开部署方案。

### 可选：由同机浏览器发起工作副本的终端确认

这不是普通只读 `disk-web` 的附加权限。仍在非 root 本机前台选一种固定复修、它的独立普通卷镜像（未挂载且未作 loop 后端）、完整外部 SHA-256 及尚不存在的输出目录。以下三种只选与镜像相应的一个：

```text
helper repair-ext4-copy web /绝对路径/input.img --sha256 可信的完整SHA256 --output /绝对路径/未占用的新目录
helper repair-exfat-copy web /绝对路径/input.img --sha256 可信的完整SHA256 --output /绝对路径/未占用的新目录
helper repair-fat32-copy web /绝对路径/input.img --sha256 可信的完整SHA256 --output /绝对路径/未占用的新目录
```

1. 打开此命令打印的单独回环页面，两分钟内配对。页面只看终端预选的格式与字节数，不接收格式选择、路径、上传、设备号、工具选项或密码。等待期间不读取镜像内容、不取读租约、不创建输出；仅持实际选件，可能阻挡正常卸载。原隔离的非 root 页面不持任何卷、文件正文、输出父目录或前台终端描述符。
2. 90 秒预览票只可请求原前台显示确认，一次请求后网页关闭。网页寿命最多八分钟、最多接收 256 个本机请求。发送回执不等于确认或开始；关闭、超时和未回传均不自动续作。如果浏览器没有收到回复，先看原终端，不另发请求。
3. 原进程核同一工人已关监听、真正退出且原通道 EOF 后，在同一前台显示真实输入、可信摘要与输出，再发新的终端确认码。只有批准且原件仍相同才按固定的 [ext](ext4-copy-check.md#只修新建的工作副本)、[exFAT](exfat-copy-check.md#只修新建的工作副本) 或 [FAT32](fat32-copy-check.md#只修新建的工作副本) 流程运行。只在新文件上修复和复查，不改原镜像或原盘。结果、新工作目录或失败提示只在终端。没有可用的页面隔离时，可独立使用原终端命令，不会自动降级。

自动修复可能丢弃工作副本中的受损内容，不替代备份。三个选项均仅有源码，尚未运行或部署；浏览器操作不代替实际原件和输出核查。

### 待运行验收

在独立 Debian 13 amd64 验收机上使用已验证的已安装发行物、受限普通用户和独立准备的 FAT32、exFAT、ext4、XFS、NTFS、Btrfs 测试卷镜像：
- 不预选、非固定安装或非前台终端不能取得检查授权；无参数面板仍可观察。两种 FAT 的错摘要、超限不进入预览；ext4/XFS/NTFS/Btrfs 错摘要只能得到未确认结果，且不得调用检查器。
- 两种 FAT 封存后替换原路径仍按原封存摘要检查。ext4/XFS/NTFS/Btrfs 等待配对或预览期间不会阻止打开自有夹具用于写入；持有写端、确认前换件/改动，或检查后核不到原名都不能得到成功。另一会话、跨源、缺凭据、伪票、过期未使用的票均不能启动。
- 同票双击/模拟浏览器断开后再查询：最多一项上游检查，类别与对应 CLI 相同；没有确认的统计不补 0。用大于 128 MiB 的 ext4/XFS/NTFS/Btrfs 副本验证预览无内存封存，完整结果区分镜像大小和文件系统范围。缺依赖、已更换安装、子进程信号或输出残缺无任何“未报告问题”回执。页面和回执不传原路径、工具原文或卷内文件名。
- 用三种各自的工作副本单独验证网页只显示终端预选的格式、无法切换格式或提交工具参数，且无新鲜终端确认不写入。验证普通结束、终端发出中止及请求已送出但应答丢失的实际状态；不把没有收到浏览器回复当作已取消或已成功。清理未证实时不得据以升级私有工具包。

另有专用隔离机用的[配对与同票验收脚本源码](../tests/disk_web/exfat_roundtrip.py)，只取两项显式 clean 夹具环境变量，覆盖实际配对、跨源/错票拒绝、预览不会启动、查看与重复确认取同一回执及原文件未变；本次未运行。

核对点见 [Linux 非可执行 memfd](https://docs.kernel.org/userspace-api/mfd_noexec.html) 和 [父进程退出信号](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)。
