# 不留配置地找现有 ZXS 池候选

`helper discover` 是一次本机只读查询，没有常驻进程、不访问服务管理器，也不读取或保存 Helper 配置、历史、上次选择或缓存。可以在旧部署已运行时查询。它不重装、不自动初始化，也不把候选路径交给停机维护命令。

不传参数时，只从当前进程的真实 Linux 挂载表筛选最多 **64** 个本地整文件系统挂载根，不递归找目录。网络、伪文件系统或自动挂载不作为存储候选，其已知子链也不访问；不将 bind 子树或 Btrfs 子卷当整根自动发现。原 SYSTEM 如果是挂载里的子目录、不在可见挂载中或没有读取权限，自动查询可能完全看不到它。只在现场知道原目录时，明确选择本次的一处路径：

```sh
helper discover --system /mnt/control/pool
```

两种方式都要求本机真实 procfs 和逐级核对的本地挂载。只按已知唯一的本地挂载转换查内核缓存，不为发现唤起自动挂载；缓存未命中、路径跨入未登记挂载、叠挂或身份不符都不重试。这里只在可核的本地路径上查询，不能证明底层设备没有使用网络，也不承诺抵御宿主管理员并发换挂载；观察不是原子快照。上限限制记录、路径和读取字节，不承诺本地内核 I/O 的耗时。

查询只在已挂载、符合本地文件系统规则、具有非 root 所有者的私有目录上尝试固定证据：原 ZXS 卷标的 101 字节、同目录同挂载私有 `SYSTEM.sqlite3` 的元数据。卷标从持有的原件以只读且不更新 atime 的方式读取；数据库只保有临时 `O_PATH` 元数据句柄，不打开其正文或任何日志，不枚举目录正文，不查询账户或口令，也不选任何 F/R。`historical_init` 来自卷标，不是已核实的提交回执。路径输出转义，仅用于让人在本次会话辨认；不会作为权限或受信配置重用。

- `candidate-only`：本次在所查范围内只观察到一个候选且没有已尝试但未确认的选项（状态码 0）。只说明卷标和文件元数据相符，不证明它是现用原池、SQLite 正常、操作已提交或可开始维护。
- `ambiguous`：观察到多个候选（含同卷的多个可见名字），不选第一个。`incomplete`：证据不足或有可见原件变化；如还有观察到的候选，它们仍不是权限。
- `none-in-scope`：没有在本次有限范围内观察到候选，不表示未安装或可以建新池。后三种均为状态码 2。

真正维护仍需独立核对权威原 SYSTEM、已提交的原 INIT/SETUP、相关卷标及宿主批准，并实际取得原目录排他锁；这份查询不改现行停机入口。它也不使目前由 Helper 监督的 SMB 可独立重启；后续 ZXS 自有监督与只用原部署的重装验收是另外的工作。
