# ZXS-PORTABLE-1：首次登记与确认下界

**本片只定义首笔原认领和空池的读写契约，不开放初始化命令。** 首登记录哪一笔原请求建立哪个逻辑池、当时选择了哪些根，以及原登记确认到哪里；操作者的真实授权另验。卷标是由这笔原认领导出的反馈，不是另一份决定。账户、加盘、业务帧及非零前沿的具体动作各有独立契约；旧格式不作为备用解释。

## 1. 原认领字节

下列串按顺序直接连接，无填充。引号内为 ASCII，`\0` 表示一个实际零字节。整数无符号大端，`id` 是非全零的 16 个原始字节，摘要是 SHA-256 的 32 个原始字节。不得把十六进制文本、宿主结构或规范化的路径作为散列输入。

```text
B       = "ZXS-PORTABLE-1/GENESIS\0" | pool:id | init_op:id | approval_ref:id
        | storage_uid:u32 | count:u16 | row[count]
row     = role:u8 | volume:id | component_limit:u8 | path_n:u16 | path[path_n]
G       = SHA256(B)
GENESIS = B | G
FLOOR   = "ZXS-PORTABLE-1/CONFIRMED\0" | G | sequence:u64 | frame_bytes:u64 | head:32
```

- `approval_ref` 是原首登批准的**非秘密**关联号，随原单固定；它不是批准凭据、账户、口令或管理员授权。存储属主 `storage_uid` 来自受保护部署的非 root 服务账户，不接受 0 或 Linux 无效 UID `0xffffffff`；与当前网页用户、请求人或临时提权身份无关。精确续单绑定池、原动作/Op、这个引用、属主及整份有序选择，另获真实授权。不用哈希或这些字段本身证明是谁批准的。
- 共 3–64 行：第 0 行角色 0=SYSTEM，第 1 行 1=唯一回收卷，其余 1–62 行均为 2=普通数据卷。VolumeId 两两不同；普通行按原路径的**无符号逐字节**字典序严格递增。各根路径全表不同，任何两根都不能按完整路径组件互为祖先。`path` 是 1–4096 字节绝对非根 Linux 原路径，1–256 个非空组件；禁 NUL、点/点点、重复或尾随斜线，不要求 UTF-8。它是初始明确选择的位置，不是用来扫描/追随替件的授权。
- `component_limit` 为当时在相应原目录上核实的正的单组件字节上限与 255 的较小值，1–255；未知不填默认值。记录可解与实际能否认领、落下私名或受理未来特定文件名是两关。每一真实操作另外核其所需的名字和空间；不得借字段证明回收卷与其余卷有独立文件系统或物理盘。
- B 的固定头为 77 字节，每行固定部分 20 字节，GENESIS 最大 263,533 字节（含末尾 G）。先按界验证可变长度与加法，再读精确串。GENESIS 不含卷标、卷标摘要、指针文件、设备号、inode、挂载号、私有 ioctl、扩展属性或任何未来帧。首登的每个[103 字节卷标](portable-volume-claim-v1.md)均由 `(role,pool,volume,init_op,G)` 唯一得出；后来加入的卷必须引用自己的加入决定，不能借 G。

## 2. 三个 SYSTEM 名字与同一把锁

原 SYSTEM 受保护根内，`INITIALIZING` 是待完成原登记，`REGISTRATION` 是发布名，二者是**同一普通 inode 在不同阶段的名称**，不得并存。第三个名字 `CONFIRMED` 存 FLOOR，是一个独立的普通文件，不是第二本操作账。三者均只在 SYSTEM 解释，不占用普通数据目录的业务名。卷标另在各卷使用已约定的唯一根级私名。所有控制文件均为受保护存储属主的 0600、单链接普通文件；显式从原父不跟链接地分别核实真实名字/类型、当前实体、挂载、属主、模式和链接数。外来或既有同名物绝不截断、改属或接管。

1. **先保住原件，再写首笔。** 使用操作者明确选择且有可信新根来源的完整 S/R/F 组。从原目录取得共同非阻塞排他锁，全部取齐后复核路径、挂载、原物、互不重叠与未认领；R 须可证与 S/每一 F 分属不同文件系统。仅新标缺失/普通名字为空不算新盘。固定 `INITIALIZING` 用独占新建；随即在同一首建打开文件描述（OFD）上取 `flock(EX|NB)`，在此前不得写任何可认池字节或产生在线可消费名称。保留该 OFD，不在另一打开上补锁。完整写 GENESIS，同步该文件、原 SYSTEM 目录，从原父重核命名仍系本物并实读完全相同的字节和 EOF。空/半写、失锁或来源无法区分时保留原场，不重签 PoolId/VolumeId 或清除未知名字。
2. **先有完整原单才认领。** 合格的 PENDING 只证明原请求已见，未授权在线使用。冷续须显式提供完整原根和原单，不从待定字节打开外部路径；取得同一原登记 EX 及整组原卷锁，先核全组、再做第一项变更：在原 S 只可见该原 INITIALIZING、本阶段允许的准确 FLOOR 与卷标；其余显式根除本阶段允许的标签外须空，不忽略陌生文件。冷接续重新同步并复核原登记及原父，然后才发后续反馈。先不覆盖地建立/复核零 FLOOR，实际同步文件与 S、重开核对，再按**登记行顺序**逐卷建立/复核精确标记；每卷文件及其真实父均须同步、从原父独立重开核全长/EOF 和归属，才处理下一行。可见标记应为从 S 开始的一段连续前缀；有标无 FLOOR、次序有洞或错标均不是可补的“缺标”。返回前再核整组。两次执行间可能留下部分**准确**反馈，另经授权只能续同单；未知、部分写且不能归属的普通文件保持原样。
3. **发布只改名字，不换锁对象。** 在原 OFD EX、整组根锁和唯一受保护写域下，最终重核本次原单、完整 GENESIS、零 FLOOR、各卷已同步且重读的原标记、原源名及目标空缺；对原父作原子**不覆盖**的 `INITIALIZING → REGISTRATION`，同步原父，从同一父重新打开并验证现名仍是手中原 inode，旧名不在，状态与卷标仍准确，才可报告确认。占名、改名成功但父同步失败/结果未知等，都不回滚、删标或换票；纯查询不替调用者续办、同步确认或证明旧回执已送达。普通 Linux 名字操作不是针对不合作的同权限写者的源 inode CAS；需要受保护的父与所有合法写者遵守相同的锁规则，否则不执行。
4. 已发表后，业务参与者在同一原 REG 普通文件的实际 OFD 持 `flock(SH|NB)` 至最后受保护 I/O；离线维护改动须在该原件上持 `EX|NB`，卷认领还须持相关真实卷根 EX。原 SYSTEM 目录另有短事务锁：取账时持共享或排他锁，追加/切换下界时排他，使原登记与下界来自同一切口；多名在线 REG 共享持用者本身**不能**串行追加。先在显式选择的 S 下验第 0 行与该原根、原 REG 和 S 自己的卷标/下界，之后才能按获准范围打开该池其他路径。仅解码其他行不产生寻址、业务或操作权限。

## 3. 下界不是第二本日志

FLOOR 恰 **105 字节**（25 字节域＋32＋8＋8＋32）。空池唯一值 `(G,0,0,G)`；第 1 笔业务决定的前驱是 G，第一帧从完整 GENESIS 后开始。`sequence` 不计 GENESIS，`frame_bytes` 只计确认的连续后续帧**累计实际字节**，不计 GENESIS、FLOOR 或其他普通文件。既定上限分别为 8,192 个逻辑决定和 8 MiB 确认帧总量；不是单帧配额，也不是可以用尽恢复预留的许可。没有消息可跳过，不能只凭尾 32 字节认为确认成立。非零值必须由该版本已理解的完整连续帧从 G 验算出准确序号、字节计数和最终 head，否则不受理。

`CONFIRMED` 是当前的一份下界。变更下界时**绝不替换、截短或重建 REGISTRATION inode**。未来有正式非零帧格式的写者，须在共同 SYSTEM 短事务锁内重新核当前原前沿；先按原票完整追加、同步原 REG，核实际帧；在同一受保护父中独占创建本动作私有新普通文件，写完整新 FLOOR、同步并复读；仅在旧下界仍是这笔操作准确原前驱、目标命名与原物受控时，才原子切换**这个**下界名字，再同步父并从原名重开核验，最后才回执。初设时没有合法旧 FLOOR，应**不覆盖**建立零值。不能因看到临时文件就选最大的序号，不能把可见但未同步的替换当作原单完成；无法排除陌生写者或无法保证上述语义时拒绝。未知临时材料保留，不是当前下界。

| 原登记与下界 | 仅认识首登记的读者可得出的结论 |
| --- | --- |
| 只见完整 `INITIALIZING`，无尾；无 FLOOR 且全未标，或有准确零 FLOOR 与连续准确的卷标前缀 | 仅可在原单、显式整组和各阶段证据成立时报告待完成；即使全标已在也不是 READY。无下界不是“已确认零”。 |
| 只见 `REGISTRATION`、GENESIS 后严格 EOF、完整零 FLOOR，已核 S 与 S 标 | 可报告“该 SYSTEM 上的首登记与零下界相符”。另核实际原卷才能报告当前在位/可用；这也不证明操作员先前收到了成功答复。 |
| 已发表但下界缺失/错 G/计数越过账、指向不同 head；两登记名同时在、PENDING 的标记次序不相符或登记材料截短 | 不认空池、不修复、不另起首登。已确认下界外的证据不能用于倒退它。 |
| 零下界但 REG 有任何尾字节；或见到非零下界/后续帧 | 不把尾帧、半帧、完整但未确认的帧视为已确认。本首登记读者不能按空池继续，报告需对应完整格式/原单判读；不自动采纳、截尾或降到旧前沿。 |

所有字节完全相同的另一套媒体，会给出相同逻辑标识。普通文件协议不可能单独鉴别全套克隆或完整一致回退；不可把逻辑自洽当作已确认的物理原盘、操作者授权或永久防回滚。显式可信部署来源、原件/锁/挂载的在场证据和故障后的确认是分别验证的。此处没有启用恢复、初始化或新的服务入口。

[固定四根向量](../tests/portable/genesis-v1.txt)给出 B、G、两种登记名下相同的 GENESIS 字节、四份卷标及零下界；第二个 F 的原路径含非 UTF-8 字节。另给两字节未知尾和声称确认它的下界，二者都是**拒绝用例**：把这段尾附于 GENESIS，无论配旧零下界还是该非零下界，都不成合格空池或已理解的业务决定。向量为公开的合成样本，示例路径永不打开。未实测两个实现、普通文件系统的持久性或断电恢复。
