# 离线维护的原件与权限

供维护者和故障复核人员使用。本页描述当前代码共同使用的角色、锁与原件证据。
运行结果与未覆盖范围见[交付核对表](../../RELEASE.md)，具体操作见[离线池维护](../guides/headless-offline.md)。

## 证据经过哪些边界

[架构数据流](../../ARCHITECTURE.md#数据流)区分本地配置动作与已安装 ZXS 的固定离线动作。
首次设置尚无原描述文件；取得原状态目录排他锁后才选择新池和角色身份。检查与预览不会自行登记。
可选的嵌入式发布器另有[独立的宿主和目标规则](../guides/embedded-image.md)，不能代替首设。

## 持有同一件原件

- **账号和目录。** 首设与维护使用专用非 root 服务账号。核对目录所有者、权限、实际挂载和可见路径链；角色标记用于绑定原池及预期角色。
- **锁和顺序。** 停机维护在固定状态目录持有与服务共同使用的排他锁，保留原 `server.conf`，再按原登记顺序核对所有角色。路径同名不等于同一目录。
- **再检查。** 操作边界再次比对名称与持有的原件。若挂载、原描述文件或角色身份无法确认，不能采用同名替代、改用另一套目录或删掉旧记录重试。
- **固定执行。** 目标名称查询、初始化已登记 DATA 和文件导入只使用固定、受保护的 `/zxs/bin/zxs` 原件及对应离线入口。不会向正在监听的服务发送维护命令。

## 允许的写入与恢复

- **首设：**先发布角色标记，最后发布状态配置。前台确认及不回显口令由本地终端处理。
- **密码重置：**只更新原账号的代次、盐和验证值；用户名、池身份、磁盘及业务文件保持不变。
- **加盘、初始化、退盘：**这些是不同动作。空盘退役还须核对[对应回收回执](../specs/recycle-retirement-receipts.md)；不会为退盘复制或擦除整盘。
- **导入：**Helper 持有同一个来源并验证原票；由 ZXS 发布完整容器。重放使用同一份原计划，不生成替代操作号，不删除来源。

中断、输出断开或报告不确定不是未写入的证明。保留原配置、原角色标记、已有暂存和原导入票。
先核对原操作的证据，只用各指南中明确允许的同参数恢复，不删除未知记录。
