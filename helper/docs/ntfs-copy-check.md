# 已保存的 NTFS 卷：有限只读观察

在获准的普通 Linux 用户终端，明确选择一个独立、未挂载且未用作 loop 后端的本地普通文件。它从 NTFS 卷的第一个扇区开始，并包含完整声明范围、实际备用启动扇区和独立取得的可信完整文件 SHA-256。不是整盘/分区表、元数据摘录、压缩或容器镜像、原设备，也不是活动虚拟机的后端。

```sh
helper check-ntfs-copy /绝对路径/volume.img --sha256 可信SHA256
helper disk-web --ntfs-copy /绝对路径/volume.img --sha256 可信SHA256
```

第二项只通过[本机配对页](disk-web.md#可选在网页上检查一个已保存的卷镜像)预览和确认同一项。等待网页期间只持原路径与实体引用，不读数据、不取租约。确认后才从原文件描述符打开，只取一次连续的只读租约，按固定缓冲区验证整份 SHA-256 和真实 EOF，直到隔离工具完全退出且原名、同挂载和属性复核。不会封存或复制全卷。摘要和租约不证明输入来源，也不证明原设备的使用状态；如果仍挂载、用作活动后端或存在写端，不能作为此动作的合格副本。不能取得原证据即停止，不回退到宿主工具或设备。不套用 FAT 的 128 MiB 封存上限；小头只核 512/1024/2048/4096 字节扇区、完整声明范围及末端。这版上游对普通文件用有符号 64 位探测长度，为避免其加倍/取中点运算越界，仅受理不超过 2^62 字节的文件。

只执行 Debian 安全仓固定的 **`ntfsfix -n`**（`1:2022.10.3-5+deb13u3`），不接其它选项。隔离工具仅看到真正只读的镜像 `/image`、自己的最小运行库和固定空 `/etc/mtab`；空表只适用于这个无设备的视图，不取宿主挂载表，也不证明宿主未挂载。没有宿主 `/dev`、`/proc`、`/sys`、FUSE、网络或其它文件，且不做任何 NTFS 内核/FUSE 挂载。上游失败分支即使尝试以可写方式重新打开，客体仍不可能写这份副本；不重放日志，不清 dirty、不标记重启检查、不清坏簇、不修复或修改配置。

| Helper 退出码 | 实际含义 |
| --- | --- |
| 0 | 原工具确实在首次只读打开后完成了其有限的 MFT 及镜像记录处理、实际最后扇区与主启动扇区的比对，并有完整的原终场报告和干净的独立退出。只确认本次有限观察。 |
| 2 | 有额外诊断、打开/重试/收尾不合格、确切结果缺失、时间或资源超限，或副本、隔离、摘要/租约等条件不满足。不是“已确认坏盘”，也不能报告正常。 |

**不是 Windows chkdsk。** 成功不验证全部 MFT、普通文件正文或整个卷的完整性，也不确认 NTFS 日志是否干净、Windows 休眠/快速启动或是否适合挂载。中间可能存在的尾部不另作结构检查；`image_bytes` 是完整文件摘要范围，`declared_bytes` 是卷头的声明字节数。不回显原路径、卷标、文件名或上游诊断原文。网页只用配对后的剩余十分钟（包含完整摘要与工具观察），较大的副本可用终端；终端仍对上游阶段设十分钟、300 秒 CPU 和有界输出，且不会保证阻塞的宿主 I/O 立刻响应取消。

依据：[Debian ntfsfix(8)](https://manpages.debian.org/trixie/ntfs-3g/ntfsfix.8.en.html)、[Debian 安全版来源](https://security-tracker.debian.org/tracker/source-package/ntfs-3g)。发行须由独立核准确切 SHA-256 的[私有材料](../packaging/debian13-amd64/README.md)提供。本内容只完成源码及上游静态对读，未组包、运行或做现场验收。
