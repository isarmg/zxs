# 用 e2fsck 只读检查 ext4 副本

先准备独立保存、未挂载/未通过 loop 使用的**整卷普通镜像文件**，并从可信的独立记录取得该文件的完整 SHA-256。在非 root 的专用本机维护身份下，只指明这一个文件：

```sh
helper check-ext4-copy /绝对路径/volume.img --sha256 <完整副本的独立64位十六进制摘要>
```

也可用 `helper disk-web --ext4-copy IMAGE --sha256 HEX`，在[本机配对面板](disk-web.md#可选在网页上检查一个已保存的卷镜像)预览终端提供的预期摘要并确认一次。等待浏览器时不打开镜像读取、不取读租约；确认才开始整份核验及同一个隔离检查。页面不收路径或参数，也不延长原有十分钟会话，长时间检查可用独立 CLI。

这里的镜像从卷起点开始，不是整盘分区表、qcow2 等容器、块设备或 live 文件系统。工具本身适用于 ext2/3/4 家族；报告不根据一个魔数硬猜是哪个版本。只在合格的本地数据文件系统上读一个无符号链接、无硬链接别名的普通文件。保留原描述符及磁盘上这一份副本，不写新镜像，不把大小限成 FAT32/exFAT 的 128 MiB，不往内存或临时文件系统复制正文。整份摘要必须读到实际 EOF；这会花与镜像大小相当的读取时间。如果普通镜像尾部有填充字节，仍计入 `image_bytes` 和摘要，但上游结构检查只到 `filesystem_bytes`，不识别外层分区。命令不证明副本如何取得，也不代为判断原盘是否安全。

只保存元数据不等于完整卷副本：[e2image](https://manpages.debian.org/trixie/e2fsprogs/e2image.8.en.html) 默认及单独使用 `-r` 不包含普通文件数据，`-Q` 产生的 QCOW2 也不是此入口支持的格式。匹配 SHA-256 只证明所选文件与预期相同，不证明已经从源卷取得完整文件数据。

在第一次读取前取得原只读文件描述符的 Linux 读租约。已有写入者、无权限、文件系统不支持租约或无法确认场景时，不降级只靠普通只读打开。若检查期间有进程请求写入、原名/挂载/原件改变，或用户取消，结果不成立；可能短暂阻挡其他进程打开这份副本用于写入，请只选择不再使用的独立副本。读取结束与检查器原进程退出后仍核租约、原物、原长度和实际 EOF，不复取租约来补证明。无需提权；较低的宿主限额、临时不可用的读租约或隔离能力欠缺都会明确失败。

实际运行指定 Debian 13 amd64 [e2fsprogs 1.47.2-3+b12 发行件](https://packages.debian.org/trixie/amd64/e2fsprogs)的固定 `e2fsck -fn`。同版的内部显示名参数固定为 `-N /image`，只影响输出，不让卷标决定解析，也不作为用户的可调参数。启动器只把已核的运行库及这份保存镜像的只读投射交给新的隔离环境，不挂宿主的 /dev、/proc、/sys、mtab、blkid 缓存或 e2fsck.conf，不供外部日志或设备查找；内部临时 /dev/null 只是空的普通占位，不是设备。没有宿主工具/库兜底、重放、挂载、修复、扫描坏块或输出原始报告中的名字。检查器隔离运行的 wall 时限为 10 分钟；检查器 CPU 上限为 300 秒，进程地址空间至多 2 GiB，输出限 64 KiB。大卷的上游位图检查可以使用同一进程内的线程，但不许派生新进程或离开进程组；同一用户的任务数限额最多 256，较低的继承限额不提升。宿主卡死的 I/O 不保证能立即退出；也不以升高宿主限制强制继续。

| helper 退出 | 含义 |
| --- | --- |
| `0` | 这次强制只读结构检查未报告问题：实际工具退出 0、五个阶段及完整统计相符，且无额外诊断。 |
| `1` | 工具返回 4，报告有未修复问题；不保证走完所有检查阶段。没有修复。 |
| `2` | 未完成或不能确认，包括外部日志、标记需重放的日志或待清孤儿、已截短的镜像、工具故障/取消/额外告警、任何其它或混合退出位、固定安装物不可核、摘要不符、镜像换件或超出执行预算。若实际得到工具结果，`checker_status` 保留其原退出码。 |

即使退出 0，也不是原磁盘健康、全部备份超级块、文件正文、数据未丢或未来可安全装载的证明。主超级块只是单卷范围与日志边界门；结构核查仍由上游做。如果上游选择尝试备用超级块或报告跳过日志，即使同样退出 0，也不是本命令的成功迹象。不自动修复、不从 Web 接收镜像。

本批为源码，尚未构建、组包或运行。上游参考：[Debian e2fsck 手册](https://manpages.debian.org/trixie/e2fsprogs/e2fsck.8.en.html)、[1.47.2 实际主流程](https://github.com/tytso/e2fsprogs/blob/v1.47.2/e2fsck/unix.c) 与[Linux 文件租约语义](https://man7.org/linux/man-pages/man2/F_GETLEASE.2const.html)。

## 只修新建的工作副本

```text
helper repair-ext4-copy /绝对路径/input.img --sha256 可信的完整SHA256 --output /绝对路径/未占用的新目录
```

这是另一条本机非 root 前台命令，网页仍只有只读检查。先确认独立取得且没有挂载或作为 loop 后端的普通输入镜像，再在同一终端批准精确输入/摘要、输出和工作目录。只读租约期间按偏移完整复制并正核输入摘要及 EOF，源描述符不交给修复子进程。目标父目录须由当前用户控制、其他人不能写，是可写的本地文件系统；输出名必须不存在。同一文件系统可以使用，不需要第二块盘；需要足够空间写入整份工作副本，不套用 FAT 镜像的 128 MiB 限制。

同一已核发行件在隔离环境仅收到新普通文件，固定运行 [`e2fsck -fp`](https://manpages.debian.org/trixie/e2fsprogs/e2fsck.8.en.html)（非交互，只尝试上游允许自动安全处理的问题，不给 `-y`、外部日志、坏块扫描或设备）。使用与只读入口同样的 ext 主超级块范围及日志门：外部日志、明确待重放或孤儿恢复不进入这条路。工具根和认证过的库只读，宿主设备、配置、日志和原镜像不进入；原来那份普通输入保持只读。不会提升继承的文件大小限额。每轮工具最多 10 分钟／300 秒 CPU，整份复制和 SHA 的时间另算，内核 I/O 卡住不保证立即退出。

仅观察到真实工具正常返回 0 或 1 及其完整终场统计后，才同步、关闭写句柄，从新工作原 inode 取得独立读句柄和只读租约。完整计算新文件 SHA-256，再按同一标准运行独立的 `e2fsck -fn` 五阶段。只有确切返回 0 且没有额外诊断才在同一个原父用无覆盖改名发布 `新目录/image.ext`，同步并核最后原名及原对象。返回 0 意味着**新副本**本次复查未报告问题，附其完整摘要；不证明原盘健康、文件内容无损、任何镜像可安全挂载或各类修复都已支持。返回 2 或没有回执表示没有可确认的复查成品；可能保留有部分写入的私有暂存目录，或在提交后丢失回执时留下最终目录。保留两者，不接管、不清理、不覆盖或自动重试。只有源码，未实机、未运行检查／复修。
