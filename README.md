# ZXS 文件存储系统

ZXS 在登记的磁盘根下管理独立的文件容器（FILE）。普通文件夹用于组织文件；版本、分支和正文属于文件，不属于整个文件夹。服务通过 Web 管理元数据，通过 SMB 或受控 HTTP API 读写文件。

一台 Linux amd64 服务端管理文件及其备份。`zxs` 是守护进程，`zxs-helper` 用于离线维护。正常启动要求系统已经初始化；日常账户管理仍由主服务 Web 提供。磁盘添加、注销/移除、外来接入与初始化正按[辅助工具职责](docs/design/helper-disk-management.md)分阶段迁移，不能把改名当作四项功能已经迁完。

存储目录不限定 Btrfs，也不要求程序核实物理设备独立性；共享底层设备、控制器、电源等故障域由用户自行保证。目录身份、完整文件、认证及持久化校验仍保留，多个目录不等于多个独立物理副本。

## 存储布局：当前与目标

已发布的主线源码仍使用原有磁盘分区目录。下一版只分两种数据位置：FILE 容器保管正文、版本和文件本身的元数据；ZXS 系统盘保管登记、拓扑、普通路径与操作决定。用户删除时，原容器进入专门配置的回收盘，不进系统盘或备份盘。备份只允许主数据盘直接写入指定的备份盘；可有多个独立目的盘，不允许备份盘接力。跨盘移动要保留同一 FILE 及全部历史，不是复制一个新文件。**这些是目标，不是现有磁盘的操作或升级说明。** 详见[磁盘角色与移动、回收规则](docs/file-only-migration.md#disk-target)。

## 核心功能

- 文件管理：按磁盘浏览文件和目录，Web 保留文件浏览、移动、改名、版本树及元数据管理，不提供文件上传、下载或预览；正文读写通过 SMB，受控 HTTP API 保持可用；正常入口不分发管理子命令；最小离线救援由独立工具提供。
- 版本与分支：内容写入形成独立完整版本；文件分支先引用冻结父版本，首次写入才保存自己的内容。切换一个文件的分支不会切换同目录的其他文件。ZXS 不提供目录仓库、目录提交或 Worktree。
- 合并与标签：显式选择文件分支的合并结果与归属，为版本节点添加可继承的标签。
- 备份与恢复：新目标是[主盘直达备份盘](docs/09-backup-topology.md)，每份完整副本单独核验。此前已运行的链式备份用例不是新规则的验收。

## 平台与架构

业务核心和 Web 界面使用 Rust 实现。浏览器通过 WASM 界面和 HTTPS 业务 API 访问服务；SMB 通过独立的 Samba → 本机桥接接入同一存储核心。桌面和移动设备使用浏览器或系统 SMB 客户端；项目不再提供原生 App、WebView 宿主或 App 安装包。

服务端、Samba VFS 和原生构建宿主仅支持 Linux amd64（64 位 x86_64）；当前登记和验收目标为 `x86_64-unknown-linux-gnu`。浏览器产物保留 `wasm32-unknown-unknown`。其他 Linux amd64 ABI 的必要共享实现保留为未验收预留，不代表已经通过构建或运行验收。

项目持续开发中。主线源码更新不等于正式发行、部署或现有磁盘升级。已经运行的 API 与进程内 SMB 测试、尚未通过的场景及旧格式处理原则，见[文件容器的使用边界与验证状态](docs/file-only-migration.md)。

## 文档

[文档目录](docs/README.md)：本地运行、操作手册、设计规范、构建与发布及当前限制。开发与评审统一从[工程规范](docs/20-engineering.md)进入，命名与测试细则分别链接到唯一维护入口；规范要求与实际验收结果严格区分。

项目采用一个 Git 仓库、一个根 Cargo 工作区和一个根 `Cargo.lock`。自有应用和工具统一从根工作区构建；`src/foundation/` 仅保存纳入同一依赖图的基础源码组件，没有自己的 Git 仓库、工作区或锁文件。基础组件通过本地路径依赖使用根锁文件统一解析，并按 [12 类职能父目录](docs/architecture/foundation-groups.md) 组织；分类不改变包身份或依赖数量。

目录与内部包名按职责命名，例如 `src/engine` 的 `storage-engine`、`src/interface` 的 `web-interface`、`src/naming` 的 `name-policy`，工具入口使用 `web-build`、`web-bindings` 等职责名称。目录和组件合并规则见[单仓库结构](docs/monorepo.md)。所有说明文档集中到 `docs/`；全部许可证、版权通知与来源收据集中到 [compliance/](compliance/README.md)，原始来源、版本、提交、归档校验和和迁移映射继续保留。

[Rust 第三方源码清单](docs/THIRD_PARTY_RUST_SOURCES.md)记录业务运行库、过程宏和构建辅助库的来源、许可证、用途及本地修改。正式 Cargo 构建使用仓库源码与唯一根锁文件，以 `--offline --locked` 执行；Rust 工具链、平台 SDK 和原生组件继续按原方式管理。源码完整性检查入口为 `bash .github/scripts/check.sh rust-sources`。
