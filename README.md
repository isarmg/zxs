# ZXS 源码仓库

本仓库只把三个独立项目放在同一个 Git 仓库。根目录的目标结构只有下列项目与这份索引；这里没有共同的构建入口、运行配置、私有协议、数据目录或发布包。

| 项目 | 设计职责（不代表已交付） | 独立文档 |
| --- | --- | --- |
| `zxs/` | 存储普通文件与目录；维护单文件版本和工作稿；以同一容器进行跨盘移动、回收与还原。 | [ZXS 架构](zxs/ARCHITECTURE.md) |
| `helper/` | 对操作人员明确指定的本地文件、目录和挂载做通用检查；只按本项目自己的安全边界执行操作。 | [辅助工具入口](helper/README.md) · [架构](helper/ARCHITECTURE.md) |
| `zxs-workspace/` | 管理整目录版本与本地 Worktree，提供 CLI 与桌面图形交互。 | [目录工作区架构](zxs-workspace/ARCHITECTURE.md) |

## 独立性是交付条件

- 任一目录单独拷走后，其源码、构建说明、依赖声明、入口、测试源码、许可与来源记录仍齐全；另外两个目录缺失、改名、运行或未运行都不改变它的行为。不采用根级工作区、共享 crate、`../` 依赖、兄弟进程调用、内部协议或捆绑发布。静态审查须逐项核对，不把审查称为构建验证。
- 各项目只接触自己拥有的数据和用户明确选定的系统资源，各自恢复自己的数据，不检测、命名或推断另外两个项目。普通文件路径、文件系统、SMB 等通用接口不构成产品间协作。凡需要理解存储服务私有状态的初始化、磁盘登记、账号撤销及恢复功能，都由存储服务自己的操作入口承担；通用工具不是第二个写者。
- `zxs/` 优先使用自有或现有已改造组件；确有缺口才改造必要的上游源码并在本项目留存许可证、来源和补丁。其余两个项目按需使用成熟依赖；每个项目维护自己的清单、工具链约束和适用锁定信息，不伪造生成结果。

## 数据和功能边界

- 存储服务只有系统盘的全局登记、路径、唯一当前位置、原操作决定，以及文件容器内部的正文、版本和工作稿等本地材料。普通文件夹不是容器；取消旧外层数据分区及所有托管备份。专用回收盘保存被删除的原容器，不是第二份持久副本。跨盘 MOVE 保留 FILE 身份和历史：目标材料完整验证后，由原操作一次切换权威归属，之后才能安全退役源；切换前暂存不可见，切换后的未清残留不能继续提供读写，也不是备份。用户明确 COPY 才创建新身份。同名冲突、目标离线或空间不足时不改变源。不迁移旧盘，不凭同名或同哈希重新认领原件。
- 通用辅助工具以用户指定的实体和真实观察为事实。默认只读，不监听服务、接管账号或写入某个存储产品的配置。不把路径存在当作磁盘健康、存储身份或修复成功。
- 目录工作区把完整提交保存在标准不压缩、不加密的 ZIP／ZIP64 中，`.zxs` 是本项目自己的扩展名。检出和提交由本项目负责；目标只需是普通文件存储。桌面界面与 CLI 共用应用操作，真实支持程度由本机能力决定；移动端、虚拟磁盘和 Release 单列，不拿界面源码替代已实现或已验收的平台支持。

## 从任务到代码

本索引和三个项目的架构已完成静态审查。各项目把仍适用的任务拆成可独立审阅的业务批次，标明「待实现」「源码已审、未运行」和「明确取消」，为每条旧任务记录原行或编号、负责项目、保留或取消原因及验收证据／下一步；保留已有实际失败与证据；不把重写、搬目录或写出测试源码当作任务验收。每组一人编写、一人只读审查，把反馈直接给编写者。完成并复核的批次正常提交 `main`，不等其他组。

各项目分别记录已提交的源码、待办和验收证据：[ZXS 交付与验收](zxs/TASKS.md)、[helper 任务清单](helper/TASKS.md)、[目录工作区任务清单](zxs-workspace/TASKS.md)。

本仓库根级 Cargo 工作区和共用 Cargo 配置已退役；遗留源码、文档、脚本和工作流暂留供迁移核对，不是新项目的构建入口。需要复查旧根级工程时，请使用相应历史提交。这里记录的是源码状态，不是发布或运行验收。当前不运行程序、构建、测试或 CI，不部署或操作现有磁盘。
