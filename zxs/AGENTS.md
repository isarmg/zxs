# ZXS 工程边界

先读 [架构](ARCHITECTURE.md) 与 [任务清单](TASKS.md)，再从 [使用说明](README.md) 定位当前入口。面向本项目独立构建、测试和交付；不能依赖上层目录的源码、工具链或运行环境配置。

- 单一权威检查代替重复检查，但不删除真实的输入、落盘、身份或权限边界。判断一项检查能否删除，先说明所有入口共有的证明，以及权限、介质、进程或代次变化后证明何时失效。
- 用受约束类型及明确构造器表达不变量。把解析与验证放在信任边界，不把业务层拆成无必要的通用框架，也不以吞掉错误或 panic 来代替精简。
- 优先自有实现；仅在有必要时引入适用的上游源码，在本项目记录许可、来源及变更。测试源码、静审、实际故障验证和发布证据分别记录。
