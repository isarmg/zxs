# SYSTEM：一个 SQLite 数据库决定归属，一套普通文件保存正文

**新池规范，尚未启用。** 在宿主预先挂载的本机可信文件系统中，每池只有一个 `SYSTEM.sqlite3`。ZXS 在线业务和停机的独立 helper 使用同一公开关系模式与操作语义，不共享实现、不互调程序、没有第二份业务授权库。此规范取代旧 SYSTEM 自研登记/决定流、序号前沿、INTENT 与它们的锁协议；不导入旧池、不迁移、不双写、不回退。**SQLite 事务只覆盖这一个数据库，不覆盖普通卷、回收卷或专用 Samba 的唯一用户凭据库。**

## 谁保存什么

| 权威数据 | 唯一落处及约束 |
| --- | --- |
| 池与卷 | SQL 保存 PoolId、初始化原操作、稳定存储属主、各 VolumeId、角色、登记位置/代次、认领标识、状态；活动池恰一 S、一 R、至少一 F。角色标签只把已选的实际根对应到同一 SQL 原认领行，不能选主或发命令。新族卷标绑定原 PoolId、VolumeId、角色、claim Op 和一次固定的认领标识，**不引用 GENESIS、数据库文件摘要或易变设备号**。首登记子集的准确字节与夹具见下文；未启用。 |
| 账户和权限 | SQL 保存两个固定角色的稳定 AccountId、Web 慢 KDF 和 SMB 非秘密账户／操作代，不存 SMB 密验。后者只属于专用 Samba 的 tdbsam；两端共同受[首设/恢复契约](first-account-v1.md)约束。SQL 还保存共享根、停用/只读/读写设置及其变更原单。唯一双账户只在本池**从未**首设且另有一次性离线授权时建立；重置另验恢复身份。同 Op 不重生盐/ID/代次。存储 UID、管理资格、共享定义都不等于数据读写权；撤后重授不复活旧句柄。秘密或快速猜测口令的摘要不进请求号、普通回执和日志。 |
| 业务命名、历史、标签 | SQL 保存目录/EntryId/FileId、原始拼写、确切父、放置代、分支/HEAD、不可再变的 NodeId/VersionId 与父子、创建时名、工作模式/修订、当前表示、材料引用、原事件、未来用户标签和对象关系。标签是业务元数据，不授权也不指到物理路径。根也有**非 NULL**的明确父键；FILE/目录同表同父精确字节唯一，不用 NOCASE，不用 NULL 假装根唯一。逻辑冲突与实际物理名冲突分别判。 |
| 任务与结果 | SQL 中每个 OperationId 一次，绑定池/主体、类型、规范输入摘要、原实体与所需代次。未决任务可记录已占位置、确切目标材料、原来源、资源额度；完成记录保存明确业务结果。节点、工作修订、归属和相关原回执必须在**同一提交**中发布。任务进度与已确认结果不是一回事；不造逐帧重放或第二个确认水位。 |
| FILE 容器和数据卷 | 普通文件只保存 FILE 二进制身份头、实际工作变化字节、规范扁平区间索引、分块校验表、完整 RAW 和必要的原物见证。不把账户、权限、用户标签或可独立裁决 HEAD/归属的日志写入各 FILE。SQL 不存整份正文或每个读块的明细副本，引用确切 MaterialId、长度、表示代和经核的索引/逻辑内容承诺。两个相同 SHA 不是同一物料。 |

完整库不可用/损坏：停止业务写、授权与清退，保留原件。单盘 FILE 可按证据诊断材料，不据它重建 ACL、已确认回执或抢占归属；SQLite 完整性检查不证明外部正文完好。仅用普通文件不能分辨全池连身份与数据一起一致复制/回退；发现冲突先停。不承诺不同文件系统一定是不同硬件。

## 打开、只读与独占维护

1. 从受保护配置指明唯一规范 SYSTEM 目录；验证整条可信路径、原目录、挂载、属主、权限和无歧义，不遍历陌生卷发现数据库。介质须能可靠提供本机锁、文件持久同步、父目录同步以及所需不覆盖语义；ZXS 外部材料/认领的正确性不靠品牌白名单、私有 ioctl、reflink、导出句柄或远端网络库；不据此宣称上游 SQLite VFS 从不为自己的临时文件选择可用的 OS 优化。
2. 生命周期锁直接取在**明确选定、仍持有的原 SYSTEM 根目录普通 FD**，两产品使用同一 Linux `flock(LOCK_SH|LOCK_NB)` / `flock(LOCK_EX|LOCK_NB)`。两个独立持有者必须分别 open 同一实际目录 inode，**各用独立 OFD**；不通过 dup、fork 或传 FD 让在线和离线共用一把可被转换的锁。仅单个持有者自身持续保留那一个原 OFD。在线服务及任何独立业务进程先取 SH，再开 SQLite；整个空闲/慢 I/O/后台/最终 flush 和排空保持，**关闭所有 SQLite 连接、完成所需同步并释放所有业务句柄后**才放原 OFD。helper 同一原目录 EX 覆盖完整离线操作。SH 允许多个合格在线持有者，只排斥离线 EX，不是单在线实例或写权限证明；在线并发依 SQL 条件事务及各 FILE/任务的真实守卫。没有独立锁文件，不在 DB inode 加这把锁；跳过/换用另一种锁、换 FD 自锁或无锁降级均不允许。名称/挂载/原实体、权限不匹配即停；同一路径重挂另一根不得自动认领。不能保证可靠本机目录 flock 时明确不支持。宿主 unit 状态不是锁，更不防整套资料一致复制。
3. 首次认领、加盘/退出等取齐 S 和受影响的真卷根，排除别名/重复，按双方共同的**本次仍持原根**顺序作全组非阻塞 EX；任一忙即释放整组，没有部分认领。组内 S 的**同一 OFD、同一次 EX**就是离线生命周期租约，禁止另开 S 再取第二把。若先要读旧配置拟计划，在 S 的只读 SH 下只观察；关闭连接/释放后再整体取 EX，重核原单/资格/现场，绝不假定升锁无缝。此后直到实际卷反馈、最后同步与关库不放 S。R 必须可证与 S 及每个 F 为不同的文件系统；不清则拒配置。已有标签、半库、外池/旧格式或未知物不得按空域接管。
4. 首次建库只在上述受保护全组 EX（包括同一原 S）下进行。先确保 DB、journal/WAL/SHM 等预期名字均无不明物，再以 OS 独占创建定名全新 `SYSTEM.sqlite3`（0600），同步首建普通 FD 和 S 父目录后关闭该普通 FD，**当时同进程没有 SQLite 连接**；SQLite 随后只按此唯一路径以 `SQLITE_OPEN_READWRITE` **不带 CREATE** 开户，并验 `sqlite3_db_readonly(db, "main")==0`；若预留已消失或换物即拒，绝不再建。仅这次允许初始化新库；`sqlite3_open_v2` 的 `SQLITE_OPEN_EXCLUSIVE` 不是 OS 独占创建。先以一个 SQL 事务建立模式、待初始化池、原单及确切卷行，成功后才准按原单留下卷标。每一实际卷标不覆盖地具名、同步文件和原父并核同一原件；全组独立重开验证后，再以一笔 SQL 事务转活动并落初始回执。仅初始认领激活这一整组；后来加盘、转换或恢复只改本单所绑定的卷和结果，不得顺带将无关失联/正常下线卷激活。中断时有原 SQL 未决单才续准确同单/原件；只有未认领的空文件或半库、无可验原单时**不删、不收养、不改标**，不能把「尚未成功」当空池写许可。
5. 通常只通过 SQLite 的标准本机 Unix VFS、唯一路径打开已有库，禁止 CREATE、URI 自选、ATTACH 另一数据库、外部加载扩展、immutable/nolock、私造 VFS。只允许正规 SQLite VFS 对库/恢复日志作 I/O；核私有规范 DB 名的类型/属主/模式/单链接和原父可用不打开文件的现场 stat 完成。写者核 `sqlite3_db_readonly` 实际可写；纯检查独立 `SQLITE_OPEN_READONLY`，遇 `SQLITE_READONLY_ROLLBACK` 等需恢复时报告不可读，由已有写权限的 SQLite 连接按原生协议恢复。不能把 `query_only` 或“只执行 SELECT”说成 OS 只读。活动数据库的任何原始文件 FD 都不为查 hash/魔数而额外开关，也不硬链/重命名/覆盖数据库；使用入口和 SQLite API 核 `application_id`、`user_version`、模式/关键约束与原 Pool/S 行，而非凭文件名、页首或任意同版本 DB 取得业务权限。一个进程只用一份 SQLite 实现操作该库，不跨 fork 继承活动连接。SQLite 自己的热 journal 属恢复，不手工清理。见 [开户标志](https://sqlite.org/c3ref/open.html)、[只读恢复错误](https://sqlite.org/rescode.html#readonly_rollback)、[SQLite 的锁与损坏风险](https://sqlite.org/howtocorrupt.html)。
6. 基线选 `journal_mode=DELETE`、`synchronous=EXTRA`、`foreign_keys=ON`、`trusted_schema=OFF`。初始化显式定模式；所有连接在事务外核实际值，对连接级项显式设置并读回，不能因 PRAGMA 未识别/无结果假定成功。已有库若是 WAL/未知模式，拒服务，不偷偷切换；纯读取不试写 journal_mode。DELETE 适合短元数据提交且只在本机服务，不让长 SMB 传输持 SQL 读事务。EXTRA 在删除回滚日志后另同步目录，FULL 在此模式不一定能保住断电前最后一笔。WAL 会引入额外的文件/检查点及长读者问题，没有并发实证不引入；不关 journal 或同步换性能。以上耐久依赖正确实现锁与持久同步的文件系统、设备，不是断电实测。[PRAGMA](https://sqlite.org/pragma.html#pragma_synchronous) · [原子提交](https://sqlite.org/atomiccommit.html) · [WAL](https://sqlite.org/wal.html) · [外键](https://sqlite.org/foreignkeys.html)

## 操作与故障点

- **只有 SQL 元数据。** 已认证主体在短 `BEGIN IMMEDIATE` 中按原请求定位已有 OperationId。相同且当前获准披露的只取旧结果；同号异主体、输入、基底或目的拒。新单复核所需最新 credential/grant、确切 FILE/父、分支、放置或材料代次；一次提交业务行和不可混用的回执。比较更新必须影响预期的唯一行。提交 BUSY 不是“已经成功”，事务仍活动时只按 SQLite 规则处理该事务；I/O 错、崩溃或 SMB 回包丢失导致结果不确定时，从受信库重新查同一原操作。查清前不按新号重发、不承认所有权、不清理。错误时通过 SQLite 确认或回滚连接状态，绝不拿本地 bool 当 COMMIT。恢复已经提交的本单未完的交接/清理义务仅续它的原授权范围；不能拿它给别的节点发新的 WRITE。[事务语义](https://sqlite.org/lang_transaction.html)
- **有外部材料。** 短事务可先登记按 FileId/任务隔离的待办及真实容量/预期额度、原父、预期放置和唯一候选身份，它不发布节点/归属。放开 SQL 后，在准确目的开新私名，写入并验证/同步所有必要正文、索引、见证及父。实际落位不覆盖；重新开启准确原件，保持所需业务/介质守卫。最后短事务重查同单、权限、源版本、目标和资源及持有原物未变，原子选定该表示/位置、记原回执和余下任务，再报告真实状态。除单列的同盘更名在途窗口外，此前确认过的原内容仍可服务；迟来碰撞、ENOSPC、变体、不可验证候选均不夺其位置。不在 SQL 事务里等复制、全读、SMB 客户端、Argon2 或旧读者。待办不是全池下一序号，也不是可永久锁死兄弟 FILE 的全局许可。
- **手动 SAVE。** 每 FileId/分支只有一轮活动数据文件与一个已选逻辑工作修订，不后台全拷。工作视图不是正式不可变 RAW：SQL 原修订绑定确切段的物理偏移、**该段封存的有效长度/分块校验边界**、逻辑终长与成图承诺；哪怕是最后半块，核验只到该封存端，不从今天的物理 EOF/mtime 反推旧内容。工作读者固定所选修订、封存范围和真实材料至 flush；它不占逻辑写者席位。一个真实写句柄独占同一 (PoolId,FileId) 的写权，原代再验后在不影响任何旧读者的未引用区域准备本轮变化并同步，短事务选新图、记原回执；**确认不等旧读者**。本轮只用这一个增量，空间不足且没有可安全复用的区间时本次确认失败而不动旧稿；不得改仍被引用的字节/末块校验表，旧读也不能因追加使全文件的 mtime/EOF 改变而误拒。保留的是活读/在用修订需要的旧材料，不永久留每次保存的副本。若追加一字节后未提交即中断，旧选择仍读旧长度及原最后一块；未知尾不收养或擅删，绝不让“物理长度变了”自动令旧稿坏掉。引用未释放前不复用；释放后如何安全复用留待后续。本次实现保守追加到同一物料对，不会另存每次 SAVE 的文件副本，尚未接已失引用区间的局部回收。显式提交时才把本轮增量封存为真正不可变材料，以直接区间索引选择仍贡献的变化，自此任何下一轮不得复写；历史读取继续要求准确不可变实体、长度/stamp、校验表与原最后块。丢回包仅取原工作修订。
- **手动提交。** 只有明确提交才原子选择已冻结的本轮增量、记录直接父、NodeId/VersionId 和原 Op 回执。普通文件保存只确认工作修订；不产生正式节点、自动队列或整份复制。已有节点与被引用材料继续保留；不按保存次数推算历史。[工作轮与引用规则](portable-storage.md#工作保存与手动提交)。
- **跨盘 MOVE / 删除 / 还原。** 精确同一 FileId 的源仍是唯一被选址，复制所有保留版本所需的实际不同材料，不按 HEAD 大小或等内容摘要折叠身份。以原操作给目的全组不覆盖安装、具名核实并同步；随后 SQL 才切唯一归属、冻结删除原父/时间/还原资格、立原收据与清源责任。提交前只见源；SQL 已切后只从目标服务，不能因源掉线退回，若目标不可证则报告不可用。退休仅碰已冻结且重核的原源物，保留替身、未知物及活读者；源离线不堵无关 FILE。R 不是普通可写共享，仅按本次真实交接转移材料，不授 R 泛写。还原要匹配当前保留代和删除原操作，不能以更早删除回执恢复同名/同 FileId 后一轮。
- **同文件系统真改名。** 在第一处物理名变化之前，先于短 SQL 事务核准操作者当时的精确权限与完整前提，冻结 FILE、原/新父、源实体/目标名/外见证及预期代，**不可撤销地批准仅这一笔 rename 的执行**。此时还没有公布新位置或成功回执；该 FILE/两名统一显示待安装并阻新写。按原单、实际两父及 NOREPLACE 逐名安装并同步两父，再核旧位已空、目标原物和必要成员，最终短 SQL 事务核同一生效待办/两端/业务代，发布新位置及原结果。途中撤销原操作者、断连或禁用不废这笔已批准的改变：受信恢复者只把原单做完，绝不以此发新的用户动作或向旧主体披露；同一组不分批向外可见。冲突/掉盘保持这个 FILE 待办，不擅撤销、不回退同名或改票跨设备复制，无关文件可用。
- **迟到取消/孤儿。** 仅在判断原操作尚未发布、目标确系该原单所发且无在途或已提交引用时，才在明确权限下清其私物；遇 COMMIT 未知、原 DB 不可用等保留现场。恢复用 SQL 原单及真实文件，不另写手工 redo 决定，不从名字、内容时间或 SQL 自增号猜最后一次成功。


## 唯一 DDL 与互操作样本

[唯一 DDL](../src/system/schema.sql) 定义 `application_id=0x5A585331`、`user_version=9`（本次重建候选，尚未联发）。初始卷组三表：`operation` 保存原操作/主体、规范请求摘要和阶段；`pool_birth` 保存一次初建的 PoolId、稳定服务 UID、原批准关联和组大小；`volume_claim` 保存这次领出的有序各卷、真实组件上限与一次性非秘密 32 字节认领标识。同一 DDL 还包含两种固定协议身份、分开的凭据、普通根共享/模式、首笔普通根 FILE 出生与首份工作修订；没有逐用户 ACL。工作原单 `kind=10` 只抬同一 FILE 的已确认物理端点；手动节点 `kind=11` 只冻结准确的旧已确认平图，不产生全量拷贝。打开新一轮不读或生成 FULL，直接继承原已冻结平图。真实每 FILE 写柄保同一独立 OFD 排他，读柄不取它；重复 SAVE 不另建 DATA/checks。连接中断后新原票若要抬旧轮物理起点，须先同步同一对已观测原尾；不同未确认新轮只保已观察的私名，不固化并未落盘的占位。管理 HTTP 只为一次明确选中的 FILE/工作版本提交任务，保会话、同源与 CSRF，另由一个有界 worker 在原 S 下核原 FILE；超期、注销或停机在最终授权切前挡住。此源码仍未联发或运行，不代表现行 SMB 可写。实际只读开户以同一读事务核确切 schema，而不只看版本号。同一行状态 `0=pending I/O` 与 `1=committed` 区分未决观察/已完成回执，磁盘是否目前可用不写入这个历史结果。创建初始组用同一事务执行 DDL 和所有 INSERT；若在既存库读出不全的 pending 或公有字段不合原请求，拒绝做任何介质动作，不补生成 ID、不补齐表。不要执行 `IF NOT EXISTS`、`OR REPLACE`、自动建库或另存原单。SETUP_PAIR 不是 INIT，不兼容旧首管管理档。新池只接受此确切 schema，不迁移或回退早期研发关系模式。

**v9 DDL。** SMB 只存非秘密身份和原操作，历史业务引用继续有效；当前代不得跨过较新的待办。原 v6/v7 不作后备。数据库没有证明 Samba 原件已同步或网络已验密的能力。

**请求与结果分开。** INIT=1，独立离线主体与这次授权范围经另一路真实验证后，原输入为 `"ZXS-SQLITE-1/INIT\0"|OpId[16]|actor[16]|approval_ref[16]|storage_uid:u32be|root_count:u16be|(role:u8,path_len:u16be,canonical_raw_path)*`。标识均为原二进制，字符串末尾是一个实际 NUL。角色依次 S=0、R=1、其余每项 F=2；3…64 个互异非嵌套根，普通根按原始路径字节严格递增，不比较区域设置。稳定存储属主 1…4294967294；绝不拿这个 UID 或原请求摘要代替维护认证。路径、组件、深度须在实际能力内。**只有 S 的管理路径**还须可无损作为 UTF‑8 交标准 VFS；选定 VFS 的 `mxPathname` 必须容纳实际 DB 和 `-journal` 名（保守计终止 NUL）并与根的真实几何相容，首建预留之前验证，不给 Linux 4096 字节一刀切或改名绕过。R/F 用原 BLOB，允许非 UTF‑8。完全相同的原请求即使丢过首次回答也不需要重给随机结果；已获准的观察者可用[原单查询](../src/system/original-init.sql)找回原 PoolId/状态，再在同一短读事务取得[原始各行](../src/system/initial-catalog.sql)。异主体/输入或同号冲突拒，未获准不披露；查询无行不能发行新号。初生 PoolId、VolumeId、每行认领标识和当时实测组件上限仅一次写入，不能重抽，均不计入原请求 SHA-256。

**现场标签不是数据库。** 仍只用每个 S/R/F 根原已保留的 `.zxs-new-ffffffffffffffffffffffffffffffff-0`，但 SQLite 新族仅承认 101 字节 `"ZXS-SQLITE-1/VOLUME\0"|role:u8|PoolId[16]|VolumeId[16]|claim_op[16]|claim_token[32]`，无旧 103B 变体、GENESIS 摘要或平行前沿。先在已知 S 核数据库内原池/原认领行和指定 S 真标签，再按需核指定 R/F；单读标签绝不发现池或授权写。领用时每个根真实无未知物、受保护、下级无替身、独立 R、无覆盖、原件曾落盘且可靠，须由持全组 EX 的离线实现正面验证；DB 不能验证这些。两阶段之间 SQL 重读完全相同的行，最终执行[条件完成语句](../src/system/complete-initial.sql)；只有返回确切一个原 OpId **并且** COMMIT 成功或恢复查询证明成功，才能发已完成回执。保留错误/不明原件。更多见[固定四根请求与标签](../tests/sqlite/init-v1.txt)。本片没有执行 SQL 或实际建池。内部 `InitialReader` 通过固定的 SQLite 只读接口核已提交的初始卷表；不代办首设、授予 FILE 权或证明在线/离线互通。账号/凭据及同一原单的准确参数、规范样本与认证核验见[SQLite 首管](first-account-v1.md)。

### 当前已接入的只读源码

`InitialReader` 直接打开真实的 `SYSTEM.sqlite3`，只用固定上游标准 Unix VFS 的 READONLY/NOFOLLOW，不调用旧登记、helper 或裸文件读取 DB。先持实际可信 S 的独立长 SH，用不打开文件的 statx 对 DB/控制名检查，SQLite 自己确认 DB 未换名；空闲时不持 SQL 事务。每次短读在同一事务读取 ID/版本、精确的 sqlite_schema 及原始各行，并独立核 S 的卷标/权限/组件上限。不在这里打开缺席的 F 或 R，也不把这次元数据读取说成那些盘在线。为避免靠手抄 SQLite 内建索引名字或自写 SQL 解析器判 schema，在每个观察者的第一次实际读事务**之前**，临时内存连接仅执行一次项目内固定公开 DDL，按 SQLite 原生生成的类型、名称、归属表和定义（含 NULL、字节长度、顺序与总数）取模板摘要后即关闭。没有用户行或持久文件，不 ATTACH。每次短读仍从当下同一业务库事务重取实际 schema 比对，绝不缓存一次“曾经正确”来授权后继。该引擎编译时排除 WAL（`SQLITE_OMIT_WAL`）：若现有 DB 记录 WAL 读版，即使没有 -wal/-shm，也由 SQLite 自己拒绝，不为查模式创建两个附属文件。不能仅靠 READONLY 或目录预扫达到这一点；不裸读页首、不动态切模式。错误、热日志需恢复、未完成 INIT、未知表/控制物都不给业务准入。每次容量采样先取一个新的已确认 SQL 切面，按 VolumeId 选择**一个普通卷**，放开 SQL 事务后在已登记原始路径保留实际目录 SH/原卷标，并用同一 held FD 的 POSIX fstatvfs 读取这个文件系统的总量和可用字节。R 或 S 不走这个入口，R/其它 F 不在线也不用探；它不是盘健康、配额保证、独占物理容量、卷 UUID 或任何账号/FILE 的读写权。在本次已持原根被同名替换时即拒。重新开根则只能核当前受信路径、属主、几何与那一份原 F 标签；即使只复制这个标签到另一合格目录，新的观察也不能分辨，不证明和未打开的 R 是不同文件系统。这个容量及登记观察入口只读，无网络入口。真实非特权目录锁/SQLite 故障夹具只写了源码，尚未运行。

### 首装计划的普通数据盘目录

Helper 以单独的现场批准选择已经确认 INIT 的普通 F、精确目录名和初始只读或读写，并在实际原生账号物料完成后同一 SQLite 事务提交 SETUP、PUBLISH_ROOT 和首个 SHARE_MODE。S、R、未知卷或另一个池均不行。名字是精确 UTF-8 单组件，按原字节比较，不折叠大小写、不做规范化。ShareId、发表 Op 和首次模式 Op 都从批准计划与普通卷 ID 确定性派生；首装之后不能从 Web 另发名或加入卷。计划不以卷正在联网或已起 SMB 为证。

原请求为 `SHA256("ZXS-SQLITE-1/PUBLISH-ROOT\0" | PoolId[16] | OpId[16] | AccountId[16] | credential_op[16] | generation:u64be | VolumeId[16] | label_len:u16be | label)`。绑定的是当前准用的凭据原动作与代次（首代为 1），ShareId 是该计划限定的一次性身份。初始提交以首设 Web 主体和 gen1 留下 `root_share` 与 `operation(kind=3,state=1)`，同一事务另写首个明确模式。旧回执只供对照，不恢复已改过的模式或给未选卷加权限。例：Pool=04、Op=81、账号=55、credential_op=44、Volume=13（各为该字节重复 16 次）、标签“报告”，122 B 预像的 SHA-256 为 `d2385e10d25e4681b83926ab28134d2c3fa82751845c480d6b4c4f5481016d06`。

单独的 kind3 只建立定义，无首模式即停用。实际首装同笔写足 kind4，随后 Web 只管理已选盘模式；Web 管理身份不能因此浏览或读写 FILE 正文。没有新用户或逐人 ACL。

### 唯一 SMB 账户的共享模式

管理者通过 `set_installed_mode(OpId, ShareId, 原模式操作, 新模式)` 更新首装已选目录的配置；没有用户参数，也没有逐人 ACL。没有变更时就是停用、revision=0、原模式操作就是发布 Op。模式 0=停用、1=只读、2=读写。每次真实变更须以最新原操作作前驱、修订号精确加一，并将模式与原单在同一短 SQLite 写事务内提交。不重新授权同一原回执：例如 RW→RO→停用后查原 RW 单最多得到当时结果，共享当前仍停用；重新启用产生新的模式代。重复设置相同模式不是新动作。

原请求 SHA-256 的字段为 `"ZXS-SQLITE-1/SHARE-MODE\0" | PoolId[16] | OpId[16] | WebAccountId[16] | credential_op[16] | generation:u64be | ShareId[16] | previous_setting_op[16] | mode:u8`（域末实际是一个 NUL）。`share_mode` 与 `operation(kind=4,state=1)` 同笔；任何错误或 COMMIT 结果未知只按原单核实。管理查询/回执不返回密码，不能变成 SMB 句柄；真实 SMB 操作仍必须由已验证 SMB 登录并核当前模式。所有已选普通卷仍只出现在同一个 ZXS 业务共享下；更新目录模式不产生别名，不复制文件，也不开放来宾。

### 普通根的首个 FILE

`CREATE_ROOT_FILE` 只受理读写共享。一个共享没有一份独享的文件树：同一普通 VolumeId 上相同 UTF‑8 拼写不能通过两个共享重复创建；大小写不同是两个名字。业务输入是原 Op 和精确显示名，不是本机路径。原请求绑定池、SMB AccountId、已验证的凭据原操作与代次、ShareId、模式原操作、普通 VolumeId 和名字；新生成的 Entry/File/History/BranchId 及物理票只做本单结果，不参加重试输入。只读共享可在其当前模式下重开已经发表的同一根成员，不能 CREATE。停用或改代后旧会话不会变成新许可。实际原生 CREATE 须先获得本次真正的 share-mode 条目并从同一私有句柄送回确切完整 FileId，才允许做下述原单与实物。网络已接真实已验证会话；仍未进行实际客户端验证。

1. 独占所选实际普通根的目录 OFD，检原卷标、实物名称、登记中的 R 几何和真实目录枚举预算，不要求 R 在线。先在短事务为准确原请求写 `root_entry` 和 `operation(kind=5,state=0)`。这一行不表示 FILE 已存在；名字被该卷留给原单，不能由别的共享占用。
2. 不持 SQL 事务备料。仅在一个新建的私目录里独占创建普通头文件，写入并同步。父中已有私名语法的第七槽作该头文件的普通硬链接（不另存正文）。双名指向同一真实私有受保护对象、与 SQL 原操作及完整 FileId 等字段相符后，才向派生终名不覆盖更名并同步父。中断于仅有私目录／半头且不能证明原双名：保留现场，只报未完成，不接管、不滚动重抽票，不挡另一正常名字。没有跨故障辨认全部标签与两名同时被一致替换的承诺。
3. 在另一个短事务重验同一 SMB 凭据与共享模式、准确原单、现场普通根/头及双名，再将原单从 0 改为 1。已完成但丢响应按相同原请求返回同一身份；这不证明现在有盘。要打开 FILE 必须另按当下允许的共享、准确的名字和 FileId，在该卷冷核原件。出生是无正文的手动 FILE，没有版本节点；实际工作 SAVE 是下面另一笔原单。资格源码：[SQLite/普通文件](../tests/unit/sqlite_create_file.rs)，未执行。

## 首份工作修订

具名独立回读与已确认的正文读取共用一个固定的直接区间视图。首稿仍以原 SAVE 的一份已发行实料在内存构造首图；逻辑长度和范围选点从这份图读取，不以物理 EOF 或后来发布的工作头替换它。这条首稿路径与既有原回执不变。正文与校验表共用同一个验段器，先分别限在已选的物理起点与截止处；段的末校验块按该段原长，不按后续追加后的文件 EOF。现役整件入口仍要求原有两件精确长度；非零段的源码例不是发行许可。

重建中的 kind 10 `work_edit` 保存同一 FILE 确切前修订、工作轮、当时最新手动父、真正写柄、当前共享与凭据，以及实际新增正文/校验与直接范围表的两个窗口。待决不改 `selected_work`；只有仍是同一原前驱和最新原票才能升为确认。单一确认视图取当前 round 和 revision，不能从目录或物理 EOF 倒推。kind 11 只由当前 Web 管理员明确发出，对已确认 work 的同一轮至多一个节点；它引用精确 SAVE 和父，不复制正文。发出节点后第一次实际改动才可在新 round 起始位保留物料；接着同轮继续改，不需要 FULL。原生 WRITE/FLUSH、正常脏 CLOSE 与明确的 Web 手动提交均消费同一工作图及授权，不引入独立持久表示；本候选未运行，不支持从旧模式升级。

`FIRST_WORK=6` 只接手动提交制 FILE 的未保存→工作 revision 1；0 B 的确切首次 SAVE 也有回执。它不产生 NodeId、VersionId 或全量复制，不在每次写入后新增一个正式历史文件。继续编辑使用 WORK_EDIT=10；首个及后续逻辑轮的原叶选择见手动工作范围。原 Web 管理员没有此权，不为 SMB 客户端增加专有 SHA/Op 字段。

1. 在当前独立 SMB 账户、原凭据代和这一共享的同一次 SQLite 切面选原普通卷及已完成出生的 FILE。由服务端实际持有的已完成接收的普通输入 FD 测得长度、平面 SHA-256 和原块表目录承诺，不从用户路径或自报 SHA 发票。读慢输入不占 SQL。原请求为域 `ZXS-SQLITE-1/FIRST-WORK\0`、池/本 Op/SMB 账户/凭据 Op、代次 u64be、ShareId/设置 Op/VolumeId/出生 Op/EntryId/FileId/HistoryId/BranchId、原工作代 0u64be、尝试序号 i64be、一个标记字节（有前一未确认尝试时为 1，跟其 16B Op，否则为 0）、原尝试留存角色的 1B 位图（数据/数据证/块表/表证依次占低四位）、输入长度 u64be、32B 平面 SHA、32B 块表目录承诺（ID 均 16B；域末一个 NUL）。临时 FD 不是经操作系统加了写封的声明，前后会在同一 FD 重验字节与现场状态。未发行前真实容量检查是当时的普通盘余量，不保证日后写入；实际写/同步失败不会返回成功。
2. 短事务先留这同一 FILE 的一张 `first_work` 和原 `operation(state=0)`。持本 FILE 的排他目录锁、真实普通根及系统服务 SH，但不持全普通卷写锁或长 SQL，才在确切容器创建该原 Op 第 0 项的已有普通材料角色：`change-` / `pin-data-`、`checks-` / `pin-checks-` 加原 Op 和槽。每一对是本地同 inode 的普通硬链接；不用跨盘链接、专属 FS、单独的版本索引或额外一份持久正文。只允许准据相同、双名均能证明的未完成项逐字比现有前缀再补尾。不覆盖异字节、孤立单名或未知物；不能证明的保持原单未决，不阻无关 FILE。
3. 两个普通文件及父同步，从真实名字独立重开、核对还是刚写的同对原件，逐块验全正文和输入平面摘要后，再短事务核本凭据、同一 RW 设置/原父、原 FILE、材料集和原 Op，原子转为已确认。中途撤权不发布。当前仍有效的原单只有原请求可继续；只有其原 RW 设置已变且首稿仍未确认，才允许当前确实拥有 RW 的同一专用 SMB 身份，以新 Op/新输入在原 FileId 接替。原尝试不能复活或覆盖。原 SQL 保留不可分叉的尝试链，在本 FILE 排他下只记录当时确实存在的最多四个原角色名；残件原样留下，不打开、不收养、不删除，也不假称已腾出空间。没有落下材料的尝试不占物理名额。新发前给所有保留名及新四名核确切枚举上限与当前剩余容量；名额或盘满在确认前拒，后续原物清理须另有明确授权，不冒充自动回收。原单热/冷可区分已完成、未完成和无权。已完成丢响应可单查原结果；若重送实际数据，同号异内容/不同文件不获承认。
4. 允许的只读或读写共享都能单独按**准确业务名**冷开当前修订，保留真实 F、FILE/头与原数据/块表 FD、S 服务租约到最后的 flush。未确认工作不变成可读字节；已保存空稿与从未保存的 0B 文件在修订上可区分。新范围只读取相交的完整校验块，块核验通过才裁剪输出；已交前缀不重发。短 SQL 选择、保留原件与后续重新验权分开；没有把 SQLite 读事务留在慢 sink 中。

[断点与冷开源码](../tests/unit/sqlite_first_work.rs)只把真正的 SMB 成功认证事件作为测试边界，不代理 Windows 会话、网络协议或 helper 安装器。未运行程序、数据库或测试。

## 交付顺序

1. 冻结本设计和两产品边界。第一项实现是唯一规范 DDL、连接准入与明确初始化/打开现池的区分；helper 独立照同一 schema/行为向量实现。先正向证明空池/实际卷角色与他池/错父/DB 缺失/热日志拒绝，再接存储身份、账户/共享和当前授权。没有任何自动迁移与双写期。
2. 在同一次实际授权切面选 FILE 与材料，接普通 SAVE/元数据操作的原回执，再接手动提交、跨盘/清源的带条件事务。复用已审的材料/区间/块读与独立全写读回；旧的 FILE 小日志或 CLI 只作历史检验基准，不作产品备选写者。旧自研 SYSTEM 模块/驱动从产品构建和开放入口退出；不使一个池同时可被两种后端开户。
3. 最小源码反例：热日志下纯检查不修库；S 换挂/不同库同名拒，在线事务已空但仍有慢读时，独立 open 的离线 EX 必忙（dup 不是竞争者）；无对外授权的首管不能读；同父完全同名 FILE/目录不撞穿。材料同步前、具名同步后 SQL 前、COMMIT 未知、已入库但响应丢失、源清退中分别冷接同一 Op；同盘改一名后撤权，只按已批准原单收尾；手动区间尾部未选时旧半块仍可读；写者/普通根掉线时兄弟继续。在一个工作轮内重复覆盖十笔，再显式手动提交，检查原结果与真实数据，C→D 仍有引用时不清；分别记录数据库页面/等锁与文件读写，不把逻辑成本当实测。
