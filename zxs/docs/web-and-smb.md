# Web 管理，SMB 传输文件

ZXS 只有两个在线产品入口，职责不对称。Web 是管理界面；SMB 是普通文件的目录及数据接口。没有产品业务 CLI。已编写[管理 Web 的登录、会话和共享表单](web-management.md)，经单独 TLS 前端的受保护本机套接字连接同一 SQLite 管理主体；没有直接对外的明文端口。Samba VFS、实际部署和真实客户端互通尚未完成。开发验收驱动不是产品接口。

## Web 的第一条真实路径：登录后查看和管理

1. 通过 TLS 或受保护的可信终结链路登录，只核当前 SYSTEM 的唯一 Web 管理员、启用状态和凭据代次，再签可撤销的短时安全会话。服务从受保护的配置选原池；浏览器不能提交原生路径、伪造 UID 或以账号名代替授权。后台会话在服务重启或过期后失效；首设/重置不是 Web 登录动作。
2. 只向**唯一 Web 管理员**返回固定账户的非秘密设置、共享配置、系统/磁盘状态以及版本元数据（例如节点、父、标签、提交时名称和时间）。查询和命令都要核本人当前权限、确切的池/对象；版本元数据权限不是 SMB 正文权限，首管也不因此能读全部 FILE。适用的显式版本管理命令独立绑定原操作，重试不重复发表。
3. 状态分别标明来源、时间及已登记/在线/就绪/待清/未知。ZXS VolumeId 不当成文件系统 UUID；无真实健康/速率样本不显示为健康或零。写管理动作须防 CSRF、处理撤权与并发；回执同样受授权。停机维护、首设/密码恢复、磁盘配置、systemd 仍由独立 helper 承担。
4. Web 不提供普通文件内容上传、预览、下载、分块转发或临时链接。管理 HTTP 请求当然可以有表单/JSON 并返回页面或元数据，但没有打开 FILE 正文的 handler、静态根映射或兼容 URL。

## SMB 的第一条真实路径：按共享打开和读取

只接受真正 Samba 验证的唯一 SMB 用户，准确匹配原受信域、SID、AccountId 和当时凭据代次；guest、匿名、错误凭据、Web 身份一律拒，不能据此列出任何共享。再核已启用 ShareId、只读或读写模式、确切普通卷根或已安装 DirectoryId 及可见成员。在同一原 SYSTEM 切面验证授权、父名录、EntryId/FileId 和所选材料，不能先拿许可布尔值再按另一个前沿重开。不同协议身份、同名兄弟、错池/错代次、SYSTEM 与回收原件都不得借读。不把宿主目录直接共享，未知或未实现的操作不能绕为 POSIX 直通。

**禁匿名验收不是一项。** 固定实例须读取运行中的有效配置：全局 `map to guest = Never`、`restrict anonymous = 2`、仅允许合格的强认证；所有 ZXS 共享 `guest ok = no`、`guest only = no`，没有另一个 guest 可用的共享或账号后备。用互不共享凭据缓存的全新 Windows/SMB 会话分别验证：① 已知 SMB 用户输错密码、未知用户和 Web 管理员尝试登录均不映射来宾；② 完全不带凭据的新会话不能访问 IPC$ 或列举共享，直接猜共享名也无权；③ 唯一有效 SMB 用户能在启用的共享按 RO/RW 做相应操作。核实际拒绝而非只看配置文件。参见 [Samba restrict anonymous](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#RESTRICTANONYMOUS) 和 [map to guest](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#MAPTOGUEST)。以上仅待运行的资格条件。

客户端看到业务名和当前内容，不见物理 FileId 后缀。大小写敏感，要求已采用的 Samba 实例实际配置为 case sensitive = yes（非默认 auto），由真实客户端分别列/读 Report.xlsx 和 report.xlsx；全大写错名不得命中。[Samba 配置文档](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html)。跨进程 VFS 只在受控的本机对端与已验证会话之间移交不透明业务句柄，不传 argv、任意环境变量或原路径作权限。

打开持真实目录/正文、工作或历史边、当前位置和 原 S 目录共享锁；按 offset 多次读不能随新版本改换已选材料。正常打开选当前稿，不能因为非空首次工作稿还缺准确的有界随机读，就改读上次正式版本。已有 PublishedVersion::open_listed 是显式固定已发表 Node 的**业务内核**，不是普通 SMB 当前读的退路，也不是网页接口。保留其真实节点、材料校验、范围/空区间、慢流与最终 flush 的原锁。读/写、设置 EOF、追加/裁短、FLUSH、CLOSE 和冷重开各核其原句柄；写入和关闭都不虚构正式提交，不要求正常 SMB 客户端提交私有摘要或 OpId。

## 排空与验证（均未运行）

在线服务含空闲期持续持原 S 目录共享锁；先停管理请求和 SMB 新准入，再排空已接工作、完成必要同步或明确失败，最后释放原物。短 SQL/卷观察不跨慢客户端。宿主 unit stopped 不证明仍在的读者/写者已放锁。

- **先保业务证据。** 现有四个通过 `CARGO_BIN_EXE_zxs` 的源码夹具：`formal_receipt_cli.rs`（原提交/错误票/离线回执）、`ordinary_directories_cli.rs`（父、FILE/目录同名、原物）、`recycle_cli.rs`（删还和原单）、`two_increments_cli.rs`（A/B 编辑、F0/I1/I2、五件跨卷和原单往返）。逐个迁为直接调用实际库、保留冷开及真实持有物的夹具；原来依赖进程退出/丢 FD 的裁切不能只换一个同进程函数调用，须保留窄测试进程/分离 OFD 证明其实际要求。不保 stdout/argv 兼容或为用例新增产品命令。

- **分别验适配。** 浏览器验登录、越权/撤权、账户/共享配置、真实状态与获准的版本元数据；请求普通 FILE 字节的路径不会给出正文或泄漏原路径。真实 SMB 客户端验同名不同 FILE、大小写、权限、打开/offset/EOF、断连、原材料改变、重开及真实写语义。一个协议的假调用不是另一协议的证据。

- **随真实接入退役。** 对应在线路径与库级验收接替后，删除原业务 argv 分发和只有字符排版意义的断言，不另留隐藏或不支持的兼容 CLI。ZXS 留真正在线协议/启动/排空、故障离线及正常下线。helper **独立实现**停机后核原池/卷/容器、查询准确原操作结果、诊断及基于原单的有限恢复；只读查询不自动续写，任何维护写须同一原 S 目录 EX 和必要的真实卷根排他。首次设置/盘初始化、加入、转换、永久退登记、管理员重置和宿主服务控制仍属 helper。双方用同一 SQLite 模式与原操作，独立实现、现场验证后才开放；不复制日常 FILE 服务。
