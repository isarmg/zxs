# Web 管理，SMB 传输文件

ZXS 只有两个在线产品入口，职责不对称。Web 是管理界面；SMB 是普通文件的目录及数据接口。没有产品业务 CLI。已编写[管理 Web 的登录、会话和共享表单](web-management.md)，由默认监听所有 IPv4 接口的原生 HTTP 验同一 SQLite 管理主体；不要求证书或域名，HTTPS 由用户可选的外部软件提供。受管 Samba 和普通文件路径已有源码；实际部署与客户端互通尚未验证。开发验收驱动不是产品接口。

## Web 的第一条真实路径：登录后查看和管理

1. 浏览器默认直接走 HTTP（应使用可信网络），或经明确绑定的外部 HTTPS 代理登录，只核当前 SYSTEM 的唯一 Web 管理员、启用状态和凭据代次，再签可撤销的短时安全会话。服务从受保护的配置选原池；浏览器不能提交原生路径、伪造 UID 或以账号名代替授权。后台会话在服务重启或过期后失效；首设/重置不是 Web 登录动作。
2. 只向**唯一 Web 管理员**返回固定账户的非秘密设置、共享配置以及版本元数据（例如节点、父、标签、提交时名称和时间）。磁盘信息与诊断使用 [Helper](../../helper/README.md)。查询和命令都要核本人当前权限、确切的池/对象；版本元数据权限不是 SMB 正文权限，首管也不因此能读全部 FILE。适用的显式版本管理命令独立绑定原操作，重试不重复发表。
3. 共享只显示逻辑标签、VolumeId 与当前停用／只读／读写设置，不以这些字段推断实际物理挂载状态。写管理动作须防 CSRF、处理撤权与并发；回执同样受授权。停机维护、首设/密码恢复、磁盘配置、systemd 仍由独立 helper 承担。
4. Web 不提供普通文件内容上传、预览、下载、分块转发或临时链接。管理 HTTP 请求当然可以有表单/JSON 并返回页面或元数据，但没有打开 FILE 正文的 handler、静态根映射或兼容 URL。

## SMB 业务入口：一个总目录

只接受真正 Samba 验证的唯一 SMB 用户，准确匹配原受信域、SID、AccountId 和当时凭据代次；guest、匿名、错误凭据、Web 身份一律拒，不能据此列出任何共享。再核已启用 ShareId、只读或读写模式、确切普通卷根或已安装 DirectoryId 及可见成员。在同一原 SYSTEM 切面验证授权、父名录、EntryId/FileId 和所选材料，不能先拿许可布尔值再按另一个前沿重开。不同协议身份、同名兄弟、错池/错代次、SYSTEM 与回收原件都不得借读。不把宿主目录直接共享，未知或未实现的操作不能绕为 POSIX 直通。

**首装及唯一入口。** 新池按同一套 ZXS/Helper v11 成对供给。Helper 在终端明确选定实际 LAN、数据盘、目录名及初始只读或读写，并核首次可用的独立回收盘和回收目录名；同一次原账号确认事务发布这些目录，不要求再登录 Web 开启。专用 smbd 仅在每个批准地址的 TCP 445 对真正 socket 验证后才发送监听回执，而且每个连接的对端须落在那个本地地址批准的前缀。监听回执不证明登录、列文件或读写已经实测。

客户端访问 `\\服务器\ZXS`，每个已选数据盘都是其中一个一级目录；只有这个业务共享，不提供逐盘别名或真实宿主路径。盘、真实子目录和文件的逻辑名均按原 UTF-8 字节区分大小写；同一个普通父下，目录和文件不能占同一名称。Web 只能改变首装已选目录的模式，不在线新建共享。停用或改代不让旧请求/句柄拿到新权限。同树回收目录按原删除单区分轮次，允许枚举、读取和到实际可写数据盘或已发表子目录的原生同树还原，不覆盖。物理 R 从不直接共享；R 暂不可用不拦已验明的普通盘。原生 IPC 不是业务入口。

**禁匿名验收不是一项。** 固定实例须读取运行中的有效配置：全局 `map to guest = Never`、`restrict anonymous = 2`、仅允许合格的强认证；所有 ZXS 共享 `guest ok = no`、`guest only = no`，没有另一个 guest 可用的共享或账号后备。用互不共享凭据缓存的全新 Windows/SMB 会话分别验证：① 已知 SMB 用户输错密码、未知用户和 Web 管理员尝试登录均不映射来宾；② 完全不带凭据的新会话不能访问 IPC$ 或列举共享，直接猜共享名也无权；③ 唯一有效 SMB 用户能在启用的共享按 RO/RW 做相应操作。核实际拒绝而非只看配置文件。参见 [Samba restrict anonymous](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#RESTRICTANONYMOUS) 和 [map to guest](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#MAPTOGUEST)。以上仅待运行的资格条件。

客户端看到业务名和当前内容，不见物理 FileId 后缀。大小写敏感，要求已采用的 Samba 实例实际配置为 case sensitive = yes（非默认 auto），由真实客户端分别列/读 Report.xlsx 和 report.xlsx；全大写错名不得命中。[Samba 配置文档](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html)。跨进程 VFS 只在受控的本机对端与已验证会话之间移交不透明业务句柄，不传 argv、任意环境变量或原路径作权限。

打开持真实目录/正文、工作或历史边、当前位置和 原 S 目录共享锁；按 offset 多次读不能随新版本改换已选材料。正常打开选当前稿，不能因为非空首次工作稿还缺准确的有界随机读，就改读上次正式版本。已有 PublishedVersion::open_listed 是显式固定已发表 Node 的**业务内核**，不是普通 SMB 当前读的退路，也不是网页接口。保留其真实节点、材料校验、范围/空区间、慢流与最终 flush 的原锁。读/写、设置 EOF、追加/裁短、FLUSH、CLOSE 和冷重开各核其原句柄。SMB 协议没有通用的 Ctrl+S 事件。普通 WRITE/SET EOF 只改原写者私有暂存，写者读自己的变化；对端真正成功的脏 FLUSH、需要写穿的写入、或带未确认变化的正常 CLOSE 才是相应确认边界。先按同一旧基线、实际变更和原单持久确认，再给该次操作成功；普通 WRITE 返回接受的字节数不等于发布节点。干净的 FLUSH/CLOSE 不产生新工作修订；已确认的 flush/写穿不释放仍打开的写者席位。不要求客户端提供私有摘要或 OpId。上述 SMB 操作从不发表节点，只更新本轮同一个增量。只有另行明确的手动提交才冻结本轮。断线不是应用的正常 CLOSE：停止准入、让旧写者不能再写并收尾或使已派发的操作失效，绝不把没有确认的暂存谎报为已发表；已提交但丢响应只能按服务端已绑定的原单回查。

## 排空与验证（均未运行）

在线服务含空闲期持续持原 S 目录共享锁；先停管理请求和 SMB 新准入，再排空已接工作、完成必要同步或明确失败，最后释放原物。短 SQL 事务不跨慢客户端 I/O。宿主 unit stopped 不证明仍在的读者/写者已放锁。

- **先保业务证据。** 现有四个通过 `CARGO_BIN_EXE_zxs` 的源码夹具：`formal_receipt_cli.rs`（原提交/错误票/离线回执）、`ordinary_directories_cli.rs`（父、FILE/目录同名、原物）、`recycle_cli.rs`（删还和原单）、`two_increments_cli.rs`（A/B 编辑、F0/I1/I2、五件跨卷和原单往返）。逐个迁为直接调用实际库、保留冷开及真实持有物的夹具；原来依赖进程退出/丢 FD 的裁切不能只换一个同进程函数调用，须保留窄测试进程/分离 OFD 证明其实际要求。不保 stdout/argv 兼容或为用例新增产品命令。

- **分别验适配。** 浏览器验登录、越权/撤权、账户/共享配置与获准的版本元数据；请求普通 FILE 字节的路径不会给出正文或泄漏原路径。真实 SMB 客户端验同名不同 FILE、大小写、权限、打开/offset/EOF、断连、原材料改变、重开及真实写语义。一个协议的假调用不是另一协议的证据。

- **随真实接入退役。** 对应在线路径与库级验收接替后，删除原业务 argv 分发和只有字符排版意义的断言，不另留隐藏或不支持的兼容 CLI。ZXS 留真正在线协议/启动/排空、故障离线及正常下线。helper **独立实现**停机后核原池/卷/容器、查询准确原操作结果、诊断及基于原单的有限恢复；只读查询不自动续写，任何维护写须同一原 S 目录 EX 和必要的真实卷根排他。首次设置/盘初始化、加入、转换、永久退登记、管理员重置和宿主服务控制仍属 helper。双方用同一 SQLite 模式与原操作，独立实现、现场验证后才开放；不复制日常 FILE 服务。
