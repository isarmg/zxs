# Web 与 SMB：先打通同一份普通 FILE 的读取

**现状与边界。** 产品入口只有 Web 和 SMB。库中已有带类型的普通父、FileId、历史、范围读、原操作与唯一 SYSTEM 决定；`src/main.rs` 是会实际读写的过渡验收分发器，不是服务、稳定 RPC 或兼容承诺。尚无网页、HTTP listener、Samba VFS 模块、网络账户签入或两协议互操作证据。本设计不添加业务 CLI；服务内部的启动、排空与停止是生命周期，不是给用户执行文件操作的一套 CLI。

## 首个双方都能验收的路径（待实现）

一个已授权用户打开同一已发布普通共享，在浏览器里逐层进入目录并查看／下载一份 FILE；在普通 SMB 客户端对同名对象完成列举、打开、按 offset 读及关闭。两边看到准确的业务名和同一当前正文，只呈现可见成员，不泄露真实容器名、物理挂载路径、私槽、回收或 SYSTEM。此批只读；不可冒充已交付写入、办公软件保存或全部 SMB 协议。目录列表、空文件和合法 EOF 是成功；卷不可用、无权限、实体未证、未知条目或范围错误不能伪装成空目录或零字节。

1. **真实主体和共享绑定是放行门。** 对外不传 SYSTEM 路径或信任请求自述的 UID、FileId、用户名。后台从受保护的服务配置选择同一真实池；Web 会话、SMB 已认证会话各自映射到同一 SYSTEM 账户、授权范围和撤销代次，再把准确共享映射到普通 VolumeId＋根／已安装 DirectoryId。存储属主 UID 与远端主体分开。打开、枚举、复用句柄和任何查原回执须受主体/共享/FILE 可见性约束；撤权阻断新读，不将既有句柄或历史结果作为新许可。账户/授权、受信共享映射和会话撤销来源尚未闭合之前，外部入口关闭，不用本机特权替代。两个账户同名、同服务 UID、猜到别人的 ID/操作号也不能串读。
2. **一个目录选择、一个冻结的读句柄。** 在同一原前沿，用普通父/原拼写逐级查 EntryId 和 FileId；打开时绑定账户、共享、原 FILE、位置、确切工作边或正式节点、长度与原材料。一次 SMB 打开的后续 READ 反复用这个句柄，不按路径或“最新 revision”重开；同时保存也不能中途换字节。Web 同一响应共用一个选件，后续请求用确切版本验证器区分两个不同选择。当前可核的小范围读支持已发表 FULL、INCR 和已确认的区间组合；第一份未提交的非空顺序工作稿目前只有顺序读。要宣称一般共享可读，须补这种真实稿的有界随机读，不能为了小读扫描/复制整文件或把存在的文件从列表隐藏。
3. **两层薄适配，不造第三个存储。** Web 直接走同一在线业务选件，安全输出原拼写，提供目录视图和正文 GET/HEAD、单段有效 Range；长度、ETag、206/416 及 If-Range 按被选中的同一表示。流已部分发出后遇原件失效则中止响应，不能把截断称完整成功。[HTTP 语义（RFC 9110）](https://www.rfc-editor.org/rfc/rfc9110.html)。SMB 由真实 Samba 处理线上认证及协议；项目仅写匹配所选服务 ABI 的薄 VFS 桥，凭经验证的会话/共享向**同一业务服务**取得不透明目录/FILE 句柄，映射目录列举、属性/打开、偏移读、close 和错误。若在另一进程，限定本机对端身份、会话上下文和 FD 生命周期；不以 CLI 文本或可自由设置的环境变量传权，不重做网络 SMB 栈。不能把物理数据目录直接共享，或在找不到、拒绝、未实现时回退为宿主文件操作。对外大小写敏感，保留原拼写并在共享上要求 `case sensitive = yes` 而非默认 `auto`；禁映射/枚举导致 `REPORT.xlsx` 命中另两种拼写。[Samba 配置文档](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html)。
4. **在线服务和慢流共用原登记生命周期。** 守护期间（包括空闲）、受理的两侧请求、独立尚在的真实读写/同步和最终 flush／close 必须连续持同一原 REGISTRATION 常规文件的共享锁；停准入→排空或明示失败→完成必要同步→释放最后持有。短 SYSTEM／卷事务仍只跨实际事务。当前内核首个慢读切片不能代替全部写、恢复、服务或其他会话已持锁的证据；宿主 reported stopped/active 不证明数据安全。有受保护业务未排空，离线独占必须失败；取不到原持有不以其他盘/同名路径或 helper 代替。

## 此后才接写，不伪造协议动作

Web 的密封上传／工作保存、显式发表、历史、还原与业务状态分别操作。SMB 的 OPEN/WRITE/EOF/FLUSH/CLOSE 作用于实际打开的写句柄；WRITE/FLUSH/CLOSE 不等于显式正式提交。客户端不提供源码夹具的 SHA 或私有 OpId；可信适配器按真实入站字节形成摘要和适用的原请求／重试关系，丢响应不能再发表一次，不把一次网络重试或晚到旧句柄改绑新稿。随机写按已认证变化范围持久化，不能默认重传整个大文件。文件夹改名/整组回收、自动版本和未实现的 Samba 操作逐项开门，不默认绕过后端。公开服务只调用一套有类型业务接口；Web 不复刻 VFS，SMB 不假装每个 Web 管理动作都有客户端对应命令。

## 用例、移交和退出顺序

- **先保业务证据。** 现有四个通过 `CARGO_BIN_EXE_zxs` 的源码夹具：`formal_receipt_cli.rs`（原提交/错误票/离线回执）、`ordinary_directories_cli.rs`（父、FILE/目录同名、原物）、`recycle_cli.rs`（删还和原单）、`two_increments_cli.rs`（A/B 编辑、F0/I1/I2、五件跨卷和原单往返）。逐个迁为直接调用实际库、保留冷开及真实持有物的夹具；原来依赖进程退出/丢 FD 的裁切不能只换一个同进程函数调用，须保留窄测试进程/分离 OFD 证明其实际要求。不保 stdout/argv 兼容或为用例新增产品命令。
- **再验真实适配。** 同一主体经浏览器和真实 SMB 客户端对 `Report.xlsx`/`report.xlsx` 取得不同正文，`REPORT.xlsx` 不误中，另一个受限账户不能列/读/借句柄。验实际 offset/EOF、失联与重开、打开期间新保存仍固定旧内容、关闭后新开才见新内容、名字没有 FileId 后缀；原隐藏项和 R 不可达。真实客户端、Samba 插件/服务版本与同一构建、Web 页面和 HTTP 网络都要独立留证；库假调用、未执行源码或两次命令输出不是通过结果。本轮不实际运行。
- **随真实接入退役。** 对应在线路径与库级验收接替后，删除原业务 argv 分发和只有字符排版意义的断言，不另留隐藏或不支持的兼容 CLI。ZXS 留真正在线协议/启动/排空、故障离线及正常下线。helper **独立实现**停机后核原池/卷/容器、查询准确原操作结果、诊断及基于原单的有限恢复；只读查询不自动续写，任何维护写须同一原登记 EX 和必要的真实卷根排他。首次设置/盘初始化、加入、转换、永久退登记、管理员重置和宿主服务控制仍属 helper。只有明确发布的格式和原实体/互斥允许互认；目前公开 MAINT-1 仅为空池，未发布的普通业务日志/账户或物理状态一律未知，不得通过 stdout、扫描或调用 ZXS 来猜。helper 不另做日常创建、工作保存、正式发表、普通 MOVE 或业务回收；在真正的离线替代和互斥闭合前不偷删唯一维护途径。
