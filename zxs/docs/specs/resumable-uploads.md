# v1 完整文件的分块续传

状态：[仅静态]。服务端入口已接入正式监听；安装后的真实流式 HTTPS/HTTP/2 仍待验。供客户端与验收维护者使用。
前置：已验证的 HTTPS/HTTP/2 门面与[当前单账户会话](sessions.md)。此方案只增加显式续传，不改变旧 R3 整文件入口、原操作回执、磁盘路由或[正文读取](payload-range.md)。

## 请求

根路径为 `/zxs/v1`。请求都须恰好有一个 Bearer 授权头及一个 `Zxs-Op-Id`。旧 `Zxs-Operation` 不作别名。标识 C、O、N 和非 `main` 的分支号均为 32 位小写十六进制，不能全零；U 为 64 位小写十六进制的不透明非零上传号。客户端不自行构造 U，凭 U 不能获得授权。

| 方法与路径 | 正文与额外要求 |
| --- | --- |
| `POST /uploads` | `application/json`，恰好 `container_id,node_id,target,length,sha256`；显式声明原意图。 |
| `GET /uploads` | 不带查询或正文，须带 `Zxs-Container-Id: C`。只按精确 C/O 读，不列举上传；适用于首次回答丢失、尚无 U。 |
| `GET /uploads/{U}` | 不带查询或正文，须带 `Zxs-Container-Id: C`；在同一个 C/O 下额外核对 U。 |
| `PUT /uploads/{U}?offset=B` | 须带 `Zxs-Container-Id: C`、`Zxs-Chunk-Sha256`、`application/octet-stream` 与精确 `Content-Length`；B 是从零起算的规范十进制偏移。 |
| `POST /containers/{C}/commits` | `application/json`，仅有 `{"upload_id":"U"}`；原 C/O 必须一致。 |

JSON 控制正文上限 4 KiB，必须有唯一、非零的规范十进制 `Content-Length`。字段不区分顺序，禁止重复、额外键、第二份 JSON 或尾随非空白。GET 长度省略或恰为 0。禁止内容编码、传输编码、Range、Content-Range、尾部字段、100-continue、重定向与认证降级。
SHA-256 字段为 64 位小写十六进制。整长为 0 至 1 TiB 的 JSON 整数；零长只能声明空字节串的 SHA-256，起始即 `complete`。

| `target.kind` | 必需且仅允许的其它字段 |
| --- | --- |
| `first_main` | `name`：现有显示名规则，原样 UTF-8，不是盘上路径。 |
| `branch` | `branch`：`main` 或既有分支号；`expected_head`：预期原头节点号。 |
| `historical_main` | `branch`：待新建分支号；`from_node`：精确历史 main 节点号。 |

## 进度、重试与原回执

开始、查询与分块成功均为 `200`、`Content-Type: application/json`、`Cache-Control: no-store`。严格返回 `upload_id,container_id,operation_id,node_id,target,length,sha256,next_offset,state`。
`next_offset` 是已持久化的连续前缀长度，不是收到、写入缓冲或尚未确认的字节数。

- `open`：偏移小于 L；`complete`：偏移等于 L，只有全部分块到齐；`committed`：有当前纪元、同一 C/O/U 的登记证明，且原操作有完全匹配的明确保存回执，偏移等于 L。
- 只能发送已声明的整块或最后一块：B 是 8,388,608 的倍数、B < L，长度恰为 `min(8,388,608,L-B)`。不接受洞、部分重叠、附加字节或错哈希分块。
- 正好从持久偏移写入时，先核对整个分块及当前资格，再同步 DATA 正文，原子发布并同步新检查点，最后回答。已完整确认的旧块如请求正文、哈希与保存的同一区间全相符，只答当前偏移，不重复写、不刷新块。
- 实际已写而检查点未落定的尾部不计入偏移。重开不将其自动纳入；下一次同一未确认整块只覆盖该未确认区间，不能修改已确认前缀。同步报错不会猜测结果，精确查询重证后才可显示偏移。
- 发布成功返回原 R3 `save_node` 回执及其原 C/O、节点、目标、整长、整 SHA、序号，格式不变。客户端在中断或重开时先查询 `GET /containers/{C}/operations/{O}`；上传状态 `committed` 不能替代这份原回执。
- 冷进程未显式登录不发请求；成功登录后可自动只读核对原回执及进度。即使确定没有结果，也不自动发 `POST` 或 `PUT`。用户续作必须验证完整原意图；不用新操作号绕过冲突。

| 未成功 | 含义 |
| --- | --- |
| `400` | 路径参数、正文长度帧、JSON 或必需头无效。 |
| `401`，仅 Bearer 质询 | 授权不存在、无效或已到期；不得自动改送 Basic。 |
| `403` | 当前认证有效、未找到已发布原回执，但原暂存不在当前密码纪元；保留原件。 |
| `404` | 对合规的 GET、PUT 或提交，已核对精确原回执及暂存均不存在；不提供偏移。无此路由的方法也返回 404，但不能用来确定原操作。 |
| `409` | 同号异意图、U 不符、跳过或重叠偏移、已发布后再 PUT，或原头/路由/回收选择冲突。若原回执已存在但没有当前同一上传登记，仍返回 409；只能查原操作回执。 |
| `413` / `422` | 声明超过正文限额 / 截断、入站超时或 SHA 不匹配。 |
| `503` | 已登记盘、空间、登记容量或证据无法确认，或同步、停机状态不允许继续；不是不存在。 |

只有通过授权、帧校验且原回执与暂存均已核实不存在的进度 GET，才在空的 `404` 上附加唯一 `Zxs-Upload-Status: not-found`。未知路由、其它方法及旧服务不带此标记；缺失、重复或值不同均不能判定原上传不存在。原操作回执的 GET 不变。
失败除指定质询外均为空正文、不缓存。不以已有回执或进度绕过本次授权。未完整消费正文或响应的连接关闭；合格交换沿用现有有界顺序复用。新 PUT 原始正文从首读起固定 180 秒，JSON 控制正文 60 秒，均检查停机与会话。8 MiB 整块的最低裸数据速率约 0.373 Mbit/s；不能用低速续送无限延长。旧 R3 排空、全量本地核验和任意磁盘同步不使用这个原始入站限时。

## 原暂存与持久身份

每池最多 16 个未收尾登记，声明整长合计最多 4 TiB，同一 C 同时最多一个登记。异纪元或尚未退休的登记也计入容量，超限返回 503，不替换旧记录。只从原持有且核过挂载的 DATA 取样，扣除新续传尚未写入的配额并保留至少 1 MiB；选择净空间最多的，等值按令牌字节排序。已有 CR1 始终选原盘；没有 CR1 只登记此上传候选，不能占用容器名、建立 CR1 或改变原 R3 决策。空间估计不保证配额或并发旧写入有余量。

- `SYSTEM/upload-intents/{C}` 是唯一可恢复的上传控制记录；新记录需有效授权和已校验的 C/O/N/目标/整长/全 SHA。同一账号由原池与密码纪元绑定；同一纪元重启、重登录仍是同一 U，无需留旧 Token。改密不迁移或接管旧暂存。
- 尚无 UR1 时，创建前要在登记 DATA 上核定同一 U 的正文候选都不存在；发现孤儿或不能确认则拒绝，不另盘重复创建。
- 原正文只在该 DATA 的 `staging/u-{U}/payload`。准备态先在 SYSTEM 同步固定意图、U 对应盘和零偏移；再建立空正文并依次同步文件、DATA 暂存目录及父目录，最后在 SYSTEM 记录原目录和原正文的 inode 与原生创建时间，以原子检查点将其变为已登记。
- 准备态从未答过成功，只能由显式完全相同的开始请求续作。只接纳同一持有盘上的尚不存在、空目录或只有同名 0 字节私有普通正文的准备形状；不替换或认领其它形状。没有精确准备记录，即使磁盘有同名候选也不可使用。
- 已登记态核对盘令牌及两份原生身份：在持有的原 FD 上用 Linux `statx` 取 `STATX_INO|STATX_BTIME`，精确比较 inode 和创建时间。每项还保持当前挂载、权限、命名和 FD 证明；不持久化 `st_dev` 或挂载号。
- 开始前先核对候选盘已持有的暂存命名空间和私有普通记录能提供原生证明。缺失或无法核定只令该 DATA 的新续传不可用，不限制整个服务、原 R3、读取或 Helper。不能用 mtime/ctime 推定创建时间；同盘重挂可重证。
- 已登记正文长度至少为持久偏移，且不得超过该偏移后一块的末端（完整时恰为 L）。超界尾部、原目录/文件替换、坏记录或未知格式均拒绝，不读作缺失。
- 重启旧平面暂存清理不能处理 `u-` 目录。已登记、暂时不可用及旧纪元原件不得因重启、容量、到期或头冲突被删除。无自动过期或删除入口；GET 不退休控制记录或清理正文。

`intent` 的字节序列为 `pool[16] || epoch[16] || C[16] || O[16] || node[16] || length:u64BE || SHA[32] || target`。U 是 `SHA256(b"ZXS upload intent v1\0" || intent)` 的小写十六进制。

| 目标 | 规范编码 |
| --- | --- |
| 首次 | `00 || name_len:u8 || name_utf8` |
| 追加 | `01 || branch || expected_head[16]`；branch 是 `00`（main）或 `01 || branch_id[16]` |
| 从历史分叉 | `02 || new_branch[16] || from_node[16]` |

控制记录为 `UR1\0 || phase:u8 || DATA_token[32] || dir_birth || file_birth || offset:u64BE || intent || SHA256(此前全部字节)[32]`，最多 512 字节，严格读至 EOF。birth 为 `inode:u64BE || sec:i64BE || nsec:u32BE`；纳秒小于 10⁹，创建时间不得全零。
phase 0 的两份 birth 及偏移全零；phase 1 的 inode 非零，偏移按块对齐或等于 L。未知版本、尾随字节、坏记录不自动修复。更新只用同一目录内已同步的私有待选记录，核对精确旧记录和持有身份后原子替换并同步目录。
初见 `upload-intents` 时，即使名称已可见，也须确认该原目录、同步自身及持有的 SYSTEM 父目录，再复核命名，才可使用。
待选名为 `.{C}-0h.incoming`（h 为一位小写十六进制），每个 C 有 16 个槽位。崩溃遗留待选不证明进度，不覆盖或删除；槽位耗尽或清单无法确认时返回 503。

## 发布与验收切点

查询和发布先以原 C/O 读取正式回执。同一现时已登记（phase 1）的正式回执须匹配完整意图，才可答 `committed` 或返回原发布回执。若已发布但原登记已退休、属于旧纪元或不匹配，开始、查询、分块和发布均不从正式回执推造 U，返回空 409；原回执 GET 继续可用。

- 同一 C 的续传锁串行保护登记、分块、完整扫描和发布。网络正文读取不持有该锁；分块前后重证原登记和原文件，只有从确切持久检查点才能推进。进入正式发布时沿用对象锁、再取名称锁，不反向获取续传锁，其他 C 不因原正文扫描被锁住。
- 已读到正式回执的 GET 永不退休控制记录。只有有效的、同纪元同 C/O/U 的显式提交可在正式回执与完整意图一致、并在原持有盘证实原暂存名已不存在后，移除其精确小控制记录；不删除仍存在的正文。

- 从持有的原正文核对确切长度、EOF 及整文件 SHA-256，不以分块摘要代替；保留同一对象引用，但长扫描在容器写锁外并可取消。全进程最多两项完整扫描，与网络分块额度独立。
- 待选回执先完整写入并同步到独立的旧平面私有暂存，再无覆盖送入完整 `u-` 目录中的 `receipt`，重新核对原字节及文件戳，并同步该暂存目录与小回执的原父目录。冷重放只复用严格规范解码、同一完整变更且等于当前拟选序号的原待选回执；合法旧序号冲突，未知内容拒绝，均不覆盖或删除。尚未选中的回执不构成正式结果。
- 沿用对象锁下既有头比较、首次名检查和持久 CR1 顺序。首次 CR1 及创建活动容器目录各自紧邻本机操作重证同一控制与完整暂存。用同盘无覆盖原子重命名将已同步整文件与原回执一起发布，同步正式目的与原 DATA 暂存父目录后，重证同一个移入目录、原正文与原回执；只有确定才返回原回执。回执已确定后，小登记清理未完成不撤销它。失败或不确定不改盘、不开新号、不清除未发布原件。
- 验证只在明确请求提交且授权有效时读取原件。阻塞读取后再次核对授权；过期时最后未接受的字节不推进 SHA，且不作发布动作。I/O 损坏、换名、旧纪元或其它拒绝不当成可继续的验证。
- 可在进程内暂存两个验证原件（扫描中与暂停合计）。暂停闲置五分钟失效；下一次有权提交时才回收过期内存原件。不保存密码、令牌或证明到盘。重启或证明失效只丢内存验证，不能丢暂存或把验证当作回执。
- 同一纪元可显式登录，再用同一 U/C/O 请求提交：首先查询原回执，复核完整 UR1、原持有正文与文件戳，才可从上一已核验块继续。结束仍须活授权下核对 EOF/全 SHA 和现时分支，再走同一发布切点。GET 不续跑或延长验证。
- 单次会话 900 秒读完 1 TiB 约需 1.14 GiB/s，不能把声明上限当实际支持。正式监听仅在命中本页路径并通过 Bearer 验证后接入；上线前须验真实 HTTPS/HTTP/2 的超时和显式重认证，不得自动重送或放宽过期授权。
- 假件逐一核：授权失效/错误作用域不触盘，丢开始答复可纯读找回，部分尾写无偏移，旧块同字节重发不写，跳块/错摘要不写，已完成的坏整 SHA 不发布，同号 inode 但出生时间不符拒绝，路由或头变化保留暂存，冷待选回执精确复用，提交过断点只用同号原回执收敛。实际盘重挂、掉电和 HTTPS/H2 另验，不由源码检查替代。
