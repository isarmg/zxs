# 活动名称的派生视图

状态：[仅静态]。只加速既有全局名称查重，不改列表、任何磁盘记录或返回的原操作回执。

## 唯一权威

CR1 只证明容器号绑定 DATA，不占显示名称。既有 OC2 回执账本重放唯一决定活动容器的当前名称；SYSTEM 的明确回收选择与原 RECYCLE ready、原容器子目录相符时，名称不再占用。回收前到达的副本、上传登记和路由暂存不参与查重。保持原名原字节与 Linux 大小写区分。改名可忽略自身，不可忽略另一个同名容器。

冷构建只接受实际持有的 Store 和原 SYSTEM、角色挂载及 owner 文件，扫描前后复核共同命名空间。名称锁内不再进入其它容器的对象锁；对象→名称→短 SYSTEM 选择切点的顺序不反转。观察到读写、介质、描述符或选择不确定时不出视图。对于冷发布，沿用既有账本目录同步与验证，不读取正文，也不做修复。视图不是正文或全盘健康证明。

## 完整重建

- 逐个核定每个已选 CR1；同时核对 DATA 的直接容器名与 SYSTEM 的已选回收，发现错盘、可见无路由原件或未知共同命名空间时拒绝，不在其他盘推断结果。
- 记录每个 CID 的已核定状态：保留路由但尚无首次回执（可有原空容器子目录）；已活动（原子目录、名称和账本证据）；已回收（完整原选择、R 子目录和相符的元数据账本）。只有活动状态入名称表。线上不会重新认领未选中的其它候选。
- 原盘或已选原件离线、曾见路由消失、同号路径的原件替换、曾见活动账本回退/前缀变更、曾见回收选择丢失、活动名称重复：不生成新视图。冷观察记录的是当前托管角色的真实本机身份，不写盘、不以当前设备号替换永久 DATA 令牌。不把外部直接改写托管存储或不可见的损坏解释为可安全查重。
- 最多 131,072 路由与 32 MiB 名称 UTF-8，名称字节由两个内存表共用。一次只展开一个账本，最多 65,536 回执、32 MiB 编码元数据及 262,144 标签项；在超出前停止缓存，不悄悄跳过记录或覆盖原快照。没有新的磁盘格式或索引文件。

## 生效条件与切点

只在持有唯一协作写者或 Helper 原离线独占租约时启用。首次占名或改名在真实持久发布后只更新受影响的容器和确切新回执；保留上次查过的旧账本前缀与明确写入的新回执两个独立见证。对冷重建，更晚的无关元数据不能替代其中任何一个。即使用降级路径完成的写入也保留原回执和本机见证。若到达容量或不能保留已确认操作的见证，不撤销已确认回执；该进程不再从不完整的表答名称可用。

回收暂存、到达、选择和源清理前先使热视图失效；回收同时进行时不得热命中。SYSTEM 选择明确落定后、清理前，单独记住原回收选择与 R 子目录；暂有原 DATA 不代表选择可以撤回。首次 CR1、活动目录建立和最终选择紧邻本机操作复核已有的命名许可与本机范围；只接受本次写入明确触碰的父目录变化。独立观察到的角色或选中元数据错误使已缓存许可失效。目录时间戳不是热命中承诺，也不能单独证明账本内容未变。

热查重仅在已核定的本机角色见证和内存代次不变时读名称表，不枚举 CR1 或重放别的账本。受限、可复核的降级才走既有查询；缺席的无关 DATA 不等于所有容器不可用；降级仍须握住所需 DATA（含本次目标）及 SYSTEM、已选中的 R，直至本机发布切点。若无法核对先前已见状态，也不得答名称可用。不尝试重映射、隐式修复、加兼容索引或修改原操作回执。
