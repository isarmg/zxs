# 跨 DATA 移动：原意图、互锁与就绪

状态：[仅静态]。私有本机工序、固定进程入口和互锁仅待配对验证，没有发布迁移命令或真卷验收。总体恢复流程见 [离线移动设计](../../../helper/docs/specs/offline-data-move.md)。

- 从原停机独占范围取得原 STATE、SYSTEM、RECYCLE 及两块原 DATA。持有已有的原角色 owner，核对原 CR1 的精确字节和 native inode/创建时间；不打开通常会补同步或清扫的 Store 入口。
- 源仅读取有界 OC2 账本和所选原件元数据。主账本沿用原序号和操作验证；每个原件结构、所读回执、文件类型和长度均核对。只读取元数据，不读取正文或改变任何 DATA 名称；后续复制仍需验证正文的真实长度、EOF 和完整 SHA-256。
- 用原 SYSTEM `data-relocations/{C}-{O}/` 保存唯一的 `source-proof` 和 `INTENT`。不覆盖旧文件，也不把名字相同的未完成目录变成新意图。先同步原证明，再复核源和候选/目标/暂存的原持有父目录并同步准确缺失，才写原意图。两文件、操作目录、其原父目录及原 SYSTEM 各自同步，再重新核对。冷重开只允许同一个完整原意图及其相符证明；部分或外来材料保留。
- 写互锁前单独核对当前原源/路由、角色和有效前置名，确认候选 CR1、目标 DATA 名及专用 DATA 暂存名均在准确、已同步的父目录中缺失。存在同 C 的上传、回收选择/到达、无法归属的回收暂存或涉及原盘的退盘记录/待选等，拒绝开始，不读取这些位置的正文。
- 在同一个原 STATE 写 `.move-guard-draft-{C}-{O}`：新私有记录的创建时间和已校验意图严格绑定，文件本身先同步。再次核对原意图、原挂载和私有候选后，才以原父目录同位无覆盖重命名到 `.server-stage-move-{C}-{O}`。重新打开并比较改名后同一原文件的 inode/创建时间与字节，不用旧 ctime 当作身份。
- 可见活动名不是成功。原 STATE 父目录同步后，还要证明活动名为原互锁、备用名准确缺失；冷重试只确认这一个相同已知原件。坏记录、未知同名、阶段后缀或已有 READY/SWITCHED/DONE 均不被这个前置入口重用、不覆盖、不删除。

这些持久记录没有临时 `st_dev`、挂载号、密钥、口令或盘路径；会话中仍核对活文件描述符与挂载。I/G 步骤不写入 DATA。需使用同版的配对进程；活动互锁在普通服务和其他离线 Core 工序打开 Store 前拒绝，不能带互锁降级。

## READY：私有目标，不是已切换

只有同一已同步活动互锁才可独占创建 `TARGET/staging/move-{C}-{O}/`。逐项复核原 OC2 与原生证明：保存项流式复制完整正文并核对长度、EOF、SHA-256，纯元数据项只复制回执。每份原文只读一次；同步写出的目标文件、对应目标目录和原暂存父目录。独立遍历目标账本和形状，复核新文件的准确原生证明，不在同一新鲜复制中重读全部正文。

在原 SYSTEM 操作目录独占准备 `target-proof` 和 `new-route`。后者是给目标盘的准确 CR1，READY 另外绑定它的原生 inode/创建时间；它不是现有业务路由。同步前置证据，重验原路由、租约、互锁和源/目标；最后独占写入并同步 `READY`、原操作目录及其父层，重验准确命名。此处没有发布 `.<C>.incoming`、没有发布 `TARGET/data/{C}`，也未改变原 CR1 或删除源。

READY 刚形成时，冷重开核对准确布局、原互锁和未发布的原候选，并读目标正文一次（长度、EOF、SHA-256），不重读源正文。同名不同原件、未知后代及无法核对的同步须保留，不覆盖不另选盘。这里不证明真卷掉电、设备掉线或安装后的命令恢复。

### READY 前的普通进程中断

活动 G、准确旧 CR1、完整原源和未发布位置已证明后，以 `TARGET/staging/move-{C}-{O}` 保存私有复制草稿。同一 EX 排除在线服务和其他维护；普通清理不认此名字。尚无 COPYING 只接受原父目录下准确的空名，不接管非空目录。

在开始正文前先同步草稿目录及其原父。在原 SYSTEM 的 `data-relocations/.{C}-{O}.COPYING` 写不可变 152 字节见证：8 字节 `ZXDMC1\0\0`，I/G 的指纹各 32 字节，目标 DATA 令牌 32 字节，原目标暂存父与草稿 inode 各为 8 字节大端，最后 32 字节 SHA-256 绑定前 120 字节。用实际原介质和挂载证明，无全局 DATA 创建时间要求。

冷重试仅使用同一准确见证，验证原源及整份有界草稿清单。仅能丢弃原私有草稿中的已识别复制前缀及至多末尾一项的部分输出；先核对全部内容形状，随后按已持有的原件逐项清理，再从仍完整的原源重写。无回执的满长尾项还须核对 EOF 和原正文 SHA-256，不能把摘要错误当成中断并删除。非预期材料保留。这个范围不承诺识别人为改写专用服务账号私有内容。

COPYING、READY、SWITCHED、DONE 和目标证明/候选先在同一原持有 SYSTEM 的不生效名称完整写入并同步，然后无覆盖发布；可辨认的本操作短候选仅作未发布草稿，不作为选路或删源依据。普通中断不应暴露半写的正式阶段记录。

## 已就绪原件的顺序到达

同一停机范围内，先把已证目标树从原暂存名无覆盖移动到 `TARGET/data/{C}`。重开准确目标名称，核对仍为原暂存树的 inode、实际挂载和完整账本；原暂存父目录和目标父目录都同步并复核后，才可移动候选。

候选从原 SYSTEM 操作目录的 `new-route` 无覆盖移动到原 `container-routes/.{C}.incoming`。核对它仍是 READY 的原候选文件，精确字节与 inode/创建时间一致；不得把改名之前的 ctime 当作身份。原操作目录和原路由目录都须同步；同步共享路由目录前后均核对原选中 CR1。到达不修改 `container-routes/{C}`，不写 SWITCHED/DONE，不清理源。

冷重开仅承认仍持同一互锁和**原**选中 CR1 时的三个状态：目标和候选都在各自暂存位；目标到达、候选仍在原位；两者按序都到达。分别证明两对名称的准确存在和缺失。冷重开只读目标全量正文一次；同次继续使用持有的完整证明。混合、同名替代、缺失或不确认的现场均保留，不选路、不恢复未知材料。

## 原子选择与 SWITCHED

此步骤只在两处原件已按序到达、原 CR1 仍绑定源盘、且同号互锁仍受持有时执行。先复核准确的目标版本和回执；慢检查完成后，在原 SYSTEM 路由目录重钉候选与原 CR1 的名字、内容和原生身份。只用同父目录一次原子替换，把原候选改名为 `container-routes/{C}`，不先删除原路由，不改写任何 DATA 内容。

重新打开新 CR1，核对它仍为 READY 的同一 inode/创建时间与精确字节，并证明两个候选名和旧目标暂存名均缺失。同步原路由父目录，前后均复核新 CR1；再独占写与 READY 指纹相连的 72 字节 SWITCHED，并同步文件、原操作目录和其父层。只凭新 CR1 可见不能报告 SWITCHED 已确认。

同号冷重开只接受原 CR1 加原候选的准确到达态，或精确新 CR1 加候选缺失的已选择态。冷重开只读一次目标全部正文，不重复读源正文；同次用已持有的完整证明。完整、同源的可见 SWITCHED 可以复核后同步；缺失只在精确新 CR1 已同步后允许创建，未知、部分或混合证据保留并拒绝。此阶段不删除原源文件、不给出 DONE，也不启用迁移命令或解除互锁。

## 只退休准确的源，最后确认 DONE

退休只接受准确的 SWITCHED、新 CR1、原互锁和两份完整证明。冷重开先完整验证一次目标正文并确认原路由目录、SWITCHED 及其父层已同步；同次复用已持有的目标证明，不重读源正文。逐项核对准确目标账本及所有尚存源项的原生身份和原回执字节，遇到额外文件、错误原件或不合顺序的缺失，不删任何源项。

按账本顺序同步删除原 `payload`、原 `receipt` 和原空项目录；每次删除前重验采用的目标、同号互锁与该项准确原件。续作只接纳已清理前缀、至多一个按原顺序部分清理的项及未清理后缀。已缺失的名字也须在其实际原父目录同步并重验，不把进程所见当作持久。最后只移除准确的空源容器目录，同步并复核原 DATA 父目录。

目标仍准确且原源缺失已同步后，才独占写入并同步与 SWITCHED 相连的 DONE 及其父层。之后才可释放这个操作的准确活动互锁，或确认它已经缺失；两种情况均同步原 STATE 并复核。别的活动互锁和不明证据保留。冷查同一 DONE 只核当前授权、原 STATE/SYSTEM 及固定记录、原操作参数与可选原互锁，不访问旧盘或当前容器路由，不证明此刻仍在原目标，也不再次复制或退休。
