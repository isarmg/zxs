# 回收盘选择记录与来源证据

状态：[仅静态]。适用：维护 ZXS、Helper 或离线目录读取器的开发者。
前置：已登记的 SYSTEM、DATA 与专用回收盘，三者继续使用当前运行时的原挂载和 FD 校验。

## 选择记录

新写入只用 RC2。SYSTEM 的 `container-moves/<容器号>` 与回收盘的
`containers/<容器号>-<操作号>/ready` 存放同一条、逐字节相等的记录。
路径身份是固定宽度的小写十六进制；回收信封的 `container/` 是完整归档容器。

RC2 固定 172 字节，无尾部填充。偏移均从 0 开始；整数为大端。

| 偏移（含首不含末） | 内容 |
| --- | --- |
| 0..4 | 字面 `RC2\0` |
| 4..20 | 容器号，16 字节 |
| 20..36 | 原操作号，16 字节 |
| 36..44 | 原容器最后一个账本序号，u64 |
| 44..60 | 登记池令牌，16 字节 |
| 60..92 | 原路由 DATA 令牌，32 字节 |
| 92..124 | 登记回收盘令牌，32 字节 |
| 124..132 | 原 DATA 容器目录 inode，u64 |
| 132..140 | 已到达回收信封目录 inode，u64 |
| 140..172 | 回收信封内 `source-proof` 的完整 SHA-256 |

容器号、操作号、序号、令牌、inode 不可为零；两个盘令牌不得相同。
DATA 令牌必须匹配该容器的原 CR1 路由；读选中状态只承认仍在名册中的盘或精准 DT1 退役记录。
回收盘必须匹配启动时限定的池和盘令牌、信封 inode 和当前可信挂载。

## 原件证据

`source-proof` 每项一行、按原操作号的原始字节升序排列，RC2 每行恰为 104 字节。
依次为：操作项目录 inode（8 字节）、回执戳（48 字节）、正文戳（48 字节）。
每个戳为 inode、长度、mtime 秒、mtime 纳秒、ctime 秒、ctime 纳秒，各占 8 字节；时间为有符号大端。
没有独立正文的元数据记录以 48 个零字节作正文戳。

- 冷恢复在新选择或删除尚存原件前，按账本的正文长度和摘要重读回收盘的每份完整正文。选择和清理期间保留同一个回收归档目录。
- 删除之前核对原目录及现存成员、所有行和完整证据摘要；随后逐项按正文、回执、目录顺序同步删除。
- 运行时仍验证相同的实际挂载、原名称、设备号、inode、属主和链接；不可用不等于不存在。

## 冷启动与旧格式

同一已登记原盘可在原配置路径冷重新打开，即使 Linux 临时设备号变了。
不搜索其它路径、不自动接管热插拔或克隆；登记令牌不能证明物理磁盘序列号。

已选择的 RC1 固定 108 字节：至偏移 44 的头部同上，仅使用 `RC1\0`；
其后为原设备号、原 inode、回收设备号、回收 inode（各 8 字节）和证据 SHA-256（32 字节）。
旧证据每行 128 字节：项设备号和 inode、56 字节回执戳及 56 字节正文戳；
各戳比 RC2 多一个前置设备号。旧读与同号清理仍要求原坐标和完整旧证据。

旧 RC1 已到达但未被选择时，不自动选中、改写或清理；两个副本都保留。
已有选择在坐标或正文不能验证时不会变成“未找到”；已选择 RC2 的损坏副本阻止清理。
对现有记录、正文和临时材料不做格式转换。
