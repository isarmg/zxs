# v1 会话与后端请求边界

状态：[仅静态]。此页定义候选 v1 会话，不代表默认客户端已切换。
读者：客户端与存储服务维护者。前置：同一显式选择的账户，以及经过验证的 HTTPS/HTTP/2 客户端门面。

## 登录与回执

向 `POST /zxs/v1/sessions` 明确登录。路径不得有查询；只接受一个 Basic 授权头和一个 `Content-Length: 0`，请求无正文。
不允许重定向、自动重试、Bearer 登录或自动降级到 Basic。客户端只在原主机、证书链及 ALPN `h2` 验证完成后构造授权头。

成功为 `200`、`Content-Type: application/json`、`Cache-Control: no-store`。正文恰好以下字段，无重复或其它字段：

| 字段 | 类型与值 |
| --- | --- |
| `access_token` | 32 字节内核随机值的无填充规范 Base64URL，43 个 ASCII 字符 |
| `token_type` | 字符串 `Bearer` |
| `expires_in` | JSON 整数 `900`，秒 |

本切面仅允许 `Authorization: Bearer <token>` 用于原回执 `GET /zxs/v1/containers/{container}/operations/{operation}`。路径、原 DTO 和精确未找到结果不变。
列表、详情、下载及全部旧 R3 写入仍仅接受原 Basic 模式。不能因 Bearer 错误改送 Basic，也不能在续登录或重启后自动重新提交正文或变更。

## 授权边界

- 每次登录申请先经过专门限流，再使用现有 Argon2id 凭据校验一次；已有 Bearer 证明不做 KDF。
- 单账户、单运行服务，全局滚动 60 秒最多 8 次格式正确的登录申请，包含无效凭据。服务器不拿来源地址或代理头当用户身份。
- 只在进程内保存令牌的 SHA-256、原池、密码纪元和单调期限；最多 64 个活跃条目。到期、密码重置或服务重启后失效，不驱逐仍有效的条目。
- 每次原回执查询重新验证授权与期限。令牌绝不授权旧 R3 写入；后续 v1 写入的资格与发布检查须另行批准。
- 不记录授权头、原始令牌或密码。不增加匿名读接口，不修改旧 Basic R3 的状态或回执。

| 结果 | HTTP 响应 |
| --- | --- |
| 无效 Basic 登录或无效、已到期 Bearer | `401`，`WWW-Authenticate` 仅为本次路径使用的方案 |
| 有效 Bearer 请求仅限 Basic 的现有业务路由 | `403`，无授权质询，空正文 |
| 登录限流 | `429`，`Retry-After` 为剩余向上取整秒数（1–60），空正文 |
| 校验服务、随机数或会话容量不可用 | `503`，空正文 |
| 登录路径形状或方法错误 | `400`（长度或正文帧错误）或 `404`（不支持的方法），空正文 |

## 明文后端连接

外部客户端保持已验证的 HTTPS/H2 连接。TLS、前置代理与监听地址不由本功能配置；客户端不发送任何 HTTP/1.1 连接控制头。
后端仍只接受严格 HTTP/1.1，按连接顺序处理，一次最多一个业务交换。

- 旧 Basic R3 一次请求、原响应后关闭；只有成功的登录和已授权的精确 Bearer 回执查询有资格复用。
- 前一项声明的唯一长度必须完整消费，响应也须完整写出；若约定错误、认证失败、写入失败或正文没消费完，关闭连接，不丢弃正文来猜下一个请求。
- 不因为共用后端连接而信任上一请求的账户或令牌；不支持 Transfer-Encoding、Trailer、Upgrade 或 `100-continue`。
- 后端最多 8 条已获复用的连接、每连接最多 32 项，后续单个请求头从读取开始最多 5 秒；不改原首次请求头限额。
- 5 秒限额只约束新交换的下一请求头；不改变已接纳 R3 正文、原操作或停机收尾的现有规则。
- Range、上传偏移、分段提交与线上过渡仍要另行验收。
