# 离线批量导入的本地交接

状态：[仅静态]。适用：ZXS 和 Helper 维护者。前置：原停机 EX OFD 租约、已登记角色和固定的普通账号二进制。
旧的单文件入口和 kind 45 不变；批量不向服务监听端口发送命令。

## 原计划

固定入口 `__offline-import-batch-v1` 不接受额外参数。FD 0 是原 EX OFD 租约，FD 3 是带凭据的 Unix `SOCK_SEQPACKET`，FD 4 是完整封存的本次命令。
FD 4 总长不超过 32 MiB；所有整数大端，不接受多余数据。

| 部分 | 格式 |
| --- | --- |
| 前缀 | `ZXIBC1\0\0`（8）、原 `server.conf` 的 SHA-256（32）、非零本次域令牌（32） |
| 原计划 | `ZXBATCH1`（8）、行数 u64（1–65,536）、依次为票长 u32 与完整原票 |
| 尾部 | 从 `ZXBATCH1` 至最后一张票的完整 SHA-256（32），随后 EOF |

ZXS 在绑定写入器之前验证整份计划。每张票保留现有 `ZXIMP1\0\0` 字节；同批只允许同池、同目标 DATA 路径和盘令牌、同来源根。
原操作号、来源相对路径和目标名不得重复。

## 逐项确认

每条消息 138 字节：`ZXSAMW1\0`（8）、kind `47`（1）、本次域令牌（32）、摘要（32）、正文（65）。
步骤 1–7 的摘要是该行原票的 SHA-256，正文末八字节 `57..65` 是从 1 开始的原行号。
正文首字节是步骤；未列出的字节为零。

| 步骤 | 方向 | 正文与描述符 |
| --- | --- | --- |
| 1／2 | ZXS 请求／Helper 应答 | 步骤 2 的 `1..9` 为当前来源挂载 ID；只在此应答中附一枚原文件只读 FD。 |
| 3／4 | ZXS 挑战／Helper 应答 | `1..9` 为该行从 1 递增的重验计数，答复逐字匹配。 |
| 5／6 | ZXS 确认 | 已存在的原回执／本项保存后的回执；`1..9` 为序号，`9..25` 为容器号，`25..41` 为操作号，`41..57` 为节点号。 |
| 7 | Helper 确认 | 重验原选择、必要时重验来源并刷新该项输出后，回送 5／6 的精确正文，仅首字节改 7。无 FD。 |
| 8 | ZXS 结束 | 摘要改为整个 FD 4 的 SHA-256；`1..9` 为已确认的总行数，其余保留位为零。无 FD，Helper 校验 EOF 与正常退出。 |

每项先查原回执，只有没有原回执时才请求来源。收到精确步骤 7 前不处理下一项。
任一交接失败即停止；已持久化的原回执仍可用同一原计划核实，不自动续写或撤回已完成的项。
