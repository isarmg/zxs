# 离线验证的本地交接

状态：[仅静态]。供 ZXS 与 Helper 的维护者使用。先保留原停机 EX OFD 租约，以及已登记的池、角色根和原启动描述符。

`__offline-verify-container-v1` 只接受固定入口，不接受额外参数。FD 0 是原租约，FD 3 是带凭据的 Unix 顺序包套接字，FD 4 是密封的精确请求。无网络入口。

## 88 字节请求

| 字节（含首不含尾） | 内容 |
| --- | --- |
| 0..8 | `ZXOVF1\0\0` |
| 8..40 | 原描述符与本次实际选中根的共同 SHA-256 |
| 40..72 | 非零本次域令牌 |
| 72..88 | 非零原容器号 |

共同摘要依次包含：领域字面 `ZXS verify live roles v1\0`；原 `server.conf` SHA-256（32 字节）；角色数 u8（3–64）；依描述符顺序的 SYSTEM、RECYCLE、各 DATA 三元组。
三元组为设备号、inode、挂载 ID，均 u64 大端；inode 和挂载 ID 不可为零。双方在读验证前与收尾核对自己原持有的角色，不把这些坐标写盘。

只查指定容器原 CR1 路由。若已有回收选择，只查经登记并匹配的回收信封与账本，不降级回 DATA。
按原选中目录读完整账本；每个留存版本逐字节核长度、EOF 和整份 SHA-256。仅有路由尚无首节点不发成功。

## 65 字节成功正文

沿用 138 字节 `ZXSAMW1\0` 外框的 kind `48`、同一个域令牌和整个 FD 4 的 SHA-256。
只发一条成功消息，无附加 FD。Helper 还必须核对原子进程正常结束与 EOF。

| 字节 | 内容 |
| --- | --- |
| 0 | `1`，已验证 |
| 1..17 | 精确原容器号 |
| 17..25 | 回执数，u64 大端 |
| 25..33 | 正文数，u64 大端 |
| 33..41 | 所有正文总字节，u64 大端 |
| 41 | `1` 活动 DATA；`2` 已选择的 RECYCLE |
| 42..65 | 保留，全零 |

回执数不得少于正文数；正文数至少 1，总字节可为零。任一路径、原身份、摘要、计数、租约或文件不精确，不发该消息。
不读取其它容器，不触碰原件的访问时间。不初始化、重选、修理、同步、清理、写回或改名。
只报告本次可见的选定账本和正文；不证明断电持久性、回收删源证据或整盘健康。
