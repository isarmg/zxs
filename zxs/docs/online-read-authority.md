# 在线权限：一个 Web 管理员，一个 SMB 文件用户

此页是现行规则。账号不增删、没有成员表或逐人 ACL。[首次设置](first-account-v1.md)将两种身份绑定到一个可信池。Web 口令由 SQLite 验证；唯一 SMB 口令只由同一专用实例的原生 Samba tdbsam 验证。业务授权和共享模式只从原 SQLite 选取，任何一边的单独成功都不代替另一边。Web 管理员不能通过 SMB 读文件；SMB 用户不能登录管理网页。**禁止匿名、guest、错误密码回退和不经认证的共享枚举。** 登录页本身可见，但在认证之前不返回账号/池/共享/磁盘/文件或版本信息。

| 操作 | 唯一 Web 管理员 | 唯一 SMB 用户 |
| --- | --- | --- |
| 查看固定账户、管理共享／查看版本元数据 | 认证后可用；不收发文件正文 | 拒绝 |
| 磁盘信息、状态与监测 | 不提供；由 Helper 独立办理 | 不提供诊断；常规 SMB 文件系统容量查询仍受实际获准共享与原物约束 |
| 发布普通根共享 | 可以；任何新定义初始停用 | 拒绝 |
| 浏览共享／列名／开文件／范围读 | 拒绝 | 仅已启用的只读或读写共享 |
| 创建／实际写入／截长／删除 | 拒绝 | 仅已启用的读写共享，仍受原文件受管操作约束 |
| 未发布、停用或无法证明的共享 | 可见自己有权管理的定义；不构成数据权 | 不可见、不可打开，不从真实目录列出 |

共享只记录自己的状态：停用、只读、读写。修改由已认证的 Web 管理员显式进行，原操作要绑定同池、ShareId、当前设置原 Op 和新模式；无模式变更记录就是初始停用，不等于默认只读。读写模式不是额外系统管理员、账户管理或回收盘原始权限。两共享引用同一普通根时仍共用一个业务名字域，不能制造第二份 FILE 或通过一个旧句柄借另一个共享权限。

SMB 每次真实打开/查名/恢复持久句柄，都用真实已认证会话的 SMB 身份及代次，在同一短 SQLite 切面核 ShareId、模式修订、精确普通父、成员/对象及需要的动作，再持实际原件。写确认必须再次核该份授权，先启用后停用、RW 降为 RO、停用后重开、凭据重置都不会让旧写入或句柄自动升级。管理账号或外来 UID、客户端传的账号/SID、某个库函数返回的原元数据不能充当凭据。Web 登录状态不转发到 SMB。Web 只管理，不上传、下载或预览普通正文，亦不转发文件流。

真实 Web 接入须有 TLS 或受保护的可信终结、短时服务端会话、不可伪造的随机令牌、Secure/HttpOnly/SameSite cookie、限流和 CSRF；令牌、密码不放在 URL、argv、常规日志或回执。SMB 必须由独立的实际 Samba 认证确认非匿名、非来宾、确切受信域/用户、当时凭据代和连接，再把结果限制在原 S 生命周期内。明确禁止 guest 映射、不启用匿名 IPC/探测入口；不声称设置两个配置字就完成整条协议。没有此证据就拒绝。

源码、运行与现场验收分开。现有类型化 Web 管理身份与原共享登记不是监听网站；并未证明 Windows/Samba 接入或能按路径读写文件。首个验收只需：完成初设 → 真管理员发布并启用普通根读写 → 真 SMB 主体创建一个 FILE、写入并读回 → 冷开原池/原容器仍得到原数据。再验未登录、互串凭据、错误密码、只读写入和降级中途提交均不泄露或改变数据。两种协议分别验，均未运行。
