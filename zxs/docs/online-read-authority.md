# 在线主体与授权：Web 管理和 SMB 文件访问

**职责。** 这是完整服务的业务/恢复边界；目前只有受限[首管原决定读取](first-account-v1.md)，不是网站或可开启的端口。已经冻结的 MAINT-1 空池 GENESIS、标签和零前沿不改。首管建立/密码重置由独立 helper 停机执行，ZXS 读原决定；日常登录与授权属于 ZXS；Web 只管理账户/共享、系统与磁盘状态、版本元数据，SMB 承担目录及普通 FILE 内容 I/O。绝不由 helper 发日常文件读/写、由 Web 伪装离线维护、或由两个程序各建一套账户库。

## 同一个池的原事实

- 池的普通文件、账户和权限使用**同一个 SYSTEM 已确认决策前缀/下界**，不是另放一个可改名替换的 ACL/JSON 作为权威。新必需帧须有区分的版本/操作域、唯一原 Op、前序和确切主体；累计操作和回收还原预留仍共用已有约束。未知、截短、未确认帧、未封原单、同名替登记、旧版没有账目或正在初始化，均不产生账户或共享许可。空池读者继续仅接零；已公开恰好首笔账户原帧及合成向量，ZXS 有独立原物读取。后续账户/共享/普通事务、helper 的真实授权写入和中断重开仍须各自完成，不能从该只读切片推断互通。没有认识并实际持有原登记 SH/EX 的所有旧调用者不能并行写新介质。
- 一个账户的键是 `(PoolId, AccountId[16])`，由原操作产生非零随机 ID，终身不复用；登录名只是定位器，不由 UID、显示名、电子邮件、域缩写或传入 ID 推算。同一名称不能同时指向两活动账户；即使名称将来允许重新分配，也不可继承用户、权限、会话或回执。建立、禁用、重置等按原前驱决定/凭据代次匹配；代次单调，绝不复用或溢出。先前会话只有太旧而没有“自动升级”。
- 第一次建立管理员要求：原池可完整核对、该池**历史上**从未有首管（不只是当前可用管理员数为零）、维护主体已获这一次首设授权、同一常规 REGISTRATION 持 EX。重置必须额外获该池受保护的离线恢复授权，选择原 AccountId+当前凭据代次并确认；仅独占原物、系统服务已停、root 身份或网页会话均不够。恢复授权的具体签发/撤换与受保护的本地通道，需 helper 独立静审后闭合，无可信来源时宁拒。两类操作原单幂等；普通查询不推进，回执不含口令、凭据验证值、缓存令牌或恢复秘密；通用请求/原操作摘要也不得含明文、可快速试猜的口令摘要或无盐派生值。中断重试不重新发 AccountId、盐、凭据代次；先查确切原单的非秘密结果，如果不能安全比对新的口令输入，不把已做原单当再次设密或口令校验器。用户确需另设，须另获授权和新原单。重置/禁用后即使旧凭据能通过某外部提供者，也不能获旧授权或重新接回旧 SMB durable handle。
- Web 口令验证只用经审上游慢 KDF，候选参数为 [RFC 9106 §4](https://www.rfc-editor.org/rfc/rfc9106.html#section-4) 的 Argon2id 1.3、64 MiB / 3 次 / 4 lanes、每次新随机 16 字节盐、32 字节验证结果。持久私有验证值按账户/代次绑定；在原 SYSTEM 上确认它所属的记录，不能把同名替物、测试负载、自述 PHC 参数或另一账户的旧验证值当当前证据。新写的参数/长度、库及互认向量另行固定；不手写密码散列、不用存储 SHA 作口令散列、不保存或回显明文。密码和恢复秘密不经 argv、环境、URL、普通日志或操作回执。SMB 认证用 Samba 已验证的连接/安全令牌与唯一受信任认证域＋原用户 SID 映射；不能把 Web 验证值转换成 NT 密钥、把 Samba 的名字/任意客户端 header 当 AccountId，或在密码重置后继续接纳旧的 Samba 签入代次。即使用户用旧的外部凭据**重新**认证得到完全相同 SID，也绝不可把今日 SYSTEM 代次贴到它上面；不能从实际可核的凭据更新/失效及新认证来源证实对应代次，整个 SMB 认证通道保持关闭。若实际 Samba 身份源、凭据轮换与会话失效没有闭合，只开放已经具备真实授权的适配器，不假报两协议可用。

## 从共享里选中对象，而不是根据路径授予权限

首管的确切成立记录只产生**管理账户、发布共享、授予或撤销读能力**的初次管理资格，不隐含 FILE 读权、不产生默认共享。建立下一账户、绑定受信 SID、发布/改址/撤回共享、为指定账户/共享作首笔和后续权限修改，均由在线已认证且当前持相应管理能力的主体在原决定上明确签发，带被管理对象及精确前驱。普通用户不能凭知道自己的/别人的 ID、管理员名字或已经能浏览，给自己授予读权；离线 helper 的首设/恢复也不代作日常授权。在真实授权发行/确认未实现时，即使真首管已建立，服务仍默认没有可读共享。

- 原始共享发布记录 `ShareId → (PoolId,普通 VolumeId, Root|已安装 DirectoryId)`；改址或撤下明确更改原发布代次。权限绑定确切 AccountId、ShareId、能力与原授权版本；只要缺一项即拒。初始读能力区分列举/导航、读当前、读确切正式历史；没有“是管理员就能读取所有文件”的隐含快捷路。要进入/看见对象须有对应父路径遍历/列举及所求动作许可；授权模型若要求更细的对象限制，首片不得把它降级成全共享许可。共享/目录/FILE 上的未知 ACL 不能默认允许。
- 在同一已核 SYSTEM 切面查账户启用、凭据和授权代次、分享的确切普通父；从已发布根沿业务名字的原 UTF-8 精确匹配直接子项，拒兄弟/跨池/祖先替换。对已选历史再核当下父、(EntryId,FileId)、本 FILE 的原 NodeId 及实际材料。当前 SMB 读写不能在工作稿不可随机读时偷退到历史。R/SYSTEM、物理路径及 FileId 后缀都不是对外目录。不能在前沿 A 签一个布尔值，再在前沿 B 以裸 ID 另开材料；账户/ACL、成员与选件都来自同一个短 SYSTEM 切面。共享改址、先撤销再重授即使对象、权限位和用户 ID 相同，旧会话中的对象句柄也不能升级为新授权，须重新获准打开。身份/权限检查先于管理元数据、SMB 目录/文件属性及正文、出错细节和历史回执；名外对象与猜中的未授权 ID 不泄漏存在与否。离线卷可有合法历史回执，不因此授权开正文。
- Web 只从 TLS 或严格受保护的终结链路接登录；会话令牌为真随机、高熵、不透明、短时的服务端会话，交给浏览器只用 Secure/HttpOnly/同站 cookie。日志无令牌、未知登录名同样有有界口令验证、按来源及全局节流和并发内存限额；完成慢验证后重新按原账户/代次核一次，失败不签会话。SMB VFS 在受信的本地协议端使用实际认证令牌而非可由客户端提供的辅助头。两边最终得到同一池/账户的准入，不给外部调用者 `authenticated=true`、用户名或路径型快捷口，也不借 OS 存储属主 UID。
- 一次 Web 管理请求先核管理范围，只发该用户可见的账户/共享配置、状态或版本元数据，不能提供普通文件上传、预览、下载、下载地址或正文代理。一次 SMB 打开/READ 则核真实会话、当前共享、父/FILE 和冻结材料。撤权或移出共享阻止下一次打开/READ/续传；一次已经获准的操作可按排空策略完成或明确中止，已发送的字节不能收回。重复 offset 读不会把旧句柄升级成新权。在线与慢操作持同一原 REGISTRATION SH 至排空；systemd 状态不是安全证明，真实认证条件不全不开监听。

## 最早能诚实交付的业务路径

1. helper 在独立生成的空池上以真实原 EX 写首管；ZXS 识别同一原池和后续业务前缀以及确切账户。先在库夹具用真实原操作/授权与两个不同账户、一普通根两个已装子父、相同拼写不同 FILE 验浏览与打开。含未确认首管/截断拒、重置后旧会话、已撤共享、跨父/池/节点、异主体查回执。没有上生产前，不可用测试构造器开网络。
2. Web 首条路径为受保护登录→按权限看账户、共享、系统与盘状态、版本元数据及相应管理动作。服务从受信配置取 SYSTEM；不接受原始文件路径，绝不把物理根当静态站点。未授权不透露对象是否存在，也不把元数据许可解释为可读正文。
3. Samba 承担普通文件传输。真实认证主体/共享绑定后，从同一原切面取得目录和当前业务句柄，按 offset 读写、flush、close；明确支持的历史对象也须另核其确切节点和读权限。未知操作不降为 POSIX 透传，Web 不代传正文。浏览器管理、Samba 模块、跨进程互斥各自留证，未运行的库夹具不等于实际网络或安全验收。
