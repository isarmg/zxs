# 原生 HTTP 管理页

新站点的 Web 源码由同一个前台 `zxs` 按[原站点契约](../src/smb/launch/site/CONTRACT.md)启动。受信 root 前台持实际原件、监督两个降权角色；只有 Web 角色持已批准的实际管理 HTTP 监听 **`0.0.0.0:8443`**。这是绑定地址，不是访问网址；已另行核准的实际实例从受保护网络访问其 IPv4 地址。原池由保护站点记录选择，不能从环境变量、HTTP 请求或旧池配置重选。候选不安装或启用宿主服务，不改防火墙、证书、DNS 或系统网络，本文不是部署或验收结果。

**直连是明文。** 同一路径上的第三方可能读到密码或会话；共同密码泄露也危及 SMB。本候选的明文登录只在受保护的隔离开发网络验证。服务核对 HTTP Host 必须等于这一条实际接受 TCP 的本地 IP 和端口；不把仅能指向它的陌生域名当作同源。监听所有 IPv4 接口不等于允许对公网开放。

## 外部 HTTPS 反向代理

ZXS 仍只监听原 `0.0.0.0:8443` 上的 HTTP，不加载证书或 TLS 密钥。外部代理在**同一 Linux 宿主**终止 HTTPS，校验实际 TLS 请求的外部 authority；只为这一 TLS 虚拟主机回源 `127.0.0.1:8443`，保留准确的 Host 和浏览器 Origin。不能在外部明文 HTTP 上回源管理请求，也不要合成或改写 Origin。代理应拒绝有歧义的请求、清掉所有客户端自带的 `ZXS-Proxy-Key`（字段名不区分大小写），只在批准的 TLS 路径注入一次。ZXS 不信 `Forwarded`、`X-Forwarded-*` 或它们声明的身份、协议和地址。

1. 在代理侧用可信随机源生成 **32 字节**专用代理密钥，写成恰好 **64 个小写十六进制 ASCII 字符**。不能用账户口令代替。仅代理保存原值并在上述路径的回源请求中添加 `ZXS-Proxy-Key`；原值不放命令行、可回显终端、请求日志、返回页或浏览器。对这 **64 个 ASCII 字符本身**算 SHA-256，不解码、不加换行。
2. 在启动 ZXS 的实际前台批准处，选择 `RUN-ZXS <随机确认码> WEB-HTTPS <外部origin> sha256:<64字符的小写十六进制摘要>`。只输入摘要，**不输入原密钥**。例如 `https://admin.example`。只接受普通小写 ASCII DNS、规范 IPv4 或方括号内的非映射 IPv6；不接受 IDN/`xn--`、IP 缩写或进制别名。非默认端口写入 origin 和 Host，默认 443 不显式写；不带路径、参数或用户名。短的原 `RUN-ZXS <随机确认码>` 则明确选择直连明文 HTTP。ZXS 不持久保存此项选择，不通过环境变量或在线切换；每次前台重启要重新确认，不合法的代理选项不降级成直连。
3. 代理模式只接受实际 IPv4 本地和对端均为 `127.0.0.1` 的原连接，且每请求都要核对唯一准确的回源密钥、Host 及现有同源规则。裸后端不会处理局域网请求或无密钥的本机请求；监听仍是通配地址，不能当作关闭端口或阻断 TCP 连接。使用专用外部主机名，不与不可信服务共享其 Cookie 范围；按实际部署限制网络暴露。凭据与 Cookie 必须由真实 HTTPS 前端传输，ZXS 不证明代理的 TLS 或系统网络设置。

代理模式的会话使用 `__Host-zxs`、`Secure`、`HttpOnly`、`SameSite=Strict`、`Path=/`，无 Domain。直连仍为独立的 `zxs-http`。浏览器实际 HTTPS、旧/错误 Origin、回源绕行、正常停机另须验收；本页是源码候选的配置契约，不表示已部署或验证了外部代理。

## 管理页外观

登录、版本入口和账号卡使用[旧 ZXS G4 轮廓生成的页内 SVG](../web/NOTICE.md#管理页-g4-圆角)，不支持时回退普通圆角。共享列表窄屏分行、卷编号可展开。无 JS、WASM 或外部 SVG；请求和授权不变。

## 登录、共享与传输

- `GET /login` 无管理数据；`GET /` 未登录只转登录页。共同账户必须通过本池当前 Argon2id 核验才能建立 Web 会话。拒仅有 SMB 会话、匿名或失败凭据。每次管理动作再核同一账号的 Web 主体及共同代。管理页只显示一个非秘密登录名及分页共享，保留共享的逻辑卷标识与当时授权模式，不把配置当作物理盘或网络在线。仅修改首装已选的数据盘目录模式，不在线登记新共享。可从已确认文件的分页列表选工作稿作显式提交，或单独看已提交版本的序号、节点/父节点、版本 ID 和该版逻辑长度。历史页只查当前管理员的原库元数据，不探磁盘、不验证正文、不更换原提交表单；不接受上传/下载/正文预览、宿主路径或通用 SQL。停机恢复不在此服务。
- 已打开的历史链接仍按原 FileId 查询。如果原库已核实某个上级目录的改名尚未确认，历史页只显示 FileId 和既有已提交版本，不显示旧路径、拟用路径或卷，不提供提交入口，也不把工作稿列作正式版本。无法核实原身份、目录或版本记录时，仍不返回历史结果。
- 每个 POST 都核精确浏览器 Origin；不接受缺失、`null`、异源或用 Referer 代替。页面使用 `Referrer-Policy: same-origin`。登录签发随机会话；修改目录设置、提交工作稿与退出另核会话自己的随机 CSRF。当前直连 HTTP 使用 `zxs-http`，不是 Secure Cookie；它仅限主机，`Path=/; HttpOnly; SameSite=Strict`，不设 Domain；会话还绑定确切浏览器 origin，不能换名字在另一入口、地址或端口借用。浏览器 Cookie **不按端口隔离**；同一主机名/IP 上的其它服务可能收到它。不要与不可信站点共用管理主机名/IP；上述绑定不能防止窃走 Cookie 后在它原入口重放。15 分钟闲置、8 小时绝对有效期；退出或重启失效。不超过 32 个同时会话，每分钟最多 12 次登录验证。
- 页面值按文本转义，内置样式无外部资源。设置和手动提交仍绑定各自表单的原操作 ID 与确切前驱。手动提交未收到结果时，可在仍有效的原表单选“只查本次回执”。查询需要原登录会话、同源和 CSRF，只从原库核对本次操作、FileId、工作修订及确切已确认正式版本，不读取正文或打开普通数据卷，也不提交或重试。未找到回执只是本次只读观测，原请求仍可能在处理；不能核对则明确未知。只有仍在同一登录会话、且没有再次打开任何文件的提交预览时，才可主动重送原表单。预览失败也会使旧表单失效；失效表单不提交、不核对上一次，也不以新操作号自动重放。
- 一个 TCP 连接处理一个原始目标 HTTP/1.1 请求并关闭。只接受 GET 和定长表单 POST；上限为 8 KiB 请求头、64 个字段、4 KiB 表单；拒重复 Host/Origin/长度、混用 Transfer-Encoding、折行、升级/隧道。读取和回复各限总计 4 秒，至多 8 个独立 I/O 工作者，慢客户端不在 SQLite 事务中。一个业务 owner 按序授权；SIGTERM/SIGINT 或真正监听故障关闭业务准入；TCP 已接受或排队均不算业务已开始，尚未派发的请求不再执行。已通过准入的当前工作可以收尾，所有 I/O 工作者退出后才释放原 S。单个待接受连接中止或有网络错误并不使服务停机。客户端丢响应不等于撤销已经确认的数据库操作。
- Web 不提供磁盘清单、物理挂载、容量、文件系统标识、健康或读写监测，也不把磁盘请求转给 Helper。需要这些运维信息时使用独立 [Helper](../../helper/README.md)，其观察不是 ZXS 写授权。此边界不改变 SMB 受权限约束的文件系统容量应答或内部原物、空间与只读检查。
- 待实际验收：隔离网络中的浏览器直连与受信代理 HTTPS、错 Host／Origin、后端绕行拒绝、改密后退出、慢客户端与停机排空。本次均未运行。参考 [HTTP/1.1 消息格式](https://www.rfc-editor.org/rfc/rfc9112.html)、[Fetch Origin 规则](https://fetch.spec.whatwg.org/#append-a-request-origin-header)。
