# 原生 HTTP 管理页

已配置存储池后，直接启动无参数的 `zxs`。它用非特权存储身份持有原 SYSTEM 租约，监听 **`0.0.0.0:8443`**。在浏览器打开 `http://服务器实际IPv4:8443/`，用 Web 管理员登录。无需证书、域名、nginx、socket 激活或任何 Web 环境变量。`0.0.0.0` 是绑定地址，不是访问网址。已有池的 `ZXS_SYSTEM_ROOT` 与 `ZXS_POOL_ID` 仍来自受信服务配置，不由请求指定。服务不改防火墙、证书、DNS 或系统网络。本仓库只完成源码及未运行的用例，不声称部署过服务或用浏览器验收过。

**直连是明文。** 同一路径上的第三方可能读到密码或会话。请在可信网络使用；需要加密时由你自己的软件提供 HTTPS。默认服务核对 HTTP Host 必须等于这一条已接受 TCP 连接的真实本地 IP 和端口；不把仅能指向它的陌生域名当作同源。仍开放所有 IPv4 接口，不预设某个站点、网卡或回环地址。

## 可选的外部 HTTPS

ZXS 不提供 TLS。要让应用识别你现有代理前面的 HTTPS，受信部署方**同时**设置：
- `ZXS_WEB_PUBLIC_ORIGIN`：浏览器使用的确切 HTTPS origin，例如 `https://admin.example.org`（证书、域名与端口由站点选择）。不带路径，默认 443 不写。
- `ZXS_WEB_TRUSTED_PROXY`：与 ZXS 建立这条 TCP 连接的那个代理的**实际源 IPv4**，不是任意客户端传的地址。只可指定专用于该可信代理且管理方能保护的源地址及路径。若同机有其他不受信进程可从该地址发起连接，或后端段可被窃听，不能把该段当作隔离/保密的生产代理链。这是可选部署信任，不是密码验证。

代理须验证真实 TLS/站点并保留原 Host、Origin 和 Cookie，转给后台时使用普通 HTTP/1.1。不要向同一个入口转发未加密的客户端请求；限制请求大小，关缓存、自动重放、表单体落盘和带密日志。只有 accepted peer 与公开 Host 同时匹配才选择该 HTTPS origin 和 Secure Cookie；不认 Forwarded、X-Forwarded-* 或代填用户。只配一个变量、非法配置都会拒绝启动，不静默弱化。其他客户端仍可按真实 IPv4 直连。未配置时不自动信任某个转发域名或替用户配置代理。

## 登录、共享与传输

- `GET /login` 无管理数据；`GET /` 未登录只转登录页。仅 Web 管理员通过本池当前 Argon2id 核验可以建立会话。拒 SMB 账号、匿名或失败凭据。每次管理动作再核当前身份/代。管理页显示登记卷、两账号非秘密名称及分页共享，不把登记当作在线。仅修改首装已选的数据盘目录模式，不在线登记新共享。可从已确认文件的分页列表选工作稿作显式提交，或单独看已提交版本的序号、节点/父节点、版本 ID 和该版逻辑长度。历史页只查当前管理员的原库元数据，不探磁盘、不验证正文、不更换原提交表单；不接受上传/下载/正文预览、宿主路径或通用 SQL。停机恢复不在此服务。
- 每个 POST 都核精确浏览器 Origin；不接受缺失、`null`、异源或用 Referer 代替。页面使用 `Referrer-Policy: same-origin`。登录签发随机会话；修改目录设置、检查单卷、提交工作稿与退出另核会话自己的随机 CSRF。直连 HTTP 使用 `zxs-http`，不是会被浏览器拒收的 Secure Cookie；受信外部 HTTPS 使用 `__Host-zxs` 且必须 Secure。两者都仅限主机，`Path=/; HttpOnly; SameSite=Strict`，不设 Domain；会话还绑定确切浏览器 origin，不能换名字在另一入口、地址或端口借用。浏览器 Cookie **不按端口隔离**；同一主机名/IP 上的其它服务可能收到它。不要与不可信站点共用管理主机名/IP；上述绑定不能防止窃走 Cookie 后在它原入口重放。15 分钟闲置、8 小时绝对有效期；退出或重启失效。不超过 32 个同时会话，每分钟最多 12 次登录验证。
- 页面值按文本转义，内置样式无外部资源。设置和手动提交仍绑定各自表单的原操作 ID 与确切前驱。手动提交未收到结果时，只能在同一登录会话、且没有再次打开任何文件的提交预览时，重送原表单。预览失败也会使旧表单失效。失效的 POST 不提交，也不核对上一次的结果。提交成功页会显示版本 ID；没看到该页，不要用新表单当作重试。重启/过期后不以新操作号自动重放。
- 一个 TCP 连接处理一个原始目标 HTTP/1.1 请求并关闭。只接受 GET 和定长表单 POST；上限为 8 KiB 请求头、64 个字段、4 KiB 表单；拒重复 Host/Origin/长度、混用 Transfer-Encoding、折行、升级/隧道。读取和回复各限总计 4 秒，至多 8 个独立 I/O 工作者，慢客户端不在 SQLite 事务中。一个业务 owner 按序授权；SIGTERM/SIGINT 或真正监听故障关闭业务准入；TCP 已接受或排队均不算业务已开始，尚未派发的请求不再执行。已通过准入的当前工作可以收尾，所有 I/O 工作者退出后才释放原 S。单个待接受连接中止或有网络错误并不使服务停机。客户端丢响应不等于撤销已经确认的数据库操作。
- “系统与磁盘”只在管理员点击“检查此卷”后核对一个已登记的 SYSTEM、普通数据卷或专用回收卷。用当前 Web 服务所见的原路径、原卷标和同一个实际目录 FD，在一次 [fstatvfs](https://man7.org/linux/man-pages/man3/statvfs.3.html) 采样中显示总容量、内核报告可用空间和挂载只读位。只读时可以仍有非零空间；未标记只读也不是写授权。[内核文件系统标识接口](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/fs.h#L60-L71) 若返回非零有效标识，16 字节显示为 UUID；较短时只显示内核给出的原字节及长度，不补成 UUID。没有可靠值就显示“未取得”，不扫描块设备或代用 VolumeId。容量和标识不是硬件编号、目录配额或 SMB 当前挂载的证明。不能核对的卷不会显示为零容量或空回收。
- ext4 的两个可选指标也从同一个已核目录 FD 出发，只访问[内核交给该文件系统的 sysfs 观察目录](https://github.com/torvalds/linux/blob/v6.12/fs/ioctl.c#L735-L746)，不按设备名、设备号或 UUID 猜测另一件介质。`errors_count` 是 [ext4 已记录的文件系统错误数](https://github.com/torvalds/linux/blob/v6.12/fs/ext4/sysfs.c#L222-L229)，0 不代表硬件健康，也不是文件系统检查的结果。在可用的 64 位构建上，尝试被动间隔 250 毫秒读取两次 [`session_write_kbytes`](https://github.com/torvalds/linux/blob/v6.12/fs/ext4/sysfs.c#L61-L67)，按实际短窗报告主逻辑设备写入计数的增量和约速率，含该设备上 ZXS 之外的写入，不包括单独的外部日志设备，也不表示物理盘已持久化、客户端速度或测速成绩。增量 0 只表示两次计数相同。其他文件系统、原观察目录消失或不确定、计数不能比较等分别显示“未取得”，照常保留本次可靠的容量和标识；不回读旧值。
- 本操作不探测其他卷、不打开块设备、不读取正文、不记录历史，不返回宿主路径。只有一个独立的检查工作者，无候补探测；HTTP 等待最多 10 秒，超时不声称取消了已经进入内核的调用，停机仍等该工作者退出后再放原 SYSTEM 租约。待隔离环境实际验收：两套可区分的 ext4 文件系统上交叉核对所选卷的计数，与不支持该接口的文件系统对照；不注入磁盘故障，也不以业务访问量或标称速度替代内核计数。本次未运行。
