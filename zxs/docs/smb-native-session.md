# 专用 SMB 登录：谁验证，谁完成会话

这里定的是下一段接线，不是增加一种网络认证，也不是已能登录。目标是用 Windows 的 `ZXSLOCAL\<已设的 SMB 用户名>` 连接专用 smbd。口令和 NT 密码等价物只属于 SQL 中这一名 SMB 用户；Web 管理员、Unix 映射用户、挑战、登录结果都无权替它选账户。

| 同一次新登录 | 必须使用的原件 | 不能用来代替 |
| --- | --- | --- |
| 发挑战 | 已受控的真实客户 smbd 子进程、刚接受的这一条 TCP、它为这一次原生 GENSEC 建的临时私端；存储短事务选本池唯一现行 SMB 槽，固定 AccountId / credential_op / generation / SID / 登录名；随机挑战由存储选择 | 一个 PID、共用 fd 3、上次 READY、此前成功登录、调用者传来的挑战或任意用户名 |
| 校验标准 NTLMv2 | 原 GENSEC 已按 NDR 解析的这一次 NT 字段；仅对绑定的同一域、同一登录名和服务器原挑战；已消耗的尝试及第二次证明直接作废。存储进程在原 S 租约内再次比当前凭据代，只从本池唯一现行行供给定版 Samba 原生校验 | 不用 Linux 密码、其他域大小写/空域重试、LM/NTLMv1 或另一个 passdb；不提供按名字/SID 查询密码等价物的 API |
| 回到 GENSEC | 只许到本次仍存活的原认证子进程和原 tevent 请求。一次校验确实成功时的短时会话材料只进入这次 Samba 原生后验，用于交换密钥、核协商要求的 MIC 和签名；不在公共路由、持久介质、日志、SQL 回执、环境或独立诊断接口返回。原 NT 校验物不离开存储进程 | 一次 `true` 不足以签 SMB 报文；短时结果也不是对外 bearer、账户登录或 FILE 权。另一进程/子进程/尝试不能收取或重放 |
| 对外会话成立 | 原 GENSEC 后验成功，实际普通 token 的主 SID 准确匹配本域 RID1000，当前代仍然相同；将非秘密来源留给本次 `smbXsrv_session`，等上游新会话成功分支真正 `session_claim` 后那一次 `smbXsrv_session_update` 成功才激活，不能取握手中途也会调用的同名更新。以后按原实例、会话和共享现行设置复核 | 不根据 SID、Unix UID、NSS 名、PDB 查询、单条成功日志或 SMB 会话编号反推身份。未实现的重认证/绑通道/durable 恢复继续拒 |

**与上游的界限。** 采用与 Samba 自身委派口令校验相同的职责分离，但不用系统 winbind 的通用 socket。专用、非 root 的存储进程使用同一 Debian Samba 发行里的严格 NTLMv2 校验；原生供给端没有单独的监听地址、可查询的密码/会话密钥操作、任选账户/挑战或调试开关。私端有界、仅使用一次，来源不明、轮换、中断、超时、禁用密码算法或失败即销毁，不把旧结果递给后来的登录。新代码为证明和原一次结果创建的私有缓冲限定在这一次真实请求，禁 core、诊断及跨 fork 继承，用后擦除。这个约束不等同于 Samba 全部协议状态根本不写文件。不能证明实际收件人/材料寿命时不发送。完整标准握手、目标信息、协商的签名与加密仍留在 smbd，不自己重写 NTLM；不给 root smbd 打开 SYSTEM.sqlite3，也不另建 tdbsam 用户库。

**现在已接的两端。** 存储端只在核实真实监听进程的分派、原客户进程及这条 TCP 且还有尝试额度之后，才在所持 SYSTEM 下重新选上述唯一非秘密账号行；核对独立 BOUND 的本域和 RID，再发原格式的随机挑战。最多 32 个进行中的尝试共用每秒至多一次的在途重核，空闲时不读 SQLite；新申请仍逐次取自己的快照。无法重核、原代消失就关原尝试，不移植到后来者。`READY` 时碰巧有账号不能取代这一步。还**不读取口令等价物，不接受口令响应，不输出任何会话密钥**。

普通 Linux socket 证明发件进程或建端者，不证明在 fork 后只剩谁能收。这份限定 Debian amd64 的专用 smbd 在真实接连接的子进程重初始化之后、能建立认证私端之前，安装不可逆的本进程 seccomp 限制；允许同一进程、实际共享内存及 FD 表的线程，不准另建进程或 exec，不更改监听者、清理进程、存储或宿主设置。同步覆盖已存线程失败，该客户 worker 不接手。stock Samba 的这条直接访问已知普通共享的路径没有必须再生一个 OS 进程的前提；禁 PAM 和 token 外部脚本，NSS 只许已预配的本地非特权身份。用 [Linux seccomp](https://man7.org/linux/man-pages/man2/seccomp.2.html) 而不是把 `CLOEXEC` 说成 close-on-fork。本门只约束诚实受管二进制的继承；宿主仍必须隔离进程调试、FD 读取/送出、core、换页等，不能给任意 root、插入模块、占用原端者或同 UID 进程授信。不支持依赖在此 worker 临时 fork 执行 RPC/外部脚本的方式，也不因此开放匿名 IPC$。只实现了原尝试与接收者的边界，未据此开放登录。

**这次原生登录的末端。** 专用 auth3 只有在原请求确实成功、返回普通账户对象和上游要求的本次会话材料时，才记录那一个对象；生成 token 的回调也必须收到同一件。原 GENSEC 负责后验及签名密钥。进入真实新会话的最后一步时，在原认证私端异步取一次**非秘密**的现行账号切面。存储独立重读 SQL，只有与发挑战时选中的池、账号、凭据单/代、SID、登录名完全相等才回复。该回复不是成功验密。原连接、仍待完成的原会话/认证对象、原生普通 token 的账号/SID 和专用低权 Unix 数值身份必须仍然相符；等待不提权、不持 SQL 事务。只有 claim 及随后的最终 session_update 成功，来源才留在本进程该会话上，不会写入线上格式或全局 TDB。SQL 切面与原生更新不是跨进程事务，后续业务操作仍须复核现行资格。Windows 正向仍未开放：当前受控密码回调不会返回成功对象，正确密码也不例外。本片不接受密码响应或从存储输出会话材料。

**原生协议自己的临时状态不是账户数据库。** 三种材料要分开：① SQLite 的长期 NT 校验物不离开存储进程；② 本次校验的短期结果只准一次交回真实 GENSEC，不作可再次领取的文件或回执；③ Samba 成功会话确实会用它生成签名、应用、加密或解密材料。定版 `smb2_sesssetup.c` 将这些材料置于会话结构，`smbXsrv_session.c` 确实以 `lock_path("smbXsrv_session_global.tdb")` 保存序列化状态，不是纯内存对象。正式配置的 `/instance/lock` 必须由受信宿主为这次运行提供独占、非持久且不换页落持久介质的本地文件系统；结束后终止整组、清退本次运行层，重启不复用 TDB。还须管控进程内存换页、core、休眠及宿主备份，不能仅凭 0600、名字、tmpfs 或 VOLATILE 标志声称密钥不落持久盘。宿主无法正面确认这些条件时，正向认证保持关闭；不据此抹掉 SQLite、域数据库或让宿主提供另一个用户权威。

专用宿主另外提供锁定的非特权 `zxs-smb-client` 作为 Unix 运行身份，不能让它取得存储 UID、管理 Web、宿主账户库、其他组的权限。不是第三个产品账号。登录成功也不让 IPC$ 列出未启用的分享；真实数据树仍须以原会话在 SQL 选择该共享，读/写分别核验。失败响应不泄露账号是否存在或哪一步匹配。

**验收顺序（待做，未运行）。** 真实 Windows 冷新会话正确凭据一次完成，随后从 RO 共享列出并读回一份已知 FILE；错误密码、匿名 IPC$/干净枚举、Web 凭据、错域、撤销再授权及上一 TCP 的凭据上下文不能登录或发数据。原证明正确但 GENSEC 后验失败、会话更新失败、完成前原凭据代已变：没有业务会话或可复用的原结果。客户端重试必须独立申请新挑战；原 worker/监听停止、慢超时或并发尝试不会把结果分给别人。SMB 原生 share-mode/字节锁以及本项目按逻辑 FILE 的单写仍另外验，不用“登录成功”代替文件操作验收。

依据：本项目固定的 [Debian trixie Samba 源包](https://packages.debian.org/source/trixie/samba) 中 `source3/auth/auth_winbind.c` 的 pass-through 职责、`libcli/auth/ntlm_check.c` 的原 v2 核、`auth/ntlmssp/ntlmssp_server.c` 的 GENSEC 后验与 `source3/smbd/smb2_sesssetup.c` 的实际 session 更新，以及 [MS-NLMP 的标准 v2 报文](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/aee311d6-21a7-4470-92a5-c4ecb022a87b)。上游通用 `ntlm_password_check` 包含不适用于这里的兼容分支，不把其任意一次成功当成本项目所需的原 v2 身份证明。
