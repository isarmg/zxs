# 一个用户文件名，一个 FILE 容器名

> 对外名字、完整 FileId 和内部叶名推导继续适用。下文旧原始帧长度、原日志接线和标签只是上一实现的历史，不能作为新库权威。 当前权威见 [SQLite SYSTEM](sqlite-system.md)。


这是新格式的实施设计，不是已经提供的 SMB 服务。它取代前两个目录/回收设计中“普通 FILE 的物理叶等于显示名”和“R 终名含删除票”的约定。其他原件、签决、容量和清退门槛不变。

## 两个名字只表达两件事

用户在父目录里看见 **方案.xlsx**；若 FileId 是 `0123456789abcdef0123456789abcdef`，普通盘与专用回收盘上的容器都叫 **方案-0123456789abcdef0123456789abcdef.xlsx**。普通目录仍用自己的对外名字。FILE 的稳定身份来自 SYSTEM 已确认的 FileId 与容器内原 FILE 元记录，不来自目录枚举、名字中的一串数字、路径、inode 数值或正文摘要。

* **对外名**是一个组件，存原始显示拼写，不翻译、不自动去尾、不丢失大小写。目录索引的唯一键为“确切普通卷和 Root/DirId＋原名字节”；FILE 和目录共享此键。收到同名独占创建、MOVE 或还原就拒绝，不覆盖；打开已有对象须从该键解析真实类型、EntryId、FileId/DirId、现址和当前权限。“查询文件”不把容器当普通目录，“查询目录”不把 FILE 当成同名文件夹。过渡验收驱动、受权 Web 管理元数据及 SMB 的目录枚举只给业务名字；Web 不返回普通文件正文。
* **物理容器名**由唯一函数从“此次位置决定冻结的显示拼写＋非零 128 位 FileId”产生：取最后一个不是首字符且后面有字符的 ASCII 点，在这个点前插入 `-` 和完整 32 位小写十六进制 ID；没有这样的点则追加该后缀。`a.tar.gz` → `a.tar-ID.gz`，`README` → `README-ID`，`.env` → `.env-ID`，`.env.local` → `.env-ID.local`（这里 ID 均代表全部 32 位）。本来长得像带 ID 的名字仍是完整人类名，不先剥后缀。编码在合法定义域内可还原原拼写；业务查找只正向派生，不提供按反向解析认领/恢复的入口。外层 FileId 不是内层 15 位版本存储号。
* **大小写敏感，精确相等。** 对外是一串合法 Unicode 标量；在磁盘格式中用唯一有效 UTF-8 表示。从客户端 UTF-16 转换时拒绝孤立代理项，不替换为“�”。同父只比较完整原名字节，如此才无大小写折叠、转小写、locale、NFC/NFD、全角半角或短名别称。`Report.xlsx` 和 `report.xlsx` 可同时独立创建、打开、搬走及还原；由两个不同 Unicode 序列组成的名字即使看起来一样也不合并。**只支持能够保留并区分原名的客户端和设备，按此为前提实现**，不做不敏感模式、名称探猜、后备算法或设备兼容层。大小写敏感不等于每种介质都可分别寻址 NFC/NFD。它们在 ZXS 是不同逻辑拼写，不承诺所有后端都能同时落盘：若已知会合并、改写或命中同一物理名称，在出票前拒；NOREPLACE 和实际目录返回的精确字节、原生实体复验仍不可少，不能把返回的另一拼写当本对象。现行“小写 ASCII、120 字节”是旧限制，不是 SMB 标准。新档接受中文、大小写、合法内部空格和前导点，拒绝空名、`.`、`..`、NUL/控制符、路径分隔符、普通客户端禁用的 ASCII 字符（< > : " / \ | ? *）、尾空格/尾点。这里不提供 DOS 设备路径、流、短名或其大小写别名，不声称每种客户端都能表示全部名字。不为比较引入 Unicode 折叠/规范化数据表。
* **再过物理占用门**。逻辑无冲突不保证能落盘。例如可见目录恰叫某 FILE 将使用的完整物理叶，仍须在出票/复制前拒；反向先建 FILE 再建该目录也同样拒。某个普通用户文件的显示名刚好长得像别的物理叶，不必一律拒：只有逻辑原名或两者各自的实际目标名字节碰撞才拒。按原前缀，从业务行算预期原件再与实际命名对照；未知或等字节替件停下，不用剥后缀、忽略大小写或遍历把外物升格为 FILE。
* **私名与 FILE 物理终名从构造上分开**。新格式只留两种私目录形式：`.zxs-new-<T>-<i>`（43 字节；T 是完整非零 32 位小写十六进制原票，i 仅 0…7）和 `.zxs-moveout-<T>_`（46 字节，末字符是下划线）。两种拼法唯一的点都在首字节。有扩展名的 FILE 物理叶必有非首点；无扩展名的 FILE 叶必以连字符和连续 32 位十六进制结束，私名末尾的 `-i` / `_` 均不满足。因此多点、前导点、连字符、原名已像票号等都不能把任何正常 FILE 派生成私名。普通目录物理名就是对外原名，**仅对目录**保留这两种完整、精确的私名语法，不保留任意 `.zxs-` 前缀，不折叠大小写。`.env`、`.zxs-move-out`、不同大小写的拼写等不因前缀被拒；FILE 甚至可以使用与这两个模式相符的显示名，其实叶另有完整 FileId。实际签票时必须确认各候选私名没有异物；冷接只有同原票/原父/阶段/实体才有处置权限，先前未绑定空槽只按原协议处理，不接管、不按前缀清除。

## 一次原决定，两端原物

CREATE 在父下预留的是“业务名＋已选 FileId 派生的物理叶＋本次私票”。不同父可以有同一对外名；同父不同 FileId 不能借物理名不同绕过业务占名。原 FILE 的出生名、当前主分支显示名、某一正式节点的提交时名、某一删除决定冻结的名字分别回答不同问题。初建时相同不等于可互相替代。以后将 `a.xlsx` 正式改为 `b.xlsx` 才可按同一 FileId 无覆盖更改外层名；应是单独的现址决定，旧节点、其内部正文叶、提交时 `a.xlsx` 以及旧回执不重写。此批不新增改名接口。

普通 MOVE 不改名；DELETE 从原普通父转入唯一独立文件系统的 R；RESTORE 从 R 转回删除时确切 Root/DirId 或明确的新普通父。三者源、目标最终容器叶使用**相同字节**。R 不是可浏览普通父；无删除时间、计数、Op 或“回收”后缀。不同 FileId 的同名文件可同在 R。相同 FileId 的第二轮删除会使用相同叶，绝不能以此给第一轮还原：每一轮比对当前 Retained 的 FileId、删除 Op、原决定摘要、当前归属代次和冻结父。每笔额度只兑本次原还原；前一轮旧 Op 的已完成回执只说那次发生了什么，不到 R 开当前容器。R 已有异物、等字节不同原件或上一轮尚未清退，不覆盖、不改后缀另存、不收养、不凭遍历删除。

仍是一份持久服务原件。所有新的读写先用同一确认前缀确定父及归属，再从持有的原登记根/确切 DirId 逐级定位派生叶，验原生体与本地 FILE 身份。跨文件系统在已发行的私票下暂放并验证**整个保留历史**，签唯一决定，目标独立重新打开后才按原票隔离/逐件清退来源；不因旧源离线或迟到冲突改读旧址。私槽和清退隔离名只属短期操作，绝不是额外持久容器名。普通同挂载 NOREPLACE 后，以及重开见终名时，在首次确认可服务之前核原父旧位已空、新父现名确为原件，同步两真实父。专用回收两方向只作跨文件系统交接。改变最终叶的拼法不放松已封未确认的回退、FrameSynced 后再验、精确旧操作离盘重取及不可回滚的已确认决定。

## 真实预算及格式边界

按 UTF-8 **字节**和组件分别算，不按字符数截短。原执行接口每一原生组件上限 255 字节，若所在文件系统可接受的上限更低按较小者，不能验证时不签新操作；普通 FILE 的物理叶比原显示名恰多 33 字节，所以在 255 字节文件系统上显示名至多 222 UTF-8 字节；目录没有这 33 字节。普通客户端的单组件长度另验不超过 255 个 UTF-16 code unit，不能把它和落盘 UTF-8 字节相混。绝不缩写 ID、砍扩展、换哈希名、以覆盖来通过。历史内部 FULL/INCR 和工作/私名各按自己的实际组件检查，不拿外层容器名改写它们。

对根和每级真实子父，**新驻留或交接**须在慢传、持久预留前检查所有本次会用到的组件：普通父的人类名（名录）、带完整 ID 的最终叶、8 个 43 字节暂存名、46 字节源隔离名；R 用同一物理终名及对应私名。原父/目标父的路径上限 4096 字节、256 组件按实际路径预算逐一计算，目录枚举行数和总字节按实际占用重新计；直系名录不把长度不同的逻辑行冒充物理行。对可作源的短名 `a.txt`，父长 4049 时最长 46 字节隔离名恰为 4096，4050 时即使暂存可用也必须拒。人类名长 20 字节时物理叶 53，父 4042 刚好、4043 即拒。255/256 原生组件边界另测（222/223 字节人类名）；超限不出票、不留私名、不耗还原额度。新建 FILE（包括将来显式生成新 FileId 的拷贝）、主分支改名等**形成新的物理终名时，必须同时按唯一 R 的原登记做无 I/O 的几何预检**：用该原父路径字节/深度和在注册持有 R 时核实、写入同一 SYSTEM 原登记的原生组件上限，核这同一终名、R 必须用到的 43/46 字节私名。无法取得可验证的上限不登记新池；不能默取 255。20 字节显示名、R 父 4042 即 4096 可，R 父 4043 即 4097，纵使 A 很短也必须在新建/改名出票前拒。普通 SAVE、读或同名搬移不因这个预算额外打开 R、不预留未来容量；真正删除/还原还须核当时两端真实父、实际组件限制与空间，预检不是在线保证。

只持久化原显示名与既有 FileId，不重复存可派生的长物理串或另一份名字键。按现有不可变字段、165 字节最大原生身份和 222 字节 FILE 显示名，子 FILE 的原出生 ALLOC 上界为 1023/1024 字节；两子父和五个角色的 custody 原帧及原 ALLOC 分别 2442/4096、1586/2048 字节。是字段求和，不是运行或吞吐证据；若编码改变须重新证明。扩名还须核目录帧/原票、FILE 头、独立版本组件、受限盘点和只属本单的还原额度。

**只支持一种新格式。** 同一批切换新池 SYSTEM genesis 的明确布局代号及根标签绑定、读写/冷重放的唯一名称策略。之前以人类名为物理 FILE、R 带删除票的池即使暂时为空也不能当新布局打开。没有按“哪种路径存在”降级、两套名称、就地迁移、扫描收养或清旧盘。既有用户介质不接触；对新池成功才产生新协议下的权利，未支持的旧格式报告不支持。

## 改动顺序和验收

| 源码边界（位于本项目 src/ 下） | 必须一起满足 |
| --- | --- |
| `ordinary/wire.rs`、`identity.rs`、`ordinary/journal/names.rs`、`pool/format.rs` | 一个精确显示名/原字节索引/物理 FILE 叶的实现；已确认行仍保留原拼写；双类型占名，原 FILE 身份不变；旧 genesis 拒在任何业务写前。 |
| `ordinary/material.rs`、`ordinary/directory/{file_home,inventory,path}.rs`、`ordinary.rs` | root/子父的出生、安装、当前/历史打开、目录创建、完整枚举以及原票恢复统一区分逻辑键与实际叶；准确区分未知占位与正常同名不同父。 |
| `ordinary/custody/{purpose,source,destination,placed,finish,retire,inventory,lifecycle*}`、`pool/lease/recycle.rs` | 去除 R 的删票终名，保留原删票授权。旧 `material::check_siblings`、`custody/incoming.rs` 及 `custody/target.rs` 的 ASCII 不敏感检查须一并换为精确逻辑名/原生名的准入，不能让 CREATE 成立而回收或原单安装又混称。统一两端实际叶与父、F0/I1/I2 五件、同挂载双父同步、跨挂载容量、私阶段和原实体退役。以前缀和本次完整名字过热/冷相同门。 |
| 对外枚举/FILE API、版本与以后 SMB | 只投影原业务显示名；未来 SMB 按对外名查真实 FILE/Directory，不发布私叶或内部版本名。这里不交付 SMB 服务、主分支改名、组移动或永久删除。 |

先静审纯名字与边界，再审可消费的内部件。根 FILE/目录/回收所有签发、读、恢复、物理名盘点与明确新格式必须作为**一致**切换，不能发出只有新写端或只有旧读端的介质。不存在沿旧物理名的子 FILE 兼容入口。N2 的本机 -at 命令沿用同一个派生终名，并用已确认的真实 Parent/Entry/原删除证据处理子父；旧根式命令不因此改为接受子父。源码验收至少：中文示例、多点/.env/已有 32 位后缀；同父同时创建 `Report.xlsx`、`report.xlsx`，写入不同内容，各按原拼写读取并核不同 FileId，分别删除、交叉顺序还原并核两份历史；`REPORT.xlsx` 在未建时不得命中其中之一，完全同名目录仍挡还原，Unicode 组合/分解形式互不代认；私名与正常物理名的正反边界及异物不被删除；同父跨类型逻辑冲突和越过逻辑层的物理碰撞两向；同显示名两 FileId 一起回收/分别还原；同一 FileId 删还再删与旧 Op；实际两端终名字节相等且无删除后缀；两个同名不同 DirId、失联/等名替父、F0→I1→I2（历史创建名/原内容）、迟到冲突/重开与后期清退；CREATE/MOVE/两类 RESTORE 的边界及超界保原物与额度。这些是设计验收条件；已有源码与用例不代表已经执行，也不是性能或实盘结论。
