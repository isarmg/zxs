# 单 FILE 移入专用回收盘和按原单还原（功能设计与本机成对源码边界）

**与新 Btrfs 后端的分界：** 以下是既有回收设计。新格式中尚待物化的自动节点若随原删除/还原跨盘，须把同一任务的目标 Raw、真实全量读写、具名全读及同步证据一起绑定进本次原决定，不再复制第二遍；缺证不得将其作为已物化节点接收，R 不获得普通写权限。[完整前置与还原竞态](btrfs-storage.md#校验搬盘和边界)。

这是一对业务动作，不单独交付一个“已经删除但没有还原路径”的入口。过渡验收驱动的旧根式调用仅表示普通卷根；[N2 的类型化业务](files-in-directories.md)也接受已安装的准确普通子父。这些不是产品 CLI。两者都要求同一 FILE 已收尾、无工作稿并已确认首 FULL；当前可含后续一至两个正式 INCR。包括曾正常搬到另一普通卷的相同干净材料；搬后才在新址正式发表的 INCR 不是此前 MOVE 搬过的物件。目录、脏稿、永久删除、内容导出、跨池、网络授权/客户端另案。源或目的身份不能证明就停，不恢复旧格式、不增加数据库、管理子目录、持久副本或查盘投票。

**位置和目的。** 每个可服务 FILE 在准确的普通父（卷根或已安装 DirectoryId）有一个按[存储命名](storage-names.md)派生的真实物理叶；软删除完成后同一 FileId 在本池登记的唯一专用回收根。同一 FILE 不可能同时属于两处。SYSTEM 保存原 EntryId/FileId/HistoryId、删除时的原普通父（原根式请求为确切卷根，子父请求另绑定原 DirectoryId、原目录决定与原物）、原人类名、删除操作、主体和经 SYSTEM 选定的删除时间。回收物理叶保持此次普通位置的原显示名＋完整 FileId，不加删除票或后缀。区分回收轮次的是 SYSTEM 的 FileId、原删除 Op 与决定摘要，不以物理名字、时间或同内容判同；两个不同普通根上的“a”分别保留。时间在原保留中一次固定、复用，不以文件时间或用户参数代替；按原决策序分页/排序，时钟回拨不改变原序。版本正文后缀、节点、分支、标签不因生命周期动作改写。

**同一发布流，不是第二个生命周期决定者。** 普通搬移、软删除、还原有不混淆的类型及请求域；仍用原 SYSTEM 日志/有界下界/唯一保留/密封槽和逐件退役。选取同一已认证前缀的 (池、FileId、创建事实、当前状态与位置 epoch、当前原站点决定、分支/版本前沿)。原处已不是出生地时，只接受该前缀的实际当前 native 根、目录和各叶；先前搬来的角色用其目标原物证明，后来新增的角色用后发 FILE 原决定证明。每次位置变化只增一次 epoch。删除从 Active 到 Retained，只能 Ordinary→登记的 Recycle；还原从 Retained 到 Active，只能该 Recycle→一个明确 Ordinary，绑定同 FILE、准确原删除 Op/已决定摘要、当前保留代次和所选目的根/人类名。旧删除不能恢复后一次删除，旧地址不能授权新 I/O。若要保留多笔历史，复用原日志按 FileId 与 Op 回放，不养一张回收库。原请求摘要包括操作类型、原主体、FileId/epoch 与原源/目的、以及还原的删除标识；改变目的必须是不同请求。SYSTEM 仍须给原持久操作留够帧/日志空间，失败不先隐藏源。

**能力和物理交接。** 原业务 API 只能借 Ordinary。回收专用持有类型只给当前经授权的删除/还原处理器，用原 SYSTEM 封包选定根与物理叶；不把它加入普通读、按名写、枚举、SMB 导出或路由。无跨池/错角色/同名新注册/替盘/借另一回收盘，也不把已认证但离线的角色说成有可读字节。当前仅相同已授权本机维护主体操作；不是首个发请求者或知道 ID 就能读回收区。以后服务应按原目录/文件与当前权限限制清单、回执和还原。回收盘必须是本池唯一原始登记的专用角色，且与 SYSTEM 和每个普通根均是可独立辨识的不同文件系统。删除/还原仅可真实跨文件系统 Transfer；相同挂载或文件系统 UUID、错角色、证据不全均在保留前拒绝，不改用 rename、其他盘或“逻辑删”。这是独立文件系统身份，不声称验证了不同物理硬盘。普通 MOVE 不获得 R 能力。准备前检查实际根、规范叶和所有必要私名边界/占用/最坏物理空间、完整源目录和真实读写租约。准备、读回、命名、同步及不覆盖均用原单；物理拷贝所有已核内容包括非当前 FULL，并按角色重证目标，不重放源 xattr 作为目的权能。准确新址独立重开前不清源，之后只隔离/逐件退役原源，确认实际原空目录才可结束。任一侧失联/未知/有人占用都不删除其名下任何可疑材料。

**可见性、离盘、同名和重试。** 删除未决定，原普通 FILE 可读；回收准备不是可见 FILE。删除已决定，原普通打开/名称枚举不再选它；回收列表可按授权显示原单、原位置/时间及“已决定、待安装/源待清”，区分 SYSTEM 已知和当前实物已核，不直接开放 Retained 正文。删除收尾前不复用原业务名，也不并发还原。还原先查回收原件和目标：默认若提供“原位置”意图，就锁定该次删除记下的原普通注册/父/名，离线、父缺失、代次变化或已有另一个 FileId 时拒绝，不重造原目录、不碰新 FILE。用户可显式选择另一已登记普通卷上的可用普通父（卷根或 -at 指定的已安装子目录），也可选择同卷另一父；实际目的必须无同名冲突，仍保留原人类叶名；这是新请求，不是将未完旧请求改投他处。原源卷已不在时，从已收尾的回收原件还原到另一显式目标不应打开原出生卷。回收盘不可证，恢复不允许部分交付。还原决定后，在目的全量重开之前不回读回收位、目录提示整单待安装；重开后目标可读、旧回收容器可能待清，写要等原单收尾。删除与还原各自的相同主体+Op+原参数请求查询原结果，不以今天是否重新命名/同名新建/已再次删除作否认，不用在线数据盘伪造原结果；重试若需物理收尾才核原绑定。列表逐项呈现当前状态；历史删除单仍可查但不当作还可还原的当前条目。分页游标冻结主体、过滤、原前沿和序号；时间回拨、R 失联或后来的删除均不改写旧页，续页重新核披露权限。R 离线是“原始状态已知、实物未核”，不是空列表。已有 A 读句柄可按其冻结原租约结束，新 by-FileId/by-NodeId、range/current 以及 CREATE 占名必须依据最新原状态；不因此让无关读取停摆。没有“修复”可通过扫描同名、相同摘要或把旧路径消失当成已退役。

**先为每个已回收 FILE 留出可还原的一笔，不靠未来日志轮换。** 由完整已确认原前缀推导当前处于 Retained 的确切键集合 (FileId, 原删除决定)；不是 R 目录的条目总数，也不是新持久登记。每个键不可挪用地占一个还原决定名额和一份最坏帧字节（当前 MAX_FRAME=4096；必须先证实本格式任何接纳的还原均能装入）。所有种类的原操作使用同一预算函数，普通写也不能借这个额度。设可信前缀有 N 笔、M 帧字节，本次候选的预留帧长度上界 S≤4096，模拟它的原始作用后保留键计数 K：普通业务 K 不变，DELETE 新增且仅新增自己的键；RESTORE 仅在严格匹配当前 FileId/删除原单/epoch 时消耗自己的一个键。只有 N+1+K≤8192 且 M+S+K×4096≤8 MiB 才允许新保留；整数运算全按不溢出。冷原合同/密封/原帧和下界回放遵同一作用与名额，不在每次重试重复收取固定槽位，也不能把未确认帧算成释放名额。已决定但源清未完的单据继续占实际全池操作槽，不能通过造第二笔还原绕过。该预算只保证还原日志名额，不保证 R/目标在线、不保证目录空位或真实目标磁盘空间；这些另验。同时保护笔数、字节：分别把一项边界挤到仅余1格/1帧时 DELETE 拒绝；两份不同同名回收物时，无关 X 写和第三删除都不能吃掉那两份剩余额度，还原其中一份只用自己的且另一项仍受保护。恢复权限、目的冲突和旧 R 损坏须独立拒绝，不通过释放预算或永久删除掩盖。

**前缀/重复周期的确切反例。** A→B 的普通 MOVE 冻三件；B 首次正式发表新 INCR 后，B→R（删除 N1）必须按其前驱位置与当前各叶实际原件冻结四件。R→B 或显式另一已核普通 A 的还原产生下一代，以新普通位置为当前；再软删 N2 时，N1 的历史查询仍成立但不能恢复 N2。不能对后续源套出生地的物理集合；每步在热/冷均核前序 custody 原帧摘要、正面角色、epoch、源/目的的各自实际叶名。原位置不宜使用时若在保留之前拒，仍可另发显式 B 请求；若已持久保留/已经决定只能续同主体、同 Op、同删除、同目标的原操作。此切片不含取消，不自动释放或重定向，必要时原单挂起。

**必须在开入口前成对提供的源码场景。** 真普通根 A/B + 本池专用回收 R。两个同名不同 FileId 分别移入，列表、原删除单、三/四项各自材料不串；错角色/外池 R、替 R、原 A 离线、空间不足，源仍在。已真实删除后 A/name 被另一 FILE 占用，原位置还原拒绝且 R 原件和替身不变；显式 B 还原不打开掉线 A，同 FileId/EntryId、旧 NodeId/VersionId 全可读，单 FULL 还原后按 B 原件能 SAVE/发表第一 INCR；已先搬 A→B 再在 B 发表的 INCR 随后删除/还原，原 MOVE 仍只冻结三件。删除/还原分别在保留、两端命名/同步、唯一决定前后、目标独立重开、每个源隔离/退役和末次空目录同步处重试。同一原单既不多发也不改址；错主体/原删除/代次、读者未放、占名、等字节换 inode、未完旧操作等全部有保全反例。未证明正确前不开放任何新入口。

**单列的容量/等待验收，没有测量或优化承诺。** 对当前完整核验路径，普通同挂载 rename 不复制 payload，仍至少有三次逻辑 FULL 核读（原源签决、改名前原核、安装名独立复核）。普通跨挂载 MOVE 连续完成时至少三遍原源（原核、复制、退役前核读）和四遍目标（匿名、已命名签决前、落位前/后）；同次源隔离保留已核句柄，重试丢失句柄才回到冷核验。本项减省不适用于专盘删除/还原；它们仍在源隔离前后分别核读。保留的 INCR 原件及其合成内容另计。这是不同阶段的逻辑读取，不是硬盘实读次数或墙钟耗时；缓存、系统重读/重试都不同。不能用「不抄同挂载数据」暗示不读、也不能只按当前逻辑长度预估回收盘空间。后续在独立投放的测试源码记录“巨大非 HEAD FULL + 裁成很小的 HEAD/INCR”，逐阶段分开计量实际逻辑字节/内容扫描、临时目标完整历史所需容量、外层原操作槽位等待。另设独立 FILE X（不属本 MOVE）和源 A 的长期冻结读者/源掉线：同一 MOVE 上 B 已可读、X 仍可读，但 X 的新 CREATE/SAVE 暂拒且无原回执；原 MOVE 精确完成后同一个 X 写请求才可成功。不要为这个用例放松池级占用，也不把该等待夸作并发保证。
