# 同一 ZXS ELF 的受托启动（隔离候选）

现有 Rust SMB 低角色仍只认原 `fd3` 匿名 SEQPACKET、原 `fd4` pidfd、单报文的内核 root 凭据和同一个内核发送者对象。先验证固定描述符，再核真实 EOF、封印、原账户和原 SITE；这就是唯一维护的 SMB 启动世系：不接受第二种启动、降低签名要求或回落到外部服务。

私有父侧预备从 Linux 原始 PID 和用户 namespace 核验当前唯一 root 线程、原 PID 1 的挂载/网络 namespace 与根，以及既有主管所需能力和可等待的子进程语义。它持自己的真实 pidfd 和实际运行的 `/proc/thread-self/exe`；比较独立批准的同一个原文件 FD 时还核原挂载和变更戳。不用 argv、环境、自算散列或任意 PID 作为授权。固定新通道只有匿名启动两端，从内核核原创建者、类型及每报文凭据选项。准备对象本身不发送报文，不创建公网或 SMB 监听；没有新命令。

内部启动源码只在同一份实际批准下组合实际宿主站点、SYSTEM 共享锁和同一宿主站点排他锁、明确的本地批准及独立的实际低权 SQLite 当代账户。仅进程或 ELF 形状绝不授予读凭据或文件的权限。独立低权预检只见原 S 的私有投影，不收可逃出投影的宿主目录 FD；子进程构造源码现在只执行同一已校验原文件，`clone3` 与原 pidfd 一次取得，私有数据投影不含 Loader、程序、秘密或宿主目录 FD；隔离 PID、mount、net、IPC、UTS 后只用固定内部角色、空环境、真实 null 标准流、降权、no-new-privs 和原父死亡绑定。父端匿名通道的唯一原端绑定亲生进程所有权，发任何 FD 前无入口换接。原 PREPARED 证明这条实际子进程已备好，不是整体准入、客户端互通或停机资格。先核实际原出生 pidfd、映像、投影、低权限和已安装的 TERM 处理，再在原 START 可能交出服务权的发送边界记下这一阶段。此后即使发送结果不明、没有 PREPARED，也只向同一原 pidfd 发 TERM；不同于已证还未交出服务权的启动失败。发信号／等待结果不明时保持封闭和原锁，保留原物直至实际退出并回收；已达交接边界的进程不能因超时或观察失败改为强杀。不保证外部强制杀死仍正常排空。独立低权预检只有原 S 的只读投影（不会更改宿主原挂载），只收公用封印、回复同原 scope 的有界公用清单并正常退出，不授予业务。父侧只返回私有的真实运行持有者；正常入口按[站点启动契约](../src/smb/launch/site/CONTRACT.md)组合两个隔离角色，不读 Helper 的运行状态来授权、没有独立公开 SMB 命令。首次实际安装签发、同制品冷启动和原生客户端分别验收；不接管或迁移现有池。

内核边界按 Linux 6.12 的 [保留初始 namespace 身份](https://github.com/torvalds/linux/blob/v6.12/include/linux/proc_ns.h#L37-L44)、[pidfd namespace UAPI](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/pidfd.h#L18-L28)、[procfs 当前线程解析](https://github.com/torvalds/linux/blob/v6.12/fs/proc/thread_self.c)和[私有挂载 ABI](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/mount.h)收口。新增源码夹具只说明两个匿名端都要能证明同一原 pidfd，未运行；不涉及真实池、密验、账号或端口。

高侧先让同一已批准的静态 ZXS ELF 在仅有原 S 的只读私有投影中证明当代已提交 ACTIVE 与原 F/R 清单，收其实际出生 fd 的一次性同原回执并等待零状态 reap。实际媒体凭原名、原挂载及固定角色标记取得持有；没有独立回收源时留空，不借用其他卷。只有易失的同终端、同真实站点、同原低权回执、同被批准媒体的一次性同意可开启原有计划的本地 TCP/445 地址；高侧不读密验正文。原 START 封印后交同一个实际低子进程，直到同原 PREPARED 与再次核验才取得真实子进程持有者。两个降权角色的 START 各带同一个不可改写放行门的真正只读 FD，绑定这次父进程、原 S/安装、同一实际共同账户代和同一绝对截止。收到两条精确 PREPARED 与原 EOF 并再次核存活后，只有原父在其保留的 FD 上能一次封印放行。各角色验证这一个放行，之后才 accept 或启动冷写任务；先存在的监听 backlog 不表示已办理客户端。原父最后复核存在失败或超时即不开门；共同放行也不是两个真正 accept 或处理成功的回执。只要不能确认确切退出/回收就留原现场，检查或接受失败也不能回退到其他运行方案。Web 是同一 `zxs` 中独立隔离的管理角色，不是 SMB 的文件数据通路；离线维护另有权限和锁。首次发行/切换不依据这段父侧源码或外部服务的历史结果。
