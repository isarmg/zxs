# 唯一存储后端：Btrfs

**实施目标，不是已开通的格式或实盘结果。** SYSTEM、每个普通数据根和唯一回收根都要求 Linux Btrfs。手动模式只在每轮首改时 reflink 出一份可写稿；自动模式每次确认真实变更时已经有一个可独立打开的不可变节点，后台仍须为**该节点**真实复制一份完整内容。两种模式不共用一条“后台复制”语义。Web 只管账户、共享、状态和版本元数据，正文只供有权的 SMB/业务句柄。

## 卷、实体与维护

- 管理员在 Linux 外部挂载文件系统。产品只使用明确选定、受保护的登记目录：不自行挂载、格式化、建子卷、修改挂载参数或把其他树接管为池。目录可以位于子卷内，不要求每个 FILE/节点都是子卷。普通目录不是快照。
- 先从不跟随链接的已持 FD 核 `fstatfs(BTRFS_SUPER_MAGIC)`；从 Btrfs 原生 `BTRFS_IOC_FS_INFO` 取非零 FSID，从同一原物取 `statx(AT_EMPTY_PATH)` 实际返回的子卷号、inode 号及完整类型＋原生 export handle（含实体世代，按不透明字节核）。池的 VolumeId 另由原登记颁发。**持久键**是 FSID＋子卷号＋inode＋原生出生；**本次现场**再查准确实名父链、原 FD、挂载实例、权限、角色和原标签。不能持久依赖 `st_dev`（Btrfs 按子卷分配临时 anon_dev）或重挂前的 mount ID；同 inode 号、复制标签或快照替身也不等于原件。新现场无所需内核能力或返回掩码不全即拒，不以路径/mount 输出代证。[Btrfs ioctl](https://btrfs.readthedocs.io/en/stable/btrfs-ioctl.html)、[内核实体与子卷](https://github.com/torvalds/linux/blob/v6.12/fs/btrfs/inode.c#L7362-L7366)、[原生出生句柄](https://github.com/torvalds/linux/blob/v6.12/fs/btrfs/export.c#L16-L35)。
- R 的 FSID 必须与 S 及所有普通根不同；同 FS 的另一子卷/挂载/目录不算独立 R。各普通根可在同一 FS，也可各不相同；不同 FSID 不证明不同物理硬盘。已登记根必须互不重合、互不套入；不能让子卷、bind mount 或快照提供未登记的捷径。外部以 `subvol=` 挂载可能藏住实际包含它的上层。两端须能从受信、已持的外部视图核清包含链和所有受管祖先；子卷包含关系的 parent_id/dirid 不等于快照来源 parent_uuid，仅凭当前挂载树或一个 treeid 不能证明无旧认领。所需祖先无权或不可达统一报“无法验证包含链”，不是坏盘，不私自挂载顶层、扫描或认领。冷开先从操作者选择的原 S 和原 REGISTRATION 核第 0 行、出生、标签、前沿，才使用表内其它路径；掉线只阻断确实需要该卷的工作。
- 新格式族拟名 **ZXS-BTRFS-1**，登记及卷标须有独立且不可混认的鉴别符，具体公共字节和独立向量另审。沿用 `user.zxs.volume` 的**属性名作为占用哨位**，只换值内不相混的族标识。空目录也可能已有旧认领；对候选根及受管祖先，只有实际 ENODATA 才是缺标，不知格式、空值、超长、读取无权或混合 PENDING 均拒且保留。恢复本次 PENDING 只能缺标或匹配同一原单，不能补异标。原 REG 本身须实在第 0 行 S 的同 FSID、同子卷中，是与该 S 目录不同的原常规 inode/birth。旧 dev/mount 排序不充当新跨池锁序；新规范用两边相同的稳定原生身份规范字节排序。拒绝旧 ID-LEAF-1 和 MAINT-1，包括位于 Btrfs 上的旧介质。不读旧池再改标签、不提供旧格式写、自动迁移或 ext4/XFS 备用引擎。只读识别不代表可写。helper 独立实行停机维护；ZXS 不调用它，也不代写它的安装/格式化逻辑。既有原 REG 常规 FD/OFD 在线 SH、离线 EX、初建根 EX 与跨池争同一真实卷根的有序 EX 均要保留；锁稳定原物至同步、活跃句柄排空，短目录锁或 systemd 状态不能代替。共享的是盘上契约，不是源码。
- 写入新登记或新加入卷前，离线有权的维护实现先取得所有需改的真实根锁，逐根留在同一原根 FD 内检查实际能力：在两个不同的私有匿名普通 inode 上测试；先在源写满超过该 held FS_INFO.sectorsize 的有界非稀疏数据（如两个扇区、用不易压缩的合成字节），同步，避免单字节内联数据就冒充已测过普通数据 extent 的克隆路径，再执行真正的整文件 `ioctl(FICLONE)`，核目标读回，改目标的相交字节后再次核源未变；只处理本次匿名物，不改任何已有用户文件。任一角色、身份、实际 CoW 或同步不符，在新认领前拒绝；恢复已发 PENDING 须保留旧标签/原票。只读盘状态不创建探针，区分“Btrfs 实物已见”“登记时曾证明”“本次真实克隆成功”。每一实际 FILE 首改/新自动节点仍须在精确的两个普通文件上成功克隆，不推测 NOCOW/校验配置兼容，不改配置求通过。同一文件系统是必要而非充分条件，clone 失败绝不偷偷变全量复制。必须确认原件遵守本协议的 COW 和业务校验要求；没有 NOCOW 位不等于已证明 Btrfs data checksum 或设备健康。不把块层加密称为已支持文件密钥策略，不明或不匹配不降级。[Btrfs 内联数据的克隆分支](https://github.com/torvalds/linux/blob/v6.12/fs/btrfs/reflink.c#L479-L499)、[Btrfs Reflink](https://btrfs.readthedocs.io/en/stable/Reflink.html)、[Linux FICLONE](https://man7.org/linux/man-pages/man2/FICLONE.2const.html)。

## 同一份业务历史，两种保存时序

正式关系记录 FileId/HistoryId/BranchId、父 NodeId/VersionId/原决定、本次 OperationId、版本创建名、正文长度与内容承诺。提交后不得将客户端的写 FD 或可写映射留在该正式 inode。每版可直接从该节点当前的一个真实普通文件读。不再以 F0+I1+I2、区间回溯或深链拼接解释它的正文；共享 extent 的引用和释放由 Btrfs 管。节点数只受真实日志、目录、存储和文件描述资源，不设两代或别的低世代上限。旧 Op 查询原事实，不给新的 I/O 许可，已撤权会话不继承新授权。

**手动：一份可写稿。** 读/开、相同字节且相同长度的操作不复制也不自动建节点。第一次实际改变时，在本 FILE、当前正式基底和工作代的租约内，取原节点当时已核的完整 inode（自动节点的 Hot 或最终 Raw 都可），在同一 FILE 原容器中新建不同私有 inode，实做整文件 FICLONE，写本次改变及准确终长、核相交块并同步。确认第一笔工作 SAVE 前原正式文件不得变。无正式版本时，从本 FILE 新的空原稿开始，不虚构父节点；既有语义中的首次已确认 0 B 稿有自己的回执，可后续显式提交空文件，无须复制。**没有后台全量复制，也不对已有 reflink 全范围预分配而强迫拆共享。**

后续每次成功 SAVE 用**同一可写稿 inode**。等待旧工作读者或写冲突只在本 FILE，不能先占全池唯一写槽。局部更新需要正常掉电语义：先持久保存本次有界 redo 的真实数据（含需要重建的边界块、截短/增长及相关索引更新）；SYSTEM 原 SAVE 对工作代、直接前驱、原稿身份、新修订/长度、脏布局和索引根确认后，才在排他的原私稿上应用并同步。确认后未应用完时，新读先按**同一原单**完成应用，或明确待恢复；不得读到半块、倒退或另调一个新 SAVE。确认线上不能有第二次决定；普通收尾后删除自己的 redo，不永久堆积每次写包。旧正式读者不锁工作稿，旧工作句柄按所选修订排空；完整应用前不复用同名替物或假定“同 inode 就好”。局部写撕裂时靠原 redo 的可用字节，而不是靠 hash 猜内容。已确认未应用的 redo 不得被重新分配的下一交易覆盖；长时读/复制不持池的下一决定号。

显式提交冻结实际工作修订（含索引），同步并把它作为本次正式不可变 inode 发布；以后不再给该 inode 可写 FD。新一轮等到第一次实际更改才 reflink，不直接开写旧正式版本。跨模式时须排空/明确处理已有稿，不用切换来丢稿或代提交。转手动不等候自动 C 的后台任务：C 的热原件本来就完整可读。

**自动：先发表，后实抄。**

1. 每次真正改变并被确认的保存是**一笔**事件：确认之时已经有一个新的、独立可读的正式 NodeId/VersionId 及原回执。已有父时对该父此刻的完整只读 Hot/Raw 实物取租，向新的独立 inode 真实 FICLONE 后精确应用本次写入、截短/增长；同步、核实新原物后才能确认。只有修改触及的范围需要新数据，不承诺确切写盘块数。无父的第一次真实保存直接以空白独立原件开始，仍须发表且进入同一后台规则。没有改动、失败或同一 Op 重试不制造第二节点。不能在第 21 次只记工作稿、合并多个已确认 SAVE 或以队列满为由吞版本；资源不足须在确认前明确拒。
2. 这份 **Hot(V)** 是逻辑上的完整独立普通文件，只是最初与父共享未改的 Btrfs 数据块。读 C 不必打开 B；D 以 C 为直接逻辑父，可立刻从 C 热原件克隆并发表，不等 C 的后台完成。局部覆盖越过 A/B/C 的既有字节时只改变该区间；截短后再增长，旧尾不复活。长读/克隆/移动捕获同一原节点、表示和位置租约，获取后不因同节点的另一次表示切换错读。
3. 对**每个**尚未完成的节点，依已确认的节点及其表示代恢复任务。向新且无共享来源的不同 inode，按完整逻辑范围分块 `pread` 源、`pwrite` 目的（包括语义零）；同步、从实际具名目标独立全读、验承诺/长度、核同 inode/出生并同步父。禁止以 FICLONE、硬链接、`copy_file_range`、文件系统快照或单改标签冒充此步骤。`copy_file_range` 可以用 reflink 实现，[Linux 说明](https://man7.org/linux/man-pages/man2/copy_file_range.2.html#NOTES)。不得仅从分配块数声称“独占”；此处的“独占完整文件”指这次通过独立新 inode、全量实际读写建立，不能由其他节点引用来提供缺少的字节，不承诺未来合法的 clone 永不共享其块，或特定磁盘扇区布局。
4. 持久阶段/角色有**不同名字**：例如正文热件 `.zxs-hot-<完整VersionStorageId>`，最终 Raw 仍为 `<完整VersionStorageId>-<版本创建名>`；完整的核验索引是该节点的独立角色，后台工作私槽属于本次操作。不可先删除或覆盖 Hot 给 Raw 腾名字。先核目标与原任务、确切现场位置和角色，后以同一 SYSTEM 的表示更新指向新 Raw；这不是一次 SAVE 或第二节点，不改 NodeId、VersionId、父、时间、长度、逻辑承诺、原提交回执或当前 HEAD。C 的迟到任务不把 HEAD 从 D 改回 C。成功前 Hot 仍权威，失败/中断仅留下原任务可识别的未完副本；源盘/必要原件不可用只能报原事实及当下不可读。成功后 Raw 才权威，不因 Raw 丢了重选旧 Hot。旧 Hot 在已获得的读者、发子节点的克隆、转移证据和旧任务均安全释放（及目录同步）后方可依原许可退役；已完成的 D 自持完整 inode，其共享 extent 的引用不需由应用补写。后台限每盘并发、可逐节点暂停重做，不让私副本占池写号等磁盘，更不能永久把队列当作“只做增量”。每次自动确认前须同时留出本节点后台完成所需的原日志槽/材料预算；对当时实际不可保留的未来空间明确背压，后来的设备故障/ENOSPC 报待办而非假报已经全量。

## 校验、搬盘和边界

- 新内容承诺明示算法和类型。一个位置绑定的分块索引（长度、按逻辑序号认证的块、树根）随工作或节点原件持有。工作后继在同一经验证原基底上克隆索引，复核相交原块、边界、被更改及新增零范围后更新受影响的页与根；索引不是正文来源。大段新零可用由长度/位置确定的零子树证明，不按扩展长度扫描父正文。掉电不能拿同 inode 的旧正文＋旧索引自认新修订。新节点不把父 SHA 与增量 SHA 的任意拼接说成文件平面 SHA。需要扁平 SHA-256 时从实际数据流另算，后台目标全读须与原节点长度和块承诺一致。旧文档的平面 SHA 只是旧格式事实，不改变字义。
- 同挂载、同 FSID、两**真实父在同一子卷**，且容器本身是其内普通目录时，普通 MOVE 才可选择 `RENAME_NOREPLACE`，成功后核旧名空、目标原件、同步两父。不同子卷/挂载，在确认前就绑定完整 transfer；跨文件系统普通 MOVE 和进出独立 R 必须实际流式复制、验证原 FILE 的全部保留历史材料、按原决定安装后再退原，绝不以 reflink 伪装，也不因 EXDEV 在确认后改票。R/普通之间同一 FileId、容器物理名，回收不加后缀，不存备份。巨大历史、极小 HEAD 不能只算 HEAD；也不把本机 COW 的共享空间误当跨 FS 的节省。[Btrfs 同子卷改名的内核约束](https://github.com/torvalds/linux/blob/v6.17/fs/btrfs/inode.c#L7821-L7837)。
- 每次交接冻结准确放置和表示代、所有保留节点的实物/索引及仍需完成的任务。短栅栏排空会改变表示的旧写者、停止再领旧址任务；不因排队或旧读者已存在就误删其原件，不用长期硬等所有后台全量做完才搬。实际确认前仍核同一原前沿、已同步目标、不覆盖；冷重开以同一操作所承诺的有序原件表判每个角色。若交接本身满足下一条完整物化条件，就只复制一次；否则新址按原 NodeId 接着物化，不能重复发表、借别代/旧址或拿传输成功直接冒充物化已结束。旧任务若丧失放置代即无权改旧处。退源要每个剩余实物的确定身份与可恢复的一步授权，已同步实空证明前不能把一个丢失的目录当作退完。
- **跨盘实拷与原自动任务合为同一份工作。** 对尚为 Hot 的 C，普通 transfer 或进出 R 若能达到该任务的全部条件，在发票前就绑定同一池/FILE、原 Node/Version、原 Hot 身份/表示代、该节点未完的任务、原/目标放置和应当建立的 **Raw(C)**。不是把 Hot 名字照抄后看标签猜测。由该次任务向新私有、无共享来源的目标 inode 做完整真实读写；只为这个节点写一份正文，核完整逻辑承诺、实际具名目的全量读回、索引、同步及可恢复的目标原生身份。身份页明确“原 Hot(C) → 目的 Raw(C)”，不能仅记“COPY 成功”。同一个原 MOVE/DELETE/RESTORE 决定原子记录放置及该节点完成物化的表示事实，消耗**它自己**的任务额度，保留原 SAVE 回执和原发布时间，不在 R 给一般后台写权，也不再抄第二遍。下界未抬则旧 Hot/旧任务照常；下界已抬未安装则按原票正面安装/重开，不能答“当前已可读”或从源回退；旧源读者与每件退役许可另算。
- 若某条路仅做同子卷 rename、目标仍共享、或不能给出完整的任务证据，不得记物化已成。普通新址用原任务再作真正实拷。R 首版只采用上条带完整证明的接收，无法证明就**在 DELETE/RESTORE 确认前拒绝**，不让只剩 Hot 的 C 在 R 里无限期等待，也不引入通用 R 写入接口。未来若确需容许 Hot 在 R 内独立收尾，应另审绑定原删除键/当前 Retained 放置代/原节点与原任务的专用借据；本基线不开放。验 C 仍 Hot 时 B→R、后台任务与 DELETE 抢先的两种次序、到 R 需可辨“未确认 / 已确认待装 / 可读且源待清”、随后还原及复删；旧 B worker 和旧删除 N1 均不能借新一轮切换或清物。还原额度预留最坏合法目的角色，不能因本节点物化挤掉别的原还原。
- 同一 SYSTEM 原确认者保留位置/逻辑历史和可重放的材料身份，有界原头绑定有序材料页（页序、总长、角色数、摘要；仅作为同一操作的附件而非逐页表决）。页可恢复、可在旧卷离线时从原 SYSTEM 确认，目标真实 native 身份必须在原表中。未完整页只凭原 INTENT 且相同已写字节前缀续本单，不截不明尾；全部同步并核原件才提升唯一确认下界。8192 个逻辑决定与 8 MiB 区间两项均计入真实花费；本次及未还 FILE 的一笔还原/其最坏身份页、以及已确认自动节点必需的表示更新额度不能互借，不用单帧 4096 字节限制代数。目录容量、精确长名/临时共存名、FD、数据与 Btrfs 元数据/配额都须计；事前估算不等于 `fsync` 一定成功。清理不删除未知对象。

## 实施与验收顺序

1. **先冻结边界，再接媒体。** 两项目分别实现同一新登记身份、原生只读观测与准确实克隆；不共享实现、不新增 CLI。现在的 `src/pool/format.rs` 及 `src/ordinary/wire.rs::NativeObject` 仍持久记录 dev/inode，新原池登记、原子父与所有 FILE/操作票必须共用同一稳定身份定义；不能只换登记格式却让旧 FILE 身份在重挂时误拒原物。`src/fs/birth.rs`/`src/linux.c` 仅有通用 UUID/handle；MAINT-1 空池/首管读件不证明 Btrfs。补“重挂 dev 变仍是原子卷 / 快照或别子卷同号 inode、同名字节替件均拒 / 同 FS 的 R 拒 / 非 Btrfs 不发任何新票 / 只读探测不修改盘”。
2. **一套原生 FILE 写读。** 替换 `ordinary/interval`、`delta`、`journal/graph`、`formal/baseline` 的常规工作/表示入口；不保留旧两代解释器作为第二后端。原 SYSTEM 的唯一确认、NodeId/历史回执、普通父/命名、同原登记租约到输出结束、已撤权不放行继续使用。补手动首改只有真实 clone、后续同稿、0 B/旧读者/同 Op/断电；自动 60 秒内 21 笔、C/D 逆序物化、各固定 Node 独立读取和第 k 次失败、等长同 inode 改物拒、无后台全量回执不得假称已完成。
3. **整盒接通才启用。** `ordinary/custody/{transfer,source,retire}` 与专盘不再按 3/4/5 固定叶角色搬；按原表做完整目的读回、收尾与可重试。覆盖 A→B→C→D（D 的一次覆盖跨 A/B/C 三个来源）、截短再扩的零、任意历史、普通卷→另一普通卷→R→原/显式父、离线 A、原删除/还原及老 SAVE 重试。原号不因后台任务/新位置生出新结果。监管非空数据盘使用需有单独迁移授权；项目本身不迁移旧池。新格式共同登记、读写、收尾与完整故障夹具闭合才切唯一业务入口并删除旧格式发行/恢复分支；不并行维护、不用当前过渡 argv 提供兼容。发布源码、编译/测试、在真实 Btrfs 验证及实际 SMB/管理 Web 可用是四件不同的事。
