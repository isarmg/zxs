# ZXS-MAINT/1：空池原登记、标签与同一原件上的互斥

**范围。** 这是新鲜介质上首次登记的字节和原生持有契约，不是 RPC、首管记录、业务已启用声明或跨实现运行证据。登记同时设定唯一 SYSTEM、一个专用回收根和 1–62 个普通根；没有备用卷。账户、既有池加盘/转换/永久退登记、重置、业务日志格式和服务启动仍各需独立准入。当前运行入口继续只认既有 ID-LEAF-1 介质。本规格的纯解析结果无权打开卷、签票或启动服务。不得在缺少覆盖每一入口的整段互斥时开启新格式写入。

## 1. 精确字节

整数全为无符号大端，没有填充、结束符（明确写出的 NUL 除外）或可选字段。`id` 为原始 16 字节，拒全零；不是 32 字节文本。`sha` 是 32 字节 SHA-256。长度均按字节，先验界，失败拒整件。

```text
GENESIS  = "ZXS/FILE-POOL/MAINT-1\0" | pool:id | init_op:id | storage_uid:u32
         | original:Entity | original_birth:Birth | count:u16 | row[count]
         | sha256(从 magic 第一个字节到最后一行的最后一个字节)
Entity   = st_dev:u64 | st_ino:u64                 # inode 不得为零
Birth    = n:u8 | filesystem_uuid:16 | handle_type:u32 | opaque[n-20]
row      = role:u8 | volume:id | Entity | Birth | component_limit:u8 | path_n:u16 | path[path_n]
label    = "ZXS/VOLUME/MAINT-1\0" | role:u8 | pool:id | volume:id | init_op:id
         | genesis_sha[32] 仅限 SYSTEM；另外两类在 init_op 后立即结束
frontier = confirmed_sequence:u64 | confirmed_frame_bytes:u64 | confirmed_head:sha
```

`Birth.n`＝21..148；文件系统 UUID 非零，来自持有 FD 的 Linux `FS_IOC_GETFSUUID`。类型保留 `name_to_handle_at(AT_EMPTY_PATH)` 原 32 位位型，opaque 为原 1..128 字节，不把它当路径重开。读得的真实 `statx` mount ID 用于每次持有期间重验，不能充当跨重启的 opaque handle。`component_limit` 是同 FD 的 `fpathconf(_PC_NAME_MAX)` 正值与 255 的较小数；未知、失败、零不默认为 255。`path` 为 1..4096 字节的绝对非根 Linux 原路径，1..256 个非空组件；拒内嵌 NUL、点/点点、重复或尾随斜线；不转 UTF-8 或做大小写/Unicode 归一化。

`count`＝3..64。依次 role 0（SYSTEM），1（回收），其余每行均为 2（普通）；普通根按原路径无符号字节字典序严格递增。VolumeId 两两不重；包括原登记普通文件在内，所有 Entity 各异、完整 Birth 各异，同文件系统的同型同 opaque 句柄不能冒充两物。各规范根路径互异且没有按组件计的祖先关系。原登记与 SYSTEM 同 dev、同 FS UUID。回收根与 SYSTEM 及每个普通根的 dev、FS UUID 均不同；多个普通根可与 SYSTEM 或彼此共用文件系统，但不是同一个原对象。这些纯关系不代替持有时检查别名、挂载和真实祖先。GENESIS（含 SHA）最多 275968 字节。

卷根属性名恰为 `user.zxs.volume`。原登记常规文件属性名恰为 `user.zxs.confirmed-frontier`，新空池必须为 `0:u64 | 0:u64 | genesis_sha`，总 48 字节。有属性但值为空不等于未设置；已有陌生标签绝不覆盖。`INITIALIZING` 和零前沿空池验收都要求完整 GENESIS 后无字节。已发表的 `REGISTRATION` 以后可有真实业务帧；零前沿解析器不得吞掉尾部或用 xattr 代替真实帧，已有业务须走完整前缀/操作解码，否则显式不支持。

`storage_uid` 是被部署时保护的 **存储服务属主**；根、登记原常规文件及运行时物理验证与此对齐。单个受限的本地维护服务主体是首次发行者；操作在其受保护的池/发行者命名空间内由 init_op 和所选原根集确定。不把发起页面的 Web 用户、`sudo` 调用者或临时 eUID 写作服务属主。维护授权在受限的本地入口独立检查，不能从此数或一把锁推出。首个管理员、凭据和重置不在此记录中；重试原登记不创建管理员、也不授业务会话。

## 2. 原生锁与发布

1. 新鲜池只有显式物理根选择。逐原路径组件不跟随链接，核真实祖先无已有卷标（包括空标），命名未换、实际目录、正式属主与不可被其他主体改写的模式。打开任何具名 `REGISTRATION/INITIALIZING` 前先以 O_PATH 不跟随链接核类型；私有普通文件须 0600、一个链接、同原挂载。持有正规 FD 后再次核原实体与出生句柄，不能因同名同内容而改认一物。所需 OS 接口不支持即拒，不降级。
2. 同一池现有在线守护进程、每个独立读写/恢复命令在**确切原登记常规文件**上取非阻塞共享 flock；在任何受保护业务 I/O 前取得，闲置、慢传和释放短锁期间仍持有，到最后排空、同步后才释放。离线操作者在同一原普通文件上持非阻塞排他 flock 到最终原件与回执读回/父同步之后。两边在锁后重新核原命名、正当阶段、原生对象/属主、池及前沿，不可从 systemd 或空闲推断。业务短事务锁位于 SYSTEM 目录（另一个 inode），不是该生命周期闩。一个命令内部用同一个 open file description 或受控 dup，不能用新 open 冒充同一把锁或泄漏给无关子进程。
3. **尚无登记时**先对所有将改变的真实根目录（含 SYSTEM、R 和普通根）按 `(Birth 载荷 UUID|type|opaque 的无符号字节序，不含 n，st_dev 数值，st_ino 数值)` 统一排序，取得整组 `LOCK_EX|LOCK_NB`。任一忙、重名/别名/嵌套、目录不可信、原认领不同或无法确认都退出；未签票不留任何认领。全部锁齐后重采原根/祖先、原空目录/标签、当前挂载和 NAME_MAX。不同 SYSTEM 即使各能拿本池 EX，也不能并步认领同一个真实原根。现池改变卷认领时先持常规登记 EX，再同序取全部受影响真实根；恢复若锁次序相遇全部用 NB，失败释放本次各锁，不持锁等待。
4. 在原 SYSTEM 用 O_TMPFILE 造 0600、nlink=0 的新登记普通文件；取得**同一个真实普通 FD** 的 EX，再由该 FD 的 Entity/Birth 构造 GENESIS，完整写、按 CREATE 新设初始前沿、同步并复核。用该原 FD 非覆盖 link 为 `INITIALIZING`，先 fsync 原 SYSTEM 目录；跨具名和之后改名都保留此 OFD 或受控 dup。按本单原选择为确切原根 CREATE 卷标，遇既有标签仅在**续同一已持久原单**且原物、全部字节吻合时接受，逐原根同步；不从取名或有无某标猜归属。全部反馈重验后，`renameat2(RENAME_NOREPLACE)` 将 PENDING 原件改成 `REGISTRATION`，同步原父，再确认只见 READY、与一直持有的那个普通 inode 相同、原前沿/角色标签吻合，才报告首次完成并释放。PENDING/READY 不可同时存在；禁止双名、复制成另 inode、覆盖、回退、靠扫描补标。
   - 有 READY 时只从**调用者明确选择的 SYSTEM** 开始：在原常规 FD 的生命周期锁内先对第 0 行的原路径字节/实际根实体及 Birth、原登记常规 FD 的身份、SYSTEM 卷标签所载 genesis SHA 和真实下界/已确认字节全部验明，才可采用表里其他路径；不能拿一份可自算 SHA 的未知文件指引去开盘。
   - PENDING 的恢复使用本次明确提供的**完整根集**，不是从中随便挑一个“可用盘”。全组锁后，先检查 SYSTEM 严格只有本次 PENDING，所有 R/F 目录严格没有任何条目；逐一核原物、路径、角色、NAME_MAX 和每个已有标签（只可缺或准确等于本票）。全部合格才补第一个缺标；发布前在同一组锁下再次核完整目录集、每个原标签和 PENDING 原物。后序根出现异物，本次调用一项也不改。
5. 冷接续须重新获得相同原件/根的全份锁和证据。持久 PENDING 仅可依同一规范 init_op、池/角色/实际原根集和原服务属主继续；原 inode 即使在路径/数值身份复用时缺原生出生证也拒。改名已成而父同步未知时先同步重核；历史回执不证明 R 或业务当前可用，纯查询不能推进。旧 MAGIC、未知标签或原本应在的证据丢失不自动新建；这不是旧介质转换。短时 flock 或单方实现不是互通证明。

## 3. 互操作向量与开放门

[固定的四根二进制证据（十六进制）](../tests/vectors/maintenance-genesis-v1.txt) 是合成字节，不接触示例路径；SYSTEM 与两个 F 共用一个模拟 FS，R 不共用，F 中有不可解码为 UTF-8 的路径。两边须独立实现并对照完整 GENESIS、原 SHA、四份角色标签及零前沿；不可共享项目源码。改 magic、行序、长度或角色、别名真实句柄、不合祖先、同 FS 的 R、变更主体或路径而不更新摘要、缺前沿/把 R 标当 SYS、尾随任意字节、同名等字节异 inode均有明确拒绝边界。物理身份、权限、锁或在线状态不能由内存向量冒充。

交叉时序：两个在线 SH 共存，任一未退出（含闲置、慢流、已停接入正排空）离线 EX 必拒；离线 EX 在任一最后反馈/同步前在线 SH 必拒；两个进程首次竞争、同池换 inode、不同 SYSTEM 争同一 F/R 均不可造成双认领。原声明可用且完整的前提，是独立离线实现确实写成原物、在线端由同一真实 inode 冷开并持到最后一个 I/O，且反方向的繁忙/替换均能拒。两个不同 SYSTEM 可在不同时刻中断，各自在自己的系统中留下 PENDING，却争同一个尚未标记的 F。失锁后至多一个原操作可最终认领该真 F；败者须保留其原票、自己此前已留在 S/R 的原标签及全部外物，拒绝继续，不“修复”成另一个池、也不保证历史上零痕迹。锁竞争未签出原单即失败的零副作用，不扩展到已有 PENDING 的中断史。这里没有宣称这些验收已执行，也不启用任一写入口。
