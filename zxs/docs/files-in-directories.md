# N2：在真正的普通目录中存放一个 FILE（本机源码实现范围）

> 以下 N2 的原票/帧和大小仅解释既有源码。确切父、完整历史、同名/不覆盖、收尾的业务边界保持，不以旧日志接入新池。 当前权威见 [SQLite SYSTEM](sqlite-system.md)。


此处的根式和 -at 调用仅区分过渡验收驱动的两种参数范围，不是用户接口或兼容协议。[Web 只管理、SMB 传输普通文件](web-and-smb.md)；下面的身份、原材料与重试语义属于同一个业务内核。

目的：把 FILE 创建在已经登记并安装的普通 DirectoryId 下，用户能在原父目录看见它，按 FileId 编辑，按 NodeId 读原版本，也能把同一 FILE 搬走或放入专用回收盘再还原。不是根据字符串查找第二个容器，也不是增加另一套工作区。下列契约共同约束本机入口，尚无构建、运行或实盘验证。

**一个父，一个原件。** 业务地址是 (普通 VolumeId, Root|DirectoryId, 规范叶名)。另有永不随现址变的 EntryId、FileId、HistoryId 和操作 ID。采用 N1 的同一次 SYSTEM 前缀：普通根取真实注册；子父取此前本卷上已确认且安装完的 mkdir 原决定，核其 DirId、原帧摘要、原生实体，并自注册根逐级重开同挂载、无链接、无卷标的原目录。只在已授权的父下读取或写入。末端有东西只能拒绝目的占用，不能据此证明它是给定 FILE，也不能把 FILE 容器或回收区当普通父。不能用目录名/最新路径补未知字段，不在普通目录里加索引文件。使用现有名字、总路径/层数、目录项数/字节、FD 与票槽上限。

**原决定与现址分开。** 现有根级 CREATE 的原帧类型明确表示 Root；新增子目录 CREATE 的原帧/请求和原 ALLOC 有专门判别，必有同一登记卷、确切子父 ID＋原父摘要/实体，拒绝缺字段、Root 别名和多余字节。两类严格解码到同一个 FILE 出生模型／原名录，不做猜测、迁移、双写或平行登记。用户选父的含义就在原请求中；父原生凭据由本次受核前缀补入已签发票，不由用户输入。核本池、维护 UID、全局 Op/票、Entry/File/History 身份和原前沿；完整未确认尾撤回其占名/索引，原 ALLOC 只在自己原父排他占名。物理 FILE 元记录与 F0/I1/I2 的正文、节点、版本、分支、原名和摘要不因父/盘变化而重写。出生收据说“创建在哪”；file-info/当前目录则说“现在在哪里”，不要用其中之一伪造另一个。完成且丢响应的原请求先返回原据，不要求当前原父或数据卷在线；同一 Op 换父绝不是重试。新 I/O 一律从现行原决定取得位置、代次、确切 FILE 容器及被选叶。

**创建及名录。** 新入口取稳定普通父＋一组件名字；原根层 file-create 和 file-list 的准确含义不变。复用同一 FILE-ALLOCATION、一个确认下界、同一容器/FILE 元数据出生和 NOREPLACE 安装；父不是路径参数。所有可能需要的名字按实际父和票在持久预留前预检，包括业务名和八个私槽。私槽始终由原票、原父、原实体授权；未绑空槽不认领/删除。FrameSynced 后抬下界前重核原父链、准确原票和容器元记录、完整父名录及终名；决定后只认私名或终名之一的同一原件，补原父同步再报现场完成。dir-list 只列此父直接 FILE＋Directory，file-list 只列根直接 FILE，不递归或把子 FILE 混入。决定未确认不列，决定已过但安装未证须明确 pending 或拒绝完整列表。已有 FILE 的晚到待清、专用回收与私名只计原父范围；同名不同父互不占用。入新子目录前也必须能创建、查看已登记父的其他普通目录，不把合法子 FILE 当作未知。

**不能把 FILE 放到以后仅因路径长度就无法移出的子父。** 首次在 Child 创建、普通 MOVE 移入 Child、RESTORE 返回原 Child 或指定另一 Child，均在慢复制和签发原保留之前，用同一真实已安装父的绝对路径／组件深度核由显示名和完整 FileId 派生的实际终名、八个 43 字节私槽和将来 46 字节的源隔离私名。隔离名由格式固定宽度，与未来具体票值无关：父路径 4049 字节时，4049＋1＋46 恰为 4096；父为 4050 字节时，即使业务名和全部创建槽合法也必须拒绝，前沿不动、不留票或私名，原源仍在。未运行的原生用例分别覆盖子出生和 MOVE／RESTORE 移入的正反边界（`tests/unit/child_file_start.rs`、`tests/unit/custody_handoff.rs`）。这只是路径几何检查：不领未来操作票、不预留未来空间、不打开未来目的卷或回收盘。真正的移交仍须在原操作时按真实两端、完整历史、准确原票与规范名重新核验；此次几何门不改变已有纯根请求或已决定原回执。

**实际读写不能只接出生。** 从同一个已确认 SYSTEM 截止签出可重开的普通父与 FILE 选件，替换 material、working、formal、interval、delta 中把 volume.root 当作业务父的调用；只在实际执行阶段授予最小读/写。按 FileId 在子父完成空读、首稿、第一正式 FULL、顺序范围 SAVE 与受支持的 I1/I2，能读当前叠加和各个旧 Node。慢 stdin 及输出仍按已固定原件/租约，不持全局锁；重新取得 writer 时校验同一原工作边、当前放置原键、父链与源及目标实体。旧工作句柄不能因同卷/同名就跨父改绑。未完成原提交拒绝时不能动保留稿；已确认的原帧不可回退。查询已有原回执与报当前可读分别进行。

**同名移交和回收成对。** 当前为根的原 MOVE/DELETE/RESTORE 继续按原票重放。子父涉及移交时，普通端原票必须携带/派生并核实确切源、目的的有类型父和各自原实体；R 端取与普通端完全相同的 FileId 派生容器名；只能凭当前保留的原删除单核准该原件，不能按终名代认删除票，也不伪造普通父；不同父对象不允许借用同盘/同名的旧许可。普通 MOVE 保留目前首次 0→1、两个不同已登记普通卷、同名、干净 F0 至 F0+I1+I2 的支持边界；目标明确是注册根或已安装普通 DirId，不能写成未输入/未核准的根。删除以删除时的现址为原位置（可能已经不是出生地），RESTORE original 恢复到该确切父/叶，不到同名新目录，也不降级到卷根；显式新目的可在另一普通父收原 FileId，保留前不打开无关离线旧父。若已发行原保留不得临时重定向。返回真实恢复页/原状态所需的父信息属于该次原删除事实，历史查询不走 R 或原父。已有回收额度只供自己的原操作；在任何签票前证明新编码最坏原帧≤4096、ALLOC 可完整容纳，并核实际全历史容量和每个源隔离/目标私槽以及最终叶的真实路径。对保留库仍只计一笔和一个最坏帧，不能靠以后可能清理的日志过限。MOVE/DELETE/RESTORE 的完整历史核验、独立重开目的和逐件隔离退役不缩减；同挂载 NOREPLACE 改名之前的核验或同步不能证明安装；实际改名后（包括冷开已见终名），首次承认可读以前必须在同一原 writer 重新核两条原父链、原源叶已空且目标叶正是同一原实体，并同步旧名所在确切父和终名所在确切父，然后复核。任一父不能验即待办。跨挂载已独立重开的目标可在旧父离线时读，不回退旧处；旧源隔离与逐叶退役只承认该票冻结的原父/原叶/原实体/隔离名，不能找同卷另一个父下同名物替代。专用 R 两向仍只跨文件系统 Transfer。已决定装好/源清理待办不是两个活 FILE，目标离线不回读源。此次不做同卷目录间 relocation、整目录移动/删除、业务改名、分页授权或网络入口，未支持组合在复制/原预留前明确拒绝，不能造半单。

**原请求如何认父。** 不仅封存的材料要认父：MOVE/DELETE/RESTORE 的规范请求本身、ALLOC/INTENT、历史原回执的离线匹配均须绑定每个普通端的完整 Root(卷) 或 Child(卷,DirId)，以及操作域、原主体、FileId、Op、原代次；RESTORE 还必含原删除的 Op＋决定摘要。R 端只取专用角色和这张原删除。原根协议不是按卷放宽的别名：MOVE 双普通端都为根、DELETE 原址为根、RESTORE 所求删除原址和恢复目的均为根，才走各自现有根请求语义；出现任何子父均在明确的父作用域内编码、重放，不能在根专用命令中靠同一卷匹配成功。RESTORE original 在 SYSTEM 原删除前缀就解析出完整父地址，显式输入只有与这个完整地址逐项相等时才表示同一个规范请求；不能借当前挂载/名字计算原址。同一 Op/Epoch/卷从 B/left 换成 B/right 绝不是相同请求。出票前实际来源、原删除事实或已准备材料属于另一父，就在写票前拒绝；不能用为 B/left 选好的材料签 B/right。完全未发行时另选新目的须重新受理/准备，不能称为已签原单的重试；一旦有原票，直至全单已完及卷离线，错父请求一律拒绝，不改原单。回收分页的 SOURCE 仍指整个普通来源卷，冻结行另报删除当时的父与叶而非今天路径，由 FileId+原删除区分同名物；不增隐含跨父授权。

**分片及验收（源码，不执行）。** 先做根/子确切原协议和亲子位置投影、再做共享基于持有原父的出生和既有读写、再做移交/回收两端父与直接清单的完整收口。过渡阶段即使已写编解码和内部类型，公开和冷签发均不得接受缺少下一阶段读写/回收证明的新出生；不把一个不可用或只能读的 FILE 提前放到普通目录。以两卷 A/B、专用 R，A/left 与 A/right 下各一同名 FILE，A 根再有同名 FILE/替身为对照。用实际 CLI 原请求+断点证明：(1) 根与两父各列自己的 Entry/File/Dir，子父 mkdir 和 FileId→F0/I1/I2 全链，旧节点正确；候选同名不同 FileId 绝不能补来源；(2) 票在完整帧/下界/安装前后、两种迟到碰撞、父或祖先移位/同名重建，热冷失败不占新票，不误认已决定；原历史已完成的请求离线返回；(3) A/左→B/指定父，A 失联后读真实 B（能编辑的正式阶段仍可编辑），原名新 FILE 不动；(4) B/父→R，同名新 FILE/目录或同名替代父挡原地还原，原单未发票，显式新目的可成功；决后换目的不可，所有历史/身份不变；(5) A/root→B/left、A/left→B/root 都验证下界边界，B/left 与 B/right 同名不能串票；把删自 B/left 的 FILE 原位恢复只进 B/left，即便 B/right 有同名 FILE，后者的 inode/历史/内容皆不变；同挂载在 rename 与双父同步之间被打断，两原父都重开之前不放行，跨挂载目标已独立重开而旧父离线仍可读；(6) 同 UID 慢读/写、两张保留额度、未知对象和异常不触碰，长路径恰过/刚超、五件中被遮盖的最老实物损坏都按原门拒绝。这里只使用可信本机维护主体，不声称抗同 UID 主动篡改、跨用户授权、性能/实盘或系统断电保证。
