# 分块续传的安装验收

[设计中] 本页是独立 Linux 客机验收计划，不启用服务入口，不表示已验。线协议见[分块续传](../specs/resumable-uploads.md)。本轮不连接现有服务、现有盘或用户账号。

## 固定实物与隔离

- 固定审核后的 ZXS 候选提交、Helper、工具链、系统镜像、TLS/HTTP2 依赖和试验夹具摘要。候选用真实服务入口、原角色/账户和正常安装方式，只在手动受控的无网卡临时客机运行。主分支、现有服务启动选项、默认客户端、代理配置与部署不变。
- 专用夹具只转发固定环回的目标、规定的方法/URL 和保留的精确长度。真实 TLS 验证指定 SAN、信任链及 `h2` ALPN；没有服务身份注入、Basic 兜底、凭据或内容日志。
- 当前已安装客户端的 CA/原回执夹具不是流式证据：中转最多收 16 KiB，等待完整消息后转交，只将 POST 正文转送。保持它原样，另用窄范围流式中转；收到受控请求头后先打开固定后端，将每个受限 H2 DATA 分组直接送入同一精确 H1 正文，不能在边缘组装整个块后一次送出。循环、队列、请求/回应和测试总时长均有限。

## 通过条件

| 步骤 | 必须观察 |
| --- | --- |
| 鉴权前拒绝 | 新续传入口缺证、错证或送 Basic，均不进入上传正文或注册；夹具的 SYSTEM 控制命名空间、DATA 原件和值都不变。 |
| 已开始但答复丢失 | 本来成功的开始答复不交给客户端。随后只查原 C/O 的回执和固定 GET 进度，取得真 U，不新建第二条登记，不自动重发。 |
| 合法慢块 | 真实传入 8 MiB，按约 0.6 Mbit/s 的裸数据速率实际流向后端。记录后端首/末原始字节、转发总量及服务答复，首末间隔明确大于 60 秒、小于 180 秒；准确得到持久偏移。仅在前端延时或后端一次性收到正文不计通过。 |
| 绝对超时或截断 | 同一整块约定在前一持久偏移之后发，受控通道不给足字节或持续低于固定时限；记录实际不完全流量和拒绝。原声明偏移为唯一依据，后续原 C/O/U 的读验证不推进。拒绝不把下一请求数据并入本次正文。 |
| 重新授权 | 重开真实服务后，旧 Bearer 原样拒绝；用户明确同纪元登录，先做准确的原回执 GET。只有明确再次操作才可续 PUT/提交，不因状态缺失、`complete` 或令牌变化自动写入。 |
| 精确提交 | 对同一个 C/O/U 重核原目标、整长、SHA-256 和 EOF，同一个 Store 原始业务回执才是成功。单独查原回执与实际不可变正文核对；不接受额外操作、重复登记或换盘。 |
| 保持旧路径 | 原 Basic 整文件写入和现有只读回执/区间入口还按原规则处理，不为坏续传代送原 Basic 或添加任何别名。 |

8 MiB 在 60 秒内的裸速率约 1.118 Mbit/s，180 秒约 0.373 Mbit/s。现实代理、认证和 TCP 等待需要额外余量。测试须使用后端接收相邻时间点，明确开始条件、停止原因和是否见到完整回复；不能用客户端睡眠时间代替实际流量，也不能以通用 TLS/网络故障充当特定预期拒绝。

## 明确不计入的证明

- 原始协议驱动只证明安装后的服务器与实际 HTTPS/HTTP2 传输。默认客户端不改变，另需显式、类型限定的客户端入口及其原工作区/授权证据；必须独立证明没有隐式开始、重传、提交或认证降级。登录 POST 与资源写 POST 分开计数。
- 重启用来证明旧令牌失效及持久登记仍正确，不冒充同进程内 900 秒会话过期或内存 SHA 继续证明。真正的同进程时间范围/显式重认领是另一个有界资格。
- 候选、本机源码及自动测试不是实盘掉电、源盘重挂、任意代理配置或部署性能保证。只保留可对比的候选摘要、日志判据和状态/计数，不发布数据、令牌或真实盘坐标。
