# 新池首设与离线重置：Web 和 SMB 共用一个账户

本私有候选的 Web 管理和内置 SMB 使用**同一用户名和密码**。一个规范 AccountId、一个名字、一个待决或生效的凭据代。两条协议仍分别认证：Web 登录状态不能换取 SMB 会话；SMB 会话不能管理 Web。SQLite 里的两个稳定角色主体键是权限域，不是第二账号，也不是令牌。无默认密码、匿名、来宾、在线改密或回退认证。

- 登录名是 1–64 B 规范小写 ASCII，首字符为字母或数字，余下可含 `.`、`_`、`-`；排除 `guest`、`anonymous`、`nobody`、`root`。Web 比较原样；SMB 按其协议规则接受同名的 ASCII 大小写，不产生另一个配置名。固定域为 `ZXSLOCAL`；SID、目标和监听来自同一受保护的原安装，不采用来信自报 SID。
- Web 只使用随机 16 B 盐和 32 B Argon2id v19 校验值（64 MiB、3 次、4 lanes），留在原 SYSTEM SQLite。SMB 只使用 [`vault/credential.v2`](../src/smb/credential-record.md) 的原 NTLMv2 等价材料：仅核实本次低权 SMB 角色才可读取实际正本。Web 不读 SMB 正本，SMB 启动不取 Web 校验值；高侧只核公开绑定和原件元数据。输入同一个受保护口令不等于存两份明文、持久化 NT hash，或在两角色间传密码/会话。
- 首设和重置各是一笔有独立批准的原操作。重置不改名字，不轮换角色主体键。一笔已确认的历史仍以当时的主体/凭据代解释；旧会话、旧工作单与旧票据不能因新的共同凭据代而继续获得当前权限。
- [管理 HTTP](web-management.md) 是明文，泄露共用口令同样危及 SMB。请只在受保护的网络内访问。

## 原安装内的离线顺序

1. 一次本机维护批准绑定完整原池/INIT/SETUP、实例、PLAN、登录名、目标记录及前驱。停在线两角色并确认实际排空与退出；原 S EX 再取同一原站点 EX。新设只针对明确获准的新站点、从未首设的新格式池。不从未知或半成现场建新单；不从 unit 状态、路径、原名或旧回执获得许可。若实际前驱仍有未解决的 FILE 出生或未退出占位的目录出生，或扫描不能在界内作结论，重置拒绝，不另做清理。预审和实际原 T1 都必须有此判定。
2. 同一低权维护输入在受保护终端读取并核对重复输入；分别派生 Web 校验值与 SMB 材料。SMB 材料写本次受控的原 staging inode，不能用于登录。短事务 T1 只为这笔原单保留共同操作/代和非密记录号，并提交正确的 Web 校验值及盐。首设用 kind 2，重置用 kind 9。T1 一旦确证 PENDING，两路都不得继续旧代，也不得提前使用新代。旧单未决、混合现场、不可读或不能证明同一原单都不是回退许可。
3. 同一原 vault 内按确切前驱放置正本；同步该文件与原目录，独立重开重核真实名、inode、同一公开前缀和范围。短事务 T2 再核同一 PENDING、前驱、代、已落位正本的实证和原 Web 盐/校验值，条件提交后才使**同一代**对两角色生效。首设时同笔写入批准的原始 F 发布和初始模式。SQLite 的原子性只覆盖库内，外部文件发布靠独立持久/原件信号；看见 vault 条目或 SQL 更新行并不等于确认。若换成不同口令，旧口令两路皆不得通过；无论输入如何，旧会话与旧代权限不复活。
4. 中断先查原 Op 与真实现场；原未知、已换物、已变代、无法核验或提交回复丢失都不能重发新号、绕过读回、清异物、猜成功。本候选不接续、收养或清理既有 PENDING；新的设置/重置拒绝已有同单，回执查询只读。原回执只说明确证的原状态，不是当前登录或原件清理许可。

## 公开字节与验收边界

[唯一 v18 DDL](../src/system/schema.sql)、[公开比较字节实现](../src/system/shared_account.rs)与[固定独立样本](../tests/sqlite/shared-account-public-v1.txt)定义同一合同。两个操作分别用含尾 NUL 的 `ZXS-SQLITE-1/SHARED-SETUP-1\0` 和 `ZXS-SQLITE-1/SHARED-RESET-1\0`。共有前像依次为 Pool、INIT、SETUP、Instance、Bind、AccountId（各 16 B），原 INIT 与整份安装描述的 SHA-256（各 32 B），1 B 名长与原名、28 B SID、原维护主体和本次批准（各 16 B）。首设追加首记录号；重置追加本 Op、前驱 Op、前驱记录号、8 B 大端前驱正代及目标记录号。两个业务主体键分别取 `SHA256("ZXS-SQLITE-1/ACCOUNT-ACTOR-1\0" | AccountId | role:u8)` 前 16 B（Web=0、SMB=1）。没有秘密进入这些摘要、配置、命令行、普通日志或回执；知道摘要不能授予权限。

SQL 的唯一当前选择先看**最高尝试代**，再验证这代完整且已提交；历史代仅供解释原操作。部署启动须两角色各自核同一原 SYSTEM 安装/当代，给出本次原 PREPARED，由父进程一次共同放行，之后才接受客户端或启动冷写任务。新 SQL 族标识和新 SMB 正本版本是隔离旧双代语义，不是升级程序。旧格式不打开为业务、不改写、不迁移，没有长期并行维护路径。公开向量、真实隔离 SQLite/Argon2 测试与原生客户端端到端验证是不同证据；完整离线签发、实际双角色冷启、断电/换物和两协议同账号登录仍需以同一批 **ZXS＋Helper** 制品检验。
