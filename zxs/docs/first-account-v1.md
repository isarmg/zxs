# 首次设置与离线重置：SQLite 的 Web 管理员与 Samba 的唯一用户

两个固定身份、两个互不代验的协议。SQLite 是池、Web 凭据与业务授权的唯一权威；专用实例的原生 Samba tdbsam 是 SMB 凭据的唯一权威。[在线登录契约](smb-native-session.md)说明如何把两者正面相交。两库不做分布式事务，不在 SQL、收据、原单、环境、命令行、日志或普通中间文件留 SMB 密码/NT 验证值、派生校验串或备用秘密。设置或重置只能由独立 helper 在本机执行，还必须有**这一次、针对所选角色的实际维护授权**。

### 身份、代号与保管

* 池仅有一名 Web 管理员及一名 SMB 用户，各有不同的 AccountId 和规范名，无默认密码。两名维持已有小写 ASCII 文法、1…64 B、不同名；拒保留的 guest/anonymous/nobody/root 及任何与实际部署不相容的身份。域 `ZXSLOCAL` 和 RID 1000 的真实 SID 由独立受管安装及其 BOUND 和原域核证取得，不能由客户端或运维者提供一个裸 SID 替代。Web 密码的 Argon2id v19（64 MiB、3 次、4 lanes、16 B 随机盐、32 B 验证值）只留 SQL；协议名、固定低权 NSS 执行名和线上的认证授权各有职责。
* 给唯一 SAMU 的保留描述字段 `acct_desc` 写入一个**非秘密**的精确 ASCII 标记：`ZXS1:<池>:<实例>:<SMB账号>:<本次凭据Op>:<代次>`。前四个变量各为原 16 B 标识按原顺序的 32 个小写十六进制字符、非零；末段是正整数的 16 位零补小写十六进制，首代 1，上限 0x7fffffffffffffff。[跨实现固定样例](../tests/sqlite/smb-native-epoch-v1.txt)。语义载荷总长 153 B；上游账户记录以 154 B 存放，末尾只有一个 NUL。在原生解包还有显式字段长度时核长度、载荷、单个尾 NUL；不能仅凭 getter 的 strlen 排除被截去的内嵌 NUL 或后缀。没有可选字段/空白。名字、域和 SID 从原 SAM 和绑定另验。标记不含密码/其摘要，不是登录票、原盘证明或用户自填的描述。其作用是**在同一次原生 TDB 凭据提交中区分新旧操作**，不是外置的新台账。固定源 `passdb.c::init_buffer_from_samu_v4/v3` 持久化该字段，`pdb_tdb.c::tdb_update_sam` 在一个原生事务中写账户和 RID 项。
* 新 SQL 仅保留角色/主体、实例/域/账户绑定、原 Op、前驱、代次及阶段/回执。历史 SAVE/CREATE 引用的旧凭据 Op 必须仍可查，当前授权只能选该账号唯一活动代；旧代已经确认的 FILE/回执不消失，新代能在当前共享权下正常读它们，原在途 FILE 写单不能借新代升格。不能因换密破坏历史 FKs，也不能用历史 Op 授新权。新库没有 `smb_password.nt_owf`、密码镜像或按名字取 SMB 材料的查询。原数据库 v6 的写入和夹具只是待退役源码，不是另一种新池。

### 先封住在线准入，再改一份真凭据

1. 停止双方对该实例的新会话，排尽旧会话、FILE 句柄、异步工作和在途确认；确认整组退出，旧进程不能再写。helper 按共同顺序在原 S 目录得 EX、在准确实例原目录得 EX，保留至最终同步/关闭。一个停机状态字符串、一个文件路径或改动后才发的撤销通知都不够。错池、未批准、数据库/域被换、原操作或准确旧代不符时不作任何持久写。维护密码不由服务/Web 或 Samba 网络 RPC 接受。
2. 在 SQL 短事务登记准确原操作、原池/已提交 INIT、实例/BOUND、主体与批准、目标角色/账号、前驱与期望新代。首设还冻结两名、两个新 ID、Web 盐及验证值，但 **SETUP_PENDING 不可登录任一协议**。重置仅关被重置角色的准入；另一角色的绑定和代次不变。原操作不确定先用明确的原池、操作、主体与规范非秘密请求查验；待办和已完成必须可分别识别。**只有此事务耐久后**才允许产生本单的原生持久效应。
3. 仅 SMB 首设或 SMB 重置：在已核的那一个原专实例内，使用固定版原生凭据库。首次只准明确授权的新现场；不得收养陌生同名库、覆盖现有用户、升级不明格式或拷贝密码库来做回退。精确新建需在专属 accountdb 父的原维护权下独占留置新库，原生事务直接初始化准确的版本两项 4 和 0，不用 stock 空库也会进入的升级、复制临时库或导入旧 winbind 状态的分支；掉电后只有 SQL PENDING 和今天路径缺失，并不足以区别“从未创建”和“已丢原库”。不能证明则停。旧代重置只可修改原唯一普通用户，不能改名/SID或重生账号。受限离线录入口把新密码只用于目标原生凭据行，在**同一 Samba 账户事务**中同时更新凭据及新标记；调用结束并核原名下库、父目录同步，再经独立原生重开复核唯一准确账户、名称、域/SID、普通启用策略和完整新标记。同一原 TDB 的 USER_ 帐户键与 RID_ 索引须**完整遍历成功**并逐项一一匹配，仅有该用户和 RID1000；孤立/重复项、额外或禁用账号、未识别的用户数据、不完整遍历或读错均拒。原生数据库控制键不是用户。只遍历 RID、会跳过异常/不返回底层完整状态的 stock `search_users` 不可作此证明，不导出密码字段。纯查询还须真只读，不能用会自动解锁账号/写登录计数的高层 `pdb_getsampwnam`、不能改库或暗中恢复。禁 LM、保存明文、密码历史、自动格式转换/备份及弱认证降级。不能直接用会忽略密码转换失败、计算 LM 或保留暂存明文的 stock setter；原生读写 SAMU 时涉及的历史等策略须从受管实例中确证，不能暗建全机策略库或改宿主配置。原生 TDB 的内部崩溃恢复不构成第二个登录库；不声称底层介质无陈旧字节。核验不导出或比较密码等价物；秘密不出原受限进程，不交给 SQLite 或业务服务，也不拿 NT 哈希作重复操作识别。
4. 只有上述原件和同一原操作都可证，才在短 SQL 事务由 PENDING → ACTIVE，并写同一不可重复的原结果；首设才同时开放 Web 与 SMB。SQL 最终 COMMIT 未知：重开原库查原单，不能擅自换密或另开账号。崩溃后，若已看到准确原账户的**目标标记**，不再询问或改密码，但可见并不等于耐久。获准恢复者在原双 EX 下先完成必要的原生事务恢复，重新同步同一具名 TDB 和原 accountdb 父，再独立重开、核原物、双向索引、目标标记，方可完成 SQL；单纯查回执既不补同步也不推进。若确证仅有同一**前驱**（首设是原可证的新/空现场），源操作未在原生库生效，须重新取得该单维护权和现场安全输入才可继续，不宣称能核原本未保存的口令。其它标记、额外用户、未知遗留物、丢失原库、未明的写/同步结果一律保持该角色关闭，不能靠同名、时间戳、文件哈希、收据或猜测补成成功。当前动作重放永不改动后来一代；想换另一个已生效的密码必须另下重置原单。只有受管维护者能改密码和保留描述；原生允许的登录计数不能改这两项。标记不是密码的数字签名：绕过这一边界的宿主特权写者、两库和保护材料的一致整体倒回，不在此证明内。
5. 仅 Web 重置：在相同原池和批准下，以已确认 Web 前驱/Op 更新 Web 原密验、代和回执，均在同一短 SQL 事务；不打开/改写 SMB passdb、不改 SMB 代。SMB 重置不读取 Web 验证值或修改 Web 的代。停机可以使网络/浏览器会话消失，两种持久权限不会互相代替。首设可当场拒绝两次输入相同的口令，单角色重置不向另一个库试密，故不承诺能跨库证实两段口令永不相同。新登录必须在新的原生运行上下文中核原池、原配置、实例、真实账户代和当前约束，不能恢复旧会话或耐久写者。
