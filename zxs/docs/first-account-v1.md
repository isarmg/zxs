# MAINT-1 账户原决定：首位管理员的只读候选

这是首个**原账户读取**切片的私有候选，不重写 GENESIS、不允许发票、重置、登录服务或盘写。先落实一个能区分真假口令与原池、且绝不会因为“首管”授予任何业务读的切片；更多账户／共享和网络入口须接同一原账继续正向实现。空池读者继续只认确实为零的前沿。

- 唯一位置为真实 MAINT-1 SYSTEM 原 `REGISTRATION` 的 GENESIS 之后。第一个首管仅准在确切已确认空池之后第 1 个决定；这是本期较窄的**发首管前先不能发其它业务决定**，已有非空但无账户的未知介质不收养、不倒推。外层复用现有统一决定信封 `"ZXS/FILE-DECISION\0"|total:u32|pool:16|seq:u64|previous:32|kind:u8|request:32|body|SHA256(前述字节)`，u32/u64 大端，total 含魔数、4B 长度与末尾 32B 摘要，本片 total=255+login 字节数（256..319，仍≤4096）；pool=原 GENESIS PoolId、seq=1、previous=原 GENESIS 的尾 SHA。D=SHA256(frame[0..total-32])，即末尾存下的既有值，不再连同 D 二次散列；“FILE”拼写不改变这是 SYSTEM 中唯一原决定流的事实。旧 ID-LEAF 原池不接受账户动作。
- 本片 kind=9，body 精确为 `"ZXS/ACCOUNT/1\0"|0x01|OpId:16|AccountId:16|operator_ref:16|login_length:u8|login|salt:16|argon_tag:32`。三个 ID 非零；OpId 不等于 GENESIS init Op；operator_ref 为本次真实系统维护流程保留的**非秘密、一次性获授权操作引用**（不是储存 UID/恢复密钥/账户本身）。作者必须持另行验证的本地一次性首设授权并持原 EX 才可提交；读者只能观察已由可信写端确认的原决定，不能仅凭此字段或从完整自校验 bytes 赋予维护方权限，不能在尚无受保护签发证据时对外开启认证。首管初始密码世代 1，世代的原证为D，另外的 Op/同名账户不能复用。
- 登录标识暂限 1..64 字节严格 ASCII 小写字母、数字、点、连字符、下划线，首字符须小写字母或数字；不得归一化、按显示名/系统 UID 兜底。它不是 FILE 或 SMB 业务文件名。盐与标签从私有原准备生成；盐实际用密码学随机源，每次重设换盐，重试原单保持原值。口令验证用 Argon2id v=19、m=65,536 KiB,t=3,p=4、盐16、tag32，引用受维护的上游常量时间验证实现，不执行命令代验，不自写 KDF。此行只存真正 KDF 的高成本验证材料、不存普通口令或可快速猜测的派生值。口令按输入的原始 UTF-8 字节经已受保护接口限 1..1024 B、不截断或规范化；设密强度政策可以更严格，但不影响读取已确立的原 verifier。通用 request=SHA-256(`"ZXS/FIRST-ADMIN/REQUEST/1\0"|pool|OpId|AccountId|operator_ref|login_length|login`)，特意不含任何秘密派生；另行提供的密码不能借同 Op 获“是否相同”的回复。相比独立应用，确认下界是 1_be64 | total_be64 | D，不含 GENESIS 长度；无缺字段兼容，不接受未确认尾当首管。
- **原物及授权决定不同。** 首片在线读取必须在生命周期 SH 内，先从明确配置的 SYSTEM 验原目录/注册常规 inode、原注册 ROOT 的 native、SYSTEM 标签所载 GENESIS 摘要、同一 REG 的准确确认下界及私有属主；不走全部数据卷，不让一份从任意目录来的等字节原件选池。完整/部分未确认尾、未知后继、双名或任何陌生、空/损坏及未收尾侧件暂全部拒（确切原 SYSTEM 中仅准同一个 REGISTRATION 名，并必须实在），不把它当空池、旧账户或有效登录。入口受限时，对更晚账户/FILE 操作**拒绝而非退用第 1 帧登录**，随后接中央重放才允许混合。口令 KDF 不持短 SYSTEM 锁，完成后在原 SH 内重取同池原凭据决定、许可世代和原 native 注册，才得到独立于用户名的已验证 AccountId；原值改变/重置/未证、用户名错误、凭据错误一概不得签会话。首管只有明确列出的三类管理范围；这一切片只能验证其是否有读/列举权：没有共享/授权决定，结果**一律拒**，不能返空列表伪装成功。旧回执不授新权限，KDF 返回成功也不单独开 FILE。
- 本期不纳入持久 SID 映射、初次授权/重置回执的通用查询、SMB 凭据、网络 Cookie 或 HTTP 接受器；无需第三份帐号库。下一片正向测试填入同一正规确认流的第二账户/普通共享/明确授权。Web 只开许可内的管理元数据；SMB 对文件另从相同受验切面选择真实 FILE，不能借 Web 会话转发正文。实际写端首设、原流程重启、reset/disable、无密码读取缓存、全局并发/速率限制、强 TLS 和外部凭据权限都要独立留证；以旧媒体、手造 bytes、测试中人为拨动的下界、单方 fixture 或库的正例不能据称两端互通或公网可用。

本片的口令验证依赖目标 Linux 的 [libargon2 参考库](https://github.com/P-H-C/phc-winner-argon2/blob/20190702/include/argon2.h)，以 20190702 的 argon2id_verify C ABI 为依据。这是当前代码真实的目标构建/认证依赖，不是已内置的资格方案。常规动态链接时，构建机/交叉 sysroot 须有目标架构的 [libargon2.so 链接入口](https://packages.debian.org/trixie/amd64/libargon2-dev/filelist)；离线交付物须随附已核准的同架构 ABI 库及适用许可，或明确要求宿主预装等效 [libargon2.so.1 运行包](https://packages.debian.org/trixie/amd64/libargon2-1/filelist)（链接示例为 Debian trixie amd64）。不能承诺无需运行库的单文件；没有 ABI 不用自写或弱散列后备，安装者须在启用前核对而不是让 ZXS 自动下载安装。本项目不复制、修改或内置该库的源码；上游[许可证](https://github.com/P-H-C/phc-winner-argon2/blob/20190702/LICENSE)为 CC0-1.0 或 Apache-2.0。使用固定参数重建 PHC 并调用库的 argon2id_verify，不从输入接收 PHC、参数或任意摘要；不依赖命令行也不自行下载工具。一次进程内最多一个 64 MiB 的验证，繁忙会拒绝，不能代替网络登录所需的限流。合成[字节向量](../tests/vectors/first-account-v1.txt)的盐与验证标签取自 [argon2-cffi 25.1.0 公开示例](https://argon2-cffi.readthedocs.io/en/stable/howto.html)；相应公开测试输入仅供夹具使用，绝非默认账户口令，不进入原决定、请求或回执。这里没有构建、实盘或独立写端互通结论。
