# 通用存储：一次定位到正文，不依赖文件系统专用功能

**实施目标，尚未切换介质或入口。** ZXS 只使用一套普通文件格式。既不要求、也不探测或调用特定文件系统的克隆、快照、子卷、私有 ioctl 或 sysfs；不存在“可选快路径”。Linux 在产品外挂载，ZXS 只用已登记的私有目录。Web 管理账户、共享、系统/磁盘与版本元数据，不传正文；SMB 是日常文件 I/O 入口。helper 独立停机维护；两边不调用对方程序或共享源码。

## 正式版本直接寻址

每个已确认 Node 有不可变逻辑身份：池、FILE、历史/分支、直接父 Node/Version 和原决定、此次 Op、版本创建名、时间、终长和带算法的内容承诺。父边用于历史与准入，**不用于逐代查正文**。无两代上限，不强制作 FULL。节点的一种当前表示为普通完整 Raw＋校验索引；另一种为完整覆盖逻辑地址的**扁平区间索引**＋不可变普通材料，二者都是当时可读的正式版，不是“将来才能读”的队列项。

按逻辑起点严格递增，非空段无重叠、无空洞，刚好覆盖 [0,终长)。每段要么是显式零，要么是同一 FileId 下一个已发行的 **MaterialId、材料内字节偏移及长度**。材料有原操作、不可变长度与分块校验承诺；绝不取名字/SHA 当物料 ID，不合并不同归属的同字节件。相邻零合并，同一材料且物理字节紧接的段合并。零长度有唯一空表。不存在 Parent、某个旧节点 HEAD、路径或“向前找不到就是零”的段。截短裁掉尾；再扩长产生新零，旧父尾巴不复活。

新版本从**实际直接父已经验证的扁平表**复制/分裂所需元数据、切入本次真实改变及准确终长，形成规范的新表。只继承实际原物，不复制父正文来构表。先核资源和边界（含加法、源偏移、成员归属、原材料足长）；提交前同一 SYSTEM SQL 事务中的位置/父与已有原材料重验。读某个正式 Node 时选它自己的已确认表示，按 offset 在有序段表二分或按已验证索引页定位第一相交段；只到实叶，不打开父节点解释器。校验所需索引/页面与实际相交数据块后才交付，不把未读取的正文称已校验。慢读持 原 S 目录的共享 OFD、所选表示和材料读租至最终 flush。大文件总耗时、索引大小、逻辑读取量和盘速是不同概念，没有跑分。

**逻辑承诺与平面 SHA 不混。** 固定“按逻辑位置分块的内容承诺”算法及长度/空版/零区间的域；索引与每个原物另外有自己的摘要。写时核相交旧块、改后块、边界及终长后形成新承诺；不能把父 SHA 和变更 SHA 拼成整文件 SHA。需平面 SHA 才实读计算。物理表示可换，节点的逻辑承诺永不因换文件改义。具体 wire、可恢复的材料身份、限额及公开独立向量需逐项另审，本设计不授权发票。

## 工作保存与手动提交

新 FILE 只占名字，未发布历史。每轮从上次明确提交（或空基底）开始，第一次真正改变才建**一个普通增量数据文件**。本轮的 Ctrl+S、应用自行保存、脏 FLUSH、写穿和脏 CLOSE 都在同一个文件中更新工作内容；不为每次保存另建增量文件、发正式节点或整份复制。索引、分块承诺和同一原物的链接见证不是第二份正文。不变或干净的操作不造新修订；首笔 0 B 保存可有原业务回执，无节点。

确认前，在这份增量里写入不会碰到任何仍被选中、正在读取或已预留区间的新字节，独立核准确范围并同步。短 SQL 事务比较旧工作修订、原写者和授权，切换到覆盖全逻辑地址的直接区间表。未触及部分直接引用原基底；截短后再扩是零。区间的校验终点取其**封存长度**，不取活动文件的当前 EOF。读者持自己的冻结视图，写者不为此等待读者或另开一份工作文件。断电未确认的尾部不成为工作内容，不能同时据文件长度推断归属或清理许可。

**只有明确的手动提交才发行历史节点。** 冻结本轮同一增量及所选区间、正式基准、逻辑终长和对应校验；在同库一笔有前驱条件的事务确认新节点、原回执和结束本轮。新一轮首次真正改动才另建增量，已发表材料绝不再写。发布不需要把完整基底再拷一遍，读取也不循父节点找字节。同一 Op 已确认只返回原结果；如果没有未提交的改变，不隐式制造下一节点。既有正式历史保留。

当且仅当同一物理区间已无当前稿、正式历史、待决保存/交接和在途读引用，才可在仍活动的增量里复用它；不要按“今天的工作图不再指它”单独据以覆盖。未知、正在交接或无法证实就保留，仍有可用空间时在同一个增量尾部追加。[同一实际文件的区间交错源码例](../tests/unit/flat_index.rs)验证多个冻结视图选取同一增量的不同位置；它不发行 SQL 历史、不代替跨进程清退许可。生产 SQL/冷恢复、活读固定、普通 SMB 重复保存与显式提交的完整联接尚待实现；首笔保存和扁平区间读写组件不是此整条已经跑通的证据。

## 跨普通卷、回收与冷接续

同一普通父域的无覆盖改名要在确认前取得真实两父可安全执行该类切换的证据；不足就**事前**选真 transfer 或拒，不在确认后改票。跨盘以及进出独立回收 R 始终真实流式复制。冻结全部保留的节点/逻辑承诺、原 FILE 与放置/表示代、准确成员表（各节点扁平索引及独特 MaterialId 的集合、完整 Raw/索引、同单已预留的成员）。按原物 ID 去重，只复制真正相同的材料，完整历史绝不按当前 HEAD 的大小算。读一段、建 D 的成本，和跨盘验证及保留整份历史的成本分开。跨盘先以同单具名/独立读回/文件和父同步，再事务切换位置/记原回执，其后才逐件清源。同盘在首个改名前的 SQL 待办已批准准确物理动作，不预报成功；直到名字/父同步与原物齐全后才公布新位置；读者/决定/收尾三态分开。

跨盘复制或回收只为这笔经批准的交接服务，须保全所有已冻结的历史与工作材料，不能把移动写成新版本。专用 R 从逻辑回收入口服务，不作为普通文件目录对外；还原以原删除单、保留代、同一 FileId 与明确的未占用数据盘目的为准。

SQL 中的交接原单及其成员行冻结确切身份和所需资源，不把成员表塞进单个 4 KiB 帧，也不用应用级 INTENT 分页/重放。允许的深度取决于实际 SQL、目录、字节、FD 与还原额度，不继承旧 8192 条/8 MiB 决策账上限。不得挪占另一 FILE 的还原额。

## 什么叫“通用”

**代码现状与目标不同。** 在现行旧入口，[src/linux.c](../src/linux.c) 的 `zxs_anonymous_file` 用 O_TMPFILE，卷/材料/确认下界/阶段读写仍用 xattr，`zxs_native_birth` 用 FS_IOC_GETFSUUID＋name_to_handle_at，`zxs_allocate_stream` 用 fallocate。这些是尚未替换的真实依赖，不是新介质能力清单。下表是替换与验收计划，不代表当前正式业务已在不支持这些接口的挂载上工作。

| 现在旧实现的要求 | 新格式的要求与替换门 |
| --- | --- |
| 文件系统名称、品牌 UUID ioctl、特定快照/克隆/子卷 | 不作为功能、探针或注册/读写前提。选择受保护普通根，核当前外部挂载映射、权限与真实物。无品牌白名单。可见 UUID 只作可归属状态字段，未知就不填。R 仍需有证据与 S/所有普通根分属不同文件系统，不是另一个路径就行，也不是证明不同硬盘；通用 OS 与部署提供的证据不足则不登记该组合。 |
| 永久 st_dev、export handle、卷/阶段/前沿 xattr | 逻辑 Pool/Volume/Directory/File/Material/Op ID 由原 SQLite 事务发行，并与受保护卷标、确切原请求/材料和摘要关联；文件内容服从原承诺。现场仍在持有 FD 与确切父上核原对象、无链接跳转、原生同物/挂载与权限。路径、mtime、untrusted token、单个 st_dev 数字或自行算出的散列不授签发/读/清理权。完全复制/整体回退的全套介质在原件不在时，单靠普通软件不能鉴别；含糊、双现或未有证据不自动接管/删除。 |
| O_TMPFILE＋私有 xattr、固定 fallocate、仅凭命名缺失判完成 | 使用本操作唯一的私有普通暂存名，排他创建、显式原操作和角色、原文件及目录同步；冷开只续同一原件/原票相符的阶段，不收养已有无归属空目录。可用普通受保护名称固定已领原 regular 的第二个名字作为必要的同物见证；这不是另一份数据或另一授权。若同名替件与原出生不能证明相同，停在非破坏态。空间预检与顺序真写/同步分别处理错误，不靠稀疏大小、预分配或专用块计数证明成功。 |
| 更名的覆盖、根/服务的排他 | 即使通用也不能用“先看不存在→可覆盖 rename”替代原子不覆盖。针对所操作的普通文件/目录须真有独占创建/不覆盖发布、原子切换、持文件锁、文件及父目录同步的语义；准备全在原控制域，能力无法验证的操作据实不支持。临时名若撞既有物保留并拒，不清理未知。用户看到的 FILE/目录仍按同一逻辑父＋原 UTF-8 精确同名跨类型互斥。 |

首次认领、现池冷开和独立停机互斥只按 [SQLite SYSTEM](sqlite-system.md) 做：原 S 目录的同一个 flock 管生存期，SQLite 自己管理数据库、事务及热 journal。不能使用原登记文件加确认下界决定归属，不能由旧原票补新卷标。只有来源不明的空目录、旧 xattr/旧认领或同名他物时拒绝自动接管。

既有 GENESIS/CONFIRMED 的源码与合成向量只记录已终止的实验；本文件的扁图/改变材料/LogicalV1/完整 RAW 保留，其发布、引用、原单与任务关系只来自新库。

## 分片与验收

1. 扁平范围索引/校验与资源约束；用 A→B→C→D 让 D 一次覆盖横跨此前三个真实来源，裁短、再增长出零；早/中/末任意 Node 定点仍见当时原字节；序数 >255，读 D 不需要回开 A/B/C 节点。纯计划/索引实例不是正式 I3 已发行。
2. 同一轮同一真实增量的同一逻辑区间重复覆盖；旧读一直返回原非整块尾，当前读见最新确认字节；裁短再扩读零。直到明确手动提交为止无正式节点、无全量复制。旧读关闭且其余引用均不存在后才复用旧区间。断电、ENOSPC、撤权、同 Op 重试不影响先前确认。
3. 单一可信 SQLite 库、普通介质资格及跨项目同一 原 S 目录锁/模式；两类普通父、任意件数 cross-volume MOVE/DELETE/RESTORE、跨不同文件系统移交本次冻结的真实材料、源 A/B 掉线、同名替件、R 自己的还原额度、已确认后不得选另一原件。受理向量必须能区分旧格式、掉线、仅登记、未清、已安装且可读。只有通用版进/出/续作齐全才切换正式发行、移除旧专用依赖，不新增产品 CLI/网络正文路由。这里不声明已编译、执行、实测或上线。

**单物增量按封存范围读取。** 已核原长的首稿仍在准确 EOF 打开，已打开的工作正文读者保留原数据 FD 和两个同物名称。其摘要只覆盖原来选中的实际块（包括不足 4 MiB 的旧末块），同一数据文件后来追加不会使旧末块变大；未选尾部一个字节也不能发给旧读者。表、标、正式历史和未选择此规则的读者仍要求整件原 stamp。按原受理的物理窗口恢复只能比较已有前缀并追加缺尾，不截断、不改写旧区间；缺链接、超窗口或异字节拒。当前生产入口只给已受理首稿发第一窗口；后继多次写窗口仍须由真实 SQL 原单/写句柄授权并在同步后切当前扁平表，不能凭实物 EOF 领取。非空/零长脏确认、显式提交及旧区间安全收回各有自己的切点，这个字节层不代发任何回执或版本。
