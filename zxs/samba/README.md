# 专用 Samba：启动守卫和接入边界

目标是 **Debian 13 amd64 的专用 standalone 实例**，不是把文件系统目录直接共享给 Windows。helper 装配实例并在单独获准的首次供给中初始化其 SAM 域；ZXS 在线消费该实例的认证结果并实现 FILE 业务。唯一用户权威仍是 SYSTEM 的 SQLite：

- Web 管理员不能登录 SMB；SMB 用户不能登录管理页。禁止匿名、guest 和错密码后转 guest，包括匿名 IPC$ 登录和共享枚举。
- 每个共享只取当前 SQL 设定（停用/只读/读写）。一个已成功的 Samba 身份不等于任意共享可用，更不等于可直接打开宿主路径。

## 源码已接到哪里

该私有源码覆盖由[Debian 原文件补丁](debian-trixie/0001-managed-standalone.patch)和[专用运行、控制与 passdb 源文件](debian-trixie/new/source3/)组成。组装时将 `new/` 下这些文件按相对路径放入同一已验证的专用 Debian 源树，再应用原文件补丁；Waf 已列出实际源及 tini/GnuTLS 依赖。缺件不构建，没有回落系统 smbd 的第二条路。没有新增网络服务或自写 NTLM：

| 实际切点 | 这段代码能判的事 |
| --- | --- |
| smbd 首次加载、配置热重载及认证路径的直接重载 | 用 Samba **实际装入的有效配置**核 `ZXSLOCAL`、指定 private/state、standalone/user、NTLMv2-only、拒外部 Kerberos keytab（standalone 的原 GENSEC 因此禁用 Kerberos）、强制签名、禁 guest 回退、`restrict anonymous=2`、禁别名/用户共享/打印/多通道等。逐活动 share 核无 guest、用户替代、wide links 或用户/root 连接/关闭脚本；生成的 IPC$ 只读且不加 VFS 模块，拒只有默认 VFS 或另带模块的业务共享。IPC$ 保留原生管道所需的内建后端；普通数据 share 只装下述专用 VFS，不在其底部放 POSIX 磁盘，也不按配置加载动态模块。唯一守卫在私有 `lp_load_with_shares` 本身；`reload_services` 及认证的 `auth_generic.c` / `auth_ntlmssp.c` 直接调用同样必经。失败终止当前进程，不依赖调用者检查布尔返回。 |

这不是可用的 Windows 登录程序。该 passdb 只承接这份经核对的本地域，不从通用账户查询返回任何账户或密码材料，也不继承 Samba 默认的系统用户/组创建、策略或者秘密读写方法。Samba 内部仍可能构造用于自身运行的 guest 对象；它不是一次成功的客户端认证。将来的固定 `zxs-smb-client` 只作受限本地 Unix 身份映射，与存储 UID、Web 管理员和 guest 分离，不是第三个产品账号或口令来源；本批不创建它。尚缺实际 SMB 口令验证、`zxs_file` 的正向业务回调、准确认证尝试到成功 SMB2 session 的凭据代次传递、逐次 SQL 共享授权和现场验收。不会把操作系统用户名、裸 SID、Samba 日志或来源不明的 socket 当作成功认证。当前库级 FILE 夹具代入已认证事件，不替代上述任一项。

### 受管原件怎样交接

helper 供给的 `/instance/domain.bound` 正好 128 字节：`ZXS-SAM/BOUND-1\0`、三个 16B 标识（Pool/Instance/供给原单）、32B **上线**原配置的 SHA-256、8B `ZXSLOCAL`、24B 本地域。这不是秘密。两个普通原文件 `/instance/domain.bound`、`/instance/smb.conf` 必须真正只读投射；`/instance/private` 与 `/instance/state` 是宿主选定的两个不同原目录。本机宿主先确保来自该次已批准的安装正本并在隔离配置中核池/实例/原单；只读标志、文件属主、这些字节本身都不构成宿主授权。ZXS 不自行挂载或供给。

私有 smbd 只接受固定前台启动方式，不接受替代配置环境或额外 `--option`；对同一份已持 BOUND 及普通 live 文件，先核类型、权限、现场原物/挂载和原配置摘要，再以这**同一缓冲**送 Samba 原始 `tini_parse`（不另开路径、不重写配置解释器）。配置需 1..1 MiB、没有内嵌 NUL；拒 include、config file 重定向、注册表配置或动态注册表共享在解析时加载其他来源。原约定的两个目录、两个文件和真正具名、单链接 0600 的专用 SAM 状态持续同物。只用 dbwrap 提供的原 TDB 现场标识与当前受保护名字相比，不额外打开 TDB 来算摘要或枚举键。子进程继承原描述符、只用带偏移读取。真正的运行资格切口单独复验域；核固定私有 TDB 时才短暂用 Samba 已有的可信服务身份，及时恢复，不给客户端任何宿主路径/SQLite 权限。普通 SID 格式化可用已核不可变缓存，不签新登录。原物失效干净终止该专进程，不对既有上游调用者泄出 NULL、也不以 panic 或 core 当正常拒绝。运行中换挂载/原件、改配置、替换 BOUND 或缺域都不能用新名字刷新信任。需要变更由宿主另行授权、替换并重新启动；不干扰管理员通过 SQLite 改共享 RO/RW。

**接线顺序。** 宿主须先持有经批准、互相吻合的 PoolId、InstanceId、ProvisionOp、上线配置原件 SHA-256、`ZXSLOCAL` 和原 SAM 域；引导配置/工作组名不是上线原件。启动端必须核实际加载的专用实例、配置/依赖、private/state 和 SQLite 内该域 + RID 1000 的 SMB 行，之后才接受连接。禁不受控 include、配置重定向及任意插件。仅看到配置字段、读到域或对完整拷贝算得相同摘要不足以鉴别宿主。当前已接以上受管配置和 SAM，以及下面的原池/固定 SMB 账户启动核对；真正 SMB 口令验证与最终会话交接仍未齐，不能据此启用文件服务。实际口令验证取用的**第一份** SMB 行要在本次认证上下文中绑定 Pool/AccountId/SID、凭据原操作及代次；后续重查用户名或凭 SID 命中缓存不得替它签发。通过账户策略、真实非 guest 安全令牌并成功发布这一 SMB2 session 后才向对应 tree 打开 FILE。无相应证明的恢复/新通道不受理。

### 仅两端的启动控制通道

宿主监管者新建阻塞的匿名 Linux AF_UNIX/SOCK_SEQPACKET socketpair，严格只将一端作为 fd 3 给受保护的专用 smbd，另一端作为 fd 3 给本项目独立的非 root `zxs-smb-storage` 进程；不给 Web、系统级 Samba、其他实例或客户端。后者的 fd 4 另由宿主打开为已批准实例的**原 BOUND 只读投射**（root 属主、原单链接普通文件）。宿主分别提供 `ZXS_SYSTEM_ROOT`、`ZXS_POOL_ID`、`ZXS_SAMBA_INSTANCE_ID`、`ZXS_SAMBA_PROVISION_OP`、`ZXS_SAMBA_LIVE_CONFIG_SHA256`；必须来自原安装的独立选择，不从 socket 对端或所读记录反填。两个端点无文件名、无监听、不可连接；SO_PEERCRED 在 socketpair 上属于创建者，不能证明后来执行哪套二进制。宿主须验证实际启动的两份发行件，且在各自 exec 后关闭自己及其他进程不需要的副本；不得跨 UID 映射辨不出该 root 创建者却放宽准入。此通道与离线域供给不相通。

只有在 smbd 已用同一配置字节并从真实专用 SAM 复验时，才向原通道发其 128B BOUND，并用同一消息只交接一件内核原物：专 smbd 刚建的匿名 Linux pipe 的只读端。写端不携数据，留在 smbd 及其 fork 的参与进程，禁止转交给第三方。存储进程独立持原 SYSTEM 目录 SH，用同一 SQLite 短读切面核 INIT/原卷标、唯一配对及其当前 SMB AccountId/凭据单和代次，域须为原本地域＋RID1000。受管 BOUND 在整个核对中保持原 FD、戳与相同字节。答复固定 212B：16B `ZXS-SAM/READY-1\0`、所核同一 BOUND、16B SMB AccountId、16B 凭据原单、8B 大端代次、28B 账户 SID。先完成字节数和原件核对才回复；不会选取或发送口令、NT 验证材料或 Web 凭据。成功仅描述启动瞬间证实的这份账户；不是 NTLM 验证、正面登录票、共享授权或目录就绪。

握手有截止时间，只在第一条 BOUND 接收精确一个 kernel pipefs 的只读、非阻塞读端，拒普通文件、目录、可写/具名 FIFO、额外或截短的辅助数据；READY 不收 FD。以后不能经此通道查询账户或 FILE。存储停止先半关控制 socket，连空闲的专 smbd 父进程也由真实 tevent 读事件触发正常退出，子进程沿 Samba 原本的父死亡管道收尾。无论控制端仅半关还是整个 socket 已关，皆不证明所有参与者已关闭。非 root 存储进程不跨空闲持 SQL 事务，直到内核报告这根匿名 pipe **全部写端已经关闭**才正常释放本次原 S SH。宿主监督者另负责停止并回收整套受管进程（异常/卡住的不宣称已经排空）；未来各实际读写任务还必须持自己的原 S 租约到同步/flush/关闭，不能拿管道 EOF 当作其他服务已完成 FILE 的证据。私端断开、非预期的控制消息、换配置/实例，不能用另找的服务代替。一次握手不会让未来文件 I/O 绕过当时的账户和共享权限。

待联调：由受信 supervisor 只交上述两端及原 BOUND；无账户、他池/实例、同形异域、错误控制地址、可写 BOUND、smbd/存储端异常关闭均不取得操作许可，双方关完真 FD 后 helper 才可取同一 S EX。当前只编写了真实 Linux 消息与 SQLite 行选择的源码用例；没有部署、运行或验过 Windows 登录。

### 每次新 SMB2 握手的服务端挑战（仍无成功登录）

真实的全新 SMB2 SESSION_SETUP 尚未建立会话时，只能为本次请求预取一次挑战。主通道拥塞立即拒本次登记；等待私端答复使用 Samba 原 tevent，十秒超时或取消即关本次等待和端点，不占用事件循环、未创建可访问的会话。其他连接/请求可先得到自己的答复。通用认证/RPC 调用、重认证、通道绑定、客户端改挑战或超时后在原上下文换挑战均被拒。专用 smbd 在这个上下文新建匿名 socketpair，向原已配对的 fd 3 发送 16B `ZXS-SAM/BEGIN-1\0` 和单独的对端 FD；多个 smbd 子进程在共用 fd 3 上**只发注册、不收挑战**。存储进程从系统随机源取 8B 非零值，仅向此次单独端点回复 16B `ZXS-SAM/CHLNG-1\0` 加原 8B。原 GENSEC 接手已就绪的这一个端点和挑战，正常对象销毁即关闭；以后查询不等待，按本机单调时钟和原私端复核，30 秒外即使远端还未关闭也拒。资格失败不改用 Samba 的其他随机源。

每次受管进程配对最多同时保留 32 个待处理挑战，按各自的 30 秒期限清退；满时只拒新的一次；原 BEGIN 完整但内核未能交出一件正确的 FD 时也只拒本次。坏控制帧/关闭仍撤销整次运行配对。超时、对端结束或私端额外输入即放弃原尝试。内核 poll 最长每 500ms 清理，不能据仍有一个 FD 声称已经验证。停止时全撤，仍等原生命周期 pipe 的最后写端真正关闭。此处不查密码、不接收客户端证明、不计算会话密钥或写 SQL；挑战是非秘密数值。本阶段原生密码回调对这种上下文明确失败，不能回落到 SAM/guest 或拿挑战换会话。未运行的源码用例覆盖独立的本机端点、队列、缺 FD 和过期；专用源码构建的 tevent 小夹具让第二个真实可读回调先于仍无答复的第一个执行。未实测系统 FD 枯竭，也不是 Windows 登录验收。

### 真实客户子进程与接入连接

只有专用前台 smbd 已配对的监听父进程在真正的 TCP `accept` 成功后、为它 `fork` 之前，才在本次调用栈记录原网络命名空间与原 socket 的内核 cookie。子分支完成 Samba 自身重初始化和专用 SAM 复核后，在同一已接受的 socket 上一次性认领。新 SMB2 SESSION_SETUP、其异步挑战回调、后续消息和最终令牌门都要求本次进程/连接仍相符；原 GENSEC 取挑战还核原工作进程。用另一个连接占用相同 FD 号不能接续，原连接的 `dup` 不改身份。父进程、通知/清理辅助进程、再派生的子进程、inetd 与交互分支不获此角色。这里没有给进程持有额外 TCP FD，不改已发布盘格式。

此处证明的是**这份受控代码本次处理了哪条连接**，不是存储进程已经从操作系统独立验明应该向谁供给凭据，也不是客户通过认证。原密码判断继续关闭；PID、cookie、原挑战通道或 READY 均不能单独作为对外授权。测试源码用两条不同的回环 TCP、原 FD 替换、辅助 fork 和二次 fork 区分这些条件；未执行。

### 原生 NTLMv2 输入与诊断边界

这份专用 Samba 的 GENSEC 只将经过原生 NDR 解码、两个版本字段均为 1 的 NTLMv2 结构交给后续口令判断。保留上游对服务端目标信息、通道绑定、时效及协商的 MIC 的检查，不凭长度识别；同包可以携带 LM 字段，但不将它交给口令判断，也不改原消息用于完整性核验。原生后验只接受确切长度的 NT 会话基钥，不接受 LM 替代。依据 [MS-NLMP §2.2.2.7](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/aee311d6-21a7-4470-92a5-c4ecb022a87b)，保留字段不用于授权。结构合格不是已经验密；现有业务会话入口仍关闭。

同一私有发行禁编译密码调试，原诊断入口的编译上限及运行时实际读取的调试级别均不高于 0，即使有高等级类设置也不打印 SPNEGO 报文或 NTLM 的详细结构。专用配置同时拒绝 `debug encryption = yes`：原 Samba 的这一选项甚至会在 0 级打印 SMB3 密钥，不能只靠降低日志级别。专用日志的二进制转储入口也明确拒绝 0 级：即使 SMB2 签名不符，仍按原协议拒绝，但不打印收到的或计算出的 MAC。保留失败结果文字；不改变签名比较、协议字节、非日志回调或正文。不改宿主其他 Samba 的日志设置；这里未验证外围监督者、主机转储或第三方日志。只写了真实日志回调和无秘密结构的源码用例，未运行。

## 业务共享的原生 VFS 基座

在固定 Debian 的 `smbd_vfs_init`，只有实际服务号就是 IPC$、请求确为 IPC 且没有额外模块时，才选已静态注册的上游默认栈。普通业务服务必须只声明 `zxs_file`；它直接安装专用前端与 Samba 同一固定版本的完整 ABI 50 终止表，不调用磁盘模块或动态加载器。安装前也核终止表没有空回调，不依赖发行版可能关闭的开发断言。两类设备不匹配、打印、wide links、未知/额外名称或已有其他栈均拒。内部 DFS 连接携带的 Unix 名同样不能取得 FILE 访问。

专用 `CONNECT` 目前明确拒绝：获得服务名、Unix 名或上一段启动 READY 并不是一次已验证的客户会话和当前 SQL 共享。未来只逐项实现真正有业务来源的操作，终止表保留；不以未支持回调的缺省数值宣称磁盘容量、成功写或字节锁。未运行的源码用例直接走 Samba 分发表核连接、元数据、读、写及删除没有宿主文件后备。当前初装配置仍只有 IPC$，无业务共享被对外开启。

## 文件并发要求（尚未接到成功业务打开）

**只限制单写，不额外禁读。** 跨进程、路径别名及不同共享，写者键是 `(PoolId, FileId)`；拥有者是真正成功打开的那一笔业务 handle，不是账号、连接、共享名、底层 RAW inode 或当前物理表示。创建/接管写句柄先验当前 RW 和 SMB 原生 ShareAccess；存在别的写者时写类打开明确拒，不降为只读。同一 FileId 的写、截短、删除、覆盖/替换目标不能绕过。可在 CREATE 返回句柄前已经截断的 OVERWRITE/SUPERSEDE 必须在第一个副作用前准确暂占，失败只放本次占位。DELETE_ON_CLOSE 的设置和最终 unlink、服务器 COPYCHUNK 的目的端也受同一限制，不支持就明确拒绝。不同 FileId 不相互上锁。

读句柄仅按其自己的权限、ShareAccess、字节范围锁及当前已确认修订处理；**不因存在写者额外拒读**，不读别人还没确认的编辑。写者自己的正常读写语义不变。SMB 共享访问模式控制读/写/删除的兼容性；字节范围锁保护具体范围；协议缓存 lease/oplock 不等于前两者，也不等于业务单写锁。不得以一把长期 SQL 写事务或整盘锁实现单写。

- 同账号三次独立打开：A 持兼容读取的写句柄，B 能读已确认稿，C 请求同 FILE 第二写被拒；换共享路径、物理表示或另一个 smbd 进程结论不变。若 A 的**原生**共享参数明确拒读，则 B 也应被拒；无关 FILE 可写。
- 同一 FILE，原生读/写/删除共享各按请求核，字节锁分别验重叠、不重叠、显式解锁和关闭。临时文件＋改名替换是常规应用保存：目标句柄已关闭且没有活写者时，按稳定顺序取得所需源/目标资格，核当前 RW、基线及两端原生 share/delete 条件，准许正常替换，不要求继承已结束的句柄。若目标仍被写者占有，只允许能证明正是该目标 owner 的操作；同账号、进程或连接不是证明。失败不留下半替换。
- 正常 CLOSE 或确认断线收尾，先使旧句柄不可再改，排空或使已派发异步写/待提交 SQL 失效，再交下一写者；未实现 durable/reconnect 时明确拒，不用重连/同账号绕过。读者持确切已确认材料到交付结束，不能让后台换成 Raw 后重新按 inode 独立加第二把写锁。
- 对已绑定基底的保存，在短 SQL 提交中核前修订和原操作，过时即冲突；同单重送不重复 SAVE。客户端关闭后另开新句柄、用应用自己保留的旧内容整份写回，没有通用凭据能把它认成旧基底。要保先前编辑仍须按真实客户端行为验证。

SQLite 首份手动 SAVE 的真实库路径已分开准备写者与读者：容器 EX 只约束本次原生准备写者，Current 不参与该写锁，仍持出生头/真实已确认材料并重验当前读权。新开读在未确认时只选空的前修订，确认后新开读选修订 1；原已开空稿句柄不升级、不阻止确认。源码用例跨两个独立 SQLite 连接，在真实源文件已同步/未提交时检查此区别。只覆盖这个首稿，不是跨进程 SMB 逻辑写句柄、原生 ShareAccess/字节锁、后续修订或 Windows 实测。

### 普通共享根 FILE 列表（存储业务层）

从本次已授权的共享定位其唯一普通卷，不接客户目录路径；按显示名的 UTF-8 原字节分页（每页 1–16 项）。仅列已确认出生的 FILE，返回显示名、FILE/条目标识、已确认工作修订和逻辑长度。只读及读写共享可以指向同一个命名空间；未确认的创建、物理文件夹名、标记、改动材料及回收卷不会被列出。已确认首个 0 字节 SAVE 与尚未保存都显示 0 字节，但修订号不同。列出尺寸不证明正文完好，读数据仍另走原块校验。

非空页的首尾各枚举一次该 F 的真实目录项，各 FILE 另验自己的成员；按页计成本，不是整个目录只扫两遍，也不是正文 I/O。空 SQL 页免扫 F 子项，仍复核同一根、授权及空结果。每一页在归还结果前复核同一 SQL 权限及该页成员、同一 F 和实物双名 FILE 头。选件变化/断点返回错误，失败不会推进游标或泄出半页。游标跨页不占 SQL 事务或卷写锁；并发新增而排在已交付显示名之前的项需重新枚举，遇到结束后也需重开。存储端也可按这份列表**选中确切 FILE 再读**：在调用者当前共享的一次真实 SQL 切面核 PoolId、VolumeId、原显示名、EntryId 和 FileId，实际重新打开该 FILE 头与已确认工作材料。列表不是授权，撤权后旧 Tree 拒；同根另一当前获准共享可以打开同一 FILE。普通 OPEN 固定打开时已确认的修订，不把之前列出的大小当历史版本承诺。名称碰巧相同但成员不同不接受。此处不是 SMB2 `QUERY_DIRECTORY`/`CREATE`/`READ` 的协议实现；未运行。

### 逻辑 FILE 在 Samba 的同物键

创建普通根 FILE 时，SQLite 同一写事务以现有 16 字节 FileId 的 BLOB 索引检查前八字节对应的号：包含待办和所有普通根，不按共享或是否可见过滤；只为新原单选空号（保留 0–255 及全一号），原单重试不重抽。所有未来出生或迁移须保留这个池内唯一号。打开已确认的真实 FILE 后，存储端用当前授权、原成员和当次原物复核，再给出 Samba 三个 64 位字段 `(PoolId 高半, FILE 号, PoolId 低半)`。若既有数据没有唯一合格号，该投影拒绝，不借原生 inode、路径或散列修补。两个字段的 Samba 缓存仍须按专用池隔离。这里没有新 SQL 表、协议文件句柄、持锁或已生效的单写；正向 VFS 接入时同一对象的 stat/fstat 和每个真正打开均须使用此键，同时保留原始完整身份与原生 ShareAccess/字节锁。
