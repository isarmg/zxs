# 专用 Samba：启动守卫和接入边界

目标是 **Debian 13 amd64 的专用 standalone 实例**，不是把文件系统目录直接共享给 Windows。helper 装配实例并在单独获准的首次供给中初始化其 SAM 域；ZXS 在线消费该实例的认证结果并实现 FILE 业务。[新模型](../docs/smb-native-session.md)中，专用 Samba tdbsam 是唯一 SMB 密验库；SQLite 只持 Web 密验和两种身份的业务映射／授权。下面先列不变的原生认证切点，再列 v9 普通文件路径。严格校验原生账户不等于已经验证了一次客户端口令：

**仅支持 SMB 3.1.1（线值 `0x0311`）。** 专用实例首次加载与真实重载都要求有效 `server min protocol = SMB3_11` 且 `server max protocol = SMB3_11`。SMB NEGOTIATE 保留上游长度、方言列表、预认证上下文、签名与后续认证检查；即使客户端同时列出较早方言，原生匹配只能选 3.1.1。不含 3.1.1（含仅报 2.??? 的旧兼容引导）不建立业务连接。源码里的 `SMB2 CREATE/READ` 等是 3.1.1 沿用的命令名称，不代表兼容 SMB 2.x。Windows、macOS、Linux 的 3.1.1 客户端是验收目标，未实测。参见 [Samba 协议上下限](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#SERVERMINPROTOCOL) 和 [微软 NEGOTIATE 请求](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/e14db7ff-763a-4263-8b10-0c3944f52fc5)。


- Web 管理员不能登录 SMB；SMB 用户不能登录管理页。禁止匿名、guest 和错密码后转 guest，包括匿名 IPC$ 登录和共享枚举。
- 每个共享只取当前 SQL 设定（停用/只读/读写）。一个已成功的 Samba 身份不等于任意共享可用，更不等于可直接打开宿主路径。

这是一份专用 SMB 3.1.1 服务源码，不是 Windows、macOS 或 Linux 互通验证。只选择受到固定隔离的专用 tdbsam 域和单个当前账户。内建 guest 对象不等于可登录来宾。`zxs-smb-client` 是 Helper 的受管私有 Unix 映射，与存储、Web、guest 分开，不是另一个产品账户或口令。成功的原 GENSEC 会话之后才核当代授权；唯一 `[ZXS]` 与普通目录、FILE 使用下文的独立原物及授权。原生状态/口令材料不离开受管 smbd。

首个新会话的[限定认证路径](../docs/smb-native-session.md)单列了接收者、SQLite 当前账号和 Samba 自身临时会话库的区别。存储端在发挑战前只选定该账号，不从 SQL 验 SMB 密码或收发密码证明；真正的原生判断在受管 smbd 内。

### 受管原件怎样交接

helper 供给的 `/instance/domain.bound` 正好 128 字节：`ZXS-SAM/BOUND-1\0`、三个 16B 标识（Pool/Instance/供给原单）、32B **上线**原配置的 SHA-256、8B `ZXSLOCAL`、24B 本地域。这不是秘密。两个普通原文件 `/instance/domain.bound`、`/instance/smb.conf` 必须真正只读投射；`/instance/private` 与 `/instance/state` 是宿主选定的两个不同原目录。本机宿主先确保来自该次已批准的安装正本并在隔离配置中核池/实例/原单；只读标志、文件属主、这些字节本身都不构成宿主授权。ZXS 不自行挂载或供给。

私有 smbd 只接受固定前台启动方式，不接受替代配置环境或额外 `--option`；对同一份已持 BOUND 及普通 live 文件，先核类型、权限、现场原物/挂载和原配置摘要，再以这**同一缓冲**送 Samba 原始 `tini_parse`（不另开路径、不重写配置解释器）。配置需 1..1 MiB、没有内嵌 NUL；拒 include、config file 重定向、注册表配置或动态注册表共享在解析时加载其他来源。原约定的两个目录、两个文件和真正具名、单链接 0600 的专用 SAM 状态持续同物。域状态只用 dbwrap 提供的原 TDB 现场标识与当前受保护名字相比；不为它重开文件算摘要。独立的账号库则在原 root:root/0700 `accountdb` 下核同一单链接 0600 原件、原只读挂载与活身份；仅从临时 O_PATH 原件的真 procfs 别名送原生 TDB 只读打开，查毕即关，不给子进程继承新 TDB 打开句柄。上限64 MiB、单个 SAMU 不超过1 MiB；原生库的只读打开不加写锁；前后两次遍历不是快照，依赖宿主在整个实例运行期排除离线修改。libtdb 在受管 Samba 进程内读取完整物理记录（包括凭据字段），标记核查本身只用字段长度，不另取 NT 值、不给 SQLite 或外部接口。关闭文件不等于擦尽上游暂存或证明 fork 后内存无残留。完成会话的最终 SQL 切面旁，也须再从原父复核具名 TDB 的现场实体、属性和时间戳。子进程继承原描述符、只用带偏移读取。真正的运行资格切口单独复验域；核固定私有 TDB 时才短暂用 Samba 已有的可信服务身份，及时恢复，不给客户端任何宿主路径/SQLite 权限。普通 SID 格式化可用已核不可变缓存，不签新登录。原物失效干净终止该专进程，不对既有上游调用者泄出 NULL、也不以 panic 或 core 当正常拒绝。运行中换挂载/原件、改配置、替换 BOUND 或缺域都不能用新名字刷新信任。需要变更由宿主另行授权、替换并重新启动；不干扰管理员通过 SQLite 改共享 RO/RW。

**接线顺序。** 宿主须先持有经批准、互相吻合的 PoolId、InstanceId、ProvisionOp、上线配置原件 SHA-256、`ZXSLOCAL` 和原 SAM 域；引导配置/工作组名不是上线原件。启动端必须核实际加载的专用实例、配置/依赖、private/state 和 SQLite 内该域 + RID 1000 的 SMB 行，之后才接受连接。禁不受控 include、配置重定向及任意插件。仅看到配置字段、读到域或对完整拷贝算得相同摘要不足以鉴别宿主。当前已接以上受管配置和 SAM，以及下面的原池/固定 SMB 账户启动核对；原生认证与最终会话关联已有源码，但不是已部署、已登录或文件服务可用的证明。实际口令验证取用的**第一份** SMB 行要在本次认证上下文中绑定 Pool/AccountId/SID、凭据原操作及代次；后续重查用户名或凭 SID 命中缓存不得替它签发。通过账户策略、真实非 guest 安全令牌并成功发布这一 SMB2 session 后才向对应 tree 打开 FILE。无相应证明的恢复/新通道不受理。

### 仅两端的启动控制通道

宿主监管者新建阻塞的匿名 Linux AF_UNIX/SOCK_SEQPACKET socketpair，严格只将一端作为 fd 3 给受保护的专用 smbd，另一端作为 fd 3 给本项目独立的非 root `zxs-smb-storage` 进程；不给 Web、系统级 Samba、其他实例或客户端。后者的 fd 4 另由宿主打开为已批准实例的**原 BOUND 只读投射**（root 属主、原单链接普通文件）；fd 5 是宿主从创建时钉住、对应这一个前台专用 smbd **实际原进程**的 Linux process pidfd，不能由 fd 3 对端补给、启动器自己的 PID 或事后进程名替代。宿主分别提供 `ZXS_SYSTEM_ROOT`、`ZXS_POOL_ID`、`ZXS_SAMBA_INSTANCE_ID`、`ZXS_SAMBA_PROVISION_OP`、`ZXS_SAMBA_LIVE_CONFIG_SHA256`；必须来自原安装的独立选择，不从 socket 对端或所读记录反填。两个端点无文件名、无监听、不可连接；SO_PEERCRED 在 socketpair 上属于创建者，不能证明后来执行哪套二进制。宿主须验证实际启动的两份发行件，且在各自 exec 后关闭自己及其他进程不需要的副本；不得跨 UID 映射辨不出该 root 创建者却放宽准入。此通道与离线域供给不相通。

只有在 smbd 已用同一配置字节并从真实专用 SAM 复验时，才向原通道发其 128B BOUND，并用同一消息只交接一件内核原物：专 smbd 刚建的匿名 Linux pipe 的只读端。写端不携数据，留在 smbd 及其 fork 的参与进程，禁止转交给第三方。存储进程独立持原 SYSTEM 目录 SH，用同一 SQLite 短读切面核 INIT/原卷标、唯一配对及其当前 SMB AccountId/凭据单和代次，域须为原本地域＋RID1000。受管 BOUND 在整个核对中保持原 FD、戳与相同字节。答复固定 277B：16B `ZXS-SAM/READY-2\0`、所核同一 BOUND、16B SMB AccountId、16B 凭据原单、8B 正大端代次、28B 账户 SID、1B 名长及其64B 零填充规范 SMB 名。先完成字节数和原件核对才回复；不会选取或发送口令、NT 验证材料或 Web 凭据。成功仅描述启动瞬间证实的这份账户；不是 NTLM 验证、正面登录票、共享授权或目录就绪。

握手有截止时间。第一条 BOUND 只接一件原 kernel pipefs 的只读、非阻塞读端，不接受普通、具名、坏方向或额外辅助数据。收到它后，即使 READY/PLAN 因故未送，存储进程也先撤控制通道，并保持原 S SH 到该寿命管最后写端真正关闭。正常后先核 17649B `PLAN-01` 和原 SQL 首设，精确 `PLAN-OK` 仅证明所选装配；最后开 `SO_PASSPIDFD` 使之后只收不发。只有已核实际全部批准地址和 TCP 445 的 smbd parent 才通过独立 fd 4 送 176B `LISTEN1` 并写半关；主管核原 master pidfd 和 EOF。每条实际 accept 用真实本地 IP 选其批准对端前缀。控制关闭不是参与者已经关完的证据；监听回执不是登录、fd3 后续分派或文件业务成功。

待联调：由受信 supervisor 只交上述两端及原 BOUND；无账户、他池/实例、同形异域、错误控制地址、可写 BOUND、smbd/存储端异常关闭均不取得操作许可，双方关完真 FD 后 helper 才可取同一 S EX。当前只编写了真实 Linux 消息与 SQLite 行选择的源码用例；没有部署、运行或验过 Windows 登录。

### 每次新 SMB2 握手的服务端挑战

真实的全新 SMB2 SESSION_SETUP 尚未建立会话时，只能为本次请求预取一次挑战。主通道拥塞立即拒本次登记；等待私端答复使用 Samba 原 tevent，十秒超时或取消即关本次等待和端点，不占用事件循环、未创建可访问的会话。其他连接/请求可先得到自己的答复。通用认证/RPC 调用、重认证、通道绑定、客户端改挑战或超时后在原上下文换挑战均被拒。专用 smbd 在这个上下文新建匿名 socketpair，向已配对的 fd 3 发送 `ZXS-SAM/BEGIN-2\0`（16B）和原 TCP 的两个大端 64 位 cookie，随包给单独的对端 FD；多个 smbd 子进程在共用 fd 3 上**只发注册、不收挑战**。存储进程从系统随机源取 8B 非零值，仅向此次单独端点回复 16B `ZXS-SAM/CHLNG-1\0` 加原 8B。原 GENSEC 接手已就绪的这一个端点和挑战，正常对象销毁即关闭；以后查询不等待，按本机单调时钟和原私端复核，30 秒外即使远端还未关闭也拒。资格失败不改用 Samba 的其他随机源。

每次受管进程配对最多同时保留 32 个待处理挑战，按各自的 30 秒期限清退；满时只拒新的一次；原 BEGIN 完整但内核未能交出一件正确的 FD 时也只拒本次。坏控制帧/关闭仍撤销整次运行配对。同一真实 GENSEC 在完成本次登录后可在原私端请求一次相同凭据代的非秘密切面。超时、对端结束、重复请求或未知输入都放弃原尝试。内核 poll 最长每 500ms 清理，不能据仍有一个 FD 声称已经验证。停止时全撤，仍等原生命周期 pipe 的最后写端真正关闭。此处不查密码、不接收客户端证明、不计算会话密钥或写 SQL；挑战是非秘密数值。原生密码回调仅在**同一个**已就绪且未消费的 GENSEC 内有效；私端不收发密码资料，不能凭挑战、READY 或 guest 换会话。未运行的源码用例覆盖独立的本机端点、队列、缺 FD 和过期；专用源码构建的 tevent 小夹具让第二个真实可读回调先于仍无答复的第一个执行。未实测系统 FD 枯竭，也不是 Windows 登录验收。

### 真实客户子进程与接入连接

只有专用前台 smbd 已配对的监听父进程在真正的 TCP `accept` 成功后、为它 `fork` 之前，才在本次调用栈记录原网络命名空间与原 socket 的内核 cookie。子分支完成 Samba 自身重初始化和专用 SAM 复核后，在同一已接受的 socket 上一次性认领。新 SMB2 SESSION_SETUP、其异步挑战回调、后续消息和最终令牌门都要求本次进程/连接仍相符；原 GENSEC 取挑战还核原工作进程。用另一个连接占用相同 FD 号不能接续，原连接的 `dup` 不改身份。父进程、通知/清理辅助进程、再派生的子进程、inetd 与交互分支不获此角色。这里没有给进程持有额外 TCP FD，不改已发布盘格式。

此处证明的是**这份受控代码本次处理了哪条连接**，不是存储进程已经从操作系统独立验明应该向谁供给凭据，也不是客户通过认证。只有随后真实原生判断成功才可继续；PID、cookie、原挑战通道或 READY 均不能单独作为对外授权。测试源码用两条不同的回环 TCP、原 FD 替换、辅助 fork 和二次 fork 区分这些条件；未执行。

### 存储端如何认出发起这一次认证的进程

1. 宿主只运行固定发行，在**原 PID 命名空间的属主 user namespace**及其祖先里，专用 smbd 和所有能发送 fd 3 的参与者均无、也不能重新取得 `CAP_SYS_ADMIN`；不把 fd 转交给其他主体。发行入口能实查的是当前 user namespace 中有效、许可、继承、ambient 和 bounding 五组位，不是对其他命名空间权限的证明。受信宿主还必须保证原监听与传递端处于同一固定 PID namespace、它的属主正是这些进程的 user namespace，并排除向更高权限主体交付原端；无法确证此部署即不启动。服务不自行修改能力或切命名空间。原服务与运行实例的鉴别仍来自可信宿主。这不是通用的“不信任主机 root”的沙箱。
2. 服务实际 accept/fork 后，在同一父级事件回调里，直接取这个尚未被回收的**亲生**子进程的 pidfd（拒自动回收配置；对 pidfd 作不消费的非阻塞子状态检查），用 `ZXS-SAM/CHILD-1\0 | net-cookie | socket-cookie` 向 fd 3 交这一个原 pidfd，只含非秘密调度信息。父不等存储或业务；成功将消息排入队列后才放本子继续，提前调度的子只等自己的一次启动闸；拒绝/超时发生在 Samba 子进程重初始化前，此时只以 `_exit` 结束该子，不运行继承的监听父清理、更不删除父 pidfile。待实机验拒绝一笔后原父 pidfile 不变、其他已接入连接仍可服务。别的 fork 不会被计入。
3. 存储只在发完 PLAN-OK 后开启 Linux `SO_PASSPIDFD`，此后该主端只收不发，避免 Unix socket 自动绑定名字。两种角色消息均由发送进程附**自己**的内核校验身份，即使刚好已在 READY 后的队列也能取到该条消息的 `SCM_PIDFD`。父登记的发送者必须与独立 fd 5 是同一个仍存活的 pidfs 进程；子送 BEGIN 则核其真实发送者、所报原 TCP 和本次独立私端的 `SO_PEERPIDFD` 都对上这份登记。进程号、UID、socketpair 创建者、同名程序、上一条 READY 或仅持有 fd 3 都不够。重复/晚到/错件不替换原登记；最多 256 个登记、32 个进行中的挑战，进程消亡、超时及停机撤销。没有新监听或用户可查询的本机接口。参见 [Linux 6.12 的发送者记录](https://github.com/torvalds/linux/blob/v6.12/net/unix/af_unix.c#L1799-L1821)、[凭据的命名空间限制](https://github.com/torvalds/linux/blob/v6.12/net/core/scm.c#L43-L59) 和 [pidfd 的现场原物](https://github.com/torvalds/linux/blob/v6.12/fs/pidfs.c#L374-L387)。

该登记只确定“哪一个真实接入进程为哪条 TCP 进行这一次挑战”。它不提供口令、密码等价物、正向会话或 FILE 权。后续在这个受管 smbd 客户进程的原 GENSEC 中，只准由唯一原生 tdbsam 为本次登录使用该原账号的当前代，禁止独立查询接口/公开 fd 3/日志/另一个账户库输出；原登录失败、过期、凭据变化均不能靠调度证明放行。需保留原生签名与完整性后验，待准确 SMB2 session 发表成功后才可绑定当前共享和 FILE。宿主 fd 5 的实际交付、真实 Windows 登录和数据访问仍未验收。

### 原生 NTLMv2 输入与诊断边界

这份专用 Samba 的 GENSEC 只将经过原生 NDR 解码、两个版本字段均为 1 的 NTLMv2 结构交给后续口令判断。保留上游对服务端目标信息、通道绑定、时效及协商的 MIC 的检查，不凭长度识别；同包可以携带 LM 字段，但不将它交给口令判断，也不改原消息用于完整性核验。原生后验只接受确切长度的 NT 会话基钥，不接受 LM 替代。依据 [MS-NLMP §2.2.2.7](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/aee311d6-21a7-4470-92a5-c4ecb022a87b)，保留字段不用于授权。结构合格不是已经验密。随后固定的 auth3 回调消费这次原尝试，打开受保护原 TDB 的一条已选 SAMU，以原版 `sam_password_ok → ntlm_password_check → smb_pwd_check_ntlmv2` 验证，不复制密码计算算法。只认原提交的确切本地域与规范用户名，不尝试空域/别名、密码历史或 LM 路径，FIPS 不许可则拒。原生返回仅交给同进程的原 GENSEC 作 MIC/签名和会话协商，不走 IPC、日志或另一个密码库。另有仅供自测的源码，用定死的公开虚构口令走上游客户端/服务端，断言本次 NT 材料相合、无 LM，空域与损坏证明均拒。它没有运行，不模拟真实 TDB、用户、进程或签名后的 Windows 会话。固定 Unix 号只为真正的成功结果产生普通执行 token。

同一私有发行禁编译密码调试，原诊断入口的编译上限及运行时实际读取的调试级别均不高于 0，即使有高等级类设置也不打印 SPNEGO 报文或 NTLM 的详细结构。专用配置同时拒绝 `debug encryption = yes`：原 Samba 的这一选项甚至会在 0 级打印 SMB3 密钥，不能只靠降低日志级别。专用日志的二进制转储入口也明确拒绝 0 级：即使 SMB2 签名不符，仍按原协议拒绝，但不打印收到的或计算出的 MAC。保留失败结果文字；不改变签名比较、协议字节、非日志回调或正文。不改宿主其他 Samba 的日志设置；这里未验证外围监督者、主机转储或第三方日志。只写了真实日志回调和无秘密结构的源码用例，未运行。

## 业务共享的原生 VFS 基座

在固定 Debian 的 `smbd_vfs_init`，只有实际服务号就是 IPC$、请求确为 IPC、全局命名管道已关闭且没有额外模块时，才选已静态注册的上游默认栈。普通业务服务必须只声明 `zxs_file`；它直接安装专用前端与 Samba 同一固定版本的完整 ABI 50 终止表，不调用磁盘模块或动态加载器。安装前也核终止表没有空回调，不依赖发行版可能关闭的开发断言。两类设备不匹配、打印、wide links、未知/额外名称或已有其他栈均拒。内部 DFS 连接携带的 Unix 名同样不能取得 FILE 访问。

普通原生 CONNECT 只认 `[ZXS]`，用真正已验证会话和已确认的同一安装计划选树，不遍历文件系统。根下可列的盘目录按当前 SQLite 模式过滤；每个实际盘目录打开时另在同一短 SQL 切面选具体 F 与原设置，事务外持原 F/标记，再短 SQL 复核。本机窄回复不是授权转发，不含宿主路径或 inode。各盘独立受限任务，慢盘不持 SQLite 读事务；不是跨盘原子快照。物理卷名称和 ShareId 不充当另一个 SMB 入口。

`/zxs-root` 是固定虚拟值，只在真正建树的原 VFS 接点允许根规范化和 STAT；不取宿主 cwd 或 pathref。配置关闭通知、kernel oplocks、DFS、打印、命名管道及 guest。一个已建 tree 不授任意盘上的写权。

### 普通 FILE 的一次 SMB2 READ

目录不是正文。先由 Samba 的原分派验证签名/入站加密、协商上限与 credits，再核真实 TCON、该会话已经成功取得的普通 FSP、实际 FILE_READ_DATA 与原连接。复合请求不能把 IPC 或另一棵树的 FSP 带进来。保留整个三字逻辑 FILE 锁键；原生字节锁按本次持久句柄与所请求区间，在请求开始和就绪时各核一次。不因另一个写者给兼容读另加锁。专用数据共享须使用原生 Windows 锁（locking=yes、strict locking=yes、posix locking=no），没有可回退的物理 fd。原字节锁数据库读错不当作无锁；SMB2 LOCK 的客户端加/解锁入口尚未接通。目录、未知操作与未支持的 RDMA 均拒。

存储仅从该只读 FSP 原先绑定的本机端受理偏移和长度，不收路径或文件描述符。每个请求使用独立的匿名回复端；源端只读已确认修订，按已确认 EOF 裁剪，校验所有相交块，并再核确切原 S、F、FILE 和现行共享/账号代。正文先进入待发缓冲，存储在复制结束及末次复核后才给出该请求的完整确认。中途撤权、坏块、缺尾、关闭或超时均不向客户端交部分正文，空读也不跳过授权。确认后由同一原 smbd 请求处理 MinimumCount/EOF、真实签名和网络回复。普通 READ 不用宿主 sendfile、AIO 磁盘或默认 VFS；smbd 主事件循环不等慢盘，文件关闭、断树和注销能取消在途请求。一个盘目录的读取任务可以因本盘慢操作延迟同队列请求；写柄用独立原 FILE worker，不因此拦另一兼容读。未实测延迟、吞吐或客户端互通。读写柄的 WRITE、SET EOF、FLUSH 与正常脏 CLOSE 另走同一个原写者，绝不下沉到默认 VFS。

## 普通文件的单写与手动提交

普通打开现已在原生 `open_mode_check` 接入一项约束：只有实际装着专用两层 VFS 的普通 FILE，已有写/追加与新的写/追加互斥，即使双方都声明允许共享写入。两次判断（原生快速汇总、有疑义时按存活的原句柄重算）用同一条件，不改客户端的任何 ShareAccess 位。受管业务不接 OVERWRITE/SUPERSEDE；显式 EOF 在已经持有的唯一写柄上处理。读打开不会因**这项**规则而拒绝。它复用该 FILE 的原生 share-mode 记录及打开/关闭寿命，不另开 SQLite 事务，也不调用 VFS 或等待磁盘。普通具名 FILE 与 FILE_CREATE/OPEN_IF 均取得真实 Samba share-mode 记录。同一 FileId 的写柄另持原容器 EX；兼容读不取写锁。源码未实测，不是完整应用保存兼容证明。

**只限制单写，不额外禁读。** 跨进程、路径别名及不同共享，写者键是 `(PoolId, FileId)`；拥有者是真正成功打开的那一笔业务 handle，不是账号、连接、共享名、底层 RAW inode 或当前物理表示。创建/接管写句柄先验当前 RW 和 SMB 原生 ShareAccess；存在别的写者时写类打开明确拒，不降为只读。同一 FileId 的写、截短、删除、覆盖/替换目标不能绕过。可在 CREATE 返回句柄前已经截断的 OVERWRITE/SUPERSEDE 必须在第一个副作用前准确暂占，失败只放本次占位。DELETE_ON_CLOSE 的设置和最终 unlink、服务器 COPYCHUNK 的目的端也受同一限制，不支持就明确拒绝。不同 FileId 不相互上锁。

读句柄仅按其自己的权限、ShareAccess、字节范围锁及当前已确认修订处理；**不因存在写者额外拒读**，不读别人还没确认的编辑。写者自己的正常读写语义不变。SMB 共享访问模式控制读/写/删除的兼容性；字节范围锁保护具体范围；协议缓存 lease/oplock 不等于前两者，也不等于业务单写锁。不得以一把长期 SQL 写事务或整盘锁实现单写。

- 同账号三次独立打开：A 持兼容读取的写句柄，B 能读已确认稿，C 请求同 FILE 第二写被拒；换共享路径、物理表示或另一个 smbd 进程结论不变。若 A 的**原生**共享参数明确拒读，则 B 也应被拒；无关 FILE 可写。
- 同一 FILE，原生读/写/删除共享各按请求核，字节锁分别验重叠、不重叠、显式解锁和关闭。临时文件＋改名替换是常规应用保存：目标句柄已关闭且没有活写者时，按稳定顺序取得所需源/目标资格，核当前 RW、基线及两端原生 share/delete 条件，准许正常替换，不要求继承已结束的句柄。若目标仍被写者占有，只允许能证明正是该目标 owner 的操作；同账号、进程或连接不是证明。失败不留下半替换。
- 正常 CLOSE 或确认断线收尾，先使旧句柄不可再改，排空或使已派发异步写/待提交 SQL 失效，再交下一写者；未实现 durable/reconnect 时明确拒，不用重连/同账号绕过。读者持确切已确认材料到交付结束，不能让后台换成 Raw 后重新按 inode 独立加第二把写锁。
- 对已绑定基底的保存，在短 SQL 提交中核前修订和原操作，过时即冲突；同单重送不重复 SAVE。客户端关闭后另开新句柄、用应用自己保留的旧内容整份写回，没有通用凭据能把它认成旧基底。要保先前编辑仍须按真实客户端行为验证。

WRITE、写穿、SET EOF、FLUSH 或正常脏 CLOSE 使用已取得的原写柄。普通缓冲写与 SET EOF 只为该写柄留私人视图；明确 FLUSH/写穿/正常脏 CLOSE 才短事务确认工作修订。断线不自动确认。兼容读固定打开时已确认的平图；后续编辑仍在同一轮物理对，明确 Web 手动提交后才出 Node，下一轮不靠生成 FULL。四轮、0B、迟撤权及跨 SQL 连接的用例只写源码，尚未实测。

### 普通共享根 FILE 列表（存储业务层）

从本次已授权的共享定位其唯一普通卷，不接客户目录路径；按显示名的 UTF-8 原字节分页（每页 1–16 项）。仅列已确认出生的 FILE，返回显示名、FILE/条目标识、已确认工作修订和逻辑长度。只读及读写共享可以指向同一个命名空间；未确认的创建、物理文件夹名、标记、改动材料及回收卷不会被列出。已确认首个 0 字节 SAVE 与尚未保存都显示 0 字节，但修订号不同。列出尺寸不证明正文完好，读数据仍另走原块校验。

非空页的首尾各枚举一次该 F 的真实目录项，各 FILE 另验自己的成员；按页计成本，不是整个目录只扫两遍，也不是正文 I/O。空 SQL 页免扫 F 子项，仍复核同一根、授权及空结果。每一页在归还结果前复核同一 SQL 权限及该页成员、同一 F 和实物双名 FILE 头。选件变化/断点返回错误，失败不会推进游标或泄出半页。游标跨页不占 SQL 事务或卷写锁；并发新增而排在已交付显示名之前的项需重新枚举，遇到结束后也需重开。存储端也可按这份列表**选中确切 FILE 再读**：在调用者当前共享的一次真实 SQL 切面核 PoolId、VolumeId、原显示名、EntryId 和 FileId，实际重新打开该 FILE 头与已确认工作材料。列表不是授权，撤权后旧 Tree 拒；同根另一当前获准共享可以打开同一 FILE。普通 OPEN 固定打开时已确认的修订，不把之前列出的大小当历史版本承诺。名称碰巧相同但成员不同不接受。上面的存储接口本身不构成网络打开。SMB2 根目录 `CREATE`/`QUERY_DIRECTORY` 已接这份分页；普通 FILE 的网络 `CREATE(FILE_OPEN)` 已接同一业务选择，正文 `READ` 可在这份 FSP 上请求该次已确认的有界范围。均未运行。

### 逻辑 FILE 在 Samba 的同物键

在真实普通父下创建 FILE 时，SQLite 同一写事务以现有 16 字节 FileId 的 BLOB 索引检查前八字节对应的号：包含待办和所有普通根，不按共享或是否可见过滤；只为新原单选空号（保留 0–255 及全一号），原单重试不重抽。所有未来出生或迁移须保留这个池内唯一号。打开已确认的真实 FILE 后，存储端用当前授权、原成员和当次原物复核，再给出 Samba 三个 64 位字段 `(PoolId 高半, FILE 号, PoolId 低半)`。若既有数据没有唯一合格号，该投影拒绝，不借原生 inode、路径或散列修补。两个字段的 Samba 缓存仍须按专用池隔离。这里没有新 SQL 表；具名只读/可写 OPEN 和新 FILE 的真实原生 share-mode admission 复用此键；源 fixture 不是跨进程实机验收。
