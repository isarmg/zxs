# ZXS 内部 Rust SMB 服务

**这是 ZXS 唯一维护的 SMB 实现，不是通用服务；尚无本候选经过安装、挂载或原生客户端验收的结论。** 它编入同一 `zxs` ELF；正常入口按[原站点契约](launch/site/CONTRACT.md)取得同一实际原件并派生两个受控角色，其中 SMB 的资格来自原可信启动、Core、已继承监听接受的同一 TCP 流和原强签会话，不来自外部程序、参数或环境。源码已接只读虚拟根、真实普通盘目录的打开／枚举／关闭及已有子目录的独立同父改名、已有普通 FILE 的打开／读取、原单写者的 WRITE／FLUSH／显式 CLOSE、根卷属性的已签关联探测及真实退场。现有写者可显式调整暂存 EOF；原 SAVE 结果暂不能核定、或已确认后失去回复资格，停止原连接，不发确定失败或重试。已有回收目录可按原身份打开／列出，回收 FILE 可只读打开／读取／关闭；保留 FILE 的独立及窄关联同树恢复已接原 kind12；已接普通可写 FILE 与实际目录的窄 CREATE／OPEN_IF、已有普通 FILE 的同父改名及独立的同一登记 F 内跨父移动；范围锁、目录跨父、FILE 跨卷和替换仍不支持。本次清理不执行构建、启动、监听、客户端或应用验收；其他实现/制品的结果不是这里的证据。

收到合法探测不等于授予能力：CREATE 先核成员范围，再按各 context 的规范处理。[未提供租约](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/fc4f8879-f295-4995-b71e-21f309d8d7c8)和[不授耐久的打开](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/33e6800a-adf5-4221-af27-7e089b9e81d1)仍可完成适用的普通 CREATE；重连请求不能降格为按名字新开。命令应按各自条文忽略、明确失败或断连，不能一律丢弃探测，也不伪造成功。例如不支持目录通知时，合法的 [CHANGE_NOTIFY](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/05869c32-39f0-4726-afc9-671b76ae5ca7) 按命令规定失败。若目标部署要求 SMB 加密，须先真正实现并审过 AES-128-GCM，否则不支持；协商 offer 本身不是强制策略，不能以明文回退或关闭客户端安全策略求通。

`wire/path_fields` 从单条 CREATE / SET_INFO 普通 rename 消息的声明范围提取名字，`backend/path` 是唯一业务名字解析：严格 UTF-16、以同一共享为根，逐部件调用现有显示名规则，保留大小写和 Unicode 原拼写，不从名字判断数据盘／回收站，不解释宿主路径。CREATE 空名和未处理的 contexts 一起保留，不把重连请求误作根权限。rename 源是本次协议句柄，目标的替换标志不是覆盖授权。关于多部件目标，[微软 SET_INFO 条文](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/43cf22fe-84cb-49cf-b3e7-e3d7d766a7b7) 的分隔符限制与 full pathname 表述并存；[Linux 客户端](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2inode.c#L1014-L1055) 会编码目标路径。此处只给下述 ZXS 操作保留受限的目标形状，不声称通用协议兼容或原生客户端已通过。具体成员字节额度、当前盘和删除原单仍由 Core 选择和复核。

`wire/create_fields` 进一步按 [CREATE 固定字段](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/e8fb45c1-a03d-44ca-b7ae-47385cfd7997) 和 [CREATE contexts](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/75364667-3a93-4e2c-b771-592d8d5e876d) 验原成员。保留原 DesiredAccess、分享掩码、顺序与请求选项；仅去规定忽略的位，不产生实际 Grant。最多 16 个 context，Next、名称与数据各自限在原 context 中，零数据不看 DataOffset；精确标准保留 context 只忽略内容。空名偏移也必须在原成员 Buffer 对齐范围内，只表示申请打开当前共享的已有根，不执行新建／删除，也不能给耐久重连、旧版本、回放或不明扩展换成当前路径。合规 lease/durable 新申请不授缓存或持久资格；只识别 [Apple 定版的 24 字节 AAPL Server Query](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/netsmb/smb_2.h#L94-L107) 为不改目标的提示，不把 Resolve ID 当普通打开。原请求 `MxAc`（无时间与零时间不同）和 `QFid` 仍是必查的原对象应答义务，不得以假权限或伪 ID 填空。仅解析，无真实树／OPEN、Core 入口或 CREATE 成功。

目录和元数据查询不从协议数据构造业务对象。按 [QUERY_DIRECTORY](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/29dfcc9b-3aec-406b-abb5-0b4fe96712e2) 与 [QUERY_INFO](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/abb48417-27e5-4a16-82e0-3e5981db97e8) 保留原请求长度供 credits 核验，不把客户端 FileIndex 或 SMB2_FILEID 变成 Core 游标。查询目录的模式是单个分量，不可当路径；没有新模式不能让续页丢失原筛选条件。[Apple 原生实现](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/netsmb/smb_smb_2.c#L8315-L8369) 会给空模式留 offset 96 和两个零字节，当前仅和标准的零 offset 一并识别为空模式。[Linux 客户端](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2pdu.c#L5358-L5394) 与 [Apple 客户端](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L8176-L8185) 的源码分别给出目录信息类选择；这是格式依据，不是原生挂载通过证据。

一页只为有权、匹配的逻辑顺序前缀预算，独立限制条数、客户长度和复合应答剩余字节。只在记录之间算 8 字节对齐；首条装不全、下一条装不下、固定部分都装不下不是同一结果。真实适配须按原 OPEN 重核列出权，再按来源的真实排序与集合结束标记推进，不消费未回的匹配条目；不能让游标先推进再丢弃未返回的尾部，也不把过滤致空当结束。[MS-FSA 目录查询](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/fa8194e0-53ec-413b-8315-e8fa85396fd8) 的模式延续、匹配、点记录、溢出数据和结束状态仍须接线。元数据按已持对象区分虚拟根、目录和 FILE；访问属性和具体卷必须来自原始授权对象。虚拟根不挑任意实体盘冒充总容量，不对下线盘填假数据，不返回宿主路径或私有标识。

`wire/query_reply` 接原授权根 OPEN 已封存的完整非空记录，按 [MS-SMB2 §2.2.34](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/4f75351b-048c-4a0c-9ea3-addd55a71956) 编写固定 8 字节正文（StructureSize=9、输出 offset=72 及实际长度），并和待提交游标封存在同一个回复对象。原 OPEN 只留一份已提交位置和待发弱身份；不能重用该提案或靠同名重开替换。已付且整帧验签后，独立 QUERY_DIRECTORY 再核原会话、树、OPEN 两半及 FILE_LIST_DIRECTORY，重查实际 Core 投影和盘模式代。原响应完整写上同一 TCP，且末次验原 OPEN、投影与授权后，才由私有 `WrittenRootQuery` 一次提交该页及额度。部分写、撤代或投影变化不推进，已写字节不可撤回。实际无匹配分别回 `STATUS_NO_SUCH_FILE`／`STATUS_NO_MORE_FILES`；固定前缀空间不足回 `STATUS_INFO_LENGTH_MISMATCH`。首条名称装不全按 [SMB2 ERROR 外层规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/41295064-be3f-41dc-9aa5-f68545f945f0) 报 `STATUS_BUFFER_OVERFLOW`，当前不提供部分名字 ErrorData、不记成扫描成功或结束。仅支持下面列出的窄复合形状，不等于通用派发或完整原生探测。

## 已接受连接的交付与协商

未来已启用的服务所有者只能交付一条**尚未读取、独占**的 TCP/445 连接以及同次运行的私有实例。这里不建监听、不接收外部传来的已登录连接、不克隆或替换流；内核取得的这对地址只作连接元数据。[接入状态](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/91e2ec0b-530b-4558-aee0-2ca4d586f66a)与认证身份是两回事。每个未协商的入口在首次阻塞读之前与已协商连接共享最多 128 席；失败释放，成功将同一席转为原连接登记，不在注册锁内做 I/O。

首字节前用 [TcpStream::local_addr](https://doc.rust-lang.org/stable/std/net/struct.TcpStream.html#method.local_addr) 和 [peer_addr](https://doc.rust-lang.org/stable/std/net/struct.TcpStream.html#method.peer_addr) 从独占的同一 socket 取得完整 `SocketAddr` 对，拒绝本地非 445、对端零端口、不同地址族或非具体单播地址。地址对只随原流进入同一个 origin，保留 IPv6 scope、端口和地址族，不从 UNC、转发信息或测试的输入地址取值。原已付额、验签的 TREE_CONNECT 只能短借查看这一对，不能单独提供本机和客户地址。地址形状正确不等于获准：正式入口仍须在读取前识别真正已批准的本地监听及**该监听自己的**客户前缀，且业务授权仍需同一 Core 安装与账号代。此处没有准入发行者、监听或密验文件读入。

按 [Direct TCP 帧格式](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/1dfacde4-b5c7-4494-8a14-a09d3ab4cc83)先完整读四字节、检查本地首次 NEGOTIATE 68 KiB 上限后才分配，不误吞后续帧。接入首包有固定五秒预算，不把它当成已登录客户端的空闲时间。输出只加四字节前缀，原议定 SMB 全文完整写入同一 TCP 后才发布初始额度与 preauth 链；EOF、超限、零写或半包失败终止这条流，无手工“已发送”生产入口。成功写完不等于对端已经收到，更不代表有账户或文件权。三类 SESSION_SETUP 回复和后续原帧读取见下；业务持有者与通用派发仍未启用。源码夹具在 `src/test/smb/accepted.rs`，未运行或开 socket。

### SESSION_SETUP 不能手工确认发送

机制选择 MORE、实际 Type 2 挑战 MORE 和最后经严格证明签出的成功回复，只能把原额度账绑定的完整 SMB 字节加上前缀，写入原连接独占的同一流。每次短写前及写完后检查原登记、阶段、期限与所需凭据代，不在网络写入时持注册或凭据锁。选择 MORE 并不证明账号，实际挑战要在原凭据代下才转为可用；最终成功仍在同一注册和原代原子发布后才是有效会话。部分写、完整最后一字节时已撤代、失败或流丢失均不补信用、不转阶段，终止原连接。仅测试保留人工拨动完成态的原单元夹具；`src/test/smb/setup_send.rs` 另以实际完整写口覆盖三种过程与失败。这不是生产账号来源、全部入站命令或可挂载服务。

### 原流入站到真实握手与 ECHO

协商后的原 `Peer` 自行从同一套接字读下一条，不接受外部提供的字节、Connection 或另一个输出端。空闲轮询（一秒未收到首字节）保留连接，已开始但超时／EOF 的半包必须关闭。先按 [MaxTransactSize+256](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/ef8e06ba-c921-46c9-9780-a2e9843e1d30) 核长度，再分配；轮询会清理期限已过的原握手，首次登录等待在六十秒边界检查。该预算不是已登录会话空闲超时，真正的服务调度者仍须轮询或释放连接。

在单条新建／续接认证时，原 MID 先消费，选择 MORE、真实挑战 MORE 或最终签名成功依原阶段返回。已认证普通 ECHO 仍须原整帧强签。依[会话查找](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/e545352b-9f2b-4c5e-9350-db46e4f6755e)、[GSS 失败](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/5ed93f06-a1d2-4837-8954-fa8b833c2654)及[出错应答](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/41295064-be3f-41dc-9aa5-f68545f945f0)，仅对上述无签、无既有认证权的独立尝试，实际返回原 SID/MID、原额度及明确失败：找不到原登记、严格证明不通过、无可用凭据及坏 token 等分别处理；错误报文既不发权也不收回同连接另一有效会话。部分或去向不明的写绝不再补第二份回复。带签重认证、binding、旧 SID 接管、含 SETUP 的复合以及未接业务都不退回这个无签错误路径。普通业务只交原短借的受检对象，不给可重新喂包的连接；遗弃欠账要关原流，不会假装已响应。

`src/test/smb/accepted_turn.rs` 只含公开合成验证材料：三种握手走同一双工流、以实际协商盐和往返算终签、再核一个真实强签 ECHO；另区分首字节前空闲与半包超时、错连接 SID、错误证明和可继续的新尝试。无生产发行者、监听、文件权或实机结论，未运行。


## 内置 SMB 的受托接收端

专用降权子进程的私有接收源码只认固定的原 `fd3` SEQPACKET 与 `fd4` 父 pidfd，不接受 CLI 指定 FD 或外传连接。先从本线程实际 procfs 及内核身份确认初始 user namespace、真实 UID/GID、PID1 与 no-new-privs，关闭自身可转储性，再接一条有界 START 与原流 EOF。消息必须有初始 namespace 下 root 的逐条 SCM_CREDENTIALS 与匹配所持原父 pidfd 的 SCM_PIDFD；数字 PID 不替代真实 pidfs 对象。每个收到的内核 FD 始终有所有者并关闭执行继承，异常／多条／截断不留下可用 FD。[Linux 逐条凭据和 pidfd](https://github.com/torvalds/linux/blob/v6.12/include/net/scm.h)和[受限内核路径查找](https://docs.kernel.org/filesystems/path-lookup.html)分别定义了这些边界。

首个 FD 必须是真正封住写入和长度变化的公开 envelope，匹配原 80 字节消息的 SHA-256 与 nonce。第二个是父端原名重开的 240 字节 root:root 0600 单链接只读 vault，按原 dev/ino、ctime/mtime 和 FD 形状匹配，但此接收器不读密验正文或产生账户。随后 1–16 个来自内核的直接 TCP/445 非通配监听必须按 envelope 的 SO_COOKIE 顺序，IPv6 仅该地址族；形状仍不等于获准。最后一项是本次两角色共同放行门的原只读描述符，绑定同代与同一绝对截止。Core 只从同一真实接收所有者核原 SYSTEM、审批计划、当代账号和每个监听对应的地址／客户范围。只为 Linux ABI 显式引用既有锁定的 libc 源码，无新包或网络源。夹具只用固定公开合成字节和匿名本地 FD，未运行。

严格验证器只消费同一个真实启动对象中的原只读 vault，但必须先从 Core 同原 SYSTEM 原位锁、批准计划、独立 Rust 家族下取得已核当代账户。安装还活着才一次移出该 FD，读前/后核原 inode 与变更时间，恰读 240 字节并检查 EOF，随后再核 Core 原切面。密码等效字节只传给不可在该模块外构造的严格解码能力；自有输入和密钥缓冲退出时尽力清除，不承诺抹掉内核或编译器副本。比较真实池/INIT/SETUP/实例/Bind/共同 AccountId/凭据操作/记录号以及完整代和登录名，没有原名重开、旧凭据导入、默认密码或任意字面构造。仅采用同安装批准的主机实名和固定 ZXSLOCAL，VERSION 调试字段取本地 Linux release。会话在已有真实签名、原连接注册和当前验密代下才可用弱见证联结同一启动；单有数字 SID、ECHO 或合成测试 provider 不能拿业务 Tree。


从真实 `QualifiedRustInstall` 和原已签、付额的独立 TREE_CONNECT，成功支路现能把该 Core 逻辑根装入**原 Session** 唯一有界 TreeId 表。先由真实清单和权限生成 DISK、NO_CACHING、无 DFS/持久句柄和真实共享权限上界（只有真实 RW 子目录才带产品所需写位），虚拟根自身的只读状态不冒充整树权限。TreeId 不复用、预留不对查询可见。同一个已占信用并签名的回复先写完原流，再复核原会话及同一 Core 清单和模式代，才一次发布 TreeId 与账；失败/撤销关闭原流，不新增 Tree 或信用，已交 TCP 的字节不能召回。这条握手的源级夹具不建立真实挂载，也不证明后续 OPEN / 读写已经验收。

同一 `zxs` 的低权子角色先于正常入口分派，只用私有 `argv[0]` 精确角色标记、不得有附加参数。标记不是许可；缺原受信约束就拒绝，不回退到另一个入口，也不接受环境、配置或 FD 参数来启动。正常入口只按同一[原站点契约](launch/site/CONTRACT.md)选择与启动。实际 Core 原 S 读锁和密验、同次运行新 GUID 都准备好，并安装／解屏蔽 SIGTERM 后，只向前述原 [SEQPACKET](https://man7.org/linux/man-pages/man7/unix.7.html) 写一次精确 80 B PREPARED、关闭写半边。只在原父核两边都已预备并封印共同门、本人仍核现行门与父存活后才 accept 或启动冷写任务。PREPARED 或监听已存在都不表示消费过真实客户端。主线程用实际原父 pidfd 和原监听轮询，最多 8 条连接；不足席才非阻塞 accept，不另 bind 或改到父方原 OFD。只把原始未读的新连接和相同 `InheritedRun` 交到其线程；另在同线程重开／核准原 S 的 Reader，不能搬已登录连接、SQLite 或权限票。首字节前从这一原 socket 检验**该输入监听自己的**本地地址和客户网段，不用其他监听的前缀。收到 TERM 或实际父端失效即停止接收，各原连接排空／释放后再丢父 pidfd 和原 S 主读锁，不隐含保存或删除。固定字节源例不创建监听或重放受托启动，本清理未运行启动或客户端，不声明已安装服务。

## 每条直连 TCP/445 的 MessageId 和 credits

`connection` 从原始 3.1.1 NEGOTIATE 请求建立一次性起点：这时只允许 MessageId 0。保留真实客户端 GUID、安全模式、capabilities 及**完整原序的 dialect 数组**，而非仅记录是否见过 3.1.1。根据[协商处理](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/b39f253e-4963-40df-8dff-2f9040ebbeb1)，TCP/445 上 3.1.1 必须支持多额度，服务器成功回复须含 LARGE_MTU；客户端初始请求即使要 0 也至少回 1。仅已序列化且匹配本次请求、SHA-512 transcript、应发额度、实际读／写／事务大小的回复才能绑定；原发送者提交了这份字节后，才产生仅限原连接的可用窗口。已协商的连接不能再次走 NEGOTIATE。现在由同一个 Opening 生成下节所述的实际成功消息，由受托入口原流完整写出后才登记；没有启动传输服务。

- [服务端窗口](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/dec8e905-9477-4c3f-bc64-b18d97c9f905)和[序号验证](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/0326f784-0baf-45fd-9687-626859ef5a9b)：额度对应已实际发出的、单调新发的编号。可乱序接收，不能重用、跨空洞，或在 u64 末端回绕。每成员从自身 MessageId 消耗至少一格，正多额度需整个连续区间仍可用；关联成员不继承 MessageId。整批只能在同一**事前已发**窗口上扣减；任何范围无效即关本连接，不逐项执行后再发现越界。本地最多 64 格跨度，且可用额度加未完成普通请求不超过 64；不能靠不断填高编号扩张内存。这是额度记录，不替代原连接的 RequestList、会话签名或业务权。同步票已把不可换包的原字节与该项账务合在一起。将来的 RequestList 仍须按 §3.3.5.2 给每个非 CANCEL 成员登记原请求，并与后续验签、派发和在途取消绑定；不能拿账务结果另配 SESSION_SETUP 或业务帧。 本端只公布可兑现的 MaxWriteSize，不超过约束整个入站 SMB 消息的 MaxTransactSize；这是本地入站边界的约定，不要求三种协议上限相等。MaxReadSize 的数据方向相反。
- [载荷校验](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/fba3123b-f566-4d8f-9715-0f529e856d25)独立于序号：零计费不表示零消费，最多覆盖 64 KiB；正计费按每格 65,536 字节。READ、WRITE、QUERY_DIRECTORY、CHANGE_NOTIFY、QUERY_INFO、SET_INFO、IOCTL 用原始声明值。查询信息按入／出最大值，IOCTL 两边分别在 u64 相加后再比较。错误或截断不能变成少计费的成功。已花合法编号但载荷不足是成员参数错误，不归还旧编号、不伪称已操作文件；前序认证、树／原 OPEN 失败仍按对应命令的规范顺序处理。
- 唯一有固定否定答复的 IOCTL 是[查询网络接口](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/21176e9a-ec3e-4d54-adde-bed5c13f64b8)。只认原强签独立消息、无实际输入；兼收零长度尾和 [Linux v6.12 的单个零尾字节](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2pdu.c#L3109-L3156)。本服务不公布多通道，真正同一原树、两半全一的无柄标识及额度/事务上限核验后，只回强签的 `STATUS_NOT_SUPPORTED`。同一控制码的非 FSCTL 标志、错误 FileId、额度/上限和缺原树按本项协议错误拒绝，不解释成 OPEN，不转发通用 IOCTL，没有任何数据或接口。发送前后仍核实际树答复的原站点和会话，同原流完整写出后才公布额度。此项不是 Linux 登录/挂载验收。
- [CANCEL](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/57bae3d3-5dd7-4a5f-92cb-fc52e2087dad)在账务层只豁免序号消费：同步／异步形式不占新格、不产生本命令应答、不赠额度。真实候选的独立收包入口要求[四字节请求体](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/91913fc6-4ec9-4a83-961b-370070067e63)、原同连接已验证的会话和原字节 CMAC。保留字段不用于决策但仍在签名内。只有当前同步所有者确实没有任何未应答普通项时，才可无目标原样继续；不进入业务、不开异步、不以 MID/AsyncId 单独取消。缺签、错签、不同原连接／过期会话或复合形状仍在该入口拒绝，不生成拒绝应答，也不处理复合前件。`src/test/smb/accepted_turn.rs` 写有同原流后续强签 ECHO、窗口未变、坏包及仍有原未应答票的源码夹具，未运行。
- [授额](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/2e366edb-b006-47e7-aa94-ef6f71043ced)与[同步复合回复](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/dde8b59f-52ca-4cf8-8253-211bc43639cf)按成员对账。候选额度尚不可花；服务端先对最终不可变回复整链核同一次批次的原 MID／command／CreditResponse，待原传输确认成功提交才一次公布。跨连接的批次、重复公布、丢失普通应答、传输结果不明、编号耗尽都不能恢复旧额度。当没有剩余额度时，服务器须补至少一格或关闭耗尽的连接，不能留下无法继续的伪活动连接。此出口不允许异步 interim/final 冒充同步回复；未来异步只允许在 interim 发一次额度。该模块只核信用，不把正确签名、可用状态或授权视作已成立。

`src/test/smb/credits.rs` 保留初包、乱序、多额度、关联／非关联、CANCEL、原载荷边界、同步回包对账和整数末端的源级例子。未运行客户端或测试，也未对生产端口发包。

## 原生 NEGOTIATE 成功应答（不含认证成功）

对一条合法的全新 Direct TCP 请求，`connection/negotiate` 从原 Opening、应授额度和同一次服务运行的 GUID 出发，使用已有的 Linux `getrandom(0)` 封装单独取 32 字节公开盐，并按 [FILETIME](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-dtyp/2c57429b-fdd4-488f-b5fc-9e4cf020fcdf) 记录服务端当前 UTC 时间；不给空标识、随机失败或越界时钟造替代值。`wire/negotiate_reply` 写[同步成功头](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d39a64be-b8f8-424d-b8e5-a2cf5257459e)与[完整协商正文](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/63abf97c-0d09-47e2-88d6-6bfa552949a5)：只选 0x0311／SHA‑512，安全模式是启用且必须签名；只公布 LARGE_MTU，读／写／事务三项目前均为 64 KiB。上下文相对 SMB2 头 8 字节对齐；不宣告加密、租约、多通道、持久句柄、压缩、RDMA 或通知。客户端的 cipher 清单只是 offer，不是“强制加密”开关；要求数据加密的客户端／共享不得作为已加密使用，更不能静默退回传明文。

没有 Signing Capabilities 时仍强制 AES‑128‑CMAC，但不加签名协商 context；有共同 CMAC 时只回该项。合法非空清单与本端没有共同算法时，[服务器规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/b39f253e-4963-40df-8dff-2f9040ebbeb1)仍要求回选 CMAC，而[客户端规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/3b29f3af-86f9-4962-8cf3-43471cb59363)要求拒绝未提议的算法。原回复可形成，提交后本端也不给这一路可用连接或 SESSION_SETUP 起点。没有 3.1.1、没有共同预认证哈希、畸形 Signing 清单分别拒绝；普通错误回复和真正的 RequestList 仍未实现。成功包只由原流所有者提交；credits 和 SHA‑512 复核的就是交给传输者的同一份不可变字节。

[服务器初始化](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/04e0383e-e2b4-49c2-803f-1313d9c0b2ff)要求新生成 ServerGuid；[Windows 的启动行为 <26>](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/a64e55aa-1152-48e4-8206-edd96444e7f7)也是每次启动换一个。它对同一运行实例的所有连接稳定，按 [MS-DTYP 的 GUID 字节序](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-dtyp/001eec5a-7f8b-4293-9e21-ca349392db40)写入，不是永久安装 ID、池 ID 或客户端身份。不透明 `RunningServerGuid` 由同一真实受托启动建立，不是持久配置或 per-connection 自动生成。绝不能用测试 GUID 启动服务或复用旧权限。

选择标准允许的**空 GSS 安全缓冲区**（起点 128，长度零），由客户端发起认证；不编造 Kerberos、NTLM 或 GSS 服务器广告，不从空缓冲区放行匿名。原生源码方面，[Linux v6.12](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2pdu.c#L1237-L1268)在空缓冲区启用 raw NTLMSSP 选择，[Apple SMBClient](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/netsmb/smb_smb_2.c#L6891-L6951)可继续解析协商 context；均不能代替后续严格 MIC 或三端挂载验收。 `src/test/smb/negotiate_reply.rs` 保留默认／显式两套完整应答及下一条原请求哈希固定值、无共同签名、未知能力、时钟边界和本地失败源码例；没有运行构建、测试或客户端。

## SHA-512 原字节记录（已用于严格认证，未接生产监听）

`wire/preauth` 从已解析的单条 3.1.1 NEGOTIATE 出发，连接只保留请求和实际序列化回复的链式哈希。每个新的 SESSION_SETUP 尝试从该连接值单独起步；接收完整原请求，并且仅在同一 MessageId、同一已分配 SessionId 的 MORE_PROCESSING_REQUIRED 回复时继续。固定的 Rust SHA-512 实现见[上游来源及许可](../../vendor/rust/README.md)。TCP 长度头不入哈希，原 SMB2 消息头、正文、间隙/填充均入哈希。最后成功的 SESSION_SETUP 回复将使用由最后一个请求哈希派生的密钥签名，因此它不会再次进入这份 KDF 上下文。该值不是口令证明、签名或有权访问文件的会话。预认证层本身不运行 GSS/KDF，不编码应答，不查询凭据或启动生产监听。依据：[协商处理](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/b39f253e-4963-40df-8dff-2f9040ebbeb1)、[新会话](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/ea10b7ae-b053-4e4c-ab31-a48f7d0a79af)、[GSS 处理](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/5ed93f06-a1d2-4837-8954-fa8b833c2654)。

## 原连接的 SESSION_SETUP 第一阶段（不签发身份）

`Connection::receive` 先审完本帧全部成员的额度，将**这同一个已解析的不可变帧、其额度账单、原连接的 SHA‑512 基准和终止标记**一起交付。同步处理借用原接收缓冲，不复制每个大报文，也不让业务方拿另一帧搭配已花的 MessageId、签名或 transcript。连接对象释放会使尚在手中的票失效；放弃该原连接尚欠的普通回复也只终止它自己。未来真正异步保留完整独占或共享只读缓冲和有界范围，不能将同步借用延长到失效之后。

`Received::start_setup` 只能消费一次：没有 SETUP 的帧原样保留给别的处理器；含 SETUP 的复合帧在本配置整批拒绝，不顺带执行后面的文件命令。单条且头内 SessionId 为零的合法开局，从票内原 transcript 和同一 security field 得到“先选择 SPNEGO 机制”或“已有 Type 1，待真实挑战”；令牌不合法时仍保留该帧的已消费额度供今后准确失败回复，不能混成匿名或倒回 raw。非零 SID 只表示待真实注册表判定，不是重连或身份。通用额度回复入口明确不接受任何 SETUP；第一阶段分类自身不签发 SID，不创建挑战或发送成功回复。下节的专用机制选择所有者才可接着准备自己的 MORE。

### 正在协商的 SID 和第一个 request-mic MORE

每次服务初始化对应唯一不透明运行对象，包含 GUID 和所有连接共用的 in-progress 索引；知道相同的 GUID 字节不能重建这个对象。根据[新会话及双表规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/ea10b7ae-b053-4e4c-ab31-a48f7d0a79af)，在真正的 `Select` 编码 MORE 时，全服务登记从未使用的非零、非全 1 SID，原连接登记自己的阶段；连接之间不重复发号，号码不是认证凭证。全运行最多 64 个、每连接最多 8 个会话槽（进行中或已确认）；初始握手有效期 30 秒（单调时钟），并不作为已确认会话的有效期；过期、撤销和错误不能使编号复用。全局表只弱引用阶段注册；连接私有表才持有令牌状态。狭小的索引锁不跨 GSS、哈希或发送。

首包需要选机制时，发出的[SESSION_SETUP 正文](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/0324190f-a31b-4666-9fa9-5c624273a694)是真正的 STATUS_MORE_PROCESSING_REQUIRED，加[SPNEGO request-mic](https://www.rfc-editor.org/rfc/rfc4178#section-4.2.2)和唯一选中的 NTLM OID，不捏造 Type 2、用户名、guest 或成功。保留原 MID、charge 和阶段专属应回额度。用同份最终字节同时核原 transcript／GSS 和额度。只有原发送者确认这份不可变包已成功提交，才把原连接该槽从“待发送”改为“等 Type 1”并公布信用；未提交、结果不明或临界时过期则关闭本连接，不留下可续阶段。

下一条非零 SID 请求须已在**同一原连接**消费自己的新 MID，再从双方索引找到同一未超时对象、恰处于等 Type 1。仅一次移出该阶段，按同一 transcript 校验原 token；坏 token 只移除这个槽，无权触碰别的会话。跨连接借来的同号码不能接管或取消。不在表的 SID 或过期不会创建新会话。单独的机制选择只推进到有效 Type 1；下节的 Type 2 仅由持有原连接和受保护凭据代的代码签发，仍无成功会话或原生监听。生产错误回复、主动定时唤醒和其他 [GSS 完成／清理](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/5ed93f06-a1d2-4837-8954-fa8b833c2654)仍属后续；每次查找与增发都在原处检查期限，不能用被动清理延长权限。

### 本次机制挑战的生成（不签发会话）

严格机制只从原 Type 1 选已经支持的标志。按 [MS-NLMP 服务器处理](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/81d15e3e-3ac3-41f0-920d-846149f3a814)、[Type 2 格式](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/801a4681-8809-4be9-ab0d-61dcfe762786)与[协商标志](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/99d90ff4-957f-4c8a-80e4-5bfe5a9a9832)，独立服务器返回本机的 NetBIOS TargetName、受信的名称 AV、UTC FILETIME 和内核新取的 8 字节一次性挑战；不反射客户端名字、不冒充域控制器、不把 NTLM SEAL 当作 SMB 加密。原 standalone Type 2、第一次 SPNEGO 的 request-mic/NTLM OID/Type 2、已有选择后的仅 accept-incomplete/Type 2 分开编码。MORE 不同于认证成功。基础库仅接受归属本服务的一份受保护凭据代，与已签发的确切挑战、原 GSS 包和原绝对截止绑定；凭据替换后相同数字、名字或 SID 不能代替同一原对象。没有生产凭据构造、收集器、导入用户密码或认证回退。源码夹具有独立固定的完整 Type 2、短/长 DER 边界、错封装、拒绝和撤代例，无实跑。

连接现在能把这份机制挑战变成真实 SMB2 MORE，但没有启用任何服务。直接 Type 1/首个乐观 token 在本连接预留新 SID；经上一次 request-mic 得到的 Type 1 只消费当时那同一项，不延期、不另发 SID。只从本次运行持有的受保护提供者取凭据代和 Type 2，不接收单独传入的密钥、提供者或 SID。原接收票决定 MID、额度和不可换包的回复；只有提交原字节、同一代未撤销且原截止没到，状态才从 SendingChallenge 进入 WaitingAuth。未配提供者没有挑战，放弃或不确定发送终止原连接。挑战发送阶段本身不消费 Type 3、不回成功、不授 Tree；全局注册只限制有效弱项，部署时仍需终结静默到期连接。

原连接收到末次 Type 3 时，先把原 WaitingAuth 从只有一次所有权的槽中取走，再检查本包、原凭据代、完整 NTLMv2/MIC 和原截止；计算期间不持凭据或全局 SID 锁。失效／校验失败只清退该槽。成功只得到绑定原已付请求与原 Claim 的私有证明，不能从数字或用户名重建，也还不是能发包的成功会话。重复 token 即使另用合法 MID 也不能重复消费同一挑战。

## SESSION_SETUP 的机制封装（止于未验证的 Type 3）

`session/envelope` 只处理一次新的连接型 NTLMv2 尝试。它取原请求或已序列化 MORE 回复的同一个 security buffer 和预认证状态，不收另传的 token。第一次选定 RFC 4178 的 GSS-SPNEGO 或直接 NTLMSSP 后不得换层；不扫描尾部、不从坏 DER 回退、不把客户端的账户名、目标、MIC 标志或非零 SessionId 当证明。[Linux v6.12 的原生 SMB 客户端](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2pdu.c#L1708-L1846) 确有直接传两段 NTLMSSP 的代码，两种封装最终必须满足同一账户、挑战及签名要求。本段不接收 SMB1、NTLMv1 或匿名。

[初始 GSS 封装](https://www.rfc-editor.org/rfc/rfc2743#section-3.1) 只在客户端首条使用；[RFC 4178 §§4–6](https://www.rfc-editor.org/rfc/rfc4178#section-4.2) 的后续 NegTokenResp 不重复包装。保存客户端机制顺序及原 DER SEQUENCE（不含显式 [0]）给独立的 mechListMIC 校验。若 NTLM 不在首位，不使用其他机制的乐观 token 或早期 MIC，必先用实际 MORE 选择 NTLM 并请求名单 MIC；此后收到新的 Type 1 才接收 Type 2。优先 NTLM 无乐观 token 时也要先走机制选择。后续客户端不能再选机制，未知 DER 扩展有界跳过但不授予能力；即使客户端首条带有 Init2 的 NegHints，也只忽略其有界 SEQUENCE，不从提示名推出目标或身份。首答已 request-mic 而末条没有相应 MIC，按 §5(c)(V) 终止；即使形状和长度都正确也须实际核验，不能由“有字段”推出认证。

[MS-NLMP 三种报文与字段](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/033d32cc-88f9-4483-9bf2-b273055038ce) 的有界视图保留原始 Type 1/2/3、目标信息及客户端声明；启用字段不超出本条、不别名固定头或其它有效字段，不解释按标志应忽略的描述符。[MS-SPNG 微软产品说明 <8>](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-spng/211417c4-11ef-46c0-a8fb-f178a51c2088) 区分最优先 NTLM 且带 NTLM MIC 的保护与原生直接 token 行为；本版对已选 SPNEGO 的这类输入也要求名单 MIC，不能切到直接封装来逃避。未宣告 Negotiate Late Fallback，不在半途重选。没有 GSS 分片重组、Kerberos、原生客户端验收或跨连接恢复；若后续改用服务端先行 GSS，需单审机制广告／NegHints 与出站封装；当前协商明确选择客户发起，不靠假广告。

该封装层产物只是 `Unverified`，不会生成挑战、校验口令、导出密钥、创建 `VerifiedExchange`、授予 Tree 或发送成功。真正的接受端还须拥有安全随机的一次性限时挑战与原连接/凭据代，校验原协商标志、目标/时间、NTLMv2 证明、所需 NTLM MIC 和双向 mechListMIC，并复核当前业务身份，再把该次最后请求的 transcript 和导出键一起交给签名器。不能只相信客户端的 MIC 指示位。该封装层的形状夹具不是有效口令证明。

## 严格 NTLMv2 机制证明（开发资料，未启用）

`session/strict_verifier` 消费同一次握手的原 Type 1、服务器实际序列化并逐字核对的 Type 2、最后一个 SMB 请求与其 Type 3。受保护的材料是针对**一个确切账户、域和代次**的预派生 ResponseKeyNT，等同该身份的秘密，不是 Web 哈希，不从网络接收；没有生产账户提供者、密码输入／读取、账户库或网络发包函数；仅在受保护的实际凭据代存在时，内部挑战器才取新的系统熵。候选挑战只能消耗一次，包括出错；核对原 SID／MORE 的原 MID 和有限期，把最终请求的原 SMB transcript 随证明保留。连接 owner 已把不可预测挑战、限额／防重复 MessageId、独占取出和原凭据代／实例终验连在同一请求上；缺真实凭据来源或尚未完成最终提交都不产生可用身份。

按 [MS-NLMP 用户名规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/f9e6fbc4-a953-4f24-b229-ccdcc213b9ec)，登录名比较只接受本地唯一已规范的 ASCII 账户，ASCII 字母大小写等价。原 Type 3 字节仍完整参与 MIC；不重新派生 ResponseKeyNT、不试另一个域或空域，同域、SPN、NTLM 内层 MIC、应有的名单 MIC 及 SMB 强签规则保持不变。这是认证账户名，不改变 ZXS 文件／目录的大小写语义。

### 末次回复的密钥、签名与原连接发布

只有严格证明仍对应原凭据代，才能用该证明的原末请求头和机制实际输出组装最终回复。根据 [MS-SMB2 §3.3.5.5.3 第 6 至 12 步](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/5ed93f06-a1d2-4837-8954-fa8b833c2654)，从同一次 NTLM ExportedSessionKey 和截至末请求的 SHA-512 分开派生 SMBSigningKey 与 SMBAppKey，各自的标签含终止 NUL；最终回复不再进入 KDF。单通道引用同一签名密钥，保留私有会话密钥和应用密钥，不导出给存储或 RPC。服务器按原请求的 MID、SID、charge、Reserved、优先级和应回额度，对零 guest/null/encrypt 标志、真实 GSS token（直接 NTLM 为零长，SPNEGO 有独立服务端名单 MIC）及整份原消息做 AES-CMAC 后设置 SIGNED。两条签名／分离密钥固定向量从同一原连接机制证明确认，不是实机结果。机制内封存的消息本身不授会话。只有持同一原 Claim 的连接能按下述顺序处理，文件授权不在这一步。

同一次服务运行另对最多 128 个协商成功的连接登记弱引用，按实收 ClientGuid 和实际选中的 dialect 建有界客户端表。在真实 GSS 末轮检索／插入方言；不一致不能接收成功，也不影响同 GUID 的其他会话。根据[连接丢失规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/eb5bfe99-47fe-4e87-8e87-08a084dcefb6)，只有该 GUID 的最后一条已协商连接消失，才在整理登记时允许清掉客户端项；GUID 不是主体。原 ProofTaken 项只归该收到的请求。最终签名包仍要核原本应回的额度，交给原发送者之前复核凭据和原期限；仅当**原发送者已完整提交同一不可变消息**，在同一注册／凭据代的短临界区内以该 Claim 转为 Valid，再结清原额度。提交不明、过期、断连或撤代不产生可用状态。密钥和主体只留在所属连接，本运行全局只留可撤销的弱标记；没有开放后台构造器、密钥 getter、生产监听或生产凭据读取。普通消息已能从这个 Valid 会话核签并短借原成员，树／打开表和实际命令派发仍未接线；不支持重新认证或绑定，不会借它刷新原有效会话。部署时真实传输必须按提交合同处理部分写／断开，并主动回收静默连接。

## 认证后的明文消息签名（已接原流 ECHO，未接通用派发与存储）

`session/` 实现[规范 KDF](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/da4e579e-02ce-4e27-bbce-3fc816a3ff92) 的一个 HMAC-SHA-256 计数块，从同一新 NTLM 会话的 16 字节导出键和最后一个请求的 64 字节 transcript 派生 128 位签名键。标签含结尾 NUL，KDF 自己的分隔零字节另算。此段 KDF 的独立源例只含公开合成材料，并非实际登录；真正的账户及密验只从上文已受托的原 vault 和 ACTIVE 获得。只有完成挑战、主体、MIC 和当前代检查的原尝试才能交出这一对，不能从报文、Web 身份或布尔值制造会话。密钥缓冲使用 zeroize；不承诺清除所有栈临时副本。没有使用宿主加密服务。

[协商](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/b39f253e-4963-40df-8dff-2f9040ebbeb1)没有 Signing Capabilities context 时仍强制 CMAC；显式 CMAC 或合法非空但无共同算法时应答须回且只回 CMAC。计数为零、被截断或串错请求/回复不能作“无签名”处理。最终回复的签名函数只接收与最终请求同 MessageId、同已分配 SessionId 的实际未签成功响应；拒绝 guest/null/encrypt 标记。它给该响应签名，不把成功响应再加入 KDF。普通明文请求只有签名位和全部 16 字节 [AES-CMAC 校验](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/5b570c0b-0854-4324-8fb5-d410692dde3e)均成立才通过签名检查。每段用原 SMB 消息和自己的尾填充，只有 Signature 16 字节置零；关联链继承的实际 SessionId 只用来选键，不改变验签字节。不相关链可涉及多个有效会话。入站先从已实际发出的窗口扣原整帧额度，随后整批签完才给出一次一个的会话成员短借；没有这里发出的成功应答或文件授权。普通回复头的生成/签名、CANCEL 和加密 transform 不由此入站函数处理。

`src/test/smb/signing.rs` 保留两种协商下首个 TREE_CONNECT 的独立固定值、无签/错签拒绝，以及同链/异会话 compound 的原字节向量。测试只使用公开合成值，没有执行，不是实际登录或互通。原生三端验收仍须分开“无缓存端点的首次访问”和“同一身份重连”；记录 Windows 冷访问有无 multi-protocol opener，旧服务缓存的热路径不是首连通过。不增加 SMB1 文件操作或降级。

### 原连接认证成员：先验整批，再逐条短借

`connection/sessions/ordinary` 只消费同一原连接的 `Received`。对原帧中所有受支持的普通成员，按[签名检查](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/85df1680-2ee7-4d25-a916-a982371ddc75)与[会话检查](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/b495e2da-8711-4772-b292-453be0394b49)找该连接已经真实发布的 Valid 项；同一批只认同一受保护凭据代，先核每段原始签名，末段不通过也不给前段票。无 Signing Capabilities 与明确选 CMAC 的两种情况都不准首个普通命令缺签。只完成 MORE、别的连接知道 SID、报文写了有效 TreeId 都不是授权。[TREE_CONNECT 的专门规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/652e0c14-5014-4470-999d-b174d7b2da87)优先于通用签名拒绝：在这个仅明文 3.1.1、非匿名/非 guest 实现上，缺签名且确属本连接已发布会话的 TREE_CONNECT 须断开本连接，不能回普通拒绝继续使用。关联成员按已核前件的会话归属，不采信其报文内另一个 SID；未知或别连接的标识不撤销他方登记。已发布的项不再强持 NTLM 密验材料，保有的是该会话自身密钥及可失效的原代弱标记。

整批通过后仅能按顺序短借同一原消息和原会话，并在发给业务前逐项重核原登记、连接和凭据代。接线方在实际使用／提交时仍须终验，不能长期保存布尔结果；不把全局或凭据锁带入网络／存储。合法消费编号但载荷计费不足的成员没有业务票，保留成员级参数错误；后续不相关成员仍独立，相关链保留前件失败而不虚构 Tree／Open 或统一错误码。[相关链执行](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/46dd4182-62d3-4e30-9fe5-e2ec124edca1)必须用紧邻命令的真实处理结果；验签使用的继承 SID 不发共享权限、Root/FILE 权限或 MaximalAccess。此通用门本身不答复、不执行文件操作或 CANCEL；下面只有真正已签 ECHO 已接同步出口。遗弃未结的应答账会关闭原连接。`src/test/smb/ordinary.rs` 的公开合成源例从同一次协商、挑战和签名末包进入此门，没有执行测试或实机。

### 第一条同步普通应答：已认证 ECHO

只给尚未消费、整批均为已认证 ECHO 的原 `CheckedBatch`。每个实际短借按[处理规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/fa23e613-2768-49e5-aa68-97c4bba72379)核所在连接及原会话，[请求](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d939504d-57e2-4c0e-8ad5-1678b6fccca1)的 Reserved 不当成拒绝条件；合法返回[4 字节成功体](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/2abe9b3c-c5ab-417f-bcc3-9ab51f2fce35)，尺寸不符返回固定参数错误。没有传入任意 NTSTATUS／裸正文的成功捷径。相关链只延用上一个实际 ECHO 已核的会话，不授 Tree/Open；不相关的两项可以各自用不同真实会话。无会话、无签 ECHO 的连接级路径不在本片，不能据此判断三端可挂载。

按[成功头](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d39a64be-b8f8-424d-b8e5-a2cf5257459e)、[同步复合](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/dde8b59f-52ca-4cf8-8253-211bc43639cf)与[出站签名](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/a3e9ea1e-53c8-4cff-94bd-d98fb20417c0)逐项保留原 MID／优先级／Reserved／charge，填真实授额、有效 SID 和零树标识，每个成员用各自通道 CMAC 覆盖整个应答段，包含中间和末段零填充。只保留一份带 Direct TCP 前缀的不可变记录：原连接私有写端限时完整写入，部分写继续、被中断重试，错误／零写／撤代／去向不明均关闭原连接；仅整条写入本地 TCP 发送端且复核原登记后结清额度，不等同对端已经收到。无外部可注入的生产 writer，也没有 `submitted=true` 替代。下述受托入口从 NEGOTIATE 前持有原收发流；没有生产 accept/监听或账号来源。`src/test/smb/echo.rs` 保存默认／显式 CMAC、错误、相关尾填充、两会话及短写失败的合成固定答案，未运行。

原同步发送只有原连接内部可获得 `FullyWrittenSync`：它随原签名整帧、原请求账和原流一起，经末字节后的原会话复核才成立；本地写完不是账户/对象权限，也不是已发额度。最后复核才结该帧账，若原代失效或丢掉该票，关闭原流、无新额度；没有一般的“已发送”布尔值或外部发布回调。ECHO、已批准的 TCON、只读根及普通 FILE 的读写／关闭都用该原流出口，业务状态的公布仍由各命令独立复核。

## 首个 TREE_CONNECT 入口（真实已准入的单一业务树）

[MS-SMB2 §2.2.9](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/832d2130-22e8-4afb-aafd-b30bb0901798) 的名称字段以本成员头为原点；范围不能借下一复合成员的字节。只接受有界、无 NUL 的 UTF-16LE 普通 UNC `\\服务器\ZXS`；ASCII 共享名不分大小写，盘和文件名规则不变。拒绝超限或确定非法的普通 ASCII DNS 标签；短 NetBIOS 和非 ASCII 拼写仍交实际可信别名／共享作用域核对，不改写名称、不进行 DNS。不重新解释集群重连、请求扩展、DFS 或相关后件；普通盘共享无重定向，客户端能接受重定向的提示不授能力。同一已支付、整批已验签的 `VerifiedMember` 保留在每个结果里，重核原会话代。字段非法、共享名不符、会话失效各有独立失败域，不拿一个假 `TreeId` 或默认状态代替。活的 3.1.1 非访客／匿名会话缺少应有的明文签名时，原连接按 [§3.3.5.7](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/652e0c14-5014-4470-999d-b174d7b2da87) 断连，不会有这个已验成员。

已付额度、验过整帧签名的独立普通 TREE_CONNECT 可由原 `Peer` 直接结清确定的失败。按 [§3.3.5.7](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/652e0c14-5014-4470-999d-b174d7b2da87) 区分格式错误 `STATUS_INVALID_PARAMETER` 与不可能匹配的其他共享（含 IPC$）`STATUS_BAD_NETWORK_NAME`；另有真正的本地分配失败。拒绝分支不回重定向、句柄或成功，也不冒充仍需单独处理的复合、扩展或重连。ECHO 与此明确失败共用封闭的同步签发出口；原 MID、会话、额度和不可变回复在同一连接核对，整条写完且复核后才公布额度。正确的 ZXS 请求必须走下面的真实 Core 资格，不能签出空树。

只有经实际受托启动、同批会话凭据与原对端审批的 Core 统一根，能给独立 TCON 签发 DISK `ZXS` 树。原 Session 保留实际发布的 TreeId，只有原同步全写与同一可见盘模式快照复核后公布。`TreeConnect.MaximalAccess` 来自同一真实投影的共享配置上限；不把虚拟根只读误作全共享只读。[原生 macOS 的挂载逻辑](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_vfsops.c#L1555-L1565) 也会据此及卷级只读标志决定整个挂载是否只读。共享上限不授子盘、目录或文件访问：RO 子盘不准写，回收子树只读并只容后续经业务验权的同树恢复。实际普通 FILE 写入逐操作核当前 Core 盘模式和原代；切回 RW 不复活旧写票。

## 文件 I/O 请求与原打开边界（已存在普通 FILE）

同一 ZXS 树只按被批准的首段盘名和 Core 的精确目录链选择现有普通 FILE。读打开持现有 CORE 放置记录、介质和已确认的工作视图，使用同一跨会话 SHARE 投票和原 Session.OpenTable；目录根及 FILE 的两半 ID 都只在原 OPEN 上解释。已有文件的写打开另持真 FILE EX、原放置和模式代，复用同一 Core staged 写入对象；没有另一个存储写者或 SMB 自有持久化。CREATE 的 EOF 来自原已确认视图，AllocationSize 按明确的逻辑分配单位，不报告容器物理块或假时间。不办新建／覆盖、缓存／持久打开或无真实数据的特殊 context。

独立 [READ](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/21e8b343-34e9-4fca-8d93-03dd2d3e961e) 按原 Session、真实 Tree 和同一 OPEN 的两半 ID 查找；实际 FILE_READ_DATA、原请求额度和 MaxReadSize 分别核对，不从读取长度发新权限。读打开读自己的原确认 I/O 视图；持真实单写者的同一个 OPEN 可读自己的当前暂存内容和原确认底，再核真实前后存储证据，不能借另一个只读 OPEN。原数据或真实 EOF 与自己的不可变签名回包同行，原流发送前及末次分别核该 OPEN／原树和 Core 原持有证明，随后才授额；已写出去的字节无法撤回，失败不发替代数据或额度。正常 FILE CLOSE 退同一只读持有，不因此提交版本、执行 FLUSH 或回收。介质不在／权限丢失都不是 EOF。尚不派发普通命令复合链，也不声称原生客户端可挂载。

已有普通 FILE 的独立 `QUERY_INFO(FileStandardInformation)` 按原会话／树／两半 OPEN 和原额度查找，核实际持有的 Core 放置。读者返回此 OPEN 的已确认视图；写者只用该 OPEN 健康暂存的真实 EOF 和同 CREATE 的逻辑分配大小，不借其他读者的视图，不作 FLUSH／刷新，不声称数据已持久化。写穿冻结、未解决的 SAVE／视图切换或已损坏暂存拒绝，不拿旧数凑完整结果。[Windows FileStandardInfo 调用](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex) 记录为 SMB 可用的句柄查询；该信息类不另需 `FILE_READ_ATTRIBUTES` 或读数据的授权。和 [FSA §2.1.5.12.27](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/500cb1cb-b980-4a26-b517-459eed2ddc8e) 一致：单一普通逻辑链接有真实共享表待删标记时，未删除数为 0、DeletePending 为真；无标记时为 1。这不让待删文件提前移动，不读宿主容器链接数。按 [MS-SMB2 §3.3.5.20.1](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d64e0451-64a2-425a-848e-52a7dddab7b9) 和 [MS-FSCC 固定结构](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/5afa7f66-619c-48f3-955f-68c4ece704ae)，正常输出固定 24B，空间不足给 3.1.1 空错误 context；同一 FILE 票、实际视图和待删状态保留到原 TCP 强签全写前后核对。不新增 FileAll、时间、QFid 或异步，未运行客户端。

独立 `QUERY_INFO(FileAccessInformation)`（类 8）只查询确切普通 FILE 读柄或写柄。按 [MS-FSA §2.1.5.12.1](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/a7b2378a-f75f-4324-bab0-d3512a61800c) 与 [MS-FSCC §2.4.1](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/01cf43d2-deb3-40d3-a39b-9e68693d7c90)，返回原 OPEN 已取得的完整访问位，不回显 CREATE 请求、不计算或授予最大访问权，也不以当前共享许可或暂存正文代替原柄。无额外 `FILE_READ_ATTRIBUTES` 要求；有空间时返回 4 字节小端权限位，不足时返回 `STATUS_INFO_LENGTH_MISMATCH` 及 3.1.1 空错误上下文。原已付签名请求必须给出实际会话、树和两半 OPEN；用当前原文件、物证和权限在完整强签回应前后复核同一票。这不刷新或保存稿件，也不表示该权限对应的下一条操作一定成功。不新增目录、R、复合或 FileAll 查询。

独立 `QUERY_INFO(FileAttributeTagInformation)`（类 35）支持实际普通 FILE 的读类 OPEN 或原写者、逻辑共享根和已打开的普通卷根／普通子目录。按 [MS-SMB2 §3.3.5.20.1](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d64e0451-64a2-425a-848e-52a7dddab7b9)，原 OPEN 必须已授 `FILE_READ_ATTRIBUTES`，仅有读正文、列目录或写权都不能查询。回应仍核原签名、请求额度、原会话／树／两半号，以及同一个 OPEN 的原权威：逻辑根核当前原树，普通 FILE 和目录另核当前放置、模式与实际介质。固定属性与普通 CREATE 相同：普通未命名 FILE 为 `FILE_ATTRIBUTE_ARCHIVE`，普通目录和逻辑根按 [FSA 的目录规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/7ba4e65d-356b-43ca-a867-e897e5b9392a) 为 `FILE_ATTRIBUTE_DIRECTORY`。这些逻辑对象不承载重解析点，[tag 为零](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/d295752f-ce89-4b98-8553-266d37c84f0e)；不返回宿主属性、时间或暂存正文，也不刷新、提交写稿或推进目录游标。合格查询空间足够返回固定 8B，不足返回 `STATUS_INFO_LENGTH_MISMATCH` 和 3.1.1 空错误上下文。同一 OPEN 在原连接强签全写前后复核。R、复合、重解析功能与 FileAll 仍不接。[Windows CPython 的句柄查询路径](https://github.com/python/cpython/blob/v3.13.0/Modules/posixmodule.c#L1850-L1953) 允许打开目录，并在不跟随链接的分支发起该查询；这不是完整 `stat`、客户端挂载或实测验收。

[READ](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/21e8b343-34e9-4fca-8d93-03dd2d3e961e) 和 [CLOSE](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/f2b4183a-29c2-4fc0-a5de-fe290408f68c) 从各自命令取得范围或关闭意图；普通引用携两半 SMB2_FILEID，关联引用只继承同一链紧邻前件的已证实 ID，不能以客户端填入的另一组 ID 或最近打开回退。实际入口仍须验签、验 credits 与当前连接／会话／树，再以两半与原代次匹配唯一真实 OPEN；本片没有认证发行者或第二张路由表。后端入口只接已成功绑定的 Held，不收线上的 FileId、路径或替代对象。

READ 保持原请求长度供 MaxReadSize／credits 核验，偏移与终点不得超出有符号文件范围。仅 FILE 的实际 FILE_READ_DATA 可读，不把目录的列出权或共享票当读许可；原会话、媒体／视图及输出前后的资格由真实适配复核，尚未启用字节范围锁。只在原适配确认后区分满足最低计数且非空的短读、EOF／小于 MinimumCount、权限或 I/O 错误。TCP 不接受 RDMA 描述符，不把实际无法提供的直接读冒作成功；压缩提示本身不协商能力。回复容量不足不伪装成 EOF，也不暴露不完整校验的正文。

显式 CLOSE 消耗原打开的持有权，不等于异常断连。先令该 OPEN 不可再路由并结束在途操作；`POSTQUERY_ATTRIB` 只返回原句柄可获且有权的真实属性。属性取不到不冒充有效；脏写关闭由 Core 在原写权内确认并释放底层对象，之后才退共享票。仅未进入关闭的失败保留原打开；已经消费的原写者，即使确认失败，也不复活号或底层对象。丢连接／撤权只清理，不隐式写回／FLUSH、回收或发布历史。

成功 READ／CLOSE 应答体只能消费 Held 产生的私有结果，不能用任意正文、请求计数或属性生成成功。READ 保持真实返回长度，固定体后仅借已核正文；[MS-FSA](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/aa57e052-40d4-4d9f-837d-2b0ce7c87cf4) 的零长底层成功不等于线上空成功，[MS-SMB2 §2.2.20](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/3e3d2f2c-0e2f-41ea-ad07-fbca6ffdfd90) 规定实际返回 0 字节应答 EOF，包括合法的零长度请求。EOF 或未达 MinimumCount 用 ERROR 体，不夹带部分正文；原始 Core 错误保留给真实状态映射。CLOSE 只在请求、原 OPEN 实授 FILE_READ_ATTRIBUTES 且属性确实取得时标记有效；缺属性权的正常关闭仍执行，但不查询或回送元数据。正文编码不是发送权限。此处只接已付并强签的独立 FILE 请求，复合业务未派发。

[WRITE](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/829f93f5-ed10-4f12-8347-42d235019459) 只借用本命令声明的正文，不含其他命令、预填字节或尾随填充；原请求长度供 MaxWriteSize 和 credits，TCP 不消费 RDMA 描述符。追加位置来自同一个仍获权的实际写者的当前稿 EOF，不看旧读句柄的长度，不把对 EOF 写或空写当作 SET_END_OF_FILE。仅追加的权限不改写或填出空洞，只能命中该 EOF；跨出原长需要明确追加权。普通写确认原写者已接收该范围，不承诺已经持久化。

逐请求 WRITE_THROUGH 不是 CREATE 的 FILE_WRITE_THROUGH 模式。按 3.1.1 组合规则，普通缓冲打开上只有逐请求写穿标志时返回参数错误；真正的直接写没有接，不退化成缓冲成功。[Apple 原生源码](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/netsmb/smb_smb_2.c#L10684-L10720) 有特定错误后的重试，不代表该平台已验收。原持有打开要求写穿时，实际写入后还必须等同一写者完成确认；[显式 FLUSH](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/026984f6-38af-4408-8200-50557eb0a286) 也只让实际有写权的原 FILE 写者确认；目录权限不变成卷同步。写穿确认失败冻结该原写者后续数据动作；只准以原暂存态正常显式 FLUSH／CLOSE 求确认。正常 CLOSE 开始后失败也不能复活。不冒充刷盘、成功关闭或正式提交。

WRITE 和 FLUSH 成功各有私有 Held 收据。按 [WRITE 响应](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/7b80a339-f4d3-4575-8ce2-70a06f24f133)，Count 来自原写者核实的实际接收字节数，不从请求的 Length 生成；当前业务要求整段成功，计数矛盾不给成功，也不推断回退或自动重写。合法空 WRITE 可回实际 Count=0，这与 READ 的 EOF 不同。合格的空写仍核原权限、范围及原写者状态；即使写穿也不改稿件、不确认先前 EOF。确认待决或尚未重新绑定时仍拒绝。[FLUSH 响应](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/42f78e6a-e25f-48f5-8f08-b4f1bb4c4fa4) 只在原确认完成后能生成；原 I/O 失败与确认失败分开传给真实状态映射，不能包装成成功体。正文编码自身不签发会话。原命令的封闭同步出口核 SESSION→真 TREE→两半 OPEN、权限和实际输入额度，将收据和原 MID 配对，强签精确原流，发送前后都验同一写者的状态和权限，才结本帧信用。发送失败不推断撤销已确认 SAVE，也不重跑业务。

`wire/set_info` 只从仍有效、已签名／付额度的原成员读 [FILE SET_INFO](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/ee9614c4-be54-4a3c-98f1-769a7032a0e4)，用同连接 MaxTransactSize 和完整声明长度；不借下一成员或缓冲区尾填。普通 [FileDispositionInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/12c3dd1c-14f6-4229-9d29-75fb2cb392f6) 的 mark/clear 与 CREATE 每个 OPEN 的 FILE_DELETE_ON_CLOSE 分开；后者必须明确请求 DELETE，再由真实对象授予。文件 [EndOfFile](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/75241cca-3167-472f-8058-a52d77c6bb17) 是非负绝对位置，只能交给已按 FILE_WRITE_DATA 授权的同原暂存 writer；不当作 allocation、append 或普通 WRITE 偏移。Ex、DFS 和 replay 不从本通道读取。复合的 related 成员只能用本链前件的实际 OPEN。两半 FileId、具体树／对象和当前写权仍需真实核对。独立的 EOF 请求已接原写者：必须原 FILE_WRITE_DATA（仅 APPEND_DATA 不够），仅调整其同一 Core 暂存稿，沿已存在的显式 FLUSH 或正常 CLOSE 确认，不暗中保存或发布历史。原暂存收据在强签原流完整写入前后核对，按 [SET_INFO 响应](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/c4318eb4-bdab-49b7-9352-abd7005c7f19) 仅回二字节 StructureSize；目录、过短/未付额和其他不支持的信息类不改状态或回假成功。独立普通 FILE `FileDispositionInformation` 的 2 字节成功只承认原 OPEN 上当前真实的 mark/clear。它只接受原普通读柄／写柄以及它自己的 DELETE，绝不借 R 的专用恢复权限或牵动其他 OPEN；新开遇实际待删返回 `STATUS_DELETE_PENDING`。

[Apple 定版删除](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L7943-L7967) 有 related CREATE→SET_INFO→CLOSE；[Linux 内核源码](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2inode.c#L1043-L1054) 与 [libsmbclient 定版源码](https://github.com/samba-team/samba/blob/2750ed68433690b5f72c54ae54226e89ee1b9d74/source3/libsmb/cli_smb2_fnum.c#L1155-L1169) 的普通 unlink 则有 CREATE delete-on-close。普通 FILE SET_INFO 的声明与 CREATE 的原 DELETE_ON_CLOSE 不是一回事。Apple 定版在此链用 DELETE／读属性／同步、ShareAccess=NONE，并[要求无时间 MxAc／实际 related 标记](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L6290-L6320)。这条窄链现在只在真实已存在的普通 FILE 上执行一字节 SET13 mark，再由同一链真实显式 CLOSE；不拆成独立按名操作、不弱化独占请求、不导到目录／R，也不宣称客户端实测。CREATE 失败时，两个后件没有 FileId；mark 失败时，CLOSE 不执行并继承该错，只交付真正仍开的原持有者；一旦实际 CLOSE 已开始，不管确定状态如何均退原 OPEN。结果不明只终止原流。ZXS 的回收业务仍只在原普通 FILE 的**正常最后一次 CLOSE**且原对象、共享状态和权限均成立时执行。同一个 Core 确认的 kind12 历史收据（若真的移动）保留到这条原 CLOSE 应答完整写入后的最后检查，不以重开原 F 名字冒充。CLOSE 已开始的失败不会复活原句柄；若确认结果不可判定，退出原流，不发定性的失败或自动重复移动。[协议要求掉线时关闭不保留的 OPEN](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/eb5bfe99-47fe-4e87-8e87-08a084dcefb6)，但这不把异常断连、LOGOFF、停机或 Drop 变成 ZXS DELETE/FLUSH 入口；只退场和释放，不提供新授权，也不偷偷执行回收。

## 原 OPEN 的路由与退场（已接逻辑根、普通目录和现有 FILE）

`RootOpen` 必须来自 ZXS 原 `RustRoot`、实际已付且强签的空名 `FILE_OPEN` 与同一运行共享票；不同原树、错误权限、非根路径或未有原事实的 `QFid` 不会获得这条成功。按 [CREATE 处理](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/8c61e928-9242-44ed-96a0-98d1032d0d39) 和 [应答结构](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d166aa9e-0b53-410e-b35e-3933d8131927)，持有者生成两半：Persistent 在本次运行唯一（仅弱全局索引），Volatile 在原会话唯一；单会话最多 32、单运行最多 256，未发或退役号不复用。`OpenSeat` 先预留原会话表空间与真实两半号，仍不授对象、不可路由；只有相同原表能把它和实际 Held 变成待发送 OPEN。条件出生可以先取同一席，不能在已经有业务结果后才用次数耗尽报失败。丢弃此席只退配额、不重发数字，不默认撤销实际 Core 工作。不授持久句柄或 oplock。实际返回 FILE_OPENED 和虚拟 DIRECTORY，未造实体目录时间／容量；`SYNCHRONIZE` 是本路径已支持的同步权限，和树上其他对象的权利不同。签出的不可变字节在原 TCP 全部写入，经同原 OPEN 和 Core 复核后才在原会话公布句柄并结额度，无外来确认。`CLOSE` 查真实会话内两半再核原树，真正收回该 OPEN；根无可取物理时间时返回无 postquery 属性的真实关闭。

独立相对名 CREATE 先在同一真实目录/文件权限切面由 Core 判类型。普通盘根或嵌套目录持原 F、模式代和祖先证明，与根及 FILE 共用原会话 OPEN 表和服务共享票；仅真实 File 分类可转入原常规 FILE 打开，目录介质故障不能回退。请求指定非目录却选中真实目录与指定目录却选中 FILE 分开回复。目录成功只给真实 DIRECTORY 类型和两半 OPEN 号，无伪时间或容量；显式 CLOSE 退准确对象、无需重新访问已离线 F。普通目录的枚举见下一段；不能把目录作为文件读取正文。

Apple 定版 [首次枚举的 CREATE/QUERY_DIRECTORY](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L4251-L4296) 不带 CLOSE，后续继续用其真实原句柄。其 [VDIR 打开明确带目录选项](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L8114-L8120)。此窄两段只接同一已付额、逐段强签并明确带 FILE_DIRECTORY_FILE 的 CREATE(FILE_OPEN) 与 QUERY_DIRECTORY，不误判未指定目录的有效普通打开；实际逻辑根、普通目录及 R 目录各沿同既有受保护的读取。后件只收本段前产生的真 OPEN，不按后件数字重选。实际分页数据和 proposed cursor 随同一不变原包，每段按 8 对齐并分别 CMAC（数据长度不含填充）；只在全帧完整写入和最终同原资格/OPEN/目录视图核对后应用同一查询游标并公布该原 OPEN。首件失败后件无 FileId；原查询明确失败时可退相应错误，只交付仍真实已打开的前件、不挪游标。无通用组合、缓存授权或客户端实测。

真普通可写 FILE 的独立 `FILE_CREATE`／`FILE_OPEN_IF` 先在原会话及服务两层预留同一不公开 OPEN 席，再把它连原已签名／付额 CREATE 和已选真树封成一次性入场证明。现有对象仅 `OPEN_IF` 可沿原 FILE 加写柄，不覆盖；真正空位在 Core 的原 kind5 引擎先用拟出生 FileId 取得同服务的真实共享票，再使用同一物理 FILE EX、staging、证据同步和提交，将原出生移交到可写持有者。两个确证结果分别签 `FILE_OPENED`／`FILE_CREATED`；已知占用返回 `STATUS_OBJECT_NAME_COLLISION`，但获得原共享票后遇结果不明或后续绑定失败只终止原连接，不报确定失败、也不重探名字再出生；没有额外旧协议、覆盖、QFid 假值或自动业务回退。只在原 TCP 完整写入以及复核同原 OPEN 和实际资格后公布；仍未实际启动或验收。

**应用保存范围。** 已有 FILE 可由同一写柄明确设置 EOF、写入，再由实际 FLUSH 或正常 CLOSE 确认工作稿；只有 Web 手动提交发行历史。固定 ARCHIVE 仅为协议一致投影，不授写属性／EA 权。当前不接覆盖式 CREATE 或占用名替换；不把打开后截短、私有空稿、临时名或请求邻近当原 FILE 的原子替换证据，不合并临时 FILE 与原历史。真实 WPS、Excel 与其他客户端保存仍须分别验收。

明确请求 `FILE_DIRECTORY_FILE` 时，同一 seat 与 CREATE authority 走真实 Core kind13 目录出生或已存在目录打开；只在实际普通 RW 父级、没有既有不明 pending 交易、并持相同临时 DirectoryId 共享票时才创建。新实际目录与其父、物证和写规则一起核定，既有或新建各签不同动作；OPEN 只给实际支持的目录权限。不会把目录替代 FILE、取代未完成的原作业、重做不明交易或补缺失的元数据。仅源码，未部署或实测。

普通 FILE 的独立 CREATE（包括真正的 CREATE／OPEN_IF 出生）收到 `QFid` 时，只有原授权对象已实际持有、原索引证明其唯一所有者才回逻辑卷 1 和原 64 位 FILE 号。普通读柄与原单写者都使用 Core 的 SQL 唯一编号检查，沿相同实际放置、介质和模式代前后核；不会暴露宿主 inode、池 ID 或两半 SMB2_FILEID。该 OPEN 的独立 `FileInternalInformation` 也用 [同一个值](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/9b045a20-e4e7-4747-a504-a72df2f46490)，严格八字节，短缓冲明确失败。已真实出生后失去编成或发送资格时只收原连接，不签「未创建」或再创。[Apple 有稳定 FileIDs 的新建形态](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L1522-L1528) 的上下文是此依据，不代表其 CREATE→WRITE、目录 QFid、R 编号或 CREATE 后即改名／删的复合均已实现。本次只补编号，不编时间、权限或其他探测。

已有普通 FILE 的实际读类和写类 OPEN，以及已打开的普通数据卷标签和内部目录，可独立查询 [FileNormalizedNameInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/20bcadba-808c-4880-b757-4af93e41edf6)（class 48）。真实 Core 由同一当前 FILE 放置和祖先位置得出一个开头带反斜杠的树内路径，如 `\F\Archive\Report.xlsx`；保留登记拼写的大小写和 Unicode，不回显 CREATE、宿主路径、短名或文件系统的另一对象。只对已签名付额的独立 QUERY_INFO 回应。FILE 必须从该原 OPEN 的两半取证；目录必须验证同一个当前普通目录 OPEN、登记卷和实际祖先。读柄核原选定的读视图；写柄从真写者持有的已登记卷标签、祖先和 FILE 放置取名，准备后的写柄身份、工作状态和放置代次必须一致。写穿尚未确认、原 FLUSH 待定、读基线待更新或暂存已损坏时拒绝；健康暂存不改名字，不写盘、提交或刷新工作稿。卷、模式／账号代、目录位置和实际 FILE 在原强签回复前后重新核对，不改存储或游标。依据 [MS-FSA §2.1.5.12.30](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/3d5c68f8-fbc5-4f94-a51d-3600a319fd45) 与 [SMB2 的 QUERY_INFO 返回规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d64e0451-64a2-425a-848e-52a7dddab7b9)，请求空间小于 8 字节时是 3.1.1 INFO_LENGTH_MISMATCH 及默认空错误上下文；部分容纳时仍用 QUERY_INFO 正常结构和 BUFFER_OVERFLOW，保存完整路径字节长度但只附装得下的 UTF-16 单元，不补终止符。共享虚拟根、回收区 R、复合请求和 FileAll 不由此提供；[Windows 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew) 只作这一查询类的客户端背景，不代表该路径实际验收。

普通 FILE 的独立 `SET_INFO(FileRenameInformation)` 通过同一原会话、树和 OPEN 两半查找已真实打开的非写者文件，必须有其原 DELETE、当前获准 RW 模式和实际可写介质。仍接受原父内的裸文件名。[Apple 的完整目标编码](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/netsmb/smb_smb_2.c#L9242-L9276) 与 [Linux v6.12 的目标路径](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2inode.c#L1014-L1055) 提供同父操作的实际线形依据：当完整拼写的盘标签及每级父名逐字等于已持原父时，只取末尾合规的裸名，不重新查目标父或授予权限。同父分支不能把前导分隔符加一个裸名转为本父，不通过别名、转义或另一个父名选目标，不覆盖也不接正在暂存的写者。真实 kind14 改名使用同一 FILE 和 SHARE 投票，碰撞、共享冲突与删除待定是不同的确定失败。真实确认后，保留同一 OPEN 并改绑新原放置；收到原确认且在同 TCP 的原签名回复前后复核该文件，才结本次额度。已确认后失去回复资格或结果不明不签确定失败，不按名字复开或重放。独立操作与 [Apple 实际 CREATE→SET10→CLOSE 组成](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L9541-L9586) 仅共用这条同父改名。实际普通首件只承认已有 FILE 的非写者打开、明确 DELETE 和第三件的真实关联 CLOSE，不从字面后件 FileId 得权；[首件的真实无时间 MxAc](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L6097-L6105) 适用时仍须实际回应。已确认改名后的明确正常 CLOSE 只退本链尚未公布的原 OPEN；同 FILE 短见证保持到整帧完成，后验为同一实际改名结果与原权限，不留可读 OPEN、不由此 FLUSH／删除。没有实机互通承诺。

已有普通 FILE 的跨父移动仅接原付额、逐字验证强签的独立 `SET_INFO(FileRenameInformation)`，仍先找同一原 Session、Tree 和显式两半 FileId 的非写者 DELETE OPEN。本项目按原已授权的树相对目标解析：无前导分隔符，客户端 ReplaceIfExists 必须为零，完整树相对拼写按已持有的精确 F 标签进入同一登记卷（例如 `F\Archive\moved.xlsx`）；其余父部件只在该卷按原大小写解释，不能当作宿主路径。不含 F 标签的相对段最多 4,096 UTF-8 字节与 256 个部件（含末尾文件名），之后仍过实际双父物证和几何检查。与 [MS-FSA 的目标父访问规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/87f86c9b-6c2a-4803-84b7-131a74a434fa) 一致，目标须是同卷内真实安装、当前获准接受文件的父级；光有源 DELETE、盘名或字符串不能授这个权。复用 Core kind14 的两父租用、原名与目标占位、同一实际挂载的无替换物理移动和短写事务；确认后只用原 FILE 的物证把同一 OPEN 重绑到真实目标，不重开源名、不复制正文、不产生内容历史。精确原放置和耐久回执仍在同一 TCP 全部强签写入前后核验，结果不明或已确认后失去资格只终止连接。此为 [MS-SMB2 分隔符条文](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/43cf22fe-84cb-49cf-b3e7-e3d7d766a7b7) 下明确受限的 ZXS 扩展；不接关联两父请求、跨登记卷、R、目录、别名或覆盖。[Apple](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L9541-L9586) 实际发关联三段，[Linux v6.12](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2inode.c#L409-L438) 写入 ReplaceIfExists=1，均不由这条独立路径获得支持；未运行验证。

两个登记数据文件系统之间的普通 FILE 移动暂不接 Rust。Core 的 kind12 跨盘路径需要复制并校验完整原历史，再由同一原 OPEN 采用实际目的持有；原会话的同步借用和 TCP 写时限不能代替这种在途所有权，也不能拿新开的同名文件冒作原 OPEN。

**长请求的最小所有权设计（未接线）：**

- 先限为独立命令，每个原 TCP 至多一张在途票，首个实现只预留一个服务级长操作工作席，不设等待队列。收包所有者保留原不可改字节及其唯一账务、原签名已核的 MessageId、同一实际 Session/凭据代、Tree、OPEN 身份与持有代；两半 FileId 或名字都只供查找，不替代原身份。预留不足在交出存储工作前失败。工作者只收不可伪造的精确操作许可、原始实物／位置和弱活性见证，独立从同一受托启动态打开 Core 的同一 SYSTEM，不拿连接、密钥、线程本地 SQLite 或第二个 OPEN 表。完成时只交还同一许可的确定拒绝／撤回、原耐久回执与实际目标持有，或结果不明；只有原连接所有者能重绑同一 OPEN 和发最终响应。
- 原定界 TCP 在工作期间仍须服务读取和完成通知，不能把准备或等待藏进一次同步业务回调，也不能由另一个可能长期阻塞的同步磁盘命令占住收包所有者。[CANCEL](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/57bae3d3-5dd7-4a5f-92cb-fc52e2087dad)验同原连接、活动会话及其原字节签名后，同步 MID 与收到中间响应后使用的 AsyncId 都只能指同一张仍在途的票；CANCEL 本身始终不回。同 OPEN 的冲突工作不得并行；显式 CLOSE、TREE_DISCONNECT、LOGOFF 的排空与最终回复顺序要接各原作用域后再开通，不得释放原持有后仍让工作者选盘。真实 TCP EOF（包括对端关掉发送半边）、坏定界、撤权、监督者或进程停止，只撤原工作活性、排空限额并保留必要原件；不是文件 READ 返回的 EOF，不触发普通 CLOSE、隐式 FLUSH 或删除。已进内核的磁盘 I/O 不保证在 TCP 时限内返回。
- 工作活性和唯一选择是不同的检查。kind12 的提前耐久预留不等于已移动，预留或候选可能留给原有维护。只能在 `transaction_before_commit` 已核原 SQL/物证、紧邻唯一选择 `COMMIT` 的最后钩子，用原活票作一次不阻塞交割；CANCEL/EOF/停机与该门争胜。最后钩子仍需原内核端点的零等待断连见证，不能只看上次接收轮记下的布尔值；若给工作端只读见证，它只能按持有身份做探测，不给读写、裸 FD 或重接权。撤回先胜且 Core 确认没有选更新放置时，原仍活的请求才可得到 `STATUS_CANCELLED`。门先胜后晚 CANCEL 不撤回；确认为同操作的耐久结果才可应答，无法确定或失去原流就关闭该流并保留原证，不签确定失败、不重放、不重开同名对象。数据库和工作票的锁都不跨 TCP 或大文件复制。
- 如果发送标准 [STATUS_PENDING](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/c1692ece-7c6d-45c8-a0e3-6b53c0483030)，唯一非零 AsyncId 随同一张票生灭；先占真实工作席，只有完整原中间记录才公布一次额度（[§3.3.4.1.2](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/46256e72-b361-4d73-ac7d-d47c04b32e4b)），但仍欠原终局响应。最终带同原命令、MID、会话、AsyncId，`CreditResponse=0`，同原当前资格强签、完整写后才退账。中间响应的规范签名差异须在开通前另验，不能借此放宽入站或最终签名。未接 STATUS_PENDING、真实在途取消或跨盘复制，不声称客户端支持。

已有普通子目录的独立 `SET_INFO(FileRenameInformation)` 仍用原付额、签名、Session、Tree 与两半 FileId。原 CREATE 必须明确申请且该 OPEN 实际取得 DELETE，再核它与现模式代、实际可写 F、祖先和当前目录位置。只允许该真实原父内不同于当前名的新名；完整目标拼写只能逐字确认已经持有的原父，不重新查父或赋新权。虚拟根、F 卷根、回收目录、跨父及覆盖不走该通路，原名不回本地假改名成功；客户端 ReplaceIfExists 不能变成覆盖权限。目录原 marker 的独立子孙租用使物理排他化失败，不能靠协议票忽略。共享的 kind16 完成并重绑同一原目录 OPEN 后，响应才使用 [二字节 SET_INFO 正文](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/c4318eb4-bdab-49b7-9352-abd7005c7f19)；原目录位置与操作收据在同一份强签原流写入前后复核。结果不明只终止该连接，不给确定失败或重跑业务。此片不支持目录改名复合，不代为 CLOSE、删除或重新发布新柄；未运行或客户端验收。

普通 F 卷根和已有子目录的已签 QUERY_DIRECTORY 使用同一份 Core 目录读取，不从宿主目录抄名字，也不借其它 OPEN。原持有目录的卷、祖先、当前模式代与账户同切核验；过滤按原 UTF-8 字节顺序，经共同 FILE／目录物证，仅把真实匹配记录分页。原 FILE 的 EOF、逻辑 4 KiB 分配与 SQL 64 位编号和目录的零大小、真实目录标志分别编码；无法建立唯一 64 位编号的嵌套目录按 [MS-FSCC §2.1.9](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/2d3333fe-fc98-4a6f-98a2-4bb805aff407) 用不可用值，绝不截成业务 ID 或给数字查找能力。字节/记录、名称扫描和通配计算都有预算，错误或超限不是空目录。当前不伪造点或双点条目：普通 F 根可作实际名字过滤，嵌套目录若匹配形态按 [MS-FSA §2.1.5.6.3](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/fa8194e0-53ec-413b-8315-e8fa85396fd8) 需要额外点条目则明确不支持；通配 * 和 *.* 可列实际孩子。每条完整原强签 TCP 应答前后核同一 OPEN、真实 F/模式代和 SQLite 读取版本后才推进原游标，未输出名字不消耗。SQLite 并发提交可保守撤掉尚未提交的页，但不重开其它卷／文件；无新增记录/历史或实机验收。

实际普通 F 根/子目录的独立 `QUERY_INFO(FileStandardInformation)` 走同一原付额强签 Session、Tree 与两半 FileId；发送前后复核原 OPEN 票、实际目录祖先和 SQLite 当前设置。使用 [MS-FSA §2.1.5.12.27](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/500cb1cb-b980-4a26-b517-459eed2ddc8e) 的逻辑流和有效链接语义：同一已选目录只一条逻辑链接，无可读字节流，且没有目录删除入口，因此 `AllocationSize=EndOfFile=0`、`NumberOfLinks=1`、`DeletePending=0`、`Directory=1`。不从宿主 `st_nlink` 或 `st_blocks` 推导。该类按 [MS-SMB2 §3.3.5.20.1](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d64e0451-64a2-425a-848e-52a7dddab7b9) 不额外要求 `READ_ATTRIBUTES`，也不会授权列举或读取；24 字节固定输出不足时回带 3.1.1 空 ERROR context 的长度错误。虚拟根、R、关联查询和客户端验收不在本片。

已认证的独立相对名 CREATE 只在准确匹配 Core 批准回收标签时进入回收分支。按原下层完整 DeleteOp 和准确显示文件名，持同原 R 物证、实际归属和原确认正文；物证不可用或记录不存在不回退普通 F。只授当前可证读权限，同一底层 FILE 的共享票仍用同一池与 FileId。CREATE 用实际目录／文件类型和真实文件长度；已持 FILE 的签名 READ 往返携同一范围 Used 证据和真实 EOF，不按另一个名字查找。只有已存在且明确 SHARE_DELETE 的同一读视图可在移回之后使用 Core 保留的原 R 数据。回收本身不执行普通 DELETE；显式 CLOSE 只释放原持有物（回收盘已退也可释放），绝不写入、清除或恢复。无客户端验收。

实际仍在 R 的 FILE 支持独立 `QUERY_INFO(FileStandardInformation)`。原付额、强签、Session、Tree 和两半 FileId 必须选中这一个已持有回收柄。响应前后复核原 R 物证、当前唯一 FileId／DeleteOp／放置代、实际共享票没有待删标记、完整当前已确认工作记录与原持有视图一致（两者均明确尚无首稿时才按空文件；缺件或证据不足不作零）。只有这样的在位文件才返回真实逻辑 EOF、与 CREATE 相同的 4 KiB 逻辑分配、一条非删除链接及 `DeletePending=0`；不用宿主文件大小、块数或链数。按 [MS-FSCC §2.4.47](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/5afa7f66-619c-48f3-955f-68c4ece704ae) 使用已有固定 24 字节记录；短缓冲返回 3.1.1 空 ERROR context 的长度错误，不新增读正文或写权限。即使已合法保留迁出前正文的 SHARE_DELETE 读柄，恢复后也不能再取得当前 R 名的元数据。R 根／删除目录、关联 QUERY_INFO、其他类和客户端验收不在本次范围。只有源码和未运行的 Core 夹具。

只有当前原 R FILE 的真实打开对象可以通过独立、已付且强签的 `SET_INFO(FileRenameInformation)` 请求恢复。原授权只给恢复用 DELETE，不授普通删除／写入；当前有批准 RW F 时才让实际保留文件申请，真正恢复再次核原会话、树、两半 OPEN、完整 DeleteOp／位置、原 F 当前有效 RW 设置与选定目标父级。以 [MS-SMB2 §3.3.5.21.1](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/43cf22fe-84cb-49cf-b3e7-e3d7d766a7b7) 分隔符要求为边界，此 ZXS 恢复通路使用完整目标路径重新选择同一批准树内的实际 RW 父级；它不是普通 FILE 的同一 F 内两父移动，也不向普通改名授跨卷／回收权。严格拒绝越出树、写 R 和占名（客户端即使带 ReplaceIfExists 也不覆盖，例如 [Linux 请求](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/smb2inode.c#L409-L438)）。调用一个实际 kind12 移动，FILE 身份／历史不重发；签 `StructureSize=2` 只对应原确证耐久回执，不靠回头打开 R 名字证明。原恢复结果不明或发送失败不返确定失败、不自动重做。完整发送并再核同一 OPEN、目标授权和历史回执才结额度。后续真实 CLOSE 只退原句柄。此实现仍需共同的新鲜格式及同版启动配对，不对旧 v12 缺失 backing 的快照发布或迁移；[Apple 真实 CREATE→SET_INFO→CLOSE](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L9541-L9586) 的同一付额复合也接窄路径，并处理原客户端[无时间 MxAc](https://github.com/apple-oss-distributions/SMBClient/blob/99da2d9a4bbe17cde3cee382ad3edc16e25f5535/kernel/smbfs/smbfs_smb_2.c#L6097-L6105)：从同一实际 R FILE 权限上限返回，不用共享上限，不额外授普通写；带时间或无实际证据的 QFid 不伪造。SET 成功后真正消耗原 R OPEN，只留已确认的同一 MOVE 证明核签；SET 确定失败时阻止后续 CLOSE 并按前件错误回复，完整发送后只发布原真实仍打开的受限 OPEN，供正常后续关闭。关联后件传的任何字面 ID 均不得改源。此窄通路当前是原连接的同步回合，不声称 STORE 大文件时延、通用异步取消或已通过实机。

受托 Rust 角色在真实 READY 之前通过各自线程的同原只读 S 资格检查预备三个有界收尾线程，只在这次已验启动之后放行。清退线程沿现有 kind12 已确认原单、原退休证据与当前已选目的实物工作（F 仍必须是原方案、R 是原登记角色）；旧读者、安全证明不全或离线即保留。它读原库、只做已明确承诺操作的物理收尾，不从异常会话或 CLOSE 失联产生业务动作。FILE 改名恢复只沿现有 kind14 的原待决 FILE，另在同一活动 Rust 代与已安装 F／共享中核当前 RW：可完成已实际更名的一端、撤销未动原占位或按原规则退回失权已改侧，永远不从后台首次向新名改动。目录改名恢复独立使用 Core kind16 的原待决和同父物证，核该已安装共享的真实当前 Rust 代与 RW，只确认已实际完成的同一移动、撤销未动占位或退回同一原位置，不能从空记录发起业务。各收尾线程不取用户签名密钥、不借旧安装证明、不持 SQL 等传输；跟随原可信父 pidfd、TERM 与实际 S，结束并与 peer 一并回收后才放主 S 锁。未实际构建或运行。

- 真实连接先预验完整复合请求的原字节签名及当前会话，再逐成员借出有当前主体与代次的票据。这个票据不从 UUID、裸 SID、SQL 布尔或单个签名器构造。成员、后端 Held 和应答体各自不是上线权限。由原会话和树核权限，查找及失败优先级逐命令遵循规范：READ 是 Session→Tree→OPEN，CLOSE 的标准顺序为 Session→会话内 OPEN→Tree。CLOSE 查到 OPEN 仍不能绕过核对它的原树；不能把撤权、树关闭、失效 OPEN 混成 EOF。关联成员只用本链**紧邻前项**实际已确认且仍可用的 Session／Tree／OPEN；前件没有或未取得相应范围时按 [关联请求规则](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/46dd4182-62d3-4e30-9fe5-e2ec124edca1) 失败，不能补猜独立 ID。只接独立根与普通 FILE 操作和上面的窄根卷探测；不接一般复合业务链。
- 每个原会话拥有唯一 OPEN 表，条目只持有其准确原树作用域下经 `Pending::bind` 核过的 Held。先限资源、取得实物和最终原权，再发服务器自己的两半 ID 并公开；Volatile 在会话范围唯一，即使表按树分区，查出后同时核 Persistent、原树与代次；同一会话代内不得把已退休的 ID 对重新发给另一个 OPEN，旧会话不能经同名目录重找。表不取代跨会话 ShareAccess 表或 Core 单写权。Core 原树须在其借用的实际文件／目录句柄之外存活，持有本地树再建立表，销毁时逆序；不靠不安全的自引用或新的业务存储。
- 原 OPEN 可读借用，写／FLUSH 独占借用，正常 CLOSE 先摘路由阻止新请求，再取消或排空已受理操作，取得同一原件完成一次关闭。异常断连、撤权及 scope 退场是清理，不伪造显式 CLOSE 或隐式 flush；已确认和待确认由 Core 区分。底层原件保留到在途操作、相应权限和确认处理收尾，先释放它再退共享票。签出最终响应时仍核与原请求／当前会话对应，规则没有开通前不启监听。

## 目标与分工

只协商 0x0311，直接访问一个磁盘共享 `ZXS`。只接受共同账户经真实 SMB 验证后的会话，不接受 Web 会话。共享根是虚拟目录：下挂被授权的数据盘和专用回收站，不呈现 SYSTEM、真实宿主目录或容器内部。共享名匹配与文件组件的精确大小写/原拼写是两层决定；不对所有路径做不分大小写归一化。协议实现是现有 zxs crate 的私有模块；无另一个服务端、公开 API、独立二进制，也不依赖兄弟项目。

| 边界 | 责任和不可越过的线 |
| --- | --- |
| `wire/` | 验证长度、端序、请求方向和关联/非关联链；保留原始字节。命令体、credits、签名与业务授权须分别验证。客户端名、GUID、ID 和 capability 位均不是权力。 |
| 认证/会话（后续） | 受信的实际接受端创建一次性、限时的挑战，绑定原连接、具体握手、实例、唯一账户与凭据代；完成标准机制、校验保护并重新核当前代后才授不可伪造的业务会话能力。拒绝 guest/匿名/空密码、LM/NTLMv1、错误域、Web 登录与自报布尔值。按连接、会话、树和实际 OPEN 划分生命周期及额度。 |
| 操作与存储适配（后续） | 已验证的会话/树只取得当前范围的对象能力。SMB 的 FileId 二元组仅查此会话/树的打开表，不是存储 FileId、路径或权限证明。一次跨会话协调 ShareAccess 双向关系、范围锁、删除待定；另向 Core 取得跨入口唯一的每 FILE 写权或已确认读视图，不叠加另一套业务写锁。先有界预留，再在不持全局表锁时取得物件权；两边都成功才公开句柄，失败逆序释放。 |
| 维护边界 | helper 离线开户/重置；Web/存储不取得 SMB 长期密验或会话签名密钥。SQL 只记 SMB 非秘密绑定；验证使用原站点、唯一活动代的[私有凭据](credential-record.md)，不能把格式解析当成发行权。开户、撤代和真实启动另审，绝不从 Web、测试构造器或外传票据填空。共用 crate 不表示网络解析器能打开 SYSTEM、账户库或裸磁盘。 |

真实凭据切换、受保护的发行者/存储通道、原站点启动、监听和泄露边界须各自验收；不双开同一端口、不回落旧认证，也不迁移。对不可用的存储适配返回明确失败，不创建假 handle。写穿、脏 FLUSH、正常脏 CLOSE 只有 Core 应有材料与事务确认后才可回成功；干净关闭和异常断连都不是手动提交，断连不擅自保存未确认输入。共享模式或账户代变化必须撤销对应资格。物理回收站内不是任意写入或永久删除的后门。更多业务语义由 Core 维护，不在 wire 重写。

## 实现与审查次序

1. **本地有界入站。** 每个 Direct TCP 帧上限 2 MiB；最多 32 条命令；初次 NEGOTIATE 上限 68 KiB / 64 个 contexts。读取四字节长度即可在分配前判断，不要求 TCP read 等于一条 SMB 消息。保留完整协商字节和每段包括 padding 的字节视图。边界正确不代表已验证所有命令体。重复 PREAUTH、加密、压缩、RDMA 变换和签名 context 不是合法的独立能力；未知 context 只按声明边界跳过。加密和签名算法列表在处理该可选 context 时按它自己的长度解析。当前不处理 SMB1 初始包装、加密或压缩 envelope，不提供明文降级。解析器不回成功，也不启动服务。
2. **协商保护与真实认证。** TCP/445 的 3.1.1 要有实际的 multi-credit / LARGE_MTU：每连接维护不重复且可乱序的 MessageId 序号窗口，按请求/应答大小计费，CANCEL 关联原在途请求、不是新信用。资源上限不等于所有命令只能占一个 credit。同次服务初始化的全局 ServerGuid、每个回复的新 CSPRNG 盐、准确安全模式与实际支持的 contexts 都由同次已核受托启动及成功应答模块分别把关。连接 preauth 从 64 个零字节开始，逐次 SHA-512(旧值 || 原始 SMB 消息)，不含 TCP 四字节。会话从已完成 NEGOTIATE 的 hash 分支，只加入该会话的 SETUP 往返以及最后的请求；用于签最终成功响应的派生快照**不含这条成功响应本身**。
3. **消息级保证。** SPNEGO/NTLMv2 需要真实的机制/主体选择、对应 flag 和 target-info、挑战时效、适用的 NTLM MIC 与 SPNEGO mechListMIC、导出的会话密钥。按规范的 SP800-108 和准确标签派生 SMB 密钥。AES-128-CMAC 为签名基线，未签或签名不符的需签请求不得触发业务。复合包逐段验含 padding 的签名，关联链不能从其他会话/树借句柄。标准密码原语优先选取可审的最小上游源码（例如 RustCrypto 对应原语）；记录精确版本、摘要、传递来源、许可证和改动。不得自制算法，照搬其他服务端代码，或为 NTLM 关闭宿主密码策略。不记录密验、报文令牌与会话键。
4. **先接一条真实的目录访问。** 以可信凭据发行者和 Core 统一根为前提，先闭合 `TREE_CONNECT → 根 CREATE → QUERY_DIRECTORY → CLOSE` 的强签往返：用同一个真实树及 OPEN，按权限和分页返回原对象，再释放；不造占位根或句柄，不把这一步当三端验收。随后接标准元数据、普通文件读写、改长、FLUSH、SET_INFO、LOCK、删除待定、重命名／替换、树／会话正常退场，再验实际回收恢复。已认证 ECHO 和无在途项时的独立强签 CANCEL 已走原流；CANCEL 没有本命令应答或额度，实际停止工作还须接真实的原在途请求和存储决策，不能等同于任意异步或变更通知。
5. **安全互通另审。** 如确有加密部署目标，AES-128-GCM 的协商、每方向密钥、nonce 及 transform 验证独立审查；未实现不宣告。GMAC、其他 cipher、压缩、RDMA、QUIC 不在最小配置里。
