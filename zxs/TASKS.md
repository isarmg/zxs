# ZXS 交付与验收台账

Linux 正式验收：未运行。[设计](ARCHITECTURE.md) · [SQLite SYSTEM](docs/sqlite-system.md) · [FILE 格式](docs/portable-storage.md)

**启动与 SMB。** 原站点、SYSTEM、LAN、目录模式和独立 R 由新池首设固定；Web 与 Rust SMB 的同原角色通过共同放行后，才进入各自服务。依次记录构建、双角色启动、签名客户端往返和发行。[启动](src/smb/launch/site/CONTRACT.md) · [SMB 范围](src/smb/BUSINESS.md) · [首设和重置](docs/first-account-v1.md)

**首条普通文件链。** 在已安装的父目录内创建普通子目录和 FILE，验 CREATE/OPEN_IF 取得原 FileId，再用同一 FileId 验 READ/WRITE、SET EOF、FLUSH 和脏 CLOSE。兼容读应保持已确认视图；反复保存更新同一增量，手动提交才增加正式节点。分别验第 2、3、4 轮和后续轮次。确认但丢应答时查原操作。

**共同账户与冷启。** v18 只供明确全新池，并非 v17 升级。验同一登录及密码分别通过 Web Argon2id 与原 SMB 强签握手；干扰原 vault/SQL、任一原角色预备失败、PENDING、断电中止、旧会话及两个角色主体票互换均失败关闭。换用不同的新密码后，两个入口同时拒旧、分别验新。继续验原 FILE 的已确认稿、正式历史及准确回执不受影响。以上须同一对制品通过；隔离数据库/协议向量不能代替双角色冷启和实际客户端。外部 HTTPS、准确可信 Origin 与隔离原始 HTTP 后端另验，不由 ZXS 内置 TLS。

**同树回收链（源码）。** 普通 RW FILE 设置删除标记，最后一次显式 CLOSE 后移入独立 R。按 DeleteOp 查同一 FileId、工作稿和历史，向实际 RW 普通卷的空目标 rename 还原。断开不发删除；仍有旧读租或证据不齐时保留原实物。

**本轮范围。** [同一台隔离 Linux 虚拟机](docs/web-and-smb.md#本轮正式验收)上的独立客户端登录、普通读写、回收与同树还原。另列可选互通：Windows、macOS、Linux 内核挂载和应用保存。目录整组回收/还原、目录跨父或跨卷移动、同一文件系统的独立登记路径间移动、阻塞式字节锁、额外 CREATE contexts 和覆盖式替换未接通；真实掉盘和断电未验。

**WPS 表格普通保存（可选，未运行）。** 记录操作系统、WPS 版本/构建、一次性 .xlsx 的 FileId、工作修订和历史。在同一工作簿两次普通保存可辨内容；每次独立 SMB 重开核对单元格、原 FileId、更新的工作稿和未增加的历史。最后在 Web 手动提交原 FileId，检查恰增一节点、对应最后工作修订且原历史仍在。若应用用临时文件覆盖，分别记录错误或同名换 FileId，以及当时的原件状态。

**管理 Web。** [管理 HTTP](docs/web-management.md) 固定监听 0.0.0.0:8443。直连和只接受本机受信代理回源是分开的前台选择；只接受明确的外部 origin 和同一原连接，保留严格同源与会话 CSRF。仍拒绝旧代理环境参数，不提供 TLS、证书或代理服务，未验证实际外部 HTTPS。Web 不采样或展示磁盘信息。宿主 CPU、内存、设备速率和当前挂载容量由独立 [Helper](../helper/README.md) 只读观察，ZXS 不必停机；读数不证明原卷已登记或健康。原池登记和需独占原件的维护另按各自合同。浏览器、并发及停机排空仍需按该候选分别验收。

### 接着需要交付和量测的事

1. **SQLite。** 以独立 Helper 的新池为起点，验双端冷开、原 SYSTEM SH、热 journal 和崩溃边界。
2. **首个真实往返。** 用共同账户在 Web 把同一目录从停用改成 RO 及 RW；核原 SQL 回执，再用 SMB 创建、写读和冷开。
3. **工作稿。** 多次有界写复用本轮增量；显式提交留原回执，记录工作图行数、字节、FD，并在旧读仍持有时验确认。短 SQL 事务不等待正文。
4. **归属。** 覆盖无首节点、已保存稿与后续放置的跨盘 MOVE，再验目录整批回收/还原。用原 FILE 验证器核完整材料，记录实际用户路径。
5. **容量和等待对照。** 旧单槽示例：100 GB 基底、十次 10 GB 工作写入，提交到清理期间的逻辑正文峰值约 300 GB（不重叠）或 210 GB（重复覆盖）；不含格式及文件系统开销。记录 A 的旧读者/退稿持槽时间、B 的读和新写等待。新 SQL 应允许 B 在 A 等清源时创建和保存。

6. **MOVE 容量和读遍数。** 构造大 FULL＋很小的当前稿；目标只够当前时应在切换前拒绝。空间足够时记录全部历史的核读、复制、两端暂存和保留时间。旧引擎无故障逻辑遍数：同挂载不复制正文，首 FULL 至少核读三遍；跨挂载源和目标各至少三遍，INCR 另核其贡献材料。持同一经核原句柄时，落位复核名字、身份、成员和操作标记即可；失去句柄的冷重试完整核读。旧 `custody_handoff.rs` 用例覆盖目标可读而源盘/旧读阻止清退：旁边 FILE 可读，旧单槽下新建或保存暂拒且无回执；原单收尾后重试。

**命名验收。** 真正 SMB 上验大小写两份正文及各自历史、错大小写不命中、目录只列业务名。库级夹具另核子目录、回收同名不同 FILE、迟到冲突和 R 掉线；主分支改名须保留历史创建名。

**普通 FILE 跨文件系统（Core 引擎已有，SMB 未接通）。** 源和目的为同树中独立文件系统，要求当代 SMB 主体和两端 RW。先具名重读全部历史并同步，能以原证退役旧源才切换。旧句柄保留其已确认视图，新打开读当前稿。验冷开、旧租及旧源失联、授权撤销重授、同挂载双登记不抄、晚失败后无新 FILE、无覆盖及下列丢答。

**跨文件系统丢答、目标离线（未执行）。** SMB 接通后，在批准的一次性新池记录源、目标空位、FileId、稿和历史。在同树发起移动；以独立只读证据确认原单已选唯一目标，再丢本次成功答复并隔离目标卷。新连接不得重开旧源；旧读租未释放或目标不可独立核验，保留旧源。原句柄只读其获权已确认视图。两卷恢复后重连：只在目标打开同一 FileId、稿和历史。原结果仍不明时不重放、不新建同名文件、不碰底层容器。

**通用范围读（未执行）。** 在同一历史深度和长度下，比单材料与高度碎片化的 4 KiB 范围，分别记录索引、摘要、正文逻辑量及设备读量（注明缓存、窗口、设备）。100 GiB 单材料示例：一个完整块需要 4 MiB 正文、至多 32 KiB 摘要、800 B 页目录、95 B 表头，另计版本索引。碎片按不同材料计两只 FD/件加暂开余量；分别验额度拒绝、已交前缀和 flush 失败。采用有界流式前先核相同冻结视图及错误语义。

**SMB 单写与已确认读（待现场验证）。** B 持已确认非空工作修订 1（例如 4 MiB＋1 B，比整块多 1 B）并停在最后未满块，A 持兼容读的写句柄在同一 FileId 上改旧尾、追加并确认修订 2；A 的正常读在确认前能看见自己的暂存，B 全程仍读旧字节和长度，新读才见修订 2，旧读结束只影响旧材料清退。反向先停住慢写也允许 B 打开上次已确认稿；第三个写者仍拒。对同一可写句柄分别喂普通 WRITE、写穿、脏/干净 FLUSH 以及正常脏/干净 CLOSE：必要的原数据及事务成功才返回相应确认、同单重送不多发、干净不发、flush 后写者仍占席；ShareAccess 的实际冲突仍须分别验证；本候选没有字节范围锁，不能以单写者替代。未发的断线暂存和真正提交丢响应分别处理，不据应用快捷键计版本。
