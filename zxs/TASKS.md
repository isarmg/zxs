# 交付和验收

## 非空盘转换边界

- 外部普通文件可导入已登记的数据盘，保留来源；不就地覆盖非空盘，不迁移旧池格式。

## 已写完待测试

- Helper 的整目录文件导入复用单项完整首节点和原回执；已登记空 DATA 的独立离线初始化仅建立所选目标的 owner、data 和 staging，需实际验证断点续作和不变原件。
- 首次登记多块数据盘和离线加入、移除空盘；容器固定到原盘，回收或重试时仍可按原归属查询。

- 容器操作：首次保存、分支头追加、从历史 `main` 分叉、建分支、改名和标签。
- 单文件全量传输、指定历史节点读取、断线后的原操作查询；待实测回收盘记录损坏、读取途中权限撤回时，不得把不可用误报为未找到。
- 跨文件系统移入专用回收盘和查询收尾状态。
- Helper 首设和 ZXS 前台 HTTP 启动，退出时收尾。
- Workspace 的 HTTPS HTTP/2 与部署方自行选定的入口配合。
- Linux 桌面的签出、编辑卷、准备提交和回执恢复。
- 服务重启后丢弃未发布的上传；已发布节点保留。

## 验收

在同一台隔离 Linux 环境部署服务和桌面客户端，使用真正不同的文件系统作为数据盘和专用回收盘。另用两块实际数据盘检查首次落盘和缺盘冷启动；再在服务运行中断开一块数据盘，分别核对两块盘上的已知容器读取、全局列表和回收。依次完成签出、编辑、显式全量提交、读取历史、历史分叉、标签、改名和整容器回收。验证两个不同容器能独立完成提交，以及上传中断、保存后丢回包和回收后丢回包的结果均正确。Windows 和 macOS 的 Workspace 在各自平台独立验收。
