# ZXS 验收用例

本页列出待验证路径和应记录的结果。[已经验证的内容](docs/status.md) · [顶层设计](ARCHITECTURE.md) · [SQLite SYSTEM](docs/sqlite-system.md) · [FILE 格式](docs/portable-storage.md)

**启动与 SMB。** 原站点、SYSTEM、LAN、目录模式和独立 R 由新池首设固定；Web 与 Rust SMB 的同原角色通过共同放行后，才进入各自服务。依次记录构建、双角色启动、签名客户端往返和发行。[启动](src/smb/launch/site/CONTRACT.md) · [SMB 范围](src/smb/BUSINESS.md) · [首设和重置](docs/first-account-v1.md)

**首条普通文件链。** 在已安装的父目录内创建普通子目录和 FILE，验 CREATE/OPEN_IF 取得原 FileId，再用同一 FileId 验 READ/WRITE、SET EOF、FLUSH 和脏 CLOSE。兼容读应保持已确认视图；反复保存更新同一增量，手动提交才增加正式节点。分别验第 2、3、4 轮和后续轮次。确认但丢应答时查原操作。

**共同账户与冷启。** 当前模式 19 只供明确全新池，不升级旧池。验同一登录及密码分别通过 Web Argon2id 与原 SMB 强签握手；干扰原 vault/SQL、任一原角色预备失败、PENDING、断电中止、旧会话及两个角色主体票互换均失败关闭。换用不同的新密码后，两个入口同时拒旧、分别验新。继续验原 FILE 的已确认稿、正式历史及准确回执不受影响。以上须同一对制品通过；隔离数据库/协议向量不能代替双角色冷启和实际客户端。

**同树回收链（源码）。** 普通 RW FILE 设置删除标记，最后一次显式 CLOSE 后移入独立 R。按 DeleteOp 查同一 FileId、工作稿和历史，向实际 RW 普通卷的空目标 rename 还原。断开不发删除；仍有旧读租或证据不齐时保留原实物。

**本轮范围。** [同一台隔离 Linux 虚拟机](docs/web-and-smb.md#本轮正式验收)上的独立客户端登录、普通读写、回收与同树还原。另列可选互通：Windows、macOS、Linux 内核挂载和应用保存。目录整组回收/还原、目录跨父或跨卷移动、同一文件系统的独立登记路径间移动、阻塞式字节锁、额外 CREATE contexts 和覆盖式替换未接通；真实掉盘和断电未验。

**WPS 表格普通保存（可选，未运行）。** 记录操作系统、WPS 版本/构建、一次性 .xlsx 的 FileId、工作修订和历史。在同一工作簿两次普通保存可辨内容；每次独立 SMB 重开核对单元格、原 FileId、更新的工作稿和未增加的历史。最后在 Web 手动提交原 FileId，检查恰增一节点、对应最后工作修订且原历史仍在。若应用用临时文件覆盖，分别记录错误或同名换 FileId，以及当时的原件状态。

**文件标签。** 在文件行查看、添加、移除同一标签，核大小写、UTF-8 和超过一页的标签。筛选应保留子目录，在后页找到匹配文件；改名、回收和还原后同一 FileId 保留标签，同名新文件不继承。核 RO、失效会话、同名替换和旧放置不得写；不产生节点或触及正文。

**管理 Web。** [管理 HTTP](docs/web-management.md) 固定监听 0.0.0.0:8443。从实际本机监听地址核对 HTTP Host、同源和会话 CSRF；不识别外部协议或代理。Web 不采样或展示磁盘信息。宿主 CPU、内存、设备速率和当前挂载容量由独立 [Helper](../helper/README.md) 只读观察，ZXS 不必停机；读数不证明原卷已登记或健康。原池登记和需独占原件的维护另按各自合同。浏览器、并发及停机排空仍需按该候选分别验收。

## 还需验证的存储路径

1. **SQLite。** 以独立 Helper 的新池为起点，验双端冷开、原 SYSTEM SH、热 journal 和崩溃边界。
2. **首个真实往返。** 用共同账户在 Web 把同一目录从停用改成 RO 及 RW；核原 SQL 回执，再用 SMB 创建、写读和冷开。
3. **工作稿。** 多次有界写复用本轮增量；显式提交留原回执，记录工作图行数、字节、FD，并在旧读仍持有时验确认。短 SQL 事务不等待正文。
4. **归属。** 覆盖无首节点、已保存稿与后续放置的跨盘 MOVE，再验目录整批回收/还原。用原 FILE 验证器核完整材料，记录实际用户路径。
5. **容量和等待。** 记录 A 的旧读者、退稿占用时间，及 B 的读和新写等待。验证 A 等清源时 B 仍可创建和保存。规模选择可参考[早期容量例](docs/legacy-experiments.md#容量与读遍数的旧对照)。

6. **MOVE 容量和读遍数。** 构造大 FULL＋很小的当前稿；目标只够当前时应在切换前拒绝。空间足够时记录全部历史的核读、复制、两端暂存和保留时间。对比同盘真改名与跨盘转移；另记仍有原句柄和冷重开时的核对量。

**命名验收。** 真正 SMB 上验大小写两份正文及各自历史、错大小写不命中、目录只列业务名。库级夹具另核子目录、回收同名不同 FILE、迟到冲突和 R 掉线；主分支改名须保留历史创建名。

**非目标：**目录版本库/工作树、受管备份/副本及其界面、备份提升、旧格式兼容和迁移。

**普通真实目录同父改名（源码，未运行）。** 用原签名打开且已授 DELETE 的普通 RW 子目录句柄，向同一个真实父提交无覆盖改名。保留 DirectoryId、原目录和子项的实体与 FILE 历史，不改祖先或另建目录。真实还有其他目录句柄、子项读写或在途容量时不挤掉已有工作；请求应明确遇忙。新名更长时，只做有限的实物名称/预留路径几何核验，不读正文，超界在出票前拒。现场核同柄枚举、旧/新名、大小写、冲突、子项身份、失答、晚撤权和断点续作；不包括真实目录迁移或整批回收。

**普通 FILE 同盘改名/跨父（源码）。** `a.xlsx → b.xlsx` 或 `Draft\a.xlsx → Reviewed\b.xlsx`：用具 DELETE、无正文写权的唯一普通打开，在同一获权普通卷内选未占用的目标。保留 FileId、工作修订、正式版本和回收旧读；验同柄、两父同步中断、晚撤权和真实客户端。

**普通 FILE 跨文件系统（Linux 客户端验收未运行）。** 源和目的为同树中独立文件系统，要求当代 SMB 主体和两端 RW。先具名重读全部历史并同步，能以原证退役旧源才切换。旧句柄保留其已确认视图，新打开读当前稿。验冷开、旧租及旧源失联、授权撤销重授、同挂载双登记不抄、晚失败后无新 FILE、无覆盖及下列丢答。

**跨文件系统丢答、目标离线。** 在批准的一次性新池记录源、目标空位、FileId、稿和历史。在同树发起移动，验收端预先扣住本次答复；以独立只读证据确认原单已选唯一目标，再丢答复并隔离目标卷。新连接不得重开旧源；旧读租未释放或目标不可独立核验，保留旧源。原句柄只读其获权已确认视图。两卷恢复后重连：只在目标打开同一 FileId、稿和历史。原结果仍不明时不重放、不新建同名文件、不碰底层容器。

**通用范围读（未执行）。** 在同一历史深度和长度下，比单材料与高度碎片化的 4 KiB 范围，分别记录索引、摘要、正文逻辑量及设备读量（注明缓存、窗口、设备）。100 GiB 单材料示例：一个完整块需要 4 MiB 正文、至多 32 KiB 摘要、800 B 页目录、95 B 表头，另计版本索引。碎片按不同材料计两只 FD/件加暂开余量；分别验额度拒绝、已交前缀和 flush 失败。采用有界流式前先核相同冻结视图及错误语义。

**SMB 单写与已确认读（待现场验证）。** B 持已确认非空工作修订 1（例如 4 MiB＋1 B，比整块多 1 B）并停在最后未满块，A 持兼容读的写句柄在同一 FileId 上改旧尾、追加并确认修订 2；A 的正常读在确认前能看见自己的暂存，B 全程仍读旧字节和长度，新读才见修订 2，旧读结束只影响旧材料清退。反向先停住慢写也允许 B 打开上次已确认稿；第三个写者仍拒。对同一可写句柄分别喂普通 WRITE、写穿、脏/干净 FLUSH 以及正常脏/干净 CLOSE：必要的原数据及事务成功才返回相应确认、同单重送不多发、干净不发、flush 后写者仍占席；ShareAccess 的实际冲突仍须分别验证；独立、单元素的非阻塞字节锁另验原柄锁归属、重合 READ/WRITE/改长、追加原 EOF、准确解锁和关闭退场，不能以单写者替代。未发的断线暂存和真正提交丢响应分别处理，不据应用快捷键计版本。

**原回执。** 分别验丢答重查：工作稿返回原修订，手动提交返回原节点；错误代次、输入、范围或终长拒绝。

**默认 /zxs 布局（现场未验）。** 从无关工作目录无参数启动，核单一选择、原站点和同一 ELF；旧位置、错误大小写、链接、替换或子挂载须拒。沿批准的 S 冷开，回滚日志留 S；独立核 F/R 的挂载及登记。日志只追加两类前台事件，缺失、失配或不可写时走标准错误；未装站点不建路径。现场另验日志轮转。
