# ZXS 交付与验收台账

以[顶层设计](ARCHITECTURE.md)为准。这里记录还要交付的业务和验收证据，不把源码、定向执行、实机验收、发行混为一谈。**以下均为独立源码与静态复核；没有构建、运行测试、启动服务、测量性能或做真实磁盘实验。**

**目标基线是[单一 SQLite SYSTEM](docs/sqlite-system.md)＋[普通 FILE 内容格式](docs/portable-storage.md)。** 以下先记录旧源码证据，不为旧日志继续开发功能；再列新架构必须实际联通的业务。

**SQLite 第一条 FILE 路径。** 见[普通根出生与冷开](docs/sqlite-system.md#普通根的首个-file)。已有代码把请求暂留、真实头文件与父中硬链接、同步后的 SQL 可见性、已完成回执与独立重开分开。测试仅在业务边界代入 Samba 已成功验真的事件，不是 Windows/SMB 验收。[首份工作 SAVE 与冷读](docs/sqlite-system.md#首份工作修订) 已有源码：同一 FileId 的原单、实际普通数据/块表、复核后的 SQL 确认、冷会话只读共享按名读回；丢响应、同号异字节、0 B、半份、回调撤权、新授权以新原单在同一 FILE 接替零物/有物的未确认首稿而保留旧证、坏块与同卷兄弟正常创建均有未运行的源码用例。下一步：让真正获权的 Samba 树取得普通目录/文件句柄并读取已确认正文，验收已接线的 Web 管理端，之后接连续工作修订/手动提交/自动节点。不能把首个工作结果当正式历史或 Windows 验收。

**凭据权威切换（源码分阶段，双端一致后启用）。** 以[同一原生认证](docs/smb-native-session.md)与[离线首设/重置](docs/first-account-v1.md)为准。ZXS 的 v7 SQL 已不保存 SMB 密验；监听前和 fork 后已接真实专属 tdbsam 原件的只读核查。须与 helper 的相同 DDL、原生首设/重置及宿主配置一起启用，无 v6 回退。原生密码接线有源码，已有按当前授权和真实文件卷建树的源码，尚无 Windows 登录或共享数据操作验收。

**Windows SMB 源码现状。** [专用 Samba 源码与验收](samba/README.md)：Debian 13 amd64 的 smbd 有入口/重载守卫，实际 parser 使用同一份已按宿主管理记录核过的上线配置，原生只读 SAM 域需与同一 BOUND 相同，并排除 guest。非 root 存储进程现在按独立宿主选定的原 BOUND、同池 SQL 及专用本地域核该 SMB 行；有独立的原 S 生命周期租约。已接新 SMB2 握手独立索取一次短时服务端随机挑战，密码回调只消费原先准备的这次尝试，不另签文件权限。专用 GENSEC 先用原生解码限制实际 NTLMv2 输入，拒私有密钥/详细报文调试；校验走同进程 Samba 的固定原生例程与其原签名后验，仍未实测。仅选原生 `tdbsam:/instance/accountdb/passdb.tdb`，装入/重开核实际原件和本代，不查宿主用户库、不发口令材料；来源已接原生密码成功对象和末次会话更新；每个数据 TCON 已独立选定、核实、留住该共享实际普通根，随后可经原生只读根目录 OPEN、QUERY_DIRECTORY 获取当次已确认的条目，不能打开或读普通 FILE 正文。此窄实现未用 Windows 或其他客户端运行。首稿的真实库级准备写者不阻塞兼容读，旧读句柄可跨首次确认仍读旧修订；普通文件的 Samba 原生 OPEN 判据已接写－写冲突（兼容读不占写位）；仍须连通真实获权 FILE/stat 键，验证跨进程按 (PoolId, FileId) 的句柄单写、原生共享模式/字节锁、删除/替换、旧保存基线和断线收尾；只读管理 Web 不替代。

**管理 Web。** 已编写[受保护 Unix 套接字上的管理后端](docs/web-management.md)：真实 Web 口令登录、只向已核会话展示登记与共享、登记停用共享和按原代改变 RO/RW。源码用例含独立客户端套接字、错误或 SMB 身份、跨站提交、原表重试和冷开；未经 TLS 前端/浏览器实测，非 Samba 上线证据。下一步在获准现场独立验证宿主 TLS/UID/套接字配置、请求体禁落盘、真实浏览器、排空，及后续来自真实设备的状态。

### 接着需要交付和量测的事

产品入口只有管理 Web 和文件共享 SMB。[首项与迁测](docs/web-and-smb.md)：唯一 Web 管理员登录后查看和管理共享、系统与盘状态和版本元数据；唯一 SMB 用户按每共享的只读/读写列举并打开普通文件。停用/未发布不可见、禁止匿名或来宾，两种认证不互用，不再开发多账户/逐人 ACL。Web 不收发、预览或代理普通文件内容；现存本地 argv 只是过渡验收驱动。离线工具独立承接有原件与原单证据的核验、查询及受限恢复，不承接在线日常业务。

1. **SQLite 先行。** 按[单库契约](docs/sqlite-system.md)，第一份 DDL 与原 S 目录 SH 下的实际只读连接已有源码；待独立 helper 首建、双端冷开以及真实热日志/崩溃资格。旧 GENESIS/CONFIRMED/INTENT 停开发，不双写、迁移或作备用。落地前不宣称通用池已切换。
2. 先闭合唯一双身份、管理员从停用显式设共享只读/读写，共享设置的短 SQL 事务与原回执已有未运行源码；下一步由真正 SMB 用户创建一件 FILE、写入/读回、冷开。按原池/精确共享模式/成员判断，不先等待版本、移动、回收。在线账户/共享、确切 FILE/父、分支模式和标签采用同库事务。接通正式材料、原操作和当前授权时迁出旧产品源码/argv，保持核验与原单的真实反例，不将旧全局序号权威复刻进 SQL。
3. 接通手动一稿的有界写和逐笔自动 SAVE＋物化/原回执事务；快慢文件各验，SQL 不持锁等正文。验数据库实际页面、等锁及同步，与扁图/块表/正文 I/O 分列；旧 8192 条/8 MiB 属旧实验而非新 SQL 上限。
4. 其后扩展真实同身份跨卷 MOVE 到无首节点、已确认工作稿和后续放置；把已支持的干净文件软删除/还原进一步扩展到目录整批与授权服务；完整材料核验复用原 FILE 验证器，不将新的诊断命令当作任何正常移动的替代。管理 Web、SMB 文件访问、真实客户端及下表未完成项仍须在产品内逐条交付。
5. 旧实验单槽的对照（非 SQL 指标）：两个 FILE 的容量与等待分别验：在 A 的 100 GB 基准上保留十次各 10 GB 的工作写入，提交和清理间的正文峰值约等于基准 + 全部原工作材料 + 最终贡献的变化（逻辑量示例：互不重叠约 300 GB，反复覆盖同一段约 210 GB；不含头、索引、文件系统开销）。令 A 的已准入读者持续到 INCR 已发表，计量其退稿与原 SYSTEM 槽位的占用时长；分别观察 B 的读取、新建/保存被延后以及 A 收尾后 B 的原请求。不能把这个单槽设计写成吞吐保证。此为待运行验收，不是测得数值。 新 SQL 验收反过来证明：A 等老读者/清原源时，B 的正常创建或保存不长期被 A 的未决状态挡住。

6. 旧源码逻辑遍数仅作对照，不是新 SQLite/物料组合的测量。搬移另验**巨大保留历史、极小当前正文**：使 A 的首 FULL 很大，当前 INCR 将其裁得很小；B 的可用空间只够当前、不够全部保留材料时，原单应在逻辑切换前拒绝。能容纳时按阶段分别记录对完整 FILE 的逻辑核读、实际装入私有目标的字节、源/目的暂时并存与原保留占用时长。同挂载正常流程不抄 payload，首 FULL 仍至少核读三遍：首次签决、改名前再次核原源、安装名重新核实。无中断的普通跨挂载 MOVE 在源侧至少三遍（首次核读、复制、退役前核读）；随后同一源目录改作本票私名，保持全部已核原件和排他锁，只复核实际目录、成员和各件未变，不再整读一遍源。中断并失去句柄后，须从原票重开并核读剩下各件。无中断的普通跨挂载 MOVE 在目标侧至少三遍（匿名读回、签决前已命名私目录、决定后落位前已命名私目录）。同次原子改名保留最后一次核过的原句柄，最终名上的目录、成员、各对象身份与原状态、操作标签和原私名消失仍须核实，不再扫描全部正文。丢失这些句柄的冷重试须完整核读实际目标；这项去重不改变专盘删还。有 INCR 还要验自身和其贡献内容。这些是现行源码的逻辑阶段，不是设备实际读量或实测速度。另有 `custody_handoff.rs` 的独立 FILE 源码用例：原 MOVE 的目标可读，但旧读者或源盘离线阻止原单收尾时，旁边 FILE 的已确认内容可读，新 CREATE/SAVE 暂拒且无回执；接回原盘并核完同一原单后才接受原先两笔请求。未执行。

**当前命名源码边界。** 新池普通根或已安装目录中的 FILE 从原拼写与完整 FileId 派生唯一容器，普通与回收终名一致；真普通目录保留原名字节。用本机 CLI 和原生接口对大小写两份正文/原历史、专盘同名不同 FILE、迟到撞名、受限或掉线的回收卷编写了验收用例，并未执行。子目录 FILE 整链与未来的主分支改名仍单列；改名只影响当前名，不能改写历史创建名。实际 SMB 接入须验证服务配置确实为大小写敏感、错误大写不会误中、目录列表不泄露容器后缀，不能用 CLI 代替。
