# ZXS 交付与验收台账

以[顶层设计](ARCHITECTURE.md)为准。这里记录还要交付的业务和验收证据，不把源码、定向执行、实机验收、发行混为一谈。**本私有共同账户增量未安装或正式验收。** 其它修订的定向执行、既有线上状态、真实磁盘与发布证据不转移到本候选。

**目标基线是[单一 SQLite SYSTEM](docs/sqlite-system.md)＋[普通 FILE 内容格式](docs/portable-storage.md)。** 以下先记录旧源码证据，不为旧日志继续开发功能；再列新架构必须实际联通的业务。

**只维护内置 Rust SMB 3.1.1。** 同一 `zxs` 程序内的私有角色仅服务 ZXS 的单棵 `\\服务器\ZXS` 逻辑树：同次原新池安装批准具体 LAN、普通数据盘、目录名、初始读写模式及独立回收角色，再以原 SYSTEM、受信站点与当代账号核准实际启动。没有额外 SMB 服务程序、配置后端、兼容路径或现有池迁移。逐层按实际证据记录源码、构建、同制品启动/监听、隔离客户端、原生客户端/应用及发行；两个原角色的 PREPARED 与一次共同放行不代替后几项。见 [启动边界](src/smb/launch/site/CONTRACT.md)、[业务范围](src/smb/BUSINESS.md)与[离线首设/重置](docs/first-account-v1.md)。

**首条普通文件链。** 普通子目录从真正已安装的父目录创建，目录与文件共用同父原名空间。嵌套目录里文件的原生 CREATE/OPEN_IF、同原 FileId 的 READ/WRITE、SET EOF、FLUSH 与显式脏 CLOSE 复用本次真正 SMB 句柄、原 share-mode 与当前原 SQL。未满足原协议接纳和 Core 守门不发出生；确认后丢应答不假作确定失败。兼容读选已确认图、不取写锁。每轮首次实际修改新建一份工作数据增量和对应校验/索引，同一轮继续使用原对，应用保存不发布历史。Web 选择实际文件并明确提交才冻结 Node；第2/3/4及后续轮次无需任何前轮全量。没有自动历史或强制后台全量。

**共同账户与冷启。** v18 只供明确全新池，并非 v17 升级。验同一登录及密码分别通过 Web Argon2id 与原 SMB 强签握手；干扰原 vault/SQL、任一原角色预备失败、PENDING、断电中止、旧会话及两个角色主体票互换均失败关闭。换用不同的新密码后，两个入口同时拒旧、分别验新。继续验原 FILE 的已确认稿、正式历史及准确回执不受影响。以上须同一对制品通过；隔离数据库/协议向量不能代替双角色冷启和实际客户端。外部 HTTPS、准确可信 Origin 与隔离原始 HTTP 后端另验，不由 ZXS 内置 TLS。

**同树回收链源码。** 普通 RW FILE 的原生删除标记必须到最后一次显式 CLOSE 才真实迁入独立 R；同树逻辑回收按原次 DeleteOp 找同一 FileId 和已保存版本，可读或向实际 RW F（含已安装普通子目录）的空目标 rename 还原。断开不新发删除；仅有旧读租或证据不足，不清旧实物。未运行。

**仍待。** 在互相隔离的新会话验证 Windows/macOS/Linux 的登录、挂载、读写、应用保存，以及回收与原生同树还原。目录整组回收/还原、目录跨父或跨卷移动、同一文件系统上两个独立登记路径之间的移动、阻塞式字节锁、额外 CREATE contexts 与覆盖式替换仍未接；无真磁盘和断电试验结果。

**WPS 表格普通保存（现场验收，未执行）。** 记录实际操作系统、WPS 表格完整版本及构建号；不拿 Excel 或其他 WPS 版本的行为代证。在经批准的可写测试目录新建一次性 `.xlsx`，记录创建后的 FileId、已确认工作修订和正式节点/版本 ID 列表。对同一原工作簿两次写入不同的可辨认内容，每次使用普通保存，而非另存。每次保存后用独立 SMB 打开核对对应单元格、FileId 是否还是原件，并确认同一工作稿已更新、正式历史没有自动增加。最后才在 Web 明确选择原 FileId 并手动提交，核对新增一条版本、对应最终工作修订及原历史仍在。若 WPS 写临时文件再做覆盖式替换，分别记录“保存报错”和“同名但变成新 FileId”这两种结果及原件状态；都不算同一工作稿保存通过，也不因此开放覆盖。

**管理 Web。** [管理 HTTP](docs/web-management.md) 固定监听 0.0.0.0:8443。直连和只接受本机受信代理回源是分开的前台选择；只接受明确的外部 origin 和同一原连接，保留严格同源与会话 CSRF。仍拒绝旧代理环境参数，不提供 TLS、证书或代理服务，未验证实际外部 HTTPS。Web 不采样或展示磁盘信息。宿主 CPU、内存、设备速率和当前挂载容量由独立 [Helper](../helper/README.md) 只读观察，ZXS 不必停机；读数不证明原卷已登记或健康。原池登记和需独占原件的维护另按各自合同。浏览器、并发及停机排空仍需按该候选分别验收。

### 接着需要交付和量测的事

产品入口只有管理 Web 和文件共享 SMB。[首项与迁测](docs/web-and-smb.md)：同一账户通过两路独立认证。Web 管理共享及版本元数据；SMB 按每共享的只读/读写列举并打开普通文件。停用/未发布不可见、禁止匿名或来宾，两路协议会话不可互用，不再开发多账户/逐人 ACL。Web 不收发、预览或代理普通文件内容；交付程序无本地业务 argv；旧回归改用类型化库调用，真实物理测试仍另验。离线工具独立承接有原件与原单证据的核验、查询及受限恢复，不承接在线日常业务。

1. **SQLite 先行。** 按[单库契约](docs/sqlite-system.md)，第一份 DDL 与原 S 目录 SH 下的实际只读连接已有源码；待独立 helper 首建、双端冷开以及真实热日志/崩溃资格。旧 GENESIS/CONFIRMED/INTENT 停开发，不双写、迁移或作备用。落地前不宣称通用池已切换。
2. 先验同一账户及共同生效代、通过 Web 认证的管理员从停用显式设共享只读/读写，共享设置的短 SQL 事务与原回执已有未运行源码；下一步由真正 SMB 用户创建一件 FILE、写入/读回、冷开。按原池/精确共享模式/成员判断，不先等待版本、移动、回收。在线账户/共享、确切 FILE/父、分支模式和标签采用同库事务。不恢复旧产品 argv；接通正式材料、原操作和当前授权时保持核验与原单的真实反例，不将旧全局序号权威复刻进 SQL。
3. 接通每一轮一个真实工作增量的多次有界写、显式手动提交及原回执；确认不等旧读、SQL 不持锁等正文。按实际工作图的行数/字节/FD 给额，不用 F0→I1→I2 当格式上限。
4. 其后扩展真实同身份跨卷 MOVE 到无首节点、已确认工作稿和后续放置；把已支持的干净文件软删除/还原进一步扩展到目录整批与授权服务；完整材料核验复用原 FILE 验证器，不将新的诊断命令当作任何正常移动的替代。管理 Web、SMB 文件访问、真实客户端及下表未完成项仍须在产品内逐条交付。
5. 旧实验单槽的对照（非 SQL 指标）：两个 FILE 的容量与等待分别验：在 A 的 100 GB 基准上保留十次各 10 GB 的工作写入，提交和清理间的正文峰值约等于基准 + 全部原工作材料 + 最终贡献的变化（逻辑量示例：互不重叠约 300 GB，反复覆盖同一段约 210 GB；不含头、索引、文件系统开销）。令 A 的已准入读者持续到 INCR 已发表，计量其退稿与原 SYSTEM 槽位的占用时长；分别观察 B 的读取、新建/保存被延后以及 A 收尾后 B 的原请求。不能把这个单槽设计写成吞吐保证。此为待运行验收，不是测得数值。 新 SQL 验收反过来证明：A 等老读者/清原源时，B 的正常创建或保存不长期被 A 的未决状态挡住。

6. 旧源码逻辑遍数仅作对照，不是新 SQLite/物料组合的测量。搬移另验**巨大保留历史、极小当前正文**：使 A 的首 FULL 很大，当前 INCR 将其裁得很小；B 的可用空间只够当前、不够全部保留材料时，原单应在逻辑切换前拒绝。能容纳时按阶段分别记录对完整 FILE 的逻辑核读、实际装入私有目标的字节、源/目的暂时并存与原保留占用时长。同挂载正常流程不抄 payload，首 FULL 仍至少核读三遍：首次签决、改名前再次核原源、安装名重新核实。无中断的普通跨挂载 MOVE 在源侧至少三遍（首次核读、复制、退役前核读）；随后同一源目录改作本票私名，保持全部已核原件和排他锁，只复核实际目录、成员和各件未变，不再整读一遍源。中断并失去句柄后，须从原票重开并核读剩下各件。无中断的普通跨挂载 MOVE 在目标侧至少三遍（匿名读回、签决前已命名私目录、决定后落位前已命名私目录）。同次原子改名保留最后一次核过的原句柄，最终名上的目录、成员、各对象身份与原状态、操作标签和原私名消失仍须核实，不再扫描全部正文。丢失这些句柄的冷重试须完整核读实际目标；这项去重不改变专盘删还。有 INCR 还要验自身和其贡献内容。这些是现行源码的逻辑阶段，不是设备实际读量或实测速度。另有 `custody_handoff.rs` 的独立 FILE 源码用例：原 MOVE 的目标可读，但旧读者或源盘离线阻止原单收尾时，旁边 FILE 的已确认内容可读，新 CREATE/SAVE 暂拒且无回执；接回原盘并核完同一原单后才接受原先两笔请求。未执行。

**当前命名源码边界。** 新池普通根或已安装目录中的 FILE 从原拼写与完整 FileId 派生唯一容器，普通与回收终名一致；真普通目录保留原名字节。用实际有类型的存储夹具对大小写两份正文/原历史、专盘同名不同 FILE、迟到撞名、受限或掉线的回收卷编写了验收用例，并未执行。子目录 FILE 整链与未来的主分支改名仍单列；改名只影响当前名，不能改写历史创建名。实际 SMB 接入须验证逻辑名确实区分大小写、错误大写不会误中、目录列表不泄露容器后缀，不能用库级夹具代替。

**跨文件系统：已确认移动、SMB 丢答后目标离线（现场验收，未执行）。** 只在内置 SMB 接通该路径后，用经批准的一次性新池和两个已核实不同的文件系统，不据此推断两块物理盘。记录移动前的源路径、目标空位、原 FileId、工作修订和正式历史。在同一 ZXS 树发起一次移动，测试端预先拦住本次成功答复。用独立受信的只读证据确认原单已提交、唯一位置已选目标后，丢弃该答复，再隔离目标卷，保留源卷。用新 SMB 连接检查：目标当前不可访问不是移动失败，旧源路径不能重新打开；若源有残留，那只是待安全清退的旧实物；旧读租未释放或目标尚不能独立核验时，保留原物。已有读视图只按其原有效授权和真实绑定访问，不从残留重建视图、新开源路径或自动回退。原柄读到旧确认稿不等于从旧卷读取，不为造旧视图而绕过唯一普通打开限制。两卷恢复并经核对后再重连，确认旧路径没有该 FILE、目标路径打开的是原 FileId，工作内容和正式历史一致、没有第二个有效位置。客户端结果不明时，先用受信证据核对原单；仍无法确认就保留未知，不盲目重放移动、重新创建同名文件或直接读写、搬动底层容器。

**通用范围读现场验收（未执行）。** 选同一历史深度/版本长度，对比单材料和高度碎片化的 4 KiB 范围。区分首次打开直接区间表、读块摘要目录/页、实际正文读取的应用逻辑字节，与设备实际读量（注明缓存状态、样本窗口和设备归属）。100 GiB 的单一材料，4 KiB 完全落在一个完整块时，此格式可需 4 MiB 正文、至多 32 KiB 摘要页、800 B 页目录、95 B 材料表头，另加版本索引，不代表实测。碎片短读按相交的不同材料计两只被持 FD/件和暂时开名余量；记录确认前/交首字节前是否因实际额度拒绝、已交前缀与 flush 出错分别如何返回。若正常小读过早受限，再拿等价的冻结原视图/错误语义证明有界流式路线，不先降级或宣称性能收益。

**SMB 单写与已确认读（待现场验证）。** B 持已确认非空工作修订 1（例如 4 MiB＋1 B，比整块多 1 B）并停在最后未满块，A 持兼容读的写句柄在同一 FileId 上改旧尾、追加并确认修订 2；A 的正常读在确认前能看见自己的暂存，B 全程仍读旧字节和长度，新读才见修订 2，旧读结束只影响旧材料清退。反向先停住慢写也允许 B 打开上次已确认稿；第三个写者仍拒。对同一可写句柄分别喂普通 WRITE、写穿、脏/干净 FLUSH 以及正常脏/干净 CLOSE：必要的原数据及事务成功才返回相应确认、同单重送不多发、干净不发、flush 后写者仍占席；ShareAccess 的实际冲突仍须分别验证；本候选没有字节范围锁，不能以单写者替代。未发的断线暂存和真正提交丢响应分别处理，不据应用快捷键计版本。

**保存和提交分别幂等。** 已确认但应答丢失，只返回该次工作修订；已手动提交的原操作只返回当时的单个节点。两种回执不能互换。旧代/输入/范围或终长不匹配就拒，不覆盖别人已确认的工作。
