# ZXS

ZXS 是独立的 Linux 文件容器存储服务。**面向用户的入口只有 Web 管理界面和 SMB 文件共享。Web 不上传、预览、下载或转发普通文件正文；普通文件 I/O 走 SMB。管理 Web 提供登录、调节首装已选目录的读写模式及手动提交版本，固定监听 HTTP 0.0.0.0:8443；可在前台明确选择[仅本机认证代理回源](docs/web-management.md#外部-https-反向代理)，TLS 由外部软件负责；未部署/验收。** 独立 Helper 的职责是获准的离线准备、维护和诊断。此 ZXS 正常入口是前台进程，不交付服务管理或自动安装/启动。

**新架构：一个 [SQLite SYSTEM 数据库](docs/sqlite-system.md)保存池登记、Web 与 SMB 的单一账户、共同凭据代及共享模式、命名和放置、正式节点关系、任务与操作回执；FILE 容器保存普通二进制身份、扁平区间索引、校验表与正文。** 不并用旧 REGISTRATION/CONFIRMED，不迁移旧池。每轮首次实际改动只建一个增量文件，以后保存更新同一文件，不复制整个基底；只有明确手动提交才生成历史节点。宿主管挂载，格式不依赖品牌特性或 reflink。

## 当前维护的 SMB

只有同一 `zxs` 程序中的 [内置 Rust SMB 3.1.1](src/smb/ARCHITECTURE.md)。它只提供 ZXS 已授权的 `\\服务器\ZXS` 一棵逻辑树，不是可独立配置、运行或分发的通用服务器；不使用外部 Samba 进程或兼容后端。已批准的具体地址、数据盘及专用回收目录来自原新池安装记录。

候选的受信 root 前台负责持原件及监督，同一程序的 Web 和 SMB 业务角色各自降权，两个同原角色核实同一原站点、SYSTEM、共同凭据代和监听，均预备后一次放行。预备或监听回执不等于客户端连通/读写、应用保存或发行通过。具体实现边界见 [SMB 业务台账](src/smb/BUSINESS.md)；仓库不提供迁移、重新认领旧池或降级操作。

## 既有实验内核可追到的路径（不是 SQLite 实现）

- **名字和目录。** 在已登记普通卷根或已安装的子目录里创建、列出和精确定位 FILE。区分大小写，保留 UTF-8 原拼写；同层 `Report.xlsx` 与 `report.xlsx` 是两个名字，同层普通目录则会挡完全同名的 FILE。用户看到 `方案.xlsx`，真实容器为 `方案-<完整32位FileId>.xlsx`。不会从名字猜身份，也不会覆盖同名异物。[存储命名](docs/storage-names.md) · [目录中的 FILE](docs/files-in-directories.md)
- **保存和历史。** 在旧实验中，新建是空 FILE，没有正式节点。初次保存先形成工作稿；显式提交才产生首个 FULL（F0）。随后的区间覆盖、增长、截短可以顺次保存并显式发表两代 INCR（I1、I2），不会把整份基础文件复制一遍。增长不会复活曾被截掉的字节。该旧驱动只做过 F0→I1→I2 的源码夹具；这不是新存储格式的世代上限。当前读取和按 NodeId 读历史不混用工作稿或同名别物。
- **搬移和回收。** 已收尾、没有脏稿且已有首个正式 FULL 的 FILE（可带 I1/I2）可在两个已登记普通卷之间完成首次原样搬移；同挂载与跨文件系统分别校核。软删、还原通过本池唯一的独立回收文件系统；同一个 FileId 与其历史整盒转移、物理容器名不变。还原按原删除决定及原父，或一个明确且未占用的新父，不碰同名新 FILE。未提供文件夹整组搬移/回收、业务改名、永久清除。[回收与还原](docs/recycle-and-restore.md)
- **旧开发驱动的原决定不等于当前可读。** 此路径的 SYSTEM 是唯一归属与操作决定来源。完整帧同步后，还须在同一原登记 inode 持久确认下界；原历史回执不能证明今天的实体或目标就绪。确认目标不代表源已清；源离线或老读者不释放时，目标可读，但全池新的写操作仍可能等原清理单收尾。不会扫描、收养或删除陌生物，也不能识别数据与所有本地证据共同一致回滚的整盘快照。

## 既有数据面和旧实验日志的成本

4 MiB 是校验块／内存缓冲，不是文件总大小上限。初次保存支持非 seek 输入，先预留真实空间、逐块写入并读回原目标，再确认。正常首传期间兄弟 FILE 可写；若同一原操作已占下一日志序号而命名稿尚未留下，重传期间兄弟仍可读，但新写须等原单完成。首个 FULL 具名后要从实际 RAW 再整读一遍，连同完整索引校验；全程不持短 SYSTEM/卷锁，但从正式保留起已占全池下一写序号。

小范围读不是只读请求的几字节：需要核对所选各代索引和相交的完整块；三代历史可能重复扫索引，碎片化布局可重读同一来源。正式 INCR 不再写入未改的父字节，但确认时可能读遍有贡献的父内容。交接需要容纳**全部保留历史**，不能按很小的 HEAD 估空间。应用逻辑读写遍数、工作包叠加、旧读者卡清理及两类日志额度见[任务与成本记录](TASKS.md)，不是磁盘跑分。旧开发驱动每帧最多 4 KiB、每池 8192 个决定/8 MiB 决定区；每个已回收 FILE 在原日志保留一笔可恢复额度，独立于目的物理容量。

## 接入、运维与验收

[Web 与 SMB 的边界和验收](docs/web-and-smb.md)区分源码、开发验证和现场验收。[单 ELF 构建](BUILD.md)不运行或批准制品。交付的 `zxs` 只有无参数的正常前台入口和同 ELF 的私有继承角色，不解析旧登记、文件或回收命令；离线资料仍有真实有类型的库级夹具，不能把它们当上线入口。

新池采用[两种固定协议身份](docs/first-account-v1.md)：唯一 Web 管理员和唯一 SMB 用户。Web 密验在 SQLite；SMB 的唯一生效密验在原实例受保护的私有记录，两者不互代。首装由本机终端一次批准普通数据盘的初始 RO/RW、LAN 及回收目录；Web 只改变已选数据目录的模式，不另发表业务 share。匿名、guest、错凭据拒绝。

每个 FILE 只允许一名实际写者，兼容读固定所选已确认平图。明确手动提交后，下一个实际改动开新一轮，直接沿原冻结图，不等全量、不设两代上限。断开不自动确认或发新版本。回收按原可见名字和 DeleteOp 选独立未过期轮次，与正常数据盘保持同一 FileId/历史；R 不可用时不当作空库，不挡已核验的普通盘。见[普通工作稿与跨盘存储](docs/portable-storage.md)、[管理 Web](docs/web-management.md)、[内置 SMB 的验收边界](docs/web-and-smb.md#排空与验收)。

helper 在离线排他后独立做首次设置、磁盘运维及经准确原操作授权的有限恢复。检查池/容器实物、查原回执和实际续作是三种不同动作，不移植 argv、不调用兄弟可执行程序／源码。ZXS 处理在线业务就绪、卷真实角色与故障/正常下线。宿主进程状态、目录空或只看到标签都不是在线安全或原物健康证明。[单库、互斥与恢复](docs/sqlite-system.md) · [架构及职责](ARCHITECTURE.md)

本目录含独立 Rust 包、锁文件和 Linux 原生接口。多轮增量、回收冷接续、真实文件系统边界及大文件分别验收；本次源码清理不构成构建、运行、发布、操作用户磁盘或测性能的证据。
