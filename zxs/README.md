# ZXS

独立的 Linux 文件容器存储项目。本目录包含完整的 Rust 包、锁文件与源码，可在独立检出目录内构建。存储与服务边界见[顶层设计](ARCHITECTURE.md)。原生接口只使用 Linux 系统调用和 C 标准库。构建输入为 Rust 1.100.0、目标 Linux 的 C 编译器及归档器；不需要从包仓库下载依赖。

## 此批源码提供什么

`zxs check-new SYSTEM RECYCLE FILE [FILE ...]` 对**已存在、明确选择的空目录**做只读检查。示例参数顺序：`zxs check-new /mnt/system/zxs /mnt/recycle/zxs /mnt/data/photos`。输出是当时观察到的角色、路径和目录身份。该检查不创建目录、初始化池、迁移旧格式、移动或删除数据；没有挂载、格式化或自动发现行为。

- SYSTEM 和回收盘都必填，至少有一个普通 FILE 存储根。回收盘不能与 SYSTEM 或任一 FILE 根位于相同文件系统；两个普通根不要求采用不同后端。不同 `st_dev` 只证明文件系统标识不同，不证明硬件或控制器冗余。
- 每个路径必须绝对且规范。逐级用 `openat` 打开目录，不跟随符号链接；拒绝同一目录充当多个角色、互相嵌套或在检查中被替换。被选根须属于运行账户，不可由组或其他用户写入。
- 从已持有的目录描述符读取目录内容及 `user.zxs.volume` 静态卷身份标记。任何已有内容/已有标记均不视为新盘。不支持查询该属性、观察不完整或目录正被独占使用时直接报错；不降级为按路径相信、不清理任何内容。
- 共享目录锁只在这次观察期间有效，不留下锁文件。该报告不是后续写入许可：初始化必须在其自己的独占持有与原始登记决定下重新检查。

## 空池登记：本机维护命令

此入口只处理原始物理登记，不创建账户、启动网络服务或增加/注销卷。普通 FILE 命令另行核验当次操作，见下节。命令必须在操作系统已限制的本机维护账户下使用；只接受该账户持有的确切目录。不可由网络请求透传本机初始化权限。

1. `zxs new-id` 生成一个操作 ID，保留它和首次选择的路径，以便准确重试。
2. `zxs init OP SYSTEM RECYCLE FILE [FILE ...]` 独占选定的空根，检查身份与全部物理祖先。已标记祖先、隐藏原祖先的子树挂载、不支持所需 ABI、已有内容或角色冲突均拒绝。SYSTEM 将完整原操作、本机维护 UID、所选根和登记文件自己的物理身份（目录/文件的原生对象句柄和所属文件系统 UUID）先同步到同一私有原始记录 `INITIALIZING`。仅对其确切原选根设置只创建、不覆盖的 `user.zxs.volume` 标签。数据/回收根不创建目录或业务库。原记录不覆盖地改名为 `REGISTRATION` 并同步，才有一个已发布登记。
3. 尚未发布时，相同操作可以在持有并复核原有空根、已有标签与原保留文件后继续；异池、变更的原实体、未知内容或其他操作不能取得许可。发布后，相同维护主体/操作/原路径集合只从原 SYSTEM 查原结果，不因后来同名新根而重领、补标或重写。该结果不是当前数据卷在线的证明。
4. `zxs inspect SYSTEM` 是另一项只读操作，必须先在原 SYSTEM 先以 O_PATH 排除设备、FIFO 或链接，核验私有普通登记文件的原实体与静态标签，并同步确切 SYSTEM 目录以确认改名已持久；再打开登记中的每个确切卷核验角色、身份和标签。缺失或失联即报错，不探查备用路径、不迁移也不清理。当前严格登记以初始根和登记文件的真实实体为准，设备/实体编号改变不会自动重绑。

登记时需要持有 FD 的 Linux 可导出对象句柄（name_to_handle_at）及原生 128 位文件系统 UUID（FS_IOC_GETFSUUID），不能以路径、时间戳或可复用的 inode 数字代替。还需要 Linux 的用户扩展属性、挂载身份 (`statx`、可信 `/proc/self/mountinfo`)、目录锁与同步。SYSTEM 还要支持匿名临时 inode、不覆盖链接/改名和 `/proc/self/fd`。不具备即拒绝。操作系统是本机维护边界：目录锁约束协作写者，不防能以相同账户任意改盘的程序；SHA-256 仅检错，不是密码或用户认证。

**登记进度：**[设计阶段 A](ARCHITECTURE.md#7-分阶段交付与任务归属)的只读检查、显式空池登记、同操作续作和整池只读核验已有源码；尚未构建、运行、做真实双盘/断电验证或发行。其余阶段不因此完成。逐中断点、替换/失联、不同操作和未选中已登记祖先的用例源码在 `tests/unit/`。

## 登记后的第一个普通 FILE

这一批提供本机维护账户下、普通卷根层的**创建空文件、按稳定 ID 读取、完整列举和查询创建回执**。空 FILE 有自己的 EntryId、FileId 和 HistoryId。它默认手动、逻辑长度为零；没有正式版本、节点或已确认稿，不会为了返回空内容而伪造首个 FULL。命令中的 VOLUME 是登记报告里角色为 File 的 ID，不是路径或卷名。

| 命令 | 结果 |
| --- | --- |
| `zxs file-create OP SYSTEM VOLUME NAME` | 新建一个真正的 FILE 容器；响应遗失可用原操作 ID、同一创建名和同一卷重试。返回原发表结果，不保证此刻仍在线。 |
| `zxs file-receipt SYSTEM OP` | 只从原 SYSTEM 查创建：已保留、已准备、完整决定帧等待持久确认、已发表但安装未确认，或已发表。不是当前正文或使用权限。 |
| `zxs file-list SYSTEM VOLUME` | 列举所选卷的普通业务项，逐个核实容器及内部材料。原操作确切预留的私有暂存名不作 FILE，单独报告有多少项仍被占用，不宣称查明它们的来历或内容。普通项缺失、其他未知名称、超限或失联时拒绝。 |
| `zxs file-info SYSTEM FILE`、`zxs file-read SYSTEM FILE` | 按 FileId 打开原卷上实际的 FILE 容器及本地记录；前者显示身份，后者输出正文。未保存的原 FILE 读零字节；若已确认首个手动工作稿，则按当次稳定 FILE 选定并校验其实际稿件。其他卷失联不影响它。同名替换、缺失材料不当作零字节。 |

当前文件名限一个 1–120 字节的小写 ASCII 分量，首字符为字母或数字，其余可含数字、字母、连字符、下划线和点；拒绝尾点、保留名和无法安全比较的同级名称。不截短或猜测 Unicode/大小写等价。点和普通扩展名不改变文件语义。完整 Unicode、普通文件夹、后续多次/随机区间保存、多节点编辑与分支操作、网络入口和搬盘仍在[交付台账](TASKS.md)中，未在本批实现。

**创建与冷重开。** SYSTEM 排他目录锁贯穿保留、准备、写入决定帧、同步与安装。SYSTEM 先同步原主体、请求、稳定 ID、实际目标根和一张原操作暂存票，才允许在该根创建任何命名暂存项。这张票最多有八个明确的私有名字，不创建常驻隐藏目录或卷级数据库。只把本次排他 mkdir 新建并持有的真实目录身份持久绑定到这张票，再创建和同步其中的 `FILE` 初始记录。若在 mkdir 与绑定之间中断，原请求永不收养或清扫该占位：只在正面确认它仍为空后，选择同票的下一未占位置；原 FileId、EntryId、HistoryId 与请求不变。发现文件、不可读、非空或耗尽全部位置则停下，一旦已绑定不得换位。被跳过的空目录属于保留的私有名字，仍原样留存并在业务清单之外计数，不代表一份 FILE，也不是可清理的授权。准备文件均不是正式决定。

唯一业务决定是在原 `REGISTRATION` inode 上，紧接已验证的前沿写入并同步完整长度、原操作、前序与校验齐全的帧。每帧最多 4 KiB；本阶段最多 8192 个决定、决定区 8 MiB。若中断只留下原密封帧的确切前缀，只续写该原帧尚缺的后缀；未归属、不符或未知尾一律停下，不截断或覆盖。仅有完整字节也不能给出已确认回执。原帧完整核验、同步后，在**同一原 SYSTEM 登记 inode** 上同步一个 48 字节的确认下界（序号、决定区字节边界、原前沿 SHA-256）。初始下界在未命名的登记文件出生时即绑定池的 genesis。它只检错：拒绝完整帧被整段截掉、同一序号分叉或缺失；无决定内容，不能据它造决定、改盘或重建数据。下界与帧均核验并完成该文件同步才告知确认。若相差一笔，只允许同一原操作使用仍持有的原保留及密封材料确认**同一完整帧**；只读查询不提升下界。此后才不覆盖地安装原容器、重开验证、同步父目录并释放准确的原准备文件。目标离线、同名占用或原物被替换，不以其他文件补成成功。

这个下界不能发现整个文件系统及其下界一起回到完全自洽的旧快照；没有独立可信外部前沿，不作相关保证。初始或现有登记缺少所需下界均不接受，不自动补写为零。

每次根层枚举至多 8192 个条目、512 KiB 原始名称；超预算不给部分肯定结果。本阶段没有后台补做未结束操作，须按原参数重试。相同操作的已完成历史回执可在目标卷离线时查询，不取代当前读取。以上为源码和可审阅的中断用例（`tests/unit/ordinary.rs`），尚未构建或运行，亦无真实断电或发行验证。

## 首次手动保存：先落工作稿，不建历史节点

`zxs file-save OP SYSTEM FILE LENGTH SHA256` 从**标准输入**接收刚创建的 FILE 的首个稿件。LENGTH 是逻辑字节数，SHA256 是 64 位小写十六进制摘要。正文必须与两者准确匹配并结束。不读取用户提供的其他路径，不要求输入能 seek 或再次打开。成功的保存把工作 revision 从 0 推到 1；FileId、EntryId、HistoryId 不变，仍然没有正式节点或 FULL。此切片不接受第二次保存、随机覆盖或截断，也不把工作稿当作显式提交。

- `zxs file-save-receipt SYSTEM OP` 看原始保存状态，不打开正文。`file-save` 的原请求已确认且收尾后，再发一次即返回原结果，不消费输入，其他卷失联或同名新路径不改变它。如果输入未密封、没有可验的原材料，原请求需要重新供给确切字节；已密封且仍在的原数据不要求重传。
- `zxs file-info SYSTEM FILE` 检查真实 FILE 与工作材料的原生命名、长度、头部和已发表承诺，不声称已通读全部正文。`zxs file-read SYSTEM FILE` 固定一个已确认 revision，用保存的块承诺在**每一块输出之前**校验实际字节。后续块损坏或输出失败则命令失败；已经输出的只可能是已验证前缀，不当作完整成功。
- **4 MiB 是块大小，不是文件上限。** 输入先在准确的目标卷上开一个无名字的私有文件，预留最终物理布局所需空间（固定头、实际字节、每块 32 字节的校验链接）。内核不支持真实预留或空间不足即报错，不用稀疏截长冒充已备足。正常首传期间不持 SYSTEM 或卷锁，只保留这一个 FILE 的入站锁；别的 FILE 可读，也能发表新操作。若 SYSTEM 已为此原请求持久保留下一序号、但命名材料尚未留下，就必须由同一原单重新供给字节。重传期间仍不持 SYSTEM 或卷锁，已存在的兄弟 FILE 可读；新的 CREATE/SAVE 会明确拒绝，直到这笔原保留完成，不会抢占序号或返回假成功。输入短、过长或摘要不符就释放无名文件，不留下命名稿或原决定。实际上限取决于目标文件系统、配额及原生可表示长度，不用小固定总量挡住大文件。
- 流式读一次输入，将分块正文和暂态校验写入同一无名 inode，再在该 inode 上封好逐块校验链并顺序重读实际目标字节。内存不随文件大小或块数增长。重新取得原 SYSTEM 和目标卷、核验原 FILE 和初始 revision 后才保留同一 SAVE 的原始请求、将这一个原始 inode 不覆盖地链接进容器；不复制一份稿作为最终数据。原始保留、准备、唯一决定帧和确认下界与创建命令共用，没有第二本提交日志。中断后只按原请求恢复；未知或等字节替换物均不收养。
- 这条路径是**空 FILE 上首个完整输入区间**，不等于之后每次改动都要重新上传或复制整份文件。大文件的实际性能、峰值空间和故障表现尚无运行数据。中断/错误输入/同卷另一 FILE 在慢输入期间可写、跨块损坏、指定私有介质的 100 GiB 流式验收均仅写为用例源码（`tests/unit/first_save.rs`）；没有构建、测试、运行服务或实盘验收。

## 显式提交首个正式版本和固定节点读取

`zxs file-commit OP SYSTEM FILE 1` 在手动模式中针对该 FILE 已确认的第一笔工作稿，显式建立 main 分支、一个没有父节点的内容节点、一个正式版本。它不会由新建、保存、flush 或读取自动触发；没有已确认稿、revision 不符、已由另一请求建立首节点、原卷不可用或原材料不能核对都不会发出新的正式版本。零字节文件可先确认一个零字节工作稿，然后显式提交。

- 正式 BODY 在**同一个原 FILE 容器**下，名为 `15位存储ID-创建时文件名`，文件的实际字节就是完整原始正文，无压缩头、分片包头或指回旧稿的链接。独立的本地节点记录保存 FileId、HistoryId、分支、节点、版本、来源保存、零个父节点、创建名及逐块校验链接。每 4 MiB 正文仅用 32 字节链接；零字节正文仍有真实独立原始文件和本地节点。
- `zxs file-node-read SYSTEM FILE NODE` 只按真实已发表的这一 FILE + NodeId 读原 FULL，以本节点自己的校验材料逐块验证再输出。不把工作稿、同名文件或其他 FILE 的同字节当替代。干净状态下 `file-read` 使用正式版本；`file-info` 与 `file-commit-receipt SYSTEM OP` 能分别查看当前已核验的头和原操作状态，回执本身不证明今天可读。
- 正常准备对同一 FILE 持有输入边界，逐块核验已确认稿，预留独立 FULL 及有界内存处理的索引，重读实际目的字节；这段慢 I/O 不持 SYSTEM 或卷锁。只有已有原请求的中断重试会占据 SYSTEM 的下一个序号。一次 SYSTEM 决定绑定原请求、准确保存、固定标识和双方原生实体；决议前旧稿不退役，没有第二个容器或第二次表决。
- 决议后用同一原绑定重开独立 FULL，才能释放仍是该操作所消费的准确工作稿，保留原 SAVE 回执。若仍有读者持有旧稿租约、原材料变了或同步失败，原决定仍可查，清理未完成；不抢占读者、不移除未知文件，不从工作稿重建损坏的已决定 FULL。处理 100 GiB 时峰值需有原稿和真正独立 FULL 两份正文及索引的空间；不多造一份完整中间副本，不把后续区间保存改成全量复制。
- 这一批只覆盖第一笔显式提交、主分支的单个初始节点与其原始历史读取。多个 revision、后续节点/分支、自动发表、MOVE/回收等另行交付。源码有空/非空、失联、同名替换、逐块损坏、读者仍持有和逐中断点重试用例；没有构建、运行、测试或实盘验证。

### 固定历史节点的局部读取

`zxs file-node-range SYSTEM FILE NODE OFFSET LENGTH` 只取该正式原件的指定字节，不从文件头遍历此前的实际正文，也不会输出相邻字节。偏移和长度为无符号十进制；溢出或越过原长度即拒绝，不会截短请求蒙混。允许在有效偏移（包括结尾）读取零字节，但仍核验真实本地节点。

原 SYSTEM 决定同时绑定已经存在的本地节点索引的**准确字节 SHA-256**，没有第二本索引、缓存权威或副本。冷读先按 64 KiB 缓冲顺读该节点索引，核验全表并从同一次散列所用的实际缓冲提取一个 32 字节起点。对于 100 GiB 正文，索引链接约 800 KiB，另加一个小节点头。随后只读请求命中的正文块（每块至多 4 MiB）；每块实际字节和下个链接须先与该起点/前一块承诺相符，再交付所求部分。损坏的索引不能出具起点；未选正文区间未经这次检查，不声称已审计整个文件。没有持久缓存或热命中速度承诺。空区间、越界、跨块、晚段读取以及原 inode 上索引或实际块损坏均有未执行的源码用例。本功能只读固定的正式节点，不是后续区间**写**或多次保存。
