# ZXS

独立的 Linux 文件容器存储项目。本目录包含完整的 Rust 包、锁文件与源码，可在独立检出目录内构建。存储与服务边界见[顶层设计](ARCHITECTURE.md)。原生接口只使用 Linux 系统调用和 C 标准库。构建输入为 Rust 1.100.0、目标 Linux 的 C 编译器及归档器；不需要从包仓库下载依赖。

## 此批源码提供什么

`zxs check-new SYSTEM RECYCLE FILE [FILE ...]` 对**已存在、明确选择的空目录**做只读检查。示例参数顺序：`zxs check-new /mnt/system/zxs /mnt/recycle/zxs /mnt/data/photos`。输出是当时观察到的角色、路径和目录身份。该检查不创建目录、初始化池、迁移旧格式、移动或删除数据；没有挂载、格式化或自动发现行为。

- SYSTEM 和回收盘都必填，至少有一个普通 FILE 存储根。回收盘不能与 SYSTEM 或任一 FILE 根位于相同文件系统；两个普通根不要求采用不同后端。不同 `st_dev` 只证明文件系统标识不同，不证明硬件或控制器冗余。
- 每个路径必须绝对且规范。逐级用 `openat` 打开目录，不跟随符号链接；拒绝同一目录充当多个角色、互相嵌套或在检查中被替换。被选根须属于运行账户，不可由组或其他用户写入。
- 从已持有的目录描述符读取目录内容及 `user.zxs.volume` 静态卷身份标记。任何已有内容/已有标记均不视为新盘。不支持查询该属性、观察不完整或目录正被独占使用时直接报错；不降级为按路径相信、不清理任何内容。
- 共享目录锁只在这次观察期间有效，不留下锁文件。该报告不是后续写入许可：初始化必须在其自己的独占持有与原始登记决定下重新检查。

## 空池登记：本机维护命令

本批只处理原始物理登记。创建账户、启动网络服务、增加/注销卷及读写 FILE 均不包含在内。命令必须在操作系统已限制的本机维护账户下使用；只接受该账户持有的确切目录。不可由网络请求透传本机初始化权限。

1. `zxs new-id` 生成一个操作 ID，保留它和首次选择的路径，以便准确重试。
2. `zxs init OP SYSTEM RECYCLE FILE [FILE ...]` 独占选定的空根，检查身份与全部物理祖先。已标记祖先、隐藏原祖先的子树挂载、不支持所需 ABI、已有内容或角色冲突均拒绝。SYSTEM 将完整原操作、本机维护 UID、所选根和登记文件自己的物理身份（目录/文件的原生对象句柄和所属文件系统 UUID）先同步到同一私有原始记录 `INITIALIZING`。仅对其确切原选根设置只创建、不覆盖的 `user.zxs.volume` 标签。数据/回收根不创建目录或业务库。原记录不覆盖地改名为 `REGISTRATION` 并同步，才有一个已发布登记。
3. 尚未发布时，相同操作可以在持有并复核原有空根、已有标签与原保留文件后继续；异池、变更的原实体、未知内容或其他操作不能取得许可。发布后，相同维护主体/操作/原路径集合只从原 SYSTEM 查原结果，不因后来同名新根而重领、补标或重写。该结果不是当前数据卷在线的证明。
4. `zxs inspect SYSTEM` 是另一项只读操作，必须先在原 SYSTEM 先以 O_PATH 排除设备、FIFO 或链接，核验私有普通登记文件的原实体与静态标签，并同步确切 SYSTEM 目录以确认改名已持久；再打开登记中的每个确切卷核验角色、身份和标签。缺失或失联即报错，不探查备用路径、不迁移也不清理。当前严格登记以初始根和登记文件的真实实体为准，设备/实体编号改变不会自动重绑。

登记时需要持有 FD 的 Linux 可导出对象句柄（name_to_handle_at）及原生 128 位文件系统 UUID（FS_IOC_GETFSUUID），不能以路径、时间戳或可复用的 inode 数字代替。还需要 Linux 的用户扩展属性、挂载身份 (`statx`、可信 `/proc/self/mountinfo`)、目录锁与同步。SYSTEM 还要支持匿名临时 inode、不覆盖链接/改名和 `/proc/self/fd`。不具备即拒绝。操作系统是本机维护边界：目录锁约束协作写者，不防能以相同账户任意改盘的程序；SHA-256 仅检错，不是密码或用户认证。
