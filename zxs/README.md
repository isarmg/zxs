# ZXS

ZXS 是独立的 Linux 文件容器存储服务。**面向用户的入口只有 Web 管理界面和 SMB 文件共享。Web 不上传、预览、下载或转发普通文件正文；普通文件 I/O 走 SMB。当前主线已有本地存储内核，还没有可用的 Web 页面、HTTP 服务或 Samba VFS 接入。** 安装、systemd 配置和停机维护由独立的 helper 负责，不属于 ZXS 在线业务。

**新架构：一个 [SQLite SYSTEM 数据库](docs/sqlite-system.md)保存池登记、账户/ACL、命名和放置、正式节点关系、任务与操作回执；FILE 容器保存普通二进制身份、扁平区间索引、校验表与实际正文。** 不并用旧 REGISTRATION/CONFIRMED，不迁移旧池。手动首改仅存真实变化，不后台全拷；自动每次真实确认立即生一个可读节点，后台再真实整读写/验证并切同一节点。宿主管挂载，无品牌特性或 reflink。当前源码已接通 SQLite 初始卷表的只读观察：持真实 S 目录共享锁，用固定上游引擎核已提交原池与 S 卷标。账户/文件业务和 helper 首建尚未接通，未运行测试；没有对外开启服务。

## 既有实验内核可追到的路径（不是 SQLite 实现）

- **名字和目录。** 在已登记普通卷根或已安装的子目录里创建、列出和精确定位 FILE。区分大小写，保留 UTF-8 原拼写；同层 `Report.xlsx` 与 `report.xlsx` 是两个名字，同层普通目录则会挡完全同名的 FILE。用户看到 `方案.xlsx`，真实容器为 `方案-<完整32位FileId>.xlsx`。不会从名字猜身份，也不会覆盖同名异物。[存储命名](docs/storage-names.md) · [目录中的 FILE](docs/files-in-directories.md)
- **保存和历史。** 默认手动模式下，新建是空 FILE，没有正式节点。初次保存先形成工作稿；显式提交才产生首个 FULL（F0）。随后的区间覆盖、增长、截短可以顺次保存并显式发表两代 INCR（I1、I2），不会把整份基础文件复制一遍。增长不会复活曾被截掉的字节。当前上限 F0→I1→I2；不可在 I2 上继续编辑。当前读取和按 NodeId 读历史不混用工作稿或同名别物。
- **搬移和回收。** 已收尾、没有脏稿且已有首个正式 FULL 的 FILE（可带 I1/I2）可在两个已登记普通卷之间完成首次原样搬移；同挂载与跨文件系统分别校核。软删、还原通过本池唯一的独立回收文件系统；同一个 FileId 与其历史整盒转移、物理容器名不变。还原按原删除决定及原父，或一个明确且未占用的新父，不碰同名新 FILE。未提供文件夹整组搬移/回收、业务改名、永久清除。[回收与还原](docs/recycle-and-restore.md)
- **旧开发驱动的原决定不等于当前可读。** 此路径的 SYSTEM 是唯一归属与操作决定来源。完整帧同步后，还须在同一原登记 inode 持久确认下界；原历史回执不能证明今天的实体或目标就绪。确认目标不代表源已清；源离线或老读者不释放时，目标可读，但全池新的写操作仍可能等原清理单收尾。不会扫描、收养或删除陌生物，也不能识别数据与所有本地证据共同一致回滚的整盘快照。

## 既有数据面和旧实验日志的成本

4 MiB 是校验块／内存缓冲，不是文件总大小上限。初次保存支持非 seek 输入，先预留真实空间、逐块写入并读回原目标，再确认。正常首传期间兄弟 FILE 可写；若同一原操作已占下一日志序号而命名稿尚未留下，重传期间兄弟仍可读，但新写须等原单完成。首个 FULL 具名后要从实际 RAW 再整读一遍，连同完整索引校验；全程不持短 SYSTEM/卷锁，但从正式保留起已占全池下一写序号。

小范围读不是只读请求的几字节：需要核对所选各代索引和相交的完整块；三代历史可能重复扫索引，碎片化布局可重读同一来源。正式 INCR 不再写入未改的父字节，但确认时可能读遍有贡献的父内容。交接需要容纳**全部保留历史**，不能按很小的 HEAD 估空间。应用逻辑读写遍数、工作包叠加、旧读者卡清理及两类日志额度见[任务与成本记录](TASKS.md)，不是磁盘跑分。旧开发驱动每帧最多 4 KiB、每池 8192 个决定/8 MiB 决定区；每个已回收 FILE 在原日志保留一笔可恢复额度，独立于目的物理容量。

## 接入、运维与验收

[Web / SMB 接入与测试迁移](docs/web-and-smb.md)区分计划、源码和真实协议验收。`src/main.rs` 仍是 Cargo 会默认打包、能实际读写的**过渡开发验收驱动**，不是产品 CLI，不再新增命令，也不是 HTTP/SMB 或 helper 的调用协议。旧根式测试只选卷根；库中的有类型父是卷根或确切已安装的 DirectoryId。日常文件操作保留在同一业务内核，不转给 helper。

已有[账户/共享的实验路径](docs/portable-decisions-v1.md)及[libargon2 口令核验](docs/first-account-v1.md)源码。新服务从同一 SQLite 事务核账户、授权、业务成员及当前代次，不接旧帧作认证回退；管理资格仍不是 FILE 读写权。不提供 Web 或 SMB 登录的上线证明。

helper 在离线排他后独立做首次设置、磁盘运维及经准确原操作授权的有限恢复。检查池/容器实物、查原回执和实际续作是三种不同动作，不移植 argv、不调用兄弟可执行程序／源码。ZXS 处理在线业务就绪、卷真实角色与故障/正常下线。`systemctl` 状态、目录空或只看到标签都不是在线安全或原物健康证明。[单库、互斥与恢复](docs/sqlite-system.md) · [架构及职责](ARCHITECTURE.md)

本目录含独立 Rust 包、锁文件和 Linux 原生接口。两代增量、真实文件系统故障边界及 100 GiB 大文件仅有源码夹具；没有在这轮工作中构建、运行产品、执行测试、操作用户磁盘或测性能。
