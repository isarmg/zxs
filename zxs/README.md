# ZXS

独立的 Linux 文件容器存储项目。本目录包含完整的 Rust 包、锁文件与源码，可在独立检出目录内构建。存储与服务边界见[顶层设计](ARCHITECTURE.md)。原生接口只使用 Linux 系统调用和 C 标准库。构建输入为 Rust 1.100.0、目标 Linux 的 C 编译器及归档器；不需要从包仓库下载依赖。

## 此批源码提供什么

`zxs check-new SYSTEM RECYCLE FILE [FILE ...]` 对**已存在、明确选择的空目录**做只读检查。示例参数顺序：`zxs check-new /mnt/system/zxs /mnt/recycle/zxs /mnt/data/photos`。输出是当时观察到的角色、路径和目录身份。该检查不创建目录、初始化池、迁移旧格式、移动或删除数据；没有挂载、格式化或自动发现行为。

- SYSTEM 和回收盘都必填，至少有一个普通 FILE 存储根。回收盘不能与 SYSTEM 或任一 FILE 根位于相同文件系统；两个普通根不要求采用不同后端。不同 `st_dev` 只证明文件系统标识不同，不证明硬件或控制器冗余。
- 每个路径必须绝对且规范。逐级用 `openat` 打开目录，不跟随符号链接；拒绝同一目录充当多个角色、互相嵌套或在检查中被替换。被选根须属于运行账户，不可由组或其他用户写入。
- 从已持有的目录描述符读取目录内容及 `user.zxs.volume` 静态卷身份标记。任何已有内容/已有标记均不视为新盘。不支持查询该属性、观察不完整或目录正被独占使用时直接报错；不降级为按路径相信、不清理任何内容。
- 共享目录锁只在这次观察期间有效，不留下锁文件。该报告不是后续写入许可：初始化必须在其自己的独占持有与原始登记决定下重新检查。

## 空池登记：本机维护命令

此入口只处理原始物理登记，不创建账户、启动网络服务或增加/注销卷。普通 FILE 命令另行核验当次操作，见下节。命令必须在操作系统已限制的本机维护账户下使用；只接受该账户持有的确切目录。不可由网络请求透传本机初始化权限。

1. `zxs new-id` 生成一个操作 ID，保留它和首次选择的路径，以便准确重试。
2. `zxs init OP SYSTEM RECYCLE FILE [FILE ...]` 独占选定的空根，检查身份与全部物理祖先。已标记祖先、隐藏原祖先的子树挂载、不支持所需 ABI、已有内容或角色冲突均拒绝。SYSTEM 将完整原操作、本机维护 UID、所选根和登记文件自己的物理身份（目录/文件的原生对象句柄和所属文件系统 UUID）先同步到同一私有原始记录 `INITIALIZING`。仅对其确切原选根设置只创建、不覆盖的 `user.zxs.volume` 标签。数据/回收根不创建目录或业务库。原记录不覆盖地改名为 `REGISTRATION` 并同步，才有一个已发布登记。
3. 尚未发布时，相同操作可以在持有并复核原有空根、已有标签与原保留文件后继续；异池、变更的原实体、未知内容或其他操作不能取得许可。发布后，相同维护主体/操作/原路径集合只从原 SYSTEM 查原结果，不因后来同名新根而重领、补标或重写。该结果不是当前数据卷在线的证明。
4. `zxs inspect SYSTEM` 是另一项只读操作，必须先在原 SYSTEM 先以 O_PATH 排除设备、FIFO 或链接，核验私有普通登记文件的原实体与静态标签，并同步确切 SYSTEM 目录以确认改名已持久；再打开登记中的每个确切卷核验角色、身份和标签。缺失或失联即报错，不探查备用路径、不迁移也不清理。当前严格登记以初始根和登记文件的真实实体为准，设备/实体编号改变不会自动重绑。

登记时需要持有 FD 的 Linux 可导出对象句柄（name_to_handle_at）及原生 128 位文件系统 UUID（FS_IOC_GETFSUUID），不能以路径、时间戳或可复用的 inode 数字代替。还需要 Linux 的用户扩展属性、挂载身份 (`statx`、可信 `/proc/self/mountinfo`)、目录锁与同步。SYSTEM 还要支持匿名临时 inode、不覆盖链接/改名和 `/proc/self/fd`。不具备即拒绝。操作系统是本机维护边界：目录锁约束协作写者，不防能以相同账户任意改盘的程序；SHA-256 仅检错，不是密码或用户认证。

**登记进度：**[设计阶段 A](ARCHITECTURE.md#7-分阶段交付与任务归属)的只读检查、显式空池登记、同操作续作和整池只读核验已有源码；尚未构建、运行、做真实双盘/断电验证或发行。其余阶段不因此完成。逐中断点、替换/失联、不同操作和未选中已登记祖先的用例源码在 `tests/unit/`。

## 登记后的第一个普通 FILE

这一批提供本机维护账户下、普通卷根层的**创建空文件、按稳定 ID 读取、完整列举和查询创建回执**。空 FILE 有自己的 EntryId、FileId 和 HistoryId。它默认手动、逻辑长度为零；没有正式版本、节点或已确认稿，不会为了返回空内容而伪造首个 FULL。命令中的 VOLUME 是登记报告里角色为 File 的 ID，不是路径或卷名。

| 命令 | 结果 |
| --- | --- |
| `zxs file-create OP SYSTEM VOLUME NAME` | 新建一个真正的 FILE 容器；响应遗失可用原操作 ID、同一创建名和同一卷重试。返回原发表结果，不保证此刻仍在线。 |
| `zxs file-receipt SYSTEM OP` | 只从原 SYSTEM 查创建：已保留、已准备、完整决定帧等待持久确认、已发表但安装未确认，或已发表。不是当前正文或使用权限。 |
| `zxs file-list SYSTEM VOLUME` | 列举所选卷的普通业务项，逐个核实容器及内部材料。原操作确切预留的私有暂存名不作 FILE，单独报告有多少项仍被占用，不宣称查明它们的来历或内容。普通项缺失、其他未知名称、超限或失联时拒绝。 |
| `zxs file-info SYSTEM FILE`、`zxs file-read SYSTEM FILE` | 按 FileId 打开原卷上实际的 FILE 容器及本地记录；前者显示身份，后者输出正文。未保存的原 FILE 读零字节；若已确认首个手动工作稿，则按当次稳定 FILE 选定并校验其实际稿件。其他卷失联不影响它。同名替换、缺失材料不当作零字节。 |

根级 FILE 用原 UTF-8 拼写精确匹配，区分大小写，不合并看起来相同的 Unicode 字符。`zxs file-lookup SYSTEM VOLUME NAME` 返回该普通根登记且已核实的 FILE；`file-list` / `dir-list` 显示业务名。`Report.xlsx` 与 `report.xlsx` 可同时存在，未创建的 `REPORT.xlsx` 不会命中它们。FILE 和目录完全同名则冲突，不覆盖。

例如 `方案.xlsx` 的物理容器是 `方案-<完整32位FileId>.xlsx`。同一 FILE 在普通卷或专用回收卷用完全相同的容器名；还原须同时核原删除单，不能凭名字选回。根级新建时以真实原父和 SYSTEM 登记的回收卷上限预检物理叶及操作私名，即使回收卷离线，也不会签出已知永远容不下的名字。FILE 显示名最多 222 UTF-8 字节，普通目录最多 255，还须满足实际父组件和路径限制。只识别当前新池布局；旧卷、旧名不自动改造。逐项规则见[存储命名](docs/storage-names.md)。子目录中创建 FILE、业务改名和 SMB 服务仍未开放。此处为源码说明，不是运行、兼容性或性能报告。

**创建与冷重开。** SYSTEM 排他目录锁贯穿保留、准备、写入决定帧、同步与安装。SYSTEM 先同步原主体、请求、稳定 ID、实际目标根和一张原操作暂存票，才允许在该根创建任何命名暂存项。这张票最多有八个明确的私有名字，不创建常驻隐藏目录或卷级数据库。只把本次排他 mkdir 新建并持有的真实目录身份持久绑定到这张票，再创建和同步其中的 `FILE` 初始记录。若在 mkdir 与绑定之间中断，原请求永不收养或清扫该占位：只在正面确认它仍为空后，选择同票的下一未占位置；原 FileId、EntryId、HistoryId 与请求不变。发现文件、不可读、非空或耗尽全部位置则停下，一旦已绑定不得换位。被跳过的空目录属于保留的私有名字，仍原样留存并在业务清单之外计数，不代表一份 FILE，也不是可清理的授权。准备文件均不是正式决定。

唯一业务决定是在原 `REGISTRATION` inode 上，紧接已验证的前沿写入并同步完整长度、原操作、前序与校验齐全的帧。每帧最多 4 KiB；本阶段最多 8192 个决定、决定区 8 MiB。若中断只留下原密封帧的确切前缀，只续写该原帧尚缺的后缀；未归属、不符或未知尾一律停下，不截断或覆盖。仅有完整字节也不能给出已确认回执。原帧完整核验、同步后，在**同一原 SYSTEM 登记 inode** 上同步一个 48 字节的确认下界（序号、决定区字节边界、原前沿 SHA-256）。初始下界在未命名的登记文件出生时即绑定池的 genesis。它只检错：拒绝完整帧被整段截掉、同一序号分叉或缺失；无决定内容，不能据它造决定、改盘或重建数据。下界与帧均核验并完成该文件同步才告知确认。若相差一笔，只允许同一原操作使用仍持有的原保留及密封材料确认**同一完整帧**；只读查询不提升下界。此后才不覆盖地安装原容器、重开验证、同步父目录并释放准确的原准备文件。目标离线、同名占用或原物被替换，不以其他文件补成成功。

这个下界不能发现整个文件系统及其下界一起回到完全自洽的旧快照；没有独立可信外部前沿，不作相关保证。初始或现有登记缺少所需下界均不接受，不自动补写为零。

每次根层枚举至多 8192 个条目、512 KiB 原始名称；超预算不给部分肯定结果。本阶段没有后台补做未结束操作，须按原参数重试。相同操作的已完成历史回执可在目标卷离线时查询，不取代当前读取。以上为源码和可审阅的中断用例（`tests/unit/ordinary.rs`），尚未构建或运行，亦无真实断电或发行验证。

## 首次手动保存：先落工作稿，不建历史节点

`zxs file-save OP SYSTEM FILE LENGTH SHA256` 从**标准输入**接收刚创建的 FILE 的首个稿件。LENGTH 是逻辑字节数，SHA256 是 64 位小写十六进制摘要。正文必须与两者准确匹配并结束。不读取用户提供的其他路径，不要求输入能 seek 或再次打开。成功的保存把工作 revision 从 0 推到 1；FileId、EntryId、HistoryId 不变，仍然没有正式节点或 FULL。此切片不接受第二次保存、随机覆盖或截断，也不把工作稿当作显式提交。

- `zxs file-save-receipt SYSTEM OP` 看原始保存状态，不打开正文。`file-save` 的原请求已确认且收尾后，再发一次即返回原结果，不消费输入，其他卷失联或同名新路径不改变它。如果输入未密封、没有可验的原材料，原请求需要重新供给确切字节；已密封且仍在的原数据不要求重传。
- `zxs file-info SYSTEM FILE` 检查真实 FILE 与工作材料的原生命名、长度、头部和已发表承诺，不声称已通读全部正文。`zxs file-read SYSTEM FILE` 固定一个已确认 revision，用保存的块承诺在**每一块输出之前**校验实际字节。后续块损坏或输出失败则命令失败；已经输出的只可能是已验证前缀，不当作完整成功。
- **4 MiB 是块大小，不是文件上限。** 输入先在准确的目标卷上开一个无名字的私有文件，预留最终物理布局所需空间（固定头、实际字节、每块 32 字节的校验链接）。内核不支持真实预留或空间不足即报错，不用稀疏截长冒充已备足。正常首传期间不持 SYSTEM 或卷锁，只保留这一个 FILE 的入站锁；别的 FILE 可读，也能发表新操作。若 SYSTEM 已为此原请求持久保留下一序号、但命名材料尚未留下，就必须由同一原单重新供给字节。重传期间仍不持 SYSTEM 或卷锁，已存在的兄弟 FILE 可读；新的 CREATE/SAVE 会明确拒绝，直到这笔原保留完成，不会抢占序号或返回假成功。输入短、过长或摘要不符就释放无名文件，不留下命名稿或原决定。实际上限取决于目标文件系统、配额及原生可表示长度，不用小固定总量挡住大文件。
- 流式读一次输入，将分块正文和暂态校验写入同一无名 inode，再在该 inode 上封好逐块校验链并顺序重读实际目标字节。内存不随文件大小或块数增长。重新取得原 SYSTEM 和目标卷、核验原 FILE 和初始 revision 后才保留同一 SAVE 的原始请求、将这一个原始 inode 不覆盖地链接进容器；不复制一份稿作为最终数据。原始保留、准备、唯一决定帧和确认下界与创建命令共用，没有第二本提交日志。中断后只按原请求恢复；未知或等字节替换物均不收养。
- 这条路径是**空 FILE 上首个完整输入区间**，不等于之后每次改动都要重新上传或复制整份文件。大文件的实际性能、峰值空间和故障表现尚无运行数据。中断/错误输入/同卷另一 FILE 在慢输入期间可写、跨块损坏、指定私有介质的 100 GiB 流式验收均仅写为用例源码（`tests/unit/first_save.rs`）；没有构建、测试、运行服务或实盘验收。

## 显式提交首个正式版本和固定节点读取

`zxs file-commit OP SYSTEM FILE 1` 在手动模式中针对该 FILE 已确认的第一笔工作稿，显式建立 main 分支、一个没有父节点的内容节点、一个正式版本。它不会由新建、保存、flush 或读取自动触发；没有已确认稿、revision 不符、已由另一请求建立首节点、原卷不可用或原材料不能核对都不会发出新的正式版本。零字节文件可先确认一个零字节工作稿，然后显式提交。

首个 FULL 初次具名后，仍要从实际原 RAW 逐块读回完整内容，并校验已具名节点的完整索引，才允许发表。相较匿名准备时的核验，这多一遍原 FULL 的逻辑读取；慢读时持有该 FILE 租约，不持有 SYSTEM 或数据卷写锁，但未完成的原保留仍会挡住其他新写。冷重试若两件均早已具名，并在已完成的具名核验后从未更换或改变，才复用同一份核验。这里不是实测吞吐或设备 I/O 数。

- 正式 BODY 在**同一个原 FILE 容器**下，名为 `15位存储ID-创建时文件名`，文件的实际字节就是完整原始正文，无压缩头、分片包头或指回旧稿的链接。独立的本地节点记录保存 FileId、HistoryId、分支、节点、版本、来源保存、零个父节点、创建名及逐块校验链接。每 4 MiB 正文仅用 32 字节链接；零字节正文仍有真实独立原始文件和本地节点。
- `zxs file-node-read SYSTEM FILE NODE` 只按真实已发表的这一 FILE + NodeId 读原 FULL，以本节点自己的校验材料逐块验证再输出。不把工作稿、同名文件或其他 FILE 的同字节当替代。干净状态下 `file-read` 使用正式版本；`file-info` 与 `file-commit-receipt SYSTEM OP` 能分别查看当前已核验的头和原操作状态，回执本身不证明今天可读。
- 正常准备对同一 FILE 持有输入边界，逐块核验已确认稿，预留独立 FULL 及有界内存处理的索引，重读实际目的字节；这段慢 I/O 不持 SYSTEM 或卷锁。首次匿名准备不预留 SYSTEM 的下一个序号。从原操作取得预留直到收尾，包括正常的具名材料全量读回和中断重试，其他新写不能取得下一序号；其他 FILE 的独立读取仍可进行。一次 SYSTEM 决定绑定原请求、准确保存、固定标识和双方原生实体；决议前旧稿不退役，没有第二个容器或第二次表决。
- 决议后用同一原绑定重开独立 FULL，才能释放仍是该操作所消费的准确工作稿，保留原 SAVE 回执。若仍有读者持有旧稿租约、原材料变了或同步失败，原决定仍可查，清理未完成；不抢占读者、不移除未知文件，不从工作稿重建损坏的已决定 FULL。处理 100 GiB 时峰值需有原稿和真正独立 FULL 两份正文及索引的空间；不多造一份完整中间副本，不把后续区间保存改成全量复制。
- 首 FULL 路径只覆盖第一笔显式提交与其原始历史读取。多次已确认工作保存和两个后继 INCR 见下文；任意多代节点、分支操作、自动发表、通用搬移/回收另行交付；下文单列当前支持的普通搬移及成对回收形状。源码有空/非空、失联、同名替换、逐块损坏、读者仍持有和逐中断点重试用例；没有构建、运行、测试或实盘验证。

### 固定历史节点的局部读取

`zxs file-node-range SYSTEM FILE NODE OFFSET LENGTH` 只取该正式原件的指定字节，不从文件头遍历此前的实际正文，也不会输出相邻字节。偏移和长度为无符号十进制；溢出或越过原长度即拒绝，不会截短请求蒙混。允许在有效偏移（包括结尾）读取零字节，但仍核验真实本地节点。

原 SYSTEM 决定同时绑定已经存在的本地节点索引的**准确字节 SHA-256**，没有第二本索引、缓存权威或副本。冷读先按 64 KiB 缓冲顺读该节点索引，核验全表并从同一次散列所用的实际缓冲提取一个 32 字节起点。对于 100 GiB 正文，索引链接约 800 KiB，另加一个小节点头。随后只读请求命中的正文块（每块至多 4 MiB）；每块实际字节和下个链接须先与该起点/前一块承诺相符，再交付所求部分。损坏的索引不能出具起点；未选正文区间未经这次检查，不声称已审计整个文件。没有持久缓存或热命中速度承诺。空区间、越界、跨块、晚段读取以及原 inode 上索引或实际块损坏均有未执行的源码用例。本功能只读固定的正式节点，不是后续区间**写**或多次保存。

## 已提交大文件的连续手动区间保存

`zxs file-write-range OP SYSTEM FILE REV OFFSET LENGTH SHA256 keep` 从标准输入只接收本次变化的字节。REV 是该 FILE 的**准确已确认工作修订号**。首个正式 FULL 后可从 1 保存为 2，再用 2 保存为 3，依此类推。这是按修订先后分别确认的多笔保存，不是同一 FILE 两个并发写入者都能成功。每次只建立一份本次变更材料，不建正式节点或新容器。每笔绑定真实 main、已发表 NodeId/VersionId，以及直接前序的操作、原决定、修订号和长度。使用过时 REV 不能覆盖新稿；已完成的原 OP 以原参数重试即返回那笔回执，绝不倒退当前 revision。这里的摘要只属于输入的 LENGTH 字节，**不是新整文件的摘要**。

- `keep` 不裁短：范围内覆盖，末尾写入可增长；离原末尾有距离时，中间是已声明的逻辑零。将最后一个参数改为十进制 `NEW_SIZE` 才显式设置新长度，可截短或加零；它必须容纳全部所写字节。纯裁短或扩长使用 OFFSET=0、LENGTH=0、标准空串 SHA-256、空输入和不同于原来的显式新长度。拒绝溢出、含糊无效果的零写、意外额外输入、错误 revision、同 Op 不同参数。
- 目录内只多出同一笔操作的一个实际原始 extent 文件，内容是其小头、实际新字节和局部校验表。预留的是这个文件的实际大小；不会为小改动创建/读回整个基准 FULL、按新逻辑长度作整文件暂存或产生第二个 FILE。保存时会复核原 FULL 的原生命名、长度及本地节点索引；**未读取的基准正文块不是这次保存的完整性审计**。后续读到它们时逐块验证。完整导出或再发表则必须检查所有贡献字节。
- `zxs file-read-range SYSTEM FILE OFFSET LENGTH` 固定原 FILE 的当前已确认版本，按准确的基准、变更 extent 及零区间组合，先验相关真实块，再只交付所选字节。也可用 `file-read` 顺序读完整逻辑内容。原正式 `file-node-read` / `file-node-range` 不读脏稿，即使脏稿损坏也不把它当作历史替代。相反，缺失的已确认 extent 不能让当前读取悄悄退回基准。新 FILE 的首笔工作稿在首次正式提交前仍只支持顺序读，不以一次整文件扫描冒充低成本随机读。
- `file-range-receipt SYSTEM OP` 只查原请求；已完成的原保存同参重试不吃 stdin，也不靠现在同名的卷。当前完整性、准备后的断点和决议后原结果分别处理。慢输入只占原 FILE 的入站租约；已保留但未链接的冷重传仍须先完成原请求才接纳新的写操作。
- 连续覆盖选择最新写入该位置的实际字节，保留原区间未覆盖的左右部分。截短后再增长，新增长区是零，不复活基准或旧稿已裁掉的字节。当前这一步仍保留本次工作链的**每个原 extent**，包括已被较新写入完全盖住的材料；当前链缺件明确拒绝，独立旧正式节点仍可读。磁盘成本是保留的各次实际写入/原头与校验表之和，不是每保存一次再复制整份 FILE。单次合法请求仍受原生可表示长度、实际可用空间和 SYSTEM 日志边界约束。
- 一次当前读在原 `FILE` 元数据上持共享读租约，固定首个正式节点、基准 RAW 和最新工作边缘。它用内存区间图选择旧 extent 时才临时打开那一件，校验原生命名、捕获的时间/长度和实际的相关块；持有的 FD 数不随保存笔数增加。交付每次输出及最终 flush 都核对所持材料，交付成功前再复核冻结前缀的全部原 extent 身份和状态，**不**把某次较新的正常保存当旧读的结果。这不是对所有未选正文的逐字节审计，也没有常数时间承诺；元数据清点以及给下一笔保存核对原索引都随已保留工作链增长。高度碎片化时，同一来源的多个可见片段可能分别重扫它的索引、复验同一 BODY 块。
- **确认多笔稿不等于第二个正式版本**。要发表另一个正式节点，须对准确的已确认修订再发一次显式提交，见下节。已有源码用例覆盖交叉覆盖、裁短再增长、原帧未确认时保留准确前一修订、已有原回执去重、边读边确认新稿、同原 inode 或旧 extent 被篡改。另有显式 opt-in 的真实 100 GiB 首 FULL 上连续保存 4 KiB 和小覆盖、比较真实存储及当前/历史内容的用例源码。没有执行这些用例、构建、服务或性能验证。

## 在正式节点上继续编辑：一个首 FULL 与两代 INCR

在主分支的首个正式 FULL（F0）或其已确认的第一个增量节点（I1）上保存一笔或多笔区间修改后，用 `zxs file-commit OP SYSTEM FILE REV` 显式发表该已确认修订。REV 必须是仍然有效的工作边缘（至少 2）。成功响应含新节点的稳定 NodeId、原父 NodeId/VersionId、完整逻辑正文的长度与 SHA-256，以及本节点实际保存的变化字节数和它们的摘要。保存、读取或关闭文件绝不会代替这个命令。

- **实际写多少。** 同一 FILE 内新增一个按新存储 ID 和创建名命名的不可变 INCR 原件。其中本地记录标明父节点及逻辑区间，紧接着只存最后仍可见的写入字节、每块的认证链接；未改处沿已发表的直接父节点读取，不能跳过 I1 回到 F0，空洞是明确的逻辑零。不写整份基准，不保留到可变工作稿的引用，也不建立第二个容器。纯截短或补零可以只有节点记录、没有增量正文。开始清理前需同时容纳旧工作材料与新的 INCR。
- **提交的读成本不等于写成本。** 在发表前顺序组合并校验所有实际贡献字节，得到整份逻辑正文的摘要，重读验证新 INCR；退役前另检查要释放的原工作材料。增量原件从匿名变为命名之后，在同一真实文件上再次校验其全部变化字节和索引，不用新的文件状态代替数据校验。这趟读回不持 SYSTEM 或卷锁，但原操作已保留下一个序号，其他 FILE 仍可读，新的写决定要等其收尾。100 GiB 文件只改 4 KiB 时，增量节点不保存其余 100 GiB，但这次显式提交仍可能读过几乎全部父正文，在慢盘上耗时。普通区间 SAVE 和区间读不作这次全量提交扫描。高度碎片化时可能多次查验同一来源的索引或同一实际块。没有性能测量。
- **怎样重新读。** `file-node-read` / `file-node-range` 按 `FileId + NodeId` 只选择所指的 F0、I1 或 I2。对 I2 即使只读末尾的一小段，也会验证同次持有的 F0、I1、I2 三份原索引；按两代的区间映射取实际相交的正文块，零区不读无关祖先正文。不会只从磁盘读取请求的那几个字节，也不因此宣称验证了未读的正文。相交的真实块先验再交付，整读还比对整个逻辑摘要。丢失或篡改不能靠同名路径、工作稿或另一个 FILE 凑齐。提交后，`file-read` / `file-read-range` 选新节点，原正式节点仍可独立读取。
- **中断与重试。** 新节点仍由原 SYSTEM 日志的一笔决定发表。未确认时可见原工作稿；决定后先重新打开真实目的原件，再释放准确的原工作材料。旧冻结读者仍在、原件不符或同步失败时停止清理，已经发表的逻辑结果不回退。可通过 `file-commit-receipt SYSTEM OP` 区分原决定与仍待收尾；相同 OP 和原请求继续，不重复建节点，收尾后的历史回执不要求数据卷在线。
- **两个编辑周期。** A 在 F0 的中间写入并截短，保存后显式提交 I1；B 再覆盖 A 的一部分并扩长，显式提交 I2。没被 B 覆盖的字节来自 I1；被 A 裁掉的尾部再增长时为零，不会从 F0 复活。工作稿的 revision 数值即使等于 I1 的 revision，也不能把旧操作改绑成 I1 上的新稿。未确认的 I2 不取代 I1 加本轮工作稿；I2 已确认才清其自己的旧稿。
- 当前最多是 F0→I1→I2；不能在 I2 上继续新写，不提供无限增量链、自动 FULL 检查点或网络句柄语义。真实 CLI 用例源码 [two_increments_cli.rs](tests/two_increments_cli.rs) 用小正文串起 A/B、跨卷 MOVE 后在 B 上发表 I2、同一 FILE 专盘软删除和还原、三个历史节点和丢响应后的原请求重试。这些用例和既有 100 GiB/4 KiB 夹具均未执行，不是速度或实盘证据。

## 两个普通卷根之间原样搬移一份已提交的 FILE

`zxs file-move OP SYSTEM FILE FROM TO 0` 将初始放置代次为 0 的同一 FILE 从指定普通卷根搬到另一普通卷根，保留原名。FROM 和 TO 都是当前池登记的 VolumeId，不是路径。只接纳已收尾且没有工作稿的主分支首个独立 FULL，可带零、一或两个顺次发表的增量原件。FileId、EntryId、HistoryId、所有原节点和版本、历史正文及原回执不变；新放置代次是 1。无首节点、脏稿、再搬一次、普通目录和改名不属于此命令；软删除和还原只走下述专用成对入口。没有 COPY、新 FILE 身份或第二个可服务的容器。

- **决定前**只有源可服务。先核源容器的确切原件：本地 FILE 记录、首节点索引和首 FULL 的全部真实字节；另须按原顺序核过每一个增量节点的整份历史视图及其实际包。即使最新节点已完全覆盖或裁空前一节点，旧 FULL 和已不再贡献的 I1 字节仍须完整可验证。同一挂载只准备不覆盖的目录改名；不同挂载先在目标实际预留各缺件长度，流式复制并读回匿名文件，再在原 SYSTEM 保留约束下命名，逐件同步。已命名部分必须是原请求的连续前缀；未知项不收养、不删除。完整命名材料还须按目标原件独立核读，不能拿源卷上的验证冒充目标。跨挂载临时需要目标能容纳本 FILE 的**整份物理历史**；源在决定前不会被挪走，长传和逐字节校验不占全池锁。原操作占用唯一决定槽后，其他 FILE 仍能读，但新的写决定可能须等待。
- **只有一笔归属决定。** 原 SYSTEM 帧和它的已确认下界确定唯一新址。同挂载用原目录上的原子不覆盖改名，绝不在失败后改成复制；即使改名已可见，中断后首次放行也要重新核原源名已空并同步两个准确父目录。跨挂载把同一已验证私有目录不覆盖地装到指定名。一次不中断的普通 MOVE 保留该目录和其全部实际材料的原句柄；改名后重新核最终名、每件实体和状态及原私名已空，不再仅因改名整读一遍目标正文。中断失去原句柄后必须从实际已命名目标重新完整读回。决定后至完整目标重开之间，当前和历史字节都不回退到源，也不会冒称目标已可用。清单可照常列出其余 FILE，分别显示该操作待收尾与已签发私有槽，不用物理目录扫描重建归属。
- **源清理与新址可读分开。** 目标在准确的最终名字下再次打开并校验全部原历史，核对真实注册及原件，必要的进度重新同步后可独立读；此后源离线或旧读者仍在，只意味着源清理待续。跨挂载先整体取得原叶的排他租约并核全部原字节，再在原根内不覆盖地将原容器隔离到本次操作票的确切私名。重新打开证实同一原容器并同步，在原保留上每次只准一件原叶退役；后面的物件抢先消失，或整个旧目录不在原名也不在隔离名，不能冒充已清。最后对真实隔离目录查空并同步、将此事实在原保留上明确确认，才允许移除空目录（或从最后的 rmdir→同步间中断续作），并确认原根两名均空；不递归删除、覆盖或处理同名替换物。若目标不可证，停止清理。已收尾后源原名可由不同 FileId 再使用，不影响旧操作与历史。
- **搬完仍从原来的正式节点编辑。** 只有 MOVE 已完整收尾，才能在新卷按原 revision 1 保存变化。即使旧卷离线，也能继续顺次保存并显式提交第一个 INCR。每笔新稿和新节点各有自己的 SYSTEM 原决定和新卷上的实际原件，不属于旧 MOVE 搬过的内容。按原 NodeId 仍能独立读首 FULL。若目标已可读但源清理未完成，新写要等，不能改向旧卷或以旧名字下的新 FILE 接手。若搬移时已有 I1，完整收尾后可在新卷以该 I1 为父继续保存并发表 I2。旧搬移回执仍只包括搬移当时的物理原件，新发表的包不能借用旧搬移票。
- **原单重试和查询。** 用同一主体、OP、FILE、FROM、TO、初始代次重试，或 `zxs file-move-receipt OP SYSTEM FILE FROM TO 0` 只查原单。状态分别为 Reserved/Prepared、完整帧待确认为 AwaitingDecisionConfirmation、已决定目标待重开为 DecidedTargetPending、目标曾重开而源待收尾为 TargetReopenedSourcePending。CompleteCheckedNow 只由本次实际核完两端的收尾调用返回；OriginalPublished 是历史结果，之后查询/同参重试不要求任一数据卷在线，也不声称现在健康。
- `tests/unit/custody_handoff.rs`、`custody_destination.rs`、`custody_source.rs` 含同挂载保原 inode、三个独立文件系统的跨挂载、原源离线、旧读者、同票冷重试、未同步进度、替换目标/源叶、原名再用、仅首 FULL 的 FILE 搬后在新址保存及发表首 INCR 等**未执行的源码用例**。并未编译、跑测试、测吞吐或操作真实介质。


## 单个已提交 FILE 的软删除与还原

这里只接受根层且已收尾的干净 FILE：原主分支首 FULL，可带一代或两代已正式发表的 INCR。初次普通 MOVE 也支持干净的三节点原图；两代 INCR 的同一容器有一个本地 FILE 记录、F0 索引和正文、I1 与 I2 两个独立包，共五件。删除和还原都是同一 FileId、EntryId、HistoryId 和原节点历史的真实交接，不是复制到另一个 FILE，不是永久删。回收根是这个池登记的唯一专用角色，必须与 SYSTEM 和每一个普通卷处于不同的可辨识文件系统；不是任意目录，也不是另一份业务存储。没有面向网络的管理或回收正文读取入口。

| 本机命令 | 参数与含义 |
| --- | --- |
| `zxs file-delete OP SYSTEM FILE FROM EPOCH` | 指定原普通卷及当前放置代次。请保留原 OP；确认后的输出含删除决定摘要。新 FILE 放置代次为 0，已完成的每次真实交接加 1。 |
| `zxs file-restore OP SYSTEM FILE DELETE_OP DELETE_SHA256 RETAINED_EPOCH original\|VOLUME` | 只接受仍然对应这个 FILE 的准确删除单。`original` 选择这一次删除记下的普通根；也可指定另一已登记的普通根。原人类名不变，没有覆盖或换名。 |
| `file-delete-receipt`、`file-restore-receipt` | 前缀同为 `zxs`，参数与各自提交命令完全相同。只读原 SYSTEM，区分未确认、已决定待安装、目标已独立重开但原处待清，以及历史已发表，不把后者当作今天仍可还原或在线。 |
| `zxs recycle-list SYSTEM LIMIT SOURCE_OR_ALL SINCE_OR_DASH THROUGH_OR_DASH [CURSOR]` | 以原决定新到旧分页（1–128）。源卷可填 `all`，UTC 起止秒为闭区间，`-` 表示不限。继续使用返回的游标和**同样的过滤与页长**。只报告本机原登记维护主体有权看到的 SYSTEM 元数据，不打开数据盘。 |

删除决定以前原 FILE 仍可读；决定后不再提供新的普通打开或按旧 NodeId 读取。还原决定后，只有实际最终目标完整重开后才放行普通读取；原处掉线、旧读者仍持租约或原件不符会使清理待办，此时其他 FILE 的新写也要等全池原单收尾，正常独立读取不因此失效。占用原还原名时不会碰同名的新 FILE；若尚未签发该次还原，可另发明确指定空闲卷的新请求。已经保留/决定的一单不能换卷、改代次或借另一笔删除的额度。失去响应时恢复同 OP 和原参数，不要按“最新同名”重写请求。

回收页中的删除、名字、时间和排序取自冻结的真实 SYSTEM 前缀；稍后的原操作阶段和“今天是否仍由这笔删除保留”另列。专用卷后来掉线不会把列表变空，也不能将列表当作该卷健康证明。每个已保留 FILE 从原日志预留一个实际 RESTORE 的空位和最坏 4,096 帧字节；无关新工作和下一次删除都不能挪用。这不保证目标物理空间。即使当前正文很小，真实交接仍须能够容纳并核实所有保留历史，包括已被覆盖的首 FULL。详见[回收与还原设计](docs/recycle-and-restore.md)。

## 普通目录：本机创建和逐层列举

- `zxs dir-mkdir OP SYSTEM VOLUME root NAME` 在已登记普通卷根创建一个真实空目录；把 `root` 换成上一层返回的 DirectoryId，就在该目录中新建子目录。返回原创建的 DirectoryId、EntryId 与决定序号。名称是区分大小写的 UTF-8 单组件，保留原拼写；须符合真实父目录的组件限额，不能使用两种精确的内部私名。
- `zxs dir-list SYSTEM VOLUME root` 列根下的 FILE 和普通目录。换成 DirectoryId 则只列该层。输出区分 `file` / `directory`；原 `file-list` 仍只列真实 FILE，既不把合法目录误判成陌生项，也不对未知物给出完整列表。子目录 FILE 的命令见下一节。
- 目录的身份和父子关系取自同一 SYSTEM 原记录；目录自身不含元数据文件。新建先验证该卷、父链、全部可能私名、当前同层名录及原票，再创建并绑定新的原生空目录。确认后只把该原件无覆盖地安装到终名并同步父目录。已决定、未收尾的本层可能返回“待安装/无法完整列举”，不能从一个看似存在或为空的路径创建孙目录。
- 同一 OP、同一原请求重试。已收尾的旧决定即使现在有孩子或原卷离线也能返回；这不是当前可用性声明。FILE 和目录在同一父中互斥：删入专盘的 FILE 也不能还原覆盖一个同名普通目录。不同父允许同名。
- 边界仍为本机维护主体和明确选择的原卷。本批不提供目录改名、递归搬移/删除、目录分页或网络授权。原生故障和混合列举只写有源码用例，未构建或运行。


### 普通目录里的 FILE

本机命令用普通 `VolumeId` 加 `root` 或准确 `DirectoryId` 选择父目录，不接收宿主目录字符串。旧 `file-create`、`file-lookup`、`file-move`、`file-delete`、`file-restore` 仍只指卷根，不会把根当作子目录的简写。

- `file-create-at OP SYSTEM VOLUME root|DIR NAME` 和 `file-lookup-at SYSTEM VOLUME root|DIR NAME` 创建或定位直属 FILE；`dir-list` 列这一层。不同父可以有两个完全同名的 FILE，同父同名的 FILE 与普通目录不能共存。读、保存和正式提交仍使用返回的稳定 FileId；历史读取使用 FileId 与 NodeId。
- `file-move-at OP SYSTEM FILE FROM_VOLUME root|DIR TO_VOLUME root|DIR EPOCH` 在两个不同登记普通卷的指定父之间搬移，仍是初始放置的干净 F0，可带 I1、I2；不做改名或目录移动。同一挂载真实改名后要同步两个原父，跨挂载确认后只从独立重开的目标服务。
- `file-delete-at OP SYSTEM FILE VOLUME root|DIR EPOCH` 把同一个完整容器转到专用回收卷。`file-restore-at OP SYSTEM FILE DELETE_OP DELETE_SHA256 EPOCH original` 还原到原删除的准确父；用 `VOLUME root|DIR` 替代 `original` 可明确指定另一父。原父离线、被替代或有同名项，不借旁边的同名目录回填。不可接受的目的在发票前拒绝，原删除及其还原名额保留；决定已确认则只续原单，绝不覆盖。
- 为以上三个搬运命令加 `-receipt` 可查完全相同的原请求。冻结的回收行显示删除时的父；不以当天看到的路径推断历史。完成的原操作回执不证明材料此刻在线。

没有目录整组搬移、原地业务改名、任意多代 INCR 或实际 SMB 服务。`tests/two_increments_cli.rs` 和原生边界夹具只是未执行的源码，不是设备、崩溃或性能证据。
