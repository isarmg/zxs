# ZXS 四界面交互演示

直接用浏览器打开 [`index.html`](index.html)。**无需安装依赖、构建、后台、ZXS 或登录。**
需要通过 HTTP 提供时，在仓库根运行 `python3 -m http.server 8000`，访问
`http://localhost:8000/demo/`。不要将整个仓库服务器暴露到不可信网络。

桌面四区同时显示：左上辅助工具、左下 ZXS Web、右上 SMB、右下模拟磁盘。
拖动中间竖线调宽，拖动两列各自横线独立调高。分隔线支持触屏、Tab 聚焦和方向键，
Home 居中；顶部可复位布局。小屏纵向排列，每区可滚动。

## 重要边界

这是**按产品目标独立实现的可操作状态模型**，不导入任何 ZXS 代码，不代表主线完成度。
右下树展示模型中的物理位置，不访问实际磁盘。不建立 Samba 服务、数据库、加密、
OS 锁、inode、fsync、真实原子事务或跨进程恢复。所有删除、故障、管理员操作只影响示例。

依据：2026-11-13 main `2881013ea` 的 `TASKS.md`、`docs/adr/directory-history-worktree.md`、
`directory-snapshot-material.md`、`container-content-timeline.md`、`disk-names-and-retained-layout.md`
及 `docs/09-backup-topology.md`。过时目录 Git 暂存/子提交引用不进入新 `.zxs` 演示。
已停止的非容器文件/非容器目录和多文件共同树不复活。

[功能覆盖与局限](COVERAGE.md)逐项区分可交互规则、抽象实现和未决事项。

## 建议完整走一遍

1. SMB 选择报告，写入新正文并保存；左下内容节点和右下版本正文同步增加。
2. 改名，再选择旧节点：显示最新名称，内容回到旧版本。标签独立于节点。
3. 关闭自动提交，保存数次；节点不增加。显式提交才增加，未提交时切换被阻断。
4. 复制到资料目录：新身份和新历史。软删除原件后仍能切节点，正文只读；移回恢复。
5. 从同一目录节点建立两个 worktree；初始磁盘实例没有正文。编辑一个，不影响另一个。
6. 提交第一个继续来源分支；提交第二个从历史分叉。日志分别报告 MOVE/COPY，SMB 结构保持。
7. 在 worktree 导入两个同名但不同实例的新文件：当场建立两个 deleted-data 容器。
8. 未提交就软删除 worktree：保存相应文件节点，不创建目录节点；新实例从原快照开始。
   管理员恢复旧实例，名字冲突改分配空号；再次软删不重复创建相同代数节点。
9. 辅助工具展开备份：选择 B←A，计划、复制、校验、决定、安装逐步执行。
   中途注入 I/O 中断，原副本保留；继续恢复。不把准备阶段视为完成。
   设置 C←B 再迁移，右下显示 B--UUID/A--UUID 的逐级来源链。
10. 修改来源数据后，旧已准备迁移不能决定；容量不足拒绝，不拆开目录仓库。

## 状态和测试

状态默认仅在内存；刷新会重置示例。辅助工具“示例控制”可保存到浏览器 localStorage，
再模拟重启恢复；顶部可导出 JSON。布局偏好自动保存。保存状态只接受当前格式，
不对旧格式迁移。浏览器清理站点数据会删除保存的演示，不影响真实 ZXS。

`tests/model.cjs` 使用 Node 内置测试器运行本 HTML 中的实际模型，无外部包。
GitHub 定向组 `standalone-demo` 通过 `test/ci/test_zxs_demo.py` 执行该行为套件。
本次未在本地运行正式测试或编译产品。浏览器单独验证真实点击、创建和 worktree 编辑提交。
其结果不代替 GitHub 精确提交测试，更不代替 ZXS 的真实 Samba、恢复和硬件测试。

## SMB 文件管理交互

文件区采用明确单选：单击行选中，名称按钮进入目录或 worktree。顶部工具栏始终提供
新建文件夹、剪切、复制、粘贴、重命名和软删除；行或空白处右键打开同一组菜单。
触摸设备可直接使用工具栏，无需右键。F2 改名、Delete 软删除、Shift+F10 菜单，
Ctrl/Command+C、X、V 对应演示内剪贴板，不读取系统剪贴板。

拖到普通目录或 worktree 时默认移动，按 Ctrl/Command 则复制。只接受当前演示明确选出的来源，
不根据名字、内容推断身份；外部系统拖入不自动导入。普通移动保留身份，复制产生独立容器；
重名拒绝，不覆盖。删除区不可直接编辑，剪切后粘贴到 common-data 是恢复。
整个 worktree 不支持剪切/复制；其文件可按既定规则导出，普通容器可导入 worktree。
目前不提供多选批量事务，物理磁盘区只读，四区分隔线与文件拖放相互独立。

浏览器已实走拖动文件到目录、右键复制/工具栏粘贴、F2 改名、软删除及剪切恢复。
自动化浏览器会拦截剪贴板快捷键，故 Ctrl/Command+C/X/V 的真实键盘端到端结果未计为通过；
这些事件分派另有 GitHub 定向回归，工具栏为始终可用的替代入口。
