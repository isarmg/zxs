# 外来盘只读历史预览（2026-11-05）

状态：只读验证与目标映射，不是迁入提交、数据库剪裁或逐盘独立写入协议。输入是当前格式的本盘原生证明；未增加旧版本兼容、隐式升级或来源盘修复。代码位于 `src/engine/src/foreign_import/`，测试位于 `test/engine/unit/foreign_import/tests.rs`。

## 身份与信任边界

`ForeignImportPreview::inspect` 接收调用方持有的目录 FD、所观察的绝对路径及有界预算。`DiskRoot` 验证当前命名路径、目录权限与持有句柄；这份本机设备号和 inode 只属于 `ForeignLocalBinding`。原始 `disk.json` 字节保留不变，原池、盘 ID、盘位和绑定代数属于 `ForeignSourceIdentity`，不拿来源旧设备号替代本机绑定，也不把忽略旧设备号变成写入准入。

因此，一份真实复制到新 inode 的来源材料可以获得相同的逻辑预览摘要；原有 `recognize_disk` 和写者准入仍拒绝与旧物理 seal 不符的根。预览结果没有执行方法，不能用它初始化、登记、改变权限或写入该根。

原生 seal 和本盘配置证明仍按原规则解析：初始配置只能证明格式及身份匹配，角色证据明确为 `InitialConfiguration`；代际格式须通过原 authority hash、配置链、成员和 enrollment 规则。原生发布回执与摘要验证只能说明这些字节在同一协议中自洽，并不新增作者签名或外部可信根。发现到自报身份不等于用户授权。

所有 I/O 经选中根的 held-FD 原语完成，不打开配置里记录的其他磁盘路径。读取前后核对原 seal、日志、权威锚及命名根，重复读取同一锚时改变字节也会拒绝。初始 seal 下出现未提升 generation 材料时拒绝。查看和目标映射不执行修复、同步、持久化索引或正文复制。

## 历史、来源与正文

读取有界本盘日志，拒绝截断尾部，选择该日志最后一个完整 Publication。验证 Candidate、Publication、发布 seal、本盘精确回执和原生成员证明，再通过 `history_package` 解析完整分页目录及每个历史图，复用其逻辑闭包校验。合法分页摘要不替代分支、提交、节点和目录引用闭包。

`ForeignCheckpoint` 明确表示本盘观察到的发布，不声称它是断开的来源池的全局最新状态。尾部存在未发布记录时显式标注。没有外部可信检查点时，本功能不提供抗整体回滚证明。

每个版本的原一级来源来自真正新建该版本的 `workspace.commit` 发布：该版本必须出现在该次快照而不在之前快照；冻结 placement、原一级 payload receipt 和完整 CommitProof 摘要必须一致。来源键使用原池、原一级盘 ID、绑定代数和历史域，不用当前 `upstream_slot_id`、显示名称或当前同名槽代替。一个二级盘可保留多个独立一级来源，各历史域独立映射。当前原生格式的元数据目录可能覆盖全池历史，而不是只有此盘存有正文的历史；预览保留这份完整目录并分别报告正文可用性，不把元数据存在误报为独立正文备份已完成。

预览保留完整 `HistoryManifest`，不删改来源的文件/目录分支、版本、节点、标签或已验证历史。正文状态是与原逻辑 `ContentState` 分离的观察值：

- `VerifiedLocal`：本盘版本元数据、原生发布证明、校验清单、大小和全部正文校验通过。
- `TemporarilyUnavailable`：已证明的历史仍保留，但本盘缺该版本目录或正文。
- `RecordedPurged` / `RecordedMigrated`：保留原历史的明确逻辑状态，不把暂缺正文改写成这些状态。

存在但损坏的正文、错误本地证明、缺少必要元数据、符号链接和非法目录结构都拒绝整个预览，不能降格成“暂不可用”。不会返回静默截断的成功子集。预览的正文可用性只描述本次读取，任何未来执行仍须重新验证并绑定实际复制结果。

当前必须明确拒绝的情况包括：数据盘没有完整发布目录、原始版本出生发布在本盘已不可用、空历史没有可证明的原一级身份，以及一个不可拆分历史域包含多个原一级身份。本阶段不猜测、不借当前槽填空，也不做损失性恢复。

## 目标映射

`map_to_primary` 只读取已准入的目标 `Engine`，要求启用的一级盘、有效当前写入门禁，以及空根或现存空目录。源与目标的设备/inode、路径父子重叠均拒绝。每个来源历史须且只须映射一次，名称通过原命名规则，大小写/规范化冲突和已存在历史身份冲突拒绝。

`ForeignImportMapping` 绑定来源预览摘要、目标注册身份、目标状态序号、目标分支/HEAD 和完整路径映射。它不创建目录、不产生用户可写的盘、不剪裁数据库；后续执行必须重验当前授权、来源材料、目标基线和实际复制字节，发布新的目标证明，不能复用被剪裁来源的旧证明。

本轮没有实现外来三级转二级及对应一级依赖的写入流程，也没有放开非 ZXS 目录转高等级。普通目录转换继续走它自己受控的一级盘向导。

## 预算与复杂度

默认元数据读取预算为 256 MiB、日志 64 MiB、版本数 100,000、正文验证 1 TiB；构造器设置硬上界并拒绝无效预算。元数据、日志和正文分别计数，超限返回错误而不是部分结果。结束时和映射时重验权威锚采用各自有界的再次读取；这是额外读取预算，不应把单次预算误述为整个生命周期累计总量。

工作量与本盘日志发布次数、可达元数据、版本证明路径和实际校验的正文总字节相关。当前每次完整扫描，不承诺常数级浏览或增量性能；重复快照路径校验仍可能重复 I/O。没有新增 fsync、锁顺序、数据库或网络依赖。后续系统端快速索引继续使用 SQLite，只能是盘内权威的可重建缓存，不能成为与盘内日志无序双写的第二权威。

## 验证

Linux 临时目录与固定 Rust 1.99.0，使用 `--locked --offline`。未改变真实磁盘或部署。

最终定向测试 12/12 通过：

- 两个独立一级来源、完整分支历史保留和其他盘正文暂缺。
- 新 inode 副本逻辑身份不变且不能通过旧物理准入。
- 缺正文保留，损坏正文拒绝且不修复。
- 缺分页元数据和变化的配置锚拒绝。
- 各类预算不返回部分成功。
- 精确来源映射、备份目标拒绝、未知/缺失映射和名称冲突。
- 目标现存空目录、文件/不存在父级拒绝、目标序号绑定及后来非空拒绝。
- 原配置的其他盘路径被无关目录替代仍只读取选中根。
- 日志变化、截断、配置变化、出现未提升 generation 和命名根替换使原预览失效。
- 全部对象摘要合法但分支指向不存在提交的图拒绝。
- 正文存在但原生证明缺失拒绝，符号链接不当作暂缺。
- 空历史缺少原一级出生证明时明确拒绝整个预览，不返回部分成功。

运行命令为 `cargo test --locked --offline -p storage-engine --lib foreign_import::tests -- --test-threads=2`。foreign 实现阶段的 `python .github/scripts/check-rust-diagnostics.py -- cargo clippy --locked --offline -p storage-engine --all-targets --message-format=json -- -D warnings` 已通过，零 Rust warning/error；本模块 Rust 文件的 rustfmt 与 `git diff --check` 通过。随后 engine/server 组合严格 Clippy 也已通过；此后新增的 live 分支选择一致性校验仍须在下个统一节点重新检查，不能以前一轮结果代替。

这些夹具的目录 Git map 为空。新增 `history_package/directory_git.rs` 已补充非空 Git 图的校验：手动初始化身份、当前分支与暂存代数、HEAD/index 归属及合法继承、精确用户提交 marker、提交与 tree 父链一致、固定 child 提交引用、保留陈旧暂存边界以及无环闭包。Git 独立根必须反向绑定其确切 tree，所有普通提交和 Git 根仍纳入完整可达性检查；不是仅放行 `kind` 字符串。

集中构建后，`history_package::directory_git::tests` 的 9 组测试全部通过，包含完整分页往返、合法摘要但悬空 Git 引用、旧 child HEAD 钉住、继承 HEAD/index 正例以及循环/伪造 marker 负例；同一 libtest 的 `foreign_import::tests` 12 项再次全过，合计 21 项。树父链与 child 引用联合无环遍历不使用递归，提交森林通过一次 children 索引检查全部根的完整覆盖。此结果覆盖只读图验证，不等于迁入或所有 Git 工作流验收。初轮构建曾见相邻模块未使用 helper/import 的 warning，严格检查前已由其所有者消除，未添加 lint 例外。

后续静态复核补了仅限用户提交树的两条精确投影约束：marker Commit 的目录作用域内容必须等于对应 tree；父树中钉住的 child 条目和文件上下文必须等于所引用 child 提交的重定位结果。新增两组测试分别覆盖只改 tree、同步改 marker 却删 child 内容，以及换成另一合法 file context；集中构建后最终 11 组 Git 闭包测试已全部通过。该检查不改变未提交工作树的内部快照语义。

又一轮复核确认 live 已初始化目录的 Git 当前分支必须和工作选择一致，否则保存与目录提交会使用不同分支。现已按当前主命名空间一次索引校验，并增加“另一个合法已注册分支但选择未同步”和“live 选择缺失”负例；同步选择的继承 HEAD/index 正例保留，已删除历史目录不要求存在 live 选择，也不要求工作 tree 等于 Git HEAD。另加后续命名空间删除目录但保留全部 Git 历史的正例，证明没有误伤历史记录。集中构建后 Git 闭包组 12/12 全过，同一最终 libtest 的外来预览 12/12 再次通过。相关业务夹具 20/20 与 branch alias 集成 43/43 也已通过，包括删除后未提交状态和同路径新身份回归；这些相关工作流结果不代表外来迁入已具备写入能力。

最后一组因果审计补强仅作用于同一 manifest 的用户提交 marker：提交序号严格晚于初始化、直接父提交与钉住的 child 提交。内部工作快照可同序，未扩大到这些快照；跨池序号域和迁入时的映射仍未定义，不能借此假设外来写入已支持。新增同序/倒退父链、同序/未来 child 及初始化同序负例后，Git 闭包组现为 13 项，等待下一统一构建节点验证。

## 隔离协议原型审阅

另一个隔离 Python 内存原型展示了固定来源根、`previous` 历史闭包、正文暂缺、同身份不同根冲突和可重建缓存。其测试思想与本轮 held-FD、完整历史和缺失正文负例一致，但不能直接替代产品协议：它只有单一来源、简化 commit 图和 SHA256 实验地址，没有产品分支结构、作者授权、真实文件 I/O 或掉电恢复。本轮没有把其算法或摘要格式接入生产；后续逐盘权威设计应继承安全不变量，而不是把内存测试通过视为产品验收。
