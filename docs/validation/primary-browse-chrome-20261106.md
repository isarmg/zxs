# 新一级盘从发现到文件页的浏览器验收

本切片只扩充真实 Chrome runner，不修改生产服务、Web 或持久格式。它基于
一期 `8b636bda968b049c5e9b4dcfb3c3b8c6ed4c1e5a`，与文件页缓存读取、标签场景
分别维护；后续应在正式整合候选上执行完整 browser-smoke。

## 原覆盖与新增缺口

既有 `management::setup` 已通过真实页面完成无磁盘建账、登录、固定父目录
发现、候选返回/重选、确认激活，并等待真实 management status 的认证 ready、
存储 ready、recovering=false。随后立即测试普通盘转换，最后只检查 D01/N01
根按钮，尚未单独证明刚激活 D01 的空根能进入文件页。

新增 `management/primary_browse` 在同一独立首次激活夹具中、转换之前完成：

1. 在激活前安装只读观察器，保留真实 file-manager 响应与 API 写请求计数。
2. 原激活就绪检查成功后点击 Files；要求实际盘列表仅有 D01，名称是本次
   准入目录名，服务器声明一级、在线、可写，DOM 对应同一可用根按钮。
3. 真实点击 D01；要求请求为该槽的当前空根，原始响应成功、非备份/历史预览、
   条目及总数为零、快照存在、无分页游标。真实页面须完成加载、面包屑保留
   盘名、文件表为空并显示“这个文件夹是空的”。不只用空 tbody 判断成功。
4. 点击 All disks；要求新增一次真实磁盘列表读取，并返回唯一正确根。
   这段浏览不得新增 API 写请求，原选定根配置与外部保留文件仍由既有断言核对。
5. 无论成功失败，先恢复上层激活观察器，再恢复本观察器；其余转换、响应
   丢失、激活恢复、缺目录冷重启等既有场景继续运行。

观察器返回同一个原始 Response，不合成状态码/正文，不直接调用产品 API，
不保存凭据或写请求正文。每类最多保留 16 条记录，超限使检查失败；原始
网络拒绝继续传播，损坏 JSON 不变成成功，恢复后迟到响应不得补写观察状态。

## 证据边界

Node 的 12 组回归验证观察器透明性、准确请求/响应身份、负面对照、预算及
恢复，不运行 Web/WASM。Python 静态用例验证新增检查位于 ready 之后、转换
之前，并保留原 setup 顺序和 cleanup。实际 runner 的 production metadata
已通过；完整 test metadata 首轮因稀疏树未物化 Select 的 `include_str!` 输入
而失败。该同基线输入已补齐，但为让统一 Server 构建优先，test metadata 与
Clippy 未续跑；没有把静态或编译检查当作 Chrome。

已有 `e173d6b52ae2b866b805417d6e512dc228057789` 的 12 项 HTTP Router 测试
证明相关后端调用与拒绝路径；它们不能替代真实浏览器页面和生命周期验收。
本地缺少准确候选的 CLI、WASM 和 ChromeDriver，未另起大型构建，当前不得
把本场景写成 Chrome 已通过。正式执行及其提交、日志由统一 CI 记录。

## 冻结后补验

精确冻结源码未变。补齐稀疏测试输入并获得串行检查时段后，完整 browser-smoke runner test metadata 与严格 Clippy 均通过，各用时约1.77秒；没有重建产品库。首次缺少输入的失败记录仍保留。该结果仍不构成真实 Chrome／WASM 运行通过。
