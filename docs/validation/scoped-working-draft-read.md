# 共享工作稿的单容器读取

## 业务变化

普通稿的 HTTP／SMB 正文读取和显式 FILE 提交继续从相同的
`PlanningContext::draft_payload_source` 获取源，但不再为一个文件打开池内所有容器、
父目录和其它文件的稿。源使用已经服务原生增量入口的
`PublishedReplicaSource → ObservedContainerReplica` 生产准入，持有准确 owner 的
容器及父链描述符。完整稿仍认证其全部正文；段稿仍认证基线 sidecar、实际 extent
身份，读取时认证返回的范围。

原先与读取目标无关的损坏稿可能使另一个文件也无法读取。现在未选文件的正文不由
本次读取检查；完整冷启动、发布和完整快照的全局准入没有改动，不能把本接口当作
全池完整性检查。逻辑 `validate_state`、目标的当前 namespace、root／inode、
单 owner、稿大小、磁盘租约和打开后来源复验均保留。源不允许替换为同名或同字节实体。

不改任何持久字段、wire 字段、摘要、操作结果、旧收据回放或数据布局。
历史版本没有改写；未选稿、未知文件和原文件不作清理。

## 验证边界

在已有真实两文件稿选择用例中增加反例：将第一份已发表稿暂移后，第一份读取拒绝，
第二份仍按其准确保存正文读取；原第一份 inode 恢复后继续原有冷重开检查。
新增断言未执行。此提交仅完成源码审阅与 `git diff --check`，没有运行构建、测试、
格式化器或 CI，也没有真实 Samba、HTTP 或磁盘故障通过结论。
