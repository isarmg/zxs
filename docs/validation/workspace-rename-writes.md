# 当前工作区：同次写入与改名

状态：实现和回归源码已编写，仅进行官方 rustfmt 与差异检查，未编译、运行测试或 CI。必须与当前 namespace、真实 D3 和对应文件分支消费者共同验证。

## 实际变化

普通工作区可在同次保存中保留新上传内容并执行文件、目录或大小写改名。实际命名空间仍按上传后有序 namespace operations 计算；路径预计算只携带 `PortablePath`，不构造伪造的文件、版本或持久状态。名字冲突和目录形状仍由统一 namespace 实现拒绝，失败保留暂存内容。

路径事件在同次写入后绑定真正的新版本，父节点为该版本，其原版本／节点关系由新版本的既有来源证明保留。仅当准确 entry/file/history、当前发布序号及唯一原可见版本相符时接纳，不可用另一个历史版本冒充同次写入。实际新内容完成后清除 pending intent；后续独立文件保存继续原身份，不回旧路径。

当前投影和恢复从前后已认证 State 重建同一 occurrence 证明：先保留未移动的出现，再消费完整相等的移动出现；剩余移动只能消费准确可见来源，并绑定本次新建版本、同文件／历史、准确大小和唯一 source version。每个来源只能使用一次，因此原别名不能同时授权额外复制，新版本也不能让旧隐藏身份重新进入当前列表。旧 Commit、DirectoryTree 和版本不改写。

新的文件在同次改名后登记最终位置，不继承隐藏的同名文件身份。正文的原版本创建信息和选定放置路径保持原语义；改名不自动迁移正文或改变既有副本策略。

## 仍保留的破坏性重叠边界

工作区目前分别记录上传集合与 namespace operation 列表，没有跨两类动作的时间顺序或“放弃这份上传”的明确意图。任何有序 rename/delete 链最终删除某份上传，仍返回 `WorkspaceDependencyBusy`，不发布、不删除暂存字节。不能猜测用户是先删再写还是先写再删，也不能把成功回执用于悄悄丢弃上传。显式历史保存仍保持原有重叠准入边界。

## 成本与待执行范围

新增位置推导为每个上传一次当前键查询及一次操作列表遍历，O(F log N + F×O)，内存 O(F)。其中 F 是上传数，N 是当前 entries 数，O 是 namespace 操作数。不复制完整 State 或 namespace 进行预演，不增加 I/O、持久同步或新记录。

恢复中的移动匹配保留已有有序索引，多一次未匹配文件检查及新版本来源查询；不遍历所有历史版本。全部检查使用已在内存的本次状态。

新增源码涵盖普通与退出投影、真实 D3 后目录改名＋上传、旧请求回执、冷启动、同名新身份、文件路径节点准确新正文、旧历史不变、额外别名／旧版本导入拒绝，以及 destructive overlap 暂存保留。测试位于 `test/engine/unit/engine/current_namespace_workspace_overlap_tests.rs`；测试源码不是通过证据，临时目录重启也不等同真实硬件掉电。
