## 分工与执行位置

实际启动了三个独立代理：protocol 编写转换和 SPEC；search 编写独立性质、BFS、重放及搜索自测；review 核对规范、审阅两者并编写破坏规则验收。集成协调者负责运行矩阵、隔离 GitHub 验证载体、证据与交付。

云工作区只读/编辑源码、使用 Git 和静态语法检查。正式自测、搜索及反例重放只在 GitHub Actions 运行。专用 workflow 的来源模板放在 `test/publication-model/validation.yml.template`；实际 workflow 在无产品祖先的独立 orphan 验证分支中，checkout 精确工具提交。不要把验证载体合并回产品。

## 可重跑命令

要求 Python 3.11+，无额外依赖。从仓库根运行：

```sh
python3 -m unittest discover -s test/publication-model -p 'test_*.py' -v
python3 test/publication-model/run_validation.py --output /tmp/publication-model-results
python3 tools/publication-model/cli.py search --members 1 --operations 1 --replicas 1 --crashes 0 --max-states 50000 --max-transitions 500000 --max-depth 120 --max-seconds 30 --output /tmp/search.json
python3 tools/publication-model/cli.py replay /tmp/publication-model-results/counterexample-shrunken_quorum.json
```

运行矩阵先枚举小规模，再扩大到 N=3/4；每档记录操作数、崩溃、故障预算、深度、状态与转移数及所有资源截断。`BoundedExhaustive` 仅表示该明确有限抽象的队列耗尽；`Inconclusive` 不算通过。破坏规则必须搜索得到 `Counterexample` 并成功重放。原始 stdout、stderr、环境信息、精确工具/验证提交、各档 JSON 和反例均作为 Actions artifact 上传。

## 规范歧义与证明边界

基线 `docs/adr/README.md` 对 ADR 0005/0006 的状态描述与 ADR 0005 正文及 docs/10 §10.3 的“尚未启用”不同；`docs/architecture/write-flow.md` 使用“三成员”，而编号规范 docs/10 明确 N≥1。此模型采用任务明确指定的 N=1..4 与编号规范的固定 N/Q、完整新写入保护屏障；不推断免旧依赖读取已经启用。

模型不涵盖成员替换、选主、恶意写者、GC、checkpoint 裁剪、真实字节编码/哈希碰撞、实际文件系统/设备缓存行为或性能。内容仅有每操作一个版本、1 或 2 个独立完整副本。最多两槽位及两次崩溃。故障预算、操作深度和搜索资源是独立边界，结果必须同时披露。不能据此声称无限规模、真实掉电或整个产品正确性已获证明。

## 有限抽象与基线规范映射

基线固定为 `e2f33d9882cf7263412d9370b6a703e0b216357d`。本模型独立阅读规范建立转换，不导入生产实现、fixture 或实际池。它只讨论固定成员、有效单写者、最多两个顺序槽位的安全性；不证明产品实现正确或真实掉电耐久性。

### 状态与真实边界

`Config` 限定 N=1..4，完整副本数 r=1..min(2,N)，顺序操作数 1..2，进程/断电崩溃总数 0..2。内容目标固定为前 r 个不同成员，抽象冻结且合法的来源路由；每操作正好一个版本。单决定槽位串行，阶段内各成员独立执行，所以可以得到非前缀完成子集。内容生成与来源/ACL/策略解析不在本模型内；不变量只检查已冻结合法候选的发布协议。

每个槽位、成员有八种 `Artifact`：内容、PREPARE 与其不可变依赖、ACCEPT、FINALIZE、commit-proof、PUBLICATION、publication-proof、RECOVERY_RESOLUTION。前七种按阶段屏障排序，恢复中止记录有独立微步骤。每种材料具有：

- `data`：操作系统当前可读字节，0 不存在/空，1 完整，2 截断，3 损坏。
- `stable_data`：已经到达稳定介质的字节，取相同四种值。
- `file_synced`：文件同步成功返回的本进程事实；稳定字节可能在同步失败后已经存在。
- `entry`：当前可见正式名称；临时写入和正式安装分开。
- `dir_synced`：该名称已完成父目录同步。
- `done` / `failed`：协调器收到的成功/失败，独立于介质事实。

`write → file_sync → install → directory_sync` 各自是可中断转换。错误分支覆盖无副作用及已经产生副作用的错误返回；故障预算允许每个成员独立失败，因此预算至少 N 时包含任意成功/失败子集。对象、证明和日志记录统一使用“新建命名文件/新段”的较强持久化义务，而不是精确复刻当前追加日志的系统调用。已存在段的 append/目录同步优化不在本模型结论内；不能拿这个模型授权删除实际 fsync。

进程退出保留操作系统字节和可见目录项，不模拟断电。断电对每个尚未同步的写入独立枚举未落盘、完整、截断、损坏，对每个未同步正式名称独立枚举保留或丢失；不强迫成员前缀。已经正确同步的字节/名称在断电后保留，假设设备遵守刷新契约；设备谎报与真实控制器行为不在结论内。稍后内容损坏通过独立故障转换表达。

`read_fault` 是明确不可读；离线、不可读、日志损坏和完整日志确无记录不是同一种观察。安装名称存在但零字节/截断/损坏的日志不能充当不存在。成员临时返回只能恢复原固定身份；本任务不替换成员、不选主、不迁移、不 GC、不裁剪 checkpoint、不测磁盘性能。

### 观察、恢复与历史见证

`observations` 每成员取 -1 尚未观察、0 完整可信无候选、1 ACCEPT、2 正常 PUBLICATION、3 不可信/不可读、4 恢复中止记录、5 降级 PUBLICATION。只有 0/1/2/4/5 可以计入固定 Q。恢复可以从任意 Q 个可信旧成员开始；在任一可信成员见 ACCEPT 时保留候选并补交，不能根据超时直接中止。仅完整 Q 个成员无候选才能生成恢复中止；中止记录在这些成员逐个写入、文件同步、安装、目录同步，达到 Q 后才产生中止结果。第二次崩溃可以发生在这些微步骤之间。已写入的有效恢复中止记录携带原完整观察证据，返回旧盘上的少数 ACCEPT 不得使已中止槽位复活。

正常重护必须等固定 N 全部在线、可读，并显式观察剩余成员，再从实际读取到的 PUBLICATION payload 决定原正常/降级结果。恢复决策不读取全局历史见证来猜结果。没有原正常发布证据时，任一所需路由上可验证的同版本完整副本可作为补齐原目标的来源；每次恢复内容写入再次要求存在这样的实际可读 FULL 来源，不能由候选符号凭空造正文。全部来源不可恢复时才可生成明确降级结果；仍需全部 N 成员元数据。这里恢复计划、隔离及候选身份固定且唯一，符号化为 `recovery_mode`；不模拟多计划竞争或成员代际切换。

`publication_origin` 和 `publication_result` 是 PUBLICATION 记录携带的符号化 payload：前者固定记录生成时已经具备的内容/提交证明回执，后者固定正常或降级结果。只有实际读到完整 PUBLICATION 字节才能沿用该 payload；不能凭这些字段在没有记录时恢复成功。`normal_publication_seen` 只在实际读取正常 PUBLICATION 或当前写者安装完整正常 PUBLICATION 时建立，开始新一轮恢复或新槽位时清除；仅计划恢复为正常结果不产生该事实，后续新发现的内容损坏仍须阻止首次正常发布。当前内容损坏不抹除历史保护事实。缺失/损坏的元数据依赖图不在本模型内被修造；PREPARE 代表已验证的准确完整依赖闭包。

`known_publication`、`decision_witness`、`publication_witness`、`abort_resolution` 是供安全性质检查的历史见证：见证从真实 Artifact 字段捕获，不由调用方自报。`state_versions`、永久 `results`、`events`、`publish_count` 记录外部曾经观察到的业务事实；跨崩溃保留是历史 ghost trace，不意味着真实进程内存幸存。恢复重新推进同一槽位时依靠持久证据重放，并与这些历史事实比对；第一次公开必须同时更新状态、收据和事件。已有结果、事件及原始见证重放不再追加。索引失败仅改变 `index_failed`，当前内容健康由 Artifact 独立表达。

原 ID 重试与摘要不匹配在终态显式建模；未决阶段重复查询/重试返回待确认且不改变业务状态，归约为 stutter。模型不把回复发出等同于客户端收到。正常业务响应仅在完整发布闭包后；回复丢失保留原 ID。诊断 `recovery_round` 在 3 饱和，它不参与协议/性质，以避免仅诊断计数产生无限状态。

Q 个成员完成中止不释放正常新写入：掉盘返回后还须把历史 RECOVERY_RESOLUTION 向全部固定成员持久化，才能进入下一槽位。在线状态不是恢复计划隔离或前缀闭包证明；缺少该闭包时保持阻塞。

### 明确歧义与边界

基线规范没有给出某一具体文件系统在未同步时的崩溃字节集合。本模型选择上述保守有限集合，不能把穷举结果推广为真实文件系统掉电验收。规范允许更换新配置的显式恢复，但本任务明确排除成员替换；本模型只恢复同一固定成员，永久缺盘路径停留只读/阻塞，Q 中止不代表恢复可写。恢复计划本身的完整格式、日志帧/哈希链解析及候选依赖图验证属于另外真实入口测试任务，不从抽象 Artifact 的 FULL 推导解析器安全。

模型使用单版本、确定且相等的候选符号，不建模恶意协调器伪造全部回执、同槽不同候选、授权变化、成员封印解析或错误设备替换。阶段内并行只分析完成/失败顺序；没有吞吐量、真实线程、锁实现或尾延迟结论。搜索去重不交换成员身份，保留每成员和槽位、字节/名称/回执、观察与历史见证。资源/深度边界未闭合时只能给 Inconclusive；定向反例与自测不是该边界下的完整穷举证明。

## 故意破坏规则的反例与产品故障测试映射

这些是故意破坏抽象规则的反例，用来确认检查器有检出能力；不是对产品实现的缺陷断言。原始机器轨迹保存在 `test/publication-model/evidence/run-*/results/counterexample-*.json`，同目录 `replay-*.json` 保存逐动作、逐状态摘要重放结果。

| 变体 | 最短轨迹动作数 | 命中的独立性质 | 产品故障测试映射 |
| --- | --- | --- | --- |
| `shrunken_quorum` | 21 | `fixed_quorum` | N=2 完成准备后临时掉一成员；另一成员 ACCEPT 完成仍不足固定 Q=2，不得宣称决定成立 |
| `early_ack` | 16 | `publication_barrier`、`fixed_result` | 已决定但 FINALIZE／本盘证明／PUBLICATION 尚未全体完成；不得确认成功 |
| `omit_sync` | 5 | `durability_barrier` | 正文写入、文件同步、名称安装完成但父目录未同步；不得越过内容准备屏障 |
| `timeout_rollback` | 12 | `no_timeout_abort`、`abort_resolution` | 第一份 ACCEPT 已发出后 RPC 超时；没有完整 Q 无候选观察及耐久恢复中止记录，不得返回确定未发生 |
| `lost_binding` | 39 | `unique_publication` | 成功响应丢失后沿原 operation_id 重试；永久摘要绑定与原收据必须阻止生成第二个业务效果／事件 |

动作数来自已执行的 BFS 反例，具体配置、故障预算和工具 SHA 以同目录 JSON 为准。动作数只在对应模型/配置及已检查的 BFS 深度内有最短性保证；不代表真实 I/O 最短故障序列。发现反例后搜索即停止，不把剩余图说成穷举完成。

缩减依靠从初始状态进行 BFS，父指针返回最少动作的可达违规前缀。每步保存状态 SHA256，重放必须检查动作启用、实际状态摘要和同一具名违规；修改动作或摘要的负测试必须失败。`test_mutations.py` 还要求这些轨迹不能作为 `correct` 变体的同一执行重放，防止只靠脆弱或无关断言产生假阳性。

恢复深层窗口另由 `test_recovery.py` 和 `test_model.py` 的定向轨迹覆盖：Q 中止而永久缺盘保持不可写、旧 ACCEPT 不复活、恢复中第二次断电、单处正常发布后内容损坏沿用原结果、无正常发布且无好源时明确降级、一好一坏副本先补齐、计划正常恢复后新损坏不得冒充历史正常结果。这些轨迹覆盖不等于较大配置从根的完整穷举。

### 规范差异与解释边界

基线 ADR 目录对 0005/0006 的状态摘要写“条件启用”，但 ADR0005 正文及 10.3 写“尚未启用”；`write-flow.md` 描述三成员实现，而 10.2 明确 N≥1。这里采用任务给定 N=1..4 及编号规范的固定 N/Q 和发布屏障，不推导旧依赖免读或额外健康保证。

成员替换、选主、GC、checkpoint 裁剪不在抽象内。规范提及恢复中止后返回旧盘须按恢复计划/代际隔离；固定成员的临时离线/返回只允许沿同一候选恢复，不能自行补造成员替换或缩小配置协议。

### 源码审阅发现与处理

独立审阅发现并推动修正了以下工具问题；这些是模型/搜索工具的修正，不是生产缺陷结论：

1. 搜索深度边界原先检查了超出 `max_depth` 的下一条边；现在严格区分边界内反例与未完成前沿。
2. 断电原先只枚举名称存活、将全部未同步字节丢弃；现在分别枚举字节回写结果与未同步名称存活。
3. 恢复中止原先为单步原子动作；现在为各观察成员上的独立写入、文件同步、名称安装及目录同步，允许第二次崩溃中断传播。
4. 首次 State 应用时才获取保护见证会把后来的正文损坏混入历史结果；现在 PUBLICATION 的原始保护证据与当前健康分别保留，重复应用不改写原见证。
5. 恢复成功原先直接读取全局历史标记；现在恢复在全成员恢复传播前读取剩余实际成员，按可观察发布记录选定正常或降级结果。
6. 性质原先只检查“不可读不等于不存在”；现在同时核对已安装日志完整性、恢复中止多数持久证据、阶段同步屏障及首次发布见证与实际字段的一致性。
7. 搜索原先排序并物化全部后继，断电组合可能在预算检查前膨胀；现在使用固定生成顺序逐条消费，并为重放加入显式后继检查上限。
8. 双副本恢复原先因任一目标损坏直接降级；现在只要仍有可读、完整且身份正确的同版本来源，就先重建原目标并正常发布。每次恢复内容写入重新要求实际好源，避免从候选符号凭空制造正文；独立定向测试覆盖一好一坏的双副本恢复。
9. 计划恢复为正常结果曾被当作已有正常发布证据，可能跳过恢复后新损坏的守卫；现在用单独的实际观察事实区分两者，定向测试覆盖内容重护后再次损坏。
10. Q 中止后掉盘返回曾只检查在线状态就允许下一槽位；现在要求所有历史中止记录向全部固定成员完成持久化，性质独立检查，定向测试覆盖补齐前阻塞和补齐后开放。

`test_mutations.py` 包含七项合法转换反例/重放测试及三项独立 oracle 敏感性测试。后者故意构造无效状态来验证性质能发现损坏观察、缺失中止证明和伪造发布见证；它们不是可达协议反例。每种故意破坏变体还要求命中对应的具名性质，且其反例不能作为正确变体的同一轨迹重放。

### 结论与抽象限制

首阶段独立交付审阅已核对四轮逐文件 SHA256、API artifact 摘要、工具与验证提交，以及去除模块说明字符串后的源码 AST／workflow 字节一致性。该记录仅描述首阶段当时的审阅范围；本轮发现的验证强度缺口及补强另见下节。较大配置的八个 Inconclusive 档位仍未完成，不扩大结论。

转换与性质在不同模块、由不同代理编写；独立审阅不调用生产恢复实现判定对错。固定 N/Q、阶段同步、全成员发布、永久结果及事件一致性有独立性质，变异测试用于检验这些性质的敏感性。

`results`、`events`、`state_versions` 及历史保护见证是跨崩溃保留的抽象逻辑历史，用于检验对外事实不回滚和业务效果不重复；它们不表示重启后的 RAM 被保留。恢复阶段的准入与可观察证据另行约束。模型没有逐字节重建真实 State、序列化格式、索引或生产幂等存储，因此不能用它证明这些具体实现正确。

定向轨迹测试可以覆盖深层窗口，但不等于从根穷举。只有机器结果为 `BoundedExhaustive` 的档位完成所声明有限图；`Inconclusive` 不算通过，反例最短性只适用于完成到该深度的 BFS。软件模型不证明无限历史、实际掉电、真实设备同步实现或整个产品正确。

## 见证与深层恢复验证补强

首阶段的见证检查主要约束 mask 人数，不能独立保证转换没有捏造一个人数足够的 mask；恢复定向测试原先也没有逐边调用独立性质。这是模型验证强度的遗漏，不是已确认的生产缺陷。本轮在独立提交中补上：

- `decision_evidence` 在决定见证首次建立时核对实际 ACCEPT 的完整字节、稳定字节、名称及目录同步，并检查固定 Q 和真实成员全集合。
- `abort_evidence` 在中止观察见证建立时核对固定 Q 的完整无候选观察及实际日志，拒绝已有决定/发布/中止记录或损坏日志充当不存在。
- `abort_resolution_evidence` 核对首次持久中止见证对应的真实 RECOVERY_RESOLUTION 和之前已建立的无候选见证；以后保留历史见证，不因后来损坏重判。
- `test_witnesses.py` 用明确字段构造满 Q 但缺真实记录、各项耐久字段错误和伪造中止证据的负例，同时保留非前缀、失败返回但实际持久、读后掉盘和恢复中再次崩溃的合法对照。它们是独立性质的敏感性测试，不是假称可达的产品反例。
- `test_recovery.py` 的 `take()` 和 `advance_publication()` 现在每条实际边均检查 `properties.check()`，并用人工坏后继证明助手不会跳过安全性质。

首阶段多成员故障根搜索的最大触及深度为：N=2 故障恢复 17；N=3 的非前缀故障/恢复/两槽位分别 10/7/9；N=4 分别 8/6/9。它们均在 25,000 状态时截断，不能称为多成员恢复穷举。最大触及深度也不表示该深度层已经完整检查。

### 选定合法前缀后的局部搜索

`deep_search.explore_suffix()` 只从 `initial(config)` 沿提供的合法动作逐边检查，并保存每一步摘要，得到选定前缀的种子；不能直接注入任意 State。随后对该种子的全部启用后继进行 BFS，无动作过滤或额外剪枝，也不重置前缀已消耗的故障/崩溃预算。前缀和后缀资源、深度及计数分别记录，完整反例包含原始初态至违规的全部动作，可用现有 `replay()` 核对。

运行入口为：

```sh
python3 test/publication-model/run_deep_validation.py --output /tmp/publication-model-deep-results
```

矩阵包含 N=2 的 ACCEPT 准备点、N=3/4 的非前缀 ACCEPT、恢复保留候选、恢复中止写入中断及单处 PUBLICATION。每档最多 20,000 状态、200,000 转移、20 步后缀、15 秒，另限制前缀长度及每步可枚举后继；原始 JSON 保存前缀来源、请求/完成长度、摘要重放、后缀检查阶段和实际深度。`LocalExhaustive` 仅表示该选定前缀后的可达图耗尽，绝不并入从根穷举的档数；所有资源/深度截断仍为 `Inconclusive`。最大总轨迹深度是触及量，不表示完成了该层全部路径。
