# 发行验收清单

[发行流程](../release.md) · [工程规范](../20-engineering.md) · [许可资料](../../compliance/README.md)

本清单用于决定一个**精确提交和它生成的实际归档**是否具备发行条件，不表示勾选之前已经通过。准备发行不等于创建标签或公开 Release；不得用上一个提交的绿色 CI、源码测试或手工打包替代候选提交的发行验收。

## 1. 固定发行范围

- 原生服务的当前发行基线为 Debian 13 amd64 GNU ABI：单个 `zxs` ELF 内嵌 Web，通用运行库由 Debian 提供；记录实际验证的内核、GNU libc、文件系统和挂载选项。其他发行版、ABI 或操作系统不因共用源码而获得支持承诺。
- 浏览器端是管理界面，不提供文件上传、下载或预览；不提供桌面和移动原生 App。分别记录实际浏览器版本，Chrome 冒烟不等于所有浏览器通过。
- 最小部署是一块系统盘和一块数据盘；不要求配置多级备份。单数据盘发生永久故障时，管理界面可进入不等于文件内容可恢复，也不构成备份保证。
- SMB 使用系统 apt 安装的 Samba 和发行资产中的独立预编译 VFS。核对 `VFS-BUILD.json` 的精确 Debian Samba 包版本、ABI、源码身份及模块摘要；模块版本不匹配不得安装。ZXS 不内嵌或自动管理 Samba，交付文件不等于已配置系统账户、独立 SMB 凭据、Unix socket 或服务。
- 保持当前存储格式严格校验，不隐含旧格式兼容、自动迁移或任意版本降级承诺。

## 2. 自动验收证据

候选记录须包含提交 SHA、工作流运行链接、运行次数、结论和产物 SHA-256。失败、取消、跳过、仍在运行或缺少日志都不能记为通过。

摘要用于核对下载文件与记录的一致性，不是独立的发布者签名。应从核实的仓库及对应工作流取得材料；不能因为归档与同来源摘要互相匹配，就声称已验证发布者身份或具备签名供应链证明。

| 检查 | 最低证据 | 不证明什么 |
| --- | --- | --- |
| 静态与结构 | 工作流、架构策略、来源清单、脚本回归、格式与严格 Clippy | 不证明业务授权或数据恢复正确 |
| 数据与服务 | 当前业务测试、真实 Unix socket 回归、故障注入、恢复与完整性检查 | 不等于物理断电验收 |
| 依赖与安全 | 来源校验、Foundation 分片、当前公告与撤回状态完整扫描 | 扫描无发现不是没有未知漏洞 |
| Web | 正式 WASM 构建及真实浏览器会话、初始化、恢复、账户操作冒烟 | 不代表其他浏览器或长期运行已测 |
| SMB | 同提交固定 Samba SDK 构建、ABI 和 FFI 检查 | 不等于真实 SMB 客户端互操作 |
| 发行资产 | 校验实际待交付的七文件集合；使用其中单 ELF 的内嵌 Web 运行验收，并核对独立 VFS 收据、资料归档、许可及 systemd 模板 | 源码目录或旧缓存中的程序不能替代交付字节，资料归档不是启动依赖 |
| 组装与发布演练 | 严格产物集合、摘要、草稿上传/下载校验故障回归 | 假的发布客户端回归不等于已公开发行 |

优先使用发行工作流的 `workflow_dispatch` 构建演练：它不创建标签或公开 Release。若尚未执行完整演练，应明确保留待验收状态；普通 CI 成功不自动变成发行工作流成功。

## 3. 实际部署验收

只在明确的一次性测试环境执行破坏性场景，不能指向现有业务盘或真实管理员凭据。记录操作前后完整性结果和环境，而不是只记录“服务重启成功”。

1. 在干净 Debian 13 amd64 环境取得同一候选/版本的七文件集合，按 `INSTALL.md` 校验 `SHA256SUMS`、`BUILD.txt` 与 `VFS-BUILD.json`。使用交付的单 ELF 启动内嵌 Web，不传 `--web-dir`，不要求旁置静态目录或解压资料归档才能启动。按需审阅资料归档中的 systemd 模板，用实际服务账户核对程序和配置可读性，更改示例路径后确认服务正常启动和停止；另外核对系统 Samba 版本、实际 `MODULESDIR/vfs/` 下的 `zxs.so`、`vfs objects = zxs` 和 Unix socket 配置。
2. 使用一块测试数据盘完成首次 Web 初始化、管理员登录、退出、改密、磁盘登记及文件元数据管理。验证未登录、旧会话以及匿名或 guest SMB 请求被拒绝。
3. 用真实系统 SMB 客户端完成创建、读写、改名、目录列举、并发打开及断线重连；验证读取字节、访问控制、版本和历史，而不仅是连接成功。
4. 在受控测试中让数据盘不可用，再重启服务，确认 Web 管理与认证仍可进入、状态明确显示降级，业务写入被阻止且不会偷偷初始化替代盘。恢复原盘后验证设备身份与恢复过程。
5. 使用合成数据验证损坏内容、日志或索引的诊断与失败边界。索引重建不得把损坏正文认作完整版本，离线检查不能隐式修复，离线导出不能覆盖已有目标。
6. 进行资源与容量边界测试：磁盘空间不足、元数据限额、正常停止、强制终止及恢复。物理断电需另行记录设备、缓存与文件系统条件；进程终止和模拟 I/O 错误不能冒充断电测试。
7. 记录实际管理界面与 SMB 大目录、大文件及持续运行的资源表现。没有测试的容量、并发和性能数字不写入发行承诺。

## 4. 许可和发行决定

公开分发前核对实际源码和二进制依赖闭包所需的版权、许可证及通知。活动依赖和只保留历史来源的退役组件必须分别说明，来源清单校验通过不能代替缺失许可资料复核。未闭环项及其证据统一见[集中合规说明](../../compliance/README.md)，不以重命名、合并目录或删除来源记录掩盖问题。

发行负责人应记录：

- 候选提交、树、版本、七文件集合的摘要及完整演练链接；`SHA256SUMS` 覆盖其余六项，另记录下载包装归档（若有）的摘要。七项为单 ELF、独立 VFS、资料归档、`VFS-BUILD.json`、`BUILD.txt`、`INSTALL.md` 和 `SHA256SUMS`。
- 本清单各项证据，以及仍未执行的环境和场景。
- 未关闭问题、影响范围和明确的发行支持限制；安全、数据完整性及分发资料问题不能仅因 CI 成功而关闭。
- 是否允许创建发行标签并公开 Release。准备阶段不自动作出这个决定。

没有证据的项目保持“待验收”。只有测试环境可以建立的证据，不应要求用户在生产盘上尝试来补齐。

原生 target 默认值、编译覆盖存在性及 C／汇编 runtime dispatch 的证据边界见[原生构建契约](native-build-contract.md)；默认 CPU 查询不能替代发行产物最低 ISA 验证。
