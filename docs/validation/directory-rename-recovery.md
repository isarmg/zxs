# 目录分支重命名的原请求恢复

## 已核缺口与边界

固定基线 `6043e77cf082a6a317374d7b0636e2a3ff2bd5fd` 中，目录分支创建、历史节点建分支和 checkout 已保留原请求。重命名仍走仅内存的通用 mutation，刷新会丢失完整 PATCH 输入。本片将实际“重命名分支”原位编辑入口接入已有目录操作恢复队列，不新增服务端端点或存储历史字段。

依据：[目录仓库的永久幂等](../design/directory-git-repositories.md#并发与永久幂等)、[分支标签改名](../design/branch-system-logic.md#154-改名与下载)。只改分支标签，不生成目录提交、文件节点或工作树，不自动 checkout。

已提交目录节点说明仍直接来自不可变 Commit.message；独立可变注解、格式与恢复契约尚需单独设计。目录分支合并仍是待确认能力，不能用本片代替。

## 实际操作闭环

- 原位编辑仍遵守 Enter 保存、Esc／失焦取消、128 UTF-8 字节及现有命名规则。动作入口保留编辑器传入的仓库与分支身份。历史行来自独立分页，允许编辑非当前分支，不用 viewed 分支或工作列表替换目标。既有历史详情门槛核对会话、目录、listing generation 和 namespace head；原位编辑器拒绝失效位置或会话。
- 首发前捕获实际编辑行的规范 ID、提交名称、原 operation ID 和账户，保存到已有站点恢复记录并读回确认。存储失败不发送；不把显示路径当作分支身份。
- 恢复由同一 typed 请求重建原 PATCH 路径、完整 body 和请求摘要。刷新／重新登录只查询原操作号，404 或未知结果不生成新号；只有用户明确重试才发送同一请求。
- 现有服务端 rename 没有树 CAS，也没有 result.input／repository_id。客户端用原摘要绑定 repository_id、directory_branch_id 和 name，另严格校验既有结果的分支、名称、合法路径与树 ID。不得凭后来分支名称判断原结果，也不把旧观察树强加为新契约。
- 未知结果继续写入围栏；原请求重试的拒绝不证明首次未发布。当前凭据及命名冲突仍由原 HTTP／Engine 入口检查。
- 完整终态收据才进入本机清理。清理失败保持围栏，重试清理不重发 PATCH；旧会话响应不更改新会话，恢复不清除其他分支预览。

## 定向验证与未执行范围

新增独立 `directory-rename-recovery` 组选择：
1. 新的原请求固定字节、摘要、严格恢复、回执目标、原操作、会话／导航、冲突和清理围栏测试。
2. 实际非当前历史分支行、同仓旧目标／迟到代次回调，以及已有原位编辑、通用动作准入和操作轮询的原生行为测试。
3. Web 产品原生库检查与生产 WASM 编译，分别记结果。
4. 已有 HTTP rename 解码及真实 EngineBackend 标签改名、碰撞、摘要、永久重放与撤权回归。

旧 `historical-directory-web`、`web-recovery-principals` 测试及 56／131 上限原样保留。新增测试不挤占这些预算；共同构建去重，仍受 16 构建门禁。

本片未本地编译、运行测试、rustfmt 或验证脚本。上述均是待 CI 执行的选择，不是通过声明。真实浏览器的 localStorage 失败、刷新／跨标签页交错、页面布局及实际输入事件仍待验；原生状态测试与 WASM 编译不代替浏览器验收。服务端未改，完整 Engine 冷开、全工作区、SMB、其他恢复分支不由本片声称验证。
