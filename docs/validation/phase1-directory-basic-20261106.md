## 必须保持的行为

- 普通保存和状态读取不初始化独立目录仓库。初始化必须明确且绑定命名空间基线。
- 工作树、显式暂存 index、用户提交 HEAD 分开。暂存 A 后保存 B，提交只冻结 A，正常读取继续返回 B，B 仍是未暂存改动。
- 只有未暂存变化时，提交不能吸收它，创建/切换分支也不能静默丢弃它。
- 子仓库独立提交。父只固定明确审阅的子提交及相对挂载路径；子的新提交或 dirty 工作内容不自动进入父提交。
- stale index/工作树、所有权边界变化或路径身份替换必须拒绝；操作重试依旧用原 operation ID 和请求摘要。
- 删除、同路径重建和移动不复活工作区删除，不改写固定历史，不合并不同稳定身份；冷重开保留 index/HEAD/工作树区分。

当前标签生产入口属于文件节点。此次不增加目录标签协议，不把二期目录数据库模型中的标签记录当作现行可写功能。目录数据库三位置安装、目录范围定义、真实 publication 绑定与冷恢复安装仍是单独的二期工作。

## 定向运行计划

公开 Engine 的 `directory_git_index` 目标共有 10 项：

1. 暂存/提交与后续保存分离，并跨冷重开保持。
2. 未暂存工作不能被提交或分支操作丢弃。
3. 重命名子挂载路径时保持子提交 pin。
4. 仅暂存子引用不会顺带暂存父文件修改。
5. 仓库根移动不改变内部相对子 pin。
6. 已暂存文件提交不复活之后的工作删除。
7. 已暂存删除不删除同路径新建的工作文件。
8. 删除的子边界不能被同路径替代身份复用。
9. 插入中间独立仓库只改变相应直接父 pin。
10. 暂存后移动只改变工作位置，旧审阅快照及历史正文在重开后仍保留。

还需在同一候选来源核对既有目录初始化/提交/分支、历史分页、stale/权限拒绝、HTTP 与 Web 接线。真实 Chrome、完整 CI、故障注入和真实部署分别报告，不能用静态检查、旧二进制或仅编译成功替代。
