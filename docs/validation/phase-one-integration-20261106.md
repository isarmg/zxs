## 独立正式 core 门禁

新增 `Phase-one core admission and persistence` CI job 与原 workspace 长测并行，保留原 workspace、Chrome 和 Samba 验收，不减少原测试工作量。

门禁通过根 workspace 和锁文件的正式 Cargo 调用生成七个测试产物。只从本次成功的 Cargo JSON 选择准确包、源文件、测试类型与特性的 executable，并校验实际产物摘要。先枚举全部预期名称，再运行六十项：

- Server 私有单测二十九项：管理槽和 TCP 四项、流式请求授权／取消九项、SMB 新文件三项、名称准入四项、普通导入恢复两项和已有初始化保护七项。
- 公开 HTTP 集成十二项。
- 公开 SMB bridge 集成三项。
- 目录 index 集成十项。
- 标签缺陷回归三项、冷重放两项。
- 标签契约回归一项。

缺少名称、重复产物、错误 source／features、零测试、ignored 或未完成结果均失败。Server 必须有 default/core；其正式 dev 图启用既有 Engine fault-injection，不能用无故障注入的旧生产 rlib 替代。证据保存在同次 CI 的 phase-one-core artifact。

公开 SMB bridge 的本地编译和 Clippy 已完成，但三项原生 Unix 连接在进入业务前被本地环境拒绝，故没有通过结论。它们与私有 SMB 三项均须由正式 CI 实跑；真实 Samba/VFS 网络验收仍是单独的原有 job。
