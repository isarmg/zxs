# 独立于存储的管理面

守护进程在系统盘上拥有独立于数据盘根目录的管理目录。HTTP 资源、登录、注销、改密和宿主诊断的请求路径不打开存储引擎。引擎打开/恢复由一个有界后台工作线程执行；线程挂起仍占用准入槽，HTTP 超时不得无限创建替代线程。

<a id="authority-and-revocation"></a>

## 权威与撤销

`management-auth.json` 是唯一管理员凭据和会话的持久化主权威。引擎副本只作灾备快照，不能用于授权回退；旧 `auth.json` 缓存不能授权离线登录。系统状态目录中的持久 `management-authority.json` 围栏阻止主权威丢失后自动重放旧引擎凭据。主文件缺失或无效表示需要恢复，不是空安装或默认管理员。

认证目录必须由服务账号拥有且权限为 `0700`；初始化只以私有权限创建缺失目录，不自动修复已有目录。相对目录以启动工作目录为基准，目录路径不接受符号链接。`auth.lock` 使用平台统一的描述符相对打开与排他锁，要求服务账号拥有的 `0600` 普通单链接文件，并在取得锁后复核 inode。链接、FIFO 和不安全权限不会成为认证锁；凭据读取使用持有的文件描述符及 4 MiB 字节上限，文件增长也不能绕过上限。上述检查失败时保持认证关闭，不隐式重建管理员。

管理员凭据变更先提交到系统主权威。异步复制最新凭据快照期间关闭存储准入，只有匹配当前状态的副本才能重新开放。会话不写入灾备副本；副本失败不能回滚密码变更或会话撤销。

受管理请求取得引擎锁后，在实际分派前按当前主权威重新验证会话过期、登出和凭据代数。管理权威消失时不回退到引擎快照。已获准执行的操作可能完成，此边界不回滚已经执行的工作。管理认证从不获取引擎锁。

<a id="states-and-recovery"></a>

## 状态与恢复

公开 `/api/management/status` 仅暴露管理存活、认证可用性和存储状态：`ready`、`read_only`、`unavailable`、`unconfigured`、`recovery_required`。认证可用性为 `ready`、`busy`（凭据操作占有状态锁）或 `recovery_required`。`busy` 是瞬态，不表示凭据损坏，不应导致登出或恢复。状态探测不等待该锁，也不泄露磁盘路径或凭据。仅缺少存储配置不足以授权初始化。

存储观测和能力缓存；观测过期十五秒后关闭存储准入，不无限保留就绪声明。宿主遥测继续可用，磁盘采样标为不可用。数据操作在无准入时失败关闭；就绪/能力查询与受保护初始化使用独立管理容量，不受阻塞数据请求耗尽。

已认证管理员可请求 `/api/system/storage/retry`。恢复串行执行；请求、观测器或传输仍持有故障引擎时不能替换，`STORAGE_DRAINING` 明确要求持有者完成后重试。永久阻塞的磁盘调用可能需要重启守护进程或宿主干预；重启不会重置认证。

首次初始化和显式灾备恢复使用独立的受保护 Web 协议。没有有效主权威时，需要本地且有时效的 bootstrap 能力。恢复旧凭据须确认旧密码可能重现；恢复会话一律丢弃。经认证的存储恢复保留有效系统主权威。

初始化补全比凭据恢复更窄：仅本次 Web 初始化持久意图与初始化后证明绑定的原始空池，且尚未发布权威或凭据，才可补全。任何既有权威标记均阻止此路径，即使主文件缺失也如此。其余中断阶段失败关闭，需显式本地诊断。

本地配置预设是标识符，不是浏览器提供的路径或任意 JSON。HTTP 启动和预设列表不读取文件；授权预览只读选中的受保护文件，隐藏磁盘路径并返回配置摘要。初始化写入前再次核对摘要，防止本地修改静默替换拓扑或策略。

<a id="unconfirmed-browser-actions"></a>

## 浏览器动作结果不确定

修改密码的传输失败或响应中断不能证明密码未变。Pending/Unknown 状态阻止重复改密与应用语言重载；不会自动标记为已退出，也不扩大为全部业务写入门禁。应先显式退出，再核实哪个密码可用，不反向更新或自动重发改密。成功改密会撤销全部会话；不确定的持久写入继续受认证恢复围栏约束，不通过删除主库或重新初始化解决。

系统不存在账户列表或账户更新接口，无法通过旧账户快照推断密码结果。其他带 operation_id 的存储操作只由原操作终态回执确认，不用新 ID 覆盖未决结果。

登出结果未确认时，当前页面只为重试撤销而保留旧凭据。直到登出成功或服务端确认会话已无权，页面不可登录、恢复会话、初始化或执行业务动作。持有待撤销意图的页面不能以新登录替代失败登出。

Web 与内部 HTTP 客户端只接受精确的 `{"logged_out":true}` 作为登出成功回执；空成功响应、缺失/错误值和额外字段都不能清除待撤销凭据。Web 改密也只接受精确的 `changed:true` 与 `reauthentication_required:true` 两字段对象，否则保留结果未知围栏，不以 HTTP 2xx 单独证明完成。

这些浏览器围栏与待登出意图仅在内存中，不是持久或跨标签协议。应用发起的语言重载会被阻止，但手动刷新、关闭标签、浏览器重启或独立标签可能丢失本地意图，并尝试恢复仍有效的服务端 cookie。这些动作都不能证明登出或解决未知改密结果。保留失败登出页面并重试撤销，不把新登录或新页面当作旧会话已撤销的证明；持久跨标签撤销意图尚未实现。

<a id="http-resource-isolation"></a>

## HTTP 资源隔离

密码验证在共享凭据状态锁之外执行；发布会话时在锁内重新核对凭据代数、密码哈希和恢复围栏，防止并发密码变更后凭旧证明发会话。持久发布仍串行。

每个路由器在调度阻塞工作前，最多准入八项会话验证和登出任务。上传状态授权、后端状态及暂存清点共用一项同时持有后端和管理员主体读取准入的任务。HTTP 取消后，许可仍由实际阻塞工作持有。

遥测状态与历史共用独立的双任务池，准入直到阻塞工作完成才释放，包括 HTTP 取消之后；它们不消耗数据后端或管理就绪容量。

变更 API 在收集请求体前有独立的 64 请求入口上限。普通 JSON/登录请求体除字节上限外有 30 秒总期限；初始化仍用更严格的十秒外层期限。流式上传保留独立上限/期限。只读健康和管理状态请求不消耗变更池。这里的上传指保留的 HTTP API，不是 Web 产品上传功能。

守护进程在启动状态 I/O 前注册 `SIGINT` 与 `SIGTERM`，不等到 HTTP 开始服务才订阅停止信号。处理停止请求时立即关闭新请求准入，并请求 HTTP 优雅关闭。可选 SMB 启动等待及目录准备不占异步工作线程；停止时立即关闭其准入和空闲连接，不等待 HTTP 排空。HTTP 完成、失败或服务 future 取消都会释放所拥有的桥接；它不是脱离所有者的后台监听器。可选桥接失败仍保留管理 HTTP。

已接纳的 HTTP 连接有五秒客户端网络宽限，届满后断开仍未结束的连接，避免空闲长连接或迟迟不收取响应的客户端无限拖住网络关闭。该宽限不是持久化超时，也不是总停服期限：不能以丢弃 HTTP future 取消已经接纳的发布或阻塞工作。已经运行的 SMB/后端阻塞任务持有许可和恢复证据直到返回；socket 关闭可唤醒空闲 RPC 读，但不能取消文件系统调用。

原生管理工作同样需要排空：关闭入队入口，等待当前工作，停止后不再接纳后继任务。HTTP 初始化失败或服务 future 取消后，必要排空仍由运行时阻塞任务承担。启动状态 I/O 或运行期内核 I/O 不返回时，必要的磁盘/发布等待和 Tokio 阻塞任务退出仍没有时间上界；注册了信号不代表可以安全打断这些调用。示例 systemd 单元保持 `TimeoutStopSec=infinity`，没有网络宽限结束后强制退出并宣称成功的路径。管理员可显式强停卡住的进程，但这是崩溃，不是成功优雅退出；下次启动必须完成恢复。

客户端可能在操作已经持久化后、成功响应送达前因停服断开。连接关闭不证明操作失败；重启后先查询原操作号或上传状态，不自动生成新操作号重做，也不清空原暂存材料。一天内重复正常进程重启应保留同一管理权威和持久目录，并在旧进程完全退出后启动新进程。此类回归只证明进程生命周期行为，不替代物理关机开机、设备挂载时序或真实掉电恢复验收。

<a id="optional-http-files-at-startup"></a>

## 启动时的可选 HTTP 文件

HTTP 上传暂存不是管理启动的必要条件。目录准备、加锁或安全清点失败时，登录、注销、改密、受保护初始化、存储恢复和宿主诊断仍可用。上传/上传状态在正常认证及 CSRF 准入后返回 `503 HTTP_UPLOADS_UNAVAILABLE`，不使用无预算或内存回退。原暂存文件保留，修复本地原因后重启恢复清点。不可变正文读取不依赖上传暂存。

配置的 Web 资源树若缺失、不可读、不完整（无 `index.html`）、超准入上限或含被拒绝链接/特殊文件，则不安装静态服务；非 API 回退返回带 `no-store` 的 `503 WEB_ASSETS_UNAVAILABLE`，保留的未知 API 路径仍返回 JSON 404。管理 HTTP API 继续可用，但没有有效资源包就没有浏览器界面。将资源放在独立可工作的系统文件系统，才能在数据盘故障时保留正常 Web 界面。

公开管理状态的 `auxiliary.http_uploads`、`auxiliary.web_assets` 只给出粗粒度启动状态 `ready` / `unavailable`，资源还可为 `not_configured`，不含路径或内部错误。这是启动准入结果，不是持续探测，也不证明数据就绪。监听、origin、代理、准入、凭据权威、bootstrap、CSRF 和路径规则仍必须检查；不能全局忽略这些隔离可选能力之外的安全错误。

此启动隔离没有解决静态服务检查/使用时差：准入资源树运行期间必须受操作者控制且保持不变。当前静态服务重新按路径打开，因此准入后替换（含符号链接竞态）不具备安全打开保护。后续加固需要直到响应完成都使用描述符相对、禁止符号链接的打开方式，包含压缩表示、验证器及替换/竞态测试。启动期阻塞内核 I/O 也未因此有界；只隔离已返回的初始化失败。
