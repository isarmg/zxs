## 2.1 对象定义

| 对象 | 含义 | 可变边界 |
| --- | --- | --- |
| Repository | 命名、历史和配额容器，可包含多棵独立历史树 | 配置通过事件变更 |
| HistoryTree | 版本演进、合并标记与内容管理域，稳定 history_tree_id | 拆分为显式双域事务，域间无恢复依赖 |
| Directory Tree | 路径与版本的不可变目录快照 | 同域连续提交可复用未变目录描述；跨独立树不共享活动对象 |
| File / FileVersion | 稳定文件身份和不可变完整内容身份 | 每次内容保存产生新 version_id；大小和哈希固定 |
| FullPayload | 一个版本的完整普通文件及校验描述 | 不原地更新；清除通过独立事件登记 |
| Replica | 指定级别盘位上的完整文件、校验与本盘证明 | 按一级来源、路由及登记目录身份验证，路由外残留不计保护 |
| StorageSlot | 用户指定的稳定盘位，绑定一个登记存储目录及一个 copy_level | 换物理盘不改变逻辑角色，绑定变更需事务及代际 |
| BackupTopology | 用户指定的逐级来源映射及不可变代际 | 一个源盘位至多一个下一级目标，目标可聚合多个指定来源 |
| Commit | 目录快照、提交类型和 parent_commit_ids | 根零父、其他版本提交一父；父边无环，合并标记不修改父列表 |
| MergeLink | 两个分支上选定版本之间的合并连线 | 固定端点，只记录关系，不改变版本、文件或分支 HEAD |
| FileBranchMerge | 文件分支合并的全部输入、所选节点、结果和归属 | 可复用输入头；否则新建复用正文的元数据节点；消耗分支变只读别名，相关目录引用同步推进 |
| FileMetadataNode | 标签或合并的不可变文件子节点 | 引用真实 version_id；标签快照继承或按显式增删更新，不复制正文 |
| Branch | 某个稳定 file_id 的记录及实际写入后的内容演进线；未写入时读取冻结父版本且尚无本分支自有正文，旧目录快照入口仅为兼容保留 | 文件分支的 HEAD 通过条件事务推进，选择只影响该文件；归档不移除历史节点或自动清除内容 |
| DirectoryBranch / DirectoryTree | 稳定命名目录分支及不可变子树，保存成员、名称、路径和精确公共文件／子目录引用 | 创建只共用父节点；实际修改追加子树，不持有私有文件分支；切换恢复完整冻结组合 |
| FileContainer | 单个稳定 file_id 的真实命名目录，包含各个完整版本普通文件 | 重命名移动容器目录；版本内部名不变，下载使用容器当前名称 |
| HEAD | 分支指向的最新已发布提交 | 按分支条件事务推进；浏览历史和合并连线不移动 HEAD |
| ContentState | AVAILABLE、PURGE_PENDING、PURGED、UNAVAILABLE | 显式状态事件，不删历史版本描述 |
| Workspace / AccessSession | 未提交工作视图及入口绑定 | 保留基础版本、会话代际和脏文件，不冒充已提交内容 |
| SMBShare | 已授权历史树默认根目录组合的基础文件入口 | 默认组合可显式切换；旧读固定版本，相关旧写通过上下文代数拒绝覆盖 |
| Fork / Split / Purge Plan | 可审查、可重试的操作计划 | 决定前安全阶段可取消，决定后按同一计划恢复 |
| Cache | 可重建的读取数据 | 不计正式副本；未保存工作数据另管 |

## 2.2 不变量

```text
I01 每个计入健康副本的版本，均能在对应登记盘位上独立读取并校验完整字节。
I02 所有实际内容版本只采用 FULL；创建分支只发布记录和冻结来源引用，首次写入才建立独立完整版本，合并连线不创建内容。
I03 一个 version_id 固定最终大小和哈希；历史版本不会被普通保存原地改写。
I04 副本须匹配冻结路由中对应级别的指定盘位，并按登记盘位计数；物理故障域独立性由用户保证。
I05 所有正常访问和变更均经过核心授权、命名、事务与审计。
I06 Commit 谱系与文件混合节点 DAG 分开；文件父边及合并附加边无环，FULL 正文来源证明不因元数据变化重写。
I07 文件合并采用所选节点的正文和标签，推进归属及相关目录引用；旧 MergeLink 只记录关系，不能冒充已执行的合并。
I08 正常业务成功必须满足冻结的逐版本保护、全部已配置成员的元数据和原子发布条件。
I09 非法名称、未知事务、不支持语义和已清除内容不得静默替换或伪装成功。
I10 未解决事务、分支创建、拆分、清除及回收计划的恢复依据不得删除。
I11 缓存和客户端自报状态不作为持久化事实。
I12 历史内容清除保留提交、父边、目录描述及版本墓碑，不破坏其他保留版本。
I13 同一元数据决定槽位至多一个不可变候选；未收敛时不进入下一槽位。
I14 固定成员集合的多数决定不等于全成员保护；正常新状态须全部配置成员完成，不得按在线数量缩小门槛。
I15 未隔离旧写者和旧配置时，不激活新成员代际。
I16 树拆分后两域不共享活动元数据对象、内容文件或可回收引用；来源 ID 仅作审计。
I17 每版本有固定一级来源；后续份数沿用户指定的相邻级映射生成，不换目标、不跳级。
I18 同一登记盘位只绑定一个数据级别；不同盘位可共享底层物理设备；拓扑无环，每源在同代际至多一个下一级目标。
I19 指定盘满、离线或缺少路由时不得写到无关盘，不自动降低目标份数。
I20 SMB 仅访问共享对应主分支；从历史节点继续保存创建新分支，只有实际写入文件生成 FULL 版本。
I21 用户文件分支只包含一个稳定 file_id 的占位或实际写入内容及必要父目录；创建不复制来源正文，保存和切换不得改变同目录其他文件。
I22 目录分支递归批量操作各文件的独立分支，一次决定和发布；任何成员失败不得出现部分选择或部分分支创建，范围外文件保持不变。
```

最小部署是一块系统盘加一块存储盘；二、三、四及后续备份级别均可不配置。元数据成员数 N ≥ 1，决定与恢复门槛为固定配置的 floor(N/2)+1，正常发布须全部 N 个成员。单盘无冗余，不能承诺唯一存储盘永久丢失后的数据恢复；系统盘完好时管理面仍应可用。

独立 FULL 文件约束不等于物理设备独立性；程序不探测或拒绝共享底层故障域，由用户自行保证，也不承诺控制 SSD FTL 或 NAND 地址。写入过程中的范围传输或工作区复用不改变最终全量保存要求，不能登记为依赖旧版本的正式文件。

## 2.3 状态维度与统一用语

操作结果、内容是否保留、当前副本健康、连接状态和认证是不同维度，必须分别展示。已经成功的保存不会因为后来掉盘变成“未保存”；后来内容不可用时，应保留原操作结果并报告当前故障。

| 维度 | 状态或用语 | 规范含义 |
| --- | --- | --- |
| 本地工作 | 未保存、待上传 | 修改尚未得到服务端最终确认，不计入正式版本或保护份数 |
| 操作结果 | 处理中、结果未知、已完成、确定失败 | 以原 operation_id 查询为准；结果未知不等于失败，不自动重复创建操作 |
| 保存确认 | COMMITTED_AND_PROTECTED | 此次内容提交已按指定路由达到目标份数，控制元数据保护及公开发布均完成 |
| 分支未写入 | PENDING | 分支记录已发布但尚无自有正文；可见内容为冻结父版本，能否读取由visible_content_state、认证及副本健康决定 |
| 当前内容 | AVAILABLE | 内容仍被逻辑保留；能否实际读取还须核对当前认证及健康副本 |
| 清除准备 | PURGE_PENDING | 正在执行清除计划；新读取、任务来源读取及内容固定受清除屏障约束 |
| 已清除内容 | PURGED | 历史节点存在，但服务端不得继续提供该版本内容；物理残留另行清理 |
| 意外不可用 | UNAVAILABLE | 内容没有按用户要求清除，但没有可验证的可读副本；不得标记为正常删除 |
| 保护情况 | 达标、保护不足、补齐中 | 按每个指定级别的完整副本判断，不能只计文件总数 |
| 运行模式 | 正常、只读、恢复中、停止服务 | 决定哪些请求可被接纳，不改变已提交历史事实 |
| 访问结果 | 无权限、连接中断、内容不可用 | 分别返回，不能统一伪装为空目录或“文件不存在” |

“全量”描述版本文件的完整性；“份数”描述指定登记盘位上的完整文件数量（不自动证明物理冗余）；“主分支”描述当前访问目标。三者不得混用。

### 磁盘 State 的读取信任边界

快照根必须有 `radix-map-roots` 标识、准确35个映射根、events 根和独立控制认证对象引用；
拒绝旧平面根且保留文件，不迁移或重置。全部索引/叶页/认证对象通过域哈希、重复键、
字段形态和 sequence 检查，events 的20位 ordinal 必须从0连续，之后首先解码为引擎私有的
`history_package::RawState`。`journal::resolve_snapshot` 只有经过 `TryFrom<RawState>`
才返回可供引擎使用的 `State`。校验复用 `HistoryManifest` 已有的提交单父无环、
分支端点、目录组合/树、文件混合节点图和别名闭包规则，并检查全局身份与各张投影表
的精确覆盖，防止过滤投影遗漏孤儿记录；版本与 placement 的键必须完全一致；稀疏 content state 缺项继续表示 Available，
显式状态只允许引用已有版本，读取不补写缺省项。

普通打开、恢复打开、恢复检查点、降级恢复、工作区决定恢复和绑定快照修复都经过
同一读取入口。初始化构造空状态；历史包导入在包读取处验证完整 manifest，并在合并前
检查与现有身份冲突。按 key 路径读取操作凭据不是完整 State 导入，只验证所需路径而不读取无关版本、提交或认证对象；缺 key 与损坏路径不能混同。
计划输入、操作回执和审计事件不是当前历史图的活动引用，仍由各自消费边界处理；认证
控制状态仍由认证恢复边界校验。

内部变更依赖构造约定，不在每次 mutation 之后新增全量校验。分支祖先查询因此不再
重复检测缺失提交、跨历史、多父或环；缺失存储引用使用 `expect("invariant: ...")`。
用户提供的分支/提交 ID、迁移状态、授权、并发冲突、资源限制与真实 I/O 失败仍返回错误。
`storage_contract::State` 的 serde 仍是原始存储 DTO 能力，不单独证明其可被引擎接纳。
页编解码测试使用显式 raw fixture 解码器；磁盘引用损坏测试使用实际的接纳入口。

恢复将已入场 State 与候选绑定的历史包比对时使用纯 `project_state`，不再次做关系校验；
独立读入的历史包仍自行验证。现有未发布候选的 `from_state` 校验暂保留原调用范围，
本批只集中完整磁盘读取的接纳，并移除分支祖先查询这一族重复检查，不宣称全部核心检查已迁移。
