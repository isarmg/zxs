## 谁可以备份到哪里

备份的源是实际登记、当前持有该 FILE 的主数据盘。目标是用户指定的直接备份盘。例如主盘 P 可以分别备份到 B 和 C：两份都来自 P，C 不依赖 B，B 也不能给 C 充当来源。可配置不止一个独立目标；备份盘数量不能代替逐份核验。只有原件时应显示没有独立备份。系统盘与专用回收盘都不是 FILE 备份的来源、备份目标或缺盘时的替代品。

## 路径范围与登记身份

操作绑定准确的源盘、目标盘、登记代际、父目录和 FILE，而不是磁盘标签或显示路径。可以对普通目录及子项选择备份范围，包含空目录；这不产生目录版本库。目录的子范围设置与磁盘来源链不是一回事。更改未来 FILE 的放置策略也不是移动既有数据。

## 逐目标验证

每份计入保护状态的副本都要在该目标盘上验证：正确的源 FILE、被保留的版本、完整正文及校验材料、足以识别此次原始决定的证据。缓存、链接、暂存或同名的其他 FILE 不算；源版本没有新内容时不虚构正文。一个目标已完成、另一个离线或空间不足，要分别报告，不得借用完成目标的结果。相同设备上的不同目录不代表独立的故障域。版本保留和永久清除仍适用各自规则。

## 失败、换盘与恢复

备份任务固定原操作、源、目标和原始范围。失联、满盘、挂载被替换或正文校验失败时，不转向其他磁盘来伪造成功。任务重试须核对原决定和实际副本；换盘、取消或停止不代表新目标已经完整。任何切换之前应重新验存并证明可以恢复，保留原有健康材料。直连备份可作为显式恢复的只读来源；这不使该盘成为新备份的来源，也不会自动将备份提升为可写主盘。

<a id="s09-12"></a>

## 系统盘与回收盘不是一层备份

系统盘保存登记、拓扑、命名空间和操作决定；回收盘仅在用户软删除后物理承载原 FILE 容器。两者都不是上述直连保护份数的一部分。备份任务不能为软删除、归属移动或永久清除作决定。[FILE 归属及跨盘移动](design/file-container-custody.md)描述负责发布该决定的位置。

验收应分别证明：一个主盘向两个直连目标生成可独立读取的副本；某个目标失败时不改写源、不报告全部成功；拒绝把备份设为其他备份的来源；冷重开、换盘和原操作重试仍指向同一 FILE 与目标。这些新用例不能用原有多级测试替代。
