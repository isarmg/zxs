# 文件容器的使用边界与验证状态

[项目首页](../README.md) · [文档目录](README.md) · [当前任务](../TASKS.md)

在 ZXS 中，一个 FILE 容器对应一个有稳定身份的文件。文件夹只是已登记存储根下的普通路径：可以建立、浏览普通目录，不需要先把文件夹初始化成仓库。浏览某个文件夹不会生成历史，选择文件分支也不会切换旁边的文件。已发布的文件版本有自己的正文，后续保存不改写旧版本。

| 想做什么 | 在 ZXS 中怎么做 |
| --- | --- |
| 浏览文件或查历史 | 在 Web 选择盘位和普通文件夹，再选择具体文件，查看它的版本、分支和元数据。备份盘的浏览是只读的。 |
| 读写正文 | 使用已认证的 SMB 共享或受控 HTTP 文件接口。稿件被保存和新版本正式发布是两件事；结果未知时查询原操作，不重复发起另一项写入。 |
| 存放名为 `project.zxs` 的文件 | 像对待 `notes.txt` 一样保存它的字节。后缀不会触发解包、初始化、挂载或额外权限。单独名为 `.zxs` 的完整路径组件受保留名规则约束，不等于禁止以 `.zxs` 结尾的文件名。 |
| 给目录建立历史或检出工作树 | ZXS 不提供目录仓库、目录分支、目录暂存／提交、Worktree、整树拆分或脱离登记根的仓库创建。不要在普通文件夹内创建标记来开启这些功能。 |

## 磁盘角色：当前代码与已确定的目标

[当前主线基线的物理布局代码](https://github.com/isarmg/zxs/blob/0039aa9e69ff39a87ad9c1571655801d045f7737/src/engine/src/persist/layout.rs)仍使用 `common-data`、`deleted-data`、`zxs-data`。**新布局尚未实现或验收**。不要按下列规则改造已登记的盘。

| 目标位置 | 存什么 |
| --- | --- |
| FILE 容器 | 一个稳定 FileId 的正文、各已发布版本、分支及文件本地元数据。普通文件夹只组织路径，不产生目录容器。 |
| ZXS 系统盘 | 登记身份、盘位和拓扑、普通路径与 FILE 的对应关系、操作决定与恢复所需的全局记录。系统盘不是回收盘或备份盘。 |

回收盘是单独配置的**物理存放位置**：用户软删除时收下原 FILE 容器，不是第三种元数据层，也不借备份盘兜底。回收盘未配置、离线或空间不足时，删除应在改变可见性前失败，原文件留在原处。恢复仍是同一个 FILE；若原名已被占用，不覆盖新文件。文件夹仅按本次选中的普通目录树组织其原文件，不产生目录历史。上传临时文件和未决定的候选不属于用户回收站。此改动不变更单版本保留或永久清除规则。

跨盘 **MOVE** 转移整个原容器：先在目的盘准备并核验全部材料，再由系统盘发布唯一的新归属，确认安全后才退役源实体。中断只恢复同一次移动，不能同时暴露两个可写所有者或让源文件无故消失。FileId、各版本与历史均不重建。显式 **COPY** 仍是另一种命令，不改变原文件的所有者；内部为移动而复制字节并非用户执行了一次 COPY。

备份只接受**主数据盘 → 直接备份盘**。同一主盘可以指定多个相互独立的目的盘，每份单独核验；备份盘不能是另一备份任务的来源。旧多级配置不自动转换、接管或删除。原有代码、演示和链式测试尚不能证明[直连备份目标](09-backup-topology.md)已经交付。

更细的发布与冷重试条件见[跨盘移动与回收设计](design/file-container-custody.md)。

## 既有数据与恢复

当前源码只接受匹配的 FILE 池格式和原始登记身份。不支持的旧格式或无法证明的存储根应拒绝使用，并保留原有字节。**不要删除标记、补字段、重算摘要或在旧目录重新初始化。** 新池初始化只能面向明确选择且满足条件的空目录。普通登记目录、已发布操作的原始回执和登记磁盘恢复仍有用途，不能作为旧功能遗留物批量清理。此次源码变化不是对任何实际磁盘的迁移或部署。

## 哪些结论已有证据

以下是 2026-11-18 核对的主线源码状态，不是 Release 验收清单。

- [FILE 主线快照 `5026d36c`](https://github.com/isarmg/zxs/commit/5026d36cc36bf7af629a048ce4c0cfd7e28ecad1)：公开目录仓库与 Worktree 的 HTTP/SMB 入口已撤下。真实进程内 SMB 分发测试通过三项：保存后旧读取句柄仍指向原 FILE 版本；创建普通目录后重开仍可见；对错误类型调用 unlink/rmdir 不破坏原对象。它们不经过系统 Samba 或真实客户端。
- [契约校验 `0039aa9e`](https://github.com/isarmg/zxs/commit/0039aa9e69ff39a87ad9c1571655801d045f7737)：同源码输入的 Rust 契约测试 **58/58** 通过，区分写操作的直接回执、结果轮询和显式健康查询。这不是全量测试通过，也不是部署证明。
- **尚不能当作已交付：**独立 FILE 历史复制、在线加盘、新布局的跨盘 MOVE 及专用回收盘都没有随本次文档发布。原布局下的单项试验不能证明这些新盘位语义。完整 Web 流程、原生归档与角色恢复、系统 Samba/真实客户端仍有独立的验收缺口。旧的内部目录类型、投影和部分维护代码还未全部清除；它们不是可使用的服务接口。

后续状态分别记录在[任务清单](../TASKS.md)和[发行检查清单](validation/release-checklist.md)。主线提交、针对某条路径的测试和正式发行是不同的结论。
