| 场景 | 可读状态 | 可写与恢复规则 | 绝对不能做的事情 |
| --- | --- | --- | --- |
| 单个数据盘离线，版本还有健康副本 | 从相同版本和内容哈希的其他健康完整副本读取 | 修复缺失位置；新提交仍满足目标数 | 返回其他历史版本冒充当前内容 |
| 单副本版本所在盘离线 | 该版本不可用 | 等待盘恢复或显式外部恢复 | 把缺失文件当成空文件 |
| 内容副本校验失败 | 隔离异常副本后尝试其他副本 | 按可信哈希重建 | 以修改时间更新者为正确副本 |
| 文件还在但描述损坏 | 不直接信任其业务身份 | 保留对象，利用其他元数据核对 | 删除“无法索引”的文件 |
| 系统盘损坏 | 数据盘内容仍可能完整 | 以可信元数据恢复索引与服务身份 | 自动创建空仓覆盖旧池 |
| 一个元数据成员离线 | 已发布状态、当前认证和墓碑可验证时允许读取 | 按保守基线停止新严格提交，修复或更换成员 | 按在线盘数缩小固定成员集合或发布门槛 |
| 多个元数据成员离线 | 仅按可验证状态和当前授权开放；无法确认时只允许管理员隔离恢复 | 不足固定配置多数 Q = floor(N/2)+1 个可信旧成员时不恢复原池写服务；按配置证明或只读导出处理 | 用单盘缺少记录证明事务失败 |
| 日志同序号分歧 | 只读或停止受影响业务 | 保留证据并调查 writer/member epoch | 按最新 mtime 选一条日志 |
| 完整副本完成后进程崩溃 | 未提交对象不应出现在普通目录 | 重放决定；无决定则保留或安全中止 | 根据对象文件存在就自动发布 |
| ACCEPT 少于固定配置多数 Q，传播失败 | 该事务不发布，结果待查询 | 隔离写者后按 Q 个可信旧成员的完整观察补交或恢复中止 | 把单份候选直接称为已提交，或按超时直接删除 |
| ACCEPT 已达 Q 份，尚有配置成员同步失败 | 原已发布状态仍可读 | 决定保留，恢复缺失成员、证明及全成员发布 | 回滚已成立的决定 |
| 首份 ACCEPT 所在盘永久损坏 | 已发布历史仍按证据读取 | 可信 Q 成员观察集合完整无候选时记录恢复中止并换盘 | 永久等待丢失盘，或跳过证据擅自接管 |
| 提交成功响应丢失 | 以服务端操作查询为准 | 原 ID 重试返回同一结果 | 用新 ID 重传并重复产生版本 |
| 远程网络中断 | 缓存已存在范围可读 | 保留工作区，重连后重新验证条件 | 自动覆盖更新后的分支 |
| 客户端磁盘满 | 读取可能降级为无磁盘缓存 | 暂停新增缓存/写入并报错 | 清除唯一的未提交脏数据腾空间 |
| 指定级别盘位空间满 | 既有健康级仍可读 | 返回该slot/level的NO_SPACE，等待用户换盘/改拓扑 | 擅自使用其他空盘或以池总空闲承诺可写 |
| SMB 服务或桥接退出 | 共享明确不可用 | 恢复后核对原操作和服务端工作区 | 回退为直接共享物理目录或返回空目录 |
| API 网关退出 | 本地 IPC 可按部署情况继续 | 远程重试并保持幂等 | 绕过核心直接静态共享物理盘 |
| 文件名非法 | 原状态不变 | 报错并等待合法请求 | 自动删字符、截断或加后缀 |
| 系统时钟早于 Unix epoch，或版本/操作展示时间超出 UTC 格式范围 | 已发布数据不因此改变；依赖本次读时钟的操作明确返回服务端错误并保留具体来源 | 把失败时间当成 0、归咎于客户端参数，或凭失败时间放行租期检查 |
| 写租约过期 | 固定版本读取可继续 | 旧 token 拒绝提交 | 仅凭重连恢复过期写租约 |
| Web 分支切换遇到脏数据 | 原工作区和 SMB 主分支绑定保留 | 先提交、保留、导出或取消工作区 | 擅自把脏内容送到新分支 |
| 盘在外部被修改后接回 | 不直接作为健康原副本 | 哈希检查、隔离、显式导入 | 原地更新不可变版本索引 |
| 同池两实例同时启动 | 不允许第二实例获得持盘写权 | 停止冲突实例并检查数据 | 认为单机 SQLite 锁足以隔离所有磁盘访问 |
| 完整文件截断或校验清单不符 | 该副本不健康 | 改读同版本其他完整副本并修复 | 用补零或其他历史版本伪装完整 |
| 分支引用/目录子树发布中断 | 原分支、源正文和历史保持，冻结版本按实际状态读取 | 按同一 operation 恢复元数据、树闭包和缓存；首写按 FULL 屏障恢复 | 复制未写来源、生成空文件或自动增加命名分支 |
| 旧MergeLink记录失败或端点分支继续保存 | 原文件、版本及 HEAD 不受画线影响 | 查询原操作，只保存固定所选节点的关系记录 | 为画线复制文件、生成版本，或把端点改成新 HEAD |
| 文件分支合并遇到过期head或发布响应丢失 | 条件冲突整笔拒绝；结果不确定时保留原操作与全部输入 | 按原operation_id查询或重试，核对归属、来源和目录引用结果，见[合并规则](design/file-merge-tags-backup.md) | 只更新部分目录、盲目换key重试、覆盖未参与引用或改写原正文证明 |
| 旧历史被申请清除 | 其他完整版本仍可独立读 | 检查活动引用与明确确认范围，再发布墓碑 | 同时删掉其他版本或历史父边 |
| 清除墓碑已发布但离线盘残留 | 节点可见，内容返回已清除 | 残留标记与回盘清理，逻辑状态不回滚 | 以残留文件复活内容或声称物理擦除完成 |
| 拆分发布中断或并发结构变化 | 按唯一事务恢复到旧态或完整新态 | 同计划映射恢复两域，旧写租约隔离 | 仅移动分支名而继续跨树共享内容 |
| 二级B01满，B02空但不负责该一级来源 | 既有版本按健康路由读 | 新2份提交失败或等待用户明确迁移拓扑 | 把P01文件放进来源不含P01的B02 |
| 二级离线但三级仍有健康副本 | 三级完整文件可独立读 | 新3份提交仍须恢复指定二级，读取不升格角色 | 跳过二级改成“第一加第三”凑数 |
| 旧 V1 仅一份，新 V2 要求两份 | 两个版本状态分别显示 | V2 完整文件进入指定一级和二级，V1 不额外扩散 | 用 V1 加差异代替 V2 的独立完整副本 |
| 拓扑切换中断或旧盘重新接入 | 按已决定放置代际恢复 | 同计划恢复新旧路由，过时副本只作待清理材料 | 把旧来源映射重新当作当前权威 |

<a id="s18-01"></a>

唯一数据盘缺失时，系统盘完好且本机管理配置可用的管理登录、Web 和诊断仍须工作，数据请求明确失败关闭。单盘永久损失不能承诺恢复内容或原池写服务。

## 18.1 降级状态必须可观察

至少区分“内容可读但保护不足”“只读恢复模式”“提交决定未知”“仅客户端本地保存”“没有健康副本”和“无权限”。这些状态不能统一显示为“离线”。

<a id="s18-02"></a>

## 18.2 副本不等于独立备份

工作池内多份内容副本可提供设备级冗余；单份没有冗余；历史用于回看和误操作恢复。两者都不能单独覆盖整机损毁、全部盘被删除或有权限的恶意永久清理。

重要数据宜另有脱离这些工作盘的恢复副本，并定期验证可读性。全量版本和在线多份保护均不代替外部备份，也不把未纳入此固定路由的外部备份计入在线目标份数。被清除的历史节点不能据此承诺总能从备份恢复。

<a id="s18-03"></a>

## 18.3 分页历史图与独立包故障

[分页历史清单](08-full-storage-and-disk-format.md#s08-07)的根、索引和叶页都是候选哈希绑定的依赖，不是可从 SQLite 任意再生的缓存。一个成员不必独自拥有完整健康图；只读解析可逐对象从可信成员选取准确摘要的有效副本，但不得投票选新值、顺带修复或改用其他根。

| 情况 | 恢复规则 | 必须拒绝 |
| --- | --- | --- |
| 单份根/索引/叶页缺失或损坏 | 验证其他可信副本的准确域哈希，按依赖顺序复制到原地址；保留原候选和根 | 重新生成其他根来适配当前编码器 |
| 不同成员分别缺少不同依赖 | 逐对象组合已验证副本，完整图检查通过后修复 | 要求多数成员内容一致后才相信哈希，或从 SQLite 补齐图内容 |
| 图中某个必需对象的全部有效副本缺失 | 停止依赖该图的恢复/导出，保留现有材料 | 用展开清单摘要替换候选根；让恢复检查点掩盖缺失/损坏 |
| 遇到扁平投影或不匹配的包结构 | 严格字段校验拒绝，保留原材料且不执行迁移 | 从快照重建扁平根、改写证明或静默当成当前格式读取 |
| 独立包缺根、索引、叶页或证明替换 | 离线验证失败，不依赖原池或缓存兜底 | 根据便捷展开文件或另一个合法包重新定根 |
| 新对象安装中断但尚无 ACCEPT | 只可能留下未引用准备对象，不能据其存在发布 | 自动删除保留历史或把不完整图视为已发布 |

正常恢复在正文补齐及新决定前完成图依赖和证明大小预检；降级恢复也必须在 REPROTECT 前完成，损失确认不授权改写原历史清单。只有验证成功才进入修复；图修复失败不得缓存为已完成。检查点仅加速重放，仍须验证候选绑定图，不能成为新的权威。全部配置成员发布闭包和永久损失确认要求保持不变。

实验实现的测试覆盖不等于旧程序兼容或物理掉电验收。项目只维护一种无格式代际号的当前结构；遇到不认识的结构须停止自动修复，不得靠切换二进制自动迁移。当前格式的完整保留历史仍按原绑定证据保护。

## 日志与发布证据冲突

启动在恢复修复或索引重建前核对可见的完整发布封口。封口及完整回执屏障证明已有发布，而日志缺失、为空或只剩合法早期前缀时，服务返回恢复要求并保留现有投影和现场材料；不凭孤立候选对象创造缺失的决定历史。合法新空池和未发布准备残留不因此被误判为已发布。日志路径的悬空链接、异常父目录和 I/O 错误不能被视为“从未有日志”。数据引擎失败关闭不应阻止系统盘管理面的登录和诊断。
