## 13.1 操作与数据影响

| 操作 | 内容与拓扑 |
| --- | --- |
| 修改并保存 | 新完整文件版本，普通一父提交 |
| 改名或移动 | 字节未变时仅新目录快照，不必重写旧完整版本 |
| 当前文件删除 unlink | 新目录快照去掉条目，历史节点和已有内容暂保留 |
| 历史内容清除 purge | 删除获准旧版本内容，保留提交、父边、目录和版本墓碑 |
| 分支创建 | 新分支记录、来源关系和冻结来源引用；首次写入后才有独立版本 |
| 旧关系标记 `MergeLink` | 只增加所选节点间的关系记录，文件、目录、父边和分支 HEAD 均保持 |
| 文件分支合并 `FileBranchMerge` | 复用选定正文并推进归属分支和参与目录引用，保留原节点、证明和来源记录；不是历史内容清除，详见[合并规则](design/file-merge-tags-backup.md) |
| 历史状态继续保存 | 新分支仅为实际写入文件保存 FULL，其余继承父版本，不覆盖主分支 |
| 树拆分 | 同时发布两域独立对象与历史映射，不只改展示关系 |

普通 unlink 不是永久内容清除，归档不是删除历史树。界面明确区分“删除当前文件”“删除历史内容”“拆分历史树”及各自影响；SMB 只提供第一种。

<a id="s13-02"></a>

## 13.2 历史节点长期保留

历史节点至少保留 commit_id、父列表、作者、时间、目录描述、名称与路径变化、version_id、逻辑大小、最终哈希、来源摘要和清除事件。删除内容后标记“内容已删除”，仍可查看分叉、合并连线和拆分关系；旧 `MergeLink` 本身不固定端点正文。文件合并采用的当前正文仍受活动引用保护，合并来源记录不替代保留检查；已清除正文不提供假下载或其他版本代替。

目录和元数据差异仍可展示；文本或二进制内容比较必须有对应字节。缩略图、全文索引和差异缓存属于内容派生物，清除计划明确其处理，不能声称删除后仍由预览接口提供原内容。

历史拓扑与摘要默认长期保留。仓库整体销毁属于另一个需明确确认的管理操作，普通历史内容清除不顺带删除历史树。

<a id="s13-03"></a>

## 13.3 显式清除的范围与权限

可按版本、某文件版本列表、提交内版本集合或明确时间范围预览清除。展示涉及提交与分支、打开句柄、内容固定标签、各级指定位置、迁移残留、预计释放空间及不能删除的原因。

活跃分支 HEAD 使用的内容、显式 pin_content=true 的快照、有效工作区所需版本、开放读取或导出、未解决事务以及实际进行中的内容读取或拆分所需内容，均不能直接清除。尚未拥有正文的活动分支通过父版本读取，因此固定所需父正文；当前分支写入自有 FULL 或所有活动继承/工作区引用解除后，才可清理来源。父正文此前已清除仍能登记记录，但继承读取返回对应内容错误，完整上传可产生新自有内容。须先替换或移除所有相关活动引用、解除保护，或等待租约结束。归档仅保留拓扑，是否固定内容单独决定。

同 version_id 如被多个提交引用，清除影响所有这些历史视图，必须展示完整影响并核对确认范围。分支首次写入后建立的独立 FULL 版本不受来源正文清除影响。默认不自动清除；用户启用时间或数量规则时仍执行相同内容固定和业务状态检查。

<a id="s13-04"></a>

## 13.4 完整版本之间的删除独立性

若提交 C1、C2、C3 分别保存完整文件版本 V1、V2、V3，清除 V1 内容不要求重写 V2、V3，也不得删除它们的副本。版本演进边 C1 → C2 → C3 保留；C1 中的 V1 标记内容已清除，V2、V3 仍可从自身健康副本读取。

删除准入仍需核对实际引用。工作区可能暂时从旧版取得未修改字节，显式内容读取或导入也可能正在读来源；这些是进行中任务保护，不是正式版本的内容依赖。未结束前等待或返回 CONTENT_PINNED，不以清理历史破坏未保存修改。

通过日志登记 PURGE_PENDING 和计划代际后，为待删集合建立读取与固定屏障：不得新增内容固定、来源读取或普通历史内容读取租约，相关新请求返回明确的清除处理中状态。已有读取租约按计划结束后再进入墓碑发布。安全取消须持久化恢复 AVAILABLE 并解除屏障；输入变化必须重新预览。

<a id="s13-05"></a>

## 13.5 清除状态机与故障恢复

```text
PREVIEW -> CHECK_REFERENCES -> READY
       -> 第 10 章事务发布内容墓碑及清除清单
       -> PHYSICAL_CLEANUP -> COMPLETE 或 OFFLINE_REMAINDERS
```

墓碑发布前的安全阶段可取消，内容尚未被标记为 PURGED；已有读取按租约完成，新读取受清除屏障约束。取消完成并解除屏障后，内容恢复按当前认证及业务状态开放读取。结果未知时保留数据并查询原 operation_id。墓碑完成保护并发布后，内容状态为 PURGED，接口返回 CONTENT_PURGED；盘上残留不能重新提供内容，物理清理可重试但不回滚为 AVAILABLE。

物理清理与逻辑清除分别显示。清单涵盖已知完整副本、迁移残留和受管派生缓存。离线盘重新接入先核对墓碑、历史域和放置代际，再清理残留；不能登记为健康活动副本。只有实际删除后才报告空间释放，文件删除不等于 SSD 或硬盘安全擦除。

首版存在有效内容读取租约时等待或返回忙，不在打开过程擅自切断读取。已导出字节无法撤回；外部备份若还有副本，只能显式导入为新版本，保留曾清除的事实。

读取租约的期限及清除期间续约限制见[第 19.10 节](19-capacity-and-performance.md#s19-10)。工作区提醒或资源上限不授权清除工作区来源；管理员必须先处理工作状态，再重新预览清除计划。

<a id="s13-06"></a>

## 13.6 拓扑根、内容根与垃圾回收

拓扑根包括每树根、全部提交、父边、目录描述和版本摘要，不能因内容回收而删掉。内容根包括仍要求保留的 AVAILABLE 版本、活跃 HEAD、内容固定、工作区、开放读取与未决计划。显式清除事务在合法解除其他强引用后撤销选定内容保留要求。

普通 GC 只处理未发布操作的可确认孤立对象、获授权降低保护后的多余副本和已提交清除清单，不按文件年龄直接删 AVAILABLE 历史，不回收待确认工作数据。

```text
计算候选 -> 持久化候选与引用代际 -> 等待宽限期
-> 核对当前引用和未决计划 -> 原子登记 RECLAIMING
-> 删除目标物理对象 -> 持久化实际结果
```

新增读取或固定与回收准入序列化，RECLAIMING 对象不得新增无登记引用。日志缺口、配置分歧、磁盘身份未知、IN_DOUBT 或未收敛清除、拆分计划出现时，停止危险回收；按物理盘、历史域和版本核对对象，不能仅按名称删除。

<a id="s13-07"></a>

## 13.7 拆分与清除的协同

拆分固定历史域、内容状态和代际，清除不能并发改变输入。已清除节点迁为墓碑；仍承诺保留的文件必须在目标树独立完整。两树发布后分别清除本域对象，沿已批准路由处理各级及残留，不影响另一树。

来源映射长期可见但不是跨树活动引用。卸载、清除或销毁其中一树后，另一树仍须独立恢复。仅逻辑迁移归属不等于物理空间立即释放。
