# 共享增量稿、自动保护与嵌套显式提交的持久边界

状态：提案，等待所有者明确确认。本文不批准实现新格式、放宽已有解码器、迁移、启用或部署。

## 为什么需要新决定

现有 `FileWorkingState::Automatic { revision }` 没有可持久读取的工作正文、成功保存窗口或保护状态。
仅在进程内计数，或在普通保存成功后直接合成 FILE 节点，不能证明断电后最新稿、去重或保护期。
已有目录工作稿收据还严格限于根级 occurrence：`RequestDescription`、目录选集准入和
`trace_limit` 都会拒绝嵌套路径。字段已经使用 `PortablePath` 不等于已批准扩大其持久合法域。

本提案依赖[新池手动稿与目录提交](new-pool-manual-directory-commit.md)的一次共同决定，
不引入第二套 SQL 决策、逐文件提交、后台新权限或旧池默认补值。
三范围物理闭包和格式代际由同批核心 ADR 统一定义；这里列出它必须绑定的业务材料。

## 一、成功保存与后台节点分离

1. 新文件仍默认手动；仅明确的单文件模式变更能启用自动。旧手动稿不得自动升级或隐式提交。
2. 新自动状态显式保存：工作 revision、真实基准的 branch/node/version/选择代数、逻辑长度、
   不可变增量清单及承诺、最近成功保存的操作身份、保护策略及状态。清洁自动状态也显式编码，
   不靠缺字段或空清单推断。Unborn 继续使用无历史节点的真实状态，不能伪造基准版本。
3. 每次不同的成功保存用一个 SYSTEM 决定同时发布 FILE 工作行和 DISK 不可变增量清单／实体。
   收据绑定完整请求摘要、主体、原 EntryId/FileId、原 occurrence/owner、基准、前后 revision、
   原长度和新长度、写集承诺、实体清单及实际根身份。准备文件不能充当成功保存。
4. 保存确认只在共同决定及必需材料可读后发出。前台立即按该基准加增量读取新长度及正文；
   非截断保存及区间读不全扫基准。旧正文、旧稿和不能归属的 partial 原样保全。
5. 后台合成不是保存事务。它捕获一个准确已发布保存 revision 和该保存原收据，使用唯一派生任务身份，
   在独立区域合成完整正文并读回验证。发布前重新检查 mode、保护 epoch、revision、基准选择和 owner。
   任一变化只能使未决定任务失效，不能重新选择“最新同名文件”、按哈希认来源或覆盖新稿。
6. 真正建节点时仍只有一次原生 Candidate/接受/发表决定，原子消费准确已捕获稿并发布 FILE 节点。
   不因后台准备完成、备份完成或进度显示而提前清稿。保存、全量准备、节点发表、备份分别报告。
   已永久决定的原操作按原收据收尾；后来切手动或触发保护不能重写原决定。
7. 手动／自动共用相同严格写集、长度、物理实体与根预算准入，但手动只有明确文件或目录提交能建节点。
   Worktree 复用增量实体与读核，不冒充普通 occurrence；其 source/mount/选择代数和提交收据依其独立 ADR。

## 二、有界频率保护

建议首版固定策略为滚动 60 秒内最多 20 个不同的成功保存 revision。策略参数进入明确启用自动的
原请求及持久状态，不通过重启后本地配置悄悄改变。该数值是本提案待确认内容，不是现有默认值。

- SYSTEM 成功保存原决定记录服务器秒时间和严格递增 sequence；同操作、同摘要、同主体的准确重试
  返回原收据，不新增 revision、样本或节点。失败、准备、心跳、重复 flush 都不计。
- 工作行最多保留 21 个 `(revision, operation, decision_sequence, effective_time)` 样本。
  有效窗口时间为 `max(当前服务器时间, 已保存窗口水位)`，时钟回退不能清空计数。
  第 21 个样本先持久化其最新增量，再在同一决定锁存 Protected 状态和原因、触发操作及保护 epoch。
  超限后不积累样本队列，只更新最新成功稿与原收据；永久操作表仍保留真实保存证据。
- Protected 阻止新后台全量准备及未决定节点发表。允许已决定任务按原证据完成，也允许后续保存继续持久化。
  自动→手动使用同一 per-file 写入／发表围栏，不能等到新节点已经产生后再补改模式。
- 保护锁存跨重启，绝不按重启、时钟快进或过期计时器自动解除。明确恢复自动需绑定当前保护 epoch/revision，
  窗口清空并进入新 epoch；只处理恢复后新保存，不补建保护期间积压。用户仍可明确提交当前稿。
- 警告 DTO 必须给出真实 mode、最新持久 revision、保护状态、策略、触发原因及阶段，不把“保存成功”显示为
  “历史节点已建”或“已备份”。未知／缺失状态明确拒绝，不能作为未保护。

## 三、真正自动节点的不可变来源

每个新 FILE 内容节点的发布收据必须严格记录原因枚举（手动文件、手动目录、自动保存、其他既有明确来源），
不从命令名称、时间间隔、文件名、哈希或当前模式猜测。自动来源额外绑定原成功保存操作／revision、策略 epoch，
以及建节点原决定时的 repository、owner、从根到所属目录的稳定 EntryId 链与真实路径事实。
路径展示可保留当时文字，但目录归属必须来自原已准入结构，不以查询时路径追溯过去。

目录／时间窗查询采用半开区间 `[start, end)`，按实际节点发表收据时间过滤，按稳定 `(FileId, FileNodeId)`
去重，并返回准确涉及 FileId 及独立节点数。目录范围由原决定的稳定祖先链判定，父目录可包含子目录。
只计此池实际以 Automatic 原因新建并发表的节点；手动、工作稿、改名、移动、失败、准备、重试和导入的
历史副本不计。移动后原事件仍归原目录，后来新节点按新 owner 归属。复制保留的来源不伪装成本池新发布。
查询须有界分页并绑定观察 sequence；不能截断后宣称总数完整。没有新来源字段的节点不能补猜为自动。

## 四、嵌套普通工作稿和显式目录提交

扩大域仍限于新池已准入的单 owner 普通容器。写请求必须从当前命名空间准确解析原 EntryId/FileId，
逐级验证 `NamespaceDirectoryRecord` 的 parent/entry/repository/branch/owner 以及根实体。
历史相同叶名、另一 occurrence 或同哈希文件不能替代。改名只更新当前名称，不改旧版本或旧请求。

显式目录提交一次捕获整组选中的完整路径、revision、基准、payload 和目录 head；任何一项失效则全组拒绝，
且在任何新增材料或清稿前检查完整选集。只消费本次选中稿，未选稿保持原 revision/实体。
变化与无变化的现有语义不变：真实变化才生成 FILE/目录节点，无变化返回严格原不变结果。

必须同时更新生产写端、冷快照／永久收据读端和精确恢复端，而不能只删除写端根级 gate：

- `business/file_draft/selection` 按真实已准入祖先及当前 occurrence 解析，并从原状态重建 preserve 目标；
- `snapshot_worktree/drafts/scope` 的普通目录选集与 `persist/directory_draft_commit::RequestDescription`
  显式接受该新域，并拒绝 worktree、错误 owner、重复别名和没有完整父链的路径；
- `content::trace_limit` 按实际选中更改及不同祖先数推导完整分配上界，根和每个祖先的 directory branch/tree
  都计入；上限 checked arithmetic，写、读、replay 使用同一个公式，不靠加常数“试到通过”；
- Unborn 首次提交同样证明父链、无历史节点原状态及真实首次 FILE 版本，不以普通 Born 路径伪装。

该项扩大的是已存描述的合法域和分配上限，即使 JSON 字段名未变也属于格式兼容性决定。

## 五、格式门、三范围闭包与恢复

只在明确的新空根初始化产生新的已认证格式版本。SYSTEM、DISK 和 FILE 必须共同绑定该版本及原根／成员代际；
旧程序在首写前拒绝，当前程序也拒绝旧池、旧备份、缺失标记及不同版本。正常启动、管理启动、成员激活、
显式恢复、备份／复制／导入使用同一门。不得补 marker、补字段、自动迁移或接受“字段碰巧兼容”。

统一闭包至少包含：每个容器的工作行及修订、无节点 Unborn 的真实 FILE 材料、所有普通根／子目录与
worktree owner、每个基准版本与引用 extent、增量清单、保留旧稿、当前稿实体和准备来源。无历史节点不等于
无 FILE 材料；目录结构存在不等于权威已登记；unknown partial 不能被补入或删除。
逻辑长度、extent 数、祖先数、清单／收据编码和完整盘根保留量一起预算，不能仅预留正文大小。

原永久操作的身份、摘要、主体、结果和精确回放不可改写。复试先查原决定，再考虑当前 mode/revision/保护状态；
已经接受的 Candidate 只能使用原材料和原根证明完成。新格式拒绝旧格式，不借此删去原已支持格式内的成功重试。

## 验收边界

确认后先补生产端和严格冷读，再在合并后的准确 head 做定向验证。本提案及静态评审不是测试通过：

- 新池手动默认、自动明确启用、零节点首稿、增量立即可读及长度一致；非截断／区间读无全量扫描。
- 每个准备／接受／发表中断、丢响应、同 ID 重试、不同主体／摘要、旧稿与未知 partial 不变。
- 20/21 边界、不同成功 revision、重试零增量、重启／时钟回退／快进、并发紧急切手动、已有决定收尾。
- 保护期不新启动／发表后台任务，不补积压；警告及保存／全量／备份状态与真实原收据一致。
- 多层同名目录、历史 alias、owner 改变、嵌套 Born/Unborn、整组选集 CAS、未选稿和无变化零节点。
- 同目录／父子目录、改名／移动前后、并发、冷开、重复回执及拷贝来源的自动节点精确计数。
- 所有格式入口首写前拒绝，真实 FILE/DISK/SYSTEM 闭包和资源预算；真实 Samba 与大文件量化另行验收。
