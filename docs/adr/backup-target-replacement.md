# 多下级备份、不可拆分整体与后台迁移

状态：**已确认的产品约束，历史材料后台准备已有独立核心切片；完整迁移与切换待实现**。本文后段区分真实准备入口与目标协议。当前仍只允许既有不改来源边的登记操作；不提供用“仅后续写入”完成换备份盘的入口。

## 需求与非等价操作

用户已明确以下约束：

1. **更换某个盘的下一级备份盘时必须迁移所有数据。**
2. **每个备份盘可选择多个下一级备份盘；每个文件的所有内容、数据库、历史节点、标签等必须作为一个整体存在于一块盘。**
3. **目录若是目录仓库，该目录仓库也必须按一个整体处理。**
4. **子仓库先设置多级备份、后来父仓库也设置时，父子在对应备份层必须位于同一备份盘；不同盘的既有布局须完整迁移。**
5. **设置后必要的迁移、校验和同盘整理在后台自动进行，不要求逐个手工迁移。**
6. **二级及以上外来备份盘加入时，必须一次性设置并加入其所需低级磁盘；不允许先占位再补盘。**
7. **ZXS 启动与运行态只包含已经完整纳入的数据、数据库、标签和磁盘；离线辅助工具先处理外来接纳，不注册待添加/待初始化候选。**

例如将 `P → B旧` 更换为 `P → B新`，只有全部应迁整体在每个明确选中的新目标上可独立校验、能够按原承诺恢复，并完成持久化切换后，才可显示成功。拓扑候选数并未决定某个整体应选一盘还是多盘，不能代替显式放置策略。

- 这不是把目录主盘规则指向另一个一级盘。现有主盘规则只决定后续新版本的一级归属。
- 这不是为当前可见文件重跑一次备份设置，也不是只给未来版本增加一条链。
- 这不是把源目录复制过去后修改 `config.json`、`disk.json`、slot 名或物理 inode。
- 这不是外来盘离线 capsule 的发布。该 capsule 的完成标记不授予活动池写入或新拓扑权威。
- 数据全量是**受这次变化影响、仍应保留的完整文件或目录仓库集合**，不因列表筛选、软删除、分支不活跃、历史版本不再是 HEAD 而省略。某旧版本此前份数较低，也不能成为把它排除在新整体之外的理由；由新迁移收据证明补齐，旧 receipt 不改写。无关来源的材料不能被迁走或删除。
- 这是当前受支持格式内的业务数据迁移，不增加旧格式兼容、自动升级或池重置；遇未支持格式保留原数据并拒绝。

## 多下级关系与整体放置

### 拓扑边不是复制份数

一个备份盘可以连接多个紧邻下一级目标；拓扑表示**允许的直接下级集合**。具体文件/目录仓库选择哪些目标、选择一盘还是多盘，须由明确的策略决定。不能从下级数量推导份数；未明确选择策略时，不能默认向全部下级复制，也不能擅自随机、轮询或按剩余空间挑选一盘。

每条选择路径仍保持相邻级、来源绑定、无环和实际目标身份。二级及以上外来盘接入必须在同一设置/准入中提供全部所需低级盘与精确来源关系；依赖链未闭合时明确拒绝，不能先登记占位 slot、虚拟来源或声称成功后再补盘。尚未登记的私有准备目录只保存证据，既不是加入成功，也不能满足其它盘的来源依赖。 ZXS 的 Config/Current、目录树、数据库和标签读投影不得包含这些候选；离线辅助工具必须先完成外来接纳和完整链核验，再由正式决定开放完整成员。已有成员的真实损坏/掉线继续告警，不能靠隐藏错误伪造“干净”。多路径汇合时不能把同一盘上的一份材料重复计数；必须保存具体来源与路径证明。现有单链 `target_copies` 与 `route_slot_ids` 不能不经协议设计就解释为扇出分配。

### 最小分配和迁移单位

- **独立文件**：以稳定 `file_id` 的完整应保留集合为单位，包括全部正文版本、所有分支/历史节点、数据库/权威元数据、标签、删除/恢复事实和必要恢复证明。不按版本、节点或正文块分片。
- **目录仓库**：以稳定目录仓库身份及其冻结的全部应属内容、历史、节点、数据库/标签和结构为单位，不能把仓库内文件分别分配到不同备份盘来拼出“完整仓库”。普通目录名称不是仓库身份证明，须依据实际仓库登记和历史边界。
- **策略选择多个目标**：每个目标分别保存并验存整个单位；目标间材料的并集完整不合格。一个目标缺正文、另一个目标只有数据库，也不合格。
- **跨单位共享引用**：不能为凑完整度静默改 file ID、复制成新业务对象或把核心正文/数据库留成另一盘上的依赖。冲突归属和共享材料必须在同一闭包中明确处理。

### 嵌套目录仓库必须同盘

子仓库先有多级备份、父仓库随后启用时，父子在对应备份层的放置必须共同落在同一目标盘。父仓库整体不能排除子仓库的必需内容/历史来规避此约束；子仓库的独立身份、提交/分支、标签和旧收据也不能因同盘而被抹平或改写。

后台先解析稳定父子仓库身份、完整成员和共享引用，将需要同盘的父子作为联合放置约束，再生成完整迁移计划。既有布局不一致时先复制、校验父子完整材料，之后同一次决定切换对应层放置，不能先移动父库目录名称、再慢慢补子库历史。

父子多目标策略不兼容时，不能自动取交集/并集、缩减子库份数或任挑一盘。预览/后台状态必须列明冲突的稳定仓库身份、层级和目标集合，等待明确兼容的目标策略；**同盘约束已确定，不是需要再问用户的事项**。只有确实未指定的份数/目标选择语义才是待补产品契约。

### 容量与逐跳路径

容量准入以每个完整单位在每个已选目标的全部应保留材料计费，包括正文历史和必要元数据/结构，而不是当前文件大小。父子同盘联合闭包也必须能整体容纳。单盘空间不够时明确阻塞，不能把一个单位拆给两盘、缩减历史、静默减份或偷偷换盘。

每条选中路由仍按**直接上游盘名 + 上游相对结构**逐跳构造。替换中间目标时，下游相对结构和来源证明也进入同一个迁移计划；旧名称捕获/receipt 不重写。碰撞、同一单位互不一致的当前头或目标策略代数改变须拒绝，不以 mtime 或总字节数决议。

## 自动后台执行与可观测状态

用户设置父/子仓库备份或替换下级盘后，系统自动持久化所需任务并执行枚举、预留、复制、验存和同盘整理；不是要求用户再逐项“创建迁移计划/复制/切换”。内部计划是实现与审核边界，不是额外手工步骤。

**期望设置与已生效放置分离**：设置请求被接受不等于迁移完成。后台状态应区分排队、准备、复制、验存、待切换、已完成、资源/断盘阻塞、失败、决定未知和恢复中，并报告实际完整单位/对象/字节进度、具体原因与原 operation ID。不能把“已入队”或一份控制归档当“数据已迁移”。

任务队列与分阶段证据必须持久化，进程退出后自动恢复同一任务，不能依赖浏览器开着。执行使用有界并发与 I/O/空间预算；同一单位及父子同盘约束不能被两个任务独立切换。新设置覆盖旧期望时，按代数合并/停止未决定的任务并保留证据，不能修改已开始持久化的决定。

资源不足、断盘、源材料缺失或目标身份变化时停止推进并报告阻塞，旧有效布局和原数据保留；条件恢复后按同一任务重新验证并继续。最终切换前短暂冻结受影响单位、复查源变化与目标身份；初版若需要更大停写范围，必须明确告知，不能把长期全池停写称为无影响后台操作。决定后由恢复协议完成，不因客户端取消、关闭或新请求而伪称已回滚。

## 冻结计划与完整材料闭包

计划不是浏览器传来的版本列表。Engine 在同一个已准入 Current/State 边界枚举受影响对象，绑定：

1. pool、来源盘、旧/新直接目标集合的稳定身份，旧/新拓扑代际及登记 root；持有的新目录 device/inode 与独占 writer 归属。
2. 原发布序号、候选、State snapshot、历史 roots、允许的直接来源边、每个整体明确选中的完整路由/目标集合及策略代数；未决定一份或多份时任务不能猜测执行。
3. 每个文件/目录仓库整体的稳定身份、父子同盘关系、成员闭包、全部迁移项、缺失/清除/损坏分类、旧新逻辑路径、实际字节和逐目标空间预留；版本身份去重只用于枚举，不能用正文哈希去重不同业务版本的独立副本。
4. principal、永久 operation ID、审核摘要、目标精确集合。相同 operation 的重试始终恢复原计划，不能重新采样名称/目录/源范围。

原计划固定目标、整体身份、初始源边界与选择策略。准备期间允许的源变化须作为绑定该原计划的持久、可验证增量追加，逐项验存并纳入最终决定；不能覆盖原计划、静默重新枚举另一个范围，或在恢复时把未记录的变化当作已复制。

集合上限或空间不足应整笔拒绝或保持明确暂停，不能截断清单并把子集标为完成。

| 材料 | 必须覆盖和验证的内容 |
| --- | --- |
| 完整正文 | 每个受影响文件/目录仓库整体的全部仍保留版本，包括旧低份数、非 HEAD、归档/独立分支、共享引用、隐藏/软删除文件；长度、完整哈希、校验清单、版本描述、本地完成证明和真实普通文件 |
| 不可用与清除 | `Available` 却没有健康完整来源时不能切换；先恢复或报阻塞。已权威清除/迁出的正文不复活，迁移其 disposition、清除/迁移证明及所需引用闭包；不能把缺失伪装成已清除 |
| 文件历史 | 完整版本和父边、路径节点、标签/元数据节点、合并记录、分支/别名/选择/上下文、软删除及恢复事实、名称与备注。旧节点 ID、操作归属和语义保持 |
| 目录历史 | 当前与保留目录树、目录分支、选择和代数、目录仓库/共享布局、目录 Git 关系、空目录的真实快照和可恢复投影；父子仓库按同盘约束保留各自完整身份与历史，不能只迁当前路径 |
| 放置与备份结构 | 每个受影响版本的旧/新 route、目标份数、绑定代际、稳定文件备份路径、保留/继承策略、递归目录快照和直接来源前缀。改变中间级时必须纳入受影响下游，不能只复制新二级 |
| 控制与永久收据 | 已准入 State 全字段、原始发布链和成员证明、永久 operation/principal、计划/事件、清除记录、来源与恢复边界。控制鉴权材料只在池内部按原安全边界处理，不能出现在公开预览 DTO |
| 数据库 | 按权威 State/历史图及现有 SQLite 投影协议安装/重建并核对；不把运行中的 SQLite 主文件或 WAL 的盲拷当一致快照，不把缓存视为新权威 |
| 尚未发布工作 | 初版应拒绝受影响的未决 publication、封存/活动工作区及其他迁移，或在正式协议中精确转移其保留证据。不得丢弃已接受上传字节或另造成功收据 |

实现必须对 State 使用穷尽分类，对新字段显式决定迁移、保持或拒绝；不能只维护一份容易漏项的字符串字段表。目录快照等不在普通 State 表中的原生证据也必须纳入闭包。

## 协议阶段及决定点

下列名称是设计阶段，不是已经存在的 API 或 wire 字符串。

### 1. 审核和准备

后台由已接受的设置生成精确、受限的材料清单与预期新路由。选择新目标前确认身份、私有目录、权限、空目标规则、真实可用空间、固定元数据成员和现有操作状态。进入准备不切换有效路由。

新目录先持有目录句柄和 writer/生命周期责任；持久 reservation 必须早于第一次目标写。intent 精确绑定目标物理身份与旧发布边界。失败/取消保留可审查的准备材料，不覆盖无关文件。实现应以冻结快照复制并在切换时复查增量；如果初版只能冻结更大范围，必须把范围和停写代价作为明确限制，不能藏成短锁优化。

### 2. 全量独立复制

旧拓扑继续是唯一服务权威。源可以是旧路由上任一经身份和内容验证的健康完整副本；不能因为从三级读取就改变原一级归属。

逐对象复制到新目标的私有暂存命名空间，使用现有受限 FD 与 no-clobber/sync 原语。普通文件独立复制，不使用硬链接、reflink 或内容去重充当独立副本。复制结果核对长度、完整哈希、来源证明；同 operation 的已存在精确字节重新验存并同步，冲突字节保留并报错。

真实进度只能统计已完成并验存的对象/字节；hash 清单、准备计划、创建空目录和控制归档成功都不能令进度显示为“全部数据已迁移”。

### 3. 目标独立恢复验证

只使用新目标及它被承诺保留的控制证据，重新从磁盘解析：正文、原历史图、目录/标签/删除状态、永久收据、当前策略、来源证明及数据库投影。不得通过旧源回退把不完整副本误验为完整。

这里的独立恢复验证是材料完整性与离线历史恢复，不是允许单盘绕过固定成员 quorum 激活服务；活动池的恢复与新权威发布仍须满足各自原定成员证明。

原 `disk.json`、原 publication receipt 作为历史证据保持不变；新目标需要新身份和目标验存证明，不能复制旧物理 seal 后改 inode。目标身份在复制/验存/发布各必要线性化点保持有效。

### 4. 最终复查与新权威发布

冻结受影响写入后复查原 State/registry、精确材料集合、代际、空间预留、目标身份和授权。若准备期间允许并发写入，必须按同一协议补齐增量并重新验存，不能省略这步。

为迁移增加**独立的原生请求、全字段变更验证和 payload 准入分支**，绑定：

- 新活动来源边与登记/绑定身份，以及仍保留的旧历史定义；
- 全部且仅全部受影响的 current placements、目标路径和目录快照；
- 冻结计划、旧新元数据成员的必要证明、逐目标完整性证明、最终新 State 根；
- 新永久迁移收据和原收据集合逐项不变。

新 registry 和迁移后的放置必须在同一个可恢复决定中生效。不能先改一个 JSON 配置，不能先开放新写入再补旧正文，也不能放宽普通 upload/backup 的冷恢复准入来接纳任意历史 placement 改动。原固定成员 quorum 和新旧成员联合规则均不因在线数量变化而放宽。

历史拓扑与活动路由必须显式分离：旧定义仍验证旧候选；当前路由来自新迁移决定。现有 `Config`/registry 一一固定关系不支持这种替换，需在专用协议中设计并证明，而不是删除 `same_disk` 或 `continuation_state` 的相等检查。

### 5. 服务、重试与旧盘

只有新权威已完整发布、冷准入可通过时，UI 才显示完成并使用新备份盘。源盘/旧目标数据继续保留。移除旧目标上的应迁材料是独立清理动作，不是换盘的前置步骤；不能删除它承载的其他来源或元数据职责。

旧盘重新接入时按历史代际隔离，不能以旧 seal 或旧最高序号重新宣称当前。新目标故障不能自动回切旧映射，也不能让两边继续独立接受同一代际写入。

## 崩溃、取消和权限矩阵

| 中断位置 | 必须保持的结果 |
| --- | --- |
| 计划/预留之前 | 没有目标写入、没有路由变化 |
| 预留后、部分复制后 | 旧权威不变；精确原 operation 可继续；未知残片不删除、不采纳 |
| 全量验存后、决定前 | 仍是旧权威；可以按明确取消协议解除冻结，新材料不能当活动盘 |
| 新旧成员决定部分成功 | 结果未知且暂停相关写入；按持久决定恢复，不能报回滚成功或换新 operation |
| 决定后、投影/响应前 | 重开完成同一新权威；永久重试返回原收据，不再采样/复制另一目标 |
| 目标改名/换绑、损坏或空间不足 | 精确拒绝/暂停，保留源和目标证据，不降份数、不跳级 |
| 排队中权限撤销或基线改变 | 在提交线性化点拒绝；已完成的决定按恢复协议处理，不能擦除事实 |

## 实施切片与验收

第一条可宣布“迁移已实现”的纵切必须包括设置触发的真实后台复制、验存和最终权威切换，而不是只有模型或准备标记。可以先限定所有必需源可读、指定空目标、无未决操作、目标策略明确的完整单位；若只实现单目标子集，必须显式拒绝尚未支持的多目标/中间级场景。**单来源单目标不是最终架构**，实施限制不能删去多下级、父子同盘与整体不可拆分要求。

建议依赖顺序：

1. 设计与审核多下级候选拓扑、显式整体目标策略、父子仓库同盘约束、活动路由/历史证明关系及全材料闭包。
2. 设置触发的持久任务、后台准备/复制、逐目标独立验证、阻塞进度与取消/恢复。
3. 专用原生候选/精确 State+payload 证明、新旧权威决定及冷恢复。
4. HTTP 真实状态/权限/幂等入口和 Web 审核、进度、未知结果、恢复流程。
5. 更高级下游、多来源汇聚、复杂父子策略冲突、坏源恢复、整单位空间不足暂停及受控清理。多目标须逐盘完整验存，不把扇出当分片。

完成验收至少覆盖：两版以上正文（含旧低份数）、非当前分支、标签/备注、软删除、目录历史及空目录；多文件目录仓库不得拆盘；子库先设、父库后设的同层同盘自动整理。显式单目标和多目标策略各自验证，多个目标分别断开其他目标后仍能恢复完整单位。切换后移走旧盘并冷开逐版本校验；复制损坏/缺失/目标换绑/单目标空间不足不能拆分；决定前后真实故障边界；服务/浏览器关闭后后台重启恢复；精确永久重试；无关来源和旧 receipt 不变。中间级迁移还须验证后续每一级都以直接上游盘名加前缀。

### 本切片的验证边界

[真实 Engine 准入回归](../../test/engine/integration/backup_target_replacement.rs) 在 Initial/Current 两种权威下覆盖 `B01 → B02` 并重接 `C01`、同 slot 更换 disk 身份并提高绑定代际，两种普通 handoff 入口都必须拒绝。它验证拒绝后历史、标签、隐藏正文、目录和旧收据仍可冷开读取，**不验证多下级、整体分配、父子同盘整理、后台执行、复制到新盘、切换、掉电或 HTTP/Web 操作**。目录项/文件字节相等不等于全部文件系统元数据无写；运行结果单独保留，不以文档或测试存在代替实际执行。


## 历史材料后台准备切片

`Engine::start_backup_preparation` 是已有生产核心入口：先持久化本机精确任务，再绑定明确选择的空目标目录并启动受管理复制线程。常规 `Engine::open` 在恢复、准入当前状态之后自动重开同一任务，不需要再次点击复制。`backup_preparation_status` 可查询复制/校验数量、字节和具体失败原因；`wait_backup_preparation` 是宿主同步接口，不是手动推进复制。

这条入口目前只接受一个已登记一级来源的完整池、一个明确选择的新目标及一条既有末级备份边，拒绝多目标、中间级替换、多一级来源和未发布工作区。它没有把单目标写成未来拓扑约束，也没有从多个候选猜测复制份数。冻结全部历史根、所有应保留正文版本、分支、标签和软删除事实，在同一目标保存完整历史包，因此此子集不会按文件或子仓库拆盘。每个包使用已有出版证明与完整校验清单独立验存，目标不能借源回退通过。源数据、Config、Current、placement、永久操作收据和原拓扑均不改写。

任务固定 operation、pool/config/sequence/snapshot、历史根和目标 device/inode；复制持有来源正文租约与原 writer 锁，目标路径在使用前后核对。空间只看选定目标及尚缺材料，不能用其他盘容量抵扣。已存在的目标材料须与冻结输入一致并再次验存；损坏或不同内容拒绝保留，不覆盖、不截断。进度 JSON 只作显示，冷开重新从绑定任务和目标内容验存；源发布改变时标记 `SourceChanged`，不偷偷重新采样另一个范围。关闭 owner 会请求停止并等待线程退出，常规读/同步 I/O 的阻塞仍受操作系统约束，不能宣称任意故障下关机有硬时限。

热查询与冷恢复使用同一 pool/config/sequence/snapshot 绑定判定；只改变配置、尚未发布业务 State 的生命周期中断也不能沿用之前的完成状态。进度写盘不持有查询用的诊断锁，写盘期间可以返回上一份已缓存进度；这不提供强制中断底层 I/O 的保证。线程异常 join 后保留原任务与 `Blocked/RecoveryRequired`，相同请求的重试须重新核对冻结材料，不因句柄已消费或诊断缓存中毒而变成“没有任务”或健康完成。诊断中毒只关闭状态展示，不从该缓存恢复业务权威。

终态刻意命名为 **`HistoryPrepared`**：仅表示这一冻结历史材料已复制/验存，**不是备份盘替换成功**。尚缺原生控制/递归目录凭据的完整闭包、池权威中的持久任务、三层数据库迁移安装闭包、显式多目标分配和父子联合决定、新目标登记/拓扑切换、决定后的冷重放、HTTP/Web 设置与进度入口。SYSTEM 丢失时此本机任务尚不能从数据盘自动发现；一个任务保留期间不能被另一任务替换，取消/重新规划接口也未实现。其完成标记不能被登记、恢复或 UI 当作活动盘权威。

真实盘用例位于 [backup_preparation.rs](../../test/engine/integration/backup_preparation.rs)。覆盖及运行结果须以独立交付日志为准：owner 退出/重开不是物理断电认证；未测试的空间耗尽和进程中断点不按已通过报告。旧普通 handoff 的拒绝回归继续保留。

热配置窗口回归复用已有真实 disk-exit 故障点；[进度 I/O 用例](../../test/engine/integration/backup_preparation_progress_io.rs) 在隔离子进程对实际 SYSTEM 进度写入设有界门闩，不把普通延时或假状态当作查询并发证明。[线程生命周期用例](../../test/engine/unit/backup_preparation_status_tests.rs) 使用真实冻结 job/目录与受控线程 panic 检查 wait、重复请求和目标锁释放，不声称生产 I/O 会引发该 panic。运行结果与全测试接线的编译结果分别记录，不把用例存在当通过。

当前主线已有文件容器与已激活目录仓库的局部派生 SQLite 及保留式安装器；它们由源端已准入 State 恢复，不能独立选举权威。本准备入口仍只输出历史包，不把这些源端能力算作目标数据库已迁移。[组合回归](../../test/engine/integration/backup_preparation.rs) 分别检查源库原字节保持、目标没有伪造的数据库副本、缺失源库的正常冷恢复与同一准备任务重验。

### 已发布完整 State 的准备闭包（本切片代码，未编译验收）

准备 worker 在历史包之外，将同一冻结发布的 `snapshot` 对象图、配置/代际与 Candidate/Publication/Seal 证明写入独立 `pool-snapshot/`。这不是重新挑选或导入一个 State：先核原发布与 job 的 pool/config/sequence/snapshot，完整读取并准入全部 State 字段，与当时 Engine State 比较，再保存原对象字节。永久 `operations`、`operation_principals`、事件、当前软删除状态及 retained-copy receipt 中的旧 D/undo 前缀因属于完整快照而一同保留，不再声称只有 `HistoryManifest` 就包含它们。

目标验存不借用源：从目标重新加载完整快照、原发布证明和每个历史包，按完整 State 投影核对历史集合与内容；逐包校验所有应保留正文，冻结文件数/字节总数也必须相同。历史包遗漏一个历史、正文缺失、操作页损坏或完成摘要不符都不能通过。已有目标字节仅允许精确一致，不覆盖损坏/冲突文件。缺页的同一任务可在绑定仍有效时通过正常 owner 冷开补齐；源边界改变依旧 `SourceChanged`，不重新采样。

`offline_check_backup_preparation` 是只读的**目标材料检查**，返回序号、快照/完整 State 摘要、收据数量与历史报告，不返回控制凭据，不提供恢复、登记或切换令牌。它只读绑定的私有目标目录，不能将复制到另一物理根的材料当作同一任务。原 `history-prepared.json` 保持原含义和不可变字节；只读验存同时核对它的原 job 与历史报告，新 `snapshot-prepared.json` 也必须与重新验证的内容相符，旧标记不能冒充新增闭包已完成。状态仍为 `HistoryPrepared`，详情明确已补完整 State 材料，但尚未激活目标。

完整快照准备按**每次对象解码**计费（包括重复引用），限制 4096 次对象读取及 64 MiB 证明/对象字节；任何一个整体超限则明确 `ResourceLimit`，不截断。被冻结元数据上限外仍有原正文、历史包和配置资源预算。此片额外增加一次完整 State 冻结/准入与目标本地重验、历史包交叉重验；这是后台全量准备的 O(整体材料) 成本，不加入普通写入热路径，也不声称性能优化。进度的文件/字节数仍统计正文，状态区分复制与验证，并不把元数据数量假加成迁移完成。

**仍未完成**：原生成员控制归档及逐操作 Native 凭据、三范围数据库的目标安装/迁移、完整 State 的正式恢复导入、SYSTEM-loss 任务发现、多下级显式整体分配、父子旧布局合流、最终权威切换及其冷重放。普通 handoff 的替换拒绝仍保持；本片不删除源，不改路由，不使原 HistoryManifest 的跨池 restore 自动得到旧审计。文件/目录数据库仍是各自 scope 的派生物，不能用一个完整 State 包替代三份 scope 各异的数据库实现。

[目标材料真实回归](../../test/engine/integration/backup_preparation_snapshot.rs) 覆盖永久 delete/undo 及随后保存、移走源后的本地验存、缺页重开补齐、坏页保留、任务子集/虚假完成拒绝和正文缺失。另以真实 retained-copy 的双主盘池验证当前明确拒绝且旧审计/数据保全；完整 snapshot 编码覆盖 operations 不等于该未支持池已端到端迁移。文件存在不等于已运行，最终运行结果以绑定源码的交付记录为准。

目标边界补验沿 [独立准备验收用例](../../test/engine/integration/backup_preparation_target_admission.rs) 接入既有 Cargo 集成目标，额外覆盖真实 checksums 损坏、另一 job 的旧完成标记和“已准备仍不得替换已登记盘”的 Initial/Current × 两入口组合。它只验证拒绝和原权威保全，不是切换成功验收。

本切片按最新开发指示直接交付源码，未启动新 CI、Rust 编译或回归运行。上述回归为正式接线的测试源码，不是已通过的结果；完整迁移仍保持拒绝边界。


## 显式多目标完整单位准备

`Engine::start_backup_batch_preparation` 接收两个至八个**明确选中的完整副本目标**及一一对应的已持有目录句柄；不是候选盘列表，也不从选择数推导新的生产复制份数。每个目标都保存同一个单一级池的全部历史、父子仓库与已发布 State，不能按文件、历史节点、目录或数据库字段分片。当前仍保留一条既有末级边、无未发布工作区及完整来源可读的范围限制；Config 的活动拓扑仍是原协议，本入口不放宽为尚无决定协议的扇出路由。

首次进入时先在无目标写入的阶段核全目标集合：绝对规范路径、无互相嵌套、无 live pool/SYSTEM 重叠、不同持有身份、每盘完整容量及所有输入正文租约；生产模式另要求每个目标和源盘分处不同设备。开发模式允许一个文件系统中的独立测试目录，不把它称为硬件独立副本。目标上限八个、整批 intent/完成材料上限 4 MiB；共同 State 快照仍受自己的对象/字节预算，每个目标重新验存每一正文，不用硬链接/reflink去重。

先持久化不可变 `backup-preparation/batch.json`，才在目标安装原单目标 intent 与完整集合 `backup-batch.json`。一条受管理线程串行复制全部选定盘，持有原 writer 锁及全目标独占锁；状态的文件/字节总数按每盘实际完整副本计数，失败说明精确目标。容量不足、坏块、错误身份或任务冲突时整批保持阻塞，已复制的字节和原源均保留，不跳过失败盘、不降低份数、不伪称完成。只要保留任一旧单目标/多目标任务，另一种 API 都不能悄悄取代它。

正常冷开自动读取同一批任务，在打开任何目标前核原 pool/config/sequence/snapshot。原来源改变显示 `SourceChanged`，不重采样。原目标集合、次序、物理身份和全部历史闭包必须一致；缺失材料可继续原任务，冲突字节保留并阻塞。恢复不是仅相信显示进度：目标逐个本地验证完整快照、全部历史正文和原完成标记，然后整批重新核对并写 `backup-batch-prepared.json`。中断在整批标记逐盘写入之间时仍只是材料准备，下一次原任务补齐，不产生部分拓扑决定。

`offline_check_backup_preparation_batch` 必须收到全部选定盘，以持有资源逐个核原 intent、物理身份、快照/正文与整批完成材料。某盘仍可通过单盘材料检查不代表整个批次完整；移走/损坏任一选定盘，整批检查拒绝。检查本身不回源、不修复、不改目录，也不产生接纳/切换能力。

来源盘的每一级低级祖先必须已经正式启用并持有真实资源，不能用虚占位满足当前准备前置。**这不是外来三级→二级→一级同批接纳写者**：外来盘完整低级链的 helper 准入、原生控制归档、目标三范围数据库安装、源变化增量、父子旧异盘合流和一个共同权威切换仍未完成，继续明确拒绝，不向 ZXS 运行态注册待添加目标。原路径和多级直接上游前缀没有被改写。

本轮只交付源码及三项正式回归源码，按当前要求未编译、未运行测试、未做独立审查或 CI。原有历史验收不覆盖新多目标线程、资源与恢复路径。

### 原固定成员控制前缀后台准备（后继生产源码，未验收）

显式调用 `start_backup_native_preparation` 可为原单目标／二至八目标材料任务追加完整 fixed-genesis journal、逐出版 Snapshot／history 图和原收据绑定的 payload proof 复制。SYSTEM 先保存不可变全目标任务，后台逐盘验存，正常冷开续作；旧 `HistoryPrepared` 不被改写为新阶段成功。新 `NativeControlPrepared` 和只读报告均不是活动盘权威。实现范围、资源上限及未编译／测试／审查／CI边界见[原生控制材料准备](../design/backup-native-control-preparation.md)。代际归档、三范围数据库安装、完整低级链 helper 准入与最终共同切换仍未完成，普通 handoff 不放宽。
