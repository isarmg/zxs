# ADR 0005：增量发布与完整性责任分离

状态：**目标及分阶段实施方向已批准，尚未启用增量发布的旧依赖免读路径。** 本决策接受未触及旧数据的故障发现时点后移，不降低新写入持久化、读取验证或恢复证据要求；不是性能、巡检能力或故障验收已经完成的声明。

## 决策与代价

普通写入最终只准备实际写集及变化的元数据路径；未变不可变依赖可以沿用同一连续写者生命周期中真实成功发布所建立的耐久事实。发布成功仍要求全部当前配置成员和本次内容路由完成规定保护，但**不再表示本次重新读取、检查了所有旧依赖的当前字节**。已发布事实与当前健康是两种信息。

由真实读取、启动/恢复、导入导出及定期完整巡检承担相应完整性检查。必须先实现并验证完整巡检、状态与调度，再删除普通写入对未触及旧依赖的重新读验和补齐；只写文档、增加定时器或缓存一次成功结果都不满足门禁。

相对当前行为，下一次不相关的小写不再保证发现或补齐被删除的旧页，也可能直到读取、巡检或恢复才发现静默损坏。检测窗口由实际巡检覆盖和调度决定，不能承诺“下一次写必定发现”。若仍要求每次写前发现所有旧依赖的任意损坏，就保留全依赖 I/O，不能同时宣称端到端按写集增长。

当前普通准备在所有磁盘来源均缺失时，可能从仍有效的内存 State 精确重建原字段映射图或原历史根，再走原碰撞和同步规则；这不授权启动、恢复、导出从任意 State 或 SQLite 重定根。增量目标也不承诺在每次无关写入中保留这种全历史补齐时机。

## 责任与不变项

| 边界 | 必须承担的职责 |
| --- | --- |
| 普通发布 | 新写集、新节点和本次所需正文真正写入、校验、同步；全部配置成员、固定 N/Q、决定槽、ACCEPT/FINALIZE/PUBLICATION/封印的权威确认顺序不变；SQLite 是发布后独立健康的可重建加速器。复用仅适用于证明覆盖的未变依赖 |
| 实际读取 | 元数据按准确域/哈希、结构及上下文验证；持有正确正文身份，先验证可信清单及实际覆盖段的 bytes，再返回范围。打开 fd、长度相同或已发布状态都不是正文健康证明；无健康同版本副本明确失败，不补零、不返回别版 |
| 启动、重开、正常/降级恢复 | 以准确候选根和可信固定成员证据验证完整所需依赖；逐对象选可信健康副本，无健康副本即停止依赖该图的恢复。不能从 SQLite、任意逻辑投影、其他根或旧进程票据恢复权威；原有历史成功与当前内容降级分别记录 |
| 历史包导出、离线检查与恢复导入 | 验证准确根、全部可达索引/叶、逻辑闭包、发布证明与包中应保留的正文；导入重新验证外部 bytes、身份/冲突及目标路由，再执行目标池发布。复制或修复只使用已验证准确 bytes，不能以缓存成功替代源验证 |
| 单盘检查/导出 | 独立核验本盘实际持有的版本、清单、墓碑和完整发布材料；不依赖原服务器 SQLite，不推断全局最新状态或全池已恢复。N=1 合法但无冗余；唯一好副本丢失必须报不可用，不能制造内容或降低门槛 |
| 完整巡检 | 对明确发布基线、成员/绑定代际及范围实读元数据依赖和应保留正文；逐成员报告缺失、损坏、不可读与覆盖情况。检查不隐式修复，修复另按准确证据及原协议执行 |

**保留 pending 例外：** `select_file_branch` 与 `select_file_branch_at` 对待写入分支只选择冻结引用，允许来源正文缺失；非 pending 自有正文选择仍要求有效副本。前者不签发内容健康或新副本证明，不允许之后读取缺失 bytes。详见[分支语义](../06-history-and-branches.md#s06-02)及[现有回归](../../test/engine/unit/business/file_paths_tests.rs)。不得将巡检发现来源缺失一概变成禁止此类元数据选择，也不得把例外扩展为忽略损坏元数据或发布未保护的新正文。

公开库未知调用方、持久化/网络输入仍是真实边界。格式、长度、数值范围、资源预算、认证、授权、撤销、路径安全和设备身份检查保留；内部有效类型才可免重复解析。不新增旧格式兼容、双读或迁移；未知/旧格式明确拒绝并保留文件，不自动清理、重置池或改写证明。

## 已发布证明的来源和失效

目标使用私有、不可反序列化、不能由调用方构造的发布谱系证明，绑定精确 State 身份、快照/历史根、序号、配置成员和绑定代际及连续写者所有权。新依赖完成全部实际持久化阶段，完整权威发布后且原 metadata epoch 仍有效时，唯一生产路径才能签发；旧依赖必须可追溯到这一谱系内的真实成功发布。准备完成、单成员成功、磁盘对象存在或 hash 名称相同均不足以签发。不得引入公开 `already_synced` 布尔值或可伪造的假收据。

- 精确 State/根/配置不匹配、成员或绑定变化、重开/恢复、写者所有权中断、未决发布，以及发现所依赖元数据缺失/损坏或身份异常，使相关复用证明不可用。权威失败不得推进新证明；未完成的决定按原恢复规则收敛，不能回滚或开始下一槽位。纯 SQLite 索引失败不访问或改变配置成员的权威闭包，不撤销其 epoch、不改变已成立的发布结果；索引单独停用并保留原因，后续读取从 State 得到相同事实。
- 已知损坏不能仅记 warning 后继续沿用；先阻止依赖该证明的新发布，由有证据的修复/完整准入重新建立覆盖。内容健康仍按版本与操作需要判定，不抹掉上面的 pending 元数据选择例外，也不把历史成功改写为失败。
- 重开后的首次发布须完整准入并建立新的耐久依据；不能因序号/根相同复活旧内存证明。换成员须在全部所需成员重新建立真实依赖与回执，不复制旧盘收据冒充新盘持久化。
- 新编码 hash 恰好已存在时仍走真实 bytes 碰撞比较及必要文件/目录同步；它可能来自一次失败的 rename/目录同步，不能冒充已成功发布依赖。安全地址与原子安装边界不变。
- `stat`、inode、mtime/ctime、size、目录 fd、0700、flock、disk seal 或曾经 fsync 都不证明当前内容未变；没有“stat 健康凭证”。持有身份只证明自身契约，已发布谱系只证明历史耐久事实。无法察觉的外部替换/静默损坏仍是上述检测时点取舍，不能宣称被排他锁排除。

增量发布的私有 permit、对象生产来源和 PREPARE 后最终准入语义见[已发布依赖复用](../architecture/published-dependency-omission.md)。该实现说明不替代下述实际巡检、故障与 CI 放行证据。

## 分阶段门禁

阶段可独立提交；保持现有语义的容器/编码工作可以并行，但**阶段 4 的免读启用必须等待阶段 1–3 完成并验证**。每一阶段的计划、源码存在、测试执行及通过结果分开报告。

| 阶段 | 实施范围 | 放行条件 |
| --- | --- | --- |
| 1：真实有界完整巡检 | 完整元数据依赖和保留正文的执行器、状态、周期调度及明确前台资源预算；不是复用现有版本诊断结果冒充全图检查 | 覆盖下面的状态/失败/交错矩阵，正常路径和实际调度均有测试；旧依赖读验保持到门禁满足 |
| 2：持久 State 与权威写集 | 有界节点路径复制覆盖普通映射、大记录、永久 operations/operation_principals 和 events；写集继续追踪真实谱系，未知修改与超限保守回退；所有权索引由权威 State 派生并随根发布 | 旧快照隔离、随机插删/同值/移动与完整模型差分；序列化表示保持；跨历史归属、最后引用删除、批量变更和索引失败覆盖，永久幂等收据不裁剪 |
| 3：增量图与有界根 | 按写集更新历史投影与 canonical 图；快照字段根和 history→root 表改为有界树，不能把全量开销移到根或完整写集表 | 增量与独立完整编码器 hash/bytes 等价，分裂/收缩/空图/对抗键覆盖；当前格式原子更新全部读写、恢复、离线包、墓碑、预算、检查点和维护消费者，旧格式拒绝保留 |
| 4：增量发布 | 区分本次新编码和已发布谱系复用；只持久化新节点及规定协议材料，保留决定点与真实新写保护 | 阶段 1 的实际健康结果接入证明失效与写入阻断；故障矩阵覆盖失败票据、已知损坏、成员变化、恢复和 pending 例外；明确断言未触及损坏检测后移而非伪称旧行为等价 |
| 5：端到端验收 | 合法完整历史，1k/10k/100k 规模，单成员与多成员；warm 小写、冷启动/重开、修复、巡检分开测量 | 报告端到端时延、准备/决定锁等待、分配/驻留、编码/哈希/读取 bytes、对象安装及同步预算；逐项列残留全量路径，不以少写页面或单次耗时宣布完成 |

### 巡检门禁的具体含义

巡检必须有可验证的覆盖清单/游标及基线，不能仅枚举当前 State 中可读正文而漏掉候选绑定元数据；原有磁盘版本诊断还包含孤立/未发布目录及墓碑，不能静默改变其范围或计数。新增巡检与现有 `check` 是否共用执行器，须按实际生命周期证明，不以克隆配置根路径直接放锁。

状态至少区分未就绪、排队、运行、完整成功、部分失败、已取消及结果过期，记录基线/成员代际、开始/完成时间、实际覆盖、失败原因和最近完整成功时间。正常发布不刷新完整巡检成功时间。调度需有实际触发、去重/背压、重启后的未就绪规则及明确周期/新鲜度策略；没有完成覆盖、调度不可用或结果过期不得展示为健康或据此启用免读。具体周期与预算须随实现确定并验证，本文不虚构现有配置项或发现时限。

每批对象、正文缓冲、打开 fd、并发/带宽和保留租约须有上限，不能一次打开全池文件或无限积压。明确锁/资源所有者、撤权准入、取消与关闭、管理 drain/恢复隔离；处理 purge/迁移、detached 准备、最终发布与外部设备变化的交错，说明观测时间范围，不把跨盘扫描伪称原子健康快照。已观察故障应及时反馈失效，不等到整个扫描结束才容许阻断生效。

### 必需失败与回归矩阵

- 真实 bytes：同长度篡改、截断/增长、清单替换、根/索引/叶错误域或缺失、错误路由/墓碑、同名新 inode、子目录替换、换盘；一个好副本可用与全部好副本缺失分开断言。
- 发布：各成员写入、文件同步、rename、目录同步、PREPARE/ACCEPT 任意子集、FINALIZE/PUBLICATION/封印的权威失败与纯 SQLite 索引失败分别覆盖；前者按阶段保留拒绝、准备过期或未决／围栏语义及恢复证据，后者返回原发布收据及独立索引健康。失败尝试留下相同 hash 后重试仍建立权威屏障，不签发虚假证明。
- 巡检：未运行、部分覆盖、扫描错误、取消、关闭、调度停摆/重启、过期结果；同 purge/清除、发布、恢复及撤权交错，资源达到上限时保留明确结果和所有权。
- 边界：真实读回/范围返回、重开、正常与降级恢复、独立包导入导出、单盘无好副本失败、旧格式拒绝且文件保留；pending 缺失来源正文可选择而读取仍失败，非 pending 选择不放宽。

已有 [baseline 测试](../../test/engine/unit/engine/publication/history_baseline_tests.rs)只覆盖当前证明签发/匹配的部分边界，不等于上述巡检与新格式门禁通过。软件故障注入、实际调度、规模测量与物理断电验收分别给证据。

## 替代方案与范围

保留每次全依赖读取可维持当前检测/补齐时点，但 I/O 仍随总历史增长；只加 dirty bool、stat 缓存或跳过 `objects: None` 既无发布谱系，也没有健康责任闭环，不采用。新增一个全对象收据集合并逐事务复制同样不解决规模问题。

该方向不减少完整 State 的 O(N) 驻留承诺；实际改动 K 项、影响 A 个历史仍至少承担相应工作，大单记录和批量操作不可算成 O(1)。重开、修复、成员变更及完整巡检明确允许 O(total)，必须与 warm 增量路径分别报告。本决策不授权真实部署、凭据/权限变更、运行池重置或删除用户数据。
