# E：为普通文件分支的显式 Workspace 提交保留真正的创建来源

状态：2026-11-18 02:48 UTC 所有者批准下述 E。实现与回归源码分批提交，未运行或验收。既有 B 已涵盖普通 FILE 手动、目录显式、自动保存与首次节点；
本文把一种其他真实生产入口说清楚。不是新命令、自动统计扩容、格式兼容或生产部署。

## 真实入口与现在的缺口

服务端的 Workspace 提交调用实际的 `plan_workspace_commit_with_reserved`。它校验原主体、
Workspace、基准 HEAD、fence、选中的 occurrence 和上传材料；新内容由实际 `Prepared`
版本构造器产生。普通文件分支上传还受 `business/workspace/file_location.rs` 的
单一路径、不可变 base 与所选分支代数约束。这里不是目录快照的 worktree。

现有通用结果保证 commit、branch、history 和路径事实；仅在为新目录分配身份时才额外
保存可恢复的原 Workspace 输入。按同一个旧路径修改既有文件通常没有这份永久输入。
不能把 `kind=workspace.commit`、一次 Commit、同哈希、可见结果、当前文件名或当前模式
当作“这个 FILE 节点由本次显式提交创建”的证据。

## 单一请求

是否批准：在唯一全新池规范中的普通 Workspace 永久回执加入一个**必需**的来源判别，
为下列真实发表承载已定义的 `ManualFile` 原因与完整源封套？这不增加系统可写的文件种类。

- 只限 Initial、单 owner／单副本、已登记、已经有历史的普通 FILE。同一激活 FILE 分支，
  同一原始 EntryId/FileId，原注册父链未变，正好一份有实际变化的已封存上传；
  操作必须是显式业务提交。可在同一原命令的既有 native 或 wire 输入口达到这一条件，
  两者分别验证自身原请求摘要，不能混用。
- 新建（含 Unborn）、目录分支、快照 worktree、独立子仓、Current／代际、复制、导入、
  foreign、改名／移动／混合 namespace 操作、借用／未落定版本或其他原始 owner 均不记为此来源。
  未变化、准备、失败、重试也不是新节点。不能调包成“自动”，不参与自动发布数。
- 在实际构造改变的版本后，携带已验证原选择和准备产物进入同一原决定：Workspace 及原请求
  （主体、操作、workspace、base/head、fence）、唯一封存 item、完整路径、generation、大小、
  摘要、原基准 FILE 节点／版本与分支/目录选择代数；同时记录实际新 FileNodeId、owner、
  repository、由根到父的稳定目录身份、序号和**同一发表事件**的时间。哈希只验完整性。
  不保留口令、令牌、会话、正文或其他文件内容；不复制磁盘注册凭据。
- 已存在的通用提交结果仍只是一种规范：来源判别为“本次创建”或“没有这项创建”，不得省略。
  不能只相信写在收据里的判别。冷端须用同一 Candidate 的真实源/结果、原 workspace
  摘要及 FILE 版本／placement 证明，能独立决定有无义务。若真实前后状态形似该域，但
  只有封存输入才能区分混合请求、替代选择或无变化，必须附可校验的完整封存输入；
  高于现有整个收据、候选、路径或盘根预算则在写前拒绝，不在冷端接受一个方便的空值。
  具体编码须满足这个判别，不引入“缺字段即无来源”的第二读法。
- 原 Workspace 文件或上传缓存已清除也须精确冷验。被借用的可见覆写、不同主体、
  名称相同的替换物、后续选择或身体相同的旧节点不能补原材料。重复同一事务沿用原结果，
  原始已决定输入／主体／摘要不得改写或重签；未知介质首写前拒绝保留。

## 验收

要在合并后用真正的服务端显式提交、真实三范围闭包和冷重开核对：确实新建的普通节点得到
唯一原来源；相同内容／不同 FILE 或旧节点没有误认；修改任一稳定身份、源输入、主体、
决策状态、封套或判别均整体拒绝。覆盖来源在发布各界线中断、源 spool 已消失、精确重试、
有无目录／分支选择、不同入口摘要及资源上限。未有这类运行证据前，不标为验收完成。
