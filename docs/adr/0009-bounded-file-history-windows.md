# 0009：有界文件历史窗口与完整历史分离

状态：**提案（PROPOSED），尚未采纳或实现。** 建议采用下文 A：精确当前历史根上的可替换窗口。本文不改变当前 HTTP 响应、查询参数、历史保留、动作上限或恢复规则，不表示分页、资源保证或验收已经完成。端点和字段是供下一批协议评审的具体候选，不是已发布 API。

## 问题与真实消费者

当前文件管理历史路由只接受成对的 `repository_id/path`，拒绝 `limit/cursor`，一次返回完整 `versions/nodes/branches/merges`。共享 JSON 客户端最多接收 8 MiB，但服务端先构造完整投影；图算法和共享字段优化没有闭合这个容量缺口。当前事实仍以[API 规范](../15-api-and-errors.md#s15-02)、[容量规范](../19-capacity-and-performance.md)和[机器契约](../contracts/openapi.json)为准。

## 不变项与建议选择

1. 永久历史、节点、全部合法父关系、合并来源与永久操作收据不裁剪、不设 TTL。窗口驱逐只释放浏览器／请求工作集，不清除存储事实。
2. 仍可浏览并选择该文件任一获授权历史节点作为合并来源。分页和精确 ID 跳转改变访问方式，不改变该能力；搜索是可选加速，不是完整性依据。
3. 路径节点和元数据节点继续引用真实正文，不能制造 FULL、把 `node_id` 当 `version_id`，或用时间相邻推断父边。图父边、正文来源和合并输入是不同关系。
4. 只维护新的当前 HTTP 契约；不提供 `all=true`、旧整包回退、双格式解码或兼容别名。持久格式不因读取窗口而变更，未支持格式仍明确拒绝并保留数据。
5. 当前账号、对象归属、路径成员关系与写入依据继续在相应边界核验。游标和历史根不是授权、当前磁盘健康或未来操作成功凭据。

| 方案 | 取舍 |
| --- | --- |
| **A：精确当前根，可替换窗口（推荐）** | 每页要求根仍是当前目标历史的准确根；变化明确要求刷新。不保存服务端游标会话或旧快照库存，正常更新可能打断翻页 |
| B：固定旧根跨更新续读 | 浏览稳定，但要定义旧根保留、并发读租约、服务端配额、失效、恢复及当前授权；不能从“历史永久保存”推导“所有旧查询快照永久可读” |
| C：只限制节点数、提高 8 MiB、前端虚拟化或加载更多无限追加 | 分别遗漏高入度父边、分支／合并数组、服务端构造成本或浏览器累计驻留，不能闭合问题 |

## 候选协议：一个根，独立有界集合

以下路径的新增读取均使用 GET；路径中 `{file}`、`{node}`、`{version}`、`{merge}` 解析成各自 ID 类型，不能互换。所有页携带同一 `history_root`、归属和规范化查询身份。`limit` 是本页记录上限，不是历史总量；无 `cursor` 也只读首页。主历史／高级正文首页可以不提供根，由服务端捕获当前根；辅助读取和精确跳转必须提供来源页的 `history_root`，续页可由 cursor 携带。显式根与 cursor 同时提供时必须一致，不能把不同时间取得的辅助首页拼成同一观察。

| 候选端点 | 返回内容与排序 |
| --- | --- |
| `/api/file-manager/files/{file}/history` | 文件／所选上下文摘要、统一节点页、受独立边预算限制的父边预览、前后游标；节点沿现有 `(sequence DESC, node_id ASC)` 排序 |
| `/api/file-manager/files/{file}/history/nodes/{node}/parents` | 单节点完整合法图父关系的一个窗口，按父节点 ID 稳定排序；高入度节点也可继续读取 |
| `/api/file-manager/files/{file}/history/branches` | 该文件当前可展示分支的固定字段摘要页，沿用排除 Migrated 等既有规则并按 branch ID 排序；保留继承、只读别名、准确头和当前选择语义，不复制任意大小的 `pending_file_versions` 映射 |
| `/api/file-manager/files/{file}/history/merges` | 合并来源摘要页，按 `(sequence DESC, merge_id ASC)`；包含 chosen/result/survivor/reused，输入集合和保存的父关系分别给出续读入口 |
| `/api/file-manager/files/{file}/history/merges/{merge}/inputs` | 按原输入序号返回 `{branch_id, node_id}` 成对记录，不能分别分页两个平行数组造成错配 |
| `/api/file-manager/files/{file}/history/merges/{merge}/parents` | 按原记录序号读取保存的父关系页；与当前节点累计的图父关系区别表达 |
| `/api/files/{file}/history` | 正文版本摘要页，沿现有正文历史顺序固定 `(version_sequence ASC, version_id ASC)`；不夹带完整来源数组 |
| `/api/files/{file}/history/versions/{version}/sources` | 按原记录序号读取正文版本的真实 `source_version_ids` 页，独立于图父边，保留完整来源语义 |

文件管理主响应不再重复返回正文 `versions` 全集；正文节点摘要自身提供原位备注、分支创建和标签编辑所需字段，路径／元数据节点仍携带被复用的正文 ID。高级页采用正文 DTO，不反向伪造图节点。无界数组不能隐藏到“摘要”的任何嵌套字段中。

主窗口支持互斥于翻页游标的 `anchor_node_id`：在当前获授权文件范围内定位该节点所在窗口，并返回普通前后游标。点开窗口外父节点、备份固定节点或已选合并来源时**替换**窗口，不递归把全部祖先加入内存。第一页即使不含所选当前节点，也保留一个有界的当前上下文摘要和跳转入口，不能把当前标记挪到页内最新节点。无路径上下文时沿当前确定性归属选择规则解析一次，后续游标还绑定解析结果；已删除但历史仍在的文件继续可读。

### 大字段与单记录可达性

节点页只内联已有小字段契约覆盖的数据，例如 ID、时间、枚举、数值、备注、标签和受名称策略约束的路径；`message` 等尚未建立小字节上界的字段不能凭“通常很短”内联。提交消息没有由本提案新增写入长度限制。

建议为被明确外置的字段提供受同根和主体 ID 约束的字段读取，例如 `/api/file-manager/files/{file}/history/nodes/{node}/fields/{field}`。`field` 是协议枚举，不是任意 JSON 路径；正文高级页复用相同字段读取能力。响应给出完整字段字节长度、当前 UTF-8 完整片段、偏移和后续游标，每片仍受 JSON 字节预算，界面按片替换。只有确实全部读取后才标为 complete，不用省略号伪称完整，不要求客户端拼回整字段。空字段必须明确为空。

外置字段的最终清单须在实现前逐项盘点全部 DTO；作者、名称等若有现有有效上界则复用，未证明则外置，不能先分配任意大小字符串再测量。若选择不提供字段分片，则须明确承认合法大记录仍可能无法完整读取，不能宣称完整关闭历史容量缺口。这属于读取能力决策，不是提高网络上限的理由。

### 未加载父节点不是根、丢失或损坏

主响应每个节点提供显式父集合状态：`complete` 或 `more`；`more` 必须有绑定该节点的父边续读游标，即使该节点尚未分配到任何边预算。`complete` 且返回零父关系才表示这个读取范围内没有父关系。不得把“本页没有枚举到父边”写成空且完整。辅助父边页另用前后 cursor 表示所覆盖的区间；读到末页只证明后面没有更多，不能把只保留末页的界面改标为持有全部父集合。

每条已枚举父边包含真实父 ID，并区分端点 `in_window` 与 `outside_window`。后者显示“父节点未加载”及定位动作，不复制一个拥有正文／备注的假节点。主响应可据本页节点集标记，辅助页由浏览器在核对相同根后按当前节点集判定，不在 cursor 塞入全部窗口 ID。尚未枚举的父集合用一个继续读取标记表达，不列出全部未加载 ID 或为每个未知祖先创建 DOM。窗口布局只表达已加载子图，不能宣称其顶层是全历史的所有分支尖端。

跨文件、跨历史或未获授权的关系仍按业务投影排除，不能借占位符泄漏身份。`outside_window` 仅表示同一允许读取范围内的数据未驻留；与真实无父节点、PURGED/MIGRATED、永久损失、当前副本不可用及完整性错误分开。错误不能返回成功空图。合并复用祖先时为避免环省略的图边，仍由独立完整合并输入页保留来源，不伪装成分页缺边。

## 精确根、游标和授权

拟议根身份为已发布 Candidate 历史目录中**目标 history 的准确 `history-manifest` hash**，与同一个已准入 State 观察绑定；不是文件 ID、最后节点 ID、HistoryTree.generation、全池业务序号或 UI 列表摘要。现有 [`PagedHistoryRoot`](../../src/engine/src/history_package/graph.rs) 和 [`state_projection`](../../src/engine/src/state_projection.rs)覆盖版本、节点、备注、分支、别名、目录选择和永久内容状态等依赖；实现须复核当前投影新增的所有依赖也被覆盖。

当前根描述在引擎内部发布目录中，尚无适合这个读取协议的公开类型。新读取边界应取得由发布或恢复闭包绑定的根与 State，不得让 HTTP 自填根、每页重新编码全历史计算哈希，或从未经核验的 SQLite 行构造绑定。冷启动须从已验证的恢复材料建立同样绑定；不能依赖仅同进程成功发布才存在的缓存。绑定缺失或读取失败应具体失败，不用零哈希、全池序号或旧根回退。

[`PublishedDependencyReuse`](../../src/engine/src/engine/publication.rs) 的巡检覆盖和 MetadataEpoch 是当前写入免读准入，**不应成为历史查询根身份或历史永久有效性的定义**。根只标识一份确切已准入内容；不能证明当前盘健康或获得磁盘免读授权。当前健康如需展示应单列观察时间和状态，健康变差不能重写既有发布事实、丢失决定或操作结果。永久事实若经合法操作改变，新的根按普通规则使游标失效。

候选游标使用严格、长度受限的当前格式，至少绑定：

- 根 hash、history ID、file ID、端点／集合种类和适用的 node/version/merge ID；
- 原请求规范化后的 repository/path（含“未提供”状态）及实际解析的当前上下文；
- 排序、过滤／精确锚点、有效页预算策略标识与页大小；
- 方向和稳定的边界键；字段分片还绑定字段枚举与 UTF-8 字节偏移。

游标不携带全部遍历 frontier、visited、历史 ID 数组或旧页面；大小不随已读历史增长。采用无服务端缓存的非授权位置描述即可，不声称其签名、防篡改或账户绑定。客户端改写位置最多改变合法读取起点，不能改变作用域：重新解析全部类型，核对查询匹配、边界键属于该根中的允许集合，按服务端规则查询数据。无须为“安全”额外引入凭据、签名密钥或权限变更。

每页先做当前认证／撤销和对象授权，再比较根及当前位置；后续写操作仍核对当前权限和精确 expected head。对允许的当前对象，根或上下文变化建议返回新的 `409 HISTORY_CHANGED`，参数／游标与查询不符返回 `400 INVALID_REQUEST`，权限和不存在保留原具体错误。解析后的游标不能绕过这些检查，也不能把未授权对象是否变更泄漏为另一种错误。

分页按稳定键而非 offset 续读；相同根重试得到相同页和游标。在字节上限导致页长不同的情况下，前后游标仍从本页实际首尾键向对应方向读取，正向展示保持规范排序，不承诺“上一页恰好原来同样的行集合”。到末页必须显式无后续，非末页必须取得进展；拒绝空页携同一 cursor 的循环。

## 预算：先复用既有边界，不发明容量承诺

| 已有约束 | 来源和拟议复用 |
| --- | --- |
| JSON 响应 8 MiB | [`client_protocol::MAX_RESPONSE_BYTES`](../../src/contract/src/client_protocol.rs)；新增服务端页编码上限不得超过它，客户端流式／解码上限仍保留 |
| JSON 写请求 1 MiB | [`lib.rs::json_body`](../../src/server/src/lib.rs)，merge/tags 当前共用；跨页动作选择按**最终完整编码请求**预算，而不是另发明业务最大选择数 |
| merge/tags 条目不超过 `Config.max_entries` | [`file_merges.rs`](../../src/engine/src/business/file_merges.rs)、[`file_tags.rs`](../../src/engine/src/business/file_tags.rs)；保留当前核心准入。默认值不是历史容量或 UI 性能承诺 |
| 备注 128 UTF-8 字节；每节点 16 个标签，各 128 字节 | [`text.rs`](../../src/contract/src/text.rs)；直接用于节点摘要大小推导，不截断已有事实 |
| 路径 768 UTF-8 字节、200 UTF-16 单位、32 层 | [`name-policy`](../../src/naming/src/lib.rs)；沿当前路径类型，不创造第二份校验规则 |
| 目录页默认 200／最大 500、cursor 32768 ASCII 字符 | [`backend_listing.rs`](../../src/server/src/backend_listing.rs)；可作为交互测量起点和游标外层上限参考，**不能直接推导图节点或边应取相同值** |

设单个页完整编码上限为 `B <= MAX_RESPONSE_BYTES`，节点、父边、分支、合并摘要、关系成员分别有固定有限的记录预算 `N/E/R/M/I`。边预览也计入本页 `E`；不能只数 `nodes.len()`。每类记录的最小编码长度给出由 B 导出的绝对数量上界，但适合 DOM 的更小上限需要真实浏览器测量。具体页默认值和最大值是执行／交互调优，写入前要登记并测试；它们不限制用户永久历史或一次可浏览到的总量，不需要虚构“百万节点”等产品目标。

预算包括外壳、JSON 转义、分隔符、UTF-8、当前摘要、全部续读游标及占位字段。不能先完整序列化再检查 `len`，也不能只按未转义原始字符串字节计算。候选实现按已选有界记录逐个受限编码，预留外壳及游标空间，超本页剩余额度的完整记录留给下一页；已编码片段直接组成响应，不再全量二次序列化。不可拆摘要的最大编码须由字段边界证明可放入最小合法页；大字段走明确分片。预算减到无法容纳一个最小单元属于配置／请求拒绝，不返回成功但不可前进的页。

服务端只捕获必要的页 DTO 和请求寿命内的共享已准入观察，不保留按用户持续增长的页缓存。并发沿当前 backend slot 准入；响应准备、发送和取消的缓冲所有者须明确，不能在释放准入槽后无限堆积待发送页。

### 工作量与索引的诚实边界

现有 [`NodeProjection`](../../src/engine/src/business/file_nodes.rs) 每次建立合并索引、遍历首父标签链；历史展示还扫描提交、寻找来源路径。不得用它们先生成全部节点／边再裁页，或先收集所有父节点占位符。大字段、父数组和来源链也不能在 page-local DTO 之前无界复制。

首批可以保留借用已准入 State 的冷扫描，但必须分别证明请求新增空间有界、取消可达、锁持有范围和页选择完整性；其 CPU 时间仍可能随总历史／祖先链增长。若使用索引，索引只作可重建派生候选，与准确根及投影完整性绑定，索引缺失／损坏不能返回成功缺项。当前 SQLite 正文历史候选索引不自动覆盖路径节点、标签、合并、来源路径或分支。

完整 State 驻留、冷恢复、完整索引建设和发布成本不因此有界。只有在实际实现证明后才能给出页请求复杂度；本文不宣称 O(page)、吞吐提升或端到端容量达标，也不改变持久化同步预算。

## 浏览器有限保留窗口

建议页面所有者最多保留：一个主节点／边预览页、一个当前打开的父关系或合并来源页、一个分支选择页、一个字段片段、一个当前上下文摘要，以及一个紧凑动作选择集。分页为替换，关闭辅助面板释放其页；不以 `Vec::extend`、历史页 Map、不可见 DOM 或每个子节点各自 memo 留住旧窗口。

每种资源至多一个在途读取；换方向／换节点时取消旧请求，以 session epoch、文件、精确上下文、根及请求代数共同拒绝迟到响应。替换准备允许旧页与一个有界解码暂存短暂共存，安装后销毁旧布局、索引、路径、observer 与监听器；峰值预算须计入这些副本，而非只报告一个响应的 wire 字节。

合并／标签草稿只保存显式选中的 ID、expected head 及该动作必须保留的有限标签等数据，不复制候选节点／分支全集。跨页浏览继续可用；当前页没有选中项不表示撤销选择。新增选中项前核对最终动作请求 1 MiB 边界和当前核心条目约束，预留操作 ID、最长合法路径及其它固定字段；达界明确拒绝本次新增，不自动删旧选择、拆成多笔事务或提交子集。所选列表自身分页渲染；选中记录的数目和每项附属数据均由上述预算给出有限上界。任何较小的独立 UI 选中上限会实质缩小当前动作能力，须单独决定，不能混称内部调优。

用户编辑备注／分支名时，显式换页须先完成或取消该编辑；不能靠节点卸载丢输入。合并来源选择器可分页遍历任意节点并显示当前所选来源，即使它不在主图页中；最多保留一个选中来源摘要，不拉全图。搜索若新增，应明确定义匹配字段、大小写／Unicode 规则及有界查询长度，换搜索条件即新查询，不混接旧游标。

`HISTORY_CHANGED` 或动作后刷新使相关页失效并关闭旧图写入入口。已有动作选择和草稿可留作有界待重审输入，但不能自动把 expected head 更新成新值后提交；用户须看到变化并重新确认。刷新失败不能恢复旧页的可写控制。注销、文件／别名／备份目标变化清理不再适用的页与选择，不能把同 file ID 的另一条路径误认为同一上下文。

## 一次完整协议批次的迁移和验收

这不是按源文件数量划分的“先服务端分页、Web 以后再改”。同一批次应覆盖共享 wire 类型与严格解码、上述两个现有路由及新增读取路由、Backend 与准入代理、引擎页投影、Web 所有消费者、OpenAPI/schema/固定样例/契约校验及主规范。内部 `Engine::file_history` 是否继续返回完整数组按真实调用方分别判断；它不能作为旧 HTTP 全量兼容出口。

现有回归是语义起点，不表示新方案通过：

- [`backend_file_history.rs`](../../test/server/unit/backend_file_history.rs)：字段白名单、u64 文本、稀疏当前内容、严格原始 JSON 和成对路径上下文。
- [`history_nodes_tests.rs`](../../test/server/unit/engine_backend/file_manager/history_nodes_tests.rs)：图投影、准确序号及 ID 并列顺序、错误传播、脱离目录的文件历史。
- [`history_query_tests.rs`](../../test/server/unit/engine_backend/file_manager/history_query_tests.rs)及 [`revocation_tests.rs`](../../test/server/unit/engine_backend/revocation_tests.rs)：当前准入、退出／撤权与全部读取代理。
- [`read_projection/history_tests.rs`](../../test/server/unit/engine_backend/read_projection/history_tests.rs)：高级正文历史字段与锁外序列化；新正文页需要保持其事实语义。
- Web [`model/tests.rs`](../../test/web/unit/files/model/tests.rs)、[`history_index/tests.rs`](../../test/web/unit/files/history_index/tests.rs)、[`version_tree/tests.rs`](../../test/web/unit/files/version_tree/tests.rs)、[`merge/tests.rs`](../../test/web/unit/files/merge/tests.rs)、[`tags/tests.rs`](../../test/web/unit/files/tags/tests.rs)：别名、备份、真实节点、标签继承、合并来源和选中目标完整性。

新增验收至少包括：

1. **完整可达**：小预算夹具跨多页穷尽节点、正文版本、分支、合并及各关系，集合与独立完整 oracle 相等；重复请求、前后导航、同序号、u64::MAX、空集合和尾页无遗漏／重复／游标循环。正反导航不要求字节切页边界重合。
2. **极端单体**：一个节点的多父边、被反复复用的合并节点、单合并大量输入、巨大提交消息、最大路径／备注／标签及多字节转义；逐页字节和记录上限始终成立，单节点和单字段仍能完整读到，不靠截断或增大客户端上限。
3. **根与作用域**：改 file/history/node/merge、路径别名、查询、预算、方向及 cursor 偏移均不能逃逸；根改变（含只改备注／标签／选择）拒绝续接。目标历史不变而无关历史变化不应被全池序号误伤。冷重启必须得到准确根，不用热缓存替代。
4. **实时授权**：续页、字段片段、精确 ID 跳转和辅助选择器在注销／撤权后拒绝；旧 cursor 不赋权。错误和不足权限不返回伪空集合。新路由纳入 backend admission、HTTP panic/取消、auth generation 和代理转发矩阵。
5. **图含义**：窗口外父节点显示未加载；真正根、未枚举父集合、PURGED/MIGRATED、当前不可用、永久损失和损坏分开；不能因分页制造环、虚构正文或丢失复用祖先的合并来源。当前健康变化不改写永久发布结果。
6. **有限 UI**：持续翻页／展开父关系／查找合并来源时，驻留节点、边、页面、派生索引、DOM、observer 和动作选择都有可断言上界；测量短暂解码峰值。反复切换、Back/Forward、取消、关闭、注销及迟到响应均不恢复旧页。
7. **动作保真**：跨页选取旧节点、参与分支及标签目标仍可完成原完整动作；达请求预算拒绝新增而不隐式拆批；页驱逐不删选择，根变化保留输入但要求重审，刷新失败不重新启用旧依据。备份固定版本和同文件不同别名不混用。
8. **全部协议出口**：两个历史 HTTP 入口均默认分页，未知／重复参数和不支持 cursor 格式明确拒绝；不存在无界 `all` 模式或旧 JSON 回退。schema、固定样例和真实原始 wire 一致，字节预算覆盖所有辅助接口和错误外壳。

所有业务测试继续在根 `test/` 接入实际宿主／WASM／浏览器目标，保留当前本地依赖与框架策略。静态阅读、契约测试、浏览器驻留测量和真实运行分别记录，不能互相代替。

## 仍须决定的边界

- **产品行为**：是否采纳 A 的“当前根变化即重载”而不承诺跨写旧快照；采纳后明确草稿保留／重审和正在编辑时换页规则。
- **读取能力**：采用有界摘要与可完整访问的外置字段，还是明确留下合法大字段不可读缺口；不能无声删字段。分页和精确 ID 定位应保留任意历史节点选择，搜索语义可单独决定。
- **内部调优**：各页记录默认值／最大值、B 的选取、游标具体编码和大小、边预览分配、冷扫描与索引取舍；须由字段最大编码推导和浏览器测量支持，不属于历史保留政策。
- **不默认新增**：较小动作选择上限、旧快照保留服务、TTL、写入消息新上限、历史删除、持久格式迁移、部署、权限或凭据变化。

只有上述决策和所有实际消费者一起落地并验证后，才能在主规范中删除“文件历史仍整包返回”的已知限制。本文只建立下一批的设计和验收边界。
