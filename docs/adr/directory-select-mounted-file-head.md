# 外层目录提交：选挂载中的文件，在提交时取它绑定分支的最新节点

**业务决定：所有者 2026-11-18 04:44:50 UTC 最终澄清。实现分片进行中，未验收。**
用户选外层目录仓库里面真实可见的 worktree 中的**文件出现位置**，不选 FILE 版本。
同一次外层提交由写者确定该出现位置当前对应的稳定 FILE 容器、准确分支，以及**该分支
此刻的最新正式节点**；把它的完整正文固化到外层新不可变节点。它可以是继承的分支节点，
不要求由内层 worktree 刚创建。已确认但尚未发布的新稿、打开的脏句柄、原快照的旧
版本、全盘最近时间、其他分支的最新版本，都不替代这个头。没有合格节点就明确拒绝整批。

## 从现有权威取得选择

1. 外层精确 `SnapshotHandle` 和实际已登记目录身份、持有的注册根；内层精确
   `WorktreeHandle`、该次可见挂载 `visible`、修订、ledger checkpoint、实例和父目录。
   以挂载所在的真实用户目录建立包含关系，而非以 `.zxs` 存放目录、显示路径前缀、
   同 FileId、同名仓库或同一磁盘作证明。外层当前写权限与内层当前读权限必须同时成立。
2. 用户选择按外层可见相对路径排序并去重。映射到源 worktree 后按**一个出现位置**
   求分支：原节点行保留准确 source reference、原行索引和原路径；重命名只改可见名，
   移除行不可选。若该出现位置已有正式 FILE 结果，使用其准确 FILE 容器和分支（包括
   已路由的历史分叉），后来的脏修改不覆盖此结果；否则使用该行在不可变原节点中的
   Container 分支。新增文件用原 `EntryId`、birth 与正式 FILE 身份建立对应；
   未有正式 FILE 分支／节点、SnapshotOnly、目录、隐藏／未决挂载均不能被当成有正文。
3. 从该**特定**分支的原生状态读取 `head_commit_id`、分支 generation 和
   `branch_head`；用 `node_version(file,node)` 得到实际正文版本。路径/元数据节点可
   保有独立节点身份并映射到已有正文。合并决定复用正文不等于“最大版本序号”；不
   跳转 merged alias 的其他分支。分别保留 FileId、BranchId、FileNodeId、VersionId、
   version 所属 history、大小、摘要、原操作与根/容器实物。不能从 body/hash 反推分支。
4. 仅纳入能在**同一注册普通盘**核对、可正常读取且原节点未退役的来源；实际根、
   父／实体、完整正文和注册绑定证明缺一个，就拒绝／留待重试，不认作终态。外层新
   节点写独立 FULL（同正文不同出现位置仍是不同逻辑行），不 MOVE 内层正文、不升级
   内层草稿、不提交源 FILE、不随源后来写入／隐藏／原名重用而改变。
5. 外层原生 Candidate 是唯一业务决定。若准备阶段允许解锁，在同一最终写者重新核对
   外层原头、两侧授权、真实挂载关系／令牌／修订、FILE 分支及对应 HEAD；任何变化
   必须重新从其当前权威捕获整个选择或明确拒绝，不能把不同时间的各行拼成一次成功。
   成功重试按原 operation 的原决定返回，不能在变了头以后重选。容量合计覆盖每个
   来源、外层 FULL、目录/SYSTEM/DISK；先判资源，再准备物料，最后一次原生决定。

## 可达边界与施工顺序

现有 Initialize、CreateWorktree 和根级 SMB 路由目前只会产生同一注册根的来源及
挂载，目录工作稿选择本身只认自己的普通 FILE。**两个独立目录仓库的已验证包含关系
尚不是这些入口现成的事实。** 先实现／验证内层出现位置到准确分支、当前正式节点、
实物的只读生产器；此步骤不是外层提交完成。

第一个真实跨目录拓扑限定为一个已登记外层根和同盘直接子普通目录里的独立快照仓库；
依照既有“原目录之父显示 worktree”规则，内层实例挂在该外层根下，用户可选明确的
挂载内文件。必须分别登记子仓库自己的 HostEvidence 和外层父目录中的挂载权属，挂载
不换 WorktreeId，也不让宿主接管内层物料。后续按实际来源给既有目录提交增加**类型化
已发布 FILE 分支选择**，不能把它伪装为 Born/Unborn 工作稿；该类型的读取从不清稿，
也不创建独立 FILE 决定。传输／持久封套的确切字段须与负责原生目录决定和 FILE 的分片
共同核准后落地，不为未来版本增加兼容分支。不开放任意层级、跨盘活引用、递归枚举、
全盘扫描或复制整棵 worktree。
