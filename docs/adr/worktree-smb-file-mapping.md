# SMB 跨 worktree 移动：映射、提交和移出的三个时刻

**所有者于 2026-11-18 先后澄清本规则，本文采用最后的版本。设计已确定，以下新增移动路径尚未开放。**

| 操作 | 工作树中的变化 | FILE 与实物 |
|---|---|---|
| 普通目录或已删除数据 → 工作树 | 加入指向所选 FILE 的映射。目标同名且是同一个 FILE 时，将该出现位置更新到来源实际呈现的准确分支／节点。目标名未用时加入另一条独立映射，原有映射保留。 | 原 FILE、原路径和可见状态不变。普通源不隐藏，已删除源不恢复；不移动容器，不复制正文，不产生 FILE 节点。 |
| 正式提交该工作树中的映射 | 仅将正式决定实际纳入的映射记为已提交；保留该出现位置、所选节点和正文的准确对应。 | **此时**才将完整正文独立复制到本次 `.zxs` 节点，非硬链接。之后源变更、隐藏、重名或再映射均不改变该历史节点。 |
| 工作树 → 普通目录 | 目标成功时只移除本次操作所指的工作树映射；不重写其他工作树的映射或历史快照。 | 同盘：只有能从原移入与完整正式提交记录证明**同一工作树的这一次移入出现位置从未被提交包含**，才可从真实当前归属位置直接移动整个原 FILE 容器。已经被正式提交包含的出现位置则复制当前可见文件，在目标创建新 FileId／EntryId、自含首个 FULL，原 FILE 和历史不动。 |

### 不从路径推断来历

- 源读取是 SMB 此刻实际签发的原 FILE 视图（普通或保留的实际 site、stable FILE、历史树、真实分支、节点、VersionId、注册根/父/实体），不是全局最近版本。目标以真实 worktree handle、可见令牌、修订、准确相对路径和该位置的持久身份确定；名称比较遵循同一大小写／Unicode 规则。
- 一个稳定 FileId 可在多个工作树及同一工作树的多个位置出现。以原移入操作与该工作树位置的身份区分；只靠相同名、相同字节或相同 FileId，不能证明它是原移入位置。将同一路径重新映射时，保留前一出现位置/提交证据，不能让“曾提交的映射”借替换恢复成可移走原容器。缺失历史、未决定的提交、隐藏或重用的挂载均不是“从未提交”的证明。
- 实际写者须同时验证两侧当前权限、源可读的准确逻辑视图、可见令牌／修订、原 FILE 的实际 site 与归属、目标父目录和名称的空闲／冲突状态。拒绝其他 FILE 占名、物理同名替换、断开的注册、未知/冲突来源及可能丢失脏句柄的操作；不扫全盘补齐、不覆盖，也不用尚未确认的临时正文来凑成功。
- 映射仅有逻辑身份，不取得 FILE 的物理保管权。原容器直接移出须有对真实源和目标的移动授权并保持其他现存引用按 stable FILE 可解析；复制模式必须独立分配、以目标文件名创建首个版本，不能把旧版本设为新 FILE 的父提交。原 FILE 中各版本按自己提交时的名字保留，不按目标工作树路径改写。
- 移出使用一次原生决定绑定目标成功与准确源映射的退休；保留目的新身份或原移动身份和物理父／实体，原操作重试只恢复这个结果，绝不再建第二个容器。对外不可出现“已移除源但目标没发布”。具体原生提交之前可预备不可见物料，不能据此报告完成。跨盘真实身份迁移不属于这条同盘规则。

### SMB 显示名由该映射当前配置的节点决定

例：实际容器在普通目录下叫 `main-final.xlsx`，某工作树映射配置的是历史节点 `baseline.xlsx`。
SMB 在该映射父目录显示 `baseline.xlsx`，不显示 `main-final.xlsx`，也不显示带 15 位存储 ID
的物理正文叶名。稍后显式将这条映射切换至名为 `review.xlsx` 的节点，一次决定把该出现位置的
SMB 目录项由 `baseline.xlsx` 改为 `review.xlsx`；原容器、正文叶和已发布的目录节点均不改名。
若 `REVIEW.xlsx` 等价名已由其他行／保留中的请求占用，则整次切换冲突，旧映射和两条原名保持。
路径／元数据节点可能用已有正文但具有独立的正式文件名；不可只凭 VersionId／正文创建名猜它。

显式移入的目标父和所请求名称用于确定原操作与工作树里的准确出现位置，并不覆盖节点自己的
SMB 文件名。目标原行只有在稳定 FILE 与该出现位置都匹配时才可更新；新位置使用新的出现位置
身份，不能改动另一映射。新建或更新都须同时检查映射位置及**实际将显示的**目录项；同一父目录
下两个映射最终投影到同一个等价名时不静默覆盖、不藏一行、不私造别名，拒绝该次冲突。
该显示规则只限工作树 SMB，既不改普通 SMB 视图，也不强制把映射切到该分支最新节点。

### 与外层目录选文件的区别

[外层目录工作树文件选择](directory-select-mounted-file-head.md) 是**另一种**提交：用户选内层文件出现位置，外层写者在同一提交截点取它实际对应的 FILE 分支最新正式 HEAD。这个规则不等于移入时自动跟随 HEAD，也不等于从工作树移出时可用分支最新正文代替当前可见文件。
