# 0012：阶段屏障内的跨盘并行与有界正文扇出

## 决策与不变量

```text
PayloadCopy → SnapshotInstall → ManifestInstall → Prepare
→ 决定准入 → Accept → Finalize → Names → CommitProofs
→ Publication → Seals → PublicationProofs → 安装内存状态
```

Prepare、Accept、Finalize、Publication 和 Seals 每成员一个任务；正文证明按盘分组，同盘候选顺序不变。Names 保持串行。每阶段最多八个作用域工作线程，下一阶段必须等所有已开始任务结束并 join；停止领取新任务不取消已经开始的写入。最小失败成员索引的原错误优先，附加完成/失败成员集合用于诊断；非前缀成功集合不能被当作失败前缀。线程创建使用可失败接口，失败也关闭准入并 join 已启动线程；panic 在线程结束后继续传播。

同盘独占 JournalWriter 借用、PREPARE → ACCEPT → FINALIZE → PUBLICATION 日志链、Live/Recovery 追加语义、全部配置成员规则、Q 决定点和确认边界均不变。Prepare 失败保留原错误；决定准入后失败保持 IN_DOUBT，不撤销其他成员已经持久化的结果。日志写入失败仍设置恢复围栏。已有认证对象图、永久操作收据、冷 locator 根、准备命名空间对象和 seal 准入不能由并行执行替代。

正文仍是独立创建、完整显式写入的普通文件，不使用 hardlink、reflink 或内核共享副本。优化扇出的唯一读者对源块计算一次全文件及逐块散列，编码一次校验清单并核对版本长度、内容哈希和清单哈希；全部成立后才发布绑定该版本的私有 `VerifiedSourceSummary`。目标消费同一批不可变 Arc 块的 FIFO 序列，逐块 `write_all`，核对已写总长度、设置只读权限并 fsync，不对同一内存块重复散列。只有读者完整完成且所有目标封存成功，才允许 NOREPLACE rename 和目录同步，再完成该盘元数据和容器安装；所有安装共享同一份规范清单字节，不重新编码。后续安装失败保留已经封存的恢复材料，不伪装成回滚。

源证明只覆盖输入字节，不证明目标盘上的字节。准备完成后对各目标文件的实际读回、块/全量散列、持有 inode 和元数据戳核对均保留；恢复读取也不复用此内存源证明。源证明在 EOF 返回前发布到本次调用的 OnceLock，不能跨请求缓存或单独构造持久化副本凭据。即使源证明已生成，读者 unwind、目标失败或参与者 drop 仍阻止全体封存决定。

## 资源预算与回退

- 正文仍按文件分组，同文件版本串行。优化路径最多四个文件组读者，每版本最多八个目标线程：最多 32 个目标线程及四个组工作线程。成员阶段与准备阶段不重叠。
- 每目标通道最多两个共享 Arc 块；慢目标对读者施加背压。同一版本最多四个存活块，最大块 4 MiB，因此每版本正文块最多 16 MiB，四组最多 64 MiB。
- 优化准入同时计算 `ceil(logical_size / chunk_size)`，暂不扩大原保守包络 `4*K*(M+1) <= 16 MiB/版本`（K 为目标数，M 为清单编码长度）。实际校验元数据峰值分阶段计：源验证时精确预留的 digest vector D 与一次编码 M 共存；D 随编码结束释放。安装时只保留共享 M，加上每个目标不可变写入可能分配的碰撞读缓冲，至多 `M+2*K*(M+1)`。两者均受原包络覆盖，四组的这部分工作数据至多 64 MiB，正文块另计。源增长在超过版本长度时立即拒绝，不能把矢量增长到配置最大值。这里不包括线程栈、对象/路径、元数据编码、已有 Engine 资源和其他独立请求的内存，不能据此声称整个阶段或进程只有 128 MiB。
- **这不是产品文件或路由限制。** 超过八目标或校验工作预算的版本保留原串行独立复制链及校验算法；只缺一个目标也使用原单线程复制。若一次准备含任何超出优化包络的版本，全部文件组串行，避免四组放大大文件清单预算。大清单的正文证明验证同样降低为一个工作线程。现有最大 512 MiB 清单格式不缩小，单份清单的编码/读取分配仍可能为其数倍，不声称全局内存上限。
- 持久化校验清单读取先按版本长度和块大小计算精确编码上限，再读散列及解码；格式级 512 MiB 上限不能作为小版本的读取预算。损坏文件超过预期长度时在分配/读取前拒绝，读取期间增长最多额外读取一个越界字节；全量恢复验证和准备凭据复验共用该边界。
- 新复制每个活动目标持有一个正文文件及常数个目录/元数据文件，复制时不为全部路由同时打开文件；回退一次只处理一个目标。已有准备凭据最多保留 128 个正文文件；配置拥有的磁盘根、seal、日志等描述符另计。故活跃复制 FD 随固定工作线程数而非路由总数增长；不声称配置自身或整个进程的 FD 总量恒定。
- 每个目标的参与者 guard 在第一次启动线程前建立；启动部分失败时，失败闭包及所有未启动 guard 都报告未封存。读者的 RAII 所有权在错误或 unwind 时关闭全部通道并公布失败，避免目标在不存在的参与者或不会到来的 EOF 上永久等待。所有权随作用域结束，函数返回后没有后台晚写。

## 观测语义

StageSequence 从正文准备的同一个 Instant 开始，DetachedPublication 保留该起点；决定阶段不会重置时钟。阶段偏移与耗时包含真实顺序及准备和决定间的等待，不把拼接后的两个相对时钟当成一个时间轴。

StageIo 是**成功完成的逻辑工作**，不是系统调用统计：objects/proofs_completed 包含相同对象的 compare-and-sync；records_completed 只计成功追加同步的新帧，幂等旧帧为零；logical_bytes_completed 对应成功调用的对象、证明、帧及正文长度。失败/部分写入、正文侧元数据、未显式观测的验证和目录读取不在这些字节计数中。payload_source_bytes_completed 只计完整成功复制组的源长度；优化扇出单读一次，串行回退每目标读取一次；后续完整验证读取另计，不能称端到端正文只读一次。

因此这些数字不能推导 syscall、fsync 次数或物理吞吐。独立物理盘、真实 ENOSPC、掉电及延迟分位数需要单独绑定提交的执行证据；源码测试与旧快照 trace 均不代替该证据。

共享证明的回归测试核对 Arc 和编码缓冲身份、源流边界实际交付的字节/块、K 份独立文件的长度与内容，以及目标文件损坏后的读回拒绝；不在业务函数插入临时计数器，也不把手动事件声明为真实哈希调用数。唯一源散列/编码所有权由 SourceReader 的源码结构审阅确认。串行验证也复用已有承诺校验产生的编码，导出后直接丢弃凭据的调用方不会因此新增一遍编码。

## 代价及未采用方案

慢目标限制一个版本的源读取进度；跨成员失败可能留下非前缀持久化集合；每目标仍独立完整写入、同步并在后续 I/O 边界读回验证；每阶段创建线程有开销。保留全部原 fsync/fdatasync/目录同步及恢复证明，不采用组提交、省略封印、并行 Names 或降低固定成员要求。共享证明只消除同一不可变输入的重复计算，不声称消除了目标设备 I/O 或已取得物理吞吐收益。
