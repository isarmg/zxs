# 目录完整快照的不可变节点材料

## 边界

目录 `.zxs` 使用独立的 `SnapshotRepositoryId`、`SnapshotNodeId` 和
`SnapshotBranchId`，不复用旧目录 Git 的仓库、树或分支引用。此切片只建立
完整节点材料、外部决定绑定和精确冷读；不把结构 catalog、自报 marker 或目录
名字升级为权威。SYSTEM/DISK 初始化日志、线上注册、分支 head 事务与客户端
接线仍需独立完成。

目录分支 HEAD 不写入不可变 manifest。worktree 的来源固定仓库、节点、
manifest 承诺及所选分支；提交时在权威写者锁内重新判断该分支 HEAD。
源节点仍是最新时延续该分支，否则建立新分支和节点。可变 HEAD 不能反向改写
源快照材料，也不能让软删除 worktree 成为同节点新实例的来源。

## 完整材料与准入

每个节点位于 `.zxs/<snapshot_node_id>/`，内部只有：

- `manifest.json`：严格 canonical JSON，完整平铺的相对路径及文件身份。
- `files/<version_id>`：每个唯一版本的独立完整正文副本，不使用硬链接。
- `worktrees/`：独立管理的可变实例父目录，初始化时独占建立并记录 inode。

manifest 必须具备固定格式、仓库 ID、节点 ID、操作 ID 和完整 entries 表。
目录项保留空目录；文件项固定 FileId、VersionId、完整长度和 BLAKE3。
严格 lookup-key 排序拒绝重复和大小写别名；每个非根项必须有完整、同拼写的
目录父项；任何层级的 `.zxs` 管理分量均拒绝。相同 VersionId 的所有出现必须
具有同一文件身份、长度及摘要，别名只共享本节点内的完整版本副本。

manifest 以独立 BLAKE3 域承诺 canonical 字节。读取时先检查字节上限及外部
承诺，再严格解码与验证路径闭包，并重新确认 canonical 字节、仓库和节点。
不接受旧目录 Git 格式，不补缺字段，不做自动迁移或格式降级。

## 准备、决定与恢复

准备只在调用者已持有的受控仓库根下面新建节点。所有 create 均拒绝现存名称，
未知或同名空目录也不接管。逐个完整读取、验证并持久写入正文后才写 manifest，
同步 files、worktrees、节点和父目录。它返回精确 repository/node/files/worktrees
实体身份与 manifest 承诺，供原事务的永久决定覆盖，不自行发表成功注册回执。

创建后失败明确返回 incomplete，保留原材料和已观察实体身份。既有名称不得
作为一次新准备重用。此切片不自动删除、清扫或恢复未登记的部分准备材料；
完整初始化协议必须保存原操作的意图、决定及恢复权限后才能进行那些动作。

冷读要求外部已准入决定提供准确 binding。它只通过同一持有 fd 打开匹配实体，
验证 manifest、完整正文集合和每个正文的完整长度/hash。缺失、未知、损坏或
替换实体均拒绝，不尝试从 worktree 修补。每次再次打开正文仍完整验读，返回
同一受磁盘 I/O 围栏管理的只读句柄；消费者复制结束必须再验证目标完整正文，
不能把读 FD 误认为阻止同 uid 特权改写的快照锁。

worktrees 父目录本身按绑定 inode 准入，但其内部实例不扫描、不隐式恢复；
实例必须由独立生命周期记录授权。软删除实例、其修改和未知残留永远不能参与
不可变源快照的枚举、重建或修复。

## 成本与未覆盖范围

单节点硬上限：2,048 项、1 MiB 路径字节、4 MiB manifest、512 个唯一版本和
64 MiB 逻辑文件字节。逻辑字节按每个路径出现累计，不能借别名绕过预算。
准备复用磁盘受控 fresh-only 完整复制原语，以 64 KiB 缓冲流式复制；冷读顺序
验证，每次只打开一个正文句柄。
大目录、流水线复制和并发队列需各自设计，不把这个有限接口当无限制生产准入。

运行验证只对应准确提交的 GitHub 定向记录。纯结构与临时目录测试不证明
真实 SMB sibling 暴露、SYSTEM/DISK 全链路初始化或全量备份恢复；备份留待后续。
