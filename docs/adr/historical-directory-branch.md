# 从历史目录提交登记命名分支

## 决策与依据

实现《需求》历史节点分支操作及《分支系统逻辑》§6.1 的 T0 分叉：用户选择同一已初始化目录的准确历史用户提交，登记一个新命名分支。新分支引用 T0，保留其中的文件节点和固定子目录引用，首次写入前保持未实体化。

历史来源与当前审阅基线分别表达。历史 `tree_id` 决定新分支内容；`current` 保留现有 `DirectoryBranchCreateSource` 的七项当前 CAS。两者同时进入永久请求摘要。原当前来源入口、原正文、原操作 kind 和旧来源冲突语义保持。

此决策实现已确定的历史分叉行为，沿用现有持久结构、权限、发布及完整收据协议。目录合并、目录提交注解、SMB 绑定迁移及共享端点目录仍各自按原决策范围处理。

## HTTP 与请求身份

新增 `POST /api/file-manager/disks/{slot}/directory-branches/from-history`，正文为 `path`、`name`、`operation_id`、`source`。根路径沿用省略或空字符串；`source` 严格包含：

- `current`：仓库、稳定目录、当前目录分支、工作树、当前已提交 HEAD、index generation、外层 namespace HEAD。
- `tree_id`：选定的历史目录用户提交树 ID。

新增操作 kind `directory.git.branch-create-history`，规范摘要正文为 `repository_id`、规范化相对 `path`、`name`、完整 `source`。原 `directory.git.branch-create` 的编码不变。准确原请求重试返回原永久收据；相同操作号改变任一来源或名称返回既有幂等冲突。结果沿用目录分支登记字段，包括准确新分支和 HEAD、`selected=false`、`materialized=false`、零复制与零占位计数。

## 线性化与来源证明

在现有凭据和 Engine owner 锁中解析路径并核对当前权限。当前 CAS 必须仍匹配目标目录的已选分支、工作树、已提交 HEAD、暂存代数和外层命名空间；本仓库 staged、unstaged、needs_restage 继续阻断，独立孩子未提交工作可以保留。

历史树必须属于准确仓库和稳定目录，并具有已准入的真实 `directory_commit` 双向 marker。内部工作检查点、其他目录树及未知树不能作历史来源。Current 模式继续证明当前写权限，整个历史快照沿用新 scope 的隐藏项及不可用版本围栏，拒绝借保留旧树重新引入退役盘隐藏项；固定独立孩子引用沿用历史语义，孩子 dirty 不阻断父登记。

新分支的工作 HEAD、Git HEAD 和 index 引用选定历史树，父分支指向该树的来源分支。index 的直接孩子边界和已提交引用从历史快照构造，不能从当前分支 index 复制。登记保留当前目录选择、默认命名空间、SMB 视图、main 身份和孩子工作区，不复制正文、创建文件分支或伪造目录子树。选择历史分支后，既有 checkout 规则仍负责当前子仓库边界的冲突与保留。

线上计划与 Current 冷恢复使用同一确定性操作，验证准确主体、请求摘要、永久收据、事件和完整 State 写集。任何来源失效均在首次发布前拒绝，失败不生成新收据或部分分支。

## 验证与成本

行为测试覆盖旧提交分叉、当前选择和正文不变、固定旧子引用、各项当前 CAS 失效、跨目录与内部检查点拒绝、原请求重放、撤销会话和冷重开。旧入口的旧 source 409 及原摘要测试继续保留。

登记只增加分支及其 index 元数据，复用现有完整发布事务。元数据计划与 Current 完整写集证明仍随相关快照和保留 State 增长；本切片不新增跨发布缓存、正文 I/O 或同步阶段。Web 独立接线后仍须验证原请求保存、未知结果查询及实际浏览器交互。
