# 新建存储池的手动稿与显式目录提交

状态：方案已确认，待实现及定向验证。不是生产启用公告。

## 决定

- 新建存储池采用同一个严格的磁盘格式准入门。已有存储池不变更、不迁移，不向旧池补写新语义。旧版程序必须在首写前拒绝不识别的新池；只增加收据 kind 或 Snapshot 标签不构成拒绝门。正常启动、显式磁盘恢复、管理启动和成员激活均须使用同一认证格式事实。
- 新文件容器默认手动。文件进入时获得稳定容器身份，普通保存仅持久化可读的工作稿，不创建历史节点或分支。文件显式提交，或用户显式提交目录仓库并纳入该文件的更改，才可能发布新历史节点。用户明确选择的自动模式另按独立规则处理。
- 目录提交一次固定原目录分支 head、请求身份、主体、明确选集、每份稿的基准和代数。所有选中项统一校验。一次 Candidate、一次原决定、一次永久收据；禁止循环提交文件、提前清稿或留下部分可见结果。未纳入的工作稿和既有历史不改。
- 有变化时，只有正文变化的文件创建 FILE 版本。目录条目有有效变化时才创建目录节点并推进 head。将较新的已发布 FILE 版本纳入目录可以改变目录引用，但不得重复创建 FILE 节点。
- 完全无变化时，仅消费本次已验证选中的稿，保留真实的不变结果和原收据；不创建 FILE 或目录节点，不推进 head。尚无完整准入的分支必须拒绝并保原稿，不能用伪版本、伪节点代替。

## 内部持久合同

事务 kind 为 `snapshot.working.commit`，保留现有原生事务外壳。结果严格区分 `directory_draft_decision` 和 `directory_draft_unchanged`。前者绑定真实新节点、原请求和每份选中结果；后者绑定原节点，没有新节点字段或新增版本证据。原请求摘要含完整选集及次序、主体、原节点和工作稿代数。输入须有界、严格 canonical；未知字段、重复项、身份或代数错配拒绝。已有成功收据的编码、解释和重试不变。

目录索引从同一已发表收据原子更新。变化时登记一次节点并推进一次 head；无变化时只记录结果。同身份和摘要的重试返回原结果；同操作换摘要或主体拒绝。在崩溃恢复中必须用原 Candidate、原快照及原实体，不得用当前可见状态、同名实体或同字节外来副本替代。已决定但缺材料不得伪报成功。

## 实施顺序与代价

首批实现以同一原盘、已登记的已有容器和单副本为范围。在同一事务和格式准入框架下继续接入无历史节点的容器及其他已授权场景。该顺序不是取消默认手动、无历史首稿或多级备份的验收。此 ADR 不启用公共 HTTP/SMB 契约，不批准部署或操作已有用户数据。累计孤留材料限额、并发配额及大文件性能需独立闭合。

确定性来源、空间和编码门尽量在创建文件前完成。实际独占创建及读回后仍须验证完整元数据预算；失败时不得登记、清稿或按名字采用孤留文件。拒绝直接复用旧逐项 Reserve/Publish 收据：它既不能原子消费整组选中稿，也不能为不识别新格式的程序建立首写围栏。

## 验收

用 GitHub 定向 CI 验证真新池保存、显式提交和重启：新默认不建节点，批次一次可见，未选稿不变，完全无变化零节点，丢响应精确重试；覆盖选集失效、实体替换、空间不足、准备/接受/发表中断，以及不识别格式的启动与恢复首写前拒绝。仅报告实际执行的行为与产品编译；未验收不得宣称已启用。
