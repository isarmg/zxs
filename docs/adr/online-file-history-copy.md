# 在线单文件历史 fork

## 背景与选择

跨盘改名的产品要求是复制完整文件历史并保留源，不能调用无历史的普通 copy 后删除源。旧文件、节点、分支和版本身份属于源 history，直接复用会把两个独立容器的写入权混在一起。现有离线 history package 还要求原身份无冲突；foreign capsule 与独立盘实验日志都不能产生在线 namespace 成功。

有限入口选用现行在线 `Prepared → prepare_publication → decide_publication`。来源身份按 operation ID 确定地映射为新身份，保留全部文件图与 FULL；来源数据、分支和正文完全不变。源目录 namespace 提交投影为文件祖先闭包，原目录根挂接到目标已有根，不伪造目标目录 Git 用户提交，也不建立多父 namespace commit。文件分支的到达提交和目标主分支到达提交分别保持单父谱系，路径改变另记文件节点。

## 权威与恢复

新 kind 不是写权限。当前注册表从已验证 previous State、原请求、目标登记路由重放同一纯转换，比较完整 State schema 的实际写集；热路径使用每个 map 的精确 changed keys，冷读取无跟踪权威时完整比较。不可变分支、版本及旧操作事实不能被偷偷替换。Prepared 另核原副本版本、盘身份与绑定代；Candidate 另核完整目标版本向量和路由，不依赖 receipt 中任意数量或 orphan 版本。

旧版 fresh payload 门保持不变，历史版本只进入专用证明分支。正常 N 成员发布、目录同步、FULL 逐字节复制及永久幂等不减少。首次决定之后失败只能以原 operation 恢复，不回滚源或用新 operation 再做一次。缺少任何要求的正文不支持降级成功。

## 明确范围与代价

第一片只支持单个已保存文件到另一主盘的空未初始化仓库，目标路径为顶层文件名。源、目标仓库已有放置／备份规则、源文件已有备份绑定或保留版本具有不同主盘／路由时拒绝，不能用目标默认设置替代继承或自动迁移。任意目录接入、覆盖目标、目录递归、同仓库历史导出、Purged/Migrated 历史及外部节点闭包不在本片。尚无 HTTP/Web/SMB 调用方，不将库入口称完整跨盘 rename。

这是当前池模型内的逻辑历史与独立 FULL 复制，不是新三层数据库及容器整体迁移协议。权威 State／history manifest 仍在 metadata 成员盘，容器 JSON 只是缓存；不能将逻辑元数据完整等同于目标容器内已有权威数据库。现行 Config 拒绝一盘多个下级，本片不放开该限制，也未实现父子备份同层目标收敛和后台迁移。未来调用方必须先接入相应协议，不能凭此收据报告这些能力已完成。

闭包构造扫描源文件版本／节点及源 history 的 namespace 记录，完整复制成本与保留正文总字节及目标完整路由成正比，不做去重、硬链接或 reflink。原有 State 结构共享、元数据大小上限和空间预检保留；新图在 payload 准备前使用与冷读相同的完整逻辑闭包验证。未新增常驻索引或协议缓存，也不承诺这一有限同步入口的延迟满足未来 SMB 交互预算。
