# 待决：仅替换本机两份固定服务配置，保留可撤销的原文件

**提案，未批准、未实现。** 当前普通首装、同载荷修复与激活的行为不变。这不是历史发行兼容计划：不读取任何旧安装数据库或旧请求格式，不替换 ZXS 程序、VFS、发行包、池数据、账户、密码或 `smb.conf`。本案不开放匿名 root Web 控制台的新写路由。

## 操作者批准的动作

仅手动以本机 real/effective root 运行 helper。预览只读；已经存在的固定 `/etc/systemd/system/zxs.service` 为必选，`/etc/samba/zxs.conf` 只有在原预览明确选中时才同时处理。目标缺失走现有首装，不混入覆盖操作。旧配置可以是外部管理员提供的普通文件，不解析、不执行、不沿 include 读取，也不要求它出自任何旧版本。新正文只能来自本次同源码、已核验的 helper 配置生成器。不能上传配置、输入任意路径或传 shell 命令。

预览分别说明原文件属性、将写入的无秘密配置、精确目标，以及两次交换之间可能出现部分状态。旧文件可能含私密内容：不把旧正文、命令行、变量、凭据或任何截段写进计划、日志、Web、SYSTEM、备份包或新的字节副本。旧文件保留在原文件系统、root 0700 目录内的**同一个 inode**；这能撤销配置替换，不是另一介质的容灾备份。只有明确认可此限制、确认本机服务和外部配置／包管理仍停止，才接受原计划摘要的应用。停止声明不是 OS 对其它 root 写者的排他证明。

## 原件和目标封闭

* 持有原 `/zxs` 生命周期租约、实际同版程序、账号／组原数据和必要的平台程序；在现有顺序下，逐层持有固定 `/etc` 父目录与锁。拒绝重绑、链接、多人可写目录或跨文件系统交换。另核对相关 systemd/Samba 服务确实未运行；检查失败、状态矛盾、服务正在启动或不支持的管理方式均不进入替换。不 reload、stop、start、enable 或修改 drop-in。
* 每个原文件必须是 root 所有、单链接的普通文件，模式恰为 0600 或 0644，大小不超过 64 KiB。保存**原文件身份、所在父身份、大小、模式、属主/组、SHA-256**；读前后重新核对同一 fd 的内容变更戳及命名实体。新文件为固定生成的 0644 字节，保留生成输入摘要、精确字节摘要、长度及包来源。原文件仅相同字节、不符身份不能替代它。篡改、不确定或读不全都拒绝且保留。
* 最多两个目标。先检查两处的空间、inode、名称／FD 和持有资源；不可在第一处交换后才发现第二处没有原文件。执行中再次检查余量、所有持有者和停止条件。命名预算按实际目标；不提供复制、覆盖式 rename 或不同设备 fallback。

## 唯一的本机决定及其可见性

采用现有私有目录、确定性 pending、逐文件同步和正式目录发布屏障。操作按生成的 `OperationId` 及整体计划摘要标识；不从当前表单、文件名、日志或新生成的 ID 恢复。唯一的主机活动指针只含原操作与原计划摘要，通过不覆盖发布取得；其它本机配置替换和 helper 服务激活必须查验它。一次仅有一个可撤销替换，指针丢失／重复、未知内容、阶段越序或跨操作记录均不能执行。每个阶段只读取当前单一布局，没有替代解码器。

| 原记录 | 必须核对的材料与作用 |
| --- | --- |
| 计划 | 经过确认的规范化生成输入、同版载荷、已停服务约束、两处固定目的地、原父和原文件身份／摘要，以及新配置摘要。原正文绝不复制。所有字段有界且拒绝未知项。仅有计划不表示已改任何目标。 |
| 已准备 | 每个目标在其同一文件系统的固定前缀私有目录内，以 no-clobber 创建并同步该份新配置，记录准确保全目录与新 inode。**两个父目录、所有新文件及已准备记录均已发表并读回后才可交换任一活动名。** 无法证明属于原操作的准备残留不能仅凭相同字节认领、覆盖或删除。 |
| 应用的实际状态 | 在持有原 fd 与新 fd 时，用跨已持有父目录的 `RENAME_EXCHANGE` 交换活动名和准备名；同步两个文件及两个目录，重新打开两名。活动=新、保全=旧才算该项已交换；相反的原始一对才是未交换。只接受这两种**完整原件对**，缺件、第三 inode、内容或权限变化一律拒绝。ctime 的阶段内稳定性要核实，不把 rename 本身应有的变更误认成外来写入。 |
| 应用完成 | 两个目标（或原计划仅一个）都在正确方向且仍持有真实原件，才发表整组完成收据。下次查询仍读当前实物，历史收据不能代替它。中间失败展示每项已知实际状态，绝不宣称跨目录原子，没有自动回滚或服务启动。 |
| 撤销决定与完成 | 单独本机预览、确认原操作／计划摘要，并再次核对全部原件、停止条件和方向。先保全一次不可变撤销决定。从此原操作只准朝撤销方向续作：逐项只交换已应用的准确原件对，未应用项不动。同步并读回后，活动=原、保全=此次生成配置才完成。重复撤销不重复交换。 |
| 关闭撤销窗口 | 在应用完整或撤销完整、上述两侧证据仍准确时，由操作者另行明确确认关闭；先落定保留记录，再仅移除同一活动指针并同步。此后不能用旧操作覆盖后来的配置。两侧保全文件及原收据**不自动删除**。当前活动名不同或上次关闭结果不明时，绝不采用新指针或清扫未知材料。 |

断电后默认只读报告原状态。操作卡在准备、一次交换、同步或收据尾部时，仅允许操作者明确续办该原操作或明确撤销。回执或活动指针单独存在、全都消失、目录被换、已发表材料丢失、无法确定交换结果时不猜、不重建、不恢复未知文件。无完备证明时不能称“已恢复”、“可用”或“已启动”。

若所有本机原证据连同活动指针被外部擦除，现有无状态观测与“从未开始”不可区分。对持有原摘要的人只能返回未知；不得据此重新执行或签发原回执。本提案不声称仅靠两个现有文件就能识别任意整机回退，也不为此改变正常 daemon 的无痕冷启动策略；若必须实现该等级，需要另行批准独立权威。

## 待批准后才写的验收

分别覆盖仅 systemd／两目标、旧 0600 配置不复制、真实根与权限、同字节换 inode、真实跨父目录交换、已准备前零活动名变更、第二项失败保全第一项、每个同步／记录截点、部分应用后原请求续作或不可逆改向撤销、撤销重试、指针替换、关闭后旧请求不得重新打开窗口。另验实际 systemd/Samba 的停止／启动排他，不能以临时目录或指令模拟替代。若要求程序集／VFS 替换、匿名网络写入口、独立旧配置字节副本或任意历史版本恢复，均须另定边界，不含在本提案。
