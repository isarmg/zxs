# 0011：预置 Samba 账号的持久单一绑定

状态：已采纳的源码设计。真实 Samba 互操作、浏览器和故障验收必须分别验证，不由本文宣称通过。

## 背景与选择

Web 需要真实账号和密码设置，但非特权 ZXS 不拥有 Unix 账户管理权、Samba passdb 写权或 smb.conf 管理权。仅保存文本名称会使页面与真实权限脱节；为此提升整个 Web 服务权限会扩大风险。

部署者先准备所有候选的 Unix/Samba 账户、独立密码和每个共享的 valid users；--smb-user 提供首次选择，--smb-allowed-user 提供附加候选，总数上限 16。Web 管理员通过当前 Web 密码确认在候选中选择一个生效账号。Samba 继续负责实际凭据，ZXS 单一持久绑定负责 ZXS 访问范围，不自动检测或修改外部配置。

## 权威、同步及恢复

selection.json 是唯一绑定权威，只存版本、账号和单调代际，不存密码。私有系统盘目录和独占锁阻止多进程写；每次切换使用临时文件写入、文件同步、原子替换和目录同步，成功后发布内存状态。未知/已发布但同步失败时停止继续授权，须恢复后重启。缺失、损坏、不支持记录或已移除的生效候选均拒绝，不回退初始账号。

锁顺序为绑定读/写锁，然后认证锁。每个 RPC 在读锁内检查连接代际并执行操作；密码变更也在读锁内核对代际并完成有界子进程等待。账号保存先在锁外做密码哈希，然后取写锁等待已准入工作结束，提交点复核仍有效的 Web 会话及密码证明。写锁内同步持久化并断开旧 RPC socket。已返回的数据不可追回，断连工作文件遵守既有恢复规则，不自动发布或删除。

GET 只读取独立的已提交展示快照，不获取可能等待在途 SMB 操作或切换的锁。快照锁只克隆或替换不可变 Arc，不覆盖授权、I/O、磁盘同步或断连；切换尚未提交时仍显示旧账号和代际，发布不确定时撤销快照并返回恢复错误。快照不能用于授权，RPC 和改密仍必须通过操作锁及代际复核。

候选验证 O(16)，GET 在短锁内只做 O(1) Arc 克隆，每次 RPC 增加一个共享读锁及常数代际比较；切换一次序列化一个有界记录并遍历有界连接表。修改共享一个立即拒绝的并发槽，账号密码哈希另受既有密码槽限流。账号切换等待在途核心操作或最多 15 秒的改密客户端；不能通过超时宣称已取消可能发布的操作。

## 未选择的方案

- 任意自由文本账号：不能证明 Unix/Samba 账户及共享配置存在。
- 自动编辑 passdb、smb.conf 或运行 sudo：超出非特权 Web 的能力边界，也缺乏多组件可恢复事务。
- 只在新连接检查名称：旧会话会越过切换继续使用，因此必须有代际检查及主动断连。
- 每次启动重置 --smb-user：会悄悄撤回用户已保存的绑定。

对应接口、部署和恢复责任见 [SMB 组件](../components/smb.md#smb-account-settings)。
