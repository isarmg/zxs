# 目录历史节点的独立 worktree

## 状态与范围

按 2026-11-13 最新产品要求实施。此文是新 `.zxs` 快照仓库的行为决定，
不是旧目录 Git 引用模型的兼容层。现阶段有生命周期、分支目标选择和名字分配的
纯规划实现、空实例目录的独占创建／同步／准确身份冷开、既有文件的稀疏读映射与
MOVE／COPY／容器同步分类，以及定向行为测试；
尚未发布生产 HTTP、Web、SMB 或持久化 authority。
本文后续步骤必须取得真实持久化与恢复证据后才可报告上线。

适用于用户明确初始化的目录快照仓库。此前暂停的普通非容器文件／目录功能
不因此恢复。既有文件容器、已提交快照、永久收据与被保留的数据不删除，
也不将旧格式自动补齐为新记录。

## 来源、实例和可见位置

- 用户选择准确的快照仓库、分支和不可变节点。来源绑定
  `SnapshotRepositoryId`、`SnapshotBranchId`、`SnapshotNodeId` 与完整 manifest 承诺。
  这些身份与旧目录 Git 的目录树／分支身份分开。
- 每次创建分配全新的 `WorktreeId`，同一历史节点可同时有多个独立实例。
  初始内容只来自该节点原始不可变快照，不来自现有实例、最近编辑、
  上一次软删除的实例或已经恢复的实例。实例的新增、改写和删除互不影响。
- SMB 在原目录的父目录内显示新文件夹，物理内容位于
  `.zxs/<snapshot_node>/worktrees/<worktree_id>/`。该路径是目标布局，
  没有准入身份和已决定记录时，名字本身不授权接管磁盘材料。
  不使用 SMB 可写符号链接暴露 `.zxs`，而由服务端受控映射工作区目录句柄。
- **创建时 worktree 实例目录为空。** 原节点 `files/` 是不可变只读来源，
  未修改文件与空目录只通过原始 manifest 映射，不在 worktree 预建目录或复制正文。
  只有修改／新增的正文写入该实例的稀疏覆盖层，不改写原节点或其他实例。
  新建另一个实例仍只映射原始节点，绝不吸收旧实例的覆盖层。

## SMB 名字分配与恢复冲突

显示名称为 `worktree-<创建时的分支显示名>-001` 至 `-999`，固定三位数字。
分配范围是实际父命名空间中的该分支名，不只统计同节点的实例。
普通文件、普通目录、其他 worktree 和未完成的持久名字预留均占用该名字；
按既有规范化与大小写碰撞规则判断。原始分支显示拼写保留。

完整父命名空间须在同一发布围栏内观察，选出空号后先持久预留，
实际安装用 no-replace。并发同节点创建也不覆盖或合并。
纯 `names::allocate` 只计算候选，不声称已取得预留或并发安全安装。
最终名称按目标文件系统分量字节限额检查，不能只数 Unicode 字符。

软删除撤去 SMB 可见挂载，不释放实例身份或正文。其旧显示名可被新实例占用，
两者仍由不同 WorktreeId 隔离。管理员恢复时先尝试原名；已占用时分配该分支
另一空号，或接受用户明确指定且经过相同检查的名字。保留原实例的内容、
来源、修改代数和文件提交收据。全部 999 个名字占用或目标长度不合规时，
保留全部内容并报明确错误，不自动物理删除、覆盖、绕回已有名字或缩短分支名。

## 提交与分支线性化

提交首先冻结此实例的完整最终清单，包括未修改文件、修改文件、新增文件和
剩余空目录。文件删除反映在最终清单中，不用仅 staged/dirty 子集替代完整快照。
提交时修改文件从 worktree **移动**到新 `.zxs` 节点，未修改文件从原节点
**复制**到新节点。新节点包含全部最终文件的完整正文，不能用引用代替未修改文件复制。
文件保存在 worktree 或新节点，不要求两处同时保留；移动后不为维持 SMB 视图再复制回来。
SMB 用已决定的路径映射继续显示提交前目录结构，并指向新节点中的准确文件。
正文物理名字使用 `15位身份ID-原文件名`，完整身份／逻辑路径存于权威记录；
短ID及目标名称碰撞必须拒绝，不覆盖。目标文件系统和 UTF-8 字节限额都参与准入。

每个原文件按稳定身份及所选文件历史节点定位，不从当前路径猜身份。原文件
可能已移动到 `common-data` 的其他目录或 `deleted-data`；修改内容仍同步至该准确
容器，创建文件节点，并按准确文件分支 HEAD 决定是否需要分叉。
**容器磁盘实体已不存在时，不重建或操作容器**，正文只保存在 worktree 或提交后的
`.zxs` 节点中。设备离线、读取失败、登记缺失和权限不足不等于实体不存在，
不得据此跳过容器同步。定位依赖完整稳定身份及受准入实体，不按名称或旧路径猜测。

文件历史节点只为明确记录的文件修改创建；未修改文件只复制目录快照，不新增文件节点。
这覆盖早期“每个文件一律创建分支／节点”的描述。正常提交仍包含全部最终文件。
正文只来自冻结后的稀疏改动或所绑定的原节点，不回读外部路径覆盖用户编辑。

正常提交在最终发布锁内重新读取所选来源分支 HEAD：

1. HEAD 仍等于来源节点时，沿原分支创建一个新目录节点。
2. HEAD 已不同于来源节点时，从原来源节点创建新的目录分支及节点。
3. 不按 worktree 创建时的 HEAD 作决定；准备 I/O 后还须在同一提交线性化点
   验证所冻结的 HEAD。若锁外准备后发生变更，重新规划前保留完整工作区，
   不覆盖另一实例已经提交的节点，也不改变原操作的已决定结果。

文件节点、目录节点、完整快照和永久收据必须由同一个可恢复决定绑定。
目录节点引用本次真实文件结果，不能仅靠统计数量或本地 JSON 自报发布成功。
成功提交后 worktree 仍保留其准确已保存代数；后续修改产生新的代数。

## 明确操作与来源准入

全项目只识别 SMB 明确传达的操作，不根据内容、哈希、文件名或时间邻近猜测
用户意图、复制来源、移动或重命名。哈希保留完整性与已冻结材料的等价校验职责，
不承担识别操作的职责。稀疏 `FileEdit` 来自明确、已完成且绑定准确身份的写操作；
有此事实才 MOVE，没有修改事实才 COPY 原节点。不因字节相同抹去已识别操作，
也不因字节相同把一个文件关联到另一容器。

## 外部文件移入与来源不明的复制

从 worktree 外明确移动文件进入实例时，固定该文件移入前实际向 SMB 暴露的
文件分支／节点和完整容器身份。一次可恢复决定同时包含：移除原可见路径、
将整个容器移至 `deleted-data`、登记 worktree 新逻辑路径对准确旧暴露节点的映射。
不只搬一个版本、不复制正文、不重写旧版本、不从内容相等推断身份。
移入后的修改仍同步至 `deleted-data` 中该稳定身份的容器。

普通客户端复制可能只表现为源读取与目标新建／写入，不能据此可靠关联来源。
复制与移动必须按明确 SMB 操作区分：已知文件容器复制到普通目录时，在目标普通
目录创建独立新容器，源容器不动；复制到 worktree 时新容器落在 `deleted-data`，
由 worktree 映射。明确移动到 worktree 则保留同一容器身份并整体移入 `deleted-data`。
用户最新修正：**复制来源识别不出时，新建独立文件容器并放到 `deleted-data`**，
worktree 映射这个新容器；不关联或改变可能的原容器。不能依据源读取与目标写入的
时间邻近或内容相同推断复制来源。新目标写入尚未完成时不发布 FILE 节点；完整写入
封存后，由可恢复事务决定新容器身份、位置、分支／节点及 worktree 映射。失败保持
待恢复状态，不能重复创建容器或提前把半写文件显示为已发布节点。

每个逻辑文件 occurrence 已新增明确必需的 `SnapshotFileSource`：
`Container { branch, node }` 或 `SnapshotOnly`。后者仅用于权威已确认原容器不存在，
不是未知来源导入的替代路径。来源上下文与正文分离：同 VersionId 可以由不同逻辑
路径选中不同分支，正文仍只有一份，不能让去重表覆盖来源分支。所选节点是版本节点时
必须准确匹配正文 VersionId；metadata/anchor/merge 的内容关联由 FILE 权威验证。

来源持久化及投影消费现已接入：修改计划携带原选定 BranchId、FileNodeId、VersionId，
不读当前默认分支；SnapshotOnly 不能调用容器定位器或自行获得容器关联。提交后
每个修改路径的新 FILE 结果上下文仍须由外部永久收据准确供应并纳入新快照。
这不是 FILE 权威准入本身。外部移动／复制、新增文件仍待实际事务与 SMB 接线。

## 未提交删除与管理员恢复

删除一个尚未提交或在上次提交后又有修改的 worktree，先冻结并提交其全部最终
修改内容：对应容器存在时创建所需文件节点，缺失时只保留稀疏正文；
**不创建目录分支或目录节点**。文件结果及原操作收据已决定、原节点引用与稀疏
修改已持久保留后，才将实例变为软删除并撤去 SMB 挂载。
无修改的初始实例可产生软删除操作结果，但不得为未修改文件凭空创建文件节点。

已经提交且没有后续修改的实例直接保留原提交结果后软删除，不重造相同文件节点。
未知发布结果留在 `Publishing`，查询原永久 operation ID，不换 ID 重试或直接
删除。完成时核对实例、来源、修改代数、完整 manifest、操作号和发布种类。

恢复只恢复指定 WorktreeId，不新建实例，不复制／覆盖原稀疏编辑，不重新提交
软删除前已创建的文件节点。恢复后未修改又删除，复用该代数原文件结果；恢复后
再编辑并删除，需要新一轮文件发布。永久操作幂等由权威收据保存，生命周期内
保留的最近结果只优化当前代数，不替代全量永久收据。

## 实施顺序与验证

1. 新快照仓库已决定身份、不可变 manifest、独立完整正文及节点根句柄准入。
2. worktree 的独占空实例创建、同步、准确 inode 绑定和持久名字预留；
   未改文件惰性映射原节点，修改文件才进入覆盖层。
3. 冻结写者、全量逻辑提交计划、实际修改文件历史发布和目录分支 HEAD 线性化。
   COPY 原始未改文件，MOVE 稀疏改动；持久决定绑定源 inode／完整哈希、目标
   no-replace 和逐步搬移恢复判别，失败时保留原／目标事实，不盲重试或删除。
   保存永久操作结果，并为每个失败／崩溃窗口定义恢复决定。
4. 软删除／恢复索引、无覆盖重新挂载、SMB 句柄与旧会话代数围栏。
5. HTTP／Web 创建、提交、删除、管理员恢复和可恢复进度，最后才做多级备份。

生命周期测试覆盖同节点独立实例、删除只发布文件、错误收据保持冻结、
恢复原编辑、名字冲突不覆盖、恢复后不重复发布、再编辑需新发布、
当前 HEAD 延续与并发推进后的分叉。名字测试覆盖 001／999、全部耗尽、
大小写和 Unicode 等价碰撞、普通同名条目、预留及目标 UTF-8 字节限额。
纯分类器已区分修改后的 `MoveWorking`、未修改的 `CopyOriginal`、存在容器的
`Update` 以及已证明实体缺失的 `SnapshotOnly`。容器查询只按稳定 FileId，
临时故障传播为错误，不降为缺失；不会通过比较正文哈希新增或抹去修改事实。
提交后完整 manifest 必须精确保留全部逻辑路径与内容，才可将读映射指向新节点。
当前覆盖层只接既有文件替换；新增、删除、改名、目录编辑的准入和完整投影仍待接线，
不通过遗漏原条目假装支持。

本地编译／测试未执行。空实例与完整原节点的真实冷开测试已编写，尚未运行。
权威 ledger、实际 MOVE 决定/恢复、容器同步、断电故障、并发 SMB 和端到端验收仍待实现。
