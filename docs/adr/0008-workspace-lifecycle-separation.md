# 0008：工作区生命周期与永久操作事实分离

状态：**已采纳有限首批，2026-10-30 扩展至普通已发布终态，2026-10-31 扩展至精确绑定的历史保存终态。** 这是工作记录准入改进，不是通用历史退休、删除策略或无限期容量承诺。源码和测试接线不等于测试、真实 SMB 或物理掉电验证已通过。

## 问题与选择

此前 `max_retained_workspaces` / `max_retained_workspaces_per_principal` 按所有状态累计计数，默认 4096 / 1024。普通 SMB 可写打开已有文件立即创建核心工作区；无修改 Close 中止它，spool 清理不释放核心累计记录名额。顺序正常打开/关闭即可耗尽记录限额。

本次保留可写 Open 的既定语义：公开 workspace ID、冻结打开基线与选择、开始租约期限、独立工作副本、PrepareWrite/Dirty 授权和未确认 FD 修改恢复关联。延后到首次 Dirty 才创建不是纯优化，不能默默改变这些承诺。

选择将**已经中止且没有任何核心恢复材料的完整清单**退出驻留集合；清单仍在系统盘 `workspaces/<id>/workspace.json` 和原 primary `staging/workspaces/<id>/workspace.json`，保持原字节格式。没有新目录、rename、关闭 marker、退休 operation、业务序号、TTL、迁移或双格式读取。

## 准入与决定点

冷存仅限普通 purpose、Aborted、空 files 和空 namespace operations。目录盘点须证明系统与数据盘上所有可用同 ID 目录仅有 `workspace.json`；`commit-request.json`、`wire-request.json`、`.full`、`.prepared`、`.zxs-full-*` 和任何未知材料都使记录继续驻留，包括没有清单但有正文的目录。

运行期在原 Engine 独占借用内、**持久中止之前**检查目录与所有者。目标 upload claim 或任何脱离锁提交准备尚存时不冷存；历史工作区不在候选中，历史保存准入本就要求 HistoricalBranch purpose。首次冷存要求已发现系统/primary 两份清单；缺一时保持驻留，不能把零份当成功证明。扫描 I/O 或路径错误在写入前返回，不产生“中止已成功但派生状态失败”的新结果耦合。

之后执行原双镜像写入/同步；两边成功才安装预算和 Resident/Cold 分类，并从驻留集合移出。任一可能已落盘的写入失败仍封闭写入，保留原内存计数和全部磁盘材料供重启核对。没有后置分类 I/O，也没有新 fsync 阶段。canonical 字节一次构造并复用于预算和双镜像写入；仅冷记录计算固定摘要。

已有冷记录的重复 abort 先点读验证原身份、主体、内容和本进程准入的镜像位置集合，再按原语义推进 fence、原位持久两镜像并更新冷证明，不重新占用驻留名额。它不变成不推进 fence 的幂等空操作；已发布工作区的中止仍不撤销永久发布事实。

## 查询、所有者与 SMB spool

`Engine::workspace_view` 返回 `Cow<Workspace>`：驻留记录借用，冷记录以受限点读返回拥有的数据；原 owned `workspace()` 保留。授权、选择检查、上传状态和原生完成核验迁移到此接口，不建立永久增长的清单缓存。当前身份/绑定/对象授权仍在 Backend 锁内执行。

冷点读重新验证所有实际镜像及权威 primary，要求 canonical 摘要和本进程准入的 system/primary/both 集合一致。内容、镜像位置、未知材料或 I/O 改变均明确要求核对，不能用另一份健康记录悄悄替换本进程已确认的清单。Rust 借用不能跨 Engine 可变操作；脱锁准备已有 owned 工作区。含核心文件或上传/准备所有者的记录不退出驻留集合，现有正文读租约和恢复源不被移除。

SMB Writer 持有自己的完整工作区上下文和不可克隆 spool Lease。核心冷存既不删除 spool，也不释放其预算，不需要假装 SMB 已完成清理证明。成功 Close 仍按既有策略清理；清理告警、账本不确定、失败 Close、Detach 和断连继续保留各自材料和计费。仅中止状态的核心清单变为点读，不将失败/断连自动判成中止，也不将 `dirty:false` 判成无未确认字节。

## 启动、恢复与内存界限

启动逐根流式枚举；每次建立 locations 时，从已准入成员的 held root 检查 staging/workspaces 的 owner/0700，并保留同一私有目录 FD。枚举、候选探测与清单读取均绑定该 FD，不在检查后重新解析目录名称；cold 点读和只读库存共用这条准入边界，权限不符只拒绝、不 chmod。首次遇到 ID 即点读全部可用候选根，最多核对两份清单，再计费并处理下一 ID。已计费索引去重，不先收齐全部路径，也不在解码前按旧 4096 / 1024 总路径数拒绝。实际记录上限应用于分类后的驻留记录，元数据字节预算应用于全部记录。

索引按每 ID 保留主体、生命周期字节 charge，以及 Resident 或 Cold（固定摘要和镜像位置集合）。ID/主体包含于已收费清单；索引空间为 **O(全部准入元数据字节)**，不是 O(活动记录)。瞬时工作集还含当前至多两份单清单上限内的解码/规范表示、生命周期预留副本、目录迭代器及配置根。逐 ID 定点查所有可用根；仅普通空 Aborted 候选枚举目录，首个非清单条目立即否决冷存，不为其他状态遍历全部代际。镜像发现独立完成，不因提前否决遗漏第三镜像。冷点读增加文件打开、目录检查和清单解码成本；不宣称吞吐提升。

seed 仍先于 journal：只是独立正文验证的恢复提示。最终 authoritative pass 仍按已发布历史核对 branch、base、primary、请求和收据。只有无任何正文/请求材料的记录才能从 seed 集合省去，`pending_payload_source` 所需所有旧完整代际继续可达。

启动及系统盘恢复沿用原有健康镜像准入，包括原来允许的单健康镜像；单镜像冷证明明确记录其位置，不能将运行期已知镜像消失当作这一启动策略。系统盘恢复后重复 abort 可以按原持久路径补成双镜像。损坏镜像的幸存记录不冷存；冲突仍失败，不按最大 fence、最新时间或第一份放行。原成员/quorum/OS 单写者锁、完整恢复字节校验均不放宽。

配额超额仍在 journal 修复、配置发布或索引重建之前拒绝启动；诊断不隐式把池改成可写。`zxs-rescue workspace-inventory` 不构造 Engine，也不重放 journal：停止服务后持有原写锁，逐物理镜像输出 JSON 行，最后才输出 `complete:true, authoritative:false`。它不跨镜像去重、不认证发布事实、不把原始 canonical 长度当生命周期计费，遇错误不输出完整成功标记；锁文件可能被创建。迭代器不保存每 ID 索引，因此已有超额池也能只读核对。

## 配额与接口变化

- `max_workspaces` 仍只限制 Open/Sealed。
- 原 `max_retained_workspaces*` 名称和默认值保留，**计数含义改为所有未冷存的驻留工作记录**；Committed、含请求/正文/未知材料的 Aborted、过期与待核对记录继续计数。它不是单纯并发句柄限制。
- `max_retained_workspace_metadata_bytes*` 仍累计所有完整清单及原提交/关闭预留；默认 128 / 64 MiB 不变。冷存不返还字节，达到上限仍拒绝新建/增长；永久收据和原始正文不裁剪。
- capacity 两 scope 新增必填十进制 `cold_records`；`records` 为驻留数，`metadata_bytes` 为冷热总量。`automatic_retirement:true` 仅表示本 ADR 的受限自动冷存，不表示自动删证据。Web 与严格 DTO 同步，不兼容缺少新字段的响应。
- 中止时因准备所有者而仍驻留的空记录可在之后显式重复 abort 或重启无所有者后重新分类；没有后台猜测超时或扫描所有历史的热路径。

本批只改善普通无修改打开/关闭的**记录轴**耗尽。实际写入的成功提交仍消耗驻留名额，完整清单元数据仍永久增长；不能把冷存、提高上限或新的库存命令当作长期增长已经解决。

## 验证范围与后续决策

根 `test/` 中新增小记录额度循环、重复 abort、冷点读镜像/摘要变化、目录未知材料、上传/脱锁准备、分类前失败、双镜像写入失败、字节耗尽、正常重启、系统盘恢复和超额只读库存用例；SMB 用例检查连续无修改 Close 不增业务序号/版本/上传、断连仍保留未确认字节。既有 native/public 重放、已发布后关闭、全部候选副本丢失后的 retained `.full` 修复、准备结束后的撤权及根测试接线保留。

一般 Committed、历史保存、含正文记录的冷存，以及紧凑终态格式/正文留存政策尚未采纳；它们需要另行决定查询投影、原请求绑定与完整恢复源发现，不能由本次分类推广。无需继续解决原提案的跨子系统关闭 marker 或双目录 rename，因为本次不删除外部资源、不移动权威。所有存储字节预算、单写者规则和永久事实保持。

## 2026-10-30 策略扩展：普通已发布终态

本节扩展上述首批策略；前文保留最初仅普通空 Aborted 的决定与限制，不将历史设计改写成已实现的一般退休。

普通 Committed 以及该发布之后显式 Aborted 的完整清单可退出驻留集合。原请求必须通过已有
`workspace_request_matches_operation` 和 native/wire 摘要验证，绑定永久操作表中的发布结果、操作主体、
工作区、branch、base 与动作；Committed 必须为请求 fence+1，Aborted 必须至少为 fence+2。
HistoricalBranch、Open/Sealed、无发布证明的终态、未发布正文、损坏/冲突证据、未知材料和准备中的资源仍驻留。
已知请求文件和原格式的 FULL 代际可以保留；`.prepared`、`.zxs-full-*` 等未决或未知材料不能据此退休。

正常完成先验证绑定、所有者和原 system/primary 双镜像位置，再按原顺序持久两份完整清单；两边成功后才
安装预算与冷热分类。失败维持原驻留 charge、封闭写入，并保留“已发布但工作区待核对”的原结果与具体原因。
没有后置分类 I/O、新 fsync、目录移动、删除、TTL、收据裁剪或格式迁移；正文和外部 HTTP/SMB spool 的所有权与计费不变。

启动与系统盘恢复先扫描持有的 journal 描述符，在转为 writer 之前，以既有配置成员规则和 publication seal
验证发布前缀。随后从最后完整发布的 hash-bound snapshot 读取主实现现有 `operations` 与
`operation_principals`，仅在工作区准入期间借用该 State。未完成或 barrier 不足的 slot 不授予冷分类，具体失败
保留给恢复应用阶段处理。所有元数据字节与驻留数均在 journal 修复、恢复配置写入及索引重建前检查；伪造终态
不能免除记录 charge。历史 replay 仍从原前缀开始；只读预检不发布 pending 决定，不引入第二套收据或历史架构。

恢复源搜索改为遍历预算索引的所有 retained ID，驻留记录借用，冷记录受限点读并验证准入时的完整清单摘要、
全部镜像位置及镜像一致性。提示本身不授权字节使用；候选大小和内容哈希仍独立验证。即使当前清单已指向较新的
上传代际，原目录内所有旧 `.full` 仍可用于修复原 candidate。常规冷查询继续执行原请求/回执和 primary 核对；准入索引仅在内存区分空中止与已发布证明，
点读保持该证明对应的目录规则和精确清单/镜像，而不重新准入。原请求一份损坏、另一份精确且健康时仍允许原 ID 重放；
两份均不精确、actor/摘要冲突及真实 I/O 失败继续按既有重放边界拒绝。

内存保留原有按全部元数据计费的 ID/主体/charge 索引；预检额外流式扫描发布前缀，只保留最后一个已验证 candidate
及至多首个未决 candidate，并临时加载一个已验证 State。恢复 apply 对较早 candidate 再逐个读取以修复其历史闭包，
不保留 O(全部 candidate 正文) 缓存。终态分类扫描当前工作区的有界代际目录，不增加持久同步阶段。
新增五个业务闭环回归及所有者/未知材料、冷镜像证明回归；其执行结果由对应提交的独立验证提供，源码接线和 rustfmt 不代表测试通过。

## 2026-10-31 策略扩展：历史保存工作区

本节扩展前两批，保留此前明确排除历史保存的历史决定。`max_workspaces` 原本只计 Open/Sealed；
本次解决历史保存完成后仍占 `max_retained_workspaces` 的驻留记录问题，不提高任何上限。

历史保存必须由同一权威 State 中的永久 `history.historical_save` 操作和 Completed plan 共同证明。
操作 ID、发布状态、操作主体、plan ID 与摘要、history、source commit、workspace ID 必须相符；
复用通用原生请求摘要封套及现有 plan 身份/输入摘要校验。封存清单哈希固定原 branch、base、
文件代际和命名空间，原 fence+1 才是 Committed；发布后的显式 Aborted 至少为原 fence+2。
本地 Ready/Completed plan 文件、缺少发布屏障的 candidate 和终态标签均不能授予冷分类。
空历史 Aborted 只有在完全没有正文、请求或未知材料时，才按既有空中止规则退出驻留集合。

正常完成在原独占借用内先验证发布绑定、双镜像位置、目录材料与所有者，完成两份原格式持久清单后才
安装冷分类。上传所有者、脱离锁准备、`.prepared`、复制残留、未知文件、单镜像损坏或冲突均继续驻留。
历史终态目录只接受原清单及合法 FULL 代际；普通提交请求文件不能冒充历史保存证明。
发布后镜像写入失败封闭新写入，返回带固定发布结果及具体 I/O/路径来源的协调错误。原 ID 重放仍返回原结果，
不会再建 branch、commit 或版本。重启继续按只读发布前缀预检后准入，拒绝早于 writer 转换、修复、配置和索引写入。

仅增加从 workspace ID 到原 operation ID 的派生内存查找；每次装载已准入 State 时单次遍历永久操作表，
运行期只登记本次实际发布的历史操作，定点证明不反复扫描全部历史。查找不提供发布权限，每次分类仍读取并
核对 State 的操作、主体和 plan。空间 O(有工作区的历史保存操作数)，不增加磁盘对象或第二权威。
既有总元数据索引、单清单上限和冷热字节 charge 不变；不增加持久同步阶段或快照解码。

所有 FULL 代际仍可能是别的未决 candidate 的最后恢复源。恢复遍历全部已收费 ID，以已准入的镜像集合和
完整指纹验证冷提示，再独立验证候选正文的长度与哈希，包括当前清单不再引用的旧代际。
本次不删除任何字节，不回收 FULL 磁盘空间，不裁剪永久历史、plan 或 receipt，不修改磁盘格式。
工作记录可冷存不代表工作目录已可删除；无用材料的删除政策与可证明的恢复保留根仍是后续独立问题。

回归包含真实部分发布与本地伪 Completed 的三种拒绝窗口、双镜像失败的原结果/来源、所有者与未发布正文保留、
旧 FULL 救回另一笔未决历史保存，以及公开 Engine 集成的满额重放、重启、系统盘丢失恢复与元数据字节上限。
实际通过数量与未执行边界以候选提交的验证记录为准。
