# ZXS 架构复审与重构路线

审查基线：`9b808db8a66b9ab066638405555955429585622e`（main）。本文是设计与静态审查，不是实现或发布报告。

## 总判断

**建议大改存储领域模型，不建议重写整套系统。** 现有核心问题不是单个 SMB 分支出错，
而是目录组成、容器身份、当前位置和旧删除节点同时参与决定一个文件是谁、在哪、能否修改。
新需求却明确要求这些事实独立。当前 `State` 的平行映射、新旧目录模型并存及多个中间材料流程，
会让同一业务跨入口出现不同语义。优先替换业务权威，保留已经解决的可靠 I/O、认证与事务边界。

## 目标模型与布局

- **`FileContainer`**：持有 `FileId`、所属 `DiskId`、当前 SMB 名称、生命周期状态、容器标签及选中视图。版本物理名按 `15 位身份 ID-当前文件名` 派生；切旧节点不改当前名。名称限制统一使用目标文件系统组件上限减 16 字节，UTF-8 含扩展名。
- **`FileHistory` 与 `Draft`**：不可变正文节点与分支前沿分开；可变稿绑定准确的容器、基准节点和写入代数。对同一稿的替换和回收不得按目录名字猜测结果。
- **`DirectorySnapshot` 与 `Worktree`**：目录节点固化文件的 SMB 相对名称和完整正文，不保存 FILE 数据库、标签或整套历史。子仓只纳入当时对 SMB 暴露的文件，不复制子仓管理材料。worktree 初始物理为空，读映射原节点，写只存改动；新进入的文件即时建立独立容器，多个 worktree 的同名文件不共用身份。提交时 MOVE 改动、COPY 未改正文；提交时基点仍是 HEAD 才追加，否则分叉。撤销仓库只转移 `.zxs`；管理员可恢复软删 worktree，重新创建同基点实例不继承其改动。
- **`DiskRegistration` 与布局**：主盘对外为 `common-data` 和只读 `deleted-data`；`zxs-data` 是管理区，内部分开对应两区的数据。磁盘身份绑定 UUID，磁盘改名不改身份。备份目录名含源盘名与 UUID，等主流程验收后实现。
- **三范围职责**：FILE 保存容器局部事实与版本图；DISK 保存本盘命名空间、物理位置及目录仓库注册；SYSTEM 保存全局注册、决定及可验证的索引。三处的物理编码和恢复材料要在同一决定下可核验，不为“单一权威”牺牲已要求的独立恢复能力，也不让任一投影自行宣布发布。
- 仍待明确的是手动稿与目录显式提交／worktree 软删的交互，以及跨盘移动带未提交稿时目标包含哪份正文和历史。演示的选择不是产品决定；在正式语义确定前不要静默提交、丢稿或把它当已实现。

## 身份与跨盘事务详规

### 决定与范围

新布局以存储引擎为业务权威，SMB、Web 和恢复入口不各自实现移动、删除或引用规则。
本 ADR 定义目标契约，不代表生产 SMB 已接通。旧目录 Git 移动及其已发布收据不改义；
不新增兼容层，不自动迁移或删除旧数据。多级磁盘备份最后实现。

### 三种事实，不互相替代

| 事实 | 权威 | 不变量 |
| --- | --- | --- |
| 容器身份与归属 | 存储引擎的容器记录：稳定 `FileId` 和所属 `DiskId` | 一个身份只属于一个逻辑磁盘；盘名、盘位、文件名、inode 或正文哈希都不能替代身份。副本所在设备不是容器的归属盘。 |
| 当前路径与物理位置 | 引擎的命名空间和容器状态：当前区或保留区；由持有的磁盘根句柄落实 | 同盘改名、移动、软删除只变更位置，不重分配 FileId。历史引用不是活跃路径，也不能成为阻止最后一个活跃路径软删除的理由。 |
| 历史引用 | 已提交目录节点的不可变记录：归属磁盘及准确的 FileId、文件分支、节点和版本 | 目录仓库和 worktree 只引用本盘容器。同盘 `common-data` 与 `deleted-data` 均可；保留区的原容器不同于只读备份副本。历史引用不读取当前路径、默认分支或另一盘的副本来补齐。目录节点自己的完整快照正文独立保留。 |

仓库写入及恢复复用同一个引用准入规则。外部请求经一次类型化准入；
从磁盘重新读取时验证原记录和引用闭包，写入时在引擎决定点重验可能变化的身份和代数。
冷恢复使用原决定保存的磁盘身份或经原绑定证据证明的盘位及代数，不用当前盘位映射重判历史。
磁盘离线、读取失败、权限问题不能当成容器已物理删除；
只有已由权威证明原实体不存在，才只保留 worktree／目录快照正文，不重建原容器。

### 明确操作与生命周期

- **明确同盘移动**：保留原身份。同盘移入 worktree 时，按 worktree 的既定规则将原容器整体移入同盘 `deleted-data`，映射移入前选定的文件节点。
- **明确跨盘移动 A → B**：B 创建独立容器并取得新 FileId；A 原容器整体进入 A 的 `deleted-data`，只移除指定活跃路径。A 目录历史保留原 FileId、分支、节点和版本。B worktree 只绑定 B 的新容器；若目标为普通目录，则新容器放在目标目录。还有其他活跃路径且不能证明整容器可迁移时，拒绝操作，不误删其他路径。
- **复制**：目标独立建容器，源不变。只能观察到新建与写入时，按独立导入处理，不推断源或移动意图。
- **软删除不是内容节点**：位置变更记入时间线。SMB 删除区的只读视图不改变有权限的历史 worktree 写回同盘原容器的规则。不要复用会冻结所有文件修改的旧删除节点状态机。

### 跨盘决定与恢复

两个磁盘不能共享一次文件系统 rename。先按同一 operation ID 保留明确意图，
绑定源／目标磁盘身份及代数、原文件和所选版本、路径及目标新身份。
在目标盘准备独立内容并完成必要的同步和校验；准备阶段不把目标公布为成功，
也不先移除 A 的活跃路径。最终决定点重验源和目标的身份、代数、可用性与名称冲突。
目标独立创建、源活跃路径移除、A 保留位置及目标 worktree 映射由**同一持久决定**绑定，
复用既有权威发布及三份 ZXS 数据的职责，不让两盘各自产生成功收据。

决定前中断不能丢失源，也不能把半写目标显示为完成。
决定后按同一原操作和已绑定身份补完两端；不重新分配 B 的身份，不覆盖同名对象，不重新挑源版本。
未完成或无法确认时进入恢复状态，不向调用方宣告成功；重复请求返回同一原结果。
磁盘实际写入可能先后完成，对用户可见的结果由引擎决定及完成门控制。
不能把整个流程拆成两个互不关联的“复制成功”和“删除成功”。

### 实施与验收

1. 先建立引擎的身份、归属、当前位置及历史引用的准入类型；让新快照和 worktree 共用，不写旁路索引。范围外的入口不得退回旧语义冒充成功。
2. 接通同盘容器软删除、恢复和历史 worktree 写回，再在同一权威模型中实现跨盘移动；最后接入显式 SMB 操作。保留所有既有安全边界。
3. GitHub 定向验证分别覆盖：同盘历史写回、跨盘引用拒绝、跨盘移动与复制区别、重名和其他活跃路径保护、各持久阶段中断及重开。真实两盘 SMB 验收必须先提交 A 快照，再移动，核对 B 新身份和 A 实际保留路径；冷重启后打开 A 旧快照，并编辑 A 历史 worktree，证明不会更新 B。另验证无法识别复制来源时不会猜测。
4. 规划层／演示测试不替代磁盘事务、真实 SMB 或恢复验收。当前仍按定向 CI 验证，不在本地编译或跑测试。

## 接口边界与代码收敛

- **引擎是唯一业务写入口。** FILE 保存、命名空间修改、目录快照发布以及跨盘移动可有不同类型的命令，但共用决定／持久化／幂等回执机制。旧 `object_move` 按仓库和历史归属决定是否复制，不是稳定磁盘归属规则；不可复用其业务分支作为新语义。
- **HTTP／SMB／helper 只做各自的边界工作。** 外部身份、请求解码、句柄和原始意图留在各自适配层；对外传递的是受限视图和类型化结果，不把整份 `State` 给客户端，也不为每个适配器复制恢复流程。
- **减少并行数据源。** 先画出每类事实的生产者、持有者、投影和冷开入口，再删除被替代的平行写路径。名称／路径校验、盘上编码、哈希与签名证明、句柄限制、发布顺序、资源预算和鉴权都不是应删的“防御代码”。

## 实施顺序与删除门槛

1. **地基切片**：在新格式定义容器／盘归属、当前路径、历史 pin、稿件及持久决定的类型和唯一写入点。用真实双盘夹具区分同名、同内容、不同身份。先给冷恢复和单盘救援定准入，不直接将旧通用 `State` 或盘位当权威。
2. **同盘生命周期**：实现创建、提交、改名、软删／恢复、时间线和手动稿，核对 FILE／DISK／SYSTEM 的写入顺序、预算与失败。先闭合相同身份在三目录间转移，再接目录引用。
3. **新目录仓库**：生产初始化、完整快照、稀疏 worktree、独立代数、管理员恢复、按真实 FILE 收据同步。接入同盘读写后完成跨盘事务和实际 SMB 端到端，再对齐 Web 与 helper。
4. **删旧路径而非做兼容**：新格式不读取或修补旧盘。按生产调用图成组删除旧目录 Git staging／checkout、旧目录组成与共享图、旧删除节点写入、重复 API／DTO 和派生旁路。旧数据与现有 Git 历史原样保留；不在真实数据上执行清除。删除前核对 HTTP、SMB、CLI、恢复、导入和内部消费者，保留权限、边界检查与原语，不机械追求删行数。
5. **最后多级备份**：沿稳定磁盘身份、已证明的可恢复根与完整材料映射复制；备份副本不转移容器归属、不自动变主。先完成前四步及单盘救援验收，再启用多级迁移及拓扑切换。

验收以 GitHub 定向测试为准。每个切片覆盖**成功、拒绝不改状态、中断、冷重启、同一操作重试**。
真实 Samba 检查明确操作如何传入；浏览器验收只证明 UI。已有 demo #1416 与规划层 #1417
不证明生产事务。当前复审不执行本地编译、测试或正式部署。
