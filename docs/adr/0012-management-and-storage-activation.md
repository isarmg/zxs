# 0012：系统初始化与存储池首次激活分离

状态：当前源码实现；不表示已完成线上部署、物理掉电或已激活池拓扑迁移验收。

## 决策

首次系统初始化只建立唯一管理员及系统盘管理权威，不选择磁盘、不检查无关磁盘是否在线或为空、不创建 `Engine`。无存储时管理面可用，业务存储保持未配置。这不是零元数据成员池：核心配置仍要求至少一个元数据成员，首次选定一个或多个实际存储目录后才创建正常 genesis，固定正常发布成员及原多数恢复门槛。

候选发现仅浏览默认 `/zxs/data/disks` 或管理员显式设置的发现根内部目录，不枚举整个系统，不把发现根自身当存储候选。发现根是列表容器，不要求等于挂载点；候选可以在其内部任意层级。`storage-discovery.json` 在系统目录持久化发现根，修改要求当前管理员、预期旧值一致及与激活相同的独占锁。已有未完成激活阻止修改；已完成池改设置只影响未来发现，不移动既有数据。目录必须已存在，接口不创建、挂载或改权限。

挂载目录表示实际候选所在的当前已挂载文件系统入口；实际存储目录是用户选择的该挂载内目录，可以是任意合规子目录，并不限定为挂载根。挂载观察与存储根身份不是同一证明。只读发现、执行时复核和真正使用的目录 FD 必须连贯；第一次观察的路径字符串不能授权后续重开的替身。系统不通过这些接口挂载、格式化设备，或改变现有目录权限。

## 状态及持久边界

1. 首次账户设置不需要引导密钥。HTTP 保留同源、请求类型、大小及速率保护；未建立管理员且系统确实为空时，任何可访问 Web 的人可设置唯一管理员。`management-initialization.json` 在创建管理员前以 no-clobber 原子文件持久化；先创建并同步凭据，再建立管理权威。独占锁使并发只有一个凭据写者。两者完成后进入等待首盘状态。仅有新管理意图且无任何其他权威/存储证据的失败可以重试；已有池、旧初始化意图、权威或既有凭据阻止重新开户。凭据已落盘但权威步骤失败时，重启由原凭据恢复权威，绝不接受新密码覆盖。灾备恢复继续使用独立本地授权，不复用匿名开户。
2. 已登录的当前管理员选择并确认存储目录。执行时在锁内读取发现根，复核预览绑定的发现根身份并以 held FD 证明严格包含关系，再复核挂载观察、根目录设备/inode、系统目录及已选目录重叠、服务所有权、0700 权限及空目录。模式和容量限制在持久化意图前验证。
3. `storage-activation-intent.json` 保存完整当前配置和选择的挂载/实际存储路径及观察身份。意图同步之后才初始化存储；`Engine::initialize_held` 消费此前打开的精确空目录 FD，所有数据盘写入保持相对 FD，不重新打开可被替换的名称。
4. 核心按原协议创建盘封印、固定配置锚和日志。`storage-activation-ready.json` 绑定意图及每盘封印摘要。随后再次验证当前会话，把已有管理员的无会话灾备副本写入池。
5. 只有 `storage-activation-complete.json` 已持久化且与意图、当前配置一致，后台才能恢复并开放业务存储。HTTP 成功、`config.json` 存在和恢复线程已启动均不是绕过该闸门的依据。

新增控制记录使用同目录临时文件、文件同步、no-clobber 发布及父目录同步；已存在的发现设置通过原子替换更新。已发布名称不等于已持久化：读取管理意图、激活证据或保存设置时，先验证持有文件为服务所有的单链接 0600 文件，再同步同一个文件及持有父目录。目录同步失败后的可见 complete 不能使状态变为 Active，也不能使重复完成返回成功；只有重新完成持久屏障才能接纳。失败不删除意图、不重置配置、不清空盘目录。意图后尚无完整核心材料的中断保持恢复阻断，不将其重新解释为未初始化目录。

## 失败、重试和恢复

账户与首盘激活独立。首盘激活失败不撤销已建立的系统管理员；可以继续登录查看故障。完成操作只接受当前管理员，复核原意图、原目录身份、配置和封印后，先打开原根并以同一 FD 的 fstat 比较意图设备/inode，再将这些精确 FD 交给核心恢复入口；核心在取得 writer 锁及恢复写入前验证持有根和盘封印，复制当前管理权威；不接受替换路径或新凭据。首次创建、耗时盘 I/O 后和最终凭据复制前均保留当前会话复核。完整核心配置已持久化但 ready 文件尚未发布时，完成入口只在原选择、原配置和封印均匹配且核心恢复成功后补充 ready；绝不重新调用初始化。已发布管理员灾备而 complete 文件尚未发布时沿原日志恢复，匹配的灾备副本不重复写入永久收据。

挂载 ID 只是创建时命名空间观察，不能作为跨重启唯一证明。持久恢复保持原配置路径和核心封印的设备/inode绑定，不依赖新的发现设置、预览 ctime 或当前 mount ID；目录替换、配置变化或证明缺失明确失败，不能采用新空目录或凭最新 mount ID 自动重写旧证据。存储配置丢失仍由保留激活意图识别为恢复需求，不回到等待新盘状态。

## 现有池动态增删的明确边界

本决策实现“先建系统账户、后在 Web 选择首盘/首对”，不实现已激活池任意新增、排空、移除、解绑或更改已使用的存储路径。现有正常发布及恢复仍以固定配置成员验证历史 Candidate。直接修改 `config.json`、删 `DiskConfig`、改目录路径或仅复制当前文件，都会绕开保留历史、永久收据和丢失系统盘恢复证明。

动态能力必须另行实现并验证：

- 持久且可认证的拓扑代际链，保留原 genesis 成员锚；历史决定按其当时成员集合验证，不能用最新在线成员数重算。
- 元数据成员改变的联合旧/新成员决定、唯一协调器与两侧 writer 锁；新成员取得全部恢复依赖后才能切换，不能以复制一个当前快照替代永久历史证明。
- 排空计划覆盖全部可用保留版本、目录/文件策略、在途工作区、读租约和原有收据引用。每个目标独立完整复制、逐块/最终摘要验证及同步；切换拓扑和放置绑定在同一决定发布。
- “删除”首先是经过排空和证明后的逻辑退出，不删除物理设备或原数据。旧目录重新出现必须按退出代际隔离。最后健康副本、仍被历史/工作区引用的目录及未完成联合决定禁止退出。
- 故障注入至少覆盖每个持久屏障前后、系统状态丢失、旧/新侧缺盘、重复请求、撤权、并发提交/读租约/清除及重启重放。通过之前界面不能展示可成功执行的已激活池增删按钮。

首次激活最多32个目录，候选相互重叠检查为有界 O(D²)，持有目录描述符 O(D)；空目录只检查首个条目，不递归扫描无关文件。初始化沿原核心同步协议，增加系统侧意图/ready/complete 原子文件，不通过删 fsync 减少成本。

这不是旧格式兼容、旧材料升级或真实设备操作授权。未支持材料保留并拒绝。
