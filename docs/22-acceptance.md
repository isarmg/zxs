## 22.3 版本、分支和文件语义用例

| ID | 用例 | 预期结果 |
| --- | --- | --- |
| <a id="case-v01"></a>V01 | 修改 V1 并完整保存 V2，含追加、截短和局部修改 | V2 独立完整，V1 字节及哈希不变 |
| <a id="case-v02"></a>V02 | 普通版本和分支首次写入后的独立文件检查 | 无内容硬链接、reflink 或其他版本读取依赖；冻结来源引用和合并连线不新增正文 |
| <a id="case-v03"></a>V03 | 从当前或历史元数据创建分支 | 仅记录和冻结来源引用，FileVersion及正文数不增，源内容与历史不变 |
| <a id="case-v04"></a>V04 | 两分支含不同或冲突内容时记录旧MergeLink关系线 | 不比较或解决内容冲突，两边文件和 HEAD 保持原状 |
| <a id="case-v05"></a>V05 | 普通内容提交伪填多父，或旧MergeLink企图改父列表 | 拒绝改写原正文证明；合法关系标记仅独立记录，不混同统一文件图的多父节点 |
| <a id="case-v06"></a>V06 | 在两个或多个分支的指定版本间分别登记MergeLink | 每条固定两个所选节点，不创建版本或触发保存；文件分支合并另按G06—G10验收 |
| <a id="case-v07"></a>V07 | 浏览历史后继续编辑保存，再次正常保存 | 首次记录新分支并仅为实际写入生成 FULL，后续推进新分支，原主分支不变 |
| <a id="case-v08"></a>V08 | 脏工作区或开放写句柄期间变更其目标引用 | 原工作数据与读取版本保留；旧写入按原基线拒绝越界提交，不得写入新分支 |
| <a id="case-v09"></a>V09 | 受控 API 工作区同时操作不同分支，另有多个 SMB 客户端 | 管理工作区互不串用；SMB 按共享默认目录组成及文件引用解析，绑定保持稳定 |
| <a id="case-v10"></a>V10 | 旧只读句柄期间发布新版本 | 旧句柄固定旧版本，新打开解析新状态，不混合字节 |
| <a id="case-v11"></a>V11 | 一次写入触发多次 flush 但没有新修改 | 不重复产生版本 |
| <a id="case-v12"></a>V12 | 原子替换三副本目标 | 发布前满足目标保护，历史能追踪替换关系 |
| <a id="case-v13"></a>V13 | 删除打开中的文件 | 路径逻辑删除；有效句柄和历史不被提前回收 |
| <a id="case-v14"></a>V14 | 从可用历史或 PURGED 状态尝试继续保存 | 来源元数据有效即可登记冻结引用；来源 PURGED 不阻止完整新内容写入，不创建占位文件或恢复被清除正文 |
| <a id="case-v15"></a>V15 | 请求未支持的 mmap、链接、设备节点 | 明确错误，不空实现成功 |
| <a id="case-v16"></a>V16 | 写会话过期后旧客户端重连提交 | fencing 生效，不接受旧写者 |
| <a id="case-v17"></a>V17 | 多文件显式目录提交中途失败 | 整棵新树不半发布 |
| <a id="case-v18"></a>V18 | Web 元数据操作失败或结果未知 | 显示失败或待确认；重试前核对原操作，不把失败当发布成功；不存在文件上传、下载或预览入口 |
| <a id="case-v19"></a>V19 | 两个 SMB 会话从 H0 编辑不同文件 A/B，依次保存 | 核对文件及目录条件后形成 H1、H2，互不发布另一文件脏内容 |
| <a id="case-v20"></a>V20 | A 提交时 B 继续修改 | B 脏代际完整保留，不被 A 的提交清除或发布 |
| <a id="case-v21"></a>V21 | 同文件多个写句柄并发 append/truncate/fsync | 服务端序列化字节操作及 EOF，冻结边界确定 |
| <a id="case-v22"></a>V22 | SMB FLUSH、写穿透与最后可写关闭 | 按 11.3 和 [第 11.10 节](11-write-semantics.md#s11-10)完成或明确失败，不把暂存当完整保存 |
| <a id="case-v23"></a>V23 | A 的目录移动/删除影响 B 工作区 | 按稳定身份复查依赖，不直接改 base_head 掩盖冲突 |
| <a id="case-v24"></a>V24 | 一批包含不同一级来源和1/3/自定义r份版本 | 每条固定路由逐级达标；保护、拓扑或绑定变化重新准备 |
| <a id="case-v25"></a>V25 | 创建未发布文件并在同会话重新打开 | workspace-view 可读本会话内容，其他会话不可见，版本缓存不污染 |

| <a id="case-v26"></a>V26 | 单文件、目录批次及兼容整树创建分支 | 只发布记录和0600冻结来源引用，来源正文/inode及内容版本数不变，不新增保护回执 |
| <a id="case-v27"></a>V27 | 新分支首写空文件或与来源相同字节 | 产生独立真实 FULL 和版本身份，清除该文件引用；不是 no-op |
| <a id="case-v28"></a>V28 | 新分支首次范围写入、截短或 SMB 可写打开后关闭 | 以冻结父版本为基础，保留未修改范围，EOF外空洞补零；无脏写关闭不激活 |
| <a id="case-v29"></a>V29 | 目录批次只写部分文件、其余未写 | 已写文件读取自己的内容，其余读取各自冻结父版本；来源引用不加版本节点，范围外不变 |
| <a id="case-v30"></a>V30 | 来源正文 PURGED 后创建/选择分支并首次写入 | 元数据有效即可创建和选择；创建不读正文，继承读取如实报已清除，完整上传可首写 FULL，旧墓碑保留 |
| <a id="case-v31"></a>V31 | 占位创建/移除、容器改名、FINALIZE后崩溃及原请求重试 | 同候选幂等重放；不复制来源、不删既有正文；占位丢失可由权威记录重建 |
| <a id="case-v32"></a>V32 | 历史包导出/恢复待写入分支及稀疏 Branch | 包不虚增正文，恢复重建占位；空映射稀疏编码的规范字节及证明保持稳定；旧继承快照仍读取原父版本 |
| <a id="case-v33"></a>V33 | 两个待写入分支共用来源，旧工作区跨选择提交 | 固定创建时文件分支选择；即使来源版本ID相同也拒绝写串分支 |
| <a id="case-v34"></a>V34 | 历史另存只 staged 部分文件、零字节或仅命名空间修改 | 只实际写入文件拥有 FULL，其余继承父版本；不以相同hash跳过首写或在创建时隐式复制来源 |

| ID | 故障注入点 | 预期结果 |
| --- | --- | --- |

## 22.5 真实平台验收

浏览器矩阵记录浏览器版本、操作系统、CPU 架构、视口、Web/WASM 构建及文件浏览、元数据、版本树、会话和网络结果。SMB 矩阵独立记录操作系统、客户端、Samba 及桥接版本、协议、网络和缓存设置、被测编辑器及结果。独立救援工具记录构建、离线操作与失败边界；不把历史 CLI 测试当作当前产品入口验收。

分别验证桌面和移动浏览器经 HTTPS API 访问，以及实际支持的桌面和移动 SMB 客户端经 Samba 访问。Linux、Windows、macOS、Android、iOS、iPadOS 等仅用于登记真实浏览器或 SMB 客户端环境；不要求构建原生应用或移动 SDK。浏览器元数据操作、会话过期及断网状态，以及上传、下载、预览入口缺失断言，与 SMB 编辑器保存、错误、锁和断连恢复分别记录。

不能把“某个浏览器或 SMB 客户端能浏览目录”当成该组合的全部文件操作已通过。Web 与 SMB 按各自能力验证；浏览器关闭后的后台传输或原生编辑器回传不属于交付要求。

## 22.6 验收交付物

每个候选发行版应提供可运行构建、固定依赖与配置、测试报告、故障注入记录、恢复步骤，以及至少一次实际拆盘独立读取演练的结果。不能只交付架构图片便宣称整个存储系统完成。

报告使用[统一模板](templates/validation-report-template.md)，分别记录未执行、通过、失败和有依据的不适用。下列用例仍是目标；[契约附件](contracts/README.md)的静态验证只覆盖明确列出的字段和向量，不代替任何系统用例。

## 22.7 协议模型、格式与容量专项验收

| <a id="case-d05"></a>D05 | UINT64 边界、错误实体前缀、未知字段、错误结果组合 | schema 或规定的语义校验明确拒绝；不同实现结果一致 |
| <a id="case-a03"></a>A03 | 上传中断、范围重发/重叠、截短、封存后写入 | 代际、接收范围和最终哈希一致，缺范围不补零，旧操作不指向新字节 |
| <a id="case-a04"></a>A04 | HEAD 前进、分页过期、事件窗口过期及授权变化 | 固定快照不混页，失效明确；重新列举与续读无漏事件、无越权泄露 |
| <a id="case-a05"></a>A05 | 操作完成后裁剪日志、清除内容、重试旧 ID | 检查点保留去重与终态；不同请求拒绝，同请求返回原结果 |
| <a id="case-c04"></a>C04 | 账户/全池工作区、暂存、句柄和队列达到上限 | 拒绝新增但保留已有脏数据；查询、导出和必要恢复仍有额度 |
| <a id="case-c05"></a>C05 | 长期闲置工作区、清除期间反复续租、降低资源上限 | 只提醒不自动删脏数据；租约有界，已有占用只限制增长，不绕过引用检查 |
| <a id="case-c06"></a>C06 | 协议常量改值、启动配置与日志代际冲突 | CONFIG_INVARIANT_VIOLATION / CONFIG_CONFLICT，禁止静默覆盖权威状态 |
| <a id="case-p03"></a>P03 | 大文件频繁写穿透、其他会话并发及控制盘缓慢 | 测量全量成本、跨会话处理、全池阻塞和 P99；超过预登记目标不得通过该负载支持验收 |
| <a id="case-p04"></a>P04 | 决定未收敛、队列满，同时请求注销或改密 | 独立管理认证仍可响应；入口阻断不代表已接纳存储决定回滚，恢复额度有效 |
| <a id="case-s06"></a>S06 | 11.11 全部样机场景及精确 NTSTATUS 映射 | 版本、回调、请求、操作及错误证据齐全；支持矩阵逐项登记 |

新增协议规则必须先通过 M05 和 F35～F38，再用于冻结发布。静态附件校验不执行这些故障场景，不能据其成功把本表结果批量改成通过。
