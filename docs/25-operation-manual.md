## 25.1 连接与工作位置

使用前应确认服务器地址、唯一管理员登录凭据、目标仓库和历史树。系统没有其他管理员、普通账户或逐仓库授权设置。Web 使用 HTTPS 站点地址；SMB 连接使用独立发布的共享地址。二者的连接参数和工作状态分别管理。

通过 Web 使用系统：

1. 使用受支持浏览器打开服务器的 HTTPS 地址并登录。
2. 在文件页面选择一个磁盘目录，沿文件夹和面包屑浏览；副本盘明确只读。
3. 选中文件后查看它自己的当前分支、版本树和备注。文件容器的改名不改写内部版本名；Web 不提供文件正文预览或下载。
4. 需要批量处理时，在当前目录或文件夹动作中创建目录分支；状态页面查看 CPU、内存及磁盘容量，历史页面查看实际操作。

通过 SMB 使用系统：

1. 使用共享地址和部署时指定的唯一 Samba 认证账户建立独立 SMB 连接；该账户绑定唯一 ZXS 管理员，凭据独立配置，不允许匿名或 guest 访问。
2. 确认共享对应的历史树和主分支。
3. 在共享内执行基础文件操作，保存直接进入该主分支。

Web 私有工作区的分支绑定不改变 SMB 共享绑定；显式修改共享默认目录组合或其文件引用会影响后续 SMB 视图。SMB 不提供历史切换、分支管理、历史内容清除或树拆分。Web 提供当前文件/目录分支与历史查看；管理员可通过 Web 管理页执行获授权的历史内容清除、旧关系标记及树拆分，也可使用对应受保护 API。清除和拆分须先审查预览，再按摘要明确提交；表单存在不表示所有历史域均支持这些操作。日常管理不提供 CLI 入口，各表单及端点见[日常管理覆盖](components/daily-management-coverage.md)。

## 25.2 日常文件操作与保存

Web 提供文件浏览、版本树和元数据管理，不提供文件上传、下载或正文预览；SMB 按标准协议支持关联应用的读取与编辑。各入口按实际能力执行新建、复制、移动、重命名和删除。名称和路径采用统一规则，错误名称需要由用户明确修正。

一次常规保存按以下过程完成：

1. 按需在 Web 选择明确的目标文件分支或目录组合，再通过 SMB 共享打开并编辑文件；受控 HTTP API 也保留正文写入能力。
2. 执行保存，核对服务器处理和目标保护状态；外部编辑器的本地保存提示不替代服务器结果。
3. 服务端为发生内容变化的文件建立新的完整版本，按指定路由建立相应份数。
4. 正常保存完成后，检查操作结果与当前健康情况。已有历史版本保持不变。

保存一个文件不会同时发布其他文件的未保存修改。改名和移动不等同于重写文件内容，也不自动迁移既有版本的实际盘位。复制或替换目标文件时，按目标位置及保护规则保存完整文件。

SMB 或受控 HTTP API 的传输完成、已经在本地保存、正在补齐副本和 COMMITTED_AND_PROTECTED 必须分别区分。未收到确定结果时，保留原操作和工作数据，先查询结果。

<a id="s25-03"></a>

## 25.3 历史查看、比较与导出

在 Web 中选择文件、目录或历史节点，查看提交时间、作者、名称变化、版本状态及关系线；受保护 HTTP API 也提供对应历史查询。浏览历史不创建分支，也不改变当前目录。

内容仍可用时可通过受控 HTTP API 获取，离线救援导出另见维护流程；Web 仅查看元数据与版本树，不预览或下载正文，受控 API 可比较两次提交；当前 Web 没有提交比较表单。内容已清除时，节点、名称、摘要和关系仍显示，但不能打开该版本的文件字节；依赖内容的比较须明确显示不可用。

导出只产生外部副本，不自动改变在线备份目标、权限或内容保留策略。若需要在历史状态上继续修改并保存，使用下一节的分支与首次写入流程。

<a id="s25-04"></a>

## 25.4 新建引用分支与历史保存

在文件详情点击“从当前内容创建分支”，原按钮会变为下划线输入框。输入分支名称并按 Enter 创建；空白内容、点击其他位置或按 Escape 会取消，不发送创建请求。创建完成后在该文件的“当前分支”菜单中选择；创建本身不自动切换，只登记来源并生成冻结来源引用，不复制正文。从某个历史版本创建同理，来源正文已清除也可登记。选择后显示冻结父版本的元数据；通过 SMB 或受控 HTTP API 写入同路径内容首次生成自己的独立 FULL 版本，只推进该文件所选分支，其他文件不变。显式写入零字节或与来源相同内容也算首次写入。

目录批量分支使用以下流程：

1. 进入目标目录，在工具栏点击“创建目录分支”；也可通过列表的“详情”进入文件夹详情后操作。
2. 在原位置输入名称并按 Enter。系统创建稳定命名目录分支，直接引用父分支的冻结子树，不提前创建自有子树、后代文件分支或正文，创建后不自动切换。空白、失焦或 Escape 取消。
3. 在“当前目录分支”菜单选择已保存组合。系统完整预检后一次恢复目标子树的冻结条目、名称、文件引用和后代目录引用，目录范围外不变。修改文件、命名空间或子项选择时，才给原命名分支追加不可变子树，不会自动创建新命名分支。
4. 切换可能使当前新增文件从所选目录视图移出，也可能恢复旧组合中的文件和旧名称；这不清除文件历史或正文。操作前核对目标组合，不能将切换理解为只更换同名文件内容。目录本身仍按稳定身份定位到当前路径。业务可写状态、冻结引用或完整仓库条目额度不满足时整笔拒绝，不先切换部分条目。已认证的唯一管理员可选根目录默认分支，后续 SMB 操作读取该默认组合。

空目录不能创建文件分支。备份盘只读；旧数据盘根若包含多个独立命名空间，须先进入具体文件夹。来源元数据无效、目标只读或同名冲突均不会发布部分成功结果；纯创建记录不要求来源正文可读。结果未知时查询或重试同一原操作 ID，不能另建操作覆盖未决结果。

旧整目录快照管理接口属于兼容高级工具，与上述目录批量文件分支不同；已有文件分支的历史域禁止通过旧接口生成或拆分整树快照。

## 25.5 合并文件分支、编辑节点标签与旧关系标记

文件详情选择“合并分支”，勾选至少两个活动文件分支，选择该文件的结果节点，再主动选择归属分支并提交。复用输入头时不产生新文件节点；其他结果新增复用正文的合并节点。其他输入分支转只读别名，相关目录引用同步更新。目录分支合并待确认。

历史节点支持页面内编辑标签，也可选择多个节点批量增删。修改新增标签子节点；编辑历史标签不会使较新的正文退回。文件或文件夹详情可配置保存份数及每个备份盘的路径前缀，具体规则见[合并、标签与备份说明](design/file-merge-tags-backup.md)。

以下为旧 `MergeLink` 关系标记操作，与上述实际文件分支合并分别保存。通过 Web 管理页的关系标记表单填写精确的两端分支与提交 ID；表单调用同一受保护业务 API，见[日常管理覆盖](components/daily-management-coverage.md)。

关系标记只用于表达选定版本之间的关系。

1. 从历史图查询结果中取得起点的分支与提交 ID。
2. 取得另一分支某个已有提交的 ID 作为终点，可以是旧提交。
3. 在 Web 关系标记表单填写源分支、源提交、目标分支和目标提交并保存关系，检查两端是否仍为原来选定的节点。

画线不合并内容、不解决文件冲突、不复制文件、不创建新版本，也不推进任一分支的 HEAD。未保存修改不会因画线而提交，端点内容已经清除也不影响历史关系标记。

分支继续保存后，已有连线保持原端点。要表达与多个分支的关系，分别连接对应版本。实际修改某分支文件时，另行选择该分支并执行普通保存。

## 25.6 删除当前文件与清除历史内容

删除当前文件只移除当前目录项，原有历史按保留规则继续存在。SMB 删除属于这种操作。

需要释放历史文件内容时，通过 Web 管理页的历史清除表单选择明确版本 ID 并生成预览，再审查不可变计划摘要和影响，明确确认后提交；也可显式取消未执行的计划。端点与表单见[日常管理覆盖](components/daily-management-coverage.md)，一般流程如下：

1. 选择版本、某文件的版本集合或明确范围。
2. 查看受影响历史视图、各级完整副本、内容固定、开放读取和未完成任务。
3. 处理仍在活动分支、工作区或读取中使用的内容；无法解除引用时等待或取消。
4. 执行清除计划。准备阶段的新读取受屏障约束，安全取消完成后可恢复读取。
5. 墓碑发布后，检查逻辑内容已清除、物理清理进度、离线残留和实际释放空间。

历史树、版本父边和合并连线继续保留。离线盘上的内容需要回盘核验后清理，不能将任务受理或逻辑清除直接视为所有磁盘已经腾出空间。文件删除不等于介质安全擦除。 当前按盘统计的活跃 payload 预算不计 `PURGED` 或 `MIGRATED` 的旧节点，迁移后的新节点按其实际放置计入；这不是物理已释放空间的证明，残留、暂存及文件系统可用空间仍需分别核对。

## 25.7 拆分历史树

拆分将一个非根节点及其全部实际后代迁入新树。后代沿版本演进父边计算，合并标记线不会扩大范围。当前通过 Web 管理页的拆分表单填写历史域与切点提交，生成预览后按摘要明确确认提交或取消。此整树操作不支持包含独立文件分支或目录组合的历史域，遇到这些状态会明确拒绝，不能用它拆分普通文件管理页面中的文件分支；对应操作见[日常管理覆盖](components/daily-management-coverage.md)。

1. 选择切点，预览将迁移的节点、分支、内容状态、合并标记和空间需求。
2. 明确两侧的保护规则，以及需要保留或设置的主分支和共享绑定；不设置逐仓库账户权限。
3. 处理受影响工作区、开放句柄及其他维护任务。
4. 准备新树的独立完整文件和两侧恢复材料，再同时公开两棵树的结果。
5. 分别检查原树和新树的历史、文件、共享绑定与任务状态。

同一结果树内部的连线保留并映射端点，跨边界连线只留文字来源记录。已清除节点保持已清除状态，不恢复缺失字节。

全部活动分支迁出后，原树可以只保留前序历史并归档。原 SMB 主分支迁出时共享停止；由唯一管理员明确设置归属并重新绑定共享后才能继续开放。新树是否开放共享单独配置。

## 25.8 分配硬盘与设置备份路线

当前可通过受保护的首次初始化指定盘位与拓扑；已有池的线上加盘、拓扑迁移和换盘入口尚未实现，未初始化配置草稿不能代替已有池迁移。以下说明配置要求，不是已交付的在线操作步骤；实际入口见[服务端说明](components/server.md)。

最小部署为系统盘加一块一级存储盘，目标份数为 1；不必配置二、三、四及后续备份级别。单盘没有冗余，永久丢失不能承诺恢复数据，但系统盘完好时仍可进入 Web 管理。管理员可按需要登记 n ≥ 1 块独立物理存储盘，并指定各盘职责：一级盘保存第一份，二级盘保存指定一级来源中需要第二份的文件，三级及后续盘继续指定上一级来源。未分配盘保持备用。

1. 核对设备身份与已有数据，明确各盘的级别和备用状态。
2. 为每个备份盘指定上一级来源列表，检查无环、相邻级别、同源单后继及物理盘不重复。
3. 为目录或历史树指定一级归属规则，检查可支持的最大份数。
4. 设置各文件或目录的目标份数，并查看对应的逐级目标盘。
5. 完成配置及必要迁移后，按每级实际状态判断保护是否达标。

| 目标份数 | 需要的实际内容副本 |
| --- | --- |
| 一份 | 指定一级盘的完整文件 |
| 两份 | 指定一级和二级盘，各一份完整文件 |
| 三份 | 指定一级、二级和三级盘，各一份完整文件 |
| 四份及更多 | 沿固定路线连续增加指定级别，每级一份 |

份数包括原始存储。一个备份盘可以汇聚多个指定来源，不强制恰好两个来源。指定目标离线或满盘时，不能借用不相关空盘或跳过中间级别。控制元数据的 N ≥ 1 个成员另行指定，与业务文件份数分别管理。

<a id="s25-09"></a>

## 25.9 调整份数与迁移来源

提高保护份数前，先确认完整路由、目标可用性和空间。系统补齐期间显示保护调整中，全部指定目标完成后才显示新目标已达标。

降低份数须检查有效保留要求和影响范围，按授权及宽限规则清理多余级别。某个视图的要求降低时，仍须满足其他有效保留要求。归档、移目录或掉盘不会自动降低目标。

改变一级归属、备份来源或替换盘位时，查看当前与历史文件的迁移范围、峰值空间、旧盘残留及最终路线。规则只作用于后续新版本时，应明确说明；已有版本实际迁移完成前不能显示为新路线合规。

<a id="s25-10"></a>

## 25.10 处理未保存、冲突和故障

| 界面或错误状态 | 处理方式 |
| --- | --- |
| 仅本地保存、待上传 | 保留本地修改，恢复连接后继续核对和传输 |
| 操作结果未知 | 查询原 operation_id 或按同一请求重试，不创建新 ID 重复保存 |
| 文件基础版本或目录前置条件冲突 | 保留修改，查看当前状态；选择导出、明确的新分支或重新编辑，不自动覆盖 |
| 指定盘空间不足或路由不完整 | 定位具体来源和级别，释放获准内容、明确换盘或迁移配置后重试 |
| 内容可读但保护不足 | 查看缺失的指定级别并修复；新的正常保存仍需满足全部目标 |
| CONTENT_PURGE_PENDING | 等待清除完成或安全取消，不改用另一版本，也不提前视为已清除 |
| CONTENT_PURGED | 仅查看历史元数据；需要字节时从实际可用的外部副本显式导入为新版本 |
| 没有健康副本 | 停止使用该版本，等待硬盘恢复或进行显式外部恢复，不生成空文件代替 |
| 无权限或会话失效 | 停止新操作，重新验证当前管理员会话和入口绑定；历史恢复不会恢复已撤销会话 |
| SMB 共享不可用 | 按连接或服务故障处理，不将其当成真实空目录或全部文件被删除 |

## 25.11 管理员首次设置

首次设置与普通启动分别执行：

1. 登记服务器和物理盘身份，核对设备与已有数据范围。
2. 由部署者使用系统工具预先准备独立 Btrfs 文件系统、按 UUID 挂载并设置受控目录权限；ZXS 的首次初始化和普通启动都不分区、格式化或挂载设备。
3. 指定至少一个存储盘作为控制元数据成员；单盘部署使用唯一一级盘，附加备份层可选。多盘时明确成员集合、逐级备份来源及目录一级规则。
4. 通过受保护 Web 首次初始化创建唯一管理员，再配置仓库、历史树和活动主分支；没有新增其他账户或授予仓库权限的步骤。
5. 分别配置业务 API 与独立 SMB 共享，核对各入口权限及保存目标。
6. 完成启动检查后开放服务，并验证完整保存、原操作查询、历史查看和单盘恢复材料。

一块存储盘即可配置为唯一一级盘及唯一元数据成员，并按一份目标正常保存。多成员配置须全部成员完成正常发布，不能因缺盘临时缩小集合；业务内容份数与元数据成员数分别管理。

<a id="s25-12"></a>

## 25.12 巡检、换盘、拔盘与关机

当前没有线上换盘、排空或弹出入口。下述换盘与拔盘流程是维护要求，不表示 Web 或救援工具已经实现；不能直接修改已有池配置或删除登记证据来替代迁移，支持范围见[服务端说明](components/server.md)。

日常巡检检查每个指定盘位、来源链、副本状态、内容完整性、容量、未完成操作、工作区和清除残留。系统报告应能定位到来源与级别，不能只显示存储池总容量。

换盘时指定明确盘位和替换物理盘，复制并验证该角色需要的数据后切换绑定。兼任控制元数据成员的盘，必须同时执行成员更换与旧写者隔离流程。

拔盘前先决定需要维持在线保护，还是保留盘上数据并离线带走。前者完成指定目标的迁移和验证；后者展示受影响版本、可用性与保护不足，不把安全卸载等同于全仓继续在线。

关机前停止接纳新工作，处理或保留已有修改，完成已决定操作或记录恢复状态，再停止入口并卸载物理盘。超时仍有未知操作时保留证据，不报告已干净结束。

## 25.13 恢复与重新导入

单盘恢复使用支持盘上文件系统的环境和只读恢复流程。核对本盘完整文件、描述、校验及提交证明后导出，不能假定一块盘包含全部仓库或当前认证状态。

系统盘或索引丢失时，先恢复已有身份、有效检查点和日志，再重建索引，不自动创建空仓覆盖数据盘。无法验证当前授权和清除状态时，只允许管理员隔离核验与恢复导出，不开放正常业务读取。 `restore-system` 的输入须能证明固定配置的至少 Q = floor(N/2)+1 个独立旧元数据成员认可同一配置；重复成员、多个合格配置或混入另一池的成员在创建新系统目录前拒绝，不能按目录顺序任意选池。N=1 时唯一可信旧成员即可满足数量门槛；缺失配置锚的旧盘不兼容，不按在线盘数缩小原配置，也不自动迁移。

恢复元数据时，准确绑定的快照根、索引、叶页及独立认证对象可以逐对象从不同可信成员选取健康副本；历史目录也必须验证全部绑定条目及图，不能只检查目标 history 的路径证明，全部闭包仍须认证；读取本身不修盘，全配置成员写者恢复才修复这些对象。清除收尾也可从其他健康成员取得同一发布闭包的墓碑证据，不能把首选副本损坏误认为没有证据。证明缺失仍须停止相应操作；本地提交或发布证明冲突时，已验证的恢复路径保留原文件到相应 `proof-quarantine/` 后重建，不要手动删除隔离证据来掩盖问题。

遇到缺少 `radix-map-roots` 的 Snapshot/历史根、旧平面页列表、`history_manifest_hashes`、`history-index` 或旧包/墓碑结构时停止并保留材料；不要补字段、改摘要、重置运行池或自动切换二进制迁移。格式源码变更不包含真实部署授权。独立包必须有目录 `history_root_proof`，清除墓碑必须有 `content_state_proof`；证明拒绝后不能继续导入或删除正文。

已清除版本即使找到外部备份，也只通过显式导入创建新的完整版本，保留原节点曾清除的事实。文件在外部被修改后重新接回时，隔离并按导入处理，不更新旧版本字节。

## 25.14 操作结果对照

| 操作 | 检查的最终结果 |
| --- | --- |
| 内容保存 | 新完整版本、目标分支、发布时保护情况及当前健康情况 |
| 分支创建或历史保存 | 新分支与起点、来源节点、来源引用清单及实际写入文件的 FULL 发布结果 |
| 旧关系标记MergeLink | 固定的两个端点与关系记录，无新版本和文件复制 |
| 文件分支合并FileBranchMerge | 全部输入head、采用节点、结果节点、归属及参与目录引用；无新正文，旧只读历史保留 |
| 当前目录删除 | 当前目录项已移除，历史保留状态可查询 |
| 历史内容清除 | 历史节点保留，逻辑墓碑、物理清理和实际释放量分别可查 |
| 历史树拆分 | 两树状态、迁移映射、独立文件及恢复材料、主分支和共享归属 |
| 备份或拓扑调整 | 实际生效代际、指定路线达标情况、迁移任务和残留状态 |

需要核对详细规则时，分别查阅[第 6 章](06-history-and-branches.md)、[第 9 章](09-backup-topology.md)、[第 10 章](10-transactions-and-recovery.md)、[第 13 章](13-retention-and-deletion.md)、[第 17 章](17-lifecycle-and-maintenance.md)和[第 18 章](18-failure-handling.md)。
