## 19.1 按完整文件及实际位置计费

对仍保留的不同完整版本，按各版本实际目标盘位核算，普通后续提交引用的同一未变版本不重复计费。分支实际写入生成的完整版本独立计费；合并连线只计少量关系元数据，拆分后两树不通过共享文件抵消占用。

这里的合并连线指旧 `MergeLink`。文件分支合并 `FileBranchMerge` 同样复用已有正文，但需计入来源记录、必要的元数据节点及受影响目录子树，不能只按一条关系线估算其元数据预算；规则见[补充说明](design/file-merge-tags-backup.md)。

```text
完整内容预算 ≈ Σ[logical_size(v) × target_copies(v)]
总需求 = 完整内容 + 历史拓扑与元数据 + 工作区
       + 分支首写/拆分/拓扑迁移的临时占用
       + 修复预留 + 安全余量
```

各物理盘上的副本分别计费。Btrfs 压缩、稀疏、分配和元数据会影响实际占用，逻辑大小、保守预算及实际物理占用分别报告。墓碑发布不等于所有盘已释放空间，暂存和迁移残留也不能隐藏在正常内容预算里。

<a id="s19-02"></a>

## 19.2 全量版本的成本例子

10 GiB 文件保留 100 个完整版本、每版三份，内容预算约为 3000 GiB，即 2.93 TiB，另加元数据、工作区和维护预留。即使某次只修改 4 KiB，新的完整版本仍需按 10 GiB 及目标份数预留。

为含 200 GiB 文件的状态创建分支只占用元数据和冻结来源引用，不预先复制 600 GiB 正文；只有随后实际写入该文件并要求三份保护时，新的 FULL 内容预算约为 600 GiB。两个分支间的合并连线仅占用关系元数据空间，不产生文件复制开销。上述为字节量估算，不是实际空间测量或耗时承诺。

<a id="s19-03"></a>

## 19.3 分支、拆分与迁移预留

活动继承分支仍固定所需父正文，引用虽然不新增 payload 字节，却可能延长父内容保留；不能预先将被依赖父版本计作已可释放。

分支创建只准入元数据与来源引用开销；首次实际写入时再为该文件完整逻辑大小及指定副本预留空间，不因登记引用提前占用全部来源正文预算。合并连线不复制文件，无需预留额外内容空间。拆分先准备新树的独立文件及两树恢复包，拓扑迁移先准备新指定目标；不能先删除原健康文件腾空间。

准备对象可在同盘封存为正式路径，避免同一新文件无意义再复制，但不能用 reflink、硬链接或跨树引用降低独立文件预算。所有计划展示峰值占用、最终预计占用、可取消阶段和实际释放条件。历史清除不需要重写后续完整版本，但仍需保留墓碑及清理任务的元数据预算。

## 19.4 读写与前台应用成本

文件管理器每页默认 200、最多 500 个直接子项；候选选择最多保留 `limit+1` 项，仅当前页和至多一个精确已选项执行完整线格式投影。分支摘要不复制冻结条目或上下文映射，响应不随每个分支的后代文件数放大；分支个数本身尚未分页，因此不承诺跨所有维度的绝对响应字节上限。

当前存储是每目录有序的分页命名空间（[ADR 0011](adr/0011-paged-namespace-roots-and-segmented-logs.md)）：点查与目录列页先经索引定位再读本页，后代文件数读取目录记录总数；名称搜索仍枚举相关目录层，每次翻页仍在现有核心锁内执行；备份目录仍需全局轻量路径节点以检测冲突和选择可用版本。分页消除全量 JSON、客户端全量排序/DOM 与逐条重复查树，不代表解决十万同目录项的全部锁延迟。1k/10k/100k 合成元数据测试证明候选和响应投影界限，不等同于真实物理文件导入、持久化吞吐或延迟测量。

设序列化配置大小为 C：同一 `AdmissionEngine` 在两次 Engine 可变借用之间只于首个列表请求花 O(C) 构造并散列快照输入，后续只复制固定 64 字节摘要，不再重复序列化配置；持有一份摘要，不按目录、查询或游标数量增长。任意 Engine 可变借用均失效，失败写入和纯认证发布也会让下一次读取重算，未优化这个冷路径。主盘条目复用路径类型已有的末级规范键，省去重复 Unicode 规范化；小写转换、排序字段复制、逐请求查询摘要以及游标输入校验仍存在。N 项扫描和最多 L+1 候选的 O(N log(L+1)) 有序选择不变（不含变长字符串比较成本）。没有新增 I/O、fsync 或互斥锁；惰性单元在既有 Engine 锁内使用，不改变锁持有范围，也没有实测延迟或吞吐提升结论。

已发布命名空间的精确路径查询统一使用 `NamespaceTree` 借用视图。构造器仅在查询模块内可见，公开入口从 `Engine::namespace_tree/namespace_tree_at/commit_namespace` 的已发布快照发放；核心工作区内部入口同样只借用该 Engine 的已发布 State，不接收任意候选 State 或可变条目切片。发布准入先通过历史清单校验，要求规范组件键、正确 `lookup_key/name`、页内唯一键与 UTF-8 字节序及记录总数重核；查询不逐次重验或重新归一化整棵树。`get` 仅归一化查询一次并逐组件下降（索引层二分、页层二分），`get_key` 复用调用方已归一化的键；目录列页与记录总数读取同样先索引定位再读本层，不展开子树。SMB lookup、目录身份核验、工作区基线查找及下载名的首选路径复用该接口，传输与授权错误边界保持不变。

临时构建器与已发布查询视图分离：工作区编辑器以稀疏键覆盖层保存原值和最终值，按需打开受影响页、必要相邻兄弟及祖先索引，封印时只编码最终脏节点；首插／首删不再重排整个目录。全量构建仍对输入确定，但不同编辑历史不要求同逻辑树同根；对象规范编码及内容寻址不变，详见 [ADR 0011 的显式契约修订与预算](adr/0011-paged-namespace-roots-and-segmented-logs.md#page-local-editing)。`NamespaceObjects::encoding_work` 统计地址去重前的实际对象编码调用／字节，页内条目大小计算亦受已打开页范围约束；不能只数最后保留的新 hash。单点命名空间页工作为 O(路径目录数×索引深度)，事务写集驻留与触及页相关；目录移动前后实际显示前缀的字节／UTF-16／组件数均不增长时复用准入路径预算证明；任一维增长时的完整子树路径预算检查、删除事实和绝对键侧表改名仍单列 O(子树)。按文件身份寻找条目的无路径提示后备仍是提前终止的全量游走，命名空间完整校验、历史持久化仍有线性或全量成本，本次不改 SQLite 索引。以上是实现预算，不是端到端性能已通过结论。

查询回归以原 SMB 路径归一化扫描作仅测试参考，覆盖大小写、NFC/NFD、Unicode 折叠、别名、缺失、真实发布与重启后查询；损坏键、错误名称、乱序和折叠冲突须在原发布边界拒绝且保留旧状态。1k/10k/100k 合成条目测试分别计数查询归一化与实际二分键比较，验证不随每个存储条目重复 Unicode 工作；这些计数不包含字符串比较的字节成本、分配或生产锁延迟，不是吞吐实测。

文件版本树的纯图布局先用非递归强连通分量遍历识别循环，只排除同一分量内部的边；所有节点、分量间的声明边及冗余祖先连线均保留，不做传递约简。后续使用按原时间／身份顺序排名的有序就绪集合和已接纳子边索引，保留从分支尖端向祖先的最大层深、前层子节点中心分组及全部稳定次序。图遍历和就绪集合操作数随节点与边数增长，排序及有序索引仍有对数成本；临时邻接索引占 O(V+E) 内存，不是长期历史缓存。

布局单元测试以旧算法为仅测试参考，比较四节点全部 4096 种无自环有向图的完整层次与边序，并对长链、宽 DAG 和大循环计数实际遍历与就绪操作，不用耗时阈值判定性能。

连线每次测量只遍历一次实际节点边界，汇总坐标有效性、各层上下沿及全图左右沿，再按原公式生成圆角正交路径。任一已测量节点存在非有限坐标时仍不生成连线；端点缺失只跳过涉及该端点的边。路径按原父子身份有序索引，响应式属性直接查询，不再逐条扫描整组路径；尺寸变化、备注编辑或重新测量均重建本次汇总，不跨测量缓存几何数据。旧路径函数的仅测试参考逐字比较输出路径，另计数边界访问、边访问和索引查询；这些计数不包含有序映射内部比较、路径字符串生成或浏览器 DOM 布局成本。

上述优化不改变文件历史整包接口、客户端 8 MiB JSON 安全上限或全量节点／连线 DOM。纯图排序、临时邻接索引、测量、输出路径与 DOM 仍随实际图规模增长，不代表历史分页、浏览器端到端线性成本或百万节点承诺。


普通工作区提交的暂存文件命名空间段使用事务内 `NamespaceDraft`，按规范化路径建立一次 `BTreeMap` 索引。源准入包含两次线性条目遍历及索引操作，随后每个文件的冲突查找、替换和各级父目录查找使用对数级映射操作，不再逐文件扫描或 `retain` 全部条目。旧槽留空、替换项追加，结束时只展开一次；保留原有条目次序、路径别名和删除事实顺序，仍执行最终完整命名空间校验。索引与槽位是额外的事务内内存，随源条目、实际替换和新建父目录数量增长，不是分页存储或长期缓存。

1k/10k/100k 确定性测试计数实际草稿的源条目访问、映射操作、追加槽和展开槽，另覆盖共享父目录、Unicode 等价查询、别名及损坏来源拒绝；映射操作数不等于内部比较次数或运行耗时。此改进仅覆盖该命名空间段：State 克隆与历史序列化、上下文与目录选择检查、后续命名空间操作、正文及副本处理仍有成本，不能据此宣称完整提交、文件导入或整个存储系统已具备十万文件规模的吞吐与延迟保证。

另有记录级共享覆盖 State 的 `commits`、`directory_trees` 与 `versions`。克隆这些映射不复制历史记录载荷；首次写入仍共享的映射会复制全部键和记录句柄，成本随记录数增长，而非 O(1) 更新。可变访问只对仍共享的目标记录复制载荷；无需取回值的删除和批量扩展不复制被丢弃的旧记录。共享表示为每条记录增加独立分配、引用计数和读取间接访问成本；HistoryManifest 的版本映射仍保持普通有序映射。

其他 State 字段的克隆、完整历史驻留与序列化扫描成本不变，不能据此宣称整体 `State::clone` 为常数成本或历史内存有界。持久编码、规范字节和哈希保持一致；确定性克隆计数、回滚及固定发布样本验证的是隔离与编码契约，不是速度或内存实测收益。

大小 S、目标 r 份的新版本，内容写入通常约 r×S，另计工作区构建、校验和元数据。按范围上传可以减少网络量，不能减少完整版本及其指定副本的最终预算。

小文件频繁保存、持续打开的大文件和写穿透请求要分别测试。用户可选择是否启用周期检查点及其频率，界面展示空间成本；系统不通过改用其他保存方式隐藏全量保存代价。

### 有界元数据根的成本边界

[ADR 0006](adr/0006-bounded-metadata-roots.md)使 Snapshot 固定字段和 Candidate 的历史目录各持单根，新增编码按准确写集复制触及路径。路径摘要精确计算对象最大值、包路径证明和墓碑外壳预算，避免预算自身全扫 content_states 或逐个构造所有证明；恢复则必须从准确绑定图完整认证后重建摘要。

驻留描述保留键及节点，空间为 O(keys + nodes)，根 clone 为 O(1)，不缓存全部 JSON。新对象准备字节和现有完整依赖读验/安装仍占实际内存及 I/O；冷载入、`All` 写集和缺源后的精确字段重建可为 O(field)。稳定归属分支改名之外的一般 history owner closure 尚待实现。单实体、认证记录、本次 versions、成员列表和组合证明仍受实际大小上限约束。

本次没有 PublishedGraphEpoch 旧依赖免读，也没有删除 compare/fsync 屏障。应分别测新编码数、旧对象读验/安装数、峰值内存、同步次数和延迟；不得把 bounded roots、schema 通过或路径复制等同于整体 O(delta)、性能提升或物理盘验收。

### 发布元数据编码复用的局部边界

本地发布证明的预检保留每份 commit proof 原有的独立编码、大小检查和错误顺序，只编码第一份真实 `LocalPublicationRef`，用其长度减去对应 proof 长度取得共同外壳字节数；后续逐份检查共同长度与该 proof 长度的加法溢出及上限。没有硬编码字段开销、假 `null` 外壳或平均 proof；恢复仍先按健康盘位筛选，空 proof 集合不构造本地发布外壳。设共同字段编码量为 C、P 份 proof 编码量为 Lᵢ，此阶段消除的是反复编码共同字段的 P×C 项，额外保留 P 个长度值而非 P 份编码字节；不省略各 proof 的编码/哈希，也不改变组合证明的实际字节限额。

正常 PREPARE 的 Candidate，以及正常和已有发布恢复的 Publication，在原哈希位置各构造一份 `PreparedMetadataObject`，复用同一规范字节和域哈希。M 个成员的对象编码由原 `1 + 2M` 次变为 1 次，字节只保留到该轮成员安装结束；每个成员仍严格执行原位置的“对象安装 → 日志追加 → 故障边界”，不把全部对象写入提到所有日志之前。原不可变对象碰撞比对、文件/目录同步、seal/设备身份检查、commit-proof 磁盘读回、全成员发布及恢复验证均保留。这是源码复杂度与分配范围说明，不是吞吐、延迟或同步次数减少的实测结论。

回归入口为独立[冻结 R29 编码 schema](../test/engine/unit/journal/r29_local_publication.rs)、[精确预算差分](../test/engine/unit/metadata_budget/tests.rs)、[逐成员故障顺序](../test/engine/unit/engine/publication/omission_tests.rs)、[准备对象编码/碰撞](../test/engine/unit/journal/replication_tests.rs)及[降级恢复](../test/engine/unit/degraded_recovery/tests.rs)。测试源码、已执行测试和物理盘验收分别报告。

## 19.5 优化顺序

先验证完整字节、正确路由、原子发布和独立恢复，再优化范围缓存、预读、并行副本复制和后台调度。优化不能提前报告保护完成，不能省略首次写入 FULL 版本所需的完整文件封存，也不能让拆分结果继续引用另一树文件。

巡检、修复、分支首次写入及拆分任务应有进度、并发和带宽限制，可在安全阶段暂停或取消，避免后台任务持续阻塞日常 SMB 和 Web 文件操作。已进入不可撤销决定的任务继续按原操作恢复。

<a id="s19-06"></a>

## 19.6 应用看到的剩余空间

SMB 共享的容量信息只能返回保守可写预算，还受目录一级规则、份数、固定目标、配额和预留影响；不能把 n 块盘剩余容量简单相加作为共享可写空间。

共享内不同目录的路由可能不同，单个总数无法保证每个文件可写。最终保存仍执行逐文件、逐指定目标的准入检查，错误定位到对应盘位、来源和级别。

<a id="s19-07"></a>

## 19.7 容量预警与写入准入

每仓库、历史树、一级来源和备份目标分别显示当前内容、保留历史、独立分支、合并连线元数据、已清除节点、实际文件占用和计划预留。汇聚备份盘列出各来源贡献；实际残留副本单列，不计正常保护但仍计物理占用。

默认业务预算达到 80% 预警、90% 严重预警，根据最近 7 天增长估计剩余不足 30 天时提示增长风险。样本不足显示未知。这些是可配置的初始值，预测不替代实际准入。

每盘默认至少预留 10% 安全余量，并独立计算下一份检查点、未决事务及一次成员恢复所需的元数据预算，取较大要求。内容修复另有预算，不能挪用恢复控制记录所需空间。检查 Btrfs 实际可分配数据和元数据空间，不仅依赖表面空闲数字。

保存前在每个冻结目标登记空间预留，防止并行工作区共同超卖。候选阶段预留保留到结果收敛；未知长度上传逐步申请，额度不足停止接收并保留已接收数据。预估与预分配不能替代实际写入、校验和同步结果。

达到硬配额或恢复余量不足时，拒绝新增增长并暂停可取消后台任务；读取、导出和预算内必要恢复继续开放。扩容须经设备登记及来源映射检查，普通启动不自动格式化新设备。

## 19.11 文件历史候选索引与资源限制

`Engine::file_history` 保留原有完整数组和排序语义。SQLite 的 `file_history_versions` 仅提供候选版本 ID，使用 `(file_id, version_sequence_key, version_id)` 索引；序号采用 8 字节大端编码，覆盖完整 u64 范围，同序号按二进制 ID 顺序返回。返回对象始终从权威内存 State 读取，归属和业务状态仍由业务层校验，不依赖 JSON 投影建立访问能力。

候选集合的完整性由恢复后 State 生成的每文件计数校验；后续复用类型化版本差分更新计数和查询索引，不增加第二遍全版本扫描。前后版本映射仍共享同一底层分配时，因 `FileVersion` 无内部可变字段，可直接得到空差分而不遍历记录；不同分配即使内容相等也走完整比较，不依赖操作名称或人工变更清单。比较路径有序合并前后版本映射，只比较版本键、文件归属、历史域和版本序号，借用变化项 ID，不序列化实体 JSON，也不扫描其他 State 映射或事件。类型化行与投影序号在同一事务中提交；即使没有类型化行变化也必须核对并推进序号，FULL 事务成功提交后才按原健康状态和旧序号检查推进可信计数与序号。可信计数另占 O(文件身份数) 内存，不保存第二份完整 State。

引擎索引所有者持有专用 SQLite 写连接，与可信计数由同一个索引锁保护；正常 publication 复用 worker、连接设置和语句缓存，不再逐次打开/关闭。每次投影事务前释放 SQLite 未被引用的读页缓存（`PRAGMA shrink_memory`），保留 worker 和预编译语句；否则同连接已预热页可能掩盖未改变 schema cookie 的原地损坏。每次写仍核对当前路径与持有文件身份、marker 的精确 DDL 和旧序号：长期连接不是外部磁盘/其他连接不再改变 schema 的证明。WAL/FULL 提交仍是索引确认边界，关闭时的 checkpoint 不是确认条件。写连接准入时设置并读回 `SQLITE_DBCONFIG_NO_CKPT_ON_CLOSE=1`，防止随后关闭对生命周期内被替换的 WAL/SHM 名称执行隐式 checkpoint/unlink；不改变 FULL 提交和正常自动 checkpoint。正常关闭同样保留 WAL/SHM，因此不能将单独主文件视为完整数据库或离线快照；重新打开消费完整的 SQLite 文件集合。SQL 投影失败显式关闭并保持写阻塞，重建关闭旧 worker 后核验文件集合，关闭成功后才能隔离损坏文件。Engine 销毁在根写锁释放前关闭 worker；析构关闭失败只记录诊断，不把它当作成功恢复。读取仍使用独立只读限额连接，未删除首次磁盘准入或候选完整性校验。

SQLite 不再保存无生产查询消费者的通用 `entities` 镜像。启动仍从已验证的持久证据恢复 State，再事务性移除旧快照表及通用实体表或替代视图并重建当前查询投影；旧投影不能成为恢复输入。其他元数据和预览计划不要求写入 SQLite，仍按各自的 State、持久快照和本地准备文件契约读取。索引写入失败仍保持写阻塞，重开后由权威证据重建；不能把读取失败可回退解释为允许吞掉发布后的索引写入错误。

非共享映射的差分仍遍历全部版本，其他 State 字段克隆、首次写入的键与句柄复制、快照编码及恢复验证等成本也仍存在，不能据此宣称端到端 O(delta)。确定性测试区分共享映射零记录比较与独立但相等映射的完整比较；性能计数应明确区分历史候选行、序号标记与其他持久 I/O，旧通用实体行数或 JSON 字节数不能作为新索引的同口径指标。

读路径在同一 SQLite 快照中先核验三个查询对象的精确类型和 DDL，再检查投影序号、候选数、顺序及每行字段。缺行、伪造归属、损坏、数据库缺失、异常 schema 或锁竞争均回退到完整 State 扫描；失败后停用候选路径，只有从权威 State 完整重建后才恢复，普通增量写入不解除停用状态。读取连接不创建文件且只读，保持 WAL/FULL 和防御模式，忙等预算为 20 ms；连接限制单值/编码行 64 KiB、SQL 16 KiB、编译 VM 程序 10,000 操作及 16 个绑定参数。编译 VM 限额不是运行时间超时；因此必须在读取内容前拒绝替代视图。

连接与逐行校验成本会使小规模查询更慢，因此当前采用保守路径选择：总版本至少 300,000 且目标文件版本不超过 100 时才尝试 SQLite，否则直接使用原扫描。这只是内部执行策略，**不是分页、响应条数或历史保留上限**。生产候选查询最多分配 101 行（含一行超额检测）；不同环境须测量索引连接、逐行校验和扫描成本，不由 EXPLAIN 查询计划推导延迟收益。可用 `cargo test -p storage-engine --release measure_history_candidate_latency --lib -- --ignored --nocapture` 重跑合成测量。 写连接生命周期可用 `cargo test -p storage-engine --lib measure_history_writer_lifecycle -- --ignored --nocapture` 比较同一 FULL/WAL 策略下 100 次 marker 提交的逐次打开与长期持有成本；这是局部同步路径测量，不是端到端 publication 吞吐或物理掉电证明。


### HTTP spool 的资源边界

当前服务已为 `api-spool` 实现每账户/HTTP 全局累计预留和启动盘点，计入旧代际、失败上传、完成但仍保留的副本及未知文件，并为每个数据文件计入保守元数据开销。默认额度分别为 100 GiB 和 500 GiB，所在文件系统另保留 1 GiB 恢复余量；同代重试不复制正文。具体配置和取消/同步失败语义见[服务端组件](components/server.md#http-spool-budget)。

这不是跨 HTTP、引擎工作区和 SMB 的统一暂存账本。核心的 `max_workspace_bytes` 仍单独限制其目录；其他协议的句柄、公平性与全池预算见各组件的当前限制。文件长度计费不等于实际分配块数，空闲余量也不能阻止外部进程占用空间。达到上限时拒绝新数据，不通过丢弃历史、回执或未决字节来腾出额度。

`records` 与 `metadata_bytes` 的 `used`、`limit`、`remaining` 仍为十进制字符串；
任一维度达到 80% 返回 `near_limit`，达到上限返回 `exhausted`。多会话不获得额外主体额度，
`ok` 不保证下一次请求一定通过其他活动、长度、磁盘或单清单限制。

超额池仍拒绝打开写 Engine。停止服务后可运行 `zxs-rescue --root /private/pool workspace-inventory`：
不构造完整 Engine、不重放/修复、不绕过预算，逐物理清单输出有限 JSON 行，末尾完整标记才说明已枚举完。
这是未经 journal 和双镜像授权核验的诊断库存，非逻辑工作区计数；原始 canonical 字节不含生命周期预留。
命令持有原单写者锁（锁文件可能创建），不修改配置锚、清单或正文。详见[救援工具](components/rescue.md)。

64 MiB 的主体逻辑字节默认值与既有单清单读写上限一致；128 MiB 全局预算最多容纳两份
满额逻辑清单。这些是准入阈值，不是预分配缓存或实际内存占用保证。计费还包含保守的
关闭/提交上下文预留，因此并非任意原始长度小于 64 MiB 的工作区都能被接纳。
若实际清单或其生命周期预留超过单清单 64 MiB 上限，必须在持久化或发布前拒绝，
不会把预留截断到 64 MiB 来掩盖提交后的回执超限；提高总配额也不能绕过单清单格式限制。

持久基线的配置入口是未初始化草稿：由 `zxs-rescue configuration template` 生成，
在初始化前审查修改上述资源字段，再通过守护进程的本机 `--setup-config ID=/absolute/private-config.json`
预置及受保护首次初始化选择使用。配置由核心校验，文件权限和磁盘白名单仍须符合
[救援工具的草稿说明](components/rescue.md#uninitialized-configuration-drafts)。这不是 Web 在线资源配置页。
已有池的系统目录及各元数据成员均持有配置锚；不得手工改写 `config.json` 或磁盘配置锚来调额，
也不得删除清单释放名额。运行期的本机调额使用下面的显式启动参数，保留持久基线与全部证据。

<a id="runtime-retained-workspace-limits"></a>

### 本机运行期上限

`zxs` 与 `zxs-rescue` 接受同一组本机参数；四项必须同时指定，或全部省略：

| 参数 | 含义 |
| --- | --- |
| `--max-retained-workspaces` | 全池未冷存驻留记录数 |
| `--max-retained-workspaces-per-principal` | 每主体未冷存驻留记录数 |
| `--max-retained-workspace-metadata-bytes` | 全池计费元数据字节数，含生命周期预留 |
| `--max-retained-workspace-metadata-bytes-per-principal` | 每主体计费元数据字节数，含生命周期预留 |

所有值必须为正整数，且每一项不得低于实际池配置或初始化所选预设的相应基线，不是仅与程序默认值比较。
省略参数时仍使用原配置；不自动提高任何默认上限，不提供 HTTP 调额入口或进程内热更新。
参数只保存在当前 Engine 的独立运行期策略中，不写回系统 `config.json`、磁盘配置锚、初始化意图或发布证明。
`GET /api/workspaces/capacity` 显示本次进程的有效上限，当前管理员认证与既有额度保持不变。

例如，对仍采用默认基线的池，可在原有完整启动命令后追加以下参数；数值只是示例，须按实际保留量、
系统盘空间和启动内存预算选择，不代表推荐的机器容量：

```text
--max-retained-workspaces 8192 \
--max-retained-workspaces-per-principal 2048 \
--max-retained-workspace-metadata-bytes 268435456 \
--max-retained-workspace-metadata-bytes-per-principal 134217728
```

部署时将参数保留在 systemd 等主机配置中，正常停服后以完整参数重启。每次打开池、后台重试和救援恢复
都必须使用所需的上限；如果保留证据已超过持久基线，遗漏参数会使池打开以 `RESOURCE_LIMIT` 失败关闭，
但不会删除证据。守护进程的管理 HTTP 仍可用，存储保持不可用；救援命令则明确失败。提高上限不是增加写回缓存，也不减少元数据扫描、State 或保留记录的内存成本。

系统盘恢复应在第一次执行前配置足够的上限。恢复先持有原有写锁并预检保留证据，配额不足时不发布新的
`config.json`，不开始重放修复或生成索引；可以使用同一目标目录和足够的参数重试。协调目录或锁文件可能
已创建，不能把这解释为完全没有文件系统操作。通过预检后仍执行完整的权威重放、清单核对和索引重建；
其他恢复或 I/O 错误仍按既有失败处置，不保证任意失败都能无条件重试。

这只是显式、有限的准入扩容，不会改变上述冷存条件。所有元数据和未冷存记录继续计费，实际总量达到新上限后
仍会拒绝新增。活动工作区数、载荷长度、磁盘余量、单清单 64 MiB 和其他边界不因这四项参数放宽。

当前仅有普通空 Aborted 的原路径冷存，没有一般已提交或含正文证据的退休机制。
每工作区保留的 `.full`、`.prepared` 代际文件以及 `.zxs-full-*` 复制中断残留的总数还受 `max_entries` 限制，
包含零字节文件和尚未进入清单的残留代际；同一已存在代际的无新增文件重试不占新名额。
此检查复用暂存目录用量扫描，不读取文件内容，也不按每次清单变更扫描目录。
