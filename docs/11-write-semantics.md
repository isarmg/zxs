## 11.1 什么算“每次更改”

一次已封存并发布的内容变更定义为一个版本，不把每个底层 write 或 SMB WRITE 请求定义为完整历史版本。

普通应用保存可能分多次写入，也可能使用临时文件替换。工作区在封存前可以变化，已发布版本不得原地修改，历史内容清除有独立事件。每个成功版本保存完整内容，但不能在没有应用配合时精确识别每次按键或点击保存。

<a id="s11-02"></a>

## 11.2 写入工作区

```text
打开主分支或明确选定分支的文件，固定基础版本 V1
        ↓
认证会话取得该文件写入占用，建立工作文件并记录脏代际
        ↓
修改进入工作区，未变范围可暂时从 V1 读取
        ↓
保存屏障冻结本次工作代际，构建完整 V2
        ↓
沿指定一级来源和固定备份链准备全部完整副本并校验、同步
        ↓
验证基础内容与目录前置条件，原子发布一父提交和新 HEAD
        ↓
后续写入进入下一工作代际，不原地修改 V2
```

已有正文的分支可按范围读写，服务端用该分支自己的基础版本补齐未变字节；正式文件始终完整独立。尚未拥有正文的分支继承创建时冻结父版本，范围编辑保留父内容的未改字节；扩展 EOF 之外的空洞补零。完整上传替换可见内容，显式写入空文件也算首次内容保存。受控 API 的传输方式不能改变全量保存要求；Web 不提供正文上传。

显式历史编辑工作区可以固定来源版本读取旧字节，前提是来源仍可读；这是用户选择的工作视图，不能解释为分支已拥有来源正文。只有实际 staged 的最终内容才会成为新版本，未写文件仍是占位。

分支创建与内容保存分别提交。前者只登记 `pending_file_versions` 和冻结来源引用，后者首次构建真实 FULL；首次即使与来源摘要相同仍生成独立版本，只有已拥有正文的普通保存可以应用未变 no-op。历史另存只处理工作区实际 staged 的写入，未写文件保留占位，不隐式复制来源；同一路径零字节写入不等于未写入。

SMB 工作区由受控服务管理，全部基础保存固定指向主分支。从历史节点保存只由高级入口发起，并在新分支发布实际写入的 FULL 版本，不能让普通 SMB 写请求携带任意历史目标。

<a id="s11-03"></a>

## 11.3 保存边界表

| 入口或操作 | 设计行为 |
| --- | --- |
| Web 元数据保存 | 相应元数据事务发布完成后才报告最终成功；不提供正文上传 |
| 受控 HTTP API 内容提交 | 完整文件、指定副本和元数据发布完成后才报告最终成功；长任务通过原操作 ID 查询最终状态 |
| 普通 SMB WRITE | 接收至工作区；响应不能解释为新版本已完成全部保护 |
| SMB 写穿透请求 | 按已验收语义执行完整保存屏障，完成前不返回相应持久化成功 |
| SMB FLUSH | 冻结此前工作代际，完成完整版本及指定副本、元数据发布后才返回成功 |
| 最后可写句柄关闭 | 有新修改时触发保存屏障；无新修改不重复提交；失败保留服务端工作区和错误记录 |
| 临时文件替换目标 | 内容及目标保护先准备，再原子发布替换事件 |
| 受控 HTTP API 下载后写入 | 导出、本地修改、传输和服务器版本发布是分别进行的操作；本地文件由用户保留 |

以上为本系统的目标映射，须按 Samba 实际回调、客户端缓存和目标应用验证。普通 Samba 目录共享不自动具备这些版本保证。不可仅靠文件变化通知或定时扫描在事后补历史，因为这不能证明保存边界和指定副本已完成。[S03][S04]

<a id="s11-04"></a>

## 11.4 自动提交策略

在有效持久化屏障、受支持原子替换、显式保存及有修改的最终关闭阶段封存。重复 FLUSH 或关闭同一已封存代际不产生重复版本。持续打开的文件可配置检查点，但必须显示完整保存的空间和写入成本，默认不逐 WRITE 生成版本。

Web 必须处理并展示业务接口的保存错误；SMB 入口返回标准协议错误，服务端保留相应失败工作区和活动记录。Samba 进程重启不能直接清除未确认数据；Web 可查看相应任务与错误，受控业务 API 处理已有工作区；没有产品 CLI 正文传输入口，也不以 Web 状态展示暗示可以预览或下载未保存正文。

<a id="s11-05"></a>

## 11.5 已提交快照与工作视图

采用已提交快照读取和受控工作区写入语义。其他会话不在发布前看到半写字节，这与某些普通本地文件系统的原地写入可见性不同，必须用真实编辑器验证兼容性。

只读句柄在打开时固定 version_id。所属写入会话的工作视图标记 workspace-view，可读自己的未发布修改；固定旧版本的句柄不改绑。工作区缓存与不可变版本缓存隔离，不让前半文件来自 V1、后半来自 V2。

SMB 租约、oplock、目录通知和客户端缓存失效必须通过 Samba 对应契约处理。无法保证跨会话一致性的优化先关闭；不能让客户端继续用旧目录身份写入新版本，或以缓存命中绕过当前授权。

<a id="s11-06"></a>

## 11.6 原子替换与文件身份

临时文件覆盖目标时记录 replaces_file_id、旧目标版本、源身份和目标路径。普通写入、改名和移动可保留文件身份，替换的历史连续性由明确事件建立，不仅凭同名猜测。

一份保护的临时文件替换三份保护目标时，发布前必须满足目标的一级归属和全部指定副本。临时文件位于不同一级来源时，为目标创建独立完整版本，不能把临时位置算作目标第一份。失败时旧目标不半替换。

<a id="s11-07"></a>

## 11.7 第一版文件语义范围

| 能力 | 基线 |
| --- | --- |
| 普通文件、目录 | 支持 |
| 随机读取、顺序读取 | 支持固定版本读取 |
| 普通编辑器随机写、截短、追加 | 经工作区和服务端仲裁；追加不能由各客户端自行猜 EOF |
| 同一共享内改名与原子替换 | 支持并单独验收 |
| 跨仓库、独立历史树或共享改名 | 返回不支持的跨域操作，交由显式完整复制和删除 |
| 任意共享可写内存映射 | 不承诺普通本地 POSIX 语义；不支持的请求明确拒绝 |
| 硬链接、任意符号链接、设备文件、FIFO、socket 文件 | 第一版不提供 |
| Windows ADS / macOS 扩展元数据 | 只支持明确界定和有上限的能力；不丢弃后伪装成功 |
| 文件锁、共享模式和删除待定状态 | Samba 与核心统一映射，必须跨客户端生效 |
| 活跃数据库、VM 磁盘、容器可写层 | 不作为第一版支持负载；先生成应用一致的普通文件再存入 |

外部编辑器在 SMB 文件上使用本地缓存或映射，不据此推导本系统提供本地共享可写 mmap 保证。平台额外元数据选择明确侧录格式或拒绝，普通内容完整不等于全部平台属性完整。

<a id="s11-08"></a>

## 11.8 待处理写入与客户端故障

未保存工作数据不属于可随意回收的读取缓存。服务端记录操作 ID、会话、基础版本、接收范围、哈希和状态，断网或进程崩溃后按原操作恢复。网络响应未知时先查真实结果，不能新建 ID 重复提交。

Web 元数据操作没有服务器确认前不宣称保存完成；Web 不提供文件选择、上传、下载或预览。受认证 HTTP 内容 API 已接收的服务端工作数据和未知结果按原操作保留；这些接口不构成 Web 功能或日常远程 CLI。SMB 断连时同样保留已经接收的工作数据及操作状态，不以普通读取缓存回收策略清除。

<a id="s11-09"></a>

## 11.9 多文件、多句柄与多会话

工作文件以稳定身份和会话创建标识定位，不仅用可变路径。第一版同一文件的跨会话写入按文件占用及锁串行仲裁；同一工作文件多个句柄共用工作字节，追加 EOF、截短和保存代际均受控。

自动提交顺序为：

1. 选择文件 A 的脏代际并冻结，等待此前写入完成；A 后续写入等待，其他文件可继续暂存。
2. 收集使 A 可达的必要创建、父目录、移动或替换事件，不附带发布无关 B 的未保存内容；存在未封存依赖时返回 WORKSPACE_DEPENDENCY_BUSY。
3. 协调器核对 A 的基础版本、稳定身份及相关目录项。仅其他无关文件变化时，可接到最新已发布 HEAD；涉及相同文件或目录依赖变化则保留 A 并报冲突。
4. 为 A 建立完整版本及所有指定副本，按[第 10 章](10-transactions-and-recovery.md)发布。只清除 A 已提交代际，B 的基础版本和脏内容保持。
5. 结果未知时保留冻结工作文件、operation_id 及证明，恢复原操作后再继续。

A、B 从 H0 分别编辑，A 发布 H1，B 的基础及目录项未变时可形成 H1 → H2；H1 不含 B 脏内容。这是经过前置条件核对的不同文件顺序保存，不是分支合并。同一文件已变化不能自动按此规则覆盖。显式固定 HEAD 的批量计划不适用这种自动接续。

目录移动、删除或替换影响工作文件时，重新核对稳定身份和原意，不能只改 base_head。服务重启或会话失效后必须重新核对授权和全部前置条件。

<a id="s11-10"></a>

## 11.10 同步、目录与失败传播

| 操作 | 规则 |
| --- | --- |
| FLUSH / 写穿透 | 将此前所选工作代际完整发布，失败返回协议错误并保留待处理状态 |
| mkdir / 已发布条目改名、移动、删除 | 独立目录事务，成功前完成元数据保护，不保存无关脏内容 |
| 新文件创建 | 建立会话可见暂存条目，首次内容屏障发布；空文件也有明确首次提交 |
| 临时文件替换 | 冻结来源并验证目标前置条件，内容和替换事件原子发布 |
| 最后写句柄关闭 | 对未提交代际执行保存检查，结果未知不擅自清理 |
| SMB 重连与重发 | 桥接保留可恢复操作关联，按实际协议请求核对结果；新发起的复制操作不混同于原请求重试 |
| 管理 API 多文件提交 | 显式选择整批原子发布，任何项目失败不发布一半目录 |

客户端的本地 fsync、保存按钮和 SMB 网络请求不必一一对应。发行前需记录实际客户端的同步、关闭和错误反馈行为；不能仅凭回调名称声称所有应用都等待服务器完成多份保护。

<a id="s11-11"></a>

## 11.11 SMB 样机门槛与报告

P0 样机必须先锁定 Samba/桥接构建、操作系统、SMB 协商结果、客户端及编辑器版本。记录实际 CREATE/WRITE/FLUSH/CLOSE/RENAME 请求、VFS 回调、operation_id、核心决定序号和返回状态，敏感文件内容与凭据不得写入跟踪。

Samba 的 SMB2/3 FLUSH 使用异步处理。[S04] 桥接需验证异步同步回调、取消及错误回传，不在事件循环中以同步等待整份复制阻塞全部会话。关闭、写穿透和替换的实际回调路径分别跟踪；不能从 FLUSH 验证结果推导其他路径也已成立。

| 样机场景 | 必须提交的证据 | 通过条件 |
| --- | --- | --- |
| 典型编辑器保存、临时文件替换、空文件 | 请求与版本时间线、内容哈希、目标路由 | 目标原子替换；无新脏代际的重复 FLUSH 不重复建版本 |
| 1 MiB 小文件与 10 GiB 大文件局部修改 | 单次保存及多次同步的耗时、实际写字节、版本数 | 内容与保护规则均满足，P95/P99 不超过预先登记的负载目标 |
| 持续写穿透 | 每次屏障与全量保存对应关系、队列深度 | 不偷合并已承诺独立完成的屏障；成本超预算则该负载不能通过支持验收 |
| 两会话不同文件及同文件竞争 | 锁、目录通知、租约失效和句柄版本记录 | 无关文件能准备；同文件冲突明确；无跨版本混读 |
| 满盘、同步失败、关闭失败、网络丢响应 | 客户端可见错误与服务端工作区恢复记录 | 不提前返回持久化成功，重连能关联原操作且保留唯一脏数据 |
| 重启与断电 | 同步边界、磁盘证据、恢复后结果与内容 | 原 ID 收敛；不重复发布、不误删暂存、不用进程退出代替断电模型 |

发布前按[第 19.9 节](19-capacity-and-performance.md#s19-09)登记具体延迟预算和设备条件；没有预算或证据的组合标为未验证。平台未能稳定反馈关闭错误时，支持说明必须明确限制，不能将其列为完整可靠保存能力。精确 NTSTATUS 映射、回调覆盖表及原始跟踪是样机交付物，模板见[验证报告模板](templates/validation-report-template.md)。

[S04]: https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html

### 工作区清单镜像的重启恢复

工作区清单保存在系统盘和所属仓库的主数据盘。启动按工作区 ID 汇总有界候选，
不会因为其中一份 JSON 损坏就丢弃另一份健康证据，也不会按扫描顺序或最大 fence
猜测哪份清单更新。单份损坏时，剩余清单的暂存正文必须通过长度和 BLAKE3 校验；
目录身份、路径归属和恢复后的分支/历史绑定也必须成立。损坏文件保持原样，不会在
启动时覆盖或删除，提交请求回执与正文同样保留。

日志回放前的工作区记录只用于发现待修复正文；发布权限仍来自候选绑定的日志证据。
日志回放后，只有与已发布操作、请求摘要及原始 fence 相符的提交回执，才能统一
提交前后不同的工作区状态。首次保存产生的文件选择上下文变化，必须使用该操作的
原始、候选摘要绑定的发布快照重建，再与完成副本逐字段比对；不能使用后来变化的
当前选择状态。两份都损坏、内容或身份冲突、无法证明的 fence 差异，
均返回 RECOVERY_REQUIRED；不安全路径返回 UNSAFE_PATH，而非静默绕过。
清单写入任一镜像失败后，当前引擎停止接受新写入，必须重启核对已留存证据。
历史保存复用同一终态路径：Completed plan 必须来自已验证发布前缀的 State，并绑定
原 `history.historical_save` 操作、主体、完整请求摘要、源提交、工作区、封存清单与 fence。
本地 plan 文件不证明发布。成功的两份终态清单在无准备所有者和未知材料时可退出驻留配额；
原 plan、永久回执、清单字节计费及全部旧 FULL 代际保留。原操作 ID 直接重放固定结果，
不会重新执行历史保存；冷点读和恢复提示仍验证原镜像集合及完整摘要。
发布后终态镜像失败返回带原结果和具体来源的发布协调错误，不能伪装成尚未发布。
上传暂存清单若一份已推进而另一份仍是有效旧内容，且没有发布回执证明转换，重启也不会
自动选边；仍要求显式恢复，并保留两份清单和完整代际正文。重启并不保证解除全部冲突。
独立 Web 管理入口不依赖数据引擎恢复成功。
