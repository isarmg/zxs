# 鉴权已提交读快照

## 范围与决定

HTTP 登录挑战、中间件、`AuthorizedBackend` 和 managed `AdmissionEngine` 使用 `AuthReader`。
它不是一次认证永久有效的能力：每次调用取得当前已提交数据库的 `Arc`；会话读取验证到期时间、
管理员代数和会话，登录挑战仍须真实密码验证和最终发布复核；engine 锁之后的再验证同时覆盖读取与写入，不能删成“只写复核”。
嵌入式后端仍从引擎自身已恢复的受保护凭据生成准入投影。

`Mutex<AuthStore>` 保留为独立写序列及 OS 凭据锁的所有者；可变候选仅存在于该序列内。
`RwLock<Option<Arc<Database>>>` 只负责短时间读引用或替换已提交快照，锁内不做
Argon2、磁盘 I/O、JSON 编码或备份调用。读调用不获取写序列锁，也不进入阻塞任务池。
登录从同一已提交挑战区分当前管理员与未知名称的准入预算，并在锁外验证该挑战；
挑战不是会话证明，最终写序列仍检查精确用户名、代数、密码哈希及权威可用性。
密码变更或恢复期间捕获的旧挑战不能绕过最终复核，未知名称不会因稍后恢复而变为有效账户。

## 发布与失败

- 初始化、恢复读取继续严格验证当前格式、单管理员、会话数量、文件身份与权限。
- 写入仍按临时文件写入与同步、权威备份（嵌入式模式）、原子替换、目录同步的原顺序执行；
  成功后才发布只读数据库。管理模式的灾难恢复副本不是准入权威，复制失败不撤销已提交改密。
- 确定的准备繁忙不发布候选，原已提交会话仍有效。不确定备份/权威写失败仍故障关闭；
  本地名称已经发布而后续同步失败时，即使没有备份也阻止继续使用旧内存权威。
- 已开始、在线性化点取得旧快照的读可完成；注销/改密完成后才到准入点的排队读必须拒绝。
  旧 `Identity`、旧文件句柄和不可变内容都不能替代当前准入。
- 初次设置与明确恢复通过 `replace_authority` 沿用发布通道，原读者看到新权威。
  读者仅持弱引用，不会延长写者及 OS 锁的生命期；写者销毁后新读拒绝。

## 预算与限制

SHA-256 token 检查和最多 64 个会话的 BTreeMap 查询在运行时线程执行；长度检查仍先于哈希。
每次持久写发布克隆一次有硬上限的数据库，不随历史记录增长；每次读只增加 `Arc` 引用。
文件及目录同步次数没有减少。4 个密码槽、8 个会话写任务槽、来源 10 次/60 秒、每账号单飞及后端与传输
准入上限保持不变；登录键空间与已认证改密容量分离，具体上限见[登录准入](../components/server.md#反向代理登录限流)；不再由登录 fsync 阻塞纯 token 读取并耗尽其共享阻塞任务槽。
未对吞吐、尾延迟或系统级 fsync 性能作测量承诺。

回归位于 `test/server/unit/auth/snapshot_tests.rs`、`password_change_tests.rs`、
`engine_backend/revocation_tests.rs`；使用实际备份接口暂停发布，无新增业务测试 hook。
覆盖未提交登录不可见、旧会话并发读取、失败与错误来源、注销/改密生效、权威替换与销毁，
以及实际 HTTP `/api/auth/me` 在持久化期间继续响应、完成撤销后拒绝。

本地执行结果与环境限制见[本轮验证](../validation/auth-committed-snapshots.md)。
