# 快照、历史分页与增长限制

当前实现减少重复工作，不删除保留历史，也不削弱权威日志、精确候选身份，
或损坏检测/修复要求。

<a id="stable-snapshot-boundaries"></a>

## 稳定的快照边界

Snapshot、history目录和history投影现在共用确定性16路 radix，不再使用名义1/32的anchor页边界。
键文本UTF-8字节经BLAKE3后逐hex位分路，不另做Unicode规范化，索引域为 `metadata-index`，叶域为 `state-page`。
叶最多128项，多实体页最多64 KiB，不可分单实体仍受MAX_METADATA约束；值大小变化也可能触发
split/collapse，因此不能声称值更新永不改变页边界。独立完整编码与路径更新应得到相同规范根。

Snapshot和PagedHistoryRoot必须有 `format: "radix-map-roots"`，分别穷尽35/30个映射字段；
Candidate使用一个 `history_roots` 目录根。旧markerless/flat根与 `history-index` 引用明确拒绝，
保留原数据，不双读、迁移或重置运行池。marker描述布局语义，不是发行版本号。
恢复始终修复准确绑定对象，不为已决候选换用新布局的根。

每个新编码对象复用同一份规范字节计算哈希和写入副本，保留域分离摘要和实际字节限制。
业务类型仍经过字段专属序列化；OperationId使用原规范文本，generation值使用UInt64十进制字符串。
JSON Value编码继续复用整数校验、UTF-16键排序和转义规则；对象认证后仍须检查字段、页界限和路由。
此处是本次实验源码边界，不代表发布、全门禁或物理盘验收通过，完整决策见[ADR 0006](../adr/0006-bounded-metadata-roots.md)。

<a id="recovery-local-repair-reuse"></a>

## 恢复调用内的修复复用

一次恢复调用只有在全部必需副本都被安全验证/修复后，才会记住相应页面哈希。
随后重复引用这些不可变页面时，不再重复相同修复工作。
缓存最多保留 16,384 个哈希；超出限制的条目走原始完整修复路径。
缓存不跨重启保留，也绝不替代首次字节验证。

精确快照修复还取代了重放中的冗余重新序列化，避免在日志重放期间生成不受原始候选
绑定的替代根。仅在历史中使用的页面仍在修复覆盖范围内；
不安全目标和不可修复损坏仍会失败。

<a id="container-inspection-projection"></a>

## 容器检查投影

一次调用内的投影会为合并事件建立索引，并记忆化第一父节点的标签继承。
每个文件/历史的版本记录只构建一次，并在多个副本缓存间复用。
元数据优先级、显式父节点覆盖、父节点顺序、环、缺失节点及序列化字段均保持原有行为。

投影按节点记忆化祖先访问；同次调用的其他副本复用已经构建的记录。此约定不构成吞吐量或延迟保证。

<a id="paged-history-roots-and-remaining-costs"></a>

## 分页历史根与剩余成本

候选的 `history_roots` 目录绑定每个history ID到准确 `PagedHistoryRoot`。其固定映射引用可到达
`metadata-index` 和 `state-page` 对象；可移植包通过有界 `history_root_proof` 保留这一精确根身份，
而不是展平后的逻辑清单哈希。读取器验证字段集合、路由前缀、深度、重复项、对象哈希，
以及重建后的语义图。不提供针对已废弃扁平清单表示的兼容读取器。

历史与Snapshot均可逐对象从不同可信成员选择有效副本，不要求某一成员独自拥有完整闭包；
快照还必须认证独立control-auth对象，history必须认证候选绑定的完整目录。
恢复不得静默地用重新编码的根替换已经绑定的根。
格式约束见[存储格式](../08-full-storage-and-disk-format.md)。

State 的构建/克隆、受影响历史的逻辑投影、保留事件和证明/覆盖验证仍随保留状态增长。
单个页面或元数据对象有界，不代表包的对象总数、导入遍历内存或完整保存成本有界。
本实现不构成端到端 O(delta)、恒定内存操作或物理磁盘持久性保证。

## 快照编码与对象边界

events使用独立radix根，键为20位补零ordinal，完整读取验证从0连续并还原数组。缺失events、旧scalars/pages、重复或不连续键均拒绝，不迁移、不改变事件顺序。真实Append谱系只编码suffix，未知修改为All；预检与安装复用同一批冻结新对象，冲突检查仍须执行。

编码器按真实脏键及驻留的有界叶键布局点查新 State，不为编码扫描全字段或读取旧叶正文；安装阶段仍完整实读旧依赖。完整构造仍可能遍历整个字段，新编码对象字节保留到安装完成。不可变对象使用两位十六进制目录前缀；查找与清单校验拒绝旧平面对象路径，不复用、迁移或删除它们。

同步变更的 State 克隆、比较及初始工作区清单构建仍可能持有引擎互斥锁；脱锁提交的冻结阶段仅共享不可变 State，下一状态在锁外构造，见[脱锁准备的成本边界](detached-workspace-commits.md#cost-and-limits)。根已不保留全部页面/历史的平面列表；单个实体、认证对象、本次版本与成员集合、证明封装仍各有上限；分页不让证据过期，也不垃圾回收历史对象。工作区准备期间保守阻止写入，以免命名空间移动与按路径安装载荷竞争，见[写入准入](detached-write-admission.md)。

恢复检查点仍需验证日志前缀与覆盖依赖，超限或降级打开回退到完整重放，见[恢复检查点](verified-recovery-checkpoints.md)。原生夹具、CI 和内存文件系统测量不能证明物理盘独立性、断电持久性或真实设备写放大。

## 自动写集合与历史依赖闭包

当前事务在克隆下一 State 后，为每个映射开启非持久化的写集合。具名的
`insert`、`remove`、`get_mut`、`entry` 记录触及的键；同值写入也可保守地标脏。
`retain`、可变迭代及获取底层可变映射会标记整个字段。整个映射替换、失去基状态谱系、
反序列化后直接比较，以及追踪超过每字段 16,384 个键或 1 MiB 键字节时，均保守回退。
这些标记不进入 JSON、对象哈希或任何持久证据；它们依赖当前业务记录没有内部可变性。
新增 State 字段必须在事务追踪和历史依赖的穷尽分类中声明，否则不能编译。

历史失效范围按逻辑清单实际的过滤规则，从变更前后两份 State 求并集：
直接历史归属、仓库范围、版本归属、文件归属、目录历史成员及别名/选择目标分别处理。
删除、跨历史迁移、目录组合与选择重定向不能只看新归属或操作结果中的 history ID。
文件和目录反向归属目前仍各扫描一次保留版本/提交，只暂存有界的待解析脏 ID；
这不是端到端 O(delta)，也没有增加全历史内存二级索引或移除 SQLite。

只有同进程一次完整发布及 SQLite 更新都成功后，才建立私有历史基线。复用必须同时匹配
当前 State 的精确分配身份、快照、序号及配置摘要；State 即使以相同序号被替换也失效。
冷启动没有该凭据，下一次发布先完整准备；现有恢复协议不读取或相信这份内存凭据。
未变历史复用此前候选绑定的精确根，但仍重新读取并验证整个依赖图，执行原有尺寸准入、
不可变字节冲突检查以及文件/目录同步屏障。它不是“哈希存在即已持久”的缓存，
也不跳过先前目录同步失败后的补偿。全部来源缺失时可从可信 State 重建，但重建根必须
与已发布精确根相同；坏的现存副本仍由原冲突检查拒绝，不能据此覆盖。部分发布或索引失败
不会生成新基线。

未变历史不再重复全State投影和radix构造；复用图仍有读取、解码、语义准入和安装成本。
Snapshot按准确键及Append更新路径，一般history投影和State克隆仍可能全量。验证须使用独立
完整模型覆盖逐字段归属、跨域移动、空/新/删除history、谱系丢失及对象/发布失败，不由源码存在
推断已通过。幂等键、工作区和日志保留规则不变；可重建检查点不授权删除权威证据。

## 快照路径复制、准确依赖复用与预算

发布基线携带固定Snapshot descriptor及每字段的Arc MapRoot，摘要来自本次编码或完整认证的准确图。
描述保留键、节点及真实最大对象/证明长度，不保存全量JSON；根clone为O(1)，总驻留空间为O(keys + nodes)。
不再用全页引用向量或8MiB descriptor阈值决定复用。只有精确State/根/序号/配置与成功发布谱系匹配才能使用，
冷启动/失配仍完整准备，未知字段谱系为All。更新的字段由实际dirty keys驱动，generation和OperationId保留原文本规则；
control_auth独立按完整逻辑对象处理，不声称其内部增量化。

安装仍遍历准确可达闭包。未变节点从可信成员实读并验证原域哈希，将同一bytes送入不可变对象写入器；
全部成员继续检查文件类型、链接、内容碰撞及文件/目录同步。原始规范字节复用只适用于当前成功发布谱系，
重开不能凭同hash制造该凭据，新编码hash已存在也仍须完成真实compare/fsync。未启用PGE免读。

无健康来源时，当前可信State可按既有边界完整重建受影响字段，但必须与原根准确相等；这是可能O(field)的故障成本。
只读取源失败可触发该重建，visitor/安装/决定错误直接传播。按域和hash去重已完成屏障，缓存满仍验证而非漏检；
Snapshot根在所有必需映射与独立认证对象完成安装后才写入。坏的现存目标不能由重建覆盖。

正常墓碑与包预检使用驻留精确路径摘要和本次真实外壳，不全扫content_states，也不逐个生成所有proof。
墓碑摘要把版本ID和状态长度与其所在路径配对；空history目录没有成员proof。恢复重新认证准确图生成摘要，
不能相信磁盘自报统计或重新分区选择另一个根。预算本身增量不消除全旧依赖实读/安装与准备字节的内存成本。

## 后续阶段：尚未实施的边界

写集合、有界根和路径编码还不是最终的增量状态架构。一般history owner closure仍须从权威State派生，
覆盖old/new owner、引用计数和间接投影；只换容器或标记dirty history不能消除全投影。
State持久容器与事件结构、全部旧依赖I/O及元数据准备内存也是独立成本，不能用root clone O(1)代表整个事务O(delta)。
只有[ADR 0005](../adr/0005-incremental-publication-integrity.md)的完整巡检/谱系/故障门禁满足后才可启用旧依赖免读。
SQLite继续是可重建派生层，不成为owner或根身份的权威。

证据生命周期另需独立、明确的归档协议，而不是 TTL 或调高现有累计额度：

- 将活跃工作区准入与归档证据存储预算分离；终态记录通过候选绑定的分页归档根保存，
  按需读取并采用有界缓存，不能只是停止计数却仍全部常驻 RAM。
- 永久保留操作 ID、主体、原始请求摘要、原结果的绑定，以及工作区终态 fence、必要的
  manifest/原始请求/receipt 引用；旧 ID 不能重新成为可用幂等键。终态不自动意味着
  载荷或上传 generation 不再承担未决发布的恢复义务。
- 先发布并同步新的归档权威，验证全部必需成员和未决引用闭包，再回收已经可安全删除的
  staging 重物或派生物。删除及目录同步失败必须有重试补偿，不能把“路径已消失”当成功。
- 现有 SQLite、container 投影和恢复 checkpoint 不能授权退休权威证据。日志分段可以
  限制活动段及遍历内存，但若仍要求即时发现旧日志任意字节损坏，旧段仍须完整性验证；
  不得借性能优化静默推迟损坏检测。

这些后续生命周期方案尚未实施，不改变现有恢复、幂等或工作区证据保留规则；有界根格式的变更另按ADR 0006处理。


## 同归属分支值的局部图编码

当前文件分支改名等同归属的已有分支值更新消费 `branches` 的精确 key 写集。
共享的穷尽 State 字段分类保证其他历史投影输入未变化；分支自身的 key、history 和
file 身份必须稳定，新增、删除、跨归属和未知 mutation 继续完整路径。不是按
`operation.kind` 信任某个调用方，也没有每操作独立缓存。

路径 updater 复用现有 16 路 radix 规则，受影响叶的值大小变化可引起确定性拆分或收缩，
结果与独立完整 encoder 的根和对象字节相同。未变子树作为引用返回；当前发布仍展开
其准确闭包、逐成员核验字节并建立同步屏障。已被新图替代的旧路径不混入安装集合。
只有只读的旧源图读取失败时，新候选准备保留从已准入 after State 完整编码新 changed
root 的能力；不是重建一个旧 hash 的成功证明，恢复和未变历史不借此换根。后续
updater、完整语义准入、visitor、对象安装与决定错误直接传播，不进入这个读取回退。

本阶段仍完整读取和解码已绑定历史、执行 `manifest.validate()`，内存保留完整逻辑清单
及已认证对象；节点边界摘要在这次遍历后构建，而非跨发布的可信缓存。因此只缩小
本次新编码范围，不声称总 CPU、RAM、I/O 或事务成本与全部历史无关。有界Snapshot/Candidate根、驻留路径描述和精确预算已在本次C格式实现；一般owner
闭包、State容器及旧依赖免读仍是独立后续工作，不能扩大本窄路径的性能结论。
