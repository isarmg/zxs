# 快照、历史分页与增长限制

当前实现减少重复工作，不删除保留历史，也不削弱权威日志、精确候选身份，
或损坏检测/修复要求。

<a id="stable-snapshot-boundaries"></a>

## 稳定的快照边界

快照映射页在实体键上使用确定性的内容定义边界。键哈希以名义概率 1/32 选择边界，
同时保留现有每页 128 个条目的硬上限。值不参与边界选择，因此值更新不会使其他实体
跨页移动。普通插入通常只修改附近页面，而不是使后续所有按位置划分的页面发生偏移。
对抗性的键分布仍可能触及硬上限并降低共享效果；这不是恒定写入量保证。

项目只使用一种当前的、不编号的根/页面表示。通过结构检查判断分页是否合法，
不通过发布版本分支选择表示。新发布的墓碑准入使用同一个页面构建器，
已有恢复候选则使用其实际受哈希绑定的页面。
恢复修复原始根与页面，绝不为旧候选换用新布局的根。

页面构建器是迭代器，避免再创建一份完整的、克隆后的映射页面集合。
每个编码对象复用同一份规范字节计算哈希和写入副本，保留域分离摘要和字节限制。
业务类型仍经过原有字段序列化；已经解析为 JSON Value 的历史图节点，在摘要和尺寸检查中
直接借用原值编码，不再重建同一棵 JSON 树。两条路径复用整数校验、UTF-16 键排序和字符串
转义规则，域校验仍先于 JSON 校验。这不是缓存，也不省略对象摘要、页大小或路由检查。

<a id="recovery-local-repair-reuse"></a>

## 恢复调用内的修复复用

一次恢复调用只有在全部必需副本都被安全验证/修复后，才会记住相应页面哈希。
随后重复引用这些不可变页面时，不再重复相同修复工作。
缓存最多保留 16,384 个哈希；超出限制的条目走原始完整修复路径。
缓存不跨重启保留，也绝不替代首次字节验证。

精确快照修复还取代了重放中的冗余重新序列化，避免在日志重放期间生成不受原始候选
绑定的替代根。仅在历史中使用的页面仍在修复覆盖范围内；
不安全目标和不可修复损坏仍会失败。

<a id="container-inspection-projection"></a>

## 容器检查投影

一次调用内的投影会为合并事件建立索引，并记忆化第一父节点的标签继承。
每个文件/历史的版本记录只构建一次，并在多个副本缓存间复用。
元数据优先级、显式父节点覆盖、父节点顺序、环、缺失节点及序列化字段均保持原有行为。

投影按节点记忆化祖先访问；同次调用的其他副本复用已经构建的记录。此约定不构成吞吐量或延迟保证。

<a id="paged-history-roots-and-remaining-costs"></a>

## 分页历史根与剩余成本

每个候选为每段历史绑定一个 `PagedHistoryRoot`。其固定映射引用可到达域分离的
`history-index` 和 `state-page` 对象；可移植包证明保留的是这一精确根身份，
而不是展平后的逻辑清单哈希。读取器验证字段集合、路由前缀、深度、重复项、对象哈希，
以及重建后的语义图。不提供针对已废弃扁平清单表示的兼容读取器。

可以逐对象从不同的已验证成员选择历史依赖。这不适用于 State 快照：
当前快照验证要求至少一个成员拥有完整且正确的根和页面集合。
恢复不得静默地用重新编码的根替换已经绑定的根。
格式约束见[存储格式](../08-full-storage-and-disk-format.md)。

State 的构建/克隆、受影响历史的逻辑投影、保留事件和证明/覆盖验证仍随保留状态增长。
单个页面或元数据对象有界，不代表包的对象总数、导入遍历内存或完整保存成本有界。
本实现不构成端到端 O(delta)、恒定内存操作或物理磁盘持久性保证。

## 快照编码与对象边界

事件使用有序、经过验证的快照页。缺失事件、标量事件快照、重复或不连续索引、歧义表示均被拒绝，不迁移、不改变事件顺序。发布准备一次不可变快照和历史清单字节，预检与副本安装复用相同哈希和字节；冲突检查仍须执行。

编码器按页借用类型化状态条目，临时页面构建器最多缓冲 128 个顶层条目，最终编码对象保留到安装完成。不可变对象使用两位十六进制目录前缀；查找与清单校验拒绝扁平对象，不复用、迁移或删除它们。

同步变更的 State 克隆、比较及初始工作区清单构建仍可能持有引擎互斥锁；脱锁提交的冻结阶段仅共享不可变 State，下一状态在锁外构造，见[脱锁准备的成本边界](detached-workspace-commits.md#cost-and-limits)。页面引用向量、单个实体、候选根映射和证明封装各有上限；分页不让证据过期，也不垃圾回收历史对象。工作区准备期间保守阻止写入，以免命名空间移动与按路径安装载荷竞争，见[写入准入](detached-write-admission.md)。

恢复检查点仍需验证日志前缀与覆盖依赖，超限或降级打开回退到完整重放，见[恢复检查点](verified-recovery-checkpoints.md)。原生夹具、CI 和内存文件系统测量不能证明物理盘独立性、断电持久性或真实设备写放大。

## 自动写集合与历史依赖闭包

当前事务在克隆下一 State 后，为每个映射开启非持久化的写集合。具名的
`insert`、`remove`、`get_mut`、`entry` 记录触及的键；同值写入也可保守地标脏。
`retain`、可变迭代及获取底层可变映射会标记整个字段。整个映射替换、失去基状态谱系、
反序列化后直接比较，以及追踪超过每字段 16,384 个键或 1 MiB 键字节时，均保守回退。
这些标记不进入 JSON、对象哈希或任何持久证据；它们依赖当前业务记录没有内部可变性。
新增 State 字段必须在事务追踪和历史依赖的穷尽分类中声明，否则不能编译。

历史失效范围按逻辑清单实际的过滤规则，从变更前后两份 State 求并集：
直接历史归属、仓库范围、版本归属、文件归属、目录历史成员及别名/选择目标分别处理。
删除、跨历史迁移、目录组合与选择重定向不能只看新归属或操作结果中的 history ID。
文件和目录反向归属目前仍各扫描一次保留版本/提交，只暂存有界的待解析脏 ID；
这不是端到端 O(delta)，也没有增加全历史内存二级索引或移除 SQLite。

只有同进程一次完整发布及 SQLite 更新都成功后，才建立私有历史基线。复用必须同时匹配
当前 State 的精确分配身份、快照、序号及配置摘要；State 即使以相同序号被替换也失效。
冷启动没有该凭据，下一次发布先完整准备；现有恢复协议不读取或相信这份内存凭据。
未变历史复用此前候选绑定的精确根，但仍重新读取并验证整个依赖图，执行原有尺寸准入、
不可变字节冲突检查以及文件/目录同步屏障。它不是“哈希存在即已持久”的缓存，
也不跳过先前目录同步失败后的补偿。全部来源缺失时可从可信 State 重建，但重建根必须
与已发布精确根相同；坏的现存副本仍由原冲突检查拒绝，不能据此覆盖。部分发布或索引失败
不会生成新基线。

这一阶段消除了未变历史重复的全 State 过滤聚合及 radix 分页构造；复用图仍有读取、
解码、语义验证和逐对象规范编码成本，State 克隆、变更快照字段及事件的完整编码/复制尚未消除。
所有引擎发布单测以原完整历史构建器校验精确根，另覆盖逐字段归属、跨域移动、空/新/删除
历史、谱系丢失、配置/状态身份不符、对象损坏与发布阶段失败。未改变幂等键、工作区证据
或日志的保留规则；可重建检查点并不授权删除权威证据。

## 未变快照字段的精确页复用

发布基线现在也携带原快照 descriptor 和每字段的最大编码页长度，不保存页面字节。
只有当前 State 分配身份、序号、快照及配置均匹配同一次成功发布，才能使用它。
基线 descriptor 的规范编码超过 8 MiB 时只关闭这项优化，不增加准入限制，不影响原格式。
冷启动、失配和未知映射谱系仍分别回到完整快照或完整字段编码。

未变的 tracked 映射复制原页哈希序列，不重新分区或调用其业务记录序列化。
变更字段仍完整使用原编码器；sequence 和其他标量更新，events 及未追踪的 control_auth
仍正常编码。必需空映射、可省略空映射、十进制字符串计数器和 UTF-16 规范键序均不改变。

安装时逐页读取，验证 `BLAKE3("zxs:state-page\0" + 原始字节)`，然后把同一字节缓冲送入
原不可变对象写入器。这仅适用于私有成功发布凭据绑定的页：它们的哈希原本就是对
同一 canonical 字节和域前缀计算的，因此原始摘要相等证明字节未变，无需再解码成 Value。
普通语义哈希加载器可接受的非规范空白不能据此进入快路径；重启缓存也不能铸造此凭据。
每块成员盘仍检查当前文件类型、链接和字节冲突，并执行文件/目录同步。目标副本比较
按预期字节长度限界，损坏的大文件不会迫使小页面比较分配全局元数据上限的缓冲。

无健康来源时只流式重建该字段一次，逐页校对原哈希序列及最终页数，绝不换根或换分区。
visitor 对每个逻辑页面只调用一次：若中途才发现缺页，重建仍验证整个前缀，但不重复
本次调用已经成功完成的 callback；失败 callback 直接传播，不能触发回退并被吞掉。
根在所有页面完成全部成员的屏障后才安装。已有坏目标不会因重建而被覆盖。

正常发布的墓碑预算也使用确切页 visitor，仅在存在 PURGED/MIGRATED 时逐页解码
content_states，不再物化完整映射或单独选择页边界。预检重建不写磁盘；原已决候选的
精确依赖处理不变。每字段最大页长度使复用页在准备阶段仍按实际已发布大小接受或拒绝预算。

新增的复用路径只保持一个来源页缓冲，不缓存整个旧图；副本比较也限于当前页面。
这不表示整个发布恒定 RAM：State 克隆、新编码字段全部 prepared 字节的留存、事件复制、
根引用向量以及既有证明成本仍存在。它减少未变字段序列化，不跳过旧页读取、哈希或同步。

## 后续阶段：尚未实施的边界

写集合、历史闭包和未变快照字段复用仍不是最终的增量状态架构。后续在此基础上推进
类型化 `StateTxn`、合并读迭代与按页路径 copy-on-write。事务 overlay 与底层持久有序结构是两层：仅换持久容器不能消除完整
快照/证明遍历和全历史 RAM；仅叠加 BTreeMap overlay 则会把全量合并延后，或留下
无界 overlay 链。脏键驱动的页面更新仍须处理内容定义边界及 128 条硬上限造成的
边界传播，不能把普通局部更新等同于恒定最坏写入量。SQLite 继续是可重建的派生查询层。

证据生命周期另需独立、明确的归档协议，而不是 TTL 或调高现有累计额度：

- 将活跃工作区准入与归档证据存储预算分离；终态记录通过候选绑定的分页归档根保存，
  按需读取并采用有界缓存，不能只是停止计数却仍全部常驻 RAM。
- 永久保留操作 ID、主体、原始请求摘要、原结果的绑定，以及工作区终态 fence、必要的
  manifest/原始请求/receipt 引用；旧 ID 不能重新成为可用幂等键。终态不自动意味着
  载荷或上传 generation 不再承担未决发布的恢复义务。
- 先发布并同步新的归档权威，验证全部必需成员和未决引用闭包，再回收已经可安全删除的
  staging 重物或派生物。删除及目录同步失败必须有重试补偿，不能把“路径已消失”当成功。
- 现有 SQLite、container 投影和恢复 checkpoint 不能授权退休权威证据。日志分段可以
  限制活动段及遍历内存，但若仍要求即时发现旧日志任意字节损坏，旧段仍须完整性验证；
  不得借性能优化静默推迟损坏检测。

这些阶段尚未改变现有格式、恢复约定、幂等语义或工作区证据保留规则。
