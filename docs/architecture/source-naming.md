# 源码身份与来源边界

[命名规范](../NAMING.md) · [源码治理工具](../tools/rust-sources.md) · [单仓库结构](../monorepo.md)

## 三种身份

1. 活动身份：当前目录、Cargo 包名/版本、Rust crate 标识、消费者及文件摘要。名称表达职责，不附带上游发布版本。
2. 原始来源身份：原始包名/版本、`origin_directory`、归档 URL/SHA-256、逐文件摘要、许可证及版权。不能因改名或整合覆盖。
3. 互操作身份：协议字段、文件格式、系统 ABI、绑定元数据和外部符号。内部改名不授权改变这些契约。

安全扫描继续按真实上游身份匹配公告。改名不等于升级，保留的实现必须登记为合入来源，不能伪装成退役代码。集中目录不改变许可证。

## 路径与代码修改

命名、移动、整合、升级和裁剪是不同操作，普通 `refresh` 不能把目录消失或测试缺失视为已批准变更。计划必须匹配完整前序清单，验证唯一身份映射、无覆盖的仓库内目标、完整文件集合、精确摘要及必要的内容改写；拒绝逃逸、符号链接和特殊文件。

- `refresh --rename-plan`：协调包名、目录、依赖别名、特性转发、Rust 引用、宏展开、活动示例和测试所有者。可选 `file_moves` 必须构成完整文件集合的双射，不能暗中授权新增或裁剪。
- `refresh --move-plan`：在同一包内显式逐文件移动，包身份与原测试 source 标签不变。目录移动必须展开所有后代文件，未列出的文件保持原位。
- 原始来源键和旧收据保持不变，当前路径通过经过验证的映射连接。路径映射不批准任意字节变化，文本替换也不能证明没有丢失文件。
- Rust 标识按真实所属命名空间匹配，不做子串替换；`lock_api` 不能匹配 `block_api`，依赖改名不能改写 `std::time` 或其他 crate 私有模块。

分组布局下还有独立的生命周期限制，见[Foundation 维护边界](foundation-groups.md#source-maintenance-boundaries)。

## 高耦合接口

- 界面运行时、重导出和过程宏的生成路径必须一致；原生/WASM 编译与真实浏览器运行分别验证。
- `error-definition` 与派生实现精确固定相同完整版本，生成代码使用 `__derive_support`，见[错误定义](error-definition-naming.md)。
- `ring` 的 Cargo 身份、`links`、原生符号前缀与预生成汇编耦合。改变内部包名之前须明确 ABI 映射并验证原生符号，不能机械替换。
- WASM 绑定跨 Rust 宏、共享 schema、生成 JS 与工具解释器；导入/导出符号和绑定元数据必须逐项检查。
- trait、数组表示或公共类型不同的实现不能仅靠同名目录统一。实际共享密码学边界见[密码学核心](../components/cryptographic-core.md)。

## 多来源整合

已含多个上游来源的物理所有者可以作为明确审阅的后续整合输入，但每个物理根只保留一份精确当前源码/外置测试快照。每份生产文件须有路由，每份外置测试须有双射、可逆的迁移；继承来源不是额外物理副本，也不是退役身份。

schema-1 计划中，`input_consolidations[directory]` 包含：

- `receipt_id`：该所有者紧邻、尚未被消费的前序整合收据的内容寻址 ID。
- `merged_packages`：当前目录的全部精确合入来源行，保持清单顺序及共享当前文件清单。

验证要求有界无环证明图、每个前序唯一消费、来源覆盖完整且不重复、法律身份不变及精确当前输入。只有终端所有者必须存在，被消费的旧根保持不存在。外部测试授权按 `(origin, source, original source hash)` 精确匹配，保留数量与来源，不使用宽泛路径前缀。

不具备前序整合证明的旧多来源所有者、已升级输入、固定证明路由、固定基准搬迁及嵌套构建脚本退役均需要独立适配器；不能豁免来源检查。常规刷新可更新当前字节，不能重写旧收据。来源会计测试不代替行为等价性和 Rust 构建验证。

## 验证要求

变更前固定基线及已有修改；变更后运行来源验证、对应治理测试、真实消费者单元/集成/文档测试及受影响的 Linux/WASM 构建。原生 ABI、密码向量、浏览器、Samba 与部署各自验证，不以编译或历史通过结果替代。命名规则的唯一入口是[职责命名规范](../NAMING.md)。
