# 读取投影与请求内上下文

目录树读取先在引擎锁内捕获独立响应，再解锁执行序列化。响应不保留引擎引用，后续状态变化不会修改已经捕获的树。

## 实现边界

- [Tree 投影](../../src/server/src/engine_backend/read_projection.rs) 为一次请求建立来源解析上下文，而不是为每个条目重新解析分支、提交和仓库。
- [来源解析](../../src/server/src/engine_backend/wire.rs) 对已验证的规范提交使用已知条目，避免再次扫描相同的提交条目表。
- 外来条目、重复键和不规范排序继续走检查路径，保留原有首个匹配项语义，不能将“通常唯一”当作已经验证的前提。
- [文件上下文](../../src/engine/src/business/directory.rs) 复用相同的上下文构造逻辑；文件管理列表每行只解析一次上下文。
- 这些对象只在当前请求内使用，不构成跨请求的认证或业务状态缓存，也不绕过历史、分支归属或访问检查。

## 复杂度口径

[回归测试](../../test/server/unit/engine_backend/read_projection/tests.rs) 比较完整响应和参考检查路径，覆盖不同列表规模并统计重复匹配访问。已验证条目的直接路径不重复扫描提交条目表。

这不是整个响应生成为 O(N) 的声明：规范性验证仍有线性成本，映射和历史上下文可能有对数成本，响应构造及序列化仍需要处理输出数据。不规范输入的保守检查路径也不享有同样的复杂度保证。工作量计数不等于吞吐量、延迟或内存占用的实测提升。

## 保留的行为

当前与历史提交、主分支与文件分支、继承上下文、待写入内容、缺失或重复条目、冻结响应和解锁后序列化均有回归覆盖。现有 HTTP 测试继续覆盖独立文件分支、共享目录组合、移动别名以及幂等命名空间批处理。

SMB 的内部单条 lookup 在同一引擎锁内重新检查当前唯一身份、共享绑定和目标状态，只复制命中的 Entry，随后脱锁序列化；不再为 Stat/Open 往返整个 Tree 或计算全部 pending 映射。匹配仍按规范化 entry.path 线性查找首项，不假定快照有序，也不增加长期缓存。公开 Tree 接口不变，写 Open 在 workspace 创建后针对 base_head 的 Tree 查询及身份核对保持不变。

SMB 已打开的写句柄和目录句柄使用内部 `SmbAuthorizeRead` 检查当前读取准入，只返回固定的 `{"authorized":true}`，不克隆条目、不计算 pending 映射，也不生成完整 Tree。每次仍经过相同的引擎锁内身份刷新、共享启用状态、主分支及绑定代次检查，并与 Tree 共用分支／历史／仓库和当前头提交归属校验；结果不是可复用授权凭证。只读文件句柄仍按原 `Version` 路径授权其冻结版本。真实 SMB 入口使用当前唯一账户、没有 HTTP 会话令牌；带会话的内部调用仍检查会话存在、到期和凭据代次，不能把两者混为同一撤销模型。

[授权回归](../../test/server/unit/engine_backend/read_projection/authorization_tests.rs) 对照旧 Tree 元数据判定的独立参考，比较错误状态、代码、消息及优先级，并用 0 至 10k 个合成条目检查借用快照、固定响应及零次完整 Tree 投影。计数器不测量通用分配量、CPU 或实际 SMB 吞吐。该优化不增加工作区期限或写选择检查，也不改变写 Open 的基线核对、正文完整校验、私有 spool 复制和写入授权。
