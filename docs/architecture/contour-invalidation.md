# G4 轮廓的失效传播与布局批次

[界面组件](../components/interface.md) · [浏览器验收](../tools/browser-smoke.md)

本文先记录 `39fbb997` 中 `src/interface/src/contours/controller.rs` 一帧的调用链，再给出显式失效集合、读写批次与验收设计。刷新数是简化读写模型值，不是浏览器实际样式／布局刷新次数。G4 曲率、误差预算、Automatic 发现、SVG 绘制和交互监听不变；不改用原生 `corner-shape`，不要求业务标记节点，不增加旧浏览器兼容。

## 原基线（按源码调用链建模）

记号：N 为注册的 HTML 节点数，C 为本帧范围为正的候选，R 为已有记录（绘制或回退），D 为本帧 transition 策略失效的记录，K 为首次出现且声明了绘制属性过渡的候选，F 为可见前景 SVG。

控制器不是每帧无条件扫描整个 DOM：只有触发源才请求下一帧，文档遍历只在启动时进行一次，此后由 childList 发现增量维护注册表。但一旦某帧运行，它会读取全部 N 个注册节点的计算样式。

| 阶段 | 宿主调用 | 同步刷新 |
| --- | --- | ---: |
| 取出发现记录并合并注册表 | `takeRecords`、子树 `querySelectorAll("*")` | 0 |
| D 条记录的 transition 准备 | 每条：写回内联过渡 → `getComputedStyle` + 5 次读取 → 写入覆盖 | D（样式） |
| 恢复全部 R 条记录 | 内联样式与装饰子节点写入 | 0 |
| 资格判断（全部 N） | 每个节点一次 `getComputedStyle` 与范围读取；候选再读约 35 项、`getClientRects`、必要时 `getBoundingClientRect` | 1 样式 + 1 布局 |
| 其中 K 个新候选 | 循环内写入过渡覆盖，下一节点的读取再次刷新 | K（样式） |
| 绘制与提交 C 条 | 写入 | 0 |
| 前景定位 F 个 | 每个：`getScreenCTM`、`getBoundingClientRect` 后立即写 `left`/`top` | F（布局） |

每帧同步刷新约为 D + K + F + 1 个读阶段（资格判断中样式与布局各刷新一次，下文模型合计为一次）。`scroll` 事件还会在事件回调中逐个定位前景，另有 F 次布局刷新；随后仍调度完整一帧。`invalidate_transitions` 在任一作者 DOM 变更、结构变更或延迟脏标记时把全部记录设为 D。每帧对 N 个节点各新建一个 `CSSStyleDeclaration` 句柄。

触发下一帧的来源：作者 attributes／characterData 变更、childList 发现、已绘制节点的 ResizeObserver、15 种交互事件（含 `scroll`）、`transitionrun`／`animationstart`／结束与取消、配色方案媒体查询、字体 `loadingdone`、显式 `refresh`，以及仍有活动的 `--zxs-contour-extent` 过渡。

## 显式失效集合

每帧的工作由一个类型化的失效集合描述，而不是分散的布尔量：

| 触发 | 注册表 | transition 策略 | 资格判断 | 前景定位 |
| --- | --- | --- | --- | --- |
| childList 发现 | 增删子树合并 | 全部记录 | 全部注册节点 | 全部 |
| 作者属性／文本变更、绘制期间的作者写入、延迟脏标记 | — | 全部记录 | 全部注册节点 | 全部 |
| 交互事件（目标 T） | — | T 及祖先链上的记录 | 全部注册节点 | 全部；`scroll` 另在事件中立即定位 |
| 过渡／动画事件、ResizeObserver、媒体、字体、活动过渡、显式刷新 | — | 不变 | 全部注册节点 | 全部 |

资格判断保持全部注册节点。`:has()`、`:dir()`、兄弟组合器、容器查询与 `--zxs-contour-extent: inherit` 都能让没有自身事件的节点改变范围或作者绘制（见[界面组件](../components/interface.md)），不能用事件目标推导一个更小且可靠的集合。集合只把已经正确的缩小范围（transition 策略、注册表增量）显式化，并把每个阶段需要的读写分开。

## 读写批次

合并发现记录（只读 DOM 结构）并取出失效集合后执行：

1. transition 策略保留原记录顺序逐条执行（`contours::frame::TRANSITION_RECORD`）：每条完成写回作者过渡声明、读取计算后的过渡列表、写入排除绘制属性的覆盖后，才处理下一条。不按嵌套层批量恢复／读取；显式继承不是唯一依赖，兄弟组合器与 `:has()` 也能通过作者的 `[style*="transition"]` 选择器观察另一节点的覆盖。既有记录顺序不保证始终是祖先先于后代，不以重新排序冒充原行为。
2. `contours::frame::FRAME`：
   1. 写：恢复全部记录的作者绘制。
   2. 读：按文档顺序读取全部注册节点的资格、候选快照、尺寸与碎片。唯一保留的写入：首次出现且声明了绘制属性过渡的候选，仍在读取自身快照之前写入覆盖。该写入会取消正在运行的绘制属性过渡，改变该节点及后续继承节点的计算值，挪到循环外会改变读到的输入，所以 K 次刷新保持不变。
   3. 写：绘制与提交。
   4. 读：全部前景的 `getScreenCTM` 与宿主矩形；随后写全部前景的 `left`／`top`。
   5. 读：再读一次全部前景，只为位置变化的前景写入校正。前景 SVG 为 `position: fixed` 的脱离流盒，通常不影响其它盒；但若祖先有 `transform`／`filter` 等而成为其包含块，移动它可能改变滚动容器的可滚动溢出（经典滚动条出现或滚动位置被夹紧），进而移动其它宿主。这次读取能观察首轮写入造成的位移，但未证明校正写入后不会再次影响其它宿主；嵌套滚动容器仍须真实浏览器验收，不能声称一次校正已证明收敛。

transition 策略的跨节点读写顺序与基线一致；资格快照继续在所有既有记录的策略处理后读取，首次候选的循环内写入不变。按简化读步骤计，原模型 D + K + F + 1，现模型 D + 1 + K + 2·[F>0]；不宣称减少 transition 策略刷新。F=1 时前景多一次校正读取，实际收益须测量。

## 复用

- 注册表为每个节点保存一个实时计算样式句柄，在首次资格读取时取得、在离开注册表或停止时释放；每帧仍从实时句柄读取全部属性值，不缓存属性值。同文档移动也重新建立条目，故每帧 N 次句柄创建变为本帧尚无句柄的条目数，不仅是首次新增节点数。
- 几何、偏移路径、绘制图像与对象 URL 的既有缓存保持原键与上限。

## 节点移除后的清理

| 资源 | 建立 | 节点离开文档 | 控制器停止 |
| --- | --- | --- | --- |
| 注册表条目与样式句柄 | 启动遍历、childList 新增 | 发现记录合并时剔除 | 清空 |
| 绘制记录、装饰与前景子节点 | 首次为正 | 下一帧最终恢复并移除输出子节点 | 最终恢复 |
| ResizeObserver 观察 | 入选绘制 | 断开时 `unobserve` | `disconnect` |
| 活动过渡计数 | `transitionrun` | 帧末剔除未连接或跨文档目标 | 清空 |
| 对象 URL | 新绘制图像 | 非活动超过 96 个时撤销 | 全部撤销 |
| 文档、窗口、媒体、字体监听 | 启动一次 | 不按节点建立 | 全部移除 |

## 实施结果

审阅先后发现：首次候选的过渡覆盖移出资格循环会改变继承输入；transition 全量批读会改变显式继承；按祖先分层仍遗漏同层兄弟／`:has()` 对内联样式的依赖。现版本保留首次候选循环内写入，并恢复既有 transition 策略的逐记录顺序，不增加 CSS 例外表或依赖图。前景批次保留一次校正，但仍缺嵌套溢出布局的收敛证据；不能将静态审阅、主机模型或类型检查称为行为等价证明。前景读取报错时，报错前已完成的写入范围也可能与原逐条处理不同。

`test/interface/unit/contours/frame/tests.rs` 对下列确定性工作负载建模：现顺序消费控制器使用的 `TRANSITION_RECORD` 与 `FRAME` 枚举，原顺序按提交 `39fbb997` 的源码建模；初始 pending=true 是模型假设，不是每次事件必然触发布局失效的事实。刷新按读步骤计，资格判断中的样式与布局读取合计一次。该测试检查模型与公式自洽，不验证真实控制器的全部宿主调用或测量浏览器刷新；修订后的模型测试已在 GitHub 执行通过；这不扩大模型本身能证明的范围。

| 工作负载 | 原顺序刷新 | 现顺序刷新 |
| --- | ---: | ---: |
| 稳定的范围动画：R=40、F=6 | 7 | 3 |
| 单个前景：R=40、F=1 | 2 | 3 |
| 作者属性变更：D=R=40、F=6（不论嵌套） | 47 | 43 |
| 插入 40 个候选，其中 10 个声明绘制属性过渡 | 11 | 11 |
| 悬停链上 3 条相互嵌套的记录：D=3、R=40、F=6 | 10 | 6 |
| 无已绘制记录 | 1 | 1 |
| `scroll` 事件中重新定位 9 个前景 | 9 | 2 |

闭式模型：原顺序 D + K + F + 1；现顺序 D + 1 + K + 2·[F>0]。每帧 `getComputedStyle` 句柄创建由 N + D 变为本帧尚无句柄的条目数 + D。原候选报告抽出的过渡覆盖计算与原内联算法在 1,260 组输入上逐项相等，不能据此推导跨节点顺序等价。

浏览器探针改动：动画、文本更新、静默窗口与停止后的检查改以实时句柄上的属性读取判断“本帧运行过”，句柄复用另行断言少于注册节点数；同文档重排的文档顺序改以范围属性读取记录。新增 `:focus` 选择器激活与失焦恢复、隐藏后显示得到相同 SVG 绘制，以及已有 A 的内联 transition 覆盖影响兄弟 B 作者 transition 的真实 CSS 回归。前景探针按对象身份核对“全部读取 → 初次成对偏移写入 → 全部复核读取 → 变化项成对校正”，不再错误要求最后一次读取早于第一次写入；另在初次写入后注入一个真实 SVG 偏移，要求复核发现并校正实际矩形。该故障注入验证校正路径，不代表真实滚动溢出已覆盖。真实 `:hover` 须由 WebDriver 指针动作触发，不能以合成 `pointerover` 代替；字体完成由既有 fonts 场景覆盖。
