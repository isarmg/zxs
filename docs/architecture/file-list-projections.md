# 文件列表分页快照与带键行

文件表使用服务端分页与项目的 `ForSnapshot` 原语管理列表所有权、投影和行渲染。
Web 固定请求每页最多 200 项，只保留当前页，不无限追加已访问页面或累积游标栈。
采用有界分页而非隐藏全量 DOM，保留原生表格、按钮、复选框、键盘交互和现有 G4 几何。
当前 Web 不提供文件上传、下载或预览；服务端保留传输 API 不代表 Web 具备这些能力。
接口与游标语义见[API 规范](../15-api-and-errors.md)。

<a id="data-flow"></a>

## 数据流

1. 服务端先对当前目录全局过滤、排序，再分页；目录优先，名称按小写规则比较，
   同名条目采用确定性身份顺序。浏览器不对某一页再次排序或过滤，避免页间错序及漏掉
   尚未加载的搜索结果。列表仅携带目录分支摘要，不附带完整冻结子树。
   主盘列表在当前身份准入锁内捕获分页 token、目录元数据与同一发布根；直接子项的分页读取、
   过滤、排序候选选择和行投影在锁外完成。返回前再次校验当前身份；正常并发写入不否定
   已捕获的一致响应，但其旧游标在后续请求仍触发 `LISTING_CHANGED`。这不改变完整目录宽度
   的扫描成本，也不把目录分支摘要数量或所保留发布根的堆占用声明为有界。
   HTTP 复用图、活动和整树读取的并发槽、取消与工作期限；完整 JSON 编码使用现有客户端
   8 MiB 上限，超限整份拒绝，不截断列表或伪造下一页。后台 permit 延续到响应正文释放。
   备份盘仍在锁内执行原有全局路径冲突检查，本轮不将其扫描声明为可中途取消。
2. `files::Model::entries` 是当前页的不可变 `Arc<[Entry]>`。翻页或查询改变时清空旧页，
   接受响应时替换为新页；不将新页追加到旧页。`files::page` 校验页大小、总匹配数、
   快照和前后游标；不接受缺失分页信息的旧响应作为降级路径。
3. 查询输入立即废弃旧页并取消旧请求，250ms 定时器合并连续输入。定时器和读取均受
   会话、位置、请求代次约束；导航释放定时器、调用 `AbortController`，迟到的完成仍须
   通过代次检查。请求所有者释放也中止传输，但取消不证明服务端操作回滚。
4. “上一页／下一页”使用服务端提供的不透明游标，不在浏览器保存已访问页历史。
   手动刷新保留当前游标；服务端返回 `LISTING_CHANGED` 时显示目录已改变的提示，
   清空旧页并最多自动重试一次第一页。已发布修改后的目录重读从第一页开始。
5. `files::rows::Listing` 仅捕获会话代次、磁盘、目录和共享页快照。
   相等性检查对同一快照分配直接短路；无关状态通知不会克隆或遍历条目 JSON。
   真正的新分配可能需要内容比较。一个记忆化派生值按服务端顺序投影显示字段和稳定键；
   各行共享位置上下文，不捕获完整 JSON 或旧列表快照。
6. `ForSnapshot` 的键结合会话、磁盘、目录和条目 ID／逻辑路径身份。
   保留键的显示载荷通过只读信号更新；每个可变渲染字段读取该信号。
   选择、勾选和禁用状态分别响应式读取；全局通知仍可能触发本页逐行状态读取，
   本文不声称所有应用更新均为恒定时间。

硬盘根、打开硬盘与目录导航共用 `files::Model::navigate`，接收调用方持有的位置值，
不重新解析已经准入的硬盘或路径。转换只清除位置所有的页、分支、选择、历史和本地
审阅面板，并复用读取取消及代次推进；磁盘缓存与磁盘读取、发布关联、未知操作、
正在查询的操作 ID 和写入围栏均保留。会话权威与后续读取准入仍属于 action 层。
返回硬盘根保持原有隐藏目录查询／已加载标记；再次打开硬盘时清空查询并等待新页，
不借统一转换改变这一既有行为，也不新增 URL 路由或浏览器历史状态。

<a id="identity-and-event-safety"></a>

## 身份、选择与事件安全

稳定键不包含请求代次、选定版本、大小和显示名称，使同页元数据刷新能够保留行。
同一文件的不同别名保持不同逻辑路径键。移除某键后再插入时，按 `ForSnapshot`
约定创建新行；查询和翻页会主动移除旧页，因此不承诺跨查询保留行 DOM 或勾选状态。

选择、打开或勾选行之前，事件处理器按条目 ID 和路径解析当前页中的真实条目，
不使用初次渲染捕获的 JSON。即使新快照先于行信号刷新到达，也只能取得当前数据。
移除条目以及会话、磁盘、目录改变后的旧事件均被拒绝。表头全选同样校验条目仍属于
当前页；“全选”只作用于本页最多 200 项，不表示选择所有搜索结果或未加载条目。
翻页、搜索和目录导航清除勾选及当前条目选择，防止工具栏作用于已隐藏条目。

刷新详情时不能用“条目不在当前页”推断删除。列表请求可同时携带
`selected_path` 和 `selected_entry_id`，服务端在同一目录快照中独立于查询和页边界
返回 `selected_entry`。浏览器核对精确身份和路径，仅在所选对象仍与发起请求时一致时
更新详情；权威 `null` 才清除旧选择并返回列表，缺失或不匹配的响应视为契约错误。
同路径重新创建的对象不会被自动接纳为原条目；旧路径改名或移除后也不猜测其它别名。
文件历史通过其身份和逻辑路径读取自己的有界窗口（[ADR 0009](../adr/0009-bounded-file-history-windows.md)），绑定精确历史根而非目录快照；目录分页游标与历史游标不可互换。

生产列表替换由 `files/actions/browse.rs` 的导航、查询、翻页及响应接收统一处理，
没有原地修改列表。写时复制回归测试保证未来使用 `Arc::make_mut` 时仍能识别快照变化。

<a id="validation-and-limits"></a>

## 验证与限制

`test/web/unit/files/rows/tests.rs` 覆盖记忆化投影、原样保留服务端顺序、查询不会触发
本地过滤、页替换释放旧快照、别名／位置／会话键、载荷刷新和事件时身份解析。
计数器仅统计投影轮次及条目数，不代表耗时、分配量或浏览器帧时间。
分页解析、精确详情身份、查询重置及请求路径编码另由 `files/page`、`model` 和
`actions/browse` 单元测试覆盖。

`test/interface/unit/for_snapshot/tests.rs` 检查真实注册表的信号身份、重排、移除和载荷发布。
浏览器冒烟的 `file_rows` 场景检查复选框操作保留节点与焦点，而服务端查询重置本页选择、
保留搜索输入焦点。`file_pagination` 在真实 WASM／DOM 中注入明确标注的 205 项分页响应，
检查 DOM 上限、前后页替换、查询请求、快照失效重启、实际请求中止信号及故意迟到响应的隔离。
该场景不是 205 项真实引擎导入，更不是十万文件端到端或服务器排序的证明。

原生单元测试和构建不能替代浏览器执行；浏览器场景只有在真实浏览器套件成功运行后才能
记为通过。浏览器启动受环境权限限制时应记录阻塞，不以原生成功代替。此方案限制的是
当前页响应、客户端驻留条目和行 DOM 数量，不宣称整个存储引擎的内存、遍历成本或
所有历史／分支接口已与目录总规模无关，也没有浏览器帧时间或内存基准结论。
