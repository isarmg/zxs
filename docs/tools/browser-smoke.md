# 真实浏览器冒烟测试

独立 Rust 工具，直接调用本机 ChromeDriver 的 W3C WebDriver / Chrome DevTools 协议；不引入 Python、Node 或业务 JavaScript，加载真实生产 Web/WASM，不替换页面资源。业务写入使用真实临时服务；下文明确说明的生命周期、分页及宽历史场景会暂缓或构造限定的读取响应，不把合成夹具当作引擎正确性或规模性能证据。少量浏览器端脚本观察错误、已渲染内容和 computed style；独立键盘焦点与绘制回归还临时注入并移除一条装饰故障 CSS，验证真实轮廓控制器的降级行为。

文件行鼠标验收的设备是 headless Chrome 的桌面鼠标，而非触控手机；320px 等尺寸只改变 CSS 视口。启动时用 Blink 的 `primaryHoverType=2,availableHoverTypes=2,primaryPointerType=4,availablePointerTypes=4` 声明鼠标能力，避免无物理输入设备的 CI 被识别成无指针。数值来自 [Chromium 指针枚举](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/public/mojom/webpreferences/web_preferences.mojom)，同样的 headless 设置也用于 [Playwright 的 Chromium 启动器](https://github.com/microsoft/playwright/blob/main/packages/playwright-core/src/server/chromium/chromium.ts)。每次文件行检查仍读取真实 `matchMedia`、实际命中、原生鼠标触发的 `:hover` 和最终 opacity，再执行原有 G4 几何与截图像素断言；不强制伪类、不改产品 CSS 或放宽视觉阈值。诊断分别记录 primary/any 指针与 hover 媒体、触控点数，并在清理前保存失败现场。

## 依赖与运行

需要 Linux、项目固定 Rust 工具链、匹配的官方 Chrome / ChromeDriver、PATH 中的 `kill`。Chrome 保持默认沙箱，不添加 `--no-sandbox`。GitHub Ubuntu runner 使用已安装的匹配版本；其他环境从官方 Chrome for Testing 下载同版本浏览器与驱动。浏览器或驱动缺失、沙箱禁止启动、页面加载失败均返回非零，不跳过测试。

先按 [Web 界面构建说明](../components/web.md#web-build)构建真实 `build/web`，并构建 CLI：

```sh
cargo build --locked --offline -p storage-server -p storage-rescue
export CHROME_BIN="$(command -v google-chrome)"
export CHROMEDRIVER="$(command -v chromedriver)"
cargo run --locked --offline -p browser-smoke -- \
  --cli-bin "$PWD/target/native/debug/zxs" --web-dir "$PWD/build/web"
```

`CHROME_BIN` 可省略，ChromeDriver 会自动发现浏览器；`CHROMEDRIVER` 默认为 PATH 中的 `chromedriver`。这些变量接受可执行文件完整路径，不接受命令参数。Cargo 单测只验证测试工具自身，不能替代上面的浏览器命令。

## 验收范围

1. 用随机临时密码创建独立三目录开发池，启动真实 ZXS 服务；浏览器登录后必须看到三个磁盘目录。
2. 启动服务前，由 browser-smoke 内部直接调用真实存储引擎，在 P01 的 `browser-fixtures` 命名空间写入同一 UTF-8 文件的两个真实版本。浏览器进入该目录，验证文件行、勾选、搜索、DOM 与焦点保持，不通过已移除的上传入口或 CLI put/get 造数据。夹具只接受工具自己持有的临时目录，拒绝已有仓库；关闭再重新打开引擎后核对两个版本和当前字节。初始化由测试夹具直接调用引擎和认证库；产品 `zxs` 仅作为直接守护进程启动，不调用 `init` 或 `serve` 子命令，测试工具不随产品归档发布。
3. 打开文件详情与版本树，确认两个真实版本；仅在历史 GET 响应中追加 12 个明确标记的合成分叉节点，使桌面视口中的树能够横向滚动。通过原位输入向真实服务提交文件备注，等待真实目录响应的 `selected_entry.note` 和历史刷新，核对树、画布、节点及备注操作控件仍为原 DOM 对象，树的横向滚动位置保持不变。成功或失败均恢复原始 fetch；随后离开并重新打开详情，用未替换的服务响应验证已持久化备注和两个真实版本。合成宽树不写入引擎，也不证明真实大历史的服务端行为。
4. 在操作历史中确认该文件出现。文件页及详情页均断言没有上传、下载、预览、“写入当前分支”、文件输入或传输任务页；网络日志拒绝任何文件正文及写会话请求。元数据 API 与 SMB 协议未改变；普通 CLI 文件传输不是测试前提。
5. 注销并刷新，仍然必须呈现匿名登录页；检查未捕获异常、JavaScript 严重错误、意外 HTTP 错误以及登录、磁盘、历史、注销和 WASM 的成功网络响应。
6. 打开管理员状态页确认真实监测控件仍可用；用真实主题按钮切换明暗模式，并检查普通明暗主题下的键盘焦点：账户密码输入接受 WebDriver Tab 后必须具有可见焦点环；历史筛选的真实 Select 必须完成绘制并可见。普通模式下临时注入 inset shadow，使真实控制器进入不支持装饰的方形 fallback，仍必须可见。注入规则和主题在结束或失败后恢复；不伪造组件状态、API 或轮廓标记。
7. 在真实 WASM 发布启动就绪事件的同一调用栈中注入 `pagehide` 或启动失败事件，验证非缓存离开和失败会同步卸载真实节点、清除 owner 的轮询定时器；缓存离开则保留节点和定时器，并继续完成真实会话恢复。定时器观察器原样调用浏览器原生方法，不替换响应或响应式状态。每次移除注入器，最后再次验证正常导航与刷新。此项覆盖资源释放契约，不声称测量全部堆内存或真实 bfcache 命中率。
8. 暂缓真实 `/api/auth/me` 原始 Response 的交付，在已挂载应用卸载后释放同一个 Response，验证迟到的会话恢复不会访问已释放 owner、重新挂载页面或遗留轮询定时器。原始状态码、响应头和正文保持不变；成功或失败均释放等待并移除注入器。
9. 仅替换目录 GET 响应，构造 205 项分页数据及一次快照失效，验证真实 WASM/DOM 的 200 行上限、前后页替换、本页全选、跨页查询请求、搜索焦点和快照重启；暂缓后故意交付已中止的合成响应，核对新查询与离开目录后的页面不会被旧结果覆盖。成功或失败均释放等待并恢复原始 fetch，最后重新加载真实目录。此项不验证引擎分页排序、快照或规模性能；真实文件行的勾选焦点及服务查询重置另由第 2 项覆盖。
10. 独立 `browser-directory-history` 仓库先写入嵌套文件、手动初始化独立子仓库并提交，再进行两次真实写入及明确提交；两个子目录分支共用已提交 head。父仓库独立初始化后明确暂存子仓库引用并提交，保留可选择的真实预览分支。浏览器先注入一次未请求却返回 `preview=true` 的非法磁盘根列表，要求 `INVALID_DIRECTORY_PAGE` 且不安装任何文件行，再关闭该错误并显式刷新；随后通过真实分支选择器进入父目录只读预览，打开子目录详情。成功路径的列表、节点、分支和父边响应原样交付，核对实际 SVG 连线、共享已提交 head、分支定位及刷新保留原图，再从非当前历史节点明确浏览不可变快照，验证不能直接设为默认或提交，全程无业务写请求；只有刷新响应的交付时机被暂缓。该流程修正了把磁盘根响应伪装成预览而被请求／响应契约正确拒绝的旧夹具，生产预览准入检查保持严格。新增源码及夹具单测不是实际 Chrome 通过证据，执行结果以对应 CI 为准。

11. 命名夹具的仓库初始未初始化。真实浏览器明确点击初始化，核对唯一 POST 绑定当前命名空间头；编辑提交说明不发布，129 UTF-8 字节拒绝提交，合法说明只有明确提交才发布。初始化与提交均双击验证单请求围栏，提交绑定真实工作树和字符串 index generation，永久回执后才显示无待提交更改。观察器只记录真实请求与响应，不替换服务器结果。

12. `browser-directory-git` 的持久夹具保留已提交父仓库、仍归父所有的普通目录、已有用户提交但工作内容变更的独立孩子、尚无用户提交的独立孩子。浏览器先用最新代数明确暂存已提交孩子的旧 HEAD，再确认父边界；两步之间仍禁止父提交，重审也不能丢失刚固定的引用。父提交不得提交孩子工作内容或为未出生孩子创建 HEAD。进入普通目录不能自动初始化；进入已初始化孩子并明确提交后，父仍保持旧引用且无自身待提交变化，直到再次明确暂存和提交。六个写请求均核对完整请求体、准确树／代数及单请求双击围栏，读取不写入；观察器拒绝旧 `/directory-scopes`、`/directory-select` 与目录列表 `entry` 查询。独立原生夹具测试核对旧快照正文、新工作正文和冷重开，不能代替真实浏览器运行。

所有数据放在权限受限的临时目录，密码只经 0600 临时文件初始化、不进入命令行。ZXS 仅监听 127.0.0.1；驱动仅允许本机连接。服务、驱动与 Chrome 在同一测试进程生命周期内创建，并通过独立进程组在正常结束和失败时清理；不会修改用户的浏览器配置、现有池或真实磁盘。浏览器配置由 ChromeDriver 为新会话临时创建。失败会输出服务和驱动日志，并将诊断写入 `artifacts/browser-smoke/diagnostics`；临时数据自动删除。

主 CI 以 `browser-failure-diagnostics-${{ github.sha }}` artifact 保留上述失败现场 7 天，包括已脱敏的页面、DOM、控制台、网络摘要及实际截图。保留步骤总是尝试执行，缺文件不代表浏览器通过，也不会把失败构建标记为已验收安装候选。

Select 的自动化定位绑定 combobox 的真实 `aria-controls`，再经当前 listbox 下唯一 `.zxs-select-options` 滚动层定位可用选项，仍要求完整标签相等；不把选项当作 listbox 的直接子节点，不全页面模糊匹配。通知生命周期从已提交且干净的独立目录仓库创建分支，遵守手动 Git 初始化边界。

Select 快滚压力检查使用状态页真实的五个范围选项，将测试视口设为 980×180，让产品自己的定位和滚动布局产生溢出。原 260px 高度在 Chrome 中仅有 8px 溢出，不能作为充分的快滚夹具。观察器仍要求至少 24px 自然溢出、可信原生 wheel/scroll、运动中的多帧及双向移动，并保留原有边框几何与颜色检查；不修改产品样式、插入选项或降低阈值。8px、23px 拒绝与 24px 准入由工具单测覆盖，但单测不代表真实浏览器验收。

这是小范围贯通测试，不等同于生产磁盘、真实 Samba或完整 UI 回归验收。CI 的 browser-smoke job 必须执行真实浏览器命令，不能将工具编译或单测当作 E2E 通过。

## 浏览器异常与轮询错误反馈

`test/tools/browser-smoke/runner/error_feedback.rs`／`.js` 在真实生产 WASM 上注入原生 `Error`、`TypeError`、`DOMException`、字符串拒绝及响应流读取失败，核对实际名称和消息到达错误中心。测试只手动触发目标请求已经登记的 120 秒 deadline callback，不修改产品超时值；同 controller 的原始 abort reason 被识别为超时，竞态中的无关异常或 `undefined` 拒绝不被误判，新导航主动取消保持静默。启动能力夹具另覆盖 controller／reason 缺失、忽略传入 reason 与不报告 aborted，要求挂载前明确拒绝并在移除注入后正常重载。所有 fetch／timer 包装均在结束或失败后恢复。

同一夹具先通过真实文件备注写入取得成功 HTTP 响应，再丢失该响应并抛出 `AbortError`；随后仅构造原操作查询的 503 失败，核对草稿和写入围栏保留、重复查询只有一条错误提示且 `request_id` 更新、关闭后再次失败可重现。释放故障后由真实原操作 GET 回执完成恢复，断言没有重发写入，最后通过真实操作清空夹具备注。此项验证浏览器异常、反馈和原操作恢复，不是网络／CSP 实际故障、真实 120 秒计时精度或服务端故障恢复证明。原生 Web 单测另覆盖不同操作／资源／会话身份、五条上限、401、稳定关闭与轮询终态。

## 会话隔离与退出重试

管理刷新另通过 `admin_read_queue.js` 观察真实 GET，暂缓原始磁盘列表正文流，核对持有正文期间没有后续管理 fetch、峰值为 1，释放后全部八种刷新路由完成。状态码、headers 和正文原样转发，不为真实 429 增加白名单。

`management_queue_lifecycle` 先真实退出并重新登录，以免语言重载后的 cookie 恢复或前次刷新影响请求归属。夹具透明观察原生 Request 的构造；生产构造 Request 到注册 120 秒 timer 之间没有 await，据此把 timer 绑定到准确 URL、方法和原 AbortSignal。仅触发明确已构造、尚未 fetch 的 readmission GET 的回调，要求它被中止而活跃发现请求不变。此项执行真实超时回调，不等待 120 秒，也不声称计时精度。随后在旧响应 headers 交给 Rust 前暂缓读取，真实退出使旧等待项失效，新登录的管理读取先排队再释放旧 401。新 Bearer 必须非空、不同于旧登录并在后续请求中保留；只在内存比较布尔结果，不保存凭据，成功 cookie 不能掩盖 Bearer 被清空。

最后只对一次发现请求构造原生 429，保留真实服务使用的 `RESOURCE_LIMIT_EXCEEDED`、详情、请求标识和 retryable 字段；页面必须保留错误且只尝试一次，显式刷新才发第二次真实读取并成功。所有 fetch、Request、timer 包装在失败或结束时恢复。host 观测器单测由正式 `browser-smoke` 的 `admin_language_tests` 执行 Node 脚本，覆盖字节与 headers、重叠正向控制、body 失败／取消、清理、准确 timer 归属和旧请求／缺失 Bearer 负例。host 测试、Rust metadata 和源码接线不代替当前候选的真实 Chrome 运行，实际结果见[管理读取排队验证](../validation/management-read-queue-20261106.md)。

暂缓真实文件历史的原始成功 Response：有效会话继续后必须显示两版本树；注销完成后才释放的旧响应不得恢复私有文件详情。原始响应正文、状态码和头不变，不注入应用状态。另一个夹具仅中断首次退出传输，验证等待及失败阶段新建目录和文件备注控件禁止新操作、没有业务写请求；显式重试必须真正注销，重新登录恢复元数据写入准入。成功或失败均释放响应及恢复 fetch。

## 字体故障与非阻塞启动

发布样式检查使用真实 CSSOM 和 resource timing 的资源名称，要求仅加载 `styles/startup.css` 与 `zxs.css`，bundle 内没有 `CSSImportRule`，两个原字体字重和三个 data SVG 图标声明存在。随后仅阻断主 CSS 的网络请求，验证独立启动样式仍使失败提示可见、主应用隐藏、系统字体和重试按钮可用；移除阻断后点击真实重试按钮并重新检查。该观察不将 timing 字段用作 RTT／性能或下载字节结论，既有字体及 G4 验收仍独立执行。

## 版本树帧与生命周期

`test/tools/browser-smoke/runner/tree_frames.rs` 在既有文件备注测试的宽树 fixture 中执行；文件选择、导航、备注保存、会话和请求仍走真实 UI。宽树沿用该测试明确标注的 12 个合成分支叶子，并非后端分支持久化证明。

- `test/tools/browser-smoke/runner/tree_frames.js` 在 WASM 加载前包装宿主 RAF/RO/MO；只把**首个观察目标为版本树 canvas** 的 observer 关联到该组件。G4 的全局 observer 不属于该组件。measure 的证据是 canvas 上精确的 `.zxs-version-node[data-version-id]` 查询，不是全局 `getBoundingClientRect` 计数。
- 先设置窄视口并稳定布局，再点击真实版本备注编辑按钮。输入框和字节计数第二行必须让被观察节点实际增高，且同时收到原生 MO 和该节点的 RO 通知；单纯 viewport resize 不能保证 max-content 画布或达到宽度上限的节点发生 resize。记录原生／人工 delivery 独立计数、目标尺寸、通知尺寸及 pending RAF，超时打印这些诊断。显式暂停组件 RAF，然后对挂载中的两个真实 observer closure 重复 delivery；同一个 JS turn 的八次通知必须不测量、只保留一个 RAF。在原生 RAF turn 中释放它，必须恰好测量一次；检查编辑状态连线后通过真实 Escape 取消，要求原节点高度恢复，再检查最终几何，不提交合成节点 ID。重复 delivery 是测试刺激，不声称自然浏览器必然产生八批通知。
- 通过真实 Files 导航销毁 owner，断言 pending RAF 已取消、两个 observer 已断开。再人为递交已取消的**RAF** callback，断言没有树测量或未捕获错误；不调用已销毁的 observer closure。
- 真实重挂载断言新 canvas、首次测量发生于 observer 注册前、初始 tip 居中；后续测量不得抢用户滚动位置。窄屏、重挂载和桌面恢复均等待实际 `document.fonts.ready` 与渲染帧，然后核对节点宽度/G4 extent/字体、页面溢出、箭头端点/线型及采样路径不穿节点。

文件行小数滚动分成两项独立验收：DPR2 下对 0.5、1.5、7.5 的滚动请求记录浏览器实际值，允许浏览器自身量化，但产品 CSS 偏移必须始终与原生值相差小于 0.01 CSS px；随后仅将真实列表面板临时设为 CSS `zoom: 2`，再次请求同组偏移，必须实际读到非整数原生值并满足同一同步阈值。浏览器的量化与缩放关系见 [WPT 原生滚动测试](https://github.com/web-platform-tests/wpt/blob/master/css/cssom-view/scroll-offsets-fractional-zoom.html)；DPR 不是一定产生小数的保证。不替换 scrollLeft getter、不合成 scroll 事件、不跳过小数断言。共享几何探针以 `currentCSSZoom` 将 CSS 长度换算为真实视口坐标，保持 0.5px 几何阈值；不会把取整的 clientWidth 误当缩放后的精确宽度。每个样本在恢复 zoom 前保存请求值、实际值、CSS 偏移、DPR、zoom 与几何 JSON，成功或失败都还原面板原有 zoom 值及优先级。

文件搜索验收使用产品的原生 search input 与真实 WASM：点击外框左、中、右位置必须聚焦同一输入；空值提示可见、输入后提示隐藏且读屏名称不变。真实键盘录入后观察超过旧 250ms 防抖窗口，列表、勾选和请求数必须保持；组词确认／长按 Enter 的合成 guard 用例单独标明，不代替实际输入法硬件验收。提交使用 WebDriver 真实 Enter，查询即时替换列表并保留焦点。205 项夹具另断言编辑期间翻页仍使用已提交条件、键盘清空与原生 × 分别观察 350ms 后请求数及原列表不变、空草稿 Enter 恢复第一页、目录切换清除草稿，以及已有的中止与迟到响应围栏。外观探针仍在明暗主题及四种文件页视口执行，不排除搜索输入，也不移除功能来满足样式检查。这些验收必须由真实 Chrome 执行后才能记为通过，源码与模型不能替代浏览器证据。

原生 × 用例通过 Chrome DevTools 读取目标输入的真实 user-agent shadow `search-clear` 控件及边界，再发送实际指针按下／抬起；找不到原生控件或点击后输入未清空都明确失败，不用脚本改 value 冒充原生清空。350ms 请求计数从每种清空动作之前记录，独立覆盖旧 250ms 延迟窗口。
控件身份依据 Chromium 的 [shadow 元素名称](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/html/shadow/shadow_element_names.json5)及[原生清空实现](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/html/forms/text_control_inner_elements.cc)，不是页面自建按钮。


## 主盘规则对象入口

正常冒烟最后追加独立真实主盘验收；`--placement-only` 只运行这组验收，不代表整个冒烟通过。它仍启动实际 Chrome、生产 WASM 和真实临时守护进程，不接受外部用户池路径。夹具另建 P01→B01→C01、P02→B02 两条备份链，不改变既有三盘冒烟夹具。运行方式：

```sh
cargo run --locked --offline -p browser-smoke -- \
  --cli-bin "$PWD/target/native/debug/zxs" --web-dir "$PWD/build/web" --placement-only
```

- 通过仓库当前目录和文件夹详情打开“主盘规则”，检查真实仓库/目录身份与 nullable rule ID、UInt64 字符串代数自动进入请求，界面没有手填 ID/代数输入框。使用显示的实际主盘路径选择 P02。
- 第二个真实 HTTP 会话先更新同一规则；陈旧浏览器保存得到真实 `409 CONFIG_CONFLICT`，保持编辑器并重读实际新代数。成功保存后只丢失原始响应递交，再暂缓原操作结果的原始 Response；保存和关闭均锁定，原生重复点击不发第二次写入，释放查询后完成原操作。
- protected 目录实际要求两份但未配置 B02 前缀。读模型返回 `missing_backup_prefixes`，真实选择器禁选；独立真实 PUT 得到 `400 BACKUP_PREFIX_REQUIRED`，错误目录身份得到 `409 SCOPE_CHANGED`，配置不变。真实目录分支只读预览与备份盘禁写，匿名 PUT 为 401。
- 暂缓原始 GET 后关闭编辑器，以及退出后重新登录并打开另一个目录，再释放旧 Response；旧响应不能恢复已关闭或旧会话编辑器。没有伪造业务响应、状态码或应用私有状态。
- 停止测试守护进程后，以真实引擎验证旧版本记录、物理位置、校验后字节和独立备份策略均不变，再提交唯一一个新版本。新版本必须仅放到 P02。重启真实守护进程后，浏览器历史树必须仍包含两个旧版本和一个新版本；Web 全程不得调用文件正文接口。

成功运行生成 `artifacts/browser-smoke/placement/evidence.json`、`future-placement.png` 与 `preserved-history.png`，包含真实对象基线、响应与图中版本；不保存令牌、Cookie、密码或认证请求。失败保留独立诊断，所有临时响应包装均清理。新增测试源码、编译成功或单测成功不能替代此真实浏览器命令的执行结果。

文件搜索外围焦点复用共享 G4 paint 模式，正常主题不再用原生矩形 outline。文件页 320、390、980、1440 四种宽度、明暗主题、空／非空草稿均执行真实鼠标聚焦、空白处点击失焦、Shift+Tab 离开和 Tab 返回。鼠标聚焦、中立失焦及键盘返回保存 Chrome 页面截图与像素 JSON；Shift+Tab 离开单独保存原始截图、实际前一按钮／搜索框坐标和焦点状态 JSON。截图观察器同时检查四边焦点色、3px 间隙、四角外侧页面底色和弯曲处焦点像素；离开后必须回到 clip 模式，四边外环采样点恢复页面底色，四个角部采样区域也不得残留焦点色，外框宽高不能改变。它读取合成后的页面 PNG，不以 G4 源图或 computed style 代替实际显示；旧直角外环、隐藏焦点、缺失角部和失焦四边／孤立角部残环的模型反例接入原像素观察器测试。

搜索焦点弯角检查使用截图实际像素中心，在每角宽度为 2 CSS px 的对角区域内逐像素检查，范围止于半个圆角跨度，避免碰到文字或光标。每角独立要求至少两个不同像素、横纵坐标均有变化，原色差阈值保持每通道不超过 4；不再以半像素步长重复统计单个像素，也不要求恰好位于同一条对角线。JSON 保留各角命中坐标、检查数量、frame/clip 几何和尺度依据，以区分实际缺角与栅格化相位。模型覆盖对角线上只有抗锯齿颜色而旁边存在原色像素、非整数位置、单像素／直线伪证、只有抗锯齿的缺色、暗色独立配色及失焦孤立残角。真实亮暗、四视口、鼠标和键盘流程不变。

中立失焦使用 WebDriver 真实鼠标点击主内容区左侧内边距，先按实时搜索高度计算坐标，再用 `elementFromPoint` 确认命中的确是没有激活处理的 main 本身；点击后必须由 main 持有焦点且不显示键盘焦点环。Shift+Tab 则必须把焦点移到搜索框前一启用按钮，搜索框退出焦点并恢复 clip，随后真实 Tab 返回输入。两条验收分开，防止相邻按钮合法的 2px outline 与 2px offset 伸入搜索截图而被误认为搜索残环；不隐藏按钮焦点、不裁掉检查区域、不放宽失焦四角零残留门槛。各阶段同时核对 URL、目录面包屑、输入草稿和已记录的文件／仓库请求数量未变，避免点击意外激活导航或提交。

## 自动发现与接纳向导

`runner/management.rs` 的独立首次设置夹具使用固定 `--storage-discovery-root`。检查旧自由路径、挂载与浏览控件不存在；GET 自动发现返回真实空目录证明。候选位于树的 -1 层且没有伪备份边，打开与返回向导不写盘；暂存后须显式勾选确认才能首次激活。提交前核对空目录仍为空且无配置与激活意图；成功后登记为独立 D01 主盘，而不是把选择顺序当成备份链。原成功响应丢失、重复提交抑制、状态核对及服务器证明的中断激活继续场景保留。`runner/management/conversion.rs` 继续在该临时活动池中创建普通源和另一个空目标，经真实预检核对新一级角色、字节与根位置，确认预检不写入。明确确认后连续两次真实按钮点击只能产生一次提交；必须收到原 import operation 的永久发布回执、完成 UI 和新一级树节点，目标退出 -1 层，文件列表出现原文件名，源字节不变。Web 状态机单测与服务端事务测试不能代替实际浏览器执行。

共享输入观察器要求单行高度为 36px、静止与焦点底边均为零，原生焦点为可见内收 2px outline；搜索仍由外围 G4 反馈。多行输入只要求不少于基准高度，不强行压为一行。模型测试覆盖旧 44px 输入、下划线、缺失或透明焦点环等拒绝样本；真实浏览器仍需执行同一最终提交。

## 外来历史审核：独立可访问性与失败恢复场景

`--foreign-review-only` 是独立、显式选择的验收模式，不改变 CLI 默认 Chrome 冒烟链，也不能与 `--placement-only`、截图或轮廓模式组合。使用同一真实 CLI、生产 Web/WASM 与默认 Chrome 沙箱；调用方法是给上面的命令追加此参数。该模式要求已包含外来审核向导的 Web 资产，旧 Web 包缺少控件时直接失败。

CI 的单 ELF 验收步骤显式设置 `ZXS_SMOKE_FOREIGN_REVIEW=1`。`release-acceptance.sh` 先完整执行原有场景，再以同一私有目录中的最终发行 ELF、内嵌 Web 和 Debian 13 容器单独调用此模式；截图参数只传给第一次调用。不重复构建产品或 Web，不减少原场景，不改变工作流并发。开关未设置或为 `0` 时只执行原场景，其他值（包括空值）明确失败；Release 工作流不设置此开关，验收范围保持不变。任一次调用失败都让步骤失败，不生成已验收安装候选。

CI 总是尝试保留 `foreign-review-browser-${{ github.sha }}` artifact，内容来自 `artifacts/browser-smoke/foreign-review/`，保留 7 天。若前序场景或启动失败而未生成证据，缺文件警告不代表本场景通过。脚本测试使用假的 Cargo 进程核对调用顺序、同一 ELF 字节、参数隔离、失败传播与清理；它们没有运行 Chrome，也不能作为真实浏览器验收。

夹具 `runner/foreign_review/fixture.rs` 只在工具拥有的私有临时目录创建运行池，不接受用户数据盘。真实三级来源保存两个原一级的历史：第一份具有本地完整正文，第二份保留历史但本地正文暂不可用。目标是已登记一级盘的 `Reviewed` 空目录，同盘另有 `untouched.txt`，因此不能误把整盘当空目录。真实引擎冷开后再固定源快照；源和目标快照包含目录、文件字节、权限与 device/inode，能识别新增空目录或同字节替换对象。

浏览器场景只调用现有来源检查和四个审核接口：plan preview、save、status、revalidate。保存只授权系统盘不可变审核记录。新版执行意图、数据复制、盘位接纳、迁入发布均不在此场景；三级转二级与新一级仍是本地草稿，未选一级不会猜测身份，界面不得生成服务端审核或执行请求。场景验证真实多来源映射、暂不可用正文计数、原生 label 和 aria-pressed、明确的 plan-only 确认、原生 Space/Tab/Enter 与可见焦点；执行按钮必须是禁用的原生 button。

`delivery.js` 只克隆实际 Request/Response 供观察，原请求参数和响应字节保持不变。只有真实保存已返回成功后才故意丢弃该次交付；随后核对未知结果告警、SPA 页面往返后的原 ID/完整请求、重复点击只产生一次重试、实际状态查询及真实只读重验。另一个已认证临时 HTTP 会话在 Reviewed 外真实发布新目录，推进目标检查点（仅打开工作区不会推进已发布检查点），下一次重验必须收到服务端过期拒绝并撤下旧的“刚才匹配”状态。该真实写入属于夹具外部参与者，源仍不变，目标除该参与者外不得产生审核副作用。无执行请求或伪造完成回执。

成功/失败都恢复本探针拥有的 fetch 并释放挂起的原响应，不覆盖其他探针所有权。成功后在 `artifacts/browser-smoke/foreign-review/` 保存实际审核网络证据、可访问性观察与原始 PNG；不保存认证头、令牌或密码。

`cargo test -p browser-smoke` 包含真实磁盘夹具测试、回包观察器主机模型和可访问性断言模型。模型用于验证检查器的正反条件，不代表真实 DOM、键盘或读屏验收。新场景还未经过真实 Chrome；本地沙箱限制不允许使用 `--no-sandbox` 绕过。完整页面重载及会话结束后的自动恢复尚未实现，也不由 SPA 往返测试代替。逐来源输入必须明确关联同组的原来源、精确历史身份和真实暂不可用正文计数；仅存在任意有效 ID 或可见段落不算通过。确认、保存、重试、查询及重验控件须关联当前向导内的原操作与审核范围，缺失、跨组、重复、空白或已卸载描述均拒绝。主机模型分别覆盖这些反例；这不宣称已完成读屏可用性或全 WCAG 审计。
