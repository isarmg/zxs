# 辅助工具：已存在管理员的离线密码重置

基于 `aa6c3824`，本片增加独立 Web 的真实管理员密码重置，不是首次账户创建、首批磁盘初始化或 Samba 改密。**仅新增生产源码与测试源码，没有编译、测试、审查、CI 或真实主机操作。**

## 使用范围与权限

独立 `zxs-helper` 仍是手动 root 二进制、默认 `0.0.0.0:9040`、无认证、明文 HTTP、无自启。任何网络可达者都可能重置管理员密码，必须在可信隔离网络中临时使用。来源/CSRF/IP Host 不等于登录或加密，不修改防火墙。

新增 POST `/api/credentials/reset-preview`、`/api/credentials/reset-recover-preview` 与 `/api/credentials/reset`，只操作固定 `/zxs/data/management/management-auth.json`。输入本机非 root 服务账户，持有当前 daemon 使用的 `/zxs` 生命周期租约，以及实际管理凭据的 `auth.lock`，直到工作与文件持有者全部退出。`/zxs/data`、`state`、`management` 必须准确属于该 UID/GID、0700，真实当前管理权威 marker 必须完整、单链接、0600、相同所有者；根或凭据缺失、格式/权限/身份错误均拒绝，**不创建管理员、补写权威 marker、修复权限或读取 Engine 灾备副本**。

原有主服务继续使用 owner-only 的目录入口；通用 AuthStore 新的已准入目录入口接收平台已有 `PrivateDirectory` 能力，格式、原子发布、凭据锁和会话撤销共用。root 选择、固定路径、计划确认、秘密输入和持久重试流程全部在 `helper/`，没有把辅助专用工作流塞进主服务。

旧二进制、Samba 和任意第三方写者不因此全部受控。操作者明确确认已停相关外部写者，这个复选框不是 OS 锁证明。工具不执行 stop/start，也不接入服务管理器；当前 daemon 或凭据写者正持锁时直接拒绝，不先读快照再等待。

## 确认与秘密输入

预览返回真实管理员、当前代数和准确计划摘要，绑定系统/管理目录及权威 marker 身份、服务账户源和完整凭据状态的域分离 fingerprint。fingerprint 不包含明文密码、密码 verifier 或会话 token，不是认证能力。预览持有真实锁，缺少 auth.lock 时底层可创建保持服务 UID/GID 的私有锁文件；这不是“绝对零写入”的文件检查。

用户在密码框手动输入并重复新密码，明确确认仅重置所示已有管理员及撤销全部 ZXS 会话。只通过 POST JSON 提交，不提供密码 URL、CLI 参数或命令行回显；表单无带名密码字段，脚本失效不把密码放进默认 GET。请求/持久候选类型没有 Debug 或公开响应序列化。密码字段在接收时进入清零的 `SecretString`；私有序列化缓冲用 `SecretBytes`。提交立即清空输入框，完成/失败/离开页面也清空，不写 localStorage、sessionStorage、日志、回执或错误文本。

密码采用当前 ZXS 统一校验及 Argon2 verifier，没有旁路默认密码。Web 解码错误不回传可能引用输入的 parser 细节；操作错误只返回受控顶层说明，不展开私有 verifier 诊断链。能唯一取得的 HTTP 缓冲会清零，但不声称能擦除浏览器/网络栈/库中的所有副本。明文 HTTP 本身仍会暴露给不可信网络，不能用内存清零掩盖这个风险。

## 原请求与失败恢复

1. 确认字面量、密码重复、密码规则和 64 位小写摘要先准入，再打开固定系统目录。预览后的任何凭据代数/会话、身份或源文件变化都会令新提交摘要不匹配。
2. 通用凭据层生成仅含新 verifier 的类型化替换：准确前状态 fingerprint、同一管理员、代数恰好加一、会话清空。准备不改变现有密码。
3. 写入 root 所有 0700 的 `/zxs/.zxs-helper-admin-reset-<摘要>/reset.json`，文件 0600，保存原计划和受保护替换材料，**不保存新密码明文**。意图先于实际凭据替换持久化；原 helper 目录 no-clobber/pending 协议保持。
4. 仅原准确状态允许原子替换主凭据，复用 AuthStore 文件 fsync/rename/目录屏障和不确定结果围栏。若磁盘已经恰好等于该替换，重新核验并同步，不再增加代数。
5. 再写 `/zxs/.zxs-helper-admin-reset-complete-<摘要>/receipt.json`。回执只包含管理员、代数、请求摘要和范围标志，不含 verifier 或会话。

非零结果可能已经改密，不能据此断言旧密码仍然有效。保留原计划、摘要、意图和 staging，只重新输入**同一个新密码**与原请求进行续作；现有私有 verifier 验证它是否相同，不重新生成不同 salt 或覆盖原操作。完整 pending 中已有原记录可以继续目录发布；截断、未知 staging/额外文件、双名称、换目录、不同密码或随后发生的新凭据状态均拒绝并保留。已重置之后若又产生新会话或更高代数，旧操作不会擦除它们；恢复不把旧快照强写回来。

页面可保存不含密码的原请求信息。刷新或重启 helper 后，可输入原摘要读取恢复预览：只允许原状态或恰好已发布的原替换，不返回私有 verifier；必须再次手动输入原新密码并确认才会续作。更高代数/后来的新会话明确拒绝原恢复。

本片没有自动删除操作记录、TTL、备份回滚或失效操作猜测清理。完成后代数递增且所有旧 ZXS token 被撤销；密码更换本身不会“重建系统”。

## 明确未完成与工作量

- **不更改 Samba passdb/SMB 密码**；它与 ZXS 管理员是两种持久操作。
- 不更新 Engine 的灾难恢复凭据副本，回执始终 `disaster_recovery_replica_updated=false`。系统管理凭据仍是唯一主权威，普通重启不允许旧灾备覆盖它。将来显式灾难恢复须知道副本可能过时，不能宣称本次 reset 已传播到所有恢复材料。
- 不初始化管理员/磁盘/三范围数据库，不开启 ZXS，不承诺完整 clean-start 交接；现有尚未迁入的安全入口继续保留。
- 不自动加载/启用 systemd 或 Samba，不配置 VFS、运行目录或 OS 依赖，也不把已有配置文件安装记为一条龙完成。

一个 Web 工作 owner 承担本次有界请求、凭据哈希及同步，不在异步执行线程哈希，不因浏览器断开提前释放租约。单管理文件仍受 4 MiB / 64 会话限制，私有 reset 记录受 64 KiB 限制；固定数量账户/目录身份重核。新增持久意图和完成屏障是真实恢复成本，不以“少 fsync”删掉。测试源码覆盖相同操作复核、会话撤销、新状态拒绝、非 management 拒绝、记录中无明文、请求/目录边界，但未运行，不代表真实 root 主机或网络验收。
