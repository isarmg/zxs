# 节点退役原请求的文本备份与受限恢复

接续 [浏览器原请求恢复](node-retirement-browser-recovery.md) 和 [按已发布原收据恢复](node-retirement-receipt-recovery.md)。服务端结果仍未知时，仅有一个原 operation_id 不足以重建准确请求。本片允许操作者提前私下保存原请求文本，随后在相同站点与账号补回本机恢复入口。**本片只新增源码及七项未运行用例，未审查、编译、格式化、测试、浏览器或 CI；没有真实盘操作。**

## 明确导出，不自动分享

每条已保留原操作可展开“备份这条准确原请求”，再明确读取并显示备份文本。显示前重新读取本账号有界队列，要求原记录连同模式和显示标签仍完全一致。不存在、损坏或已变化时拒绝生成，先由操作者重新读取原队列，不以旧控件转向别的操作。

文本为严格 `file-node-retirement-transfer` 对象，含当前浏览器规范 HTTP(S) origin 与完整原恢复 Record。origin 包含 scheme、host 和实际非默认 port，不含页面路径、查询参数或认证凭据；文件标签、账号、稳定身份与原版本等仍属应私下保存的元数据。只提供只读 textarea 供操作者手动复制，不写剪贴板、不下载正文、不上传、不发给第三方，不增加 Web 文件上传入口。

导出不删除或消费本机记录。没有保存正文、密码、认证/CSRF 令牌、发布或清理结论，也不是操作收据、签名证明或物理持久备份保证。备份文本可被外部编辑，因此不能被用作新权限来源。

## 同源、同账号、准确原意图

恢复面板先只解析/显示粘贴文本。严格拒绝重复字段、未知字段、未知格式、位置数组、畸形身份、空/无序/重复选择及越界文本。原 origin 和 principal 必须逐字等于当前浏览器规范 origin 与当前登录主体，不支持改域、改端口、换账号、重新签发 operation_id 或自行调整版本。不能通过编辑文本绕过来源约束。

操作者核对原站点、账号、op/file/root、恢复模式和全部版本后，明确点击“仅补存准确原请求并打开恢复入口”。这一步只写入并读回本浏览器原记录，再接既有只读原回执查询与原操作面板。没有 POST、没有清理、没有自动确认未知重发，也不从导入内容恢复旧成功或正文缺失观察。

- 原请求模式仍以 Unknown/uncertain 重新打开，未知重发必须在原操作面板重新明确确认准确选择，沿用原 ID；服务器原根、完整共享图/引用、权限、租约及幂等决定仍最终裁决。
- resume-only 模式原样保留，未核到准确发布仍只能查询，不得导入后变成可重发原删除。
- 本机已有同 op/主体/file/root/versions 且同模式时复用原记录，保留本机原标签；异内容、损坏、模式冲突、配额不足均保留原数据并拒绝。不以导入替换、降级或清除其他未解决操作。
- 本会话若已持有该 ID 的 Published/Degraded/Rejected 终态观察，则不准凭它为新粘贴内容授信。使用已存在的原恢复记录，或通过已发布收据入口重新取得准确服务器请求；导入不会重置或覆盖原终态观察。

旧会话、旧输入代数或未决变更中的控件不能补存；编辑或清空输入、会话变化会清掉预览。保存时再次确认当前 origin。导入后每一条队列的 receipt 仍与原文件、原根和全部版本匹配。

## 预算与未完成边界

单份文本最多 68 KiB，其中原恢复 Record 仍最多 64 KiB、标签 4 KiB、origin 2 KiB。复用每账号 32 条/站点扫描 4,096 键上限，导出仅在明确点击时重读队列；没有轮询磁盘或复制服务端整库。单次只展示一个输入候选，每条已保留操作可以显式生成一份有界文本。独立 localStorage 键不是跨标签页事务；发生变化时保留材料、明确重读。

备份文本不解决丢失前未导出、站点/账号永久不可用、原服务端决定丢失、外部篡改、旧盘防复活、D/namespace 共同终止或全记录物理擦除。普通删除仍软删可撤销，各 file_id 独立；共享关系拆分条件未改变。七项源码用例覆盖往返无成功权威、跨源/账号拒绝、严格 JSON、预算和选择、resume-only 保留、同 ID 终态不授信、旧控件无存储/I/O；未运行任何验证。
