# 离线 worker 失败的原始观察

本片对应 H02/H05 的进程恢复诊断，不改变请求、应答字段、持久计划、摘要或回执。
它不把失败的 worker 退出码解释为原存储操作尚未发生。

同程序降权 worker 的 spawn、请求写入、响应读取、超长响应排空和 wait 分别保存
明确阶段及原始 `io::Error`。权限拒绝、根缺席、断管和超时仍是各自原因，不归为盘损坏。
wait、原请求写入、读取和排空的既有失败优先顺序不变；失败仍由外层既有恢复策略处理。

全部 stdout 仍按原额度读取，并在超额后无额外无界分配地排空；必须真实 join 后才判定
响应。非零退出或信号终止保存实际退出状态，成功退出但超额独立报告资源边界。
即使 stdout 看似成功也不能掩盖失败退出；任何错误都不自动重放或清理原意图。

领域应答 `Reply::Failed.message` 仍只含原顶层诊断，尤其首存储初始化可能经过凭据灾备
材料，不能把 source 链、子进程 stderr 或私有 JSON 片段透传。JSON 解码失败的原有
受限诊断也保留。只对不含子进程输出的宿主传输系统调用保存准确 source。

新增回归源码验证每个 I/O 阶段及原 ErrorKind、非零/信号退出和成功超额的区别。
本轮未编译、未运行测试/构建、未查询 CI；真实 IPC、目录替换、停服 lease、原操作冷恢复
与实际权限故障仍须在集成后定向验证，不能据此关闭 H02/H05。
