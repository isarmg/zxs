# 文件容器删除与恢复记录：真实来源读取

## 范围

本片把现有永久收据中的删除、撤销删除和“导入已删除状态”接到文件详情页。
这是只读生命周期记录切片，不是完整操作时间线，也不把移动、改名、标签变化重建为新事件。
不修改内容节点、不建立占位版本，不改变标签归属、持久格式、原永久收据或现存用户数据。

事件锚点是 `operation_id`。`deletion_id` 只关联同一次删除事实；删除和恢复可共用这个
关联 ID，但保持各自操作身份。复制保留的事件保留原操作 ID 和记录序号，目标删除 ID
按既有复制规则映射。界面卡片 ID 同时含 file ID 和 operation ID，不把它当版本或写目标。

## 真实数据流

`GET /api/file-manager/files/{file}/history/lifecycle` 使用独立
`storage_contract::file_lifecycle::{Request, Page, Event, Action, Cursor}`。
它经过已有认证提取器及有界历史读取槽，EngineBackend 在当前凭据持锁检查后捕获只读状态，
锁外读取，再持锁复验凭据、当前历史根和观察状态序号。响应编码继续持有读取许可。

Engine 从 `state_projection::lifecycles::LifecycleSource` 获取目标文件的永久收据成员，
经 `file_deletion::retained::events_from_source` 的完整准入链读取事实。
来源扫描复用 FILE 数据库投影的原收据归属分类，而不重建版本、提交、目录等无关成员索引。
原 `events` 消费者仍返回完整记录，两入口共享准入和事件收集核心，新读取只累积小摘要。
专用来源和借用视图保留文件 ID 类型，不把局部成员集合冒充完整 `DerivedOwners`。
普通 MetadataView 仍不携带永久操作；专用私有快照只额外持有读取所需收据和主体表，不对外返回。
响应不包含原删除的路径、作者或完整分支前沿。

完整审计包含原文件自己的永久删除/恢复事件，以及 retained copy、保留移动等既有收据中
已经捕获的扁平来源前缀，不追逐当前可变源文件。旧 graph-only copy 缺少这份审计证明时，
此读取返回 `PublicationInvalid`，不把未知前缀显示成“没有记录”。当前 D 缺少对应永久事件
也返回错误。原 FILE 消费者和既有磁盘数据不因此升级、删除或重写。

只有 Delete 的原 D `created_at` 是该事件可用的 Unix 整秒时间。Undo 和 Import 没有独立时间，
固定返回 `null`，界面显示“时间未记录”，不借用旧 D 时间、顺序号或浏览器时钟。
可表示的时间显示原 UTC；超出日历表示范围时保留精确 Unix 秒，不丢弃合法事件。
Import 是独立动作，不伪造一对恢复/删除。记录按保留序号分页，不宣称跨来源时钟顺序。

## 身份、分页与失效

请求必须提供当前 `history_root`。可选 repository/path 成对解析，沿用现有真实历史上下文解析；
保留历史可不提供当前路径，显式失效旧路径不因该接口放宽。游标绑定 file、root、实际上下文、
请求位置、页大小、观察状态序号，以及最后一项的 operation ID 和 sequence。
服务端必须在完整来源中找到完全相同的锚点；响应准入拒绝重复操作、逆序、返祖、越界序号、
跨身份页、缺失可空时间字段和错误下一页锚点。

历史图根本身不证明永久操作表。本片保守地在任意发布使 State.sequence 变化后拒绝继续旧页，
哪怕发布属于其他历史域，需从第一页刷新。它不是旧根租约，浏览不取得写权限。

Web 使用真实详情消费者，目标包含会话 epoch、目录导航 generation、完整已准入 Entry、
file/root 和解析上下文。网络返回先处理原会话的失效，再核当前目标和面板 generation。
换目标、关闭或卸载中止请求并隔离迟到完成；重复点击不产生并发同页请求。每页替换前页，
不无限累积成一个看似完整的时间轴。读取错误保留原错误，不呈现空成功或末页，也不改变内容历史、
选择、标签编辑器或其他写依据。

## 成本与容量

- 每次请求 1–64 条摘要，界面固定 16 条；编码响应上限 64 KiB。
- 既有审计准入最多 65,536 个事件，复制封套最大 12 MiB；响应不带 D 前沿。
- **分页只约束返回量，不保证 O(page size) 的读取成本。** 每页仍扫描全部永久收据，
  只保存目标文件的删除/恢复及复制成员 ID；两类无归属坏收据在全局保留拒绝语义。
  完整来源前缀准入后才取页，事件集合只保留摘要，单收据或复制封套仍完整解码。
- 收据之间和事件循环内检查取消；取消返回错误，不发布部分来源或部分页。
  单个收据的归属数组遍历和完整封套解码仍只能前后取消。上述两个来源上限不等于整项请求
  CPU/内存的统一上限，也不构成低延迟取消或大规模性能保证。
- 复用既有有界读取槽，不增加后台全量预取，不写缓存/清单/日志。

这次成本收口不修改 DTO、永久收据、State/FILE/备份格式、复制/导入事实或写入流程。
原 `ProjectionSnapshot` 仍用于 FILE、备份、历史复制和 object move，保留其完整成员及
调用内移动收据解码复用。HTTP 凭据锁、当前根/上下文、全局观察序号和 Web 迟到响应门不变。
它不修改持久删除事实或精确撤销模型。[删除图脱钩](shared-file-history.md#删除事实与内容图脱钩)
另行移除内容图中的 D 节点与边；保留的删除记录不再解释为图节点。改名和合并仍需独立收口，
不能据此宣称“仅正文变更创建节点”已经全面完成。
