## 本片消除的可确定重复工作

`ScopeEncodingMemo::Session` 为同一捕获保存了尚未提交的纯编码，但原先
`metadata`、`system` 和 `disk_pair` 只查询全局已提交项。
因此同一会话内相同输入再次出现时，先前已认证的纯编码存在于 `pending`，
调用者仍重做编码。原生前缀包含多次引用及重复投影时会经过此路径；
其实际运行次数和总成本仍待完整用例测量。

现在先查询**本会话自己的**待提交项，再查询已提交项：

- 键仍包含完整上下文、完整输入摘要和编码种类，不以长度、文件名或最终 State
  替代历史输入。不同目标上下文、不同历史和 SYSTEM／DISK 种类不会合并。
- canonical 命中仍由 journal 对新读回的完整原始字节、domain 和本次预期摘要
  重新认证。摘要键仅为查找提示，同长度内容或查找碰撞不能替代真实输入。
- 其它会话、只读 committed reader 和并发事务看不到 pending；失败或取消仍释放
  整个会话的预算，不向全局发布。返回的 SQLite 字节仍是独立拥有的副本。
- 没有删除目标原生归档／正文／三范围库／原成员／物理根／取消的读回或校验；
  既有完整 readback、最后绑定检查及显式 commit 顺序不变。
- 共享 32 MiB／256 项预算不变。容量不足或关闭 memo 仍执行原编码，不拒绝操作。

新增测试源码覆盖同会话 SYSTEM／DISK 对重用、返回值变更隔离、不同会话隔离、
丢弃回滚、canonical 原始字节／domain／预期摘要和人为查找碰撞。
这些是纯编码接口的行为用例，不代表物理切换、SMB 或冷恢复已经通过。

## 同一完整验证内的原生归档计算

后续切片处理原有 `Transaction` 内另一处可确定重复：完整 registry verification
为所有目标共用一个 transaction，但 `archive()` 只查询全局 committed 项，不看
该 transaction 已完整验证、尚待最终门禁的 transcript。因此冷态多目标验证会在
全局提交前重复计算相同原前缀，即使本次已经保留了完整读序列。

现在仅本 transaction 的后续读取可以取得自己的 pending transcript。原生 reader
仍先比较完整 manifest 原字节，再对**当前目标**执行每次原顺序 object／journal
读取、完整内容相等比较、预算与取消检查；第一次差异带实际新字节进入原验证器。
不能只以 manifest 摘要、长度、路径、相同报告或健康同伴替代当前目标材料。
外层真实根／writer／原请求以及最后投影与取消检查都保留。不同 transaction 和
committed-only reader 看不到 pending；晚失败时整笔释放，最终成功前不发布到共享表。

同一 pending key 不重复预留归档容量；人为 key 碰撞也只能退回完整验证，不能
替换原证明。查找扫描受现有 256 项预算约束，32 MiB 账户不变，不保存 State、根句柄
或 writer authority。新增真实临时归档的测试源码覆盖同事务重用、同长度内容损坏、
取消、回滚、独立事务隔离，以及不同 manifest 原字节被故意放到同一查找键时的完整
读验和准确字节预算。没有运行这些用例，没有新的时长／根因结论。

## 本次 scope 投影的摘要与完整登记

热观察原先在生成每个目标的预期 SQLite 字节时已算过 BLAKE3，但生成目标报告、
原盘／SYSTEM 共同清单和各轮本地清单时又对同一内存镜像重复哈希。现在令每个
不可变预期镜像同时持有自身字节、完整 scope 及摘要／长度。只在这个镜像的生命期内
借用描述，再次读取目标或重新生成的镜像不会继承上一次的观察。清单字段、插入顺序、
规范化编码和原回执不变；最多仍是 81 库／128 MiB。

按磁盘 ID 拼出的既有路径只找候选，返回 current/history 对前还分别检查 pool、slot、
disk ID、binding generation 和 scope 种类。目标报告取自身原目标，不再接收外部身份标签。
SYSTEM 与原盘的实际读回、每个目标的全部文件比较、每次重新捕获及最后命名根检查
都留在原处。测试源码比较原描述的准确字节、同路径不同完整身份／角色的拒绝与原材料
未替换。这是消除确定的重复内存哈希，不是新的根因或 900 秒内完成的运行证据。
