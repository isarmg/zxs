# 独立来源候选：发现范围与只读请求生命周期

本次审查基于 `b120463214a32b59ce1d26a867036b65c5782026`。这里只推进真实候选结果的进程内回传顺序，不启动发现服务，不修改现有 HTTP、Web、登记、恢复、权限或目录布局。实验模型的完整范围与唯一候选分支仍未接入产品。

## 当前发现入口能证明什么

现行 `server/storage_directories.rs` 的 `discover_disks` 在配置的发现父目录内只读枚举直接子项，并使用安全目录句柄、挂载身份与结束复核。管理层从当时的配置取得排除根和停止根。返回结构保留截断、非 UTF-8 跳过数，以及不可访问或不支持的候选状态。这些约束应保留，不能因希望得到唯一对应而删除。

但它不能直接产生独立盘来源匹配的“完整发现”证明：

1. `browse_observed` 最多扫描 4096 项、返回 200 项，会跳过非 UTF-8 名称、非目录项和受保护根。`truncated == false` 与 `skipped_non_utf8 == 0` 只描述这次枚举，没有声明哪些排除项属于唯一性判断的范围。
2. 不可访问和不支持的目录不能当作已证明不匹配。它们可能尚未取得完整身份，不能在计算匹配数量时悄悄消失。
3. 当前 `classify_candidate` 调用 `recognize_disk` 读取现行 seal/本地配置，不是独立格式的完整元数据 verifier。现行登记四元组及角色证据不能替代独立格式的 Origin、incarnation、role 与全部 publication pin，也不能直接构造已核验的 `IndependentDisk`。
4. `verify_current` 会重新读取 mountinfo 并比较被观察目录及其挂载身份，但不是所有目录与所有候选元数据的全局原子快照。最后一次复核以后仍可发生拔盘、挂载变化或 publication 推进。
5. 返回的 `DiscoveredDisks` DTO 没有拥有者、发现请求、挂载命名空间、完整范围定义、排除策略版本或连续事件证明。它是传输值，不是私有构造的完整发现回执。

对应源码：`src/server/src/storage_directories.rs::{browse_observed,discover_disks,classify_candidate,verify_current}`、`src/server/src/management/discovery.rs::discovery_scope`、`src/engine/src/disk/discovery.rs::recognize_disk`、`src/contract/src/storage_directories.rs::DiscoveredDisks`。这是对上述基线的源码审查，不是这些服务的本轮运行验收。

## 完整性证据的可行边界

任何未来的完整性回执都必须首先限定范围和时间语义，不能表示“所有可能的物理磁盘”。至少需要：

- 由服务拥有的范围定义：哪个已持有发现根、挂载命名空间、直接子项规则、允许格式、排除策略及其版本。已登记或停用根被排除时，结论只能适用于这个明确排除后的范围。
- 每个被枚举项都有明确结果，记录所有截断、跳过、错误和物理关系无法证明的情况。不能把权限失败、未知格式、尚未验证或预算耗尽改写为不匹配。
- 独立格式的安全识别与持有候选构造，再走同一个完整元数据 verifier。当前 DTO 和实验 ShapedEvidence 都不能提供这项证明。
- 能证明扫描期间范围没有未说明变化的机制及其失效规则，包括扫描启动窗口、事件丢失/溢出、重启、挂载变化和外部非合作写者。仅做两次相等读取或没有收到通知，不足以声称具有这样的机制。
- 响应应用时仍有效的拥有者、请求和来源图捕获绑定。它只能保持“这次结果属于谁”，不能反向补足扫描完整性或持续在场。

目前没有实现或验证这种生产者，因此不新增 Complete、Unique、NotFound、Online 或自动选择分支。有限显式列表的全部元素已经被遍历，也不自动提升为真实发现范围完整。即使日后能证明某个选定范围内唯一，也仍不构成用户接纳、正文可读、当前在线或写权。

可以落地的顺序是先记录“这次扫描实际覆盖了什么”，而不是先增设完整性布尔值：第一步由服务器在已持有根内保留范围、排除策略、每项结果和全部未覆盖原因；第二步增加以实际持有描述符为输入的独立格式只读识别/候选构造，再调用原 verifier；第三步在既有认证、请求及真实事件适配器上接入以下回传约束。每一步都保持部分观察语义。只有另行实现并验证了扫描期间变化的明确契约，才考虑为私有生产者增加更强回执；不能由 DTO、无错误计数或“枚举结束”自行升级。

## 本次实现：拥有者与一次性回传

`disk_authority::SourceCandidateSession` 是一个不克隆的进程内拥有者。`begin(&SourceNode)` 每次都建立新的私有请求上下文，立即清除旧观察或旧错误，返回不克隆的一次性 `SourceCandidateRequest`。即使来源节点和图捕获完全相同，重新请求也不是前一次请求。

`SourceCandidateRequest::observe(self, &[&IndependentDisk])` 消耗请求并直接调用真实的 `observe_source_candidates`。只有这条路径能构造不克隆的 `SourceCandidateResponse`。调用方不能提交旧批次、填写成功标记、拼装错误或把任意 DTO 包装成新请求的结果。

`receive` 只接受该拥有者当前 Pending 请求的上下文。旧成功、旧失败、另一拥有者或关闭后旧拥有者的响应都返回 DiscardedStale，并保持当前状态不变。Updated 只表示本次响应被存入内存，必须从 view 区分 Observed 与 Failed，不能把 Updated 当作验证成功。

上下文通过私有 Arc 分配身份比较，不使用调用方填写的代数或响应自报字段。只要旧请求/响应还存在，其分配就仍被持有，不会因地址复用使旧响应变成新请求。这个身份不是密码学令牌、认证凭据、磁盘身份或跨进程 wire ID。

view 只有 NotRequested、Pending、Observed、Failed。Observed 原样保留 b120 的 NotObserved、IncompleteObservation 或 Ambiguous；Failed 保留原输入位置、阶段及具体错误。没有新唯一性或在场状态。`invalidate` 清除当前接受关系与显示事实，不把它们转换为不存在或离线。

## 插盘与异步适配仍必须完成的工作

现行 Web 向导已经用会话 epoch 和读取代数检查发现响应；现行 foreign preview 还捕获请求侧 DirectorySource 并使用 ReadCancellation。这些是有用的既有边界，本次没有替换或删除。它们尚未消费新独立盘批次或 SourceCandidateSession，不能借旧分区的检查声称新链路已经接好。

未来适配器至少应在重发现、换来源节点、取消、关闭、会话失效及相关挂载事件时使当前请求失效，并在应用前使用调用方持有的拥有者状态。认证与对象授权继续由原服务入口验证，不由此 helper 提供。wire、重启恢复及多进程通信另需明确协议，不能序列化 Arc 指针或恢复旧观察为当前在场。

本 helper 不调度任务、不观察热插拔事件、不检测授权变化、不取消已经开始的文件系统 I/O，也不阻止一个已失效请求稍后开始其有界读取。调用方仍须负责工作队列、背压、取消资源、失败/退出任务回收；工作者被丢弃而没有响应时，拥有者必须显式失效，不能自动标成成功或未找到。被替代的请求可以继续持有自己的上下文，因此单个批次的预算不是并发请求总预算。

交付响应时不重新打开盘、不修复目录，也不把历史元数据变成当前存在性证明。候选在核验后被移走，仍属于该请求的结果可以作为历史观察存入内存；只有真正的上层事件/会话适配器能决定何时使该视图失效。本次测试明确保留这个边界。

## 成本和验证范围

begin 仅复制一个有界 SourceNode 并分配一个 Arc 上下文；拥有者保留一个当前状态。绑定判断 O(1)，返回值移动而不重复核验。替换或丢弃旧批次时，释放成本随其持有数据规模增长。observe 完整继承 b120 的候选、元数据和链条预算，不新增文件系统阶段、写锁或 fsync。没有新增依赖、持久化记录或 wire DTO。

根 `test/engine/unit/disk_authority/source_candidate_session.rs` 的 18 项测试使用真实临时独立盘与原 verifier 返回的 SourceNode/批次，覆盖同节点重试、相同逻辑新捕获、换节点、不同拥有者、关闭重开、旧成功/旧错误乱序、当前错误与预算失败、取消后只读工作、原歧义/未观察/空 pin 状态、候选移走后的历史边界及无 sleep 的真实线程反序回传。没有用伪造批次驱动生命周期测试。

这些检查针对窄生产模块，尚不表示真实热插拔、发现完整性生产者、HTTP/WASM/浏览器交互或完整当前 Engine/官方 CI 已验收。具体通过、失败和未执行项以对应运行收据为准。
