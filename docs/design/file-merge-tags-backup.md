# 文件分支合并、版本标签与备份前缀

[完整分支规则](branch-system-logic.md) · [当前支持范围](../23-delivery-and-decisions.md)。父节点在下，子节点在上。

## 文件分支合并

用户明确选择两个或更多该文件的活动分支，查看每个分支的当前节点，再从**该文件的任一节点**选择结果正文和标签，最后明确选择合并结果归属的原分支。选择来源不局限于参与分支的祖先。提交同时检查各输入分支的精确节点；任何节点已经变化，整笔合并失败并保留输入供重新审阅。

| 选择的结果节点 | 发布结果 |
| --- | --- |
| 等于任一参与分支的当前节点 | 直接复用这个节点，不新建文件子节点、不复制正文 |
| 是其他历史节点 | 新建一个合并元数据节点，引用所选正文和标签；父边记录输入节点及所选节点，不生成 FULL |

合并没有自动拼接文本或二进制内容。用户选择的节点决定合并后的正文；已有的其他正文仍按历史保留规则保管。真实正文版本、哈希和内容证明不重写。

合并采用的正文必须仍可读取并验证；已清除节点的元数据保留，但不能把不存在的正文发布为当前文件。

结果归属分支继续可写。其他参与分支保留原名称、原历史和原节点，标为只读别名，并记录其归属分支；后续写入使用归属分支。归属分支以后再次参与合并时，别名链仍可追溯，不允许环。

每次合并均保存独立记录，包括全部输入分支、输入节点、所选节点、结果节点及归属。复用现有节点时，仅追加不会造成环的关系边；例如选中的节点本来就是另一输入节点的祖先，不向它加回指。跳过连线不丢弃合并来源记录，不修改原节点的内容父证明。

所有**当前命名目录分支**中，引用本次参与文件分支的条目都更新到结果节点，包括当前未显示的目录分支；每个受影响目录只新增本次汇总子树，必要父目录同步更新引用。目录旧子树保持不可变；引用其他文件分支的目录条目保持原样。同文件不同逻辑路径逐项匹配，不能用全局文件 ID 覆盖各路径的独立上下文。相关旧写会话会冲突并保留暂存字节，旧读取继续读取原先固定的版本。

**目录分支合并：待确认，暂不实现。**原有 `MergeLink` 仅记录关系标记，保留旧功能；它与本节会推进文件分支、更新目录引用的合并操作不同。

## 标签属于文件节点

标签属于稳定文件身份下的某个具体节点，包含正文节点、路径节点和元数据节点。它不是整目录统一标签，也不是可变的文件全局属性。普通子节点自动继承父节点标签；合并采用用户选中结果节点的标签，不暗中合并两组标签。

标签名称必须非空、首尾无空白、不含控制字符，最多 128 UTF-8 字节；每个节点最多 16 个标签，按名称去重。界面使用页面内下划线输入和标签按钮，不使用弹窗。

修改标签使用增加／移除的增量集合，生成一个复用原正文的标签子节点。旧节点的原标签保持不变；同样的标签集合不再新建节点。

| 被编辑节点的位置 | 引用推进 |
| --- | --- |
| 仍为目标文件分支当前节点 | 该分支推进到标签子节点 |
| 仍被某个目录分支当前条目精确引用 | 该目录条目推进到标签子节点，新增目录子树 |
| 仅为历史节点，当前节点已有较新正文 | 只增加标签子节点，当前正文和分支头不退回 |

批量编辑显式列出节点、所属分支及预期分支头，对每个目标分别继承其原标签再应用同一增量。容量、业务可写状态、节点归属、只读别名及预期节点全部先检查；任一失败整批不发布。重试沿用同一操作 ID，不能重复生成节点。标签修改本身不算首次正文写入，待写入文件／目录的继承意图保留。

标签提交结果未知时，界面保留原操作 ID、请求路径和完整请求体；查询 404 不能当作未提交，也不能改用新 ID。用户可以显式原样重发该请求，导航不会改变其文件、节点、分支依据或增删标签。重发收到拒绝仍不撤销先前未知请求，只有原操作的有效终态收据才能解除未决围栏。

首次标签请求明确返回 409 时，保留所选节点和标签增量，重新读取当前历史及全部目标／分支依据。读取本身不授权新提交，必须明确接受重新审阅的依据；原分支已不可写时，可以选择当前可写分支后再完整审阅。迟到结果不能使已确认的操作退回未知，旧会话或旧草稿的完成不能影响新会话及新草稿。

## 历史节点备注与当前登记

路径、标签和合并节点的备注是独立的可变注解，不是正文版本或不可变节点的一部分。设置、替换和清空备注都必须指向已准入历史中真实存在的唯一节点，并精确绑定节点 ID、文件 ID、正文版本和历史域；正文版本 ID 不能冒充路径或元数据节点。节点只剩历史引用、分支已被合并，或者所属 occurrence 在磁盘注销后退出当前列表，不会抹去它的历史备注资格。

当前 registry 下的 `file.path.metadata` 发布和恢复共用同一证明：请求摘要、操作主体、永久收据、事件及业务代数必须一致；除目标节点的一条备注和普通发布信封外，所有 State 字段保持不变。没有对应收据的备注改动、额外备注改动、节点／版本／分支／目录／放置规则或旧收据的夹带修改都拒绝。同值设置和空备注清空仍有独立永久收据，不能因注解值未变而省略收据／事件验证。检查先于 unchanged-HEAD 快捷路径；从磁盘反序列化后无法利用增量写集时，仍比较完整的相关字段。

备注不会使已隐藏 occurrence 重回当前列表，不会推进分支或目录 HEAD、恢复已清除正文、重新打开 Disabled／Detached 目标根，也不授予标签修改或正文操作资格。登记下线仍保留原列表和数据；注销只移除目标登记及其独占当前 occurrence，不擦除原文件或生成恢复文件。现有 HTTP 认证、正文读取及其他业务操作的独立准入保持不变。

## 2／3／n 份与备份路径

份数包含主盘，例如 3 份为主盘一份、两个备份盘各一份；实际可用路径仍服从已配置的固定备份拓扑，不足 n 个槽位时明确失败。

用户为所设策略的文件／目录指定每个备份盘的逻辑前缀。备份逻辑路径为：

`该备份盘的用户前缀 + 相对于策略文件／目录的路径`

例如主盘真实位置为 `工作/客户甲/项目`，为该目录在 B01 配置 `档案/项目`、在 C01 配置 `离线/项目`，则 `图纸/a.svg` 的副本对应 `档案/项目/图纸/a.svg` 和 `离线/项目/图纸/a.svg`。这些前缀不来自主盘绝对路径，也不要求与主盘目录相同。单文件策略使用用户前缀加配置时的文件名。

主盘移动或改名不会重算已有副本的用户前缀和已绑定路径，也不会使文件丢失已设置的份数。用户显式修改备份配置，才更新绑定及逻辑路径。新加入策略目录的文件按该目录策略建立路径；路径均验证为安全的相对命名空间，拒绝逃逸和冲突。

保护规则显式区分两种角色，`ProtectionPolicy.inheritable` 为必填布尔值，不为缺失字段补默认值，也不转换旧数据：

- `true` 是现行规则，参加稳定文件／目录 scope 的精确查找或路径祖先继承；仅按 `path_prefix` 设置的现行规则也使用 `true`。
- `false` 是仅供 `file_backup_policies` 显式文件绑定使用的保留设置，不参加任何精确 scope 或祖先查找。仍有效的本地 scope 引用可以保留，但不代表该规则还能被新文件继承。

选择有效规则时，显式文件绑定优先；没有绑定时，按当前解析路径的层级选择更具体规则，同层级的稳定 scope 优先于普通路径规则，不依赖策略 ID 或创建顺序。目录改名后按新位置判断规则冲突，原名称可供新的路径规则使用；改名进入已有路径规则时，稳定 scope 仍优先，更具体的子规则不受影响。查询的有效策略 ID、代数、份数和前缀来自同一规则；自身策略 ID／代数只用于显式配置的条件写入。有效规则仍可继承且不同于自身规则时，`inherited` 才为 `true`，文件绑定的保留设置始终为 `false`。

重配同一 scope 时，现行规则沿用原 `policy_id`，按原 `generation` 加一，不为每次设置另建一条现行规则。只有原规则仍绑定、但不在本次实际覆盖文件集合内的文件，才共同转到一份保留旧份数、前缀和代数的快照；这些文件的已绑定备份路径不变。因此文件移出后再重配原目录，不会追溯改变已移出文件。新文件只继承现行规则，不会重新继承保留快照。

父目录配置既不覆盖更具体的独立子规则，也不覆盖文件的保留设置；要重新设定这类文件，必须显式配置该文件。没有文件引用的保留设置在配置或映射后清理，空目录的现行规则仍保留，供后续新文件继承。查询保留设置返回 `inherited:false`；用于条件写入的自身 `generation` 只取精确现行规则，没有则为 `0`，实际文件设置另由 `effective_policy_id`／`effective_generation` 表达。

`PUT /api/policies/{policy}` 只创建或更新无稳定 scope 的现行路径规则，影响后续版本，不回填历史。直接修改稳定 scope 规则或保留设置返回 `400 BACKUP_CONFIGURATION_REQUIRED`，应改用文件／目录的 `backup-configuration`，不能借通用策略更新绕过路径绑定和历史回填。

备份盘文件页直接按所设前缀展示只读目录，不在自定路径前加 `P01/`。显示路径和主盘历史查询上下文分别保存：主盘改名后，备份路径保持不变，历史查询仍定位正确文件；主盘已无条目但仍有可用副本的容器也可浏览其元数据。Web 不提供文件内容上传、下载或预览。未显式配置备份前缀的文件按默认逻辑路径显示。不同文件发生逻辑路径冲突时明确报错，不能覆盖；唯一管理员的完整当前作用域参与展示与冲突检查，不进行用户 ACL 过滤。

配置页同时考虑所选范围的默认主盘、实际覆盖文件后续写入所选的主盘、范围内仍继承此目录备份规则的放置前缀（包括空目录与尚无文件的子路径），以及可用历史版本的原主盘固定链，按全部相关链收集所需前缀，份数上限取各链可用长度的最小值。不能只填默认主盘链而漏掉历史回填或子文件后续写入的备份目标。改名、移动或主盘规则变更后，原份数可能超过当前链长度；GET 仍返回原份数和可用链供调整，无法组成所请求完整路由时 `route_slot_ids` 为空，不把较短链冒充满足原份数。PUT 按新请求份数验证这些相关链，允许显式降至可用份数，不先要求原份数仍能满足。

配置时为策略内仍可用的真实版本补足副本，保留原版本 ID 和内容证明；不伪造写入版本。父目录配置保留更具体的独立子目录／文件策略。已清除的历史正文不会因此复活。前缀是逻辑路径约定，盘内仍保留历史域和稳定文件身份的隔离结构，避免不同版本容器互相覆盖。重复补保护的证明按发布候选归档到 `protection-proofs/<candidate>/`，不覆盖原版本的首次证明。

当前磁盘 registry 发布后，正常备份配置通过专用准入重新计算稳定 scope 的当前命名视图、独立子策略、移出文件的保留设置及全部可用历史版本。原始请求、主体、registry／mask／冻结来源、完整 State 写集和实际 Candidate 副本集合必须一致；冷恢复和控制归档在读取正文证明或修复前执行相同验证。Disabled／Deregistered 盘位不重新打开；GET 保留原份数并展示可用链，PUT 只有显式降低份数才可避开不可用下游。当前 registry 下此类备份尚不支持显式降级恢复，必须保留原候选、日志和正文，等待完整副本发布，不能把降级结果冒充原始达标收据。实现边界与实际执行证据见[当前备份配置验证](../validation/current-backup-configuration-20261105.md)，不以源码中的回归断言代替测试结果。

历史包导入先完整验证引用闭包，沿用包内仓库、文件和目录身份，保留规则角色与文件绑定，按目标路由映射已选路径；无效 scope 直接拒绝，不自动修补。受支持的树拆分才创建新身份映射：无法映射的稳定 scope 引用必须清除，相关规则改为保留设置，仅保护仍映射到目标的绑定文件；不能把源 scope 留在目标，也不能改成路径继承扩大适用范围。源树也须清除仅存在于迁出提交中的目录 scope 引用，对应规则只在仍有源文件绑定时作为保留设置留下。拆分后无绑定的保留设置清理，仍有效的空 scope 现行规则保留。核心验证规则引用、文件归属、保留设置必须有绑定，以及同一稳定 scope 至多一条现行规则；无稳定 scope 的现行路径规则按规范等价路径键唯一，根路径也不例外。稳定 scope 与普通路径规则改名后的合法重合及文件绑定的保留设置不受此限制。schema 只检查字段形状，不证明这些跨对象关系。导入与拆分的目标规则仍按既有流程从代数 `1` 开始；此角色不新增格式版本号，也不改变 UTC 时间约定。

## Web 逐级备份入口

文件列表的当前范围与文件／目录详情提供独立的“逐级备份”入口；原“自定义备份前缀”编辑器保留。逐级入口读取 `/api/repositories/{repository}/recursive-backup-configuration`，展示当前份数、可用路由及冻结的来源盘名；保存通过同一端点的 PUT 提交原始完整 capture、稳定 scope 与代数，不由浏览器重新采集或拼出写入权限。

每一级只给直接来源磁盘的完整逻辑路径加来源盘名。例如二级 `磁盘A/目录/文件`，三级 `磁盘B/磁盘A/目录/文件`。Web 明确区分“盘名前缀预览”和“当前已发布路径”；前缀预览不声称包含尚未返回的主盘仓库路径。有名称的仓库仍保留仓库名，磁盘根仓库不添加仓库名。

本入口仅显式重保护当前范围内的文件与仍可用历史，不独立发布空目录，也不让后续 rename 自动传播。无文件的范围禁用保存。来源或代数改变后须重新读取并复核；结果未知时禁止替换草稿、重读来源、修改份数或新建另一操作，只沿既有操作观察最终结果。GET 的旧回调不覆盖新草稿，当前会话的 401 即使面板已关闭仍使会话失效。此入口只传输元数据，不提供正文上传、下载或预览。

文件历史展示使用 `Engine::project_file_nodes` 一次投影当前请求选出的节点，仅返回有序父边和标签，并保留逐节点错误。它复用内部 `NodeProjection`：父边查询只建立一次全局合并记录索引，首个基础父节点的标签继承在本次调用内共享遍历结果，不跨请求或发布保留缓存，也不新增 SQLite 表。服务端仍决定文件／历史域可见范围、当前路径与只读别名，过滤不可见父边，并按显示序号降序、同序号节点 ID 升序输出；合并采用来源的路径仍由原有展示逻辑解析。

这是整张请求图的临时投影，不是分页或全量图规模上限保证。合并路径来源索引和响应合并记录过滤仍保留各自的一次扫描。固定工作量回归以 1,024 个节点、257 个合并记录对照原逐节点 API：父边投影的合并记录访问从 263,168 次降为 257 次，标签链节点访问从 524,800 次降为 1,024 次；这些是测试计数，不是吞吐量或物理设备验收结果。

### 非空内容候选查询

文件详情的“相同内容候选”按用户选出的已准入文件节点发起独立只读查询。content、路径和标签/合并节点均解析到其真实正文版本；本阶段只比较**同一历史域中其他文件**的非零长度及完整内容摘要，返回真实内容版本，不把元数据节点重复计作新的正文。空文件不参与；自身文件的相同版本及其他历史域不纳入此候选页。

候选保留版本创建时名称、准确文件/版本身份与 `AVAILABLE/PURGED/MIGRATED` 持久状态。名称不是当前路径，`AVAILABLE` 也不是当次健康验证；查询不打开或验证正文，已清除正文的历史摘要仍可匹配。此功能不创建永久关联、不合并文件/分支，不实现跨历史域关联、永久解除关联、连通分量拆分或组合树。

分页按版本 ID 升序，最多 64 项；继续位置必须是该源节点/精确 `history_root` 下的真实匹配版本。服务端在锁内取得当前文件归属及不可变历史视图，锁外扫描候选，返回前重新检查当前会话和同一历史根。一次查询额外结果空间 O(页大小)，扫描 CPU O(全部保留版本)，逐记录检查取消，未引入常驻摘要索引、写入、额外 fsync 或新持久化格式。HTTP 槽一直持有至有界响应缓冲释放。

Web 单独拥有候选页、取消句柄和请求代际。普通历史翻页不会清除同一历史根的比较节点；更换源节点、文件、历史根、会话、收起结果和组件卸载会取消并拒绝旧结果。响应先处理当前会话 401，再判断旧面板/请求，不能因面板已经关闭而隐瞒会话撤销。候选面板不改变默认分支或现有历史选择。

### 自动联合投影

另一个独立入口按来源文件的全部保留非空版本自动求同域跨文件连通分量，返回真实事件、独立文件分支及非时间性的等内容关系，支持联合／本人／其他文件的只读查看。软删除或正文清除不会抹去保留关系，新同内容文件仍有独立编辑资格。它不将 `file_id` 或重复内容事件折叠为一个身份；永久解除关系、跨域和完整磁盘退出生命周期仍是后续工作。精确范围、硬预算和验证入口见[共享文件联合图](shared-file-history.md)。
