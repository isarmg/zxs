# 共享工作稿：打包改动，不打包正式历史

业主于 2026-11-18 选择便携的独立文件＋区间表。首要场景是已有单副本普通 FILE 的 SMB 保存；临时稿与正式 FULL、手动 Save 与 Commit、自动保存与自动建节点仍是不同事件。这里定义唯一新材料，不新增旧块清单的识别、回退、迁移或第二个发布决定。

## 数据和读取

- 一个连接内的有序写追加到本次私有 pack，不按传输帧创建文件。每个 pack 最多 **16 GiB 数据**，满后另起一个，同次 Save 可用多个。物理文件是数据和按顺序排列的校验尾表：每个 1 MiB 数据块（包括末尾不足整块）对应 32 字节 BLAKE3。索引承诺覆盖 pack ID、数据字节数、全部校验。清单记录类型化 ID、持有的设备与 inode、数据长度、索引承诺；总物理长度精确等于数据加校验表，无附加头部或尾巴。
- 首次写使用不覆盖的私有单链接文件；仅已同步、按实际持有 inode 读回全部新增数据并校验、再次核对原命名目录／文件后，才可把 pack 作为原 Save 的准备反馈。此反馈不是发布回执。部分上传、刷新后同名文件、同哈希不同 inode 都不能作为已接收材料。未知文件保全；本设计不引入扫描、自动删除或后台回收。
- 上层清单以严格排序、不重叠的半开逻辑区间表示 `Data(pack, physical_offset)` 或显式 `Zero`。未覆盖的区间按原可见基准前缀读取，基准以外为稀疏零；已写零不会复活原基准字节。重叠写只切分被覆盖区间，保留旧 pack 的物理偏移。截短裁掉可见范围并限缩基准前缀，再扩展只见零。顺序相邻、同 pack 且物理连续的写合并为一个区间。读取只认证请求实际涉及的 pack 块／基准校验块，不生成全量临时文件。

## 预算、发布与边界

配置的文件逻辑上限、原盘实时可用空间／预留与配置容量仍生效。独立限制当前可见区间数、同时引用的 pack 数、每 pack 校验表及有界读写缓冲、全局实际持有 FD；不把区间数乘传输帧大小当文件容量。单次保存实际追加（含随后被覆盖的部分）也须计入临时用盘；未引用物理文件仍需保留，不能以逻辑删除当回收成功。16 GiB 是换段点，不是单文件或单次保存上限。100 GiB 原文件经十次不重叠、连续的 10 GiB 写并分别 FLUSH，预期产生十个数据 pack、十个数据区间，而非每段 163,840 个小文件；这是几何关系，不是吞吐或实测结果。

只有已有原操作／主体／基准／前代／FILE 决定及正式回执可以接受清单；缺前代、缺 pack、部分写、名字替换或实体不符须保旧拒绝。显式提交或合规的自动建节点仍须提供独立、完整校验过的 FULL；不以清单、硬链接、reflink 或跨版本去重替代，不在本阶段声称优化 FULL 的物理成本。旧 held reader 在其原所有权内保留原 pack，不因新 Save 消失。

代码按物理 pack、逻辑清单、原生产入口逐步接通。在原 writer、前后清单和回放全部接通前，独立的 pack 准备能力不是已交付的手动／自动 SMB 保存。当前按要求不运行构建、测试或 CI；十次真实 SMB 写入、断电和实际 I/O 量等待统一验证。

自动路径仍按批准的 [008c584c 自动发表策略](https://github.com/isarmg/zxs/blob/008c584cc73305984785f4ff77fbe416a1e36857/docs/adr/shared-draft-automatic-publication.md#L36-L46) 顺序：100 GiB 原 FILE 上先保存 A 的 10 GiB，再保存 B 的 20 GiB；每次已确认保存只记一次，两次都进入同一 60 秒的 20 次限流统计，不因后来只建一个 FULL 节点合并成一次。A 尚未永久决定时，B 使原 A 准备过时，重新捕获 A+B 的最新平坦视图；若 A 已永久决定，则以原回执收尾，不清除后来的 B 脏代数。区间有重叠时只在重叠段取 B，不重叠时两段均保留。空间峰值不能扣除仍由原决定、旧 reader 或未知 partial 持有的 pack；同时计入目标 FULL／已保留与本次临时输出。该顺序不是本材料层新增的自动控制器或测试通过声明。
