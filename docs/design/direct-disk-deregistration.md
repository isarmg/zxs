# 数据目录直接退出登记：实施约束

状态：规定 Exit generation、实际 D3 验证与生产 I/O/bootstrap/当前投影接线正在联合整合；本轮尚未执行验证，见[退出发布记录](../validation/disk-exit-publication.md)。此文覆盖此前“在目标根保留恢复登记文件/备份”的方案；未通过的阶段不能视为已经验收。

## 用户可见语义

- 操作对象是 ZXS 登记的数据存储目录，而不是 Debian 系统设备。不同目录可以在同一文件系统；不挂载、卸载、格式化或擦盘。
- 离线/下线：保留登记、数据和逻辑记录，禁止对目标的普通或后台 I/O。计划下线若要其余成员继续写服务，仍需真实、已验证的成员决定，不能按当前在线数降低 Q。
- 删除：直接从当前登记中踢出目标，移除仅依赖它的当前文件列表/索引项。原物理文件不删除，不创建或要求目标恢复文件、恢复 capsule、恢复备份，也不要求为了写这类文件而让目标在线或可写。
- 共享内容、其它目录记录和必要控制历史不能随目标删除。历史 Placement、Candidate、永久结果保持原身份和字节。保留历史元数据不承诺仍可读取只存在于被踢目录的正文。
- 不自动把备份变成新的 primary，不降低原保护策略。保留内容的读可用性、当前命名空间和未来写路由分别处理。

## 权威与依赖

一次删除绑定准确 source publication、源 registry commitment、目标 pool/disk/slot/binding identity、operation 和请求摘要。运行中不能靠路径字符串、更改系统 Config 或内存列表执行删除。

先准备 occurrence mask，再准备 intent 和 registry successor。mask 绑定前驱 registry、源快照、目标身份和准确 occurrence，不引用未来 publication。registry 绑定这些已存在的材料，Candidate 绑定 registry 和相应成员 authority，Publication 最后绑定 Candidate。不得把同次 Publication 回填 registry，避免哈希依赖环。

控制归档仍是当前池认证已发布历史和旧成员决定所需材料，不是留在删除目标上的恢复备份。必须在保留成员上独立验证其完整性；不能只复制最新快照后丢弃旧决定证明。

## 执行顺序与恢复检查点

1. **无副作用预检**：固定当前快照和登记代数，计算共享与目标独占的逻辑影响，检查保留成员可提供原固定 Q 与目标固定 Q 的真实证明。目标不在线不等于自动拒绝；缺少安全决定所需证明才是阻塞。当前驱动仍依赖全原成员的地方必须标作实现缺口。
2. **准确操作预约与可恢复的停止探测提示**：唯一 operation 及原 fence 预约阻止并发 Add/Restore/Detach 越过同一源边界。先在保留成员完成独立控制归档、联合证据及 prepared exit authority，再持久化系统侧 stop，随后才关闭目标 I/O。系统侧提示只收紧首次探测根，不提供成员权威、不改 N/Q；不能先 stop 再期望崩溃后重开目标补全缺失证据。缺失/坏提示或系统目录丢失进入管理恢复，不能回退遍历旧 Config。
3. **收束真实 I/O**：拒绝目标新普通操作，取消/结束既有读写、维护、SMB/HTTP流、上传、目录迭代及复制；实际 FD、目录句柄、锁副本和清理尾部仍各自持有责任。只有普通责任真正归零才进入唯一控制阶段。任何清理不能在“目标已禁止 I/O”之后才第一次发生。
4. **联合决定和历史保全**：保留原/目标完整集合的独立多数规则，认证准确退出效果及保留历史。预备控制证书不是已激活退出权威。无真实票时不生成票，单份可读副本不能取代其它成员自己的日志/归档。
5. **原子发布当前语义**：规定 snapshot、成员 authority、registry successor、occurrence mask、永久操作结果共同决定一次活动切换。结果成功必须对应目标已无可逃逸 I/O 资源及可恢复的当前权威，而不是仅有 marker、系统 JSON 或一个 Publication 文件。新格式普通准入必须消费该规定发布的真实证明；未验证的准备图不能开启业务。
6. **投影与幂等完成**：系统配置、列表索引和管理结果都是已认证发布的投影。崩溃后从同一准确决定重建，不重新操作被删除目录，不创建恢复备份。旧目录再次出现也不自动重新登记。

删除不再有“写 Prepared 恢复文件 → D3 → 写 Committed 恢复文件 → D5”链。不得继续等待不需要的恢复文件完成证据；但删掉这些步骤也不免除当前权威、I/O 尾部和永久操作结果的原子性。

## 当前可写命名空间

只在列表里隐藏条目不够。每个 namespace scope、源 head 和 registry generation 都须产生同一 WriteProjection，所有以下消费者必须使用它：

- 新 workspace 的选择和 base，上传同名路径、版本上下文与 file_id 分配。
- commit draft、rename、DeleteTree、目录父项生成、同名替换和冲突检测。
- merge、rebase、历史恢复/分支创建及从旧 commit 导入的 entries。
- HTTP/SMB 打开、目录枚举和随后的写提交。

混合目录中目标独占 `a` 被移除而共享 `b` 保留后，只改 `b` 的新提交不能重新携带隐藏的 `a`。重新新建同名 `a` 必须获得新的 entry/file 身份，不能从原 HEAD、pending_file_versions 或历史上下文偷偷复用旧身份。原历史对象不改写。跨登记代数的旧 workspace 必须重新验证准确基线；不能只在创建入口加一个布尔检查。

删除目标恰为 namespace owner 时，共享内容可继续作为保留内容被表示，但不能伪造新的 primary 根或默认允许该旧 namespace 写入。新写路由须有自己的可验证规则。

后继成员变化还必须继续准确前代 registry 和当前 namespace，而非从历史 Config 或原始 heads 重新开始。Disabled→Deregister 复用首次停 IO 的持久证明，所有早期 stopped binding 的逻辑排除 guard 持续保留；恢复从已认证控制归档重放每个前代 D3 及随后普通发布。

当前普通消费者的源码接线、持久 workspace 准入、暂时拒绝的导入/移动操作及未执行检查见[当前登记命名空间](../validation/current-disk-namespaces.md)。该接线不能单独激活注销，必须消费正式生命周期的准确 D3 证明。

## 必须补齐的故障用例

- 每个持久屏障前后退出，旧 Config 仍命名目标且目标仍物理在线，从第一条 stat/open 开始证明不探测被停止根。
- 丢失系统目录、坏 hint、陈旧 head、未知 binding、合法多数中单盘坏锚；既不扩大根集合，也不缩 Q。
- 操作并发、撤权、重复请求、不同请求复用 op、后继代数及可证明取消。取消未完成时不得假称旧池已恢复正常写。
- idle 和正在执行的各类资源关闭，复制/同步/删除临时文件尾部，以及 caller 永不再 poll/drop 的实际 FD 释放。
- 目标独占与共享 occurrence 同目录、同文件多版本、多分支/多目录引用；新建同名文件、只改共享项、rename/DeleteTree/merge/rebase/SMB 不复活隐藏身份。
- 目标永久缺席且保留固定两侧多数足够，以及两侧之一不足；错误必须反映证据缺口而不是目标必须写恢复备份。
- 最后 voter 的终止池权威单独设计。不能伪造 N=0/Q=0 活池，也不能把当前未实现定义成永久禁止删除最后目录。

临时目录故障测试不等同物理掉电或生产部署。无运行证据的阶段继续保持未完成，不开放成功的行政操作入口。
