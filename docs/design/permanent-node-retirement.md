# 永久节点退役与跨文件分组

[共享文件联合图](shared-file-history.md) · [文件软删除](file-soft-deletion.md) · [发布与恢复](../10-transactions-and-recovery.md)

状态：**Engine 真实退役发布、正文清理、原操作恢复与全 State 冷准入闭包已随 `ce293dcb` 合入。本提交接入受保护 HTTP 与 Web 文件详情中的显式版本选择、条件预览、不可撤销确认、原操作重试和逐副本结果；没有物理抹除不可变认证元数据。** 本轮按用户指示不运行测试、编译、审查或 CI，下面是源码能力及限制，不是验收通过声明。

## 产品规则与不可混淆的状态

- 独立稳定 `file_id` 不合并。只要两个文件仍有非空同内容版本，或仍通过其他文件传递相连，就保持联合分量。最后一条跨文件连接退役后才分组。
- 一个文件内部删除节点不能产生多个文件身份。显示父边可以跨过退役节点，原 commit、`source_version_ids` 与 D frontier 不能为此改写。
- 普通 D 软删除保留正文、节点和关联；`PURGED`、`MIGRATED`、正文不可读也不退役节点。空正文不是跨文件连接。
- 新 `RETIRED` 是经原生永久操作认证的**有效节点域终止状态**。已发布选择不再出现在节点、版本、内容匹配与联合图查询，不能作为新分支或写入的来源。
- `State.versions`、耦合事件及旧 commit 的原记录仍作为不可变认证证据保存，普通历史 commit 审计与原始 State 也仍包含它们。因此不宣称“所有节点记录在磁盘上物理删除”，更不宣称离线盘、外部备份或旧导出字节全部擦除。

## 条件影响分析

`SharedHistoryRead::permanent_removal_analysis` 使用已捕获 owner、上下文及准确 `history_root`，先生成完整同域联合分量，再接受显式、唯一、非空且不超过 512 个版本的选择。任意同池版本不能混入。

结果给出耦合正文/路径/标签/合并事件、假设退役后的文件连通分量与显示父边，以及已知保留 commit entry 数、受影响文件 HEAD 和 D 冻结文件。每个原文件在条件分组中恰出现一次。结果没有执行凭证、持久写集或内容租约，不能直接交给 `commit_plan`。

调用方必须重验当前授权和根。执行器再次完成这一分析，不能把旧分析或 UI 选中集合当作当前准入。

## 真实执行入口与永久回执

`Engine::retire_file_nodes(read, selection, principal, operation_id)`：

1. 先走原生 actor、请求摘要及永久 operation 幂等检查。对同一原请求重试不会因已发布后的旧根失效而重复发布。
2. 新请求重验准确当前根、完整共享分量和全部显式选择，检查保留 HEAD、继承待写版本、文件上下文、目录分支/当前冻结子树及显式树选择、Git HEAD/index、读取租约、同历史域开放/封存工作区、当前 D 冻结和合并输入/结果。不能处置的引用明确拒绝。
3. 每个文件至少保留一个有效版本。本片不处理删除文件的最后一个有效节点；合并参与版本、迁出版本和任一保留分支 HEAD 也拒绝，而不是重写它们的证明。
4. 发布 `file.nodes.retire` 原生永久回执及精确 `RETIRED` 写集。请求绑定历史根、历史域、源文件和排序后的版本 ID；决定绑定所选版本、所有耦合路径/元数据事件、原父覆盖及备注的规范摘要。
5. 发布验证以穷尽 State 字段比较限制写集，只有选择的 `content_states`、一个操作、作者和事件可改变。不会删除或重写旧版本、commit、来源、D 或 placement。
6. 发布后沿现有认证 tombstone 流程清理正文。容器与准备位置最多各执行一次同步 unlink，避免中断残留同时存在时只删一路。冷恢复原有 `cleanup_purged` 同时恢复 `RETIRED` 的清理。

`PermanentNodeRetirementOutcome` 分开返回永久发布回执与 `Result<CleanupObservation>`。清理失败或副本不可达不能隐藏已成功发布的决定，也不能报成所有副本都已清除。

`resume_file_node_retirement(operation_id, principal)` 在重启后验证原操作及作者，恢复相同决定的清理，不要求重新选择节点，不生成新操作。它不能撤销退役。

## HTTP 与文件详情动作

三个管理员保护路由沿用现有认证、会话撤销与 CSRF/origin 边界，正文最多 64 KiB，响应有界编码最多 1 MiB：

- `POST /api/file-manager/files/{file}/node-retirement/preview`：严格解析 `history_root` 与 1–512 个不重复 `version_ids`；文件身份只来自路径。捕获当前身份/根，锁外完成条件分析，回锁再次核当前身份和根。预览不生成操作，也不是执行凭证。
- `POST /api/file-manager/files/{file}/node-retirement`：增加明确 `operation_id` 与固定 `confirmation=PERMANENTLY_RETIRE_NODES`。选择排序后绑定永久操作；正文未知字段、重复键、缺失确认或空/重复选择拒绝。当前管理员与 SMB 绑定隔离在 Engine owner 锁内重新准入，SMB 软删除不授予永久退役能力。
- `POST /api/file-manager/files/{file}/node-retirement/resume`：只接受原 `operation_id`，先核原作者、操作种类和 URL 文件，再继续清理。不能借详情 URL 把恢复重定向到另一文件。

同一提交请求重试先查原生回执并比较原 file/root/versions，再决定是否捕获历史根；因此成功后的旧根不阻止原请求恢复，改选择/改文件/改根/改作者则拒绝。破坏性 job 被 HTTP 所有者持有，即使等待者断开也不会自行取消、改键重提或隐式回滚。结果中的 `operation` 与 `cleanup` 分离；发布后的清理失败仍返回原发布回执与未核验原因。

文件详情而非列表提供单独折叠区，显式勾选正文版本，显示跨页全部选择、耦合事件和条件文件分组，再勾选不可撤销声明后提交。当前正文不可勾选，已知保留 HEAD/D 阻碍禁用执行；最终引用、工作区和租约仍由 Engine 判定。服务端不信任 UI 的确认状态或预览。

页面状态保存原 file/root/versions/operation，不因面板卸载或导航而换键；旧响应按会话、稳定文件、目标根及请求代数隔离。首次请求结果不确定后，后续 4xx 也不能证明原请求未发布。轮询回执除原 operation ID 外还核退役种类与准确请求。发布已知但清理信封损坏时保留发布事实，不显示清理成功；继续清理会清除旧区间观察，不把旧的缺失结论冒充新观察。

确认结果只能在明确拒绝，或已发布且本次所有当前副本均观察缺失后关闭。页面显示原操作 ID 和逐副本清理状态。浏览器整页刷新/重新登录会清空页面队列，本片没有持久浏览器恢复队列；应保留原操作 ID，通过原生 operation 查询和上述 resume 恢复，而不是新建请求。HTTP 原生回执和服务端冷恢复不受页面队列清空影响。

版本状态与所有正文来源的最终授权仍由 Engine 控制。旧式 file-history 聚合同时过滤 Retired 正文所耦合的路径/标签事件，避免将归档记录重新投影为有效节点。

## 原决定中的真实多连接分组

本提交把共享内容拓扑的有限索引/分组算法共用到当前联合图、条件分析和真实退役决定。非空 `content_hash + logical_size` 构成连接，但选择仍按版本 ID 删除：同一文件另一个相同正文版本、另一组不同的共享正文，或经第三个文件的传递路径，任意一种仍存在就不能拆分。文件内的时间父边断开不创建新文件身份。

`file.nodes.retire` 决定新增 `separation`：准确源根下完整原分量的稳定文件、当时全部有效版本 cohort、固定身份/内容承诺摘要，以及删除明确选择后的分组。生产规划和热发布验证从真实 previous State 再算完整分量，不接受 UI 提供的分组。所有文件恰在一个分组中，所选版本必须属于该完整 cohort。当前查询仍排除已退役节点，动态计算剩余全部关系，不靠缓存的分组冒充当前图。

冷恢复按收据的冻结 cohort 核身份/内容摘要并重算原分组，**不使用今日 content_state、HEAD 或后来的版本重判历史决定**。后续退役可以继续拆分，后续相同内容保存也可以重新连接有效节点，但不能改变旧收据或复活旧身份。HTTP Outcome 分开提供 `separation` 与 `cleanup`；文件详情显示原决定的真实分组并标清它不是今日图或清理证明。两种观察失败都不隐藏已发布事实。

当前原生退役记录要求完整 `inbound_references` 和 `separation` 字段。缺少它们的早期未完整记录明确拒绝，不增加默认值、旧格式双读或隐式迁移；不重置或删除原材料。本轮不操作真实运行池。

## 冷恢复与不复活

全 State 先完成结构/引用准入，再验证反向闭包：每个 `RETIRED` 必须有唯一、正确作者/请求摘要、成功状态和准确事件的退役回执；每个永久回执选择仍必须为 `RETIRED`，归档证据摘要仍准确。删除回执、改作者、删事件、裸写 token、回到 Available/Purged 或更改归档记录均拒绝。

决定同时冻结所选正文及耦合事件的既有入向引用集合：内容来源、commit 正文/待写条目、路径/标签正文和父边、显式父覆盖，以及历史冻结目录树的正文/上下文。每个引用绑定种类、原记录身份、位置及目标 ID。冷读必须与原摘要和数量一致；新增对象指向退役身份、删改既有入向引用不能伪装成“旧认证材料”。这不依据容易保留旧数值的复制版本 sequence 猜测新旧，也不会把后来当前 HEAD 当作历史证明。

所有新发布及注册表重放都运行同一守卫，历史复制快捷路径也不能绕过。旧不可变来源继续作为证明，但新版本、commit、路径/元数据节点或父覆盖不能重新引用退役身份。原版本行不被当作读取/写入准入。

**完整 native State 恢复与 portable history 包不同。** 当前包不含完整 operations/principals，故含 `RETIRED` 的历史明确拒绝包导出、包准备备份、包读入及现有 history split；不能把缺失回执降格为 Purged。后继须扩展可携带审计协议后才能开放。外来盘逐版本检查遇到 `RETIRED` 也明确拒绝缺少闭包的材料。

本地当前权威仍保留退役事实时，旧状态不能覆盖它。完全移走所有新权威并恢复独立旧备份、把旧字节作为全新身份导入、离线旧盘重新接纳，仍需外部/逐盘持久退役权威协议；本片不声称解决这些情形。

## 有效图与归档证明

有效版本索引先排除 `RETIRED`，再按全部剩余非空内容计算传递闭包。只有最后一条连接消失才分组，内部断点不拆文件。耦合路径/元数据节点也同时离开有效图；显示祖先穿过退役节点到最近有效祖先，原证明不改写。

有退役记录的历史暂不使用仍包含归档节点的 SQLite 历史分页索引，回退权威有界扫描。HTTP 真实 Engine backend 的版本/来源准入也拒绝退役身份；普通 `file_history`、node/version/source 查询、内容匹配、节点来源和父投影同样使用有效域。原始 State 与历史 commit 审计是认证证据读取，不是可复活的节点 API。

## 当前副本清理观察

只读 `inspect_permanent_removal_cleanup` 仍用于未退役的条件选择。执行及恢复则按永久回执的准确版本集观察新根下的当前 routes。

每个当前副本分别返回 `NotRequested`、`MissingTombstone`、`PayloadPresent`、`VerifiedAbsent` 或保留具体原因的 `Unverified`。只有非空结果全部为 `VerifiedAbsent`，`all_current_routes_absent()` 才为真。缺失墓碑、缺失版本身份、不可读、错误归属、停止的 I/O gate 都不是成功。

一旦查找观察到任一位置正文，就保留 `Present`，不能因后一次 stat 变成缺失而跳过另一位置。两处都观察缺失才能得到 `Absent`。

观察仅证明当前 routes 的区间状态，不证明过去 unlink 的 fsync、退役盘、外部副本或断电后擦除终态。调用方不能把 `Published` 或 SQL 状态替代实际核验。

## 资源及未验证边界
