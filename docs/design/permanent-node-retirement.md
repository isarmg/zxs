## 产品规则与不可混淆的状态

- 独立稳定 `file_id` 不合并。只要两个文件仍有非空同内容版本，或仍通过其他文件传递相连，就保持联合分量。最后一条跨文件连接退役后才分组。
- 一个文件内部删除节点不能产生多个文件身份。显示父边可以跨过退役节点，原 commit、`source_version_ids` 与 D frontier 不能为此改写。
- 普通 D 软删除保留正文、节点和关联；`PURGED`、`MIGRATED`、正文不可读也不退役节点。空正文不是跨文件连接。
- 新 `RETIRED` 是经原生永久操作认证的**有效节点域终止状态**。已发布选择不再出现在节点、版本、内容匹配与联合图查询，不能作为新分支或写入的来源。
- `State.versions`、耦合事件及旧 commit 的原记录仍作为不可变认证证据保存，普通历史 commit 审计与原始 State 也仍包含它们。因此不宣称“所有节点记录在磁盘上物理删除”，更不宣称离线盘、外部备份或旧导出字节全部擦除。

## 真实执行入口与永久回执

`Engine::retire_file_nodes(read, selection, principal, operation_id)`：

1. 先走原生 actor、请求摘要及永久 operation 幂等检查。对同一原请求重试不会因已发布后的旧根失效而重复发布。
2. 新请求重验准确当前根、完整共享分量和全部显式选择，检查保留 HEAD、继承待写版本、文件上下文、目录分支/当前冻结子树及显式树选择、Git HEAD/index、读取租约、同历史域开放/封存工作区、当前 D 冻结和合并输入/结果。只有完整终止决定中已冻结的独立文件分支／合并前沿可转为认证归档；其余引用明确拒绝。
3. 部分退役保留有效身份；选择覆盖某文件全部剩余版本时，只有已经完全脱离当前 namespace、路径上下文、D 和目录/Git 引用的历史文件才能终止；其完整独立文件分支 HEAD、选择／写入起点与合并前沿须一并固化为不可再写的认证归档。最后节点和该原 file_id 在同一决定中终止。仍有这些引用的文件继续拒绝，不重写它们的证明。
4. 发布 `file.nodes.retire` 原生永久回执及精确 `RETIRED` 写集。请求绑定历史根、历史域、源文件和排序后的版本 ID；决定绑定所选版本、所有耦合路径/元数据事件、原父覆盖及备注的规范摘要；另以 `file_terminations` 固化本次终止身份的全部保留版本集合，包含先前已退役版本。
5. 发布验证以穷尽 State 字段比较限制写集，只有选择的 `content_states`、一个操作、作者和事件可改变。不会删除或重写旧版本、commit、来源、D 或 placement。
6. 发布后沿现有认证 tombstone 流程清理正文。容器与准备位置最多各执行一次同步 unlink，避免中断残留同时存在时只删一路。冷恢复原有 `cleanup_purged` 同时恢复 `RETIRED` 的清理。

`PermanentNodeRetirementOutcome` 分开返回永久发布回执与 `Result<CleanupObservation>`。清理失败或副本不可达不能隐藏已成功发布的决定，也不能报成所有副本都已清除。

`resume_file_node_retirement(operation_id, principal)` 在重启后验证原操作及作者，恢复相同决定的清理，不要求重新选择节点，不生成新操作。它不能撤销退役。

## HTTP 与文件详情动作

三个管理员保护路由沿用现有认证、会话撤销与 CSRF/origin 边界，正文最多 64 KiB，响应有界编码最多 1 MiB：

- `POST /api/file-manager/files/{file}/node-retirement/preview`：严格解析 `history_root` 与 1–512 个不重复 `version_ids`；文件身份只来自路径。捕获当前身份/根，锁外完成条件分析，回锁再次核当前身份和根。预览不生成操作，也不是执行凭证。
- `POST /api/file-manager/files/{file}/node-retirement`：增加明确 `operation_id` 与固定 `confirmation=PERMANENTLY_RETIRE_NODES`。选择排序后绑定永久操作；正文未知字段、重复键、缺失确认或空/重复选择拒绝。当前管理员与 SMB 绑定隔离在 Engine owner 锁内重新准入，SMB 软删除不授予永久退役能力。
- `POST /api/file-manager/files/{file}/node-retirement/resume`：只接受原 `operation_id`，先核原作者、操作种类和 URL 文件，再继续清理。不能借详情 URL 把恢复重定向到另一文件。

同一提交请求重试先查原生回执并比较原 file/root/versions，再决定是否捕获历史根；因此成功后的旧根不阻止原请求恢复，改选择/改文件/改根/改作者则拒绝。破坏性 job 被 HTTP 所有者持有，即使等待者断开也不会自行取消、改键重提或隐式回滚。结果中的 `operation` 与 `cleanup` 分离；发布后的清理失败仍返回原发布回执与未核验原因。

文件详情而非列表提供单独折叠区，显式勾选正文版本，显示跨页全部选择、耦合事件和条件文件分组，再勾选不可撤销声明后提交。当前正文不可勾选，未被完整终止前沿覆盖的 HEAD 与 D 阻碍禁用执行；最终引用、工作区和租约仍由 Engine 判定。服务端不信任 UI 的确认状态或预览。

页面状态保存原 file/root/versions/operation，不因面板卸载或导航而换键；[浏览器恢复记录](node-retirement-browser-recovery.md)在首发前保存并读回准确原请求，刷新/同账号重新登录后只查询原收据；旧响应按会话、稳定文件、目标根及请求代数隔离。首次请求结果不确定后，后续 4xx 也不能证明原请求未发布。轮询回执除原 operation ID 外还核退役种类与准确请求。发布已知但清理信封损坏时保留发布事实，不显示清理成功；继续清理会清除旧区间观察，不把旧的缺失结论冒充新观察。

确认结果只能在明确拒绝，或已发布且本次原义务和所有当前副本均观察缺失后关闭。页面显示原操作 ID 和逐副本清理状态。全局浏览器恢复面板不依赖原文件仍在列表；整页刷新/同账号重新登录后从站点账号范围的不可变记录恢复原请求，不自动重发。未知结果重发须重新确认准确选择；已知原发布只使用上述 resume。清除站点数据、换浏览器/设备等仍可能失去本机记录，应另存原 operation_id；HTTP 原生回执和服务端冷恢复不受本机记录丢失影响。

版本状态与所有正文来源的最终授权仍由 Engine 控制。旧式 file-history 聚合同时过滤 Retired 正文所耦合的路径/标签事件，避免将归档记录重新投影为有效节点。

## 原决定中的真实多连接分组

本提交把共享内容拓扑的有限索引/分组算法共用到当前联合图、条件分析和真实退役决定。非空 `content_hash + logical_size` 构成连接，但选择仍按版本 ID 删除：同一文件另一个相同正文版本、另一组不同的共享正文，或经第三个文件的传递路径，任意一种仍存在就不能拆分。文件内的时间父边断开不创建新文件身份。

`file.nodes.retire` 决定新增 `separation`：准确源根下完整原分量的稳定文件、当时全部有效版本 cohort、固定身份/内容承诺摘要，以及删除明确选择后的分组。生产规划和热发布验证从真实 previous State 再算完整分量，不接受 UI 提供的分组。所有文件恰在一个分组中，所选版本必须属于该完整 cohort。当前查询仍排除已退役节点，动态计算剩余全部关系，不靠缓存的分组冒充当前图。

冷恢复按收据的冻结 cohort 核身份/内容摘要并重算原分组，**不使用今日 content_state、HEAD 或后来的版本重判历史决定**。后续退役可以继续拆分，后续相同内容保存也可以重新连接有效节点，但不能改变旧收据或复活旧身份。HTTP Outcome 分开提供 `separation` 与 `cleanup`；文件详情显示原决定的真实分组并标清它不是今日图或清理证明。两种观察失败都不隐藏已发布事实。

本片开放一个真实执行范围，不创建第二种退役操作：已经从命名空间各保留 HEAD 消失、没有 D、当前路径上下文或目录引用的历史文件，可在原 `file.nodes.retire` 操作中选择全部剩余有效版本。它可以仍有独立文件分支 HEAD／选择／写入起点／合并记录，但必须把完整前沿作为永久认证证据冻结。当前路径缺失本身不够；任何不属于该准确前沿的 HEAD、冻结目录/Git、文件上下文、工作区或读取租约仍按原入口拒绝。来源历史的开放工作区仍保守阻止本次退役。

`file_terminations.files` 逐个记录准确 stable file_id 及其全部排序后的保留 version_ids，单次上限 64 个文件、65,536 个历史版本。规划从 previous State 获取完整集合，而不是只记录本次 512 个选择。已经在此前操作退役的版本也必须覆盖。终止没有额外 State 表，也不复用可撤销 D；原生收据成为终止事实的持久权威。写集仍只有内容终态和永久操作／作者／事件，不删除、伪造或改写历史 commit、namespace、分支或 D。

全 State 冷准入要求完全没有有效版本的每个文件恰有一个终止决定，终止集合与该 file_id 的全部真实版本逐项相等，且全部为 RETIRED。删除终止段、把它替换为空列表、遗漏旧版本、再向同一 file_id 添加一个没有旧 source 边的新 version_id，均不能重新接纳。后续正常发布保留原收据和退役 token，不能通过只换正文身份复活原稳定文件。相同路径重新创建一个全新 file_id 是另一个文件，不改写该终态。独立旧备份丢失全部新权威的情形仍在下述未完成边界内。

## 独立文件分支 HEAD 的永久归档

`file_terminations.files[].retained_frontier` 为必需的准确分支 ID 集与规范摘要，绑定该稳定文件的所有原分支行、原 HEAD commit 全记录、分支别名、合并行、当前选择／写入起点和选择代数。`file_node_id` 缺省的既有 file main 分支仍按其准确 HEAD entry 获取原正文身份，不制造新 HEAD。任何跨文件分支／别名／合并成员拒绝。

这不是把 BranchState 改成 Archived 或清空 HEAD：原字段、原 commit、原 parent/source 全部保持；只有本次全部有效版本进入 RETIRED。热发布仍是原有精确内容状态写集。完整冷 State 先重算相同前沿、核完整版本集合和唯一终止回执，之后仅对这些准确原分支 HEAD／合并证据关闭“活引用”检查。新增分支、删分支、HEAD／generation／别名／选择／合并行变化都使原证明不成立，不能通过更换同名盘或导入变形完整 State 复活该身份。

普通 purge 没有这一特许；永久执行从类型化完整 Decision 取已冻结分支集。只排除这些分支的活 HEAD 检查，读取租约、当前／保留 namespace、目录/Git、路径上下文、D 与开放／封存工作区原样保留。新建该文件分支的 workspace 在分配身份或写磁盘前即拒绝；节点/body/source 入口继续拒绝 RETIRED。其他文件仍可正常提交。

条件预览新增 `archived_branch_heads`，是 `affected_branch_heads` 的排序唯一子集。已知 namespace／D／路径引用阻碍时原 HEAD 不进入该集合；其他损坏和资源错误不降格为许可。Web 仅当全部受影响 HEAD 属于条件候选且没有 D 才开放最终确认，服务端仍重做当前完整决定和全部运行时准入。它不是租约或持久发布凭证；[保留文件发现页](detached-history-discovery.md)也不能替代这一完整检查。

每个文件前沿最多 256 分支、512 合并事件和 65,536 个 HEAD entry；最多 64 个本次终止文件。摘要输入不含正文，但会读取完整匹配记录；捕获／冷核对仍按终止文件扫描保留 State，并序列化有界前沿，不宣称增量或常数成本。创建终止分支 workspace 的提前拒绝也扫描该稳定文件版本，最终权威仍是全 State 的永久收据闭包。

本片没有新增离线盘重新接纳者、外部退役目录或独立旧备份权威。原副本 slot/generation 义务继续保留，撤销／换代旧盘仍 pending；既有读 gate 与原发布证明要求未降低。包含完整新退役收据的 native State 必须保留冻结前沿，缺新必需字段明确拒绝并保留材料；RETIRED portable 包仍拒绝。

新增三个回归源码并调整原分支 HEAD 场景与终止夹具：完整分支前沿终止／冷开／新 workspace 拒绝、namespace/D 保持拒绝、cold 前沿篡改与 wire 必需证明边界。未编译、执行、审查或运行 CI，不构成验证结果。

## 冷恢复与不复活

全 State 先完成结构/引用准入，再验证反向闭包：每个 `RETIRED` 必须有唯一、正确作者/请求摘要、成功状态和准确事件的退役回执；每个永久回执选择仍必须为 `RETIRED`，归档证据摘要仍准确。删除回执、改作者、删事件、裸写 token、回到 Available/Purged 或更改归档记录均拒绝。

决定同时冻结所选正文及耦合事件的既有入向引用集合：内容来源、commit 正文/待写条目、路径/标签正文和父边、显式父覆盖，以及历史冻结目录树的正文/上下文。每个引用绑定种类、原记录身份、位置及目标 ID。冷读必须与原摘要和数量一致；新增对象指向退役身份、删改既有入向引用不能伪装成“旧认证材料”。这不依据容易保留旧数值的复制版本 sequence 猜测新旧，也不会把后来当前 HEAD 当作历史证明。

所有新发布及注册表重放都运行同一守卫，历史复制快捷路径也不能绕过。旧不可变来源继续作为证明，但新版本、commit、路径/元数据节点或父覆盖不能重新引用退役身份。原版本行不被当作读取/写入准入。

**完整 native State 恢复与 portable history 包不同。** 当前包不含完整 operations/principals，故含 `RETIRED` 的历史明确拒绝包导出、包准备备份、包读入及现有 history split；不能把缺失回执降格为 Purged。后继须扩展可携带审计协议后才能开放。外来盘逐版本检查遇到 `RETIRED` 也明确拒绝缺少闭包的材料。

本地当前权威仍保留退役事实时，旧状态不能覆盖它。完全移走所有新权威并恢复独立旧备份、把旧字节作为全新身份导入、离线旧盘重新接纳，仍需外部/逐盘持久退役权威协议；本片不声称解决这些情形。

## 有效图与归档证明

有效版本索引先排除 `RETIRED`，再按全部剩余非空内容计算传递闭包。只有最后一条连接消失才分组，内部断点不拆文件。耦合路径/元数据节点也同时离开有效图；显示祖先穿过退役节点到最近有效祖先，原证明不改写。

有退役记录的历史暂不使用仍包含归档节点的 SQLite 历史分页索引，回退权威有界扫描。HTTP 真实 Engine backend 的版本/来源准入也拒绝退役身份；普通 `file_history`、node/version/source 查询、内容匹配、节点来源和父投影同样使用有效域。原始 State 与历史 commit 审计是认证证据读取，不是可复活的节点 API。

## 原副本义务与当前路由清理

只读 `inspect_permanent_removal_cleanup` 仍用于未退役的条件选择。执行及恢复则按永久回执的准确版本集，观察原 `cleanup_routes` 与新根下当前 routes 的并集。

每个明确 slot + binding generation 分别返回 `NotRequested`、`MissingTombstone`、`PayloadPresent`、`VerifiedAbsent` 或保留具体原因的 `Unverified`。HTTP/Web 只有完整原义务与当前路由的非空结果全部为 `VerifiedAbsent`，`all_required_bindings_absent()` 才为真；只读的 current-only 观察不能替代原义务完成。缺失墓碑、缺失版本身份、不可读、错误归属、停止的 I/O gate 都不是成功。


真实退役决定从 previous State 的 placement 冻结每个所选版本的原 slot/binding generation，最多 4,096 绑定。热发布重建完全相同的集合；原生回执永久保留，冷态验证其排序、唯一性和完整版本覆盖，但不拿今日 placement 改写原义务。路由缩减、slot 重用或换代，不会把原离线副本从报告中删除，也不会把替代盘上的空路径算成原副本已清除。

普通冷恢复 `cleanup_purged` 与原操作重试继续原绑定和当前绑定的并集。只有仍正式注册且 generation 精确相同、原 held-root/I/O gate 和身份准入成功的目标才进行 I/O；缺盘、退出、换代只保留 pending，不重开被封锁的根或私自接纳旧盘。写入 RETIRED 墓碑及同步 unlink 前再次核本地 `version.json` 与独立原版本发布证明；已存在的合法墓碑不会阻止幂等继续清理。

响应增加 scope、binding_generation、original_requirement。Web 对照同一原 operation 中的永久 binding 集核对逐行完整性，拒绝漏掉离线原副本、混用新的 generation 或仅报 current routes 的“完成”。正文缺失观察仍是区间事实，不是持久擦除回执；以前未记录的过往路由、已退出旧盘和外部副本不由这个集合凭空补齐。

一旦查找观察到任一位置正文，就保留 `Present`，不能因后一次 stat 变成缺失而跳过另一位置。两处都观察缺失才能得到 `Absent`。

观察仅证明声明的原义务/当前 routes 并集的区间状态，不证明过去 unlink 的 fsync、退役盘、外部副本或断电后擦除终态。调用方不能把 `Published` 或 SQL 状态替代实际核验。

## 资源及未验证边界

- 完整联合图沿用 65,536 版本索引、64 文件、512 事件、256 分支、2,048 父边和 1,048,576 扫描步预算；条件分析另有 1,048,576 步。
- 显示祖先展开最多保留 65,536 个节点/前沿，并计入调用方扫描/取消预算；超限整批失败，不返回截断祖先。
- 当前副本观察上限为 4,096 副本、64 MiB 证明/布局读取和 131,072 检查点；总观察预算不作为元数据损坏撤销健康代数。
- 原分组 cohort 最多 512 版本、64 文件，摘要只编码有界身份/长度/内容承诺，不复制正文或全提交。单个退役决定最多保留 65,536 条入向引用的承诺；只为匹配引用分配有界集合。冷热引用核对仍扫描完整保留表，复杂度随 State 和退役决定数增长，不声称增量或常数时间。
- 执行源根按当前固定分页格式重建准确历史根；回执闭包扫描保留操作/事件/状态及引用，冷恢复本来就是全 State 工作。不是 O(选择大小) 或常数成本。现有同步清理仍扫描所有已授权 tombstone，未改成独立后台调度或增量清理协议。
- HTTP/Web 仅有上述受限动作与[本机原请求恢复](node-retirement-browser-recovery.md)，不实现所有副本持久擦除终态、离线旧盘擦除、任意旧包复活防护、真实掉电/掉盘/租约竞态证据或生产部署；浏览器记录不是服务器或物理擦除权威。
