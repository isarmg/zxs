# 在线磁盘成员管理提案（未实现）

[服务端](../components/server.md) · [API](../15-api-and-errors.md)

当前仅实现登录后的首次存储激活与原意图补全。已有池的在线添加、移除、成员迁移尚未实现；本提案不发布 API、schema、可点击占位操作或部署步骤。旧 `POST /api/admin/disks` 的不支持行为不能作为增盘实现。

## 准入与事务要求

1. **只读预览**：绑定池身份、当前拓扑代数、目标挂载及目录身份、动作、数据与副本影响、元数据成员影响、所需／可用容量和阻断原因。目录浏览或 SMART 正常不等于可用独立副本。预览不得改动成员或文件。
2. **明确提交**：用户审阅预览后，以永久 `operation_id` 和精确预览摘要提交。任何目标、代数或影响变化均须重新预览；提交线性化点复核管理员权限和目标身份。相同键与相同意图返回原结果，不能因断线生成新键重发。
3. **持久长事务**：记录已确认阶段、迁移计划、验证证据、已完成工作与下一恢复步骤。状态至少区分准备、迁移、校验、待发布、已发布、拒绝及需恢复；具体 wire 字段须随实现另行设计。客户端关闭不取消已接管工作，服务重启从持久证明恢复，不能把“任务接收”显示为完成。
4. **历史与元数据闭包**：既有历史正文、证明、引用对象与元数据成员须联合迁移并验证可恢复性，再发布新成员权威。旧／新成员交接规则和 quorum 需单独设计证明，不能先删除配置或丢弃历史证据。容量不足、成员离线或证据不完整时保留原权威，公开具体阻断原因。
5. **移出与擦除分离**：默认移出只解除已安全迁移成员的活动关系并保留盘上数据。不可逆擦除是独立、显式的破坏性动作，展示精确设备／目录、数据范围与不可恢复后果，要求第二次确认；移出批准不授权擦除。取消只能发生在有证明可撤销的阶段，已发布结果不得伪称回滚。

## 实施前验收矩阵

| 场景 | 必须建立的证据 |
| --- | --- |
| 添加独立成员／同设备别名 | 正确区分物理独立性；别名不得提升保护级别 |
| 预览后改挂载、换目录、改变拓扑 | 提交拒绝旧预览，无成员发布或意外写入 |
| 空间不足、权限变化、目标掉线 | 返回具体阻断，旧池仍可按原保护规则恢复 |
| 提交响应丢失、重复提交、并发提交 | 原 operation_id 可查询；相同意图不重复迁移，冲突意图不覆盖 |
| 各持久阶段进程退出／重启 | 逐阶段故障注入，恢复不依赖浏览器；确认结果及证据不丢失 |
| 撤权、关机、资源耗尽 | 发布前重新授权；任务有界、可等待关闭，错误不被包装为成功 |
| 有历史与删除证据的成员移出 | 当前和历史读取、恢复证明均覆盖；不能仅验证最新正文 |
| 元数据成员变化 | 旧／新 quorum 及各中断点恢复测试通过后才开放能力 |
| 保留数据移出／不可逆擦除 | 两动作隔离；未二次确认不执行擦除；移出后原数据保留可验证 |
| 浏览器返回、刷新、关闭、重登 | 原操作持续可查，旧响应不能覆盖新会话，不重复提交 |

先完成核心持久事务与故障矩阵，再公开预览／提交／查询契约和 Web 控件。真实设备、物理掉电、生产挂载与部署验收另需授权；临时目录测试不能替代这些证据。

发现范围以服务端持久设置为准：默认 `/zxs/data/disks`，可由当前管理员以原值比较更新为其他真实目录。只列其内部目录，根本身不可激活；预检绑定发现根身份，提交再次验证。范围变化不搬迁现有成员，不增加 mount/格式化权限。首次管理账户是公开的一次性设置，不需要 bootstrap；既有恢复授权保持独立。
