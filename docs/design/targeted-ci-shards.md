# 同一提交的有界定向 CI 分片

跨 crate 类型变更必须连同全部消费者原子发布，不能为了单次 CI 选择上限拆成不可构建的提交。
本配套只改变完整已审选择的调度，不删除路径规则、选择组或测试，不开启完整工作区测试。

## 准入与预算

`select_plan` 默认仍拒绝超过 16 个 Cargo 构建或 8 个 Python 模块的单片计划。
工作流 planner 显式请求完整选择，先执行同一套路径、目标、特性、测试前缀、数量、超时准入，
再按确定顺序将完整构建身份和 Python 模块分配到最多 16 片。
每片仍至多 16 个 Cargo 构建和 8 个 Python 模块；各原始目标的前缀、精确测试名数量上限
仍各为 16，单测试超时仍不超过 900 秒。合并构建的各来源 selection 独立保留原预算，
不把它们压成放宽上限的单一测试列表。每片原 90 分钟 job 预算不变，最多并行 4 片。

完整选择超过 256 个构建或 128 个 Python 模块仍拒绝。空选择、未知路径和任一非法选择
在拆片前拒绝，不通过“只验证能放下的一片”规避门禁。

## 同一精确输入与完整证据

planner、每片和最终聚合都检出同一工作流 SHA；仍以 push 的 before 或明确的完整 ancestor
comparison_base 做 diff。planner 输出 head、base、policy SHA256、完整 plan SHA256、片数和索引。
每片重新读取策略和 Git diff，从完整选择重建分片，逐项核对这些身份，不接受调用者自报的目标列表。

每片执行既有当前 Cargo artifact、inventory、非零选择和精确测试结果检查，保存独立 artifact。
最终聚合重新计算同一完整计划，要求每片恰有一份收据，head/base/policy/plan 完全一致，
计划与应选片相等，无失败、跳过或阻断；并逐项核对 Python 非零执行、编译检查、Rust 当前
inventory 所选名称与实际通过记录。少片、重复片、其他提交、仅写成功标签或部分执行都拒绝。
最终 `all-selected-shards-passed` 只表示这个提交的完整定向选择通过，不表示全仓覆盖。

## 上线范围与验证状态

此基础片不引入尚未落地的容器标签 Rust 测试名；功能策略增量须与完整生产消费者同批提交。
基础片保留现有 `ci-selection` 的 7 个 Python 模块，新增 helper/doc 规则也指向该组。
新增分片行为测试收在既有 `test_targeted_ci`，不额外增加 Python 模块预算。

尚未本地运行编译、测试、格式化或验证脚本。GitHub 定向执行后才可记录准确通过结果。
