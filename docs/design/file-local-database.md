# 文件内部数据库投影

`.zxs-file.sqlite` 是单个稳定 `(history_tree_id, file_id)` 的有界 SQLite 投影。它在普通文件的现有物理容器内保存版本元数据、独立分支和选中分支、标签、备注、合并记录、无路径的节点锚点、当前 D 及永久收据中保留的历史 delete/undo 事件。数据库不保存文件的外部路径、前一路径、磁盘路由或命名空间提交内容。路径事实仍属于系统和数据盘根的范围；现存 `container.json` 仍是旧检查缓存，不是本数据库，也不是独立恢复权威。

## 真实写入边界

- Engine 的同一候选在决定前从被冻结 State 和与之绑定的派生所有者索引构造数据库。历史旧 delete/undo 来自永久收据，而非只看当前 D。热增量索引与冷重建使用同一精确归属。
- 只有实际存在的容器进入安装。不存在的正文不会被数据库生成伪装成独立 FULL；数据库本身不证明任何正文完整或副本路线已满足。
- 安装器保留实体目录 fd、旧库 fd/完整摘要和精确新字节，暂存只在历史根的 `.zxs-layout/database-installs`。首次无覆盖安装；更新以交换保留旧物，不把 EXCHANGE 称作 inode CAS。未知数据不删除、不覆盖后假装成功。
- File 和 Directory 共用按磁盘/历史合并的保留额度，不能各自独立通过后在决定后超额。已决定恢复不因自己的孤儿暂存消耗行政额度而放弃决定；实际 I/O/格式/身份错误仍失败并保留全部材料。
- 只有 Finalize 后的名称发布或最终已准入 State 的修复调用安装。历史前缀缓存重放不写文件数据库。安装前后核最终实体名字仍指向捕获的 inode；异常进入现有不确定结果/恢复通道。

## 格式检查不等于授权

数据库枚举全部受支持 schema 对象，逐行有界解析闭合类型；每行归属绑定头部 history/file；节点和生命周期序号不得超出捕获序号；当前 D 必须等于所有保留分支当前 HEAD，历史 D 则只核其保留端点和历史时序，不拿今日 HEAD 重判过去。

自摘要只能发现损坏，不能证明完整历史未被删减。删掉一对旧 delete+undo 后重新计算摘要可能仍然结构自洽。安装器因此必须比较从当前已准入 State 重建的**精确字节**，不能将 `verify_scope` 当作授权或完整复制证书。

## 限制

- 每库 16 MiB、65,536 行、编码记录 12 MiB；一轮文件数据库总输入 64 MiB。目录库另有 64 MiB 构造上限，安装保留额度按共同历史累计。旧物不自动清理，超额拒绝新的写决定，需明确审查处理。
- 该库不是独立盘恢复的选举、签名、收据或配置权威。单靠它不能重建全部系统状态，也不宣称三份数据库要求全部完成。精确源字节绑定只证明投影忠于捕获 State，不替代上游 State 生命周期的完整准入；本片未补齐旧软删除 cold admission 的反向闭包，不能把 SQL 生命周期检查当成那组冷 State 负例已修。
- 不新增 `file.history.move`，不在 SMB 返回完整跨盘移动成功。现有受限 `file.history.copy` 仍保源，仍受原有正文/备份规则准入；本片不放宽这些限制，也不补全它对历史 D 的映射。
- 独立的 [`file.history.copy.retained`](retained-history-copy.md) 可将完整映射的旧 D/undo 审计封存在目标自己的复制收据中并写入文件数据库，不改变旧 copy 的回执语义。导入审计不是活动 D；本池冷恢复不等于离线历史包已包含收据或完成独立恢复。
- 用户确认的移动协议仍要求完整目标历史/数据库/标签及正文证明，源基线未漂移，单一决定同时产生目标和连接所有分支末端的源 D。DB 投影是前置切片，不等于该协议已完成。

验证记录应另列实际执行、失败、未执行和环境限制，不以这些设计说明代替测试。
