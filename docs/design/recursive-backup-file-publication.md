# 逐跳备份文件路径的原生发布

本切片新增显式 `backup.configure-recursive` 原生操作以及
`GET/PUT /api/repositories/{repository}/recursive-backup-configuration`（Server `core` 特性）。
它复用完整副本发布事务，实际更新文件容器的物理正文位置与持久路径映射，
备份目录读取直接消费同一映射。它不是只读预览或独立摘要模型。

## 路径与来源

每跳只在直接来源盘已有的完整路径前增加该盘名。例如一级盘 A 的
`目录/文件`，二级盘 B 为 `A/目录/文件`，三级盘 C 为 `B/A/目录/文件`。
命名仓库在一级磁盘路径中包含仓库名；磁盘根仓库不增加仓库名。
文件 scope 保留全部父目录，目录 scope 保留自身与祖先路径，不截成相对 scope 的名字。
当前盘名取已登记配置根目录的 UTF-8 basename，并按名称规则验证。

捕获值保存原始 State 序号、业务代数、登记承诺以及各启用盘的完整身份、
层级、直接上游和盘名。新提交在同一 Engine 事务内重新捕获并比较，拒绝过期、
改名、重绑定、删盘或来源变化。实际规划仍逐跳检查当前登记与启用状态，
不能借同名路径或新盘替代原来源。目标盘自己的名字不进入它自身的备份路径。

## 重试与恢复

捕获值是带严格字段的请求证据，不是 I/O 能力。原生请求摘要包含该值，
永久幂等重试必须使用原请求；幂等命中先于当前捕获检查。使用同一操作 ID
和重新读取的捕获值不是原请求重试。

发布与冷重放从原始前驱登记和原请求重建相同策略、文件路径、绑定与完整
版本副本列表，逐项核对收据、事件、State 写集和 Candidate 载荷。
冷重放不从今天的挂载路径重新取名。原有原生完整复制、启用来源、精确
来源绑定和降级恢复拒绝规则均保留。

此操作不添加旧格式默认值或迁移。原 `backup.configure` 仍是用户显式指定
前缀的另一种操作，新请求不能以旧操作类型重放；旧收据不增加新必填字段。

软删除文件的保留 Entry 和可用历史正文仍可进入目录 scope 的备份规划，
但备份写集必须保持 `file_deletions`、逻辑命名空间、分支和节点完全不变。
发布、冷重开及永久重试不会恢复当前一级命名空间的可见性；撤销删除仍需
精确删除节点。备份盘读取继续展示其可用历史版本，本操作不声称隐藏所有历史副本。

## 当前边界

- 文件 scope 发布文件容器及现存可用历史版本。独立选中的无文件目录 scope 可向元数据成员发布
  [空目录快照](../adr/empty-directory-backup-publication.md)；含文件 scope 中的空子目录需另行选择。
- 已配置 scope 内后续新增文件沿已有策略继承同一完整路径规则。
- 已保存且包含文件的递归配置按[新原生路径跟随语义](../adr/recursive-namespace-follow.md)
  跟随主逻辑路径 rename/move；原收据、捕获的仓库／盘名前缀和空目录快照不被事后改写。
  空 scope 后续新增文件，仍须显式完成一次包含文件的递归重配置才启用自动跟随。
- 需要已经接纳的当前登记视图；初始登记尚未进入该机制时明确拒绝。
- 仍使用当前固定路由与全体副本事务，不新增不同磁盘独立的 namespace 提交协议。
- Web 文件页提供独立逐级备份复核入口；保存明确替换该范围的自定义前缀。

## 验证与成本

根 `test/engine/integration/recursive_backup_paths.rs` 提供公开 API 的真实写盘、
历史版本、三级路径、磁盘根路径、新增文件继承、冷重开、幂等和来源拒绝回归。
同一 scope 内两个一级盘及各自的三级链另有实际正文路径与冷重开回归；
这不代表支持多个一级盘共享同一备份槽的另一种拓扑。
私有 Engine 测试另核对伪造 State 的实时与冷重放拒绝；Server 测试核对同一路径
映射进入现有备份树读取及严格 HTTP 请求解析。实际执行结果见交付记录，
测试源码或 metadata 编译本身不代表这些运行测试已通过。

捕获与验证在当前启用盘数上进行一次有序遍历，捕获大小为 O(D)。
前缀计算沿请求涉及的固定路由增长，既有 scope、历史版本规划及完整正文复制
成本不变。没有新增磁盘扫描、后台轮询、同步阶段合并或 fsync 减免。
