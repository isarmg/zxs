# 辅助工具准备后的普通启动前置门禁

本片基于 `9375fae1` 首批初始化。它是正常 `zxs` 可执行入口的**首启准备门禁**，不是全盘完整性证书、全路径干净运行门禁或完整首次安装。按要求没有编译、测试、审查、CI 或实际主机操作；测试仅新增/调整源码。

## 入口与拒绝

CLI/日志配置处理后，当前二进制仍先取得固定 `/zxs` OS 生命周期租约。随后、在 Tokio runtime、HTTP/SMB 监听、spool 或管理后台恢复之前，持有已存在的 SYSTEM 与 management 私有目录能力：服务身份所有、0700、拒绝链接与替换，不 create/chmod 任一缺失根。

- 目录缺失、不安全或不可读：明确退出并提示独立 `zxs-helper`；不把缺失当作初始化授权。
- 普通 SYSTEM 缺少受保护的 `config.json`：拒绝。空目录、只有首次管理员的管理态均不能启动 Web 首次设置或自行建立账号。
- 有当前 `management-initialization.json`：要求确切当前编码与确切 `management-authority.json`，不能把坏意图当作既有池。
- 使用共享 `activation_admitted` 核对当前初始激活意图、完成回执、配置及已支持的后继配置绑定；中断/不匹配拒绝，保留原材料供 helper 原请求恢复。该共用检查可能同步已存在控制文件及目录以重建耐久证据，**不是纯只读扫描**；不写新配置、账号或完成回执。

当前已恢复系统可以没有“首次管理”意图，但仍须存在配置文件，并由原生 Engine/凭据权威后续验证。本片不增加旧格式解码或将存在配置等同可读写。没有意图的损坏配置保留原管理诊断路径，真实失联/损坏仍返回故障，不生成空替代盘。

## 终态与持有能力

SYSTEM 的终态/成员中断选择优先于普通首次激活检查，仍由 `TerminalManagement` 检验当前证据。这里只读 SYSTEM，不打开已退出数据成员；选择管理分支不代表终态健康或恢复成功，后台原有终态 owner 仍须证明具体状态。若连终态选择证据也不可读则拒绝，不能猜成新系统。

普通管理工厂接受上述 `PreparedService`，凭据 writer 使用从已持有 management 目录复制的 fd，不重新接受同名替代目录。SYSTEM 目录能力进入后台恢复 owner：启动与后续恢复只能核对既有管理权威标记，标记丢失/损坏不会被后台 `claim_authority` 重建。低层库的显式 setup/recovery 工厂保留原创建语义，供已授权辅助/恢复调用；不作为普通二进制的旁路。

根目录能力与 host 租约跨 runtime 销毁及阻塞任务排空持有。使用/退出点复核名字、inode、owner、mode；复制 fd 不锁住命名空间，也不防止不参加协议的 root/旧程序。既有显式灾备操作仍遵循自身授权，不被普通后台策略隐式代做。

## 已迁与未迁

正常空系统的第一次运行现在要求先用 helper 完成准备，不再启动一个可匿名创建首个账号的普通服务。但不删除共用 setup/recovery API，也不宣称所有旧 Web 磁盘接口已经迁走。

仍未完成：所有运行入口的未知/外来候选排除、全部数据/标签/三层数据库一致性与正式成员准入；完整首次安装交接、运行目录/VFS/依赖、systemd/Samba 校验与启用；真实 SMB passdb 重置、完整外来低级链接纳。首批 helper 回执的 `complete_installation_ready=false` 与 `clean_start_gate_installed=false` 继续表示这些最终目标未完成，本片不伪造总体 ready。主服务仍需保留真实故障诊断。

前置读取最大配置正文 64 MiB，管理意图/权威各 4 KiB，激活证明沿用核心控制记录上限。只持有两个目录 fd 及所需克隆，没有全盘数据扫描或新线程；共享耐久屏障不裁剪。新增源码描述空根/管理态拒绝、错误不修复、意图/权威异常、目录替换、初始激活成功/中断及失联盘交给 Engine 的边界；尚无执行结果。
