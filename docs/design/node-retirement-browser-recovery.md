# 节点永久退役的浏览器原操作恢复

本片接续[永久节点退役](permanent-node-retirement.md)的 HTTP/Web 入口，解决刷新、重新登录及文件不再出现在列表后丢失原操作入口的问题。**源码候选，未审查、编译、测试、格式化、浏览器验收或 CI；不操作真实盘。** 它没有改变 Engine 决定、共享图分组、普通软删除/撤销或 SMB 能力。

## 首次提交与保存边界

首次永久提交仍只来自文件详情中的准确版本选择、影响预览和不可撤销确认。发送 HTTP 请求前，浏览器先写入并读回一个不可变恢复记录：当前登录主体、稳定 file_id、准确 history_root、全部排序后的 version_ids、原 operation_id 和仅用于显示的文件路径标签。保存失败、已有未处理记录、读回不一致、当前格式无效或资源超限时不发送新的永久操作。

记录使用 localStorage 的站点隔离，再按经过编码的登录主体隔离。每个 operation_id 单独占据一个键，不采用可被另一标签页整体覆盖的“单个队列 JSON”。记录不包含密码、认证/CSRF 令牌、正文、发布结论或副本缺失结论。文件名和身份等元数据会保留在该浏览器的站点存储中，详情与恢复入口明确告知。

本地记录不是服务器权威。严格解析固定 `file-node-retirement-recovery` 格式、类型化操作/文件/根/版本身份、非空排序唯一选择，并核键名、记录主体与当前账号一致。未知字段、重复字段、缺字段、旧格式及另一账号/键明确拒绝，原材料保留，不双读、不重写、不清空。

## 恢复不是自动重发

登录完成后读取本账号的记录，把原 operation_id 加入既有有界回执轮询。只查询原收据，不自动发送不可撤销动作。每条未打开的记录也核对退役种类、原文件、原根和全部版本，不能由另一个 operation/请求的收据解除围栏。

全局恢复面板不依赖当前目录、详情页或原文件仍可见。用户可打开一个原操作：

- 服务器确认原发布：只能使用原 operation_id 和原文件 URL `resume`。清理观察重新请求，不从浏览器恢复旧“已缺失”结论。
- 发布仍未知：展示准确文件、原根与全部版本，必须重新勾选不可撤销原请求的确认才可重发。始终沿用原 operation_id，不因 404、4xx、重登录、切换记录或读取失败换键。
- 恢复出的记录始终以 `uncertain` 开始。后续 4xx 不能证明更早的请求没有发布；仍保留原请求而非自动放弃。
- 同一会话的首次新请求明确拒绝，或原发布已知且本次全部原义务/当前路由均观察缺失，才可关闭确认结果。先核对并删除该准确恢复记录，删除失败保留界面入口，不删除其他操作。

控件携带渲染时的 operation_id 和会话代数；请求、重发确认和结果关闭仍核当前登录主体。旧会话的异步响应不能更新新会话，旧控件不能转向新打开的操作。结果未知的原操作继续使用现有写入围栏。不同文件仍保持独立身份，原操作返回的分组与当前联合图、正文清理分别显示。

## 资源、并发与限制

- 单条记录最多 64 KiB、路径标签最多 4 KiB；每账号最多恢复 32 条；一次最多枚举 4,096 个站点存储键。超限整体失败，不返回截断队列或删除旧材料。完整恢复记录的读取/解析总量至多 2 MiB，另有有界键扫描。
- 仅登录/会话恢复、明确重新读取及首次提交扫描 localStorage，不在心跳或每节点渲染中扫描。沿用既有原生回执轮询，不新增后台永久写任务。
- 独立键避免不同操作互相覆盖，不把 localStorage 枚举伪装成跨标签页事务或锁。另一标签页新增/完成记录后可以明确重新读取；服务器原生幂等、准确请求和当前授权仍是最终执行边界。
- 本机记录不等于外部备份或持久擦除证明。清除网站数据、私密窗口结束、浏览器驱逐/损坏、换浏览器/设备、站点来源变化，都不保证保留或迁移该记录。界面要求另行保留原 operation_id；不会宣称浏览器写入具备磁盘 fsync 或断电证明。
- 不新增孤立历史文件发现页、带 namespace/D 的共同终止、离线旧副本接纳或擦除、旧认证记录物理删除。普通删除继续软删且可撤销，没有因本片获得永久删除权限。

新增六项纯模型/边界回归源码：记录往返不恢复成功、坏记录与账号/键隔离、未知恢复须明确确认、队列每条准确请求匹配、已知发布只继续原操作且不恢复旧清理、重登录后的旧控件拒绝。它们没有执行，也不代替实际 localStorage 配额/禁用、多标签页、刷新/退出/重登、网络未知结果和真实浏览器验证。
