# 跨盘移动的共同决定输入与未闭合义务

本片对齐 `288eefd1`，承接 `f5f623e9` 的[原恢复封套](file-history-move-recovery.md)、[完整目标文件材料](file-history-move-target.md)上推进一个真实持久化步骤：把同一原 operation 的完整拟议 State、源 D 后完整文件库、目标完整文件库、目标逻辑图和旧审计，以及系统／盘根／文件三个范围的明确要求，写入同一不可变输入清单并逐根读验。

**这是决定输入，不是决定。** 没有 journal Candidate、PREPARE、ACCEPT、永久成功收据、operation/slot 预留、在线容器安装或 namespace 发布。不能凭本报告把源隐藏、开放目标编辑或返回 SMB rename 成功。不能将“范围要求已绑定”说成“三范围数据库已证明”。

## 同一原操作的材料

`prepare_file_history_move_decision_inputs` 必须先完成原恢复封套和全部目标 FULL 的独立验证。目标缺正文、校验失败、缺少任一原恢复副本、取消或来源/配置/命名空间改变时，不开始本步骤的写入。

系统根、全部原配置元数据成员，以及全部源／目标保留版本路线成员，共享完全相同的 `file-history-move-decision-inputs/inputs.json`。盘位集合按真实 disk ID 去重，不因同一盘承担元数据和正文角色而重复计数，也不以健康少数代替全部成员。每个源放置绑定与目标冻结绑定都必须对应当前启用登记；只固定 slot 文本不够。

清单逐项绑定：

- 原 operation、恢复摘要、拟用而未预留的 sequence，以及共同逻辑投影摘要；原 actor、时钟、配置和双端 namespace 继续由准确恢复封套绑定。
- 源 D 的全部分支 HEAD、去重父集合、源 file/history、原 operation 与时间，不另造一次 delete。
- 系统范围：原已发布 snapshot、完整未接受 State 的摘要和长度、准确元数据成员集合。
- 每个盘根范围：准确 pool/disk/slot/binding 和元数据／源／目标角色、全部源版本 placement、目标冻结 route，以及完整版本／分支 ID 映射。
- 文件范围：源 D 后 FILE SQLite 与目标完整 FILE SQLite 各自的 file/history/records hash。
- 每个目标盘的每个 FULL，独立读验时取得的原复制 inode／属性记录摘要。后续即使相同字节的新 inode 和一份修改后的 marker 彼此一致，也不能改变已经持久绑定的原输入。
- 五项尚未闭合的明确义务。它们不是可被读取端默认为通过的 bool，也没有将清单转成 ACCEPT 的入口。

## 真正新增的源文件库

源库保留原文件全部版本、分支、父边、标签、备注、合并及完整历史 D/undo，追加同一原 move 的唯一新 D 审计行。当前 D 与全部保留分支 frontier 对应；目标库只继承映射后的旧审计，不导入新源 D 为目标的活动删除。

这通过专门的未发布文件材料编码入口完成，输入是共同投影及当前准确来源。没有在真实 State 中伪造 `file.delete` 或 `file.history.copy` 收据，也没有放宽现有已发布文件库的正常收据验证规则。SQLite 独立读验仍核严格 schema、行关系、scope、sequence 和全部 records hash，并与本次独立重建的预期比较。数据库自摘要正确但事实不同仍拒绝。

所有参与根均保存 `joint-metadata.json`、`source-file.sqlite` 和 `target-file.sqlite`。**完整池 `unaccepted-state.json` 只写系统和已有元数据成员根。** 它包含原永久 operations/principals/events 和控制数据，以及目标图＋源 D 的共同拟议变更，故不会传播到仅承担正文的目标或源盘；普通文件移动不是复制无关系统凭据到正文盘的授权。

完整拟议 State 仍缺本次 move 的真实永久收据和事件，文件名与格式明确标为 unaccepted。它不是系统历史库、已发布快照或可直接传给 Engine 恢复安装的 State。这里保存整份原有记录是为原决定准备保留精确输入，不赋予未接受材料权威。

## 持久化与恢复边界

每根使用独占私有单槽。先写不可变原输入清单，再写该根职责要求的文件。命名根、stage 目录、系统 writer.lock／实际磁盘 seal、I/O gate 以及持有的读 fd 都参与检查；SQLite 与逻辑材料独立读取后复核文件 inode／属性和名字。新文件原子无覆盖写、原文件同步、stage 目录和所属根同步均保留。

已有相同清单允许补齐完全缺失的派生文件，重试不重采时间、不重新分配身份，不改 FULL。已有不同清单、损坏库、不同逻辑字节或只有目录而缺原清单均原样保留并拒绝，不能以新内容覆盖。任何写入后错误都说明可能部分保留，继续同一 operation；无自动取消、清槽、升级或删除。

完成复制循环后，独立逐根验证全部本次输入，然后重新读验全部目标 FULL 和原恢复副本。`FileHistoryMoveDecisionInputs` 只是当次观察，不是可长期沿用的租约、可反序列化许可证或 `OperationResult`。

- `verify_file_history_move_decision_inputs` 另核已查看的原输入 digest，纯只读，不补材料。
- 真正冷进程先使用原恢复封套重建原投影，再调用 `read_file_history_move_decision_inputs`。它无需保留旧进程的 token，但必须把所有存盘清单与独立重建的预期逐字比较，并重新验证完整 FILE/FULL；返回一个新观察，不采信自报完成状态。
- 显式 prepare 可以续写原清单下完全缺失的派生文件；无法读取任一必需盘时不返回完整输入报告。
- 无系统盘丢失恢复、自动旧槽回收或决定之后的恢复。本片不会将新业务写入锁死在准备槽；其他 State 发布会使原准备过期并保留，后续不能自动套用旧计划。

## 仍必须拒绝发布的五项义务

1. **单一永久 move 收据和双端审计归属**：现有正常源删除发布验证只接受独立生命周期事务，必须新增完整、闭合的原生 move 验证，不能跳过它。
2. **系统完整历史数据库**：这里的完整拟议 State 不是系统 SQLite 历史安装或验收。
3. **盘根完整历史数据库**：现有 current/history 派生库不等于此次源 D 和目标历史的一致权威证明。清单绑定准确各盘义务，不伪造已完成历史证据。
4. **真正 N 成员共同 journal 决定及原决定恢复**：须将完整材料纳入唯一 Candidate、全部依赖、固定 PUBLICATION 及崩溃恢复。准备文件不能提供多数 ACCEPT。
5. **双端读取围栏**：现有句柄、目录页和恢复后可见性须跟同一发布决定对应，不能先 copy 后 unlink。

报告固定列出这五项，不提供“全部准备所以成功”的分支。完整跨盘 SMB move、源隐藏和目标可独立编辑仍未开放。

## 资源与验证状态

共同 State 和逻辑图各最多 12 MiB；输入清单最多 2 MiB；每份 FILE SQLite 继续最多 16 MiB／65,536 行及原行数据预算。完整 State 编码前先计数，超限拒绝而非截断。每次只有一份有界材料在内存中、逐根顺序复制；保留现有元数据 reserve，配置容量包括本片输入和已知目标 FULL 准备开销。完整验证会重复扫描拟议 State、两个文件库和全部目标正文，不宣称常数成本或吞吐提升。

新增八项根 `test/` 回归源码：所有参与根与范围隔离、源 D/旧审计归属、两种配置的冷重建、任一副本缺失、无原清单残留保留、自摘要正确但事实不同的源库拒绝、目标 inode 与 marker 同换不能改绑、取消／损坏目标／变化来源拒绝。全部只是源码，**按用户要求未审查、编译、格式化、测试或运行 CI**，不构成真实 SMB、断电、三范围或共同决定验收。
