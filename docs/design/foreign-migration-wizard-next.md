# 外来历史迁入向导：下一阶段 UI

**职责与接入规则已修订：** 正式外来接纳迁入[离线辅助工具](helper-disk-management.md)。外来二级及以上必须同批显式设置并纳入全部所需低级链，三级同时包含二级和一级，不允许虚占位或以后另补。下述 UI 意图只记录当前尚不可执行的草稿，不能作为未来缺链接纳方案；保存计划/意图永远不是加入完成。

当前 UI 提供只读审核、系统盘计划保存，以及基于已保存审核的目标数据盘执行意图预览／保存／查询。意图仅为 `IntentSaved`，不是复制、接纳或命名空间发布；新一级接纳和三级降二级仍为本地草稿。写入执行与真实浏览器验收尚未完成。
现有服务契约见[在线磁盘管理](online-disk-management.md)。

## 真实能力与本地意图分离

1. **重建到已有一级的空目录**：使用现有 `ForeignPlanRequest`，通过服务端重新读取完整来源并核对目标一级、空父目录、各历史组与不碰撞名称。支持真实预览、明确确认后保存审核记录、查询原记录和只读重验。
2. **新一级接纳**：仅保存当前页面的类型化意图。填写明确槽位及完整逐历史映射；独立空复制目标只是可选设计输入。没有对应当前服务端审核能力，不发请求，不生成审核摘要。
3. **三级降为二级**：仅允许已核验三级来源，必须显式选择完整一级身份与绑定代数，不默认选中、不先成功再补上游。此模式同样仅为本地草稿，不能转换成当前审核请求。

后两种意图没有序列化实现，不能误发到现有 API。当前一级候选仅来自本页真实
已有一级审核返回的身份与检查点；没有伪造的一级列表。尚未提供全局一级身份
选择投影时，界面明确说明该限制。旧四元组与 sequence 不能替代未来协议的
origin、incarnation、role 和 publication checkpoint，不能自行猜测 epoch。
选中一级只完成旧本地草稿输入，不等于已经审核或接纳。正式辅助工具执行必须
改用完整低级链的同批计划；不能从这个旧草稿直接推出允许缺少二级或以后补盘。

## 来源与映射

映射以 `group_id` 为键，完整覆盖每份已经核验的历史，并保留 history identity、
原 pool/disk/slot/binding generation。相同仓库名或槽位名不合并来源；展示层
不会以物理路径充当可移植身份。当前 DTO 每份历史的 origin 语义不被 UI 改写，
未来多 origin 的历史关联须由新协议明确提供，不能强行归并到一个来源。

名称通过现有 PortableName/Path 规则检查；规范化后的目标重名拒绝，不自动改名。
空 parent 明确编码为 null，表示现有一级盘根；非空值是已存在空父目录的相对路径。
角色接纳究竟采用原盘还是复制尚未确定，不能把空目标说成用户已定前置条件。
若草稿选择复制目标，则拒绝同路径或相同 device/inode 的来源别名，ctime 改变不使其变成独立目标；
这只是拒绝已观察到的相同对象，不替代未来执行前的真实物理准入。
服务端预览必须返回同一请求、同一完整来源、同一来源摘要与每个精确目标路径。
首次目标槽位查找沿用服务端 ASCII 大小写等价规则；请求回显不改写，审核中的实际
完整目标身份和后续保存/查询/重验仍按原审核逐字段精确绑定。审核界面保留物理来源路径
及其已发布 checkpoint，不能只凭来源显示名确认。
缺失、重复、额外组、变换历史身份或路径以及未知字段均拒绝。

每个来源展示已核验正文与 `temporarily_unavailable` 数量。暂不可用正文继续
保留历史，不自动裁剪。已记录清除、已记录迁移继续使用原契约分类；未授权或
未获得证据不被推断为正文缺失。服务器超限/拒绝保持具体错误，而非部分“成功”预览。

## 不可覆盖与确认

本地输入完整不表示目标已经可用。界面先标记“尚未经服务器核验”；只有真实
预览成功才展示目标一级完整身份、检查点、审核摘要和逐历史实际路径。
预览是一次观察，不预留目录、空间或名称。后续变更需要新审核，未来执行前
仍必须重新检查且使用不可覆盖发布，不能将此 UI 验证当作文件系统保证。

保存按钮要求显式确认所有来源、缺失正文和不可覆盖映射，并明确只授权在系统盘
保存不可执行审核记录。保存成功只显示“审核计划已保存”，不显示迁入、降级、
重建或发布完成。`matched_at_observation` 也不解除执行阻断，执行按钮永久禁用，
没有任何执行端点调用。

## 请求与恢复边界

- 预览与读取受会话 epoch、页面 generation 和准确来源约束；过期响应不能覆盖新输入。
- 重复保存点击只发送一次。发送中和结果未知时保留原预览与原 operation ID，禁止编辑或新建替代计划。
- 未确认保存只查询或显式重试同一完整请求；查询 NotFound 不是未保存的证明。
- 明确客户端拒绝解除发送栅栏，但须重新审核，不能复用旧确认。
- SPA 导航取消只读结果的应用，不取消服务器的保存；未知原请求在应用状态中保留。完整浏览器重载或会话结束后的自动恢复尚未实现，用户仍需保留审核操作编号。
- 普通查询必须返回 `validation=required`，重验必须准确返回 `matched_at_observation`，且两者完整预览都必须等于原审核。
- 编辑真实字段会清除审核和确认；相同字段值不会无故丢失已审核状态。

## 成本与边界

沿用现有只读检查的 128 组历史、10,000 版本和 8 GiB 本地正文预算，不另起正文扫描。
本地映射按历史组与规范化名称建立有序集合，成本为 O(H log H)，显示与响应比较仅使用
既有摘要。仅显式保存调用现有系统盘审核记录写入；没有新增数据盘 I/O、fsync、锁或发布协议。

## 验证范围

独立测试覆盖多来源同名、完整映射、命名碰撞、精确目标、三级角色与一级完整身份、
不支持意图不产生现有 wire、明确确认、重复点击、保存不确定、导航与过期读取、
严格响应及不能伪造执行成功。具体运行结果另录；源代码断言或模型测试不代替真实
Chrome、真实服务 API、数据盘发布或故障恢复验收。没有改变来源格式、生产 API、
依赖版本、共享冻结树或已发布提交。

## 可选的目标盘执行意图

已保存系统盘审核后，才显示独立的执行意图步骤。它接入已有的
`execution-intents/preview`、`save`、`status` 三个端点，不调用
`plans/execute`。预览再次核验完整来源和目标，绑定原审核编号、当前主体、
全部历史映射和执行意图摘要；用户必须另行明确勾选仅保存目标盘意图。
系统盘审核的确认不被复用为数据盘写入授权。

保存期间以及结果未知时，冻结父向导编辑和应用内重载。SPA 离开不能取消
已经发送的保存；只读预览／查询可取消，响应仍受会话 epoch 和单调 generation
约束。未知结果只能查询或重试原完整请求，即使查询 NotFound 或重试收到 4xx
也不证明先前没有落盘。首次明确拒绝则要求新预览与确认。

状态必须逐字段匹配原目标完整身份、编号、摘要、审核关联、完整历史组数和
暂不可用正文数。未知 effect、stage、execution 和额外字段拒绝，绝不把通用
成功响应解释为接入完成。页面仅显示“目标盘执行意图已保存，未复制或接入”。
整页重载或会话结束后的自动恢复仍未提供；需保留原意图编号、目标身份和摘要，
不能据页面丢失新建替代执行。模型与响应测试不等于 Chrome 或实际磁盘接纳验收。
