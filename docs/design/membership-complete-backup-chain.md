# 新增备份盘的完整低级链门禁

本片先基于真实 main `368e02ca` 实现，再对齐 `aa3d3d85`，收紧既有纯 Add membership 写者的来源准入。它不是外来盘导入、现有备份目标替换或多下级活动拓扑实现。按用户当前要求，本片未编译、测试、审查或运行 CI。

## 同一批次与真实来源

新增二级及以上盘时，从每个新增盘沿目标配置的直接上游一直追到一级。每个所需低级盘只能是：

- 同一目标配置内的新增盘。必须与其它新增盘一起出现在原操作的完整 `added_roots` 和实际持有目录集合中，缺一个就不能登记；继续沿其上游检查，不能止于一个待补来源。
- 原池中已经正式 Enabled 的准确登记。核 pool、disk、slot、binding generation、层级和直接上游；历史 Config 中仍有名称不代表仍被接纳。Disabled、Detached、尚未建立 current registry 的配置占位都不能满足依赖。

首个源准备／目标 reservation／成员 fence 写入前，所有必要旧祖先必须持有实际根资源，命名路径与 held fd 相同、当前 membership 及原 seal 正确。待成员接纳和准备续作再次维持该条件。未相关的其它备份链不因本门禁被全盘扫描或强制在线，但原有 metadata quorum／fence 规则不变。

新增盘及其中的新增祖先仍由既有共同准备协议处理：精确全部根、实际物理身份、共同原操作、数据就绪和联合证书覆盖缺一不可。它们不会因写下 reservation、intent 或本门禁通过就成为运行态成员。

## 新决定与旧收据分开

每次将空 Joint 选择槽变为新投票前，再核必要旧祖先的实际根和当前登记。读取槽失败不被当作空槽；不同原操作／proposal／acceptance 的记录拒绝，既有选择不覆盖。

若槽中已经是完全相同的 Joint 选择，继续原收据同步与认证，不因今天的某个来源掉盘而改写、撤销或重选它。只读 Joint 验证不追加新选择，也不以今日物理存在重新定义旧决定。尚未取得的投票仍须满足新投票门禁，不能把某个已写投票当作整组已决定。

冷态 Add 权威按**该决定所认证的 registry**再次检查完整原祖先集合是否 Enabled；不把 Config 历史身份补成当前登记。该检查不访问今日根路径，不掩盖真实后续损坏或离线，也不把它们误解为旧收据应被删除。原有 lineage 校验仍要求 registry-bearing 前驱的准确 continuation。没有改变收据格式、哈希或旧选择字节。

## 成本与支持边界

链提取使用 slot 和原 disk 索引及共享 visited 集合，逻辑工作为 `O(N log N)`、内存 `O(N)`；共享祖先只进入一次集合，不依赖“每盘只能有一个后继”的假设。每轮实际准入只对必要旧祖先读取根身份、membership 和 seal，没有增加持久写或 fsync。每个新的 Joint 选择重新准入，成本随成员数与所需祖先数增加；不宣称常数时间。

当前 Config／活动 writer 仍未开放多下级扇出。此片没有把多目标隔离材料登记为新成员，没有调用普通 Add 去替代换盘决定，也不搬移任何正文、数据库、标签、文件容器或目录仓库。原完整单元、父子同层同盘、逐跳路径和旧数据保留规则不变。

外来盘仍须由离线 helper 完成真实来源映射、全链材料接纳和最终共同发布，本片仅为可复用的现有 Add 协议补一道生产门禁。SYSTEM／盘根完整历史材料、源增量追平、完整目标活动安装及最终多目标切换仍未完成。详见[整体备份迁移](../adr/backup-target-replacement.md)及根 [TASKS](../../TASKS.md)。
