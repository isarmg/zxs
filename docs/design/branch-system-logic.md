# 分支系统运作逻辑详解

文档类型：行为规范。

适用范围：文件节点、文件分支、目录子树、目录分支、分支切换与 SMB 默认写入入口。

**目录仓库采用手动初始化与独立提交。** 默认普通目录未初始化；未独立初始化的后代归最近父仓库，独立初始化后形成新所有权边界，并要求父仓库重新确认暂存。文件保存仍持久化当前工作组合，内部 T1、T2 检查点不显示为用户目录历史。显式提交只提交本仓库自身文件和已明确暂存的子仓库提交引用，绝不递归提交独立子仓库。子仓库提交后父仓库只出现未暂存引用变化。正常路径读取当前工作字节，历史快照才固定旧版本；父分支切换保留独立子仓库工作内容。数据与恢复权威仍在数据盘根目录，系统盘维护索引，不采用目录内数据库或标准 Git 格式。下文原有子树图表示工作组合，不得用于覆盖本段独立仓库边界。

**Web 浏览与持久化选择分开。** 本文后文的“切换”描述核心持久化引用变更；Web 下拉框切换只浏览冻结目录组合或文件分支历史，不执行该变更，也不影响默认读取、SMB、操作回执或新旧写入会话。用户点击下拉框右侧“设为默认分支”后，才按所浏览树／节点和当前命名空间基线发布下面的引用变更。预览只读，不能作为重命名、删除、批量操作或写入权限；拒绝保留原预览，不确定发布结果保留原操作 ID 查询。

相关规则：[文件分支合并、节点标签与备份路径前缀](file-merge-tags-backup.md)。合并可复用现有分支头，目录引用同步更新；标签修改新增复用正文的元数据子节点；各备份盘使用用户自定前缀。目录分支合并待确认。

文件或文件夹改名同时产生目录子树和文件路径节点；文件夹内每个文件各增加一个路径节点，复用原正文，后续写入接在路径节点之后。详见[改名规则](#s15)。

跨目录操作：跨目录移动按源、目标的具体目录分支分别记子树，源分支停止跟踪、目标分支接管后续跟踪，文件实体迁到目标目录；移动、复制、删除、重命名都可以批量选择作用分支。详见[移动与跟踪移交](#s23)及[批量分支操作](#s24)。

本文定义文件与目录分支的行为；第 21 节集中说明命名空间、自动命名和显式写入目标。当前可用能力见[组件说明](../components/README.md)，图示本身不作为业务验收。


本文涉及的编号、对象名称、字段和目录结构示例用于解释逻辑，不是新的盘格式或 API 契约。实现状态、测试结果和发布状态需另行核对。

## 1. 行为规则与文档边界

### 1.1 基本规则

文件与目录分支遵守以下规则：

1. 目录中的文件、子文件夹都可以切换其分支。
2. 切换子项分支也算对所在目录的一次写入，应生成新的目录子树。
3. 修改产生新的目录子树，不自动产生新的命名目录分支。
4. 如果当前目录分支尚未产生自己的子树，这次修改完成该目录分支的首次实际分化。
5. 目录本身没有一套私有的文件节点或文件分支；目录分支建立在公共文件节点的引用关系之上。
6. 创建目录分支时，直接引用父节点中各文件、文件夹所在分支的具体节点；实际写入某个文件时，才为该文件创建相应分支。
7. 创建文件分支、目录分支都不再创建空占位文件，未写入时直接读取父节点内容。
8. 主分支，即 SMB 默认使用的写入分支，可以由用户切换。
9. 历史箭头使用均匀实线、水平与垂直走线、圆角转弯。
10. 文件由目录 a 的 m 分支移到目录 b 的 l 分支时，两侧各新增子树；a.m 停止跟踪该文件，b.l 接管跟踪，实际文件保存在 b 下，未选分支保持原样。
11. 移动、复制、删除、重命名都允许批量选择作用分支，不能隐式扩散为所有分支。

创建目录分支不提前为其中每个文件登记新分支。只有首次实际写入仍继承父引用的文件时，才创建该文件的公共分支。

### 1.2 本文怎样使用“创建完成”

为避免“已经能选择，为什么又说没有创建完成”的歧义，本文区分两个阶段：

- **登记完成**：分支名称和来源引用已经持久化，可以选择，也可以读取父节点内容。
- **首次实际分化完成**：该分支第一次产生自己的文件节点或目录子树。

文件分支的首次实际分化需要真实内容写入。目录分支的首次实际分化既可以由内容写入触发，也可以由子项分支切换触发。

“尚未首次分化”不表示文件为空、目录为空或内容不可读。

### 1.3 适用边界

本文第 21 节定义三个边界：目录子树记录完整命名空间；延迟产生的公共文件分支自动命名并可改名；显式选择已有文件分支后写入该分支。

SMB 在途会话处理、发布原子性等部分是为了让目标逻辑可执行而给出的实现约束。本文列出的验收场景是检查要求，不代表已经通过。

## 2. 对象、身份与术语

| 对象 | 含义 | 是否随正常修改变化 |
| --- | --- | --- |
| 文件身份 | 用户管理的一个逻辑文件，例如 `报告.docx` | 稳定；改名不应变成另一个文件 |
| 文件节点 | 一次实际写入产生的具体内容版本，例如 `F1` | 节点正文不可变；修改形成新节点 |
| 文件分支 | 一个文件的命名演进路线，具有当前节点引用 | 分支身份和名称通常稳定，当前节点向前推进 |
| 目录身份 | 一个逻辑目录，例如 `项目` 或 `项目/资料` | 稳定；改名不应改变目录身份 |
| 目录子树 | 某一时刻的目录组成及其对子项具体节点的引用，例如 `T1` | 已保存子树不可变；修改形成新子树 |
| 目录分支 | 目录的一条命名演进路线，具有当前子树引用 | 身份和名称稳定，当前子树随修改推进 |
| 默认主分支 | SMB 默认读取、写入入口所选择的目录分支 | 用户可以切换这个选择 |

### 2.1 节点不是分支

`F1 → F2 → F3` 表示文件节点的演进，不表示创建了三个命名文件分支。

`T1 → T2 → T3` 表示目录子树的演进，不表示创建了三个命名目录分支。

一个命名分支可以拥有多个连续历史节点；创建新命名分支和在现有分支上产生新节点是不同操作。

### 2.2 子树不是新的完整内容副本

新目录子树保存新的引用组合。未变文件继续引用原文件节点，未变子目录继续引用原子树，不需要复制它们的正文。

目录子树中可以同时出现来自不同文件分支、不同子目录分支的节点。它们不必使用相同分支名。

### 2.3 公共文件分支的含义

公共表示该分支属于文件自身的统一分支体系：唯一管理员可以在文件详情中独立查看、选择它，仍须满足对象归属与可写状态。

公共表示同一唯一管理员的数据模型内共享，不表示匿名可读或跳过认证。目录引用文件分支仍须满足归属、只读状态与内容可用性检查，不附带用户 ACL。

## 3. 贯穿全文的初始示例

假设有以下用户可见目录：

```text
项目/
├── 报告.docx
├── 数据.csv
└── 资料/
    ├── 说明.txt
    └── 图片.png
```

设 `项目` 的目录主分支当前指向 `T0`：

```text
T0
├── 报告.docx → 报告文件的 main 分支，节点 F1
├── 数据.csv  → 数据文件的 main 分支，节点 G1
└── 资料      → 资料目录的 main 分支，子树 S1

S1
├── 说明.txt → 说明文件的 main 分支，节点 H1
└── 图片.png → 图片文件的 main 分支，节点 I1
```

`F1`、`G1`、`H1`、`I1` 是实际文件内容节点。`T0`、`S1` 是目录引用结构。

本文中的 `main`、`方案甲`、`审阅稿` 是展示名称；`F1`、`T0` 等是简化标识。正式对象必须用稳定 ID 区分，不能只用名称确定身份。

## 4. 文件分支的创建、读取与写入

### 4.1 显式创建文件分支

从 `报告.docx` 的 `F1` 创建文件分支 `审阅稿`：

```text
报告文件的 main 分支   → F1
报告文件的 审阅稿分支 → F1
```

结果是增加一个文件分支登记，记录其来源为 `F1`。

此时不得：

- 新建一个零字节占位正文。
- 复制 `F1` 的正文到另一个版本路径。
- 为了表示“新分支”而伪造 `F2`。
- 因尚无自有正文而把可读父节点显示为不可读。

### 4.2 首次写入之前的读取

选择 `审阅稿` 后，文件列表大小、预览、下载和 SMB 读取都来自 `F1` 的真实内容。

如果父节点实际不可用，界面应报告真实不可用状态，不能将它替换成空文件，也不能悄悄换用另一个版本。

### 4.3 首次实际写入

向 `审阅稿` 成功写入内容后生成 `F2`：

```text
F1 → F2

报告文件的 main 分支   → F1
报告文件的 审阅稿分支 → F2
```

`F2` 保存本次写入的完整文件内容，并记录来源 `F1`。它不是指向 `F1` 正文的空标记。

即使首次提交的字节和 `F1` 相同，或者首次写入的内容是真正的空文件，也应区分“仍在继承”与“已经成功写入自有版本”。

### 4.4 后续写入、局部编辑及取消

后续内容变化在同一个文件分支上继续产生 `F3`、`F4`，不自动增加新的命名文件分支。

局部编辑应以当前选定节点的内容为基础，保留未修改的字节；完整上传则使用本次上传的完整内容。

只读打开、打开后未写关闭、取消编辑、上传未提交或事务失败，都不能被当作成功发布的新节点。

## 5. 目录子树记录什么

### 5.1 每个引用必须固定到具体节点

目录记录不能只有“报告文件当前选中了 main 分支”，还需要固定该子树所引用的具体节点，例如 `main@F1`。

否则文件 main 后来推进到 `F9`，旧目录子树的内容就会发生变化。

概念示例：

```text
目录子树 T0：
  报告.docx → 文件身份 A，文件分支 main，具体节点 F1
  数据.csv  → 文件身份 B，文件分支 main，具体节点 G1
  资料      → 目录身份 C，目录分支 main，具体子树 S1
```

### 5.2 目录不私有化文件节点

文件节点和文件分支属于文件自身的统一历史。目录子树只引用它们。

不应存在以下隐藏对象：

```text
项目/方案甲 私有的报告文件分支
项目/方案乙 私有的报告内容节点
```

实际写入后产生的新文件分支应进入该文件的公共分支体系，不能只藏在某个目录分支内部。

### 5.3 子文件夹也引用它自己的具体子树

父目录中的 `资料 → main@S1` 表示引用子目录的一个已确定状态。

父目录不需要把 `S1` 里面的每个文件复制一遍，也不需要要求所有后代文件使用与父目录相同的分支名。

本节描述逻辑关系，不限定实现必须采用树形对象、规范化索引还是其他编码；具体编码必须能完整表达这些冻结引用和稳定身份。

## 6. 目录分支的创建与首次分化

### 6.1 从父子树登记新目录分支

从 `项目` 的 `T0` 创建目录分支 `方案甲`：

```text
项目目录的 main 分支   → T0
项目目录的 方案甲分支 → T0
```

此时 `方案甲` 读取的内容就是 `T0`：报告为 `F1`，数据为 `G1`，资料为 `S1`。

只登记目录分支及其来源引用，不进行以下操作：

- 不为报告、数据、说明、图片提前创建文件分支。
- 不为资料子目录递归创建一批命名目录分支。
- 不新建空文件、空版本容器或占位正文。
- 不复制文件内容。
- 不伪造“已修改”的目录子树。

### 6.2 登记后的状态

该目录分支已经可选择、可读取，但尚未拥有因自身修改而产生的子树。

界面可以说明“引用父子树”或“尚未首次修改”，但不能显示“没有文件内容”。

### 6.3 什么行为完成首次实际分化

以下行为可以产生该分支的第一个自有子树：

- 在该视图中成功写入某个文件。
- 在该目录中切换某个文件的分支或具体引用节点。
- 在该目录中切换某个子文件夹的分支或子树。

新增、删除、移动、改名同样产生目录子树，详见规则 P1。备注编辑单独记录元数据历史，不新建正文节点或目录子树。

## 7. 在目录分支中首次写入文件

### 7.1 只修改报告文件

选择 `方案甲`，首次修改 `报告.docx`。

发布时形成以下逻辑结果：

1. 从可见父节点 `F1` 为报告文件创建一个公共文件分支。
2. 将实际写入保存为该文件分支的节点 `F2`。
3. 为 `方案甲` 生成目录子树 `T1`，其父为 `T0`。
4. `T1` 将报告的引用改为新分支的 `F2`，数据继续引用 `G1`，资料继续引用 `S1`。

```text
T0                         T1
报告.docx → main@F1        报告.docx → 新公共文件分支@F2
数据.csv  → main@G1        数据.csv  → main@G1
资料      → main@S1        资料      → main@S1

目录分支：方案甲
当前子树：T1
父子关系：T0 → T1
```

实际创建的文件分支属于报告文件，不属于目录的私有内部空间。名称根据来源目录分支自动生成，必要时附唯一后缀，之后允许用户改名，详见 P2。

### 7.2 原分支保持原引用

这次写入不能推进报告文件原来的 main 分支，也不能把目录 main 改成 `T1`。

原视图仍然可读：

```text
项目目录的 main → T0
报告文件的 main → F1
```

### 7.3 只为实际写入的文件产生新内容

本次没有修改数据或资料：

- 不产生新的数据文件分支或 `G2`。
- 不产生新的资料子树或其后代文件节点。
- 不复制这些未变对象的正文。

### 7.4 首次写入不能提前宣布成功

公共文件分支、文件节点、必要的目录子树及当前引用必须一起达到可发布状态，才能确认成功。

准备中的正文、未提交上传和取消操作不能提前出现在文件列表或历史树中。

## 8. 后续修改与多文件混合视图

### 8.1 继续修改已经分化的报告文件

继续在 `方案甲` 中修改报告：

```text
文件节点：F1 → F2 → F3
目录子树：T0 → T1 → T2
```

沿已经产生的报告文件分支继续演进，同时推进 `方案甲` 的当前子树。

目录分支仍是 `方案甲`，不自动产生 `方案甲-2` 或另一个命名目录分支。

### 8.2 此后首次修改数据文件

数据文件此前仍引用 `G1`。首次修改它时，才为数据文件创建相应公共文件分支及 `G2`，并生成目录子树 `T3`。

```text
T3
├── 报告.docx → 报告的公共文件分支@F3
├── 数据.csv  → 数据的新公共文件分支@G2
└── 资料      → main@S1
```

这种混合视图是正常状态：一个目录分支中可以同时包含已经分化的文件、仍继承父节点的文件、直接引用其他既有分支的文件，以及完全未变的子目录。

### 8.3 不应因为写入兄弟文件而改动另一文件分支

假设目录冻结引用报告的 `F1`，而报告所在公共分支的最新节点已经是 `F9`。

仅写入数据文件时，报告继续引用 `F1`，不能把它改成 `F9`，也不能反过来把公共文件分支的当前节点从 `F9` 倒退到 `F1`。

目录保存自己的引用，文件分支维护自己的演进；对兄弟文件的写入不能混淆两者。

## 9. 切换文件分支

### 9.1 切换也是目录写入

假设 `方案甲` 当前指向 `T3`，报告引用 `F3`。用户选择报告的既有分支 `审阅稿`，选中节点为 `F8`。

应生成 `T4`：

```text
T3 → T4

T4
├── 报告.docx → 审阅稿@F8
├── 数据.csv  → 原有引用不变
└── 资料      → 原有引用不变
```

这次切换的实际修改是目录中的引用关系。

它不要求创建新的报告内容节点，不复制 `F8` 的正文，也不自动新增命名目录分支。

### 9.2 新目录分支第一次操作就是切换

如果目录分支 `方案乙` 仍然直接引用 `T0`，用户尚未写入任何新内容，就将报告切换到 `审阅稿@F8`：

- 可以直接生成 `方案乙` 的第一个自有目录子树。
- 这就完成 `方案乙` 的首次实际分化。
- 由于 `F8` 已经存在，不需要为这次选择制造新的文件节点或文件分支。

### 9.3 同内容不等于同一选择

两个文件分支可以暂时引用相同文件节点，或者两个文件节点具有相同字节。

如果用户实际切换到了不同分支，分支身份仍然发生了变化，应记录目录引用的变化，不能仅因正文相同就忽略。

重复选择完全相同的分支和同一节点没有改变引用，不应被误认为又发生了一次切换。

### 9.4 切换之后再次写入

用户明确选择已有文件分支后，再写入就推进该明确目标，不额外分叉。只有仍然从父目录继承引用时，首次实际写入才自动创建公共文件分支，详见 P3。

“继承 main@F1”与“用户明确选择 main@F1”可以显示相同正文，但后续写入目标不同。这次从继承到明确选择的操作改变了引用意图，应记录目录子树；已经明确选择后，再次选择同一分支、节点和意图才属于无变化。

<a id="s10"></a>
## 10. 切换子文件夹分支

### 10.1 修改父目录对子树的引用

假设父目录当前记录：

```text
资料 → 子目录 main@S1
```

用户将资料切换到另一个已有目录分支，其选中子树为 `S5`，父目录生成新的目录子树：

```text
资料 → 子目录 另一分支@S5
```

资料里面显示哪些后代文件和节点，由 `S5` 决定。

### 10.2 不将文件夹切换降格为同名文件分支批处理

`S5` 内部可能是：

```text
说明.txt → 说明文件的审阅稿@H7
图片.png → 图片文件的 main@I1
```

这是合法组合。不能因为资料选择了“另一分支”，就强制说明和图片都必须有一个同名文件分支。

### 10.3 选择已有子树不改写来源子树

引用 `S5` 不应修改 `S5` 本身，不应改写它所引用的文件节点，也不应给这些文件生成副本。

发生变化的是父目录对资料的引用，所以新生成的是父目录的后续子树。

<a id="s11"></a>
## 11. 嵌套目录的子树更新

考虑在 `项目/资料/说明.txt` 中写入新内容。

旧引用路径为：

```text
项目 T0 → 资料 S1 → 说明 H1
```

发布后的引用路径为：

```text
项目 T1 → 资料 S2 → 说明 H2
```

其中：

- `H2` 是实际写入形成的文件节点。
- `S2` 引用 `H2`，其余子项继续引用原节点。
- `T1` 引用 `S2`，报告和数据继续引用原节点。
- `T0`、`S1`、`H1` 保持原样，供旧分支或旧子树读取。

如果这是从新目录分支继承的说明文件第一次写入，才为说明文件形成相应公共文件分支；报告、数据、图片均不因此产生新文件分支。

沿修改路径生成必要目录节点，不代表每次都为沿途目录创建新的命名并行分支。修改产生子树，显式分支操作才产生新的命名目录分支。

<a id="s12"></a>
## 12. 冻结引用、所有权与来源保留

### 12.1 引用固定到创建时选定的节点

新分支直接引用父节点，是固定一个具体节点，不是动态订阅来源分支的最新状态。

来源分支继续写入，不会自动改变已经保存的文件分支来源或目录子树。

### 12.2 内容可读与是否自有是两件事

可以存在“分支尚未写入自己的内容，但继承内容正常可读”的状态。

不能通过以下信息判断文件是否拥有独立版本：

- 正文大小是否为零。
- 文件是否能下载。
- 页面是否出现一个新的分支名称。

判断应基于真实版本身份、来源关系和成功发布记录。

### 12.3 继承中的来源是真实读取依赖

只要活动视图还依赖父内容，就必须按保留规则保护这些内容。不能把“创建时不复制”错误理解为“父内容可以立即删除”。

目录子树元数据、文件节点元数据和实际正文的生命周期也需要区分。历史正文获准清除后，仍应保留历史关系，并明确展示内容已清除，不能伪造空文件或改指其他节点。

具体哪些历史状态持续固定正文、何时允许清理，仍由清理规则和后续实现验收确定；本文不承诺所有历史正文永久保留。

<a id="s13"></a>
## 13. 主分支及 SMB 默认入口

### 13.1 主分支是可切换的默认角色

用户可以选择一个目录分支作为 SMB 默认读取、写入入口。这个角色不能永久硬编码为系统初始化时创建的某个分支。

被选中的分支不必命名为 `main`，也不应因为成为默认入口就被强制改名。

### 13.2 切换后的新操作

SMB 后续的新路径操作，包括列目录、打开文件和建立写入会话，应基于用户所选默认视图。

写入仍遵守相同规则：继承文件首次写入时建立相应公共文件分支；真正修改的内容生成新节点；受影响目录生成必要的新子树。

### 13.3 默认入口切换与目录内子项切换

需要区分两个层次：

- **目录内部切换子项**：改变父目录组成，生成父目录新子树。
- **切换顶层 SMB 默认入口**：改变默认入口指向的目录分支。它本身没有一个更上层用户目录需要生成子树，也不应因此改写目标分支已有历史。

顶层默认入口选择与目录内部引用变化分别记录，避免仅切换入口就改写目标分支已有子树。

### 13.4 Web 和 SMB 共用规则，连接路径独立

Web 经 HTTPS 业务 API 操作；SMB 经 Samba 和服务端桥接访问。两条用户路径共用核心对象、认证边界与保存规则，连接独立。日常管理通过获授权 Web/API 执行；离线救援工具遵守独立的本机信任与证据边界。

唯一管理员可以显式切换默认入口，但仍受目录归属、冻结基线、只读状态、容量与占用等业务约束。

<a id="s14"></a>
## 14. 会话、并发与原子发布

本节为建议实现约束，用于避免目标逻辑在并发时出现歧义。

### 14.1 已打开读取固定版本

文件打开时应绑定具体文件节点。切换目录或 SMB 默认入口，不应让一个已经打开的读取句柄在读取中途换成另一个文件版本。

后续新打开的读取操作使用新的选择。

### 14.2 写入固定目的地

建立写入会话时，需要确定文件身份、可见基础节点、目标文件分支及相关目录分支上下文。

之后如果用户切换了相关目标，不能只看路径或内容摘要相同，就把旧会话写进新目标。

建议处理方式是报告选择冲突并保留待保存内容，让用户明确决定后续保存位置。不能通过丢弃暂存内容解决冲突。

### 14.3 无关修改不应无条件阻塞

修改报告和修改数据通常是不同文件操作。不能仅因其中一个操作生成了新的父目录子树，就把另一个会话都判定为失效。

应区分：正常追加子树、相关文件目标变更、相关目录分支切换，以及无关子目录发生变化。

### 14.4 可见状态一起发布

一次保存涉及的文件分支、文件节点、目录子树和当前选择应构成一致结果。

不得出现这些半完成状态：

- 页面已经切到新目录子树，但它引用的文件节点尚未发布。
- 新文件分支出现在详情中，却没有可读来源或已发布内容。
- 目录已经显示新节点，SMB 同一默认视图仍错误读取另一个组合。
- 重试同一次操作产生重复文件节点或重复子树。

失败、取消、崩溃恢复和幂等重试必须保持同样的对象关系。

<a id="s15"></a>
## 15. 命名、备注、改名和下载

### 15.1 用户可见文件与版本容器

用户看到的一个文件，底层对应保存其内容版本和元数据的容器目录。分支登记引用真实内容节点，不通过往容器中增加空文件表示“尚未写入”。

已有内容版本使用此前确认的命名结构：

```text
v000001_<UTC时间>_<内容摘要前8位>.<扩展名>
```

示例：

```text
v000001_20261019T103000Z_a1b2c3d4.docx
```

版本文件名方便识别；完整身份、摘要与来源仍需以权威元数据为准，不能只依靠文件名中的 8 位摘要区分版本。

### 15.2 分支名与子树标识

用户显式创建目录分支时填写名称；后续产生的 `T1`、`T2` 是子树标识，不是新分支名称。

首次内容写入时延迟产生的公共文件分支需要可识别名称，其生成规则见 P2。

### 15.3 备注与编辑方式

文件备注、版本备注等短文本遵守此前确认的最多 128 个 UTF-8 字节限制。128 字节不等于 128 个汉字，中文及其他字符需要按实际编码字节计算。

使用下划线原位输入，回车提交；空值、取消或失焦取消未提交操作，不出现创建或编辑弹窗。

备注元数据的修改不改写不可变的文件正文，也不产生目录子树；单独记录元数据操作历史。

磁盘退出登记后，当前文件备注只编辑当前投影中仍存在的稳定文件身份；显式版本备注继续保留历史入口。Disabled 保留条目但不恢复正文 I/O，Detached 独占文件不再接受新的当前编辑。同名新文件不继承旧身份备注，原成功操作仍可按准确请求重放。实现与尚待执行的验证见[退出后的元数据编辑](../validation/retained-metadata-edits.md)。

### 15.4 改名与下载

文件改名按选中的目录分支更新条目名称，保留稳定文件身份；不得把未选分支中的展示名称一并改掉，也不能因为改名而重新创建所有文件分支。

下载用户选择的具体版本时，使用当前所选目录视图中的用户可见文件名，而不是直接暴露内部版本存储名。旧子树中保存的历史名称不会被另一个分支的改名覆盖。

文件与文件夹改名都增加目录子树，并为受影响的每个文件增加一个公开的路径节点；文件夹包含几个文件，就分别增加几个文件路径节点。空文件夹只增加目录子树，不虚构文件节点。

路径节点保存原路径、新路径、父节点和已有正文版本引用，不复制正文，不产生新的 FULL。连续改名连接连续的路径节点；随后真正写入的新内容节点连接最新路径节点，同时其正文来源证明仍指向原真实版本。路径节点可独立备注，也可从该节点创建文件分支。

普通文件改名只影响该文件；文件夹改名覆盖其子目录内文件的路径。批量改名仅更新选中分支的节点引用，未选分支继续引用旧节点和名称。分支标签改名仍只改标签，不产生目录子树或文件节点。既有文件名校验规则保持独立。


实际容器的路径、名称与各分支的逻辑条目分开解析。移动时容器迁到目标目录，未选分支仍可用原逻辑路径引用其中的原版本；不能要求一个文件实体同时留在两个实际目录，也不能仅因不同分支使用不同名称就复制整套正文。

<a id="s16"></a>
## 16. 历史树及连线展示

### 16.1 两种历史各自表达真实变化

文件历史展示实际文件节点及来源关系；目录历史只展示用户明确提交的目录子树。目录历史父边跨过内部暂存检查点，连向上一次用户提交；暂存状态和最近已提交节点分别显示。

切换引用可以生成目录子树，但不能因此制造一个不存在的文件内容版本。

创建分支尚未写入时，应展示其对父节点的引用或分支标记，不增加假的空内容节点。

### 16.2 节点与箭头

- 新节点在上，旧节点在下。
- 箭头从父节点指向产生的子节点。
- 连线采用统一粗细的连续实线。
- 路由由水平线和垂直线组成，转弯处为圆角。
- 分叉、汇合、跨层连线都遵循同样的线宽和转角规则。
- 连线需要避开内容块，不得穿过其他节点的文字或操作区域。

文件历史节点使用内容块展示日期、备注和操作。

### 16.3 分支名称与历史节点分开呈现

同一个目录分支内可以连续存在多个子树节点。界面不能通过每产生一个子树就增加一个新分支选项，来代替目录历史。

“修改产生子树”和“用户创建分支”必须在操作入口、历史事件及数据身份上都能区分。

## 17. 操作结果对照表

下表描述一次成功操作的主要结果；“必要目录子树”可能包含嵌套路径上的多个目录节点。

| 操作 | 新文件分支登记 | 新文件内容节点 | 新目录子树 | 新命名目录分支 |
| --- | --- | --- | --- | --- |
| 显式创建文件分支，仅登记 | 1 | 0 | 0，若另行切换则按切换规则处理 | 0 |
| 显式创建目录分支，仅登记 | 0 | 0 | 0，直接引用父子树 | 1 |
| 新目录分支中首次写入一个继承文件 | 仅被写文件的公共分支 | 1 | 必要目录子树 | 0 |
| 已分化文件继续发生内容修改 | 0，沿已产生的文件分支继续 | 1 | 必要目录子树 | 0 |
| 切换文件到已有分支节点 | 0 | 0 | 所在目录及必要祖先子树 | 0 |
| 切换子文件夹到已有分支子树 | 0 | 0 | 父目录及必要祖先子树 | 0 |
| 新目录分支首次操作就是切换子项 | 0 | 0 | 形成首次自有子树 | 0 |
| 只读打开或无写入关闭 | 0 | 0 | 0 | 0 |
| 取消未提交编辑 | 0 | 0 | 0 | 0 |
| 切换顶层 SMB 默认入口 | 0 | 0 | 默认入口元数据变更，不改目标已有子树 | 0 |

所有操作都不创建占位正文。对未变化数据的普通重复保存是否视为新内容事件，应在实现时明确去重策略；首次实际分化不能仅因字节相同而被消除。

## 18. 完整时间线示例

| 时刻 | 用户操作 | 文件节点与分支变化 | 目录状态 |
| --- | --- | --- | --- |
| 0 | 初始状态 | 报告 `main@F1`，数据 `main@G1` | 目录 `main → T0`，资料引用 `S1` |
| 1 | 创建目录分支 `方案甲` | 无新增文件分支或文件节点 | `方案甲 → T0`，直接引用父子树 |
| 2 | 选择 `方案甲` | 内容仍来自父节点 | 当前读取 `T0` 中的组合 |
| 3 | 首次修改报告 | 为报告产生公共文件分支及 `F2` | `方案甲 → T1`，父子关系 `T0 → T1` |
| 4 | 再次修改报告 | 原新文件分支推进到 `F3` | `方案甲 → T2`，不新增命名目录分支 |
| 5 | 首次修改数据 | 这时才为数据产生公共文件分支及 `G2` | `方案甲 → T3`，资料仍引用 `S1` |
| 6 | 报告切到已有 `审阅稿@F8` | 不新增报告内容节点 | `方案甲 → T4`，报告引用改为 `F8` |
| 7 | 资料切到已有子目录子树 `S5` | 不复制资料中的文件 | `方案甲 → T5`，资料引用改为 `S5` |
| 8 | 将 `方案甲` 设为 SMB 默认入口 | 不合并分支、不复制内容 | 后续 SMB 新操作使用该默认视图 |

如果之后切回目录 `main`，应读取它原来保存的引用。不能因为 `方案甲` 发生了写入，就把 `main` 的 `T0` 内容一起改掉。

第 6 步之后再次写入报告，将推进用户明确选择的 `审阅稿` 文件分支，详见 P3。

<a id="s19"></a>
## 19. 必须保持的不变量

1. 文件身份、文件分支身份、文件节点身份相互独立。
2. 目录身份、命名目录分支身份、目录子树身份相互独立。
3. 文件正文节点和已发布目录子树不可原地改写。
4. 新分支可以引用已有父节点，引用不产生内容副本。
5. 创建任何分支都不新建空占位文件。
6. 创建目录分支不提前批量创建其后代文件分支。
7. 从目录继承关系首次实际写入某文件时，才为该文件形成相应公共分支。
8. 目录不维护私有文件内容或隐藏文件分支体系。
9. 未写入的兄弟文件继续引用原节点，不能因其他文件写入而产生副本或分支。
10. 目录引用具体节点，不能动态跟随来源分支最新节点改变历史。
11. 内容修改和子项分支切换都能产生目录子树。
12. 普通修改不自动生成命名目录分支。
13. 切换已有节点不伪造新的文件内容节点。
14. 子文件夹引用可以直接指向其已有子树，不要求后代文件同名分支。
15. 对其他文件的写入不能推进或倒退未写文件的公共分支当前节点。
16. 当前默认主分支可由已认证的唯一管理员切换，SMB 使用这个默认入口。
17. 已打开会话不能因默认入口变化而无声更换读写目标。
18. 成功发布、失败回滚、重启恢复和幂等重试必须保留相同引用关系。
19. 跨目录移动保留文件身份，源、目标选中分支分别发布移出、加入子树，并移交后续跟踪。
20. 其他分支的当前子树、逻辑名称、节点引用和历史不随这次移动、复制、删除或重命名改变。
21. 实体位置改变不能破坏其他分支对原文件版本的读取。
22. 批量操作显式指定分支范围和源目标配对，同一批次不以覆盖顺序解决冲突。

本节将最新需求整理成一致性约束；三个边界的具体规则以第 21 节为准。

## 20. 建议验收场景

下列项目是需要实现和验证的场景，**不表示当前测试已经通过**。

## 21. 命名空间与写入目标

以下规则适用于文件与目录分支的所有入口。

### P1：目录子树记录完整命名空间

目录子树记录文件和子目录的存在、名称、层级及具体节点引用。新增、删除、改名、移动都生成新的目录子树。

按这一方案：

- 切换到旧目录分支时，恢复它保存的完整组成。
- 另一个分支后来新增的文件不会自动混入旧子树。
- 从当前目录移除文件，不等于清除其所有历史正文。
- 改名保留文件、目录稳定身份；旧子树仍能说明当时名称。
- 备注属于独立元数据，不因改备注而新建内容节点或目录子树，另记元数据操作历史。
- 移动、复制、删除、重命名支持显式选择多个作用分支；未选分支的组成、名称及节点不变。
- 跨目录移动分别记录源分支移出与目标分支加入，实际文件实体迁到目标目录，跟踪责任同步移交。

不采用“仅切换当前仍存在文件的版本”的做法。目标子树里有的条目应恢复，没有的条目不从其他分支混入。

### P2：延迟创建的公共文件分支怎样命名

首次写入时自动生成名称，包含可识别的来源目录分支信息，必要时附唯一后缀；之后允许用户改名。

需要约束：

- 自动名称不能作为分支身份，身份使用稳定 ID。
- 同一文件里的名称冲突必须有确定处理方式。
- 分支名采用 128 个 UTF-8 字节限制，截断保持字符完整，并保留用于区分冲突的后缀。
- 普通目录子树只分配节点标识，不自动生成新的命名目录分支。

自动命名应用于首次写入时真正延迟产生的公共文件分支。普通修改只创建子树，不自动创建命名目录分支。实例使用 `方案甲-7c2a` 一类名称解释此规则，具体后缀长度不作为分支身份。

### P3：显式选择已有文件分支后，再次写入到哪里

如果用户明确选择了一个已有文件分支，后续写入就推进这个明确目标；仅当文件仍处于从父目录继承引用的状态时，首次实际写入才自动建立相应公共文件分支。

这样应区分：

| 情况 | 写入目标 |
| --- | --- |
| 新目录分支继承父文件节点，用户未另选文件分支 | 首写时创建该文件的新公共分支 |
| 文件已经在该目录视图内完成首次分化 | 沿已经产生的文件分支继续 |
| 用户明确切换到已有文件分支 | 写入该明确选中的已有分支 |

继承与明确选择必须能被区分，不能只比较路径、分支名或正文摘要。明确选中已有分支意味着后续保存可能推进这个公共分支的当前节点，但其他目录已保存的冻结节点引用保持不变。

## 23. 跨目录移动与跟踪移交

### 23.1 一个移动包含两个明确的目录分支

移动目标不是笼统的“从 a 到 b”，而是明确到以下范围：

| 项目 | 示例 |
| --- | --- |
| 源目录及分支 | a / m，当前子树 M0 |
| 源文件及节点 | 文件身份 f，当前引用 F1 |
| 目标目录及分支 | b / l，当前子树 L0 |
| 操作结果 | a.m 形成 M1，b.l 形成 L1，文件 f 的实体归属 b |


### 23.2 源分支 a.m 的变化

- M1 的父子树是 M0，记录文件 f 已移出及目标 b.l。
- M1 的当前成员中不再有 f，因此 a.m 停止跟踪 f 的后续变化。
- M0 仍保留移动前的条目及 F1 引用，历史不被抹除。
- b.l 此后保存 f，不会再给 a.m 自动追加子树或把文件重新加入 a.m。

“停止跟踪”不是删除旧历史，而是停止把后续写入传播到这个已没有该文件的当前分支。

### 23.3 目标分支 b.l 的变化

- L1 的父子树是 L0，记录文件 f 已加入及来源 a.m。
- 移动保留文件身份、所选文件分支和具体文件节点 F1，不因搬位置新建文件内容版本。
- b.l 接管这次移动后的跟踪上下文。从这个视图保存 f 的内容变化时，形成相应文件节点和 b.l 的后续子树。
- 后续写入仍遵守 P3：移动保留原引用意图；继承文件的首次写入才分叉，已有明确目标则继续写入该目标。

一次移动的源、目标记录属于同一个操作，双方相互可追溯。若某侧目录分支尚未首次分化，这次目录组成变化同时完成它的首次分化，不另建命名目录分支。

### 23.4 跟踪不是订阅所有文件 HEAD

| 视图 | 移动后的状态 | b.l 写入 F2 后 |
| --- | --- | --- |
| a.m 当前 | 已移除 f | 仍无 f，不追加由该文件引起的子树 |
| b.l 当前 | 包含 f，引用 F1 | 更新为引用 F2 的后续子树 |
| 未选 a.n 当前 | 保留原路径及 F1 | 保持原子树及 F1，不自动追到 F2 |
| a.m 的旧 M0 | 保留移动前快照 | 继续引用 F1 |

未选分支以后若主动编辑自己的文件视图，那是另一笔明确操作，按其自己的引用和写入目标处理。


### 23.5 文件实体保存于 b，旧分支仍可读取

移动不仅改变显示路径：真实文件容器及其版本材料应迁到 b 的存储归属下。同一文件身份保留一个确定的实际位置，不为每个仍有旧引用的分支复制容器。

未选 a.n 中的 `a/报告.docx` 是该分支保存的逻辑名称与节点引用。读取时通过文件身份、版本身份和存储位置记录找到 b 中的实际材料，不能只拼接旧逻辑路径去读取已经搬走的文件。

因此以下状态可以同时成立：实际文件位于 b；a.m 已无该文件；a.n 仍从其旧逻辑路径读取 F1；b.l 可继续生成 F2。不同分支的下载名称仍来自各自当前所选视图。

示例以同一受管存储树内的目录移动为范围；跨磁盘时还需满足既有归属、副本及发布规则，不能因本例省略这些步骤。

## 24. 批量选择分支进行文件操作

### 24.1 每次操作显式圈定分支范围

移动、复制、删除、重命名均支持选中多个目录分支。选择分支不等于把它设为 SMB 默认分支，也不要求临时逐个切换默认入口。

每个操作项至少明确文件身份、源节点、源分支、目标分支或名称，以及所依据的子树。文件夹操作同样限定在选中分支的相应子树，不能遍历并改写所有公共文件分支。

| 操作 | 源侧 | 目标侧 | 当前引用变化 |
| --- | --- | --- | --- |
| 移动 | 勾选移出分支 | 勾选接收分支并明确配对 | 源移除，目标加入，跟踪移交 |
| 复制 | 指定读取的源分支及节点 | 勾选副本出现的目标分支 | 源不变，目标加入独立副本 |
| 删除 | 勾选要移除条目的分支 | 无目标目录 | 仅选中分支移除并停止跟踪 |
| 重命名文件或文件夹 | 勾选名称应改变的分支 | 指定新名称 | 选中分支换名称，身份与正文保持 |

### 24.2 批量移动按映射处理

不能仅选一个源分支集合和一个目标分支集合，就暗中做所有可能的两两组合。例如可以明确指定：

| 映射 | 源引用 | 目标 |
| --- | --- | --- |
| 1 | a.m 中的 f@F1 | b.l 中的 f@F1 |
| 2 | a.n 中的 f@F2 | b.p 中的 f@F2 |

四个选中分支分别记录一次新的目录子树，a.r、b.q 等未选分支保持原样。f 的物理容器只迁到 b 一次，其中保留 F1、F2 供相应引用读取。

同一文件可以加入同一目标目录的多个选中分支；一笔移动不能同时为同一文件指定两个不同的实际容器归属目录。需要多个实际文件时使用复制。

不同源节点映射到同一目标分支的同一个条目时，必须先解决冲突，不能靠列表顺序静默覆盖。


### 24.3 批量复制采用独立副本语义

复制与移动不同：原文件 f 保持身份、位置和跟踪；副本 c 获得新的文件身份和初始内容节点，保存在目标目录中，之后可以独立修改。

同一次复制到同一目标目录、同一目标名称，形成一个副本身份；多个选中的目标分支引用这个副本的初始节点。复制到不同目录或不同名称则形成对应的独立副本身份。

复制的源目录只被读取，不需要为这个读取新增源子树。目标的每个选中分支记录副本加入；未选目标分支不出现副本。复制来源可记录为追溯信息，不把两个不同文件身份伪装为同一个文件。

此处用户明确要求“复制”，才产生独立副本；创建分支本身仍不复制正文。


### 24.4 批量删除只移除选中分支的条目

选中 a.m、a.n 删除 f，两者分别生成移除 f 的新子树并停止跟踪。未选 a.r 保留自己的路径和具体节点引用。

删除目录条目不等于永久清除文件版本。只要其他分支或保留规则仍需读取该文件，就不能连同实体容器和版本材料一起删掉；历史清除是单独的受控操作。


### 24.5 批量重命名仅更新选中视图

选中 a.m、a.n 将文件改名为 `客户报告.docx`，两者分别生成记录新名称的目录子树，并将文件引用更新到各自新增的路径节点。路径节点复用原正文版本，不新增 FULL。未选 a.r 仍显示 `报告.docx`，引用的文件身份和版本保持不变。

实际容器只需按此次操作的实际名称调整一次，其他分支的旧逻辑名称仍通过稳定 ID 解析。不同分支的名称不能迫使系统复制文件正文或重建文件身份。

这里的重命名对象是文件或文件夹条目。分支标签改名和备注编辑仍属于元数据操作，不因此新增目录子树。


### 24.6 批量发布和回执

在发布前统一检查所选分支的可写状态、依据子树、源条目、目标重名、目标配对和实际归属约束。任一检查失败，整批不发布，不自动跳过有问题的分支。

同一笔批量操作中，一个受影响的目录分支产生一个汇总本批变化的后续子树；必要祖先目录节点同步形成一致视图。操作回执列明每个分支的旧、新子树、移交关系及文件实际位置，幂等重试不得重复移动或复制。

涉及移动时，两侧子树和实际归属一起达到可发布状态；不能出现源侧已移除、目标侧未加入，或者未选分支引用已经不可读的半完成结果。
