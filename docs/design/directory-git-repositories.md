# 独立目录仓库：工作视图、暂存与提交

## 决策与范围

目录默认是普通目录，不因文件保存而初始化仓库。用户明确初始化后才拥有独立提交 HEAD、命名分支、待提交工作组合、暂存代际和子仓库引用。本功能提供类 Git 语义，不使用 `.git` 格式，也不提供标准 Git 命令兼容。

持久化权威仍放在数据盘根目录的既有元数据、日志与恢复材料中；系统盘保存对应运行索引。没有目录内数据库，也不承诺复制一个普通目录便携带全部历史。当前格式显式增加 `directory_git_repositories`，旧格式不隐式升级、不补默认空表；拒绝旧材料时不得删除或重置它们。

## 三个不同的事实

1. 当前命名空间和内部 `DirectoryBranch` / `DirectoryTree`：保存已持久化的工作内容，正常路径、SMB 和程序执行读取这里。内部工作检查点不是用户历史节点。
2. `DirectoryGitBranch`：记录 Git HEAD、已审阅的边界、手动暂存的子仓库提交引用和并发代际。文件保存进入自己所属仓库的待提交内容，不自动创建用户目录提交。
3. 用户目录提交：独立的不可变树，以 `Commit.kind = directory_commit` 与精确 `provenance = tree_id` 双向绑定。其树父边和 commit 父边指向该稳定目录的上一用户提交；初次提交为独立根。

独立目录根与文件历史域的内容根可以共存。恢复先验证每个目录根的真实树标记，再从所有已证明根检查完整无环覆盖；不能仅放宽字符串或忽略断开记录。

## 嵌套所有权

普通子目录归最近已初始化父仓库递归管理。单独初始化子目录后，它成为独立边界。父仓库的已审阅边界随之失效，旧暂存代际不能提交或继续暂存；当前状态显示 `needs_restage`，用户需要明确重新暂存父仓库。若父此前已把该子目录作为普通内容提交，旧提交仍保留原内容；新边界下原递归内容计为待提交删除，不能因过滤当前边界而误判没有变化。

父仓库只引用直接独立子仓库，不越过它引用更深的孙仓库。插入一个中间仓库会改变直接引用关系。重新暂存本仓库会清除不再属于直接边界的引用，但不会自动跟随任何子 HEAD。

边界改变后，刷新取得新暂存代数即可先明确固定直接孩子的已提交 HEAD；这不会清除 `needs_restage`，父提交仍须等待重新暂存本仓库。之后的本仓库重新暂存保留已经明确固定、且仍属于直接边界的孩子引用。旧代数请求始终拒绝。

子仓库必须先有真实用户提交，父仓库才能暂存其引用。子仓库之后的保存保持自己的 dirty 状态，之后的新提交只使直接父仓库显示尚未暂存的引用变化。父提交不替子仓库提交，也不自动接受新的子 HEAD。

## 示例

子仓库 `lib` 已提交 C1；父仓库显式暂存 C1 并提交 P1。随后保存 `lib/code` 为新内容但未提交：普通路径立即读新内容，P1 仍固定 C1。子仓库提交 C2 后，父仓库只显示引用变化。父仓库提交其他自身文件得到 P2 时仍固定 C1。只有显式暂存 C2 后提交得到 P3，P3 才记录 C2。

父分支 checkout 只替换自己拥有的工作范围。独立子仓库的挂载条目、当前文件、选中分支与 HEAD 保留；抵达嵌套子仓库所必需的普通祖先目录也保留当前身份。目标分支若会替换这些祖先身份，或恢复当前已删除／移出本作用域的独立子仓库，则明确冲突，不替子仓库恢复历史。父自身待提交内容或边界尚未重新确认时拒绝 checkout，不静默丢弃。创建命名分支要求本仓库自己干净，子仓库可以仍有未提交修改。

父历史中的子文件分支后来归档，不妨碍保留孩子现状的父 checkout。当前登记模式只对本次明确保留的直接子仓库历史条目放宽活动状态要求；文件身份、路径上下文、节点、不可变树和引用闭合仍须成立。父实际恢复的自有条目仍须使用活动文件分支，普通当前投影和文件合并也不放宽此要求。

当前登记下合并孩子的文件分支，也不要求未选父分支跟随孩子的新工作树。未选组合只有真正拥有本次文件及输入分支的路径出现位置时才参与合并；仅保留独立孩子历史的父组合原样保留，不作为当前内容导入或被重写。相同文件在父自有范围中的别名仍按各自路径上下文判断，参与合并的普通目录引用继续要求精确闭合。所有已选组合仍使用完整当前来源证明。

历史快照通过明确的不可变树 ID 读取；快照浏览不是将其发布为默认分支的授权。

## 并发与永久幂等

- 初始化绑定用户审阅的命名空间 HEAD。
- 暂存自身绑定工作树 ID 与 index generation。
- 暂存子引用绑定父 index generation 与准确子 HEAD。
- 提交同时绑定工作树 ID 和 index generation，要求非空说明。独立子工作修改引起的父内部检查点变化只有在旧树是当前树的可证明祖先、父自身条目/文件节点/所选文件分支完全相同且边界未变时才可通过；真正父修改仍冲突。
- 公开 checkout 入口绑定查看过的稳定分支 ID、分支树和命名空间基线；无这些基线的旧目录切换 HTTP 入口已退役。
- 每个操作保留永久 operation ID 和原请求摘要，准确重试返回原结果；不能因为分支后来推进而重新执行旧请求。

任何字段变化、边界变化或旧会话令牌失效都在同一事务线性化点拒绝，保留待处理工作内容。初始化、暂存、提交及 checkout 都走既有完整持久化发布协议，不减少同步步骤。

## 登记切换与恢复

当前磁盘登记模式下，新 Git 操作使用独立的确定性元数据规划器。它从准确请求、前状态及已准入当前命名空间重建全部写集、回执和事件，并比较完整 State；通用 kind allowlist 不授予它们写权限。初始化和重新暂存只从已准入当前视图捕获工作组合，不能借旧树重新引入退役盘隐藏条目。

显式提交不重写当前命名空间，因此父历史中的固定旧子引用不会把旧内容重新发布为工作文件。历史记录可以保留暂不可用内容；读取正文仍经过既有副本完整性与可用性检查。

所有 Git HEAD、index 树、子引用、所有权、分支继承与提交 marker 必须在历史包中闭合。内部工作树可以不是用户提交；不能把其任意引用误认为子仓库已提交。历史包分页和数据盘权威快照均包含新表，系统盘丢失不能仅靠内存恢复它。

## 成本与验证范围

普通文件保存没有增加新的 Git 发布事务或同步阶段，内部工作检查点仍会增长。状态读取在锁内捕获共享只读元数据，锁外一次构造稳定目录 ID、路径和直接所有权索引，以迭代后序计算相关子仓库 dirty。它借用已准入条目和原始上下文，不克隆完整目录投影；各循环检查取消，总预算为 1,000,000 工作步和 16 MiB 扫描／返回字符串字节，超限失败而不截断。HTTP 另有 1 MiB 完整响应上限。返回前重新鉴权，并检查状态序号及当前命名空间 publication 身份。历史分支一页共用一个索引和总预算，写操作及历史页头只计算自身范围，不递归检查子仓库。当前登记的闭合计划验证比较完整 State，显式操作成本随保留元数据增长；本设计没有声称常数复杂度。

核心行为测试覆盖手动初始化、普通子目录归属、独立子初始化失效父暂存、固定旧子提交、正常工作读取、stale 令牌、分支 checkout 保留 dirty 子仓库、不可变快照读取、故障注入与冷重开。历史包测试覆盖独立根、分页往返、继承、固定旧子 HEAD、缺失边、伪造 marker、交叉作用域和循环。当前登记退出后的真实准入、封套重建、完整写集篡改和冷恢复必须独立执行；编译成功不代替这些证据。
