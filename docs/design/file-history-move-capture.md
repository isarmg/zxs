# 跨盘移动的源快照与重验切片

`Engine::capture_file_history_move` 为后续共同决定提供受限的内存来源捕获，不执行复制、D 发布或 SMB rename。它不是移动收据，也不能作为目标已经完整的证明。

## 本片实现

- 输入除了 source/target namespace HEAD，还必须给出源稳定 file ID。按当前可见命名空间核对准确路径和身份，复用全分支删除预检，保存包括非活动／别名分支在内的完整 frontier，以及去重排序后的 D parents。
- 只接受一个当前 occurrence 的盘根文件，且不处于已初始化目录仓库中。多 occurrence 必须先显式分离文件身份，不允许移动一个路径却将其它路径一起冻结。
- 捕获经过有界完整行校验的文件本地逻辑数据库摘要，包括历史、标签、备注、分支和保留 D/undo 前缀，以及全部保留版本 ID 和准确目标路由。延续 retained copy 的可用正文、统一路由、无放置／备份覆盖、空未初始化目标和非外来图约束；旧 graph-only copy 没有完整审计前缀时仍拒绝。
- 捕获时和重验时均要求两端没有 Open/Sealed 写工作区；工作区创建尚未推进 State 也不能漏过。
- `recheck_file_history_move` 核对原 State 分配身份、完整 Config 准入身份、两端已发布 namespace witness 和当前写准入。标签、备注、新分支、D/undo 等即使没有推进 namespace HEAD，也会使原捕获失效。
- 使用 `Weak<State>` 而不是保持整池旧 State。重开 Engine 后不能复用原捕获；没有反序列化、持久化 token 或凭摘要取得权限的入口。成功重验只返回绑定当前 Engine 借用的元数据观察。

本片采用保守规则：**任何 State 发布均令捕获失效，包括无关文件的变化**。这比只比较两个 HEAD 严格，但不是后台迁移的最终增量方案。来源摘要只描述逻辑文件数据库，不证明磁盘上的 SQLite、FULL 字节或三范围数据库已经验证；本 API 不访问正文、不产生 fsync，也不保留读租约。

## 资源与仍缺的闭包

首次捕获复用受限文件数据库投影，最多 65,536 行、12 MiB 编码记录；删除预检沿当前 entry budget 限定分支／occurrence，并在扫描中检查取消。所有者索引构建仍随 State 规模增长。捕获只保留文件版本／frontier 列表、摘要、配置和两个命名空间 witness，不复制整池 State。重验不重新扫描全历史，只比较身份、已发布视图及两端工作区。

下一片须把捕获升级为原 operation 的持久请求／计划，完整安装并独立验收目标正文、历史和三范围数据库，随后在**一个可恢复决定**中发布目标与源 D。它还必须处理目标独立可编辑、源 SMB 隐藏、双端预取页／已有句柄围栏、决定前失败保源、首次 ACCEPT 后 InDoubt 和同 operation 冷恢复。不能把 retained copy 与 `soft_delete_file` 两次独立成功拼接，也不能将本片元数据重验称为这些证明。

当前 SMB 跨盘 rename 仍明确拒绝，源和目标均不改变。本片不新增网络入口或放宽其拒绝。
