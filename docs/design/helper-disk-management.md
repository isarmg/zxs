# 辅助工具的磁盘管理职责与迁移边界

[辅助工具](../components/helper.md) · [架构决策](../adr/0017-helper-disk-management.md) · [现有协调器](online-disk-management.md)

最终入口是主服务停止后手工运行的独立二进制 `zxs-helper`，以 root 运行，默认监听 `0.0.0.0`，配备无需认证、直接打开的独立 Web 控制台，CLI 可选。不注册 systemd 或开机自启，退出即停止。首次账户/系统及必要磁盘配置初始化、磁盘添加、注销/移除、外来接入、密码重置和救援归此工具；“计划下线”不是要迁入的新命令。下列状态区分已存在的能力与尚未接线的迁移，不能把检查、草稿、控制准备、界面或改名当成操作完成。

## 外来备份盘必须一次接入完整低级链

外来二级及以上备份盘不能先单独加入，再等待以后补低级盘。每个正式接入计划必须显式列出、设置并核验全部所需低级目标及关系，一直覆盖到一级；外来三级必须同批具备二级和一级。多个原一级来源分别保留原身份及完整映射，不因同名或同正文合并。虚占位、缺失目标、未设置关系或只保存执行意图均不能产生完成或可写成员。

预览摘要须绑定整条链的具体身份、角色、路径/持有目录、当前状态及映射。执行复验整个集合，并且只有全部所需盘的接纳证明与发布闭包成立才报告整批加入完成；不能先发布一个可用的高层成员，让低层关系留空。中断保留原完整计划和材料，继续时不得替换、追加或推迟原目标；未完成状态只可报告阻断/恢复要求，不能等同于允许以后另行补盘的成功接入。

这个规则约束正式接入，不限制独立盘的只读检查与隔离导出：`authority check` 仍可在原一级或中间盘不在场时核验备份盘已持有的证据和正文，不因此登记它或创造虚拟低级成员。当前没有完整批接纳写者，必须继续明确拒绝执行，不能凭检查通过放行。

## 辅助工具到正常服务的完整交接

辅助工具必须先完成准备、初始化、正式接纳及一致性核验，正常 ZXS 才准入该系统。服务的数据、数据库和标签等投影只来自已发布的受认可状态，不将外来候选、待初始化盘、仅保存的审核/执行意图或 helper 暂存安装为运行时数据。此处的“干净”是准入与可见状态一致，不是删除未知文件、孤儿、故障证据或用户历史的许可。

完成判定须覆盖准确系统/管理根、正式登记及完整低级链、当前配置代际与 publication、命名空间和历史/标签引用，以及应有的系统/目录/文件数据库投影。SQLite 仍是派生物，不能拿复制来的数据库、`completed` 或 `clean:true` 标记代替权威证明。工具和服务共用校验能力；服务每次启动仍验证真实磁盘身份、权威和投影，不把上一次工具退出码当永久许可。

任一初始化或接纳阶段未决、成员链不齐、投影未就绪或身份/证明改变时，不进入正常服务的已就绪状态。中断材料保留给辅助工具按原完整操作核对/继续，不由服务偷偷补入外来盘或另建目标。普通已发布事务的可证明恢复与正常用户写事务另有原有协议，不能混称为外来接纳完成。

已正式登记的盘在运行中失联或损坏仍必须真实显示不可用并执行相应读写围栏，不能删登记、虚构在线或谎称整个系统完整。物理上新接入但未正式纳入的目录不自动进入业务视图；外来盘选择、待初始化操作和迁移准备最终仅在辅助工具中完成。

首次管理账户、首批空目录 activation 及普通二进制首启前置已有 helper/核心源码；上述所有数据、标签和数据库的最终完整启动门禁仍未完成。最终首次运行必须在辅助工具中完成；未初始化主服务应清楚报错并提示辅助工具，不自行创建数据/数据库/标签或接纳半成配置。现有管理权威与凭据灾备副本必须保持原有边界，不能因移动入口而重置凭据、跳过认证或制造空配置让服务假就绪。

## 独立辅助控制台的端到端边界

控制台属于 `helper/`，自行运行 HTTP/Web 入口，不依赖 ZXS 主服务在线，也不把按钮转发给主服务来伪装离线操作。通用格式、认证密码学、受保护持久化与核心权威校验可共用；辅助专用页面、路由、操作 owner 和流程状态留在辅助工具目录。首个界面切片必须至少有真实后端操作、错误与恢复状态及浏览器/HTTP 验证，不能只提供静态 mock。

默认监听 `0.0.0.0` 并以 root 运行，无认证、无需账号或密码即可打开控制台。不能偷偷加一层强制登录或要求 ZXS 服务在线。首次初始化仍只有真正空的、已持有系统/管理根才可准入；已有凭据、权威或未决证据关闭“首次初始化”，必须使用各自明确的恢复或密码重置流程，不能利用无登录入口自动重置系统。

所有写入口保留不要求账号的同源/CSRF 机制和具体操作确认；确认内容包含准确来源/目标、整批低级链、操作范围及会保留或改变什么。防跨站请求不等于限制网络访问者，也不提供操作者身份认证；审计不能伪称识别了某个网络用户。注销不能默认为擦盘，初始化不能默认覆盖旧材料。启动日志及页面必须醒目标注“无认证的 root 管理控制台，对可达网络开放”，建议可信隔离网络/防火墙和用完即退出；不自行改防火墙、监听系统策略或开启自启。密码经网络传输的保密风险必须明确提示，不以 CSRF 代替 TLS。

当前文件系统边界要求根目录归有效 UID 所有，而部署的主服务通常使用 zxs 账户。root 工具必须有单独核验的所有权/权限适配方案，保证新初始化后主服务能读取正确的私有材料；不能删除当前 UID/权限检查、把目录改成宽松权限，或 chown 现有盘来绕过失败。

启动控制台不等于已经取得写权限。实际停服 owner 必须在第一笔维护读写前完成跨进程准入，并防止 ZXS 同时重新启动。每个持久操作有唯一 owner、原编号/摘要和阶段；刷新、断连、重复点击、退出控制台或进程崩溃不得产生第二个操作或丢掉恢复依据。状态/恢复与终态回执必须真实来自核心，未知结果不得清成成功。实现顺序与准确验证结果逐片记录。

## 密码重置的独立操作边界

仅开发功能，不据此改变任何实际部署密码。新密码由用户在控制台手动输入，不从历史聊天、示例或代码中猜测，不写入 argv、URL、日志、明文回显和浏览器持久存储。提交只显示成功状态与准确目标，不返回密码或密码哈希。

ZXS 管理员重置必须绑定既有唯一管理员和准确系统/管理根，持有停服 owner，沿持久认证权威原子发布新凭据并撤销旧会话；不得删除权威标记再重新初始化。凭据灾备副本和原操作恢复范围须同步证明，部分发布或结果未知不能报告全部完成，也不能自动切回旧密码。

SMB 重置绑定实际为 ZXS 配置的准确 Samba 账户，不能根据展示名猜用户名或重置任意系统账户。使用受控的本机 Samba 接口/程序，秘密通过专用输入通道而非命令参数传递，保留具体返回错误；不能仅改 ZXS 的账号选择记录便报告 Samba 密码已改。已有 SMB 会话是否仍有效必须明确，不能假称改密自动断开所有会话。

两种密码是两个独立持久操作，不假装跨 ZXS/Samba 原子提交。重复提交、密码写入后响应丢失、关闭控制台和崩溃均须保留原操作结果的不确定性，要求核对原事实而不是无条件重发或回滚。

## 一条龙安装、systemd 与 SMB 配置

辅助工具自身是临时手工运行程序，不依赖 systemd，也不安装自身自启。它可以为 **ZXS 主服务** 准备安装、systemd 和 SMB 配置。ZXS 的安装路径、服务身份、系统/管理/数据根、监听、服务启动或启用选项、SMB 共享/账户/桥接绑定都须在执行前形成完整预览，由用户确认，不把“配置 systemd”推定为授权立即启动或开机自启。

所有写入限定于经核验的安装及配置目标。保留原配置和权限、只替换明确选中的 ZXS 条目，不覆盖未知 Samba 共享或用宽松权限解决失败。先校验准备中的服务/SMB 配置及匹配程序，再发布配置；实际外部工具及退出状态保留来源，不能仅写了配置文件就报告 systemd/Samba 已生效。首次初始化和完整系统交接证明未完成前不启动正常 ZXS。

操作持有停服 owner，服务退出须真实排空，不把超时强杀当优雅停机。配置应用、账户/密码、程序发布和数据初始化是不同持久阶段；记录原计划、目标、备份与实际结果。失败只回滚已证明可恢复的程序/配置变更，不删盘、删库、删除未决证据或自动恢复旧密码。不能证明完整回滚时保留具体不确定状态，按原操作恢复，不声称整个安装已撤销。

## 内置匹配安装载荷与离线程序修复

辅助工具发行物必须携带匹配版本、提交和目标平台的 ZXS 安装载荷，不在首装或修复时临时从网络下载。构建顺序应先生成 ZXS 程序及必要运行材料，再生成带逐文件摘要、版本/提交/平台的清单并嵌入辅助工具；不能把含 helper 自身的整包递归嵌入。程序载荷与工具发行本身的来源可信度分别核验，内部摘要不能冒充对工具来源的独立认证。

安装/修复前完整验证内置清单和内容，拒绝损坏、版本/平台不符或不支持的格式。解包只接受明确允许的普通程序文件和必要目录，拒绝路径穿越、绝对路径、符号/硬链接、设备节点及未声明项；始终使用受约束、持有身份的目标。原版 NOTICE、许可和适用源码义务随发行物保留，不能因内嵌压缩而丢弃。

程序损坏时的修复默认只恢复明确程序文件，不覆盖用户数据、数据库、配置、凭据或未知材料，不隐式迁移磁盘格式，不自动降级。已有部署版本/平台与内置载荷无法匹配时明确拒绝或另行审查，不以“修复”偷换升级语义。

先停止相关服务并取得准确 owner，保留可用的原程序和发布计划，再通过可恢复的暂存/验证/替换阶段发布。崩溃后按原清单核对旧、新与已发布事实，不能只看某个二进制存在便宣布成功；数据和配置独立保留。当前没有这个执行器，本工作不下载或安装任何真实系统，也不修复实际机器。

公开 release 只包含源码归档、SHA256 校验文件、辅助工具可执行文件和 ZXS 可执行产物四类，不额外发布文档、安装包、VFS 或收据资产。必要 VFS/安装材料及其校验收据随 helper 内置载荷分发，文档、许可和来源材料仍包含在源码归档或载荷中。校验文件必须完整、唯一覆盖所有其它公开产物，版本/提交/平台绑定在可核验材料中；上传后复核实际同一集合，不只相信上传返回成功。当前明确验证目标仍是 Linux amd64，不承诺未建立构建与验收的多平台变体。

## 原实现与停服围栏

迁移输入分别位于 `src/server/src/management/storage_addition.rs`、`storage_lifecycle.rs`、相应 `engine_backend/` 协调器，以及 `setup_recovery/activation.rs`。它们的控制意图与归档绑定会影响之后的服务准入，不能只复制一个最终 Engine 调用而遗失永久原操作。

新的离线 owner 须证明服务已经释放系统及管理所有权，并在整个操作期间阻止它重新启动；只查询 PID、看端口关闭、先检查锁再释放，或仅取得某个内存 mutex 都不够。未激活系统没有已打开 Engine，不能把 Engine 锁当作所有启动状态的完整互斥。具体跨进程门禁必须随实现建立，不在本改名切片里声称已经存在。

预览绑定当前配置/代际、选中盘的真实挂载和目录身份、主体、原 operation 与请求摘要。执行使用持有目录并重验这些约束，不格式化、不挂载、不改权限，不修改来源历史哈希。失败后保留所有材料，按原操作查询/继续，不能换编号、删控制记录或清空盘来绕开阻断。

## 取消“计划下线”与保留真实状态

取消用户发起的 `PlannedOffline` 动作，不等于移除 `Deregister`。新预览/提交入口应关闭计划下线，历史结果查询和已持久未决操作仍按实际状态处理。不能机械删除 `ExitAction`、Disabled 状态或核心 stop/epoch 证明，否则可能让已停止目录被重新打开，或令已提交操作无法核对。

真实失联和不可用状态继续显示；辅助工具的“离线运行”只表示服务未运行，不是一个可切换的磁盘产品状态。注销必须保留盘字节与历史，仅沿经核验的登记和当前视图规则执行。新请求关闭与既有恢复出口须分别验证，不能以隐藏按钮替代服务端准入。

## 分阶段落地与验收

1. 统一源码、测试、构建、帮助、发布资产与文档名称；保留既有有效救援命令。逐盘检查仍只输出本盘证据，不扩大权威；这一步不等于 Web 控制台完成。
2. 建立服务/工具互斥的离线 owner 与独立辅助 Web 控制台的真实无登录/同源防护、操作和状态链，迁入首次账户/系统初始化及空盘添加的完整预览、执行和原操作恢复，并建立到正常服务的完整交接准入，不开放任何隐式重置。
3. 迁入严格注销与续作；新计划下线入口单独关闭，既有 Disabled/未决操作仍可如实诊断与按原决定收束。
4. 来源身份、完整低级链的同批目标映射及新协议发布闭包完整后再开放外来接纳；检查、审核或目标准备均不是正式接纳，也不能先接高层后另补低层。
5. 分别接通准确 ZXS 管理员与 SMB 账户的密码重置，秘密仅由用户手动输入，验证持久结果、会话影响、失败与原操作恢复，不将两个后端混成单个成功标记。
6. 接入匹配内置载荷的离线安装/程序修复及 ZXS systemd/SMB 配置，逐阶段验证和确认，保护数据/数据库/配置/凭据并提供原操作恢复；helper 自身保持临时、无自启。同步改造严格四类 release 集合及端到端验收，不能先丢掉必要运行/许可材料而假称发行已完成。

每个切片绑定准确源码和定向测试；全仓、真实设备、物理断电及生产迁移验收分别报告。名字更换不代替这些功能证明，也不授权清理真实磁盘或用户数据。
