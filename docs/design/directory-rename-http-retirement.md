# 目录分支标签 HTTP 写入口退役

## 本片边界

旧目录 Git 分支改名不属于继续开发的文件容器能力。Web 写控制退役之后，本片删除 `PATCH /api/repositories/{repo}/directory-branches/{id}` 的路由、专用名称／操作解码和 HTTP handler。请求走统一 `404 / NOT_FOUND`，不进入 Backend 写队列，不创建新操作，也不更改目录标签。机器 OpenAPI 和现行 API 表同步移除该端点。

此切片只收窄 HTTP 公共入口，不宣称完整 Backend 或 Engine 已退役。`RenameDirectoryBranch`、`Backend::rename_directory_branch`、授权适配器和 EngineBackend 转发暂时保留；删除它们需要同一后续切片更新所有必选 trait 实现和定向选择。其他旧目录初始化、暂存、提交、分支创建与默认切换也尚未删除。

## 保留责任

- 文件容器分支改名、节点、标签、合并和默认文件选择保留；不改文件版本发布、三份正文、多级备份及 SMB namespace 改名。
- 当前目录标签、默认目录和历史只读接口保留。既存 `directory.branch.rename` 收据继续由通用原操作查询返回，当前授权和撤权检查不变。
- 底层 Engine 状态、原请求摘要、永久收据与盘上字节保持原样，不迁移、清空或删除用户数据。
- 不启用非容器文件或非容器目录功能。旧浏览器恢复记录继续保全，不重放、转换或自动擦除。

## 验证边界

被删除的 HTTP handler 是这条端点的唯一入口。路由入队取消及 panic 枚举仅移除不存在的 PATCH 项，其余实际路由覆盖保留。新增真实 Engine HTTP 回归验证带令牌和匿名请求均到统一 404、当前目录读取不变且原操作号没有收据。存活文件分支改名所在集成行为、既有 Backend 标签／摘要／碰撞／永久重放与撤权回归继续选择。

定向 CI 分别覆盖服务器 core／非 core 产品编译、路由和排队边界、HTTP 退役行为及文件容器保留行为；原重叠选择的独立上限和超时不变。没有在本地编译、运行测试或 rustfmt。实际结论以准确提交的 GitHub 定向 CI 为准，完整冷恢复、真实 Chrome、SMB 客户端与其他旧目录写链未由本片验证。

目录改名选择回归的四个 Python 测试已完整并入 `test_targeted_ci.py`，旧专用测试模块删除；原 rename 组选择该共享模块，不删除断言或放宽构建／模块预算。既有目录 default 集成场景同步改为验证退役请求拒绝、无改名审计和冷重开保留原标签。
