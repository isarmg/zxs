# 目录与仓库的主盘规则入口

主盘规则决定后续新版本的主盘。它不改变已发布版本的正文或物理放置，不补历史副本，也不修改备份份数和备份前缀。备份设置仍是独立入口。

## 使用范围

- 当前目录工具栏和文件夹详情提供「主盘规则」；仓库根由其当前目录入口管理。不可写目录、备份目录、历史预览和未确认操作期间不允许提交。
- 用户选择真实登记的一级盘根路径，不输入仓库、目录或规则 ID，也不输入代数。系统管理中的原始表单保留，直到新入口完成实际验收。
- 本次沿用现有的路径规则数据模型。编辑时绑定当前目录身份防止误改替换目录，保存的规则仍按路径生效，不会随目录改名或移动自动迁移。界面明确提醒在新位置复核。
- 已有更具体的子路径规则继续生效；本入口不删除、覆盖或合并这些规则。

## 读写契约

`GET /api/repositories/{repository}/placement-configuration?path=…` 只读当前主命名空间。空路径表示仓库根，其他路径必须解析为真实目录。响应含仓库显示名、稳定范围身份、规范路径、精确规则的可空 ID 与代数、当前有效主盘和一级盘候选根路径。

`PUT` 必须携带 `path`、`primary_slot_id`、`expected_scope_id`、`expected_rule_id`（新规则显式为 null）、字符串编码的 `expected_generation` 和真实 `operation_id`。服务端在已有单写者事务中重读目录身份与精确规则。路径已被另一个目录占用时返回 `SCOPE_CHANGED`；规则 ID 或代数已变化时由统一错误映射返回 `CONFIG_CONFLICT`（核心原因 `GENERATION_MISMATCH`）。新规则 ID 由服务端生成，已有同路径规则保持原 ID；幂等重放保留原操作身份与结果。

主盘候选不包含备份盘。受本次规则影响的目录、现有文件及后续可继承的备份规则必须都能在所选主盘的固定链上满足原份数；独立子主盘规则覆盖的范围不计入父规则要求。候选列表禁用链长度不足或目标备份盘缺少现有范围前缀的目标，提交时再次按当前状态校验。不能仅因两条链长度相同就允许切换，否则后续写入会失败。当前备份界面只编辑已使用的备份链，尚不能预填另一条未使用链的前缀；本轮不把这一缺口伪装成可安全自动迁移。已通过独立备份配置明确准备目标前缀的范围，可以切换并正常写入新版本。候选兼容性不冒充实时在线或容量健康证明，正常发布仍由引擎检查实际磁盘与元数据成员。

认证沿用唯一管理员及当前凭据检查，不增加权限或凭据。全局只读与发布准入仍由引擎控制。Web 关闭、导航、替换草稿或更换登录后不接受旧响应覆盖新状态；结果不明保留原操作并复用现有查询机制，不以重新提交制造第二次写入。

## 成本与边界

这是用户主动打开/保存的配置路径，不新增轮询。范围解析读取当前命名空间；备份份数检查扫描当前命名空间和规则集合，采用已有放置/保护解析实现，不扫描全部历史版本或读取正文。写入只产生一个主盘规则的事务，不增加正文副本、fsync 阶段或部署动作。

## 验证入口

- `cargo test --locked --offline -p storage-engine --lib placement_configuration`
- `cargo test --locked --offline -p storage-server --lib http_placement_configuration`
- `cargo test --locked --offline -p storage-server --test http_engine placement_configuration`
- `cargo test --locked --offline -p web-app --lib placement_configuration`
- Web 的 WASM 编译/lint 与真实浏览器操作仍须独立完成，单元/HTTP 测试不能替代界面验收。

本补丁仅写入源码、测试和文档；本机未执行测试或构建。GitHub 定向验证和真实浏览器结果应记录在交付报告中，不在此预先声明通过。
