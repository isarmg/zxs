# 原目录暂存与提交的 Web 入口退役

## 本片范围

本片只移除原有目录 Git 语义的四类 Web 写操作：初始化、暂存当前目录工作、暂存子目录引用、提交目录。删除当前目录详情和批次源／目标入口的对应控件、提交说明草稿、输入准入、review／submit 分派及 HTTP action，不以隐藏按钮代替删除执行链。

原浏览器初始化／提交和父子目录暂存流程、其专用夹具及专用测试同步移除。运行器保留已退役请求防回归检查，并加入四类 Web 请求与控件缺席检查。这不表示服务端路由已经删除。

## 保留的实际依赖

- `files::staging` 的状态读取、响应解码、请求取消与会话／位置关联仍用于已有目录分支来源、所属目录导航、已有子目录快照预览和实体布局整理。该模块不再保有上述四类写操作或提交文本状态。
- 批次专属的初始化 `ScopeRegistration`、初始化后的重读／重试链和永久回执分派支路一起移除。普通 namespace 批次仍通过 `submitted_operation` 保留未知结果、拒绝后明确重试、准确原操作收束和勾选清理；不会借初始化创建缺失范围。
- 现有目录分支操作与 namespace 上下文暂时保留。listing、删除和布局等尚未完成物理切换，不能按名称包含 directory 就删除。
- 实体布局整理保持原准入、明确确认、未知结果围栏、存储状态刷新及原测试，不改为自动整理。
- 文件容器的独立历史、分支、标签、备注、节点图，以及 mkdir、路径导航、SMB 文件身份、权限、完整性、备份和恢复均未在本片退役。
- 浏览器 FILE、反馈生命周期、命名和放置测试仍使用真实持久夹具。命名所需的已提交来源改由测试私有临时池建立，冷重开继续核对文件身份、版本内容与来源状态；不再调用已退役的 Web 初始化／提交。其他存活探针仍消费的初始化／提交夹具辅助函数保留。

## 后续与验证边界

新的 `.zxs` 方案允许目录内同时包含普通文件和容器文件，原文件结构不动，每次提交在额外目录内复制当前文件。本片既未实现它，也未把原目录 Git 状态或布局操作称为新方案。

后继分片仍需移除不符合新方案的目录分支控制与专属恢复路径，再按实际依赖逐层收敛 server／backend／engine。现有数据与持久化契约不由本片改写，也未提供旧格式兼容层。

遵从仅在 GitHub 定向测试的约束，本地未编译、运行测试、执行 rustfmt 或验证脚本。源码与静态差分审阅不代表编译或浏览器验收通过；准确提交的定向 CI 结果另行记录。
