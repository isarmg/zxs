# 辅助控制台连接与响应所有权

本片对应 H01 的 HTTP 资源上限，未改变持久格式、原请求、回执或 JSON 响应契约。
不是 H01 全生命周期验收，也不证明真实安装或服务交接已通过。

## 边界

- 接受 TCP 连接之前取得 32 个连接槽之一；槽随真实连接存活，包含 idle keep-alive。
  连接耗尽时不创建更多请求任务，等待连接仍留在系统 TCP backlog 中。
- 单个原生 JSON 作业的许可从请求准入、阻塞执行和编码延续到响应正文的最后一份
  `Bytes` 被发送或丢弃。下载和维护 IPC 继续使用相同正文所有权规则。
- 普通错误和静态小响应受连接数量及 HTTP/1 传输自身的有界队列约束，不另建无界作业队列。
  原有请求头截止时间和 15 秒、64 KiB 请求体边界保留。
- 只有显式退出或进程信号开始排空时，所有连接共享一个固定的 30 秒 HTTP I/O 截止时间。
  客户端缓慢读取或持续取得少量进展不延长截止时间。它不用于中止原生作业。
  已在退出前等待 I/O 的连接登记独立的开始通知，不能依赖客户端再发字节或 HTTP 层重新
  轮询才启动计时。每个存活连接只持一份通知，连接丢弃即注销，不积累已关闭连接。
- HTTP 结束后仍显式销毁并等待 Tokio runtime；阻塞作业和维护子进程真实结束之后，
  `console::run` 才能返回交接。最外层 host lease 在此期间不释放，不能用 HTTP 超时
  冒充原操作已取消、已回滚或服务已启动。超时响应的原意图和结果查询规则不变。

## 证据范围

新增回归源码覆盖真实 TCP 连接上限、idle 连接、取消 accept 后归还槽、排空截止时间唤醒，
以及 JSON 成功/编码失败的准确响应对比、未读正文与克隆排队帧的许可寿命。
已有断连后原生作业继续持有 owner 的回归保留。
