# 数据库恢复读取的统一结构准入与字节预算

## 具体缺口

目录库的 rescue material 读取已验证 repository／branch／tree／commit 的完整类型及本地引用，但普通布局／安装消费者调用的 `verify_scope`、`verify_at`、`verify_located_at` 原先只解码已知 schema、记录族和自摘要。重新计算摘要的外部路径、缺失树或未知字段可越过这一层，被当成可保留／替换的旧目录库；离线救援却会拒绝同一内容。

本片把**已有**目录类型与本地父边闭包移到共享 SQLite 解码出口。摘要和物理完整性通过后，所有返回的目录记录必须再通过同一套既有 `validate_rows`；rescue material 不再重复调用一次。没有新复制的字段表、State 合并或自定义准入捷径。

普通布局核验发现非法旧库时返回原错误，不能因为新 State 可生成一份好库就覆盖、清空或删除旧材料。保全与持久安装仍由原 held-root／installer 负责；本片不修改其交换、恢复、保留额度或提交顺序。派生库拒绝不是回滚已决定业务事务的授权。

## 精确而有界的 SQLite 文本

文件／目录／盘根 current／盘根 history 四类 decoder 的 schema 名称、类型、所属表和 DDL，以及固定 identity 字段改为有界**字节**前缀。先 `CAST(... AS BLOB)`、再 `substr`、必要时转回 TEXT 给既有 UTF-8 decoder；不先按文本截断。

这是具体的格式边界：SQLite 的文本 `substr` 会在 NUL 处停止，原盘根 history 的格式／摘要前缀可能把合法值后附 NUL 与未知尾部当成合法值。字节前缀保留 NUL，已有准确格式、ID、十进制序号及摘要比较会拒绝它；不是截断后接受长输入，也不丢弃非法 UTF-8。错误继续保留 SQLite／解码来源。

- schema 文本分别最多返回 257／4097 字节，超过受支持固定值便不能精确相等；对象数量仍使用原闭集加一的上限。
- 固定格式最多返回 65 字节，ID 257 字节，u64 十进制序号 21 字节，摘要 65 字节。合法固定值本身更短，哨兵字节用来拒绝额外内容。
- 盘根 current 的结构 scope 信封最多 8 KiB，先检查 8193 字节前缀长度，再按既有严格类型核明确预期身份；history 沿用已有 8 KiB header 上限。
- 文件／目录本地行先读有界 kind／ID 和实际正文长度。所有既有行键都是固定 ID，256 字节上限不放宽其后续类型规则；键的实际字节长度必须与返回值一致。原 12 MiB 的 ID＋正文合计预算在正文复制进 Rust 前扣除，超限不先申请完整字符串。
- 通过长度预算后，正文按 `length + 1` 字节前缀读取，校验实际长度，再执行既有规范 JSON／领域结构校验。按真实表键排序与推进游标，不让截断后的 SELECT 别名决定顺序。

不支持的 schema、格式、额外行、路径字段、损坏索引和未知侧车仍保留拒绝。SQLite 只打开独立内存连接，实际文件仍经已有有界 held-FD 读取；这不是 SQL 修复、旧格式迁移或截断式救援。

## 保持的三范围与权限边界

SYSTEM 保存已有全局投影，盘根保存本盘及路径，对象库只保存对象本地历史／相对组成。本片不把外部路径添进对象库，不追随文件或子仓库的可变 HEAD，不读取外部对象补缺。目录工作树指向外层普通命名空间 commit 的既有未解析边界保留，不虚构本地 user commit。

本地结构、自摘要、SQLite 完整性和准确读回各自只能证明其原有范围。它们不证明 publication 最新性、原权限、正文可用、全成员完整或三范围共同 authority；不会激活外来链、安装 SYSTEM、放行未接受 move、改变备份写者或恢复任意单盘系统。明确选择一个盘根库时仍不读取另一个损坏库。

## 成本与交付状态

每个对象行多一次有界按键 SQL 查询，以便在复制正文之前检查合计预算；原有顺序索引、65,536 行／12 MiB 记录／16 MiB 镜像预算保持。新增普通目录读取的 typed 本地闭包会占用暂存分支／树／commit 集合并检查父边，离线救援则不再重复校验。没有额外磁盘 I/O、fsync 或后台扫描，也没有性能提升声明。

SQLite 自身仍可能为取值、解析 schema 或页管理分配内存，长度限制不是进程 RSS 或墙钟限额；既有约千万 VM 步物理扫描预算不变。最大记录集、SQL 次数带来的延迟和复杂目录正常路径兼容性尚未测量。
