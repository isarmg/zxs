# 文件软删除的持久生命周期候选

## 已实现的核心边界

`State.file_deletions` 按稳定 `file_id` 保存当前唯一 `FileDeletionNode`。节点没有 `version_id`、内容散列或正文，不伪造任一分支的正文归属；它保存各保留文件分支自身的准确 HEAD，并按节点身份去重父边。合并别名保留自己的 HEAD，不替换成 survivor 的 HEAD。

`Engine::soft_delete_file` 在实际发布时读取完整 frontier。当前范围是磁盘根中的独立文件，不覆盖已初始化目录仓库或命名仓库。新增记录、永久操作回执和事件通过现有日志／快照／历史包发布，不新增旁路数据库或同步协议。所有正文、分支、目录组成和物理容器原样保留。

`Engine::undo_file_deletion` 只接受准确当前删除节点 ID。撤销移除当前删除表中的节点，不新建内容节点、不回滚其他文件，也不清除旧操作回执。再次删除生成新的删除节点，旧删除 ID 不能撤销它。

普通规划和当前登记重放均检查已删除文件的版本、路径节点、元数据节点、合并记录、文件分支及其命名空间发生的修改。选择分支、默认分支和路径写入上下文同样冻结，即便不同分支引用同一正文、Entry 字节未变也不能切换；撤销不会暴露删除期间暗改的分支选择。其他稳定文件 ID 不被这个冻结规则限制。新 API 依然受原有单写者、准备期间的发布围栏与授权约束，未移除整状态提交基线检查。

## 可见性与剩余接线

当前 `namespace_tree` 的查找与 `visible_entries` 过滤已删除文件；历史视图仍可读。`entries` 明确保留底层原始有序行，供已有工作区、完整性与投影使用。命名空间快照也捕获同一删除表；扫描见证以跟踪身份检测删除或恢复，HEAD 没变也不能复用旧可见性。见证保留该表的共享只读引用，不持有正文。服务端普通 listing 与 SMB 目录分页已有过滤候选，仍需准确 Server/SMB 定向编译和端到端验收。

当前候选**没有默认切换既有批量删除和 SMB unlink**，也没有 HTTP 撤销接口、Web 删除节点卡片及按钮。旧版本树传输节点必须带真实正文，不能借用这套 DTO 伪装无正文删除节点。接入用户可操作的删除前，应同时交付删除节点的独立传输和精确撤销入口。

此切片保留原逻辑路径占位。允许同名新文件占用已删除位置及之后的路径冲突恢复尚未设计或验证，不能将本候选称作完整回收站。已打开 SMB 描述符、预取的虚拟磁盘首页、备份视图和断线重入尚需独立验证。

## 格式与恢复

新表在 State、逻辑历史清单和两类映射根中均为必需字段，缺失时拒绝，不用默认空表兼容旧格式，不清空或重建运行池。历史归属索引、脏键跟踪和只读元数据投影同步覆盖新表。冷读验证删除节点的全分支 frontier 及对应永久发布回执／作者。

独立历史包导入带删除节点的跨库迁移尚未验收；原删除回执没有随独立历史包迁入时不能以空默认状态放行。真实池升级、部署、数据删除不在此次验证中。

## 成本与验证

删除预检扫描当前 namespace 和分支表，辅助数据按该文件的分支数与父边数增长。正常发布冻结检查使用 tracked changed keys；解码恢复缺少跟踪时退回完整比较。删除表沿用 TrackedMap 的写时复制特性，新增／撤销删除可能复制当前删除表，不宣称恒定时间。

没有新增 payload 写入或额外自定义 fsync；持久阶段沿用既有发布协议。实际执行了新的 Contract 与完整生产 Engine 编译（无故障注入特性），以及 `test/engine/integration/file_soft_deletion.rs` 的真实生产 API 回归：两种分支 HEAD 汇合、正文导出不变、A 冻结而 B 继续保存／建分支、删除后新生同正文 C 可编辑／建分支、操作重试幂等、精确撤销、重复删除拒绝旧 ID、删除与恢复后的重新打开。另执行了 Contract 的必需 State 字段拒绝定向测试和四条新 schema 向量。

不能由 schema、格式检查或单项 Engine 回归推定 HTTP、Web、真实 Samba 和掉电覆盖。没有执行全 CI；黄金字节按独立 JSON／BLAKE3 工具更新并核验其原哈希，不宣称已运行全部历史／快照单元回归。
