# 文件软删除的持久生命周期候选

本次在 `7583e229` 上接入原 cb99 的 `94d13056` 未合入切片。**本次仅移植/续接源码，没有审查、编译、格式化、静态检查、测试、CI、真实 Samba 或真实盘操作；既有二十项定向通过只属于原 cb99 组合，不覆盖本次主线。** 普通 Web 跨目录分支批量删除/rename-replace 仍不是此片的软删除入口，下一片须显式接单文件 D，不以旧目录操作回退或冒充原文件全分支软删。

## 已实现的核心边界

`State.file_deletions` 按稳定 `file_id` 保存当前唯一 `FileDeletionNode`。节点没有 `version_id`、内容散列或正文，不伪造任一分支的正文归属；它保存各保留文件分支自身的准确 HEAD，并按节点身份去重父边。合并别名保留自己的 HEAD，不替换成 survivor 的 HEAD。

`Engine::soft_delete_file` 在实际发布时读取完整 frontier。当前范围是磁盘根中的独立文件，不覆盖已初始化目录仓库或命名仓库。新增记录、永久操作回执和事件通过现有日志／快照／历史包发布，不新增旁路数据库或同步协议。所有正文、分支、目录组成和物理容器原样保留。

`Engine::undo_file_deletion` 只接受准确当前删除节点 ID。撤销移除当前删除表中的节点，不新建内容节点、不回滚其他文件，也不清除旧操作回执。再次删除生成新的删除节点，旧删除 ID 不能撤销它。

普通规划和当前登记重放均检查已删除文件的版本、路径节点、元数据节点、合并记录、文件分支及其命名空间发生的修改。文件备注、正文版本备注及路径／标签节点备注也冻结，新增、替换和删除备注均不能绕过该文件的冻结；关联文件的备注仍可独立编辑。选择分支、默认分支和路径写入上下文同样冻结，即便不同分支引用同一正文、Entry 字节未变也不能切换；撤销不会暴露删除期间暗改的分支选择。其他稳定文件 ID 不被这个冻结规则限制。新 API 依然受原有单写者、准备期间的发布围栏与授权约束，未移除整状态提交基线检查。

## 可见性与剩余接线

当前 `namespace_tree` 的查找与 `visible_entries` 过滤已删除文件；历史视图仍可读。`entries` 明确保留底层原始有序行，供已有工作区、完整性与投影使用。命名空间快照也捕获同一删除表；扫描见证以跟踪身份检测删除或恢复，HEAD 没变也不能复用旧可见性。见证保留该表的共享只读引用，不持有正文。服务端普通 listing 与 SMB 目录分页使用同一可见性过滤。新的本机 RPC 接线在返回预取的虚拟磁盘首页前重验业务快照；已打开的 `Handle::Read` 每次 RPC 读取重新校验删除状态，包括已有读缓存；这不代表撤销已经交付的暂存写入 FD。

磁盘工作区普通文件的 **SMB unlink** 现在调用同一核心软删除事务，不创建正文，不经过旧工作区硬删；命名共享保留原行为，已初始化目录范围由核心明确拒绝，失败后不退回旧删除。既有批量删除、rename-replace 没有在此切片中改义。

唯一管理员通过 `GET /api/file-deletions` 发现隐藏文件，通过 `GET /api/files/{file}/deletion` 读取独立无正文节点，使用 `POST /api/files/{file}/deletion/undo` 携带准确 `deletion_node_id` 和 `operation_id` 撤销。Web 文件页提供已删除列表、每个分支末端到 D 的边表（每页最多100条）及删除 D 的恢复按钮。现有[同域联合图](shared-file-history.md)也保留 D 及其真实父边；恢复入口独立于只读联合图，不把删除节点伪装成正文版本。旧正文节点 DTO 没有被冒充或放宽。Web 关闭面板不清除原操作 ID 或未知结果围栏，错误及轮询复用已有全局恢复机制。

此切片保留原逻辑路径占位。允许同名新文件占用已删除位置及之后的路径冲突恢复尚未设计或验证，不能将本候选称作完整回收站。本机 Unix RPC/FD 集成验证与真实 Samba 挂载验收不同；备份视图、SMB 网络重连和掉电仍需独立验收。同一 Shared、同一 branch 下的同路径或祖先重叠活动写句柄会在删除前被 `FileWriteBusy` 拒绝，但该锁按 `(branch, path)` 组织，不保证同一 `file_id` 的其他不重叠别名没有 writer。通过别名或直接 Backend 删除后，已有暂存写入 FD 不因此撤销；核心冻结仍拒绝对已删除文件发布新内容／节点，不宣称可追回已交付字节。

## 格式与恢复

新表在 State、逻辑历史清单和两类映射根中均为必需字段，缺失时拒绝，不用默认空表兼容旧格式，不清空或重建运行池。历史归属索引、脏键跟踪和只读元数据投影同步覆盖新表。冷读验证当前删除节点的全分支 frontier，并按发布序列重放全部保留 delete／undo 回执：操作映射键与内部 ID 一致、作者／请求摘要／结果封套匹配、每次发布有唯一对应事件、撤销准确消费原 D，最终活动 D 集合必须与 State 完全相同。合法撤销保留旧删除回执；不能仅删当前表行冒充撤销。该语义准入不代替既有磁盘根和发布证明鉴别。

独立历史包导入带删除节点的跨库迁移尚未验收；原删除回执没有随独立历史包迁入时不能以空默认状态放行。真实池升级、部署、数据删除不在此次验证中。

文件内部 SQLite 从同一已捕获 State 及永久收据投影无路径的历史 delete/undo 行；撤销后的旧 D 不会因当前表行消失而从审计投影中丢弃。撤销后再次保存可以改变当前 HEAD，旧 D 只按自己的历史封套和端点校验，不能改用今日 HEAD 重判。核心冷准入不从 SQL 的自摘要或无路径行恢复授权；共同安装器继续核对由 State 重建的精确字节。此组合不改变文件数据库格式，也不使它成为独立恢复权威。

`file.history.copy.retained` 收据内的导入审计不是目标原生 delete/undo 收据，也不产生当前 D。冷生命周期闭包只重放操作表中真实的 `file.delete` 与 `file.delete.undo`；目标后来产生的当前 D 仍须拥有独立原生收据并由准确 ID 撤销，不能拿导入审计中的旧 D 代替。

## 成本与验证

删除预检扫描当前 namespace 和分支表，辅助数据按该文件的分支数与父边数增长。正常发布冻结检查使用 tracked changed keys；解码恢复缺少跟踪时退回完整比较。删除表沿用 TrackedMap 的写时复制特性，新增／撤销删除可能复制当前删除表，不宣称恒定时间。

没有新增 payload 写入或额外自定义 fsync；持久阶段沿用既有发布协议。备注冻结只扫描三类备注的实际 changed keys；冷生命周期校验扫描操作／事件一次，并对 L 个删除／撤销回执按序排序，辅助空间按这些回执及活动 frontier 增长，不在正常热写路径重放全历史。此前核心切片的证据记录了 Contract 与生产 Engine 编译（无故障注入特性），以及 `test/engine/integration/file_soft_deletion.rs` 的生产 API 回归；这些不是当前 SMB/Web 候选的重测凭证。核心回归范围包括：两种分支 HEAD 汇合、正文导出不变、A 冻结而 B 继续保存／建分支、删除后新生同正文 C 可编辑／建分支、操作重试幂等、精确撤销、重复删除拒绝旧 ID、删除与恢复后的重新打开。该历史证据还包括 Contract 的必需 State 字段拒绝定向测试和四条新 schema 向量。当前候选的通过、失败和未执行目标以对应验证账本为准。

不能由 schema、格式检查或单项 Engine 回归推定 HTTP、Web、真实 Samba 和掉电覆盖。没有执行全 CI；黄金字节按独立 JSON／BLAKE3 工具更新并核验其原哈希，不宣称已运行全部历史／快照单元回归。

## SMB/HTTP 接线的资源与验收边界

删除列表以 BTreeMap range 定位游标，取100条及一条后继，复杂度 O(log D + 100)，不扫描和克隆所有删除记录。完整 D 读取最多4096个分支/父边且编码不超过1MiB，超限拒绝，绝不截断 frontier。每个读取复用受限 HTTP 后台槽及响应体生命周期。撤销在核心锁内再次验证当前身份与准确 D；列表快照不授予写权限。没有新增核心 State 持久字段、迁移或额外正文同步协议。SMB 使用自身暂存区的 `smb-file-soft-deletion` 记录保留原操作及准确文件身份；未知结果只能查询原操作，重启后不自动重放路径删除。

本切片的正式定向目标为 `phase1_smb_rpc` 及 Web `files::deletion`。实际执行结果由对应候选的验证证据给出；未执行的浏览器、WASM/Samba部署或完整CI不能由源码接线推定通过。

## 与后继永久退役和跨盘移动的边界

当前 D 仍会阻止永久节点退役；本片不做 namespace/D 共同终止，不放宽永久删除引用守卫，也不改变多文件共享图分组。冷生命周期重放只接原生 file.delete 与 file.delete.undo，保留式复制的导入审计不伪造当前 D。正在准备的单一 native move 还没有发布源 D；后续真正发布时须把共同 move 原决定接入生命周期，不得凭此片伪造第二份 file.delete 收据。
