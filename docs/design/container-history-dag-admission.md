# 文件容器历史窗口的无环准入

本片修复已接入 Web 文件容器历史的数据流，不建立新时间线或修改盘上历史。之前响应只核验节点身份、边端点和预算，布局再静默删除强连通分量内部的真实父边，把矛盾响应绘制成普通树。本片在响应边界拒绝这样的窗口，合法图的全部可见父边继续保留。

## 准入与消费闭包

`actions/history::fetch_page` 经 `history::admit` 解码和准入，随后由 `complete_nodes` 安装到 `FileHistory`。生产中只有此路径调用 `install_nodes`；`wire::nodes` 只投影已准入 DTO，保留节点身份及父边。`browse_branch` 仅切换当前查看标记，不修改 `FileHistory.nodes` 或其父边。`HistoryIndex` 借用同一不可变快照，`version_tree::metadata` 只取标明 `InWindow` 的父边；布局据此消费唯一、端点闭合、无环的可见图，不再重复检查或删除环内关系。

布局的第二个真实消费者是关联文件联合图。`shared_history::decode` 调用现有 `SharedHistoryGraph::validate`，已核对唯一身份、完整父边、同文件归属及 DAG；按单文件筛选因此不会丢失仍被引用的父节点。投影增加的同正文 hub 使用独立身份且没有父边，只发出无箭头关系线，不会制造环。此入口不因本片重新解释为操作时间线；其 contract 和 Web 回归也进入定向选择。

响应中的 `HistoryNodeId` 仍由 contract 准入。节点数、父边数、身份唯一性、边端点归属及重复边拒绝先执行；其后使用迭代 Kahn 遍历核对可见 DAG。该检查处理的是网络响应的矛盾，不把内部错误改成 panic，也不新增 wire 错误码。原关系错误通道保留具体来源。

## 分页与顺序

- 只检查本窗口中已经加载的边，最多 64 个节点、256 条预览边；不查询全仓或完整历史。
- `OutsideWindow`、未读完的 `More` 父集和上下页游标保持原样。它们不被解释为完整根，也不自动补边。没有可见环仅证明当前可见子图，不证明完整历史无环。
- 一旦已加载部分本身形成环，即使仍有未加载父关系，也应拒绝；补充更多边不会消除已有环。
- 不按 sequence 或时间戳猜测父子顺序。合法分叉、合并、跨层与传递父边，以及顺序号不能比较为同一时钟的保留记录，仍按显式关系布局。
- 当前合法节点页的反向拓扑显示与末端排布不变。本片不声称实现操作区段最长路径对齐；该功能仍受[容器时间线 ADR](../adr/container-content-timeline.md)的事件来源和完整性契约约束。

## 错误、编辑与成本

当前请求返回环时沿既有完成路径保留先前可见节点、备注、勾选和编辑器，关闭旧历史写依据，释放该次加载状态并取消辅助读取，交给现有读取错误提示。失败页不安装；旧请求或已切换容器的迟到响应继续被目标/代数检查丢弃，不让旧错误关闭新窗口。

准入使用按 typed ID 的局部索引和邻接数组，时间为 `O((V + E) log V)`，额外空间 `O(V + E)`；图遍历不递归，不持锁、不做 I/O。布局沿用现有索引拓扑与行排序，不再保留第二套 SCC 图或布局访问计数测试钩子。大型 DAG 测试仅检查真实节点、边和确定性输出，不以生产计数器或耗时阈值宣称性能。
