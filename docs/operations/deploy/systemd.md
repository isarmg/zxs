# Linux 服务部署审阅样例

[zxs.service](../../../deploy/systemd/zxs.service) 是供部署前修改和审阅的 systemd 单元，没有安装、启用或启动。它默认只监听回环 HTTP，提供 API 和显式指定的 Web 静态目录；通过配置正确的 HTTPS 反向代理开放浏览器接入；远程运维 CLI 已移除。`zxs.example.com`、程序路径和存储盘位路径必须换成实际配置。

## 部署前条件

- 创建专用 `zxs` 服务账户；程序和 Web 发行件安装在其不可写的 `/opt/zxs` 下。`/var/lib/zxs`、受保护 socket 父目录及每个已登记盘根要求服务账户拥有的 `0700` 权限，文件默认 `0600`。首次初始化通过运行中的受保护 Web 引导执行，由服务独占初始化门控；操作员预先批准盘位与引导授权。不能把开发模式目录当作独立物理盘。
- 各盘是独立物理设备上的独立 Btrfs，已经由管理员按 UUID 挂载。不要用 `RequiresMountsFor=` 或数据配置文件的启动前检查阻止管理服务启动。按真实配置调整 `ReadWritePaths=`，数据盘路径加 `-` 前缀允许缺失挂载点；不能把挂载失败后的普通空目录当作磁盘。核心另外核对设备、UUID、根目录身份和登记封口。
- 日常账户不能打开原始块设备或数据盘目录。部署者需要单独设置设备访问和自动挂载策略，关闭会把业务盘重新暴露给普通用户的桌面自动挂载流程。`PrivateMounts=yes` 不会自动撤销宿主机原有目录或设备权限。
- SQLite 是可重建索引；不要只备份 SQLite。保护元数据、配置和凭据的恢复材料均按项目恢复流程处理。敏感内容不通过环境变量、命令行或 systemd 单元传入。

单元以非特权账户运行，不授予挂载或原始块设备读写能力。`DevicePolicy=closed` 与只读系统目录限制设备和路径访问；业务文件 I/O 只写明确列出的目录。配置需要读取 `/proc/self/mountinfo`、`/sys` 和设备 UUID 元数据，因此未使用隐藏整个设备树的 `PrivateDevices=yes`。此样例不包含挂载辅助进程、AppArmor/SELinux 策略或硬件验收结果。

检查单元语法可执行 `systemd-analyze verify deploy/systemd/zxs.service`；只有替换完示例路径、准备对应程序和挂载环境后，才可执行目标主机的实际启动验收。检查语法不能证明设备隔离、供电故障恢复或上线可用性。

## 可选 Samba 本机桥接

必须先完成 [Samba 模块构建和实际加载验收](../../components/smb.md)。可在单元 override 中重置 `ExecStart=`，保留现有盘位、初始化方案及其他启动参数，再加入实际受信任进程 UID 和一个显式 Samba 认证账户。例如以下单盘配置：

```ini
[Service]
ExecStart=
ExecStart=/opt/zxs/bin/zxs --root /var/lib/zxs/state --management-root /var/lib/zxs/management --listen 127.0.0.1:7400 --external-origin https://zxs.example.com --web-dir /opt/zxs/web --setup-disk P01=/srv/zxs/disks/P01 --smb-socket /run/zxs/smb.sock --smb-peer-uid 0 --smb-user zxs-owner
```

示例的 `0` 只适用于确认桥接在 Samba 可信 root 进程身份下连接的部署。该连接时机必须在目标 Samba 验证，不能放宽 socket 权限来适应未认证的进程。`/run/zxs` 及 socket 分别维持 `0700`、`0600`，`zxs-owner` 通过 Samba 独立凭据认证后绑定到唯一 ZXS 管理员；不接受 `Samba=ZXS` 映射、重复账户配置、匿名、guest 或 force-user 会话。Samba 配置须同时限制 `valid users` 并关闭所有 guest 路径，见[共享样例](../../../deploy/samba/smb.conf.example)。共享仓库拆分、恢复后必须显式重新绑定，不能自动接入迁移后的历史域。

共享样例的 `/srv/zxs-smb/empty-export` 是另行预建、root 所有且认证 Unix 用户不可写的真实空目录，其父路径须允许该用户遍历；具体权限见 [Samba 部署说明](../../components/smb.md)。不能将它放入 `/var/lib/zxs`、`/run/zxs`、spool 或数据盘私有树，也不能为共享访问放宽现有 `0700`/`0600` 权限。这个宿主空目录与 SMB 业务正文存储、私有 spool 均无关。

SMB spool 与 socket 目录分离，守护进程固定使用 `--management-root/smb-spool`，本样例为 `/var/lib/zxs/management/smb-spool`。完整工作文件、未确认操作证据和预算记录都留在系统盘，不能放入 `RuntimeDirectory=`、`/run` 或临时文件系统；模板的 `/run/zxs` 只保存可丢弃的 socket 运行状态。现有 `ReadWritePaths=/var/lib/zxs ...` 已覆盖该持久目录，路径单独按服务身份及 `0700` 校验，不安全或无法盘点只停止 SMB，不阻止管理 HTTP。无需用 `RuntimeDirectoryPreserve=` 保存工作数据，该选项也不能使 `/run` 跨重启持久化。旧 socket 邻接 spool 不自动迁移，升级前的留存材料处理边界见[SMB 集成](../../components/smb.md#smb-local-rpc)。

服务在启动状态 I/O 前注册 `SIGINT` 和 `SIGTERM`，模板使用 `SIGINT` 请求正常退出。处理停止请求时立即关闭新请求准入，SMB 空闲连接随即关闭；已接纳的 HTTP 连接有五秒网络宽限，届满后断开仍未结束的客户端连接。五秒不是整个停服过程的期限：已经接纳的阻塞持久化、发布及管理工作仍须等待完成，不能因客户端断开就释放其许可、删除恢复证据或强行宣称失败。启动期或运行期的内核文件系统调用也不能被信号安全取消。

模板保持 `TimeoutStopSec=infinity`，不会因网络宽限结束而强杀仍在排空的服务。若内核 I/O 持续卡住，管理员可明确决定强制终止；这属于崩溃处理，而不是正常排空，下次启动必须完成恢复。停服前后未收到成功响应不等于操作未持久化；重启后先核对原操作号或上传状态，不换新操作号盲目重做。未成功保存的完整工作文件及恢复记录保留。崩溃遗留的 socket 不自动删除，管理员确认路径身份和无存活服务后再清理；不要配置无条件删除 socket 或清空暂存目录的启动脚本。

一天内多次正常停服和启动应复用原持久管理目录与数据配置，等待前一进程完成退出后再启动下一进程。重复正常进程重启的回归不等同于物理主机关机开机验收：真实设备挂载时序、私有命名空间可见性、文件系统同步及掉电行为仍须在目标部署环境分别验证，不能由进程级测试宣称已通过。

## 数据盘故障与管理面

`zxs` 直接启动 HTTP/Web，不再需要 `serve` 子命令。管理目录、凭据、HTTP 暂存与监控位于系统盘的 `--management-root`；示例与池系统目录分开。数据引擎后台尝试打开，失败不能阻止静态 Web 和管理状态页。数据业务仍拒绝不安全请求，不会因 Web 可用而绕过元数据仲裁或自动重置池。系统目录不可用或监听端口错误仍可阻止服务启动。

监控历史缓存属于可重建的辅助状态。缓存无法打开时（包括缓存目录是被拒绝的符号链接）退回有界内存历史，不因此阻止 Web、登录、健康检查或实时监控。服务不会跟随该缓存目录符号链接、修改其目标权限或清理目标内容；修复前内存中的新历史不跨进程重启保留。不要通过放宽路径安全检查恢复缓存。

Web 静态目录无效或缺少 `index.html` 时，页面返回 `503 WEB_ASSETS_UNAVAILABLE`，但管理 HTTP API 继续可用；HTTP 暂存不可用只阻止上传，不阻止登录和管理。通过 `GET /api/management/status` 的 `auxiliary.web_assets` 与 `auxiliary.http_uploads` 分别核对，不把 `/healthz` 成功视为全部能力正常。修复目录、权限或发行件后重启服务；不要清空暂存和恢复证据来掩盖故障。

`--web-dir` 及其所有祖先必须是真实目录，资源树也不能包含符号链接。升级时正常停服后，把参数直接改为新版本的 `public/` 实目录；不要使用 `current` 等符号链接切换 Web 版本，否则静态资源准入会拒绝并返回上述 503。

生产启动前必须保持挂载目录身份和权限安全。`-` 路径选项只允许路径缺失，不代表空目录是一块有效磁盘；引擎仍验证登记身份。如果启动时目标缺失而被跳过，后来出现的挂载不能据此视为已经可见或可写；在宿主机恢复挂载后应重启服务，并在服务私有挂载命名空间中核对可见性、写权限和设备身份。此样例未做真实热插拔验收，也不自动挂载或格式化设备。

## 保留工作区证据的运行期额度

已有池可按[容量规范](../../19-capacity-and-performance.md#runtime-retained-workspace-limits)追加四项本机上限参数。必须保留原有完整 `ExecStart` 的路径、监听、初始化白名单及其他选项，不要只复制额度参数覆盖整条命令。更改后正常停服并重启，确认容量接口显示预期有效值；这些参数不修改池配置锚，也不是自动缓存扩容。系统盘恢复或更换启动方式时同样需要带上所需参数。

## 受保护的首次 Web 初始化

样例通过一个 `--setup-disk ID=PATH` 显式列出可用于初始化的磁盘，浏览器只能提交这些 ID，不能指定任意服务器路径。生产默认要求独立设备上的有效 Btrfs 挂载；不要在生产加 `--allow-development-setup`。初始化之前由部署者在管理目录私下配置 `bootstrap.key`：服务账户所有、普通单链接文件、0600、恰好 64 个十六进制字节且无换行；按 mtime 30 分钟有效。密钥不应放入命令行、日志或环境变量，Web 提交还需精确 Origin 和 CSRF 校验。数据盘失败或缺少密钥不会自动创建管理员或新池。

`--setup-disk` 与 `--setup-config` 的 ID 均为 1—64 个 ASCII 字母、数字、下划线或连字符，不是中文显示名或文件名；点号、空白及路径分隔符不允许。非法 ID 在启动参数检查时明确报错，不会启动后才从 Web 候选中消失。`PATH` 仍须为绝对路径；有效 ID 对应的盘或预设文件暂时不可用，不会因此阻止管理 HTTP 启动。

高级初始拓扑可通过本机审查的私有配置文件预置：在服务参数中追加 `--setup-config layout=/etc/zxs/layout.json`，同时为配置内的每个磁盘声明 `--setup-disk`。配置文件由服务 UID 拥有、0400/0600、普通单链接文件；不得把凭据放进此配置。Web 只选择不透明方案 ID，不接受任意路径或 JSON。仅授权提交选定方案时读取文件，预置缺失/损坏不阻止 HTTP 启动。草稿生成与安全离线编辑见[救援配置子域](../../components/rescue.md)。

最低配置仅需系统盘加一个存储盘，不强制配置后续备份级别。单存储盘没有冗余，故障可能造成数据丢失；系统盘管理凭据与静态 Web 仍可用于诊断，不能据此宣称数据可恢复。要启用可选多盘链，在启动参数与 `ReadWritePaths=` 中逐个登记额外盘；生产仍要求独立设备，已有多成员池不能以丢盘为由自动降级仲裁。
