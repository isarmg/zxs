## 23.1 支持范围

| 范围 | 当前入口与边界 |
| --- | --- |
| 服务部署 | 单台 Linux 服务器；发行目标为 Linux amd64 GNU ABI。最小部署是一块系统盘和一块数据盘，多级备份可选 |
| Web | 浏览器中的文件浏览、元数据、文件历史与分支管理、受授权管理操作；不提供文件上传、下载、正文预览或传输任务页 |
| SMB | Samba 和独立 VFS 桥接提供默认目录组合的基础文件访问；不依赖浏览器连接，不通过特殊路径提供高级管理 |
| 运维 | `zxs` 启动服务；日常管理和首次初始化使用受保护 Web/API；`zxs-rescue` 用于停服后的本机救援、历史包与未初始化配置草稿 |
| 内容与备份 | 实际写入保存独立 FULL 正文；按固定盘位路由保护，只有满足发布屏障才报告保存成功 |
| 文件与目录历史 | 创建分支先登记冻结引用，首次实际写入才产生正文；目录子树不可变，文件分支合并与 `MergeLink` 关系标记分别处理 |

SMB 模块须匹配固定 Samba SDK 单独构建，发行归档不含预编译 VFS。不提供原生桌面或移动应用、多服务器自动选主、跨机双活、NFS/WebDAV 或无条件离线自动写回。详细入口见[客户端能力](16-client-interfaces.md)、[Web](components/web.md)、[SMB](components/smb.md)及[发行说明](release.md)。

## 23.2 关键取舍

| 决策 | 收益与代价 |
| --- | --- |
| Web 与 SMB 分别接入、共享存储核心 | 管理和文件访问各用合适入口；权限、命名、保存及保护规则必须一致 |
| 只保存 FULL，分支先登记来源引用 | 不复制未写文件；实际写入承担完整版本与指定副本成本，不能靠硬链接、reflink 或跨树共享伪装独立性 |
| 固定分层来源与稳定盘位 | 职责和恢复路径明确；目标满盘或不可用时不自动借用无关盘位 |
| 固定 N ≥ 1 个成员，多数决定、全成员发布 | Q=floor(N/2)+1；不按在线数降低门槛。单盘无冗余，不承诺永久丢失后恢复 |
| SQLite 仅作可重建投影 | 权威依据是不可变对象、日志和发布证明；索引不能代替完整性或授权检查 |
| 文件合并、关系标记与标签分开 | 合并显式采用节点并推进参与引用；关系标记只连线；标签子节点复用正文，不自动拼接内容 |
| 清除正文与保留拓扑分开 | 文件历史关系可继续查看；已清除节点不保证正文可恢复，元数据仍占容量 |
| 历史域拆分要求独立材料 | 两树分别管理和恢复；需完整复制、重新编号、处理跨界关系，不能留下另一树依赖 |
| 单写协调器与显式冲突 | 不同文件可并行准备，最终发布串行；同文件及相关目录冲突不能静默覆盖 |

完整理由和替代方案见[架构决策](adr/README.md)；分支细节见[专题设计](design/README.md)。

## 23.3 当前限制

- 持久工作区证据默认条数上限为全池 4096 条、每主体 1024 条，限制未冷存记录，不是同时活动数。符合准入条件的普通及历史编辑空 `Aborted`，以及经精确发布绑定的普通和历史保存 `Committed` 及其后显式 `Aborted` 可冷存；所有冷热元数据仍计入字节预算。活跃、未决、未绑定或证据不完整的记录仍占驻留名额。冷存不删除永久历史事实、原操作 ID 及回执、全部 FULL 代际。支持本机启动参数显式提高有限的运行期上限，不提供在线 HTTP 调额；不得删除终态清单、回执或正文腾额，也不承诺无限保存或常数启动成本。按预计保存频率、元数据增长和服务周期评估[容量限制](19-capacity-and-performance.md#s19-11)。
- 有界元数据根实验源码按准确写集更新 Snapshot/catalog 路径，预算使用驻留精确摘要，但不等于端到端增量处理。完整旧依赖读验/安装和 compare/fsync 保留，无 PublishedGraphEpoch 跳读；history 仅稳定归属分支更新有窄 delta，其余 owner closure、State/冷恢复/重建仍有全量成本。驻留键/节点、单实体、本次候选与组合证明继续受实际容量限制，不承诺无限历史容量、性能已提高或格式已发布。见[有界根决策](adr/0006-bounded-metadata-roots.md)。
- 中断初始化仅在原意图与存储完成证明准确匹配的受限窗口可补全。ready 之前的部分登记不自动续做；权威发布后、凭据建立前的中断也不能伪装成空池重建。不得自动清盘或仅凭 pool ID 恢复初始化。见[初始化与恢复](management/setup-recovery.md#precisely-bounded-interrupted-initialization-completion)。
- 目录分支合并尚未实现；历史树拆分不是对任意分支模型都可执行，含目录组合的历史按当前核心限制拒绝。管理表单存在不表示操作满足执行条件。见[核心](components/engine.md)及[管理覆盖](components/daily-management-coverage.md)。
- 配置草稿仅用于未初始化部署，不是在线任意配置编辑器，也不代表线上换盘、拓扑迁移或安全卸载已经实现。见[救援工具](components/rescue.md)和[配置边界](21-configuration.md)。
- 当前严格校验唯一支持的存储格式，不提供不匹配旧格式的自动迁移、兼容回退或任意版本降级。配置锚缺失、依赖或证明无有效副本时失败关闭，保留现场材料。
- 物理断电、拔盘、长期容量与持续负载、全部浏览器和 SMB 客户端组合尚不能视为已验收。临时目录、软件故障注入、单一浏览器冒烟或 SDK 构建不能替代这些检查；性能须按实际硬件和负载测量。
- 集中许可材料仍有未关闭的复核项，特别是活动 Web 依赖的许可资料。来源清单或 CI 通过不能自动关闭这些缺口；分发前核对[集中合规说明](../compliance/README.md)。

## 23.4 规范依据

产品要求以[第 01 章](01-requirements.md)为入口，不变量以[第 02 章](02-concepts-and-invariants.md)为准；保存与发布证明由[第 10 章](10-transactions-and-recovery.md)定义，入口保存边界由[第 11 章](11-write-semantics.md)定义。操作手册说明执行顺序，不另定义行为。

[机器契约](contracts/README.md)只覆盖其中列出的对象和字段；静态 schema 校验不证明恢复、权限或真实平台行为。修改规则时同步更新当前规范、契约、样例和验收映射，避免同一规则存在相互冲突的说明。

<a id="s23-05"></a>

## 23.5 使用与发行前检查

1. 按[部署说明](getting-started.md)核对实际设备、目录权限、存储配置与入口能力；不得把模拟盘当作独立物理保护。
2. 按[第 22 章](22-acceptance.md)分别验证保存、失败、恢复、权限、容量与真实客户端行为。未执行、不支持或失败的组合不能列为已支持。
3. 使用实际候选提交及其归档执行[发行验收清单](validation/release-checklist.md)，复核资源生命周期、初始化中断和许可限制。源码检查不代替归档部署，旧构建结果不代替当前验收。
