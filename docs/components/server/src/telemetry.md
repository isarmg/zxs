# ZXS 状态、功耗和监测历史

独立的 ZXS 采样服务复用项目所有者提供的主机监测项目 `src/collectors/mod.rs` 的 CPU/内存采样实现。自有代码全部为 Rust；`sysinfo` 保持真实依赖包名。服务不枚举进程、网络连接、GPU、SMART 内容或远程代理。

`GET /api/system/status` 和 `GET /api/system/history` 均要求有效管理员会话。普通读者不能读取主机监测信息。返回值不包含系统挂载路径、传感器路径、物理设备身份或序列号。

## 实时值

CPU 使用率来自同一对象的真实计数差；第一次观察为 `null`，不制造 0%。使用 `sysinfo::MINIMUM_CPU_UPDATE_INTERVAL` 避免过快请求破坏基线。总内存、已用内存和可用内存按十进制字符串传输，已用值为总内存减可用内存。容量读取失败为 `null`。

CPU 的 `power_watts` 是所有 CPU package 的 RAPL 区间平均功率：读取 Linux powercap 的 `energy_uj`，用两次能量之差除以真实单调时间间隔，再换算成 W。已知 `max_energy_range_uj` 时处理计数器回绕，缺少回绕信息或量程变化时不输出伪造功率。只计算 `package-*`，不重复累计 core/uncore 子域，不使用 TDP、CPU 使用率或配置功率上限作为实测功耗。

每块登记磁盘的容量由存储核心读取其真实文件系统统计；`usage_percent` 为已用/总容量。磁盘功耗只读取与核心已验证的该物理磁盘或其 SCSI device 归属一致的 hwmon `powerN_input`，同通道缺少 input 时才使用 `powerN_average`；数值由 µW 转为 W。与主板、宿主整机或同一 PCI 控制器相邻的传感器不算该盘传感器。多个不明功率通道不直接求和。大多数磁盘/虚拟机不提供该接口，功耗会明确为 `null`。

Web 直接显示返回的 `used_bytes`，百分比缺失时才按已用/总容量计算；不能以总容量减可用容量代替已用值，因为文件系统预留空间可能使两者不同。`disk_sampling_unavailable:true` 明确表示磁盘采样失败，页面单独提示，不能把空磁盘数组解释为没有登记磁盘；有效的 CPU、内存和采样时间仍保留。

功耗字段与缺失原因：

- `cpu.power_watts` / `cpu.power_unavailable_reason`：`sensor_unavailable`、`sensor_unreadable`、`sampling`、`counter_reset`。
- `disks[].power_watts` / `disks[].power_unavailable_reason`：`simulated_disk`、`disk_offline`、`sensor_unavailable`、`sensor_unreadable`、`sensor_ambiguous`。
- 有实测数值时原因是 `null`；真实零功耗可返回 0，缺失传感器不会返回 0。

开发模拟盘共享底层文件系统时，其容量可能相同，不能相加当作多块独立磁盘；模拟盘也不会冒用宿主机功耗。

## 后台历史

独立的 `zxs-telemetry` 工作线程从服务启动起每 5 秒采样，无需浏览器打开。HTTP 的实时请求可读取最新计数，历史仍由后台独立采集。路由释放后，工作线程通过弱引用停止，不永久持有引擎或账号状态。

每个实例的私有、不可克隆 `HistoryWriter` 独占缓存目录、未完成分钟和维护时刻；启动同步采样使用同一个 writer，随后将其移交给既有工作线程。HTTP 持有的 `Telemetry` 只有共享历史和采样器，不持 writer，也不写历史。活动刷新可临时强持实例，完成后释放，睡眠时只保留弱引用；这里没有新增线程、队列、停机 flush 或线程 join 保证，也不提供同目录跨实例的写入排他性。实时请求和后台仍共享同一个带锁采样器，保持 CPU/RAPL 区间基线。

历史是 `system/telemetry-cache` 下的私有、可重建监测缓存，与文件版本、文件分支、发布序列和业务历史完全分离。它不创建存储发布事件，也不冒充文件历史。最近 1 小时保留 5 秒点，长期保留 31 天的分钟聚合点。每 5 秒追加最近点，完整分钟结束后追加分钟均值；重启时从真实缓存恢复，已完成但未保存的分钟可从最近点恢复。停机期间无数据，不补造采样。

缓存目录 0700、文件 0600，拒绝缓存目录/文件符号链接，不跟随 FIFO；只清理具有自身固定命名规则的过期普通缓存文件，保留外来文件。单行最多 64 KiB、单文件最多 16 MiB；有效时间范围最多 32 个日文件和 2 个小时文件；内存有点数及 128 MiB 编码数据预算。三磁盘常规配置可保留完整 31 天，设备过多触及预算时优先丢弃更旧的缓存。损坏或截断记录、未来时间记录被忽略。缓存无法创建、读写权限不足或存储只读等普通 I/O 失败时，启动和运行均退回有界内存历史，不影响当前采样或业务服务；符号链接等不安全的缓存目录仍拒绝。上传暂存目录的完整父路径在监测初始化之前创建，因此首次使用嵌套目录不会因缓存初始化顺序而失败。

编码预算沿用完整 `Sample` 紧凑 JSON 信封的字节数，包括充分统计；不含 JSONL 换行、队列结构或未完成分钟的暂存副本，不是进程 RSS 上限。最近点与分钟点分别记账，查询时排除重叠不减少实际保留队列的预算。每个入队信封计算一次长度，队列维护总量，出队直接扣除；恢复先按原有输入行字节上限准入、按时间键选择最终记录，再计算这些记录的紧凑编码长度，不能把带空白的原始行长度当作内存记账。计数、过期裁剪仍每次采样执行，编码预算仍只在分钟变化时检查：严格大于 128 MiB 才先淘汰分钟点、再淘汰最近点，并保留最后一个最近点。编码失败的记账仍采用原有 64 KiB 保守值，不替代持久化错误报告。磁盘格式、采样有效性、错误优先级及查询聚合不变。

writer 在历史锁外验证每轮输入一次，再按其独占的最后接纳时刻拒绝同秒和回拨输入；非法输入仍先报错。每轮最多准备一个已完成分钟和一个最近点，各信封只编码一次，同一编码结果用于记账和 JSONL 追加，编码字节在追加后释放，不随共享历史长期保存。先尝试分钟、再尝试最近点；分钟失败不跳过最近点，两者失败时保留最近点错误，两次尝试后才退回内存模式。失败仍在一次历史锁内发布全部新点并裁剪；读者在准备期间读取旧完整视图，发布后读取新完整视图，不复制全部历史，也不增加第二次接纳判定。

追加和目录维护均在历史锁外，维护仍遍历目录全部条目，不受有效缓存文件窗口数量限制。单独的维护失败不关闭持久化、不推进维护分钟，后续采样继续重试；本轮编码预算是否检查由维护前的旧分钟决定。启动恢复仍在共享历史锁创建前完成，恢复去重、未完成分钟重建及失败降级顺序保持不变；文件安全、类型、大小和受限读取检查仍在实际 I/O 边界执行。

增量记账避免对全部保留历史重复编码；新信封成本取决于其大小，预算总量比较和单次出队扣账为常数成本，但锁内裁剪还包含被淘汰样本的析构，整个发布不是 O(1)。正常持久化采样的编码路径从两次变为一次，跨分钟从四次变为两次；内存模式的一次／两次不变。这是源码结构计数，不是吞吐、锁等待或 RSS 测量。查询克隆/聚合仍保留原有互斥，不增加两份大查询临时内存并发驻留。历史预算单元测试使用独立全量序列化 oracle 比较增量总量、恢复替换、时钟回退、重叠队列、实际 128 MiB 精确边界及淘汰结果；writer 测试另覆盖错误组合、维护重试和受控读写交错。目录权限故障回归要求非 root runner，与普通 workspace CI 一致，不静默跳过。测试定义不等于执行通过。

```text
GET /api/system/history?range=1min|30min|1h|24h|1month
{
  "range": "1h",
  "from": "2026-10-19T00:00:00Z",
  "to": "2026-10-19T01:00:00Z",
  "interval_seconds": 10,
  "samples": [{"collected_at":"…", "cpu":{…}, "memory":{…}, "disks":[…]}]
}
```

`range` 默认 `1min`；其他值返回 400。`1month` 表示最近 30×24 小时。对应时间桶为 5 秒、5 秒、10 秒、4 分钟、2 小时，最多 361 个点。每个样本沿用实时字段结构；桶内只聚合真实存在的值、缺失值保持 `null`；最近点与分钟点覆盖重叠时排除分钟点，避免重复计算。分钟聚合为每一个指标分别保存有效观察次数与数值总和，再聚合时合并各自的充分统计，缺失值不加入分母。例如一分钟只有一次 100 和十一次缺失，下一分钟有十二次 0，合并结果是 100/13，而不是 50。容量的 u128 总和和有效计数保留在私有缓存中，API 仍返回十进制字符串，避免整数舍入在二级聚合中累积。缺少充分统计的多点聚合无法恢复有效计数，会保守忽略；合法单点记录可直接读取，并可重建最近一小时的分钟统计。采样时间是桶内最后一次真实观察时间，空桶不返回样本。

历史桶的 `online` 沿用桶末状态，不表示整桶都不可用。历史容量曲线保留桶内返回的有效均值，即使最后一次观察离线；全桶没有有效容量值时仍显示缺口。实时卡片继续将离线磁盘显示为不可用，不把历史均值冒充当前状态。

## Linux 数据来源

实现按内核公开 sysfs 契约读取；服务不写 powercap、hwmon 或硬件控制文件：

- [Linux Power Capping Framework](https://docs.kernel.org/power/powercap/powercap.html)：RAPL 的能量计数、量程和 package/subzone 层次；RAPL 没有瞬时 `power_uw`，所以使用区间能量差。
- [Linux hwmon sysfs interface](https://docs.kernel.org/hwmon/sysfs-interface.html)：设备归属、`powerN_input`/`powerN_average` 及 µW 单位。

测试覆盖能量差与回绕、package 去重、硬盘传感器归属及多通道歧义、重启恢复、损坏记录、缓存边界/符号链接保护、混合空值二级聚合与持久化、首次嵌套目录初始化、普通 I/O 失败内存降级、范围降采样、权限及无浏览器请求时继续采样。具体检查见[监测集成测试](../../../../test/server/integration/telemetry_status.rs)与[历史单元测试](../../../../test/server/unit/telemetry/history/tests.rs)。
