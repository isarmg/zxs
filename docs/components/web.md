# ZXS Web 界面

`src/web/` 是 Rust/WASM CSR 产品界面，`src/interface/` 将共享组件、浏览器生命周期和 CSR 基础原语直接合为同一包；`src/macros/` 提供过程宏编译目标。所有组件共用根工作区与锁文件，第三方基础实现位于 `src/foundation/`。来源与许可统一见 [compliance](../../compliance/README.md)。

Web 仅支持[现代浏览器能力契约](interface.md#modern-browser-contract)，缺少必需能力明确启动失败，不提供旧浏览器兼容或原生圆角降级；具体浏览器／操作系统组合仍须实际验收。

浏览器通过同源 `/api/` 完成身份验证、文件与版本操作；SMB 是独立的 Samba 集成路径。构建与运行均不依赖兄弟项目目录。

## 管理导航与对象详情

原单页“系统管理”拆成四个主菜单，沿用同一认证会话与管理模型：

| 菜单 | 实际入口与边界 |
| --- | --- |
| 磁盘与接入 | 登记磁盘树、逐盘健康与备注、初始化/转换/外来盘向导；未完成动作仍按各自回执展示，不把保存意图当作接纳完成。 |
| 仓库 | 创建独立历史域及命名共享；不是初始化目录 Git 仓库，也不提供文件/目录分支编辑。 |
| 备份与放置 | 保留路径副本规则与主盘规则；明确为只影响后续版本的高级路径规则，日常稳定身份备份从对象详情进入。 |
| 恢复与检查 | 原有存储恢复、13 项只读诊断查询、原操作未知结果查询、既有计划精确摘要审阅/取消/提交；计划可查询不等于当前核心支持执行。 |

更换某盘的下一级备份盘必须迁移所有数据，并展示真实进度与未完成状态；只有后端迁移终态凭据才可确认完成。本片未提供该迁移入口，也不把添加磁盘或未来版本主盘放置规则当作替换完成。

旧整树历史分支、手工合并连线、清理预览、拆分预览、历史保存预览的 Web 创建表单及其专用请求/响应分支已删除，不转移到“高级”菜单冒充当前模型。底层 API、持久化数据、已有计划和安全恢复能力不删除；真实 HTTP 测试对旧后台接口直接取值，只有仍在用的配置及计划审阅复用 Web 请求边界。诊断旧历史对象是只读检查，不能代替文件或目录详情中的分支/节点管理。

文件详情保留真实文件分支、节点、标签和合并操作。文件列表新增“当前目录详情”；原来散落在列表的目录分支创建/浏览/默认选择/重命名、初始化、暂存、提交与 checkout 现在实际渲染在此详情。选择子目录后的详情入口先更新目标并发起该目录读取，控件继续按真实读取完成前的原准入保持禁用，不借旧整树 API。仍无目录合并入口。当前目录详情保留原位置、查询和分页；提交准入继续核对会话、目录、仓库、代次与已读取依据。

菜单切换不清除当前配置草稿、已审计划或未知操作 ID，不自动切换表单种类；用户显式选另一种配置才切换表单。待完成/未知写入禁止换表单，原操作查询在四区可用。普通浏览器整页刷新仍受既有内存围栏边界约束，不声称跨刷新持久恢复。主导航使用原有换行布局；诊断 JSON 在面板内部滚动，不能撑宽手机页面。原生状态测试、WASM 编译和真实浏览器验收应分别报告，不相互替代。

首次空盘建目录、文件移动和目录分支原请求已有终态但本机记录清理失败时，重试清理成功后会重新执行原有有界本机记录扫描；只有扫描和原记录合并成功才解除残留错误。不会因删除一个键就清除另一条损坏或冲突记录的错误，也不会重新提交原写请求。普通无错误清理不增加扫描，其他待确认请求与写入围栏保持。

当前目录详情提供与文件列表相同的“新建文件夹”原位操作，复用原请求保留、未知结果围栏和确认后刷新。尚无仓库身份的空主盘先提示创建第一个文件夹，不再要求点击尚不存在的仓库初始化入口；取得仓库身份后，仍须明确初始化所选目录，不自动初始化或提交。首目录提示只依据当前未筛选的可写空根读取，读取中、备份盘、搜索空结果和已有命名仓库的虚拟根不作此推断。

## UTC 时间约定

界面直接显示服务端提供的 UTC 时间，不按浏览器语言、本地时区或用户位置换算。文件历史节点与操作记录统一使用 `YYYY-MM-DDTHH:mm:ssZ`，相同格式可直接排序；节点父子关系仍优先于时间。监测及健康检查的 UTC 字符串原样显示。监测图表仅为横轴坐标解析明确的 UTC 时间，不另设本地时间表示。持久化时间事实、会话有效期和单调时钟不因界面展示而改写。

## 页面与操作

默认进入文件页面，首先显示 P01、B01、C01 等独立硬盘目录。磁盘列表按当前八字段契约严格解码；离线成员仍保留行并禁用打开操作，容量未知显示“不可用”，不显示为 0。成功零容量仍显示零字节；观测失败只展示共享阶段/错误码的安全分类，不显示内部路径，解析失败保留来源。进入目录后使用面包屑、新建文件夹/重命名/删除工具栏、当前文件夹搜索和文件列表；详情在独立菜单页显示。菜单、工具栏和说明按与列表相同的紧凑文字留白排布。这里浏览的是服务管理的文件命名空间，不展示服务器系统路径。主盘按业务可写状态写入，备份盘只读查看实际持有的内容。

- **有界文件列表**：每页最多 200 项，前后翻页替换当前页，不无限追加条目。搜索和目录优先的名称排序由服务端在分页前全局执行，浏览器不逐页重排或仅搜索已加载条目。搜索框整块可点击输入，空输入显示提示，输入后隐藏提示且保留读屏名称；输入与清空只修改草稿，按 Enter（非输入法组词或按键长按）才立即提交当前文件夹搜索。提交查询或导航立即取消旧读取，并以会话、位置及请求代次拒绝迟到响应。全选只选择本页，翻页、搜索或目录导航清除本页选择；不默认为选中未加载条目。快照失效时提示并返回第一页，失败可显式重试。普通详情刷新通过精确路径和身份请求独立的 `selected_entry`，不能因条目不在本页就推断删除，也不能自动接纳同路径的新对象。原生表格及公共 G4 布局保持不变。投影、生命周期及验证边界见[文件列表分页快照](../architecture/file-list-projections.md)。
- **磁盘列表读取状态**：文件页区分当前已取得列表、读取中和未取得当前列表。刷新未完成或失败时保留已有磁盘行，并明确显示是上次读取结果；未取得列表不显示为成功空列表，也不把整次读取失败解释成每个磁盘离线。未确认状态提供“重新读取”，使用原有会话／代次保护和单次读取门禁；读取中不提供重复按钮。提示不改写各行在线／读写策略、不清除错误中心诊断，不添加文件内容传输或备份路径。
- **文件与分支**：文件详情以真实父节点关系展示历史树，箭头从父节点指向子节点；没有来源记录的版本独立显示，不按时间虚构连线。节点卡面分为备注标题、行为图标两行，展开详情保留日期、完整备注和操作；可写视图的操作包括“编辑备注／编辑标签／创建分支／从此节点合并”，只读副本仅显示只读标记；当前标识与日期同行。分叉、多父关系与跨层连线完整保留；连线为等粗实线，水平／垂直正交布线，转弯为圆角，并按实际节点尺寸绕行；手机仅在树内部横向滚动。创建分支只登记父节点引用，不创建占位文件或复制来源正文，也不增加内容版本，创建后不自动切换。待写入分支在下拉框标出；切换后继承并显示父版本，可查看元数据，也可从当前可见父版本再登记分支。历史树包含真实正文节点与复用正文的路径节点：文件或文件夹改名时新增路径节点，正文版本不增加；后续写入以路径节点为父节点。分支登记本身不增加历史节点，可见的继承正文仍标为“继承的父版本”，不会将父版本改归新分支。首次成功写入后才产生该分支自己的内容版本，零字节写入同样是实际版本。切换保留当前路径，不改变其它文件或目录。文件尚无独立分支时显示主版本。首次写入自动生成的公共文件分支也可通过当前选择器旁的“重命名文件分支”原位改名，使用同样的 128 UTF-8 字节行内输入，只改标签，不新建文件内容或目录子树。
- **独立目录仓库**：先明确点击“初始化此目录仓库”，当前目录才成为类 Git 独立仓库。未初始化子目录归最近已初始化祖先；文件保存立即持久化为未暂存工作修改，不自动生成用户目录提交。点击“暂存本仓库工作内容”固定当前自有内容；暂存后继续保存的内容保持可见但不进入本次提交。状态明确区分已暂存和未暂存。独立子仓库提交后，其父级显示引用变化，必须另点“暂存此子仓库的当前提交引用”；父级提交只包含本仓库已暂存内容及子引用，绝不递归替子仓库提交。独立边界变化时必须明确“暂存本仓库工作内容”后再提交，此操作不自动追随子 HEAD。提交固定所审阅的工作树与 index generation，说明限 128 UTF-8 字节；读取中、失败、会话/目录改变或发布不确定时禁止写操作。普通浏览读取工作内容，历史需要明确选择，内部恢复检查点不充当用户提交。历史节点的“浏览此快照”仅按已验证的分支与不可变树读取，不能直接设为默认，也不能提交或修改；返回默认视图后继续当前工作。目录分支创建、浏览、设为默认和重命名仅在当前目录已独立初始化时开放；详情入口先进入该目录核对状态，不按旧分支记录推定已初始化。分支 ID 保持稳定，创建分支不复制正文，文件分支和已启用 SMB 的当前视图仍沿共享命名空间工作。
- **批量文件操作**：文件列表支持勾选多个文件或文件夹，然后在页面内移动、复制、删除或逐项改名。源目录分支逐项勾选，移动与复制逐条指定“源分支 → 目标分支”，不推断所有两两组合；可添加映射以接收多个目标分支。目标目录读取和审阅不切换 SMB 默认入口。所有条目携带稳定身份及捕获的依据子树，同一批原子发布；某个选中分支缺少条目、名称无效或服务端冲突时保留输入，整批不会静默跳过。尚未独立初始化的范围提供明确的源／目标目录仓库初始化按钮，绑定当前命名空间头；普通读取不写元数据，也不自动跨出独立子仓库边界。未选分支、历史版本及真实移动后的旧逻辑引用由核心保持。
- **文件分支合并**：默认从“合并分支”或任一真实节点的“从此节点合并”进入，直接在图上选择至少两个不同输入节点，再选择采用的结果节点及新分支名称，不手填节点、分支 ID 或代数。可跨页选择历史输入，包括同一分支的不同历史节点；来源节点与来源分支当前头分别捕获，提交按当前头做并发校验。若旧正文节点未带来源分支，点选时单独按当前根读取真实祖先证明，不猜当前分支，也不让普通历史页承担此搜索；无独立来源时明确提示先从该节点创建分支。历史合并在同一事务中派生分支并始终创建新的合并元数据节点，采用所选结果的正文与标签，不自动拼接文件内容；原分支、较新节点、旧节点父关系及默认视图保持。归档分支和合并别名可作为来源，结果正文仍须真实可用。仍可显式切换到原“合并当前分支并结束其他参与分支”操作：选择两个以上可写分支及保留分支，其他名称变成只读别名。两种操作均有完整来源记录、当前权限和精确依据重审；目录／整树合并不在此功能范围内。
- **节点标签**：每个历史节点展示自己的标签。可勾选多个节点，选择关联的可写分支后批量添加或移除标签；标签片及输入均在页面内，最多16个标签、每个128个UTF-8字节。修改新增继承正文的元数据子节点，原节点不变；编辑历史节点只推进仍指向它的引用，不回退较新正文。没有标签变化时不请求写入。
- **备份设置**：文件、文件夹及当前目录都可读取保护策略；唯一管理员可在会话有效且存储可写时编辑，不再返回 `can_manage` 权限投影；备份盘、只读别名和其他业务限制仍有效。总份数包含主盘，每个目标盘各有相对逻辑前缀，前缀最多768个UTF-8字节。同一范围包含多条历史主盘路径时，读取完整 `backup_routes`，按所选份数收集每条链所需备份槽，份数上限取最短链；读取时将编辑器消费的范围身份、自身代数、继承标记、份数、前缀、路线、上限和路径解析为类型，只接受当前 `backup_routes`、明确的 `max_copies` 及字符串映射形状的 `backup_prefixes`／`backup_paths`；必需数据缺失、错误类型或旧格式失败关闭并保留具体解码来源，不从旧路线字段或数组别名推断，也不将损坏前缀过滤成可保存的空串。合法前缀映射中未配置的目标槽仍表示空前缀；未消费的 nullable 策略字段不新增限制。保存始终包含读取时的范围稳定身份与自身策略代数；继承上级规则时自身代数为0。单文件追加配置时绑定的文件名，目录追加相对所选目录的路径；主盘改名或移动不自动改变绑定的备份位置。备份盘文件页显示这些逻辑前缀，`path` 仅用于备份浏览，显式 `repository_path` 仅用于读取真实主目录上下文；主目录引用已删除时不构造假路径，直接按稳定文件历史读取。备份详情固定其实际存储的节点及正文版本，隐藏修改控件，历史返回的较新主盘节点不覆盖当前副本。冲突保留输入，结果未知时查询原操作。
- **元数据保存**：新建文件夹、改名、删除、分支、合并、标签、备注与备份配置通过服务端事务发布。文件页与技术管理页共用当前 HTTP 回执校验，只有原操作 ID 匹配、字段完整且发布证据一致的直接回执才能确认结果；不接受旧 `operation` 包裹或仅有 `state` 的成功对象。即时回执与不确定结果轮询使用不含健康观察的 outcome 形状，轮询走 `/api/operations/{operation}/outcome`；显式诊断才走原 operation GET，不把缺少观察解释为健康。冲突保留草稿；空值、缺字段、矛盾回执及其它未知结果保留草稿、原操作 ID 和写入围栏，继续查询原操作，不把 HTTP 2xx 或网络失败显示为保存成功。
- **备注**：文件备注、正文版本备注与路径节点备注分别保存，每项最多 128 UTF-8 字节，禁止换行与控制字符。历史卡片展开详情后，点击编辑备注将完整备注原位切换为行内输入；Enter 保存、空值清除、输入法组合期间不提交，Esc 或失焦取消。新建目录、改名和分支采用同一原位交互；文件与目录名称统一遵循当前 `PortableName`／`PortablePath` 规则，不套用备注的 128 字节限制，完整目标路径仍须符合长度与深度预算。分支名称保持 128 UTF-8 字节限制。卡片首行仅视觉省略长备注，悬停标题和展开详情保留完整原文；编辑值不截断；展示层不承诺旧格式备注可被引擎读取。删除在页面内审阅条目及分支后提交。路径节点空备注显示“改名 旧路径 → 新路径”；从路径节点创建分支保留正文版本与来源节点引用。
- **状态**：管理员查看真实 CPU 使用率、CPU 功耗、内存、各盘容量与功耗，每 5 秒刷新。带图标的卡片顶部是实时值，下方是真实历史折线；范围为 1min/30min/1h/24h/1month，最后一项代表最近 30 天。所有卡片为 3:2，桌面固定四列，末行仍保持单列宽度，手机每行一张。后台每 5 秒独立采样，分钟历史缓存保留 31 天，重启恢复。缺失采样断线，缺失传感器显示不可用；功耗不根据使用率或 TDP 推算。共享底层设备的登记目录容量可能相同且没有独立功耗，不能作为独立物理盘相加。数据来源和缓存边界见[监测实现](server/src/telemetry.md)。
- **完整性巡检**：现有状态页的只读面板每 5 秒查询真实 `/api/admin/scrub`，区分最后查询的检查新鲜度、当前排队/运行/取消排空状态、固定基线、实际读取与预期正文、最近终态和最后完整成功 UTC 时间。存储 Ready 与写成功不代替完整检查；取消、过期和部分故障不显示成功。刷新失败或响应格式无效清除旧绿色结论，会话代际拒绝迟到响应；不新增后台任务、浏览器自主扫描、文件内容页面或私有字体/几何样式。
- **历史记录**：展示最近已提交的文件活动记录及时间、路径和主体，可以按硬盘筛选；这是近期活动概览，不是完整的逐路径取证审计。删除记录来自已提交的命名空间事实，逐次记录删除时的逻辑路径和时间；删除单个别名、删除后复用路径及同次操作重复删除同一路径均保留独立记录，普通改名与仅大小写改名不记为删除。删除活动不绑定正文身份，也不延长正文保留。文件自身的版本、分支和备注在文件详情中查看。文件操作历史与状态页的监测历史分别保存。
- **账户与显示**：登录、退出、HttpOnly Cookie 会话恢复、CSRF、自助改密、错误反馈、主题及中英文切换。系统只有一个管理员，用户名在初始化时自选，之后只读；没有其他账户、角色、禁用或仓库 ACL 表单。改密成功后全部会话撤销，必须重新登录。管理页表单、查询、操作及本地输入反馈使用 `admin::messages::Message` 有限稳定 key 和集中中英映射；请求构建模块仅保留纯查询标识与唯一端点表，UI 动作及查询文案映射留在本地化模块，不向服务端契约测试引入浏览器依赖。协议 action/type/JSON 字段标识、返回的 JSON 和远端诊断保留原文。其它组件仍有 `t(zh, en)` 调用，尚未完成全站稳定 key 迁移。文案沿用公共语言选择接口，切换语言通过 `lang` 参数重新加载并恢复会话。

Web 不提供文件上传、下载、正文预览、“写入当前分支”或传输任务页面；文件浏览、元数据编辑、版本树、账户、状态和历史保留。文件正文通过 SMB 或受控 HTTP API 读写，这些协议及接口保持不变。项目不提供原生 App、WebView 宿主或 App 安装包。主页面不展示整树合并、清除或拆分等技术管理表单；含独立文件分支时，未适配的旧整树高级操作由核心明确拒绝，不隐式改变文件分支语义。

Web 系统管理不再提供独立的仓库 SMB 绑定编辑或查询表单；默认目录视图直接驱动共享，无需手填仓库、分支或代数。账户页的 Samba 账号与密码管理保留。历史拆分、恢复或旧显式操作留下的禁用状态不会被自动启用，后台绑定 API 与既有会话失效机制保留。

## 紧凑历史节点卡片

文件和目录历史图的节点卡面采用约 **10 个英文字符宽（10ch）** 的两行圆角框。第一行是节点备注或目录提交说明；空备注明确显示“无备注 #序号”，不以路径或行为词伪装用户备注。10ch 是卡面总宽，标题左右各留 .5ch，文字区域约 9ch；长中文、英文和表情只作视觉省略，完整字符串保留在提示、可访问名称和展开详情中。仅空字符串触发无备注回退，纯空白备注仍原样保留。第二行只有简笔画行为图标，分别带可访问名称及提示。正文为青色、重命名为蓝色、移动为橙色、标签更改为紫色、合并为玫红、目录提交为绿色、未细分的路径变化为中性色；亮暗主题分别提供至少 3:1 的图形对比，行为同时具有不同形状和名称，不以颜色作为唯一线索。当前态使用共享 G4 支持的外投影圈线，并仅将当前卡切为 paint 模式，避免 clip mask 裁掉外圈弧段；普通历史卡仍采用 clip，标题省略由文字行自己的 overflow 保持。不采用会使整个卡面退回方形的 inset 阴影。

卡片是原生 `details/summary` 展开入口，Enter、Space 和点击只显示或收起原节点详情，不改变当前分支、所选文件、写权限或提交状态。详情保留原有日期读取、完整备注及编辑、标签、分支与合并控件、父关系和正文处置状态。收起不卸载编辑器，刷新继续按稳定节点身份保持已有编辑。展开的详情允许比 10ch 卡面宽，现有 DOM 测量继续为实际占用范围布线。

文件图标只映射已接纳的 `Content/Rename/Tags/Merge` 类型；路径事件仅比较该节点保存的新旧路径，分别识别父目录变化与文件名变化，二者同时变化时显示两个图标。不从备注、标签、当前路径或邻居节点猜动作。节点缺路径细节时只显示“路径变化”图标。目录 API 没有逐操作种类，只显示真实目录提交图标，不解析提交说明。删除的垃圾桶线稿及红色方案已有设计，但当前文件历史协议没有删除节点，不在图上生成删除事件，也不把正文清除或普通目录条目删除冒充此类节点。

## 管理初始化与首次存储激活

首次安装表单只创建唯一管理员，提交 `username/password`，不选择磁盘、预设或存储模式。成功回执严格为 `{initialized:true,storage_pending:true}`；管理就绪不等于数据存储就绪。登录后在“磁盘与接入”从固定发现父目录的直接候选中选择磁盘并完成向导；不提供任意路径或挂载选择。

未配置存储是首次设置状态，不在每个页面展示全局恢复按钮。管理页保留状态说明和“检查管理状态”；已就绪或未配置时不显示无事可做的存储重试。未知、只读、不可用、恢复要求和终态管理仍显示对应全局状态；独立认证故障、请求失败、正在恢复及未知重试结果也不会因存储状态变为已就绪或未配置而隐藏。合法恢复入口保留原会话、忙碌和未知结果围栏，状态变化不切换页面或销毁行内草稿。

管理状态 GET 与存储重试 POST 在进入模型前按当前响应类型解析一次，复用同一存储观察投影；内部不再用 JSON 下标和默认 false 判断状态。未知枚举、缺少必要字段、错误布尔类型和多余字段返回明确响应错误，不清除认证恢复或未知重试围栏，也不启动磁盘／目录刷新。当前嵌入式 Engine 的 Ready 响应可以省略 recovering；管理后端必须提供该字段，null 不代表 false。未消费的 auxiliary 详情仅随当前信封接纳，不参与存储授权。原始 HTTP 错误保留关联编号；响应解析错误保留实际 HTTP 状态和错误来源。只有后续有效管理观察能解除重试未知状态，不会重发 POST 或将其视为文件写入回执。

首次激活通过受认证的固定范围自动发现取得 `CandidateSelection`，分别保留 `mount_path/root_path` 和设备、挂载、目录身份，再提交所选集合及模式。目录须已经存在、为空、由服务账号拥有且权限为 0700；Web 不创建、挂载、格式化或修改目录权限。选择响应不是永久授权，激活仍复核身份和当前管理员。

激活与补全成功回执严格为 `{activated:true,restart_required,recovering}`，后两者恰有一个为 true。请求开始时捕获动作和会话；未知结果保留围栏并查询存储状态，不自动重发。只有服务端返回 `completion_available:true` 才能补全原持久意图，不能改选目录、重建池或重置账户。旧公开预设初始化和初始化补全端点已移除。

管理账户与首次存储激活分离。既有池的添加、下线、注销及重新启用另由[在线目录成员管理](../design/online-disk-management.md)的独立状态机处理，不把首次激活称为在线扩容。相关源码已接入管理页，但完整 HTTP/Web、持久中断和真实设备验收尚未完成，不能据此声明可部署。

自动发现与磁盘向导只使用 systemd 固定发现父目录下的直接孩子，不提供自由路径、挂载或递归浏览控件。候选身份变化会移除过期暂存项并清除确认；未知提交结果阻止修改意图。普通目录经真实转换预检后，只能选择独立空目标创建新的一级盘，再将原文件名和内容导入新盘根；源不改写。当前需已有活动池，不支持直接将普通源作为第一个池，也不进行原地转换。界面明确展示内容与临时字节预算、元数据角色、仅内容转换及两阶段非原子风险；已登记不等于已完成导入，必须核对原 import operation 的发布结果。中断保留原编号及工作区，已有工作区时不启用重建导入。新盘注册已完成后，可以明确勾选“停止并保留”；服务器必须证明没有未决发布并给出独立永久停止回执，才显示已停止且允许新计划。来源、新盘和暂存文件均不自动注销或清理。停止中的未知结果只查询或重试原停止，不恢复导入；若原导入已永久发布，仍显示实际完成，不伪造停止。外来 ZXS 可以明确点击只读历史检查，复用固定候选来源身份；先展示原盘声明或成员代际证据，再展示真实预检的发布检查点、核对摘要及按可证明原一级来源分组的历史。正文已核验、暂不可用、已记录清除和迁移分别计数，缺正文不裁剪历史。检查限 128 组历史、10,000 个版本及 8 GiB 本地正文，超预算完整失败而不截断。当前执行能力明确不可用，没有并入、降级或重建提交按钮。

已保存系统盘审核后，可另行预览并明确确认保存目标数据盘执行意图；成功仅为 IntentSaved，未知结果保留原编号、目标身份和摘要，只查询或重试原请求。此步骤不复制、接纳、预留或发布，见[向导边界](../design/foreign-migration-wizard-next.md)。

## 浏览器异常与错误中心

管理类 GET 在同一文档内通过有界 FIFO 发出：最多一个在途、32 个等待，为服务端原有两槽管理预算留出余量。覆盖磁盘／存储管理、首次设置读取、工作区容量和 capabilities；普通文件读取、认证及写请求不进入这条队列。原 120 秒时限包含排队和响应消费，许可随真实响应持有至正文／解码完成或失败，不在收到 headers 后提前释放。队列满是本地明确失败，真实 429 保留原状态、错误码、详情和请求标识，不自动重试。

具有原 `ReadCancellation` 的请求可在排队时取消；任务丢弃也会移除自己的等待项。管理页面的既有读取并非全部持有页面取消句柄，因此不能声称每次导航都会取消管理读取。凭据变更使旧等待项失效并唤醒它们，但不重置仍在途的许可；出队前再次核对捕获的凭据代次，旧 401 不能清除新登录或新队列。原 UI 会话／请求代次校验保持。该调度只约束同一文档的 GET，其他标签页、POST 或客户端取消后仍在运行的服务端任务仍可能造成真实 429。范围与验证见[管理读取排队](../validation/management-read-queue-20261106.md)。

浏览器边界只解析一次 JavaScript `Error`／`DOMException` 的实际名称、消息，并在错误来源链中保留原始值；普通字符串拒绝保留原文。fetch 失败也可能来自浏览器策略，不能一律解释为断网。启动准入先验证 `AbortSignal.reason` 保留独立取消对象的身份；读取 owner 主动取消与请求超时只有在失败值确实等于同一个已中止 controller 的 signal reason 时才分类，取消和超时以首次中止为准；仅名为 `AbortError` 的异常不能证明主动取消，缺少 reason 的浏览器也不能把无关 `undefined` 拒绝误判为取消。该上下文同样覆盖响应正文读取，不以已收到响应头代替完整回执。

取消、超时及其他传输错误均不证明写入未发布。提交仍按原 HTTP 状态与完整回执规则保留 Unknown、草稿、原操作 ID 和轮询围栏，不自动重放写入；被新导航取代的读取继续由既有会话／请求代次围栏拒绝迟到结果。

错误中心最多保留五条提示。原操作 ID 或精确读取资源（含查询范围）与捕获的会话代次、错误码、HTTP 状态共同标识一条提示；同一工作的重复失败更新最新消息和 `request_id`，不因每次轮询产生新请求 ID 而重复入列。不同操作不按路径或错误码合并；没有明确工作身份的一次性失败保持独立。关闭使用稳定提示身份，不依赖移动后的数组位置，后续失败可以重新出现。提示去重不跳过当前会话的 401 失效处理，也不修改操作收据与恢复准入；后续成功查询不会静默删除既有诊断提示。

工作区操作提示与登录页会话提示分开保存。普通保存或目录组合恢复成功只属于发起操作的当前页面／目录访问，五秒后自动关闭，也可手动关闭；切换页面、磁盘、目录、条目、搜索或列表分页时清除该访问的成功／本地输入提示，并撤销显示后续普通成功的归属，迟到回执仍结算原操作但不在新页面显示，也不会在返回旧页面后重新出现。新操作替换旧提示，同一回执轮询不反复刷新提示或计时器。降级发布、未确认结果及本地输入警告不会按成功超时隐藏；未确认／降级发布警告在导航后仍保留，终态成功只清除原未确认警告，不在新页面显示旧操作的成功提示；目录恢复文案不能覆盖保护不足警告。请求失败清除仍显示的普通成功，但不删除错误中心诊断。导航和关闭提示均不改变原操作记录、未知结果围栏、草稿结算或请求关联。成功计时器由当前界面 owner 持有，在替换、导航、关闭及销毁时释放；过期回调带会话和提示身份，不能误删后续提示。

## 系统管理的目录、磁盘健康与备注

主导航在文件、详情、状态、历史记录之外提供“磁盘与接入”“仓库”“备份与放置”“恢复与检查”四个管理菜单。“恢复与检查”始终保留“全局存储与认证恢复”：既有管理状态检查、数据存储重试、认证恢复说明和未知结果围栏均保留，不依赖数据后端可用。其他页面在存储不可写时仍显示恢复控件；后台状态变化不再强行切换页面或销毁编辑草稿。这个全局服务状态不是 SMART，也不会套用到各张磁盘卡。

“登记目录、磁盘健康与备注”先展示按真实复制来源排列的备份磁盘树：第 1 层主盘在下，第 2 层及更高层备份盘依次向上；卡片只使用登记的真实层级数字，不再把备份顺序减一后另行编号；同一层级横向对齐，独立来源链分别占列，箭头只从实际来源盘向上指向其下一层备份盘。层级表示配置顺序，不是已经执行的备份次数、文件当前副本数或物理独立性证明。读取时解析必需的层级、明确的 nullable 来源和在线状态，拒绝重复身份、非法层级和矛盾连线；来源已注销时保留目标盘及“来源未登记”提示，不虚构节点或连线。空列表显示原空态；刷新失败保留上次关系并标为非当前状态。 未经向导接纳的自动发现候选独立置于最下方 -1 层，在一级主盘下方，不画备份箭头；点击打开并聚焦处理向导。空目录可核验后暂存、审阅再接纳；初始每个目录都是独立一级盘，不按选择顺序构造备份链。

选择树中的磁盘后显示该盘原有的详情与操作卡，离线磁盘也可查看。列表刷新保留仍存在的选择；选择已注销时回到最低层级的首盘，无盘时清空。切换节点保留各盘备注草稿及原保存依据，不改变健康查询、退出／重新启用或备注保存的准入。每张卡分别保留型号、完整序列号、容量、当前挂载设备路径、挂载目录、登记存储目录、文件系统 UUID 和 zxs ID。zxs ID 是登记身份，既不是文件系统 UUID，也不是物理硬盘序列号。长标识完整显示并可换行复制；未知观测明确显示不可用。

下线／注销按钮使用 `/api/admin/disks/registrations` 的已认证当前登记，与目录卡的 slot/disk 身份交叉核对，不从设备在线、SMART 或池总体 Active 状态推断登记。Enabled 可预览下线或注销；Disabled 只可预览注销，不能再次下线；未准入或无 voter 管理态不提供新的退出。预览及首次提交绑定原 slot/disk、binding generation 和元数据角色，登记变化后须重新预览。完成回执必须同时匹配原目标、动作、binding generation、最终登记状态与 `target_io:closed`。离开页面或关闭未提交预览只撤销该预览与迟到读取的 UI 归属，已提交原操作和恢复编号始终保留。退出与重新启用的状态读取各自持有准确请求代次：继续原操作使旧 GET 结果失效，但旧 GET 仍只释放自身读取槽；迟到完成不能释放后来的 owner，避免永久占用或覆盖新状态。服务端仍独立校验准确 registry、来源与授权；UI 检查不是权限或持久化证明。此接线的新增回归源码尚未运行。

每张目录卡的“硬盘健康”只消费该目录详情里的设备报告。成功报告显示实际查询的整盘／NVMe 命名空间路径、原生 NVMe 或 SAT 采集与 smartctl 离线解释来源、UTC 采样时间、SMART 通过／当前异常／告警记录、设备提供的温度和通电小时数。挂载分区路径与实际查询设备路径分开呈现；同一设备上的多个登记目录可能显示相同设备，不视为独立磁盘。零温度／零小时仍是有效观测；缺少可选测量显示“未提供”，不补成零。

无法确认映射、多设备、设备不支持、工具缺失、权限不足、低功耗跳过、繁忙、超时、查询失败、设备变化、格式无效或总体状态不完整，均显示明确原因及“不可用／未知”，不推断健康。成功 SMART 只是采样时设备自己的报告，不证明无故障、目录数据完整性或副本独立性，也不控制存储写入准入。服务不会为此提升权限、更改 systemd 沙箱或开始自检。现有设备权限关闭时无法读取真实 SMART 是预期结果；服务器读取边界见[契约说明](../contracts/README.md)。

进入“磁盘与接入”加载登记目录，再逐卡读取详情；列表及每卡均可手动刷新，不增加硬件轮询。初始／批量卡片读取依次进行，避免多目录同时争抢单个受限健康查询槽；原会话或列表代次改变时停止后续旧队列。一张卡读取失败不影响其它卡。失败时保留旧信息并明确标注“上次读取，不代表当前状态”；迟到响应仍受会话／读取代次围栏控制。备注按登记身份保存在系统盘，支持普通多行文本，安全文本渲染，不套用文件节点备注的128字节规则；仍受既有HTTP请求总量限制。保存继续携带 `expected_disk_id` 和 `expected_note`；冲突或结果未知保留输入，刷新不覆盖编辑文本或CAS依据，取消不撤回已发送请求。未知健康、多设备映射和数据存储只读不额外禁止备注；权限及系统盘I/O失败继续明确处理。

## 技术管理请求的局部类型边界

`admin/request.rs` 在表单、计划提交／取消和固定查询入口同时构造 `Request { method, path, body, contract }`；捕获的私有契约区分普通检查、操作／计划查询、仓库对象与两种回执，不再从内部 URL 或请求 JSON 反推动作。`response.rs` 继续校验每份外部响应的真实形状与捕获身份：提交／取消接受原始 `OperationResult`，普通变更及操作查询接受当前 HTTP wire 回执；仓库保留完整关联与内容投影检查。计划查询接受全部合法状态，提交仍要求 ready 状态与已审阅摘要；不再构造旧计划预览。

存储写入准入、成功／失败结算共用同一契约。发出前仍要求有效会话并同步置 busy 串行化，写请求另需存储可写；完成时先核对原 `session_epoch`，旧成功或旧 401 不改写新会话。普通检查与计划查询不解除未知写入围栏；只有原操作的有效发布、降级发布或拒绝终态能通过查询解除。只读查询失败不建立变更围栏，普通变更的格式错误及未知失败保留原操作 ID。计划与检查结果仍以 JSON 展示，共享 `Plan.kind/input`、HTTP／持久化协议及资源生命周期不变。

成功响应返回 `ValidatedAdminResponse`：计划以私有 `ValidatedPlan` 保留解码后的 `Plan`，提交只读取其 ID、状态与摘要，不再从显示 JSON 提取。操作结果查询保留已核对的操作身份及 `OperationStatus`，计划提交保留 `OperationResult` 至结算；显示文本不承担后续准入证明。仓库在边界解码一次，保留身份校验与具体解码来源。纯请求／响应校验不依赖浏览器 API，`ResponseError` 到浏览器错误的映射留在 Web 入口；真实 HTTP 管理集成测试复用相同校验器，将返回的 `ValidatedPlan` 直接用于提交／取消，并保留原始响应断言。

管理模型保存类型化远程／输入错误，远程提示复用公共 feedback 展示 code、HTTP 状态、detail 和可用 request ID；原始 source 链留在模型中，不向 UI 展开内部来源。专用 typed 请求消费沿用现有 fetch/decode 的认证、取消、超时和会话语义，并为端点解码错误保留实际 HTTP 状态。服务端没有提供关联 ID 时不伪造。非法成功、超时及无终态证据继续保留原操作围栏和审阅计划，不自动重试；其他操作的合法结果也不能解除此围栏。

本变化仅收紧内部上下文与穷尽分派，消除 URL 再分类和请求字段再提取；不增加网络请求、锁或同步写入，不宣称性能提升。根 `test/web/unit/admin/` 从真实构造入口覆盖请求配对、回执／投影、计划关联和会话／围栏结算；实际执行结果须以对应验证提交为准，源码或格式检查不代替原生与浏览器验收。

## 文件操作观察的类型边界

文件页的 `FileOperation` 只保存原操作 ID 和已判定的 `SaveStatus`，不保存完整响应 JSON。每份网络回执在 `record_receipt` 入口核对原 ID，并使用既有共享 HTTP 回执校验器判定一次；缺失、矛盾、错误 ID 或旧包装均保留原操作的 Unknown、草稿及写入围栏。后续控件准入、轮询与原位编辑结算直接读取类型字段，不再重复解析已接纳的回执。完整保护证据仍在每份新回执的真实网络边界校验，不能用 HTTP 2xx 或本地状态标记替代。

本地明确拒绝与不确定传输结果直接构造类型化观察，不伪造 JSON 回执；保留原错误分类、错误反馈顺序及各动作的草稿处理。观察不授予权限，会话代际和当前会话门禁保持。原操作 ID 来自已接纳的本地写入或其轮询，内部不再重复检查生成值；响应 ID 缺失、为空或不匹配仍不能结算该操作。按 ID 替换和最近 100 条上限仅约束临时 UI 观察，不裁剪核心永久幂等收据。技术管理页仍展示原始 JSON；公开／持久化协议、`Commit.kind` 开放字符串、`Plan.input` 及计划查询、取消和恢复规则均未改变。

本变化消除同一入模回执的重复完整校验和无消费者载荷留存；操作列表仍按原 Vec 扫描，不增加缓存、锁或 I/O，也不构成吞吐实测。对应回归位于 `test/web/unit/files/actions/operation/`、`mutation/`、`model/`、`inline/` 及会话／轮询测试；测试源码存在不表示已执行，实际结果由验证提交记录。

## 文件历史窗口的类型边界

文件历史使用 [ADR0009](../adr/0009-bounded-file-history-windows.md) 的当前根窗口协议。`files/history/ingress.rs` 在网络边界解码共享 `storage_contract::history_window` DTO，并核对文件、仓库／路径、逻辑历史、集合、查询、精确 manifest 根、游标方向及页预算；入模后由私有投影供详情、版本树、原位编辑、分支、合并和标签消费者使用。目录分支仍由 `page::DirectoryBranch` 处理其独立契约，不混用文件分支身份。

主节点页和分支／合并辅助页采用替换式所有权；父关系、合并输入／父关系及正文来源共用一个关系页，提交说明、作者和记录时间共用一个字段片段。索引、布局和 DOM 只对应当前节点窗口，窗口外父关系明确标为未加载，不虚构正文节点，也不把页顶当成历史根。当前上下文摘要独立于主节点窗口；任意合法历史节点仍可通过 anchor 定位，备份页继续固定所存节点和正文。

每份分支响应继续核对 `current`、`selected_branch_id`、`state`、`read_only`、alias 和内容投影。空页、未选中分支及待写入的空来源均保留真实语义；分支依据只来自显式 `node_id`，缺失时不把正文 `version_id` 补成节点头。节点身份和正文身份分别保存。根变化后保留草稿，关闭旧依据的提交准入；全部所选节点及分支必须重新读取，并由用户明确接受新的依据。

跨页选择只保存动作所需身份、expected head 与有限标签，不保留被驱逐的候选页。最终合并／标签请求仍完整核对有效 `Config.max_entries` 和原有 1 MiB JSON 上限，不拆批或静默丢弃选择。字段按完整 UTF-8 字节范围提供替换片段；最后一片只表示到达字段末端，不能冒称整个字段已同时载入。

各读取资源最多一个在途 owner，替换或上下文变化时中止旧请求；会话、文件／别名／备份身份、根及请求代次共同拒绝迟到结果。当前会话 401 的撤权处理先于请求代次围栏。读取失败不会重新启用旧写入依据；旧完成不能释放新 owner。原授权和服务端提交检查保持，UI 投影不是授权凭据。

根 `test/web/unit/files/history/`、`actions/history_tests.rs` 及对应消费者回归覆盖准入和所有权；真实浏览器另验证窗口／observer 驱逐、跨页选择、显式重审、字段片段和迟到响应。合成窗口不证明真实引擎规模性能。当前实际运行结果见 [UI/G4 与浏览器验收记录](../validation/ui-g4-browser-acceptance-20261031.md)。

## 目录历史树的独立边界

目录详情使用 `storage_contract::directory_history` 的只读、当前根分页合同，不把目录树当文件版本。普通目录以 `entry_id`，仓库根目录以 `repository_id` 固定身份；更名不换历史身份，同路径删除重建不混入旧目录的节点。目录历史仅显示用户明确提交的 `DirectoryTree.tree_id`；沿 `parent_tree_id` 跨过内部暂存检查点，定位前一次用户提交，子目录组合引用不充当历史父边。分支的工作 head、最近已提交 head 和暂存状态分别提供；未写入的命名分支可以共享来源节点，不凭标签制造历史。

节点和命名分支各持有一页，默认64条、服务端最多128条；定位当前默认节点、分支head及页外父节点都使用服务端已有稳定ID和精确 history_root，不要求输入ID。无目录记录显示真实空态，读图不调用 `POST /directory-git/initialize` 或写入任何初始化记录。备份汇总目录没有独立目录身份，明确说明应在原始文件夹查看。只读文件夹照常显示树；创建、改名及默认选择仍遵守原写权限，尚未提供目录合并。

详情组件自身拥有取消和请求代次，另以会话、磁盘、稳定目录身份与路径围栏拒绝迟到读取。普通刷新不拆除旧图，不显示刷新加载文案；根冲突保留旧图供查看并关闭旧页定位，要求显式刷新。新根节点安装时清除旧根分支名称，避免跨根混显。目录图复用仅包含身份／父边的布局和实际DOM测量连接器，不复用文件正文或合并模型。冷页扫描、精确root和取消边界见服务端目录历史接口说明；有界页面不代表全历史CPU工作为常数。

## 真实文件容器

新版本正文是独立普通文件，位于：

```text
histories/<history-id>/file-containers/<file-id>/<当前文件名>/versions/
    v000001_20261018T133000Z_ab12cd34.txt
```

稳定外层 `file-id` 保持不变，内层目录随业务改名真实重命名。内部版本名记录文件内顺序、UTC 时间、内容散列短前缀和保存时的扩展名；改名不会重写旧版本文件名或不可变证明。版本说明、校验和及发布证明仍在独立的 `histories/<history-id>/versions/<version-id>/`。

当前名称、文件备注、版本备注与选中分支由已发布 State 持久恢复，`container.json` 是供离线浏览的可重建缓存，不代替证明。当前版本记录必须包含 `storage_name` 和 `created_at`，不保留缺失字段的旧格式读取或隐式全盘迁移。准备阶段与独立历史包使用的 `content/<creation_name>` 是当前中间布局，不是旧格式兼容入口。详细规则见[存储布局](../08-full-storage-and-disk-format.md#s08-02)。

轮廓使用 `data-zxs-contour-*` / `--zxs-contour-*`，主题和语言偏好键为 `zxs-theme` / `zxs-language`。产品逻辑与轮廓为 Rust；WASM 绑定和 WASM 加载前的通用失败处理由 Rust 构建工具生成，不维护自写业务 JS/TS。

本界面复用项目所有者提供的页面与组件源码中的公共页面、明暗令牌与连续轮廓；文件浏览源码提供图标、工具栏及标签片的可访问按压选择交互，当前目录排序已移到服务端分页前统一执行，标签操作在此改为节点级原子请求；主机管理源码提供格式化与状态展示，主机采样源码提供最小采样路径并在此独立定制。这些说明保留代码来源关系，不要求读者访问原作者的私有目录，也不是运行时或构建输入。第三方许可、版权和来源统一见 `compliance/`。

## 构建与验证边界

使用根工具链指定的 Rust、`wasm32-unknown-unknown` 标准库及与锁文件一致的 wasm-bindgen CLI。第三方 Rust 依赖与 CLI 源码来自本仓库，首次正式构建也离线执行：

```sh
ZXS_WEB_BINDGEN="$(bash .github/scripts/rust-build-tool.sh wasm-bindgen)"
export ZXS_WEB_BINDGEN
cargo run --locked --offline -p web-build -- build --product-root .
cargo run --locked --offline -p web-build -- check --product-root .
cargo test --locked --offline -p web-app -p web-interface -p view-macros
```

`ZXS_WEB_BINDGEN` 指定 CLI 路径，`ZXS_WEB_TARGET_DIR` 指定浏览器 target 目录。默认输出 `build/web`，包含 WASM、生成绑定与通用启动模块、CSS、字体、确定性 gzip 和 `build-manifest.json`。服务使用 `--web-dir /absolute/path/build/web` 提供资源；运行标记为 `data-zxs-runtime="web-interface"` 与 `data-zxs-ready="true"`，需验证 WASM MIME、gzip、ETag、nosniff 与 CSP。

构建成功不能替代真实浏览器、实际 Samba、物理盘故障或发行验收；开发目录模拟盘不构成物理冗余证据。浏览器验收应检查会话恢复、分支继承/首次写入、元数据冲突与未知结果、窄屏布局和公共样式。

文件列表浏览器回归使用两类证据：真实服务的文件行场景检查勾选焦点和查询重置，明确标注的 205 项合成分页响应检查真实 WASM／DOM 中的页替换、行数上限、快照重启、中止信号及迟到响应隔离。合成场景不证明引擎规模性能；原生测试或构建成功也不表示浏览器场景已经通过。实际浏览器不能启动时必须保留环境阻塞结论，等待具备权限的浏览器执行环境验证。

## 版本树观察注册与测量边界

版本树为每个挂载的 canvas 维护 DOM identity 注册表：根与初始版本节点只注册一次；childList 批次仅遍历新增／移除子树，新增版本节点在请求帧前立即注册，批次结束仍在同一根内的移动不重复 observe，真正离开该根的节点 unobserve。移除遍历不依赖节点仍保留原 class，跨根移动不能借 `isConnected` 保留旧根注册。owner 关闭时先关闭帧调度和注册表，再断开两个观察器。

连接线 SVG 的 `NodeRef` 是输出所有权依据；仅该真实 SVG 内的 childList 与该 SVG 自身增删不请求树测量，混有真实节点变更的批次仍处理。相同 class 的外来 SVG 不是输出。G4 装饰不在此排除范围内，控制器状态仍可能影响作者布局。

此优化只减少重复 resize 注册与连接线输出反馈，保留原测量函数、单 RAF 合帧和路径算法。每次有效树刷新仍读取 canvas 与全部版本节点并计算路径（O(N+E)）；不代表 G4 全量样式读取或树几何局部化已经解决。浏览器测试分别记录 selector 查询、树 RAF 内真实 `getBoundingClientRect` 与 RO observe/unobserve/活动目标；查询次数不再命名为测量次数。该测试须在真实 Chrome 中执行，编译与 JS 语法检查不构成运行通过。

## 活动历史与监测读取边界

活动历史仅接纳当前服务端 `backend_activity::ActivityHistoryResponse` 的对象信封及完整事件形状；浏览器私有 DTO 校验字符串序号、固定 200 条上限、展开详情和必需的 nullable 字段，拒绝裸数组、未知字段、缺失字段及错误类型。合法的空列表、`timestamp: null` 和 `principal: null` 保留业务含义。成功后只将类型化展示字段入模；非法响应保留旧快照和明确错误，不显示成功空记录状态。服务端协议和开放 action 字符串不变。

监测范围切换通过既有 `ReadCancellation` 中止上一历史读取，当前完成后释放句柄；仍先处理当前会话 401，再按范围和代次拒绝迟到结果，旧完成不能结算新请求。该取消只用于读取，不推断写请求回滚。历史请求频率和服务端范围协议不变；不宣称减少网络下载。根单元测试覆盖响应边界、旧快照和取消完成竞态，实际浏览器 signal 中止行为须单独验收。


监测历史在网络入口按当前 `HistoryResponse` 解码完整私有 DTO，必需字段缺失、类型错误、未知字段、错误范围或无效 UTC 时间均保留旧可见快照并显示错误；合法 null 传感器仍是空缺，不补零。UTC 时间由仓库内 `date-time` 的 parsing 能力一次解析，图表不依赖浏览器宽松日期解析。磁盘历史容量保留 bucket 平均值语义，不因最后一条观察离线丢弃有效平均值。

当前响应投影按 sample 共享已解析时间、CPU／内存指标和磁盘 ID 哈希索引，每条磁盘记录只投影一次；单张图不再线扫每个 sample 的磁盘数组。令 S 为样本数、N 为所有样本中的磁盘记录数、D 为当前展示磁盘数，预处理期望 O(S+N)，所有图表取点期望 O(S·D)，取代原来的 O(S·D²)；共享索引 O(S+N)，各图取点合计 O(S·D)。只保留当前响应，无跨范围累积缓存；原 HTTP 响应字节边界和服务端有界聚合保持。等值投影不分配新 Snapshot，范围切换和错误不改写取消／会话隔离。根测试使用独立旧投影对照空缺、离线平均、磁盘缺席和零值，并记录有限合成规模的结构数量与耗时；不把这些结果当作真实浏览器帧耗时或生产吞吐证据。

## 版本布局的已验证输入

历史窗口 ingress 在网络边界拒绝重复节点 ID 和重复父边，wire 投影一对一保留节点。版本树元数据只保留确定排序，不再次去重；布局按 ID 排序并在索引插入时断言唯一身份，内部错误不再以“稳定择一”静默隐藏。合法输入的层级与边顺序保持不变，SCC 循环处理语义未变。根测试覆盖重复内部身份显式失败及所有四节点有向图与原布局的差分；不据此声称浏览器性能提升。

`memo!`／`slice!` 的字段路径依赖本地 `parse_separated_nonempty` 的非空成功契约；空路径和末尾分隔符由解析器拒绝，剩余 token 仍由宏明确拒绝。根宏测试覆盖空输入、畸形路径、命名／元组字段路径和生成表达式，合法运行行为另由宏文档测试验证。

## 新名称的原位校验与 NFC 确认

非空名称以用户输入的原始字节校验、提交，不 trim、不自动规范化。仅纯空白名称沿用原位编辑的取消语义；批量改名的空白名称仍作为无效新名称拒绝。命名失败保留原值和 `name_policy::Error` 来源，页面显示具体原因、字符位置（非法字符时）与修改／取消提示。

新建目录、文件／目录分支创建与改名、批量改名／移动／复制提出的目标名称，遇到 `NotNormalized` 时在原位展示原名称及 NFC 候选。“确认使用 NFC 名称”才将该条输入换为候选并重新执行提交校验；Enter 重试本身不是确认。多项批量名称逐项确认，任一项未确认或目标路径无效时不发送整批写请求。纯名称确认不改变分支选择、路径映射或服务端命名策略。

确认不是永久有效的写入授权。原位编辑再次核对会话、目录／所选对象及历史依据，目录名称按当前完整目标路径预算复核；批量交互变化使候选失效，确认后重新按当前已读取分支身份及每项真实路径构造请求。输入修改、Esc、失焦到编辑器外或取消会丢弃未提交候选；确认／取消按钮之间的键盘焦点移动不会先销毁草稿。已发出写入仍由原 operation ID 和既有 Unknown 围栏持有，不改变保存／取消结算。

此改动不新增网络预检、后台任务、锁或同步写入；每次确认沿用原 O(名称长度) 校验与 O(选中映射×条目数) 批量请求构造。根 `test/web/unit/files/` 覆盖原字节、Unicode 空白、NFC/Hangul、取消、身份与路径预算改变；`test/tools/browser-smoke/runner/naming.rs` 捕获生产 WASM 请求，确认前不应出现 POST，确认后必须是精确候选。浏览器用例采用合成 409 回应以避免测试改动真实命名空间，源码存在不等于已执行通过。

## 故障提示与行内草稿所有权

文件／详情页存在活动行内编辑器时，管理状态变为不可读不会自动切换到健康页并销毁编辑 owner；原页面上方的管理摘要继续显示故障、状态检查和存储重试入口。无活动编辑器时保留原来的自动健康页导航。此门禁复用已有编辑器注册计数，同时保护未提交、Unknown 和已拒绝待修正的文本；不新增草稿副本、缓存或持久化格式。

Unknown 仍绑定原 operation ID 并继续查询，写入围栏不因健康恢复而解除；仅匹配的终态回执结算该草稿，Rejected 保留原文供显式修改／取消。会话失效及用户主动页面导航仍按原所有权规则取消本地编辑，不能将导航理解为取消服务端操作。根管理状态／行内 effect 测试与 browser-smoke 的备注恢复场景覆盖该边界；浏览器场景使用明确合成的丢失／不完整回执和健康故障，不证明真实存储故障恢复。

## 轮询展示与错误来源

监控图表将首次加载提示与已经加载的数据分开投影。数据未变化时，轮询的 loading 状态切换不会重建已有 SVG；首次加载、数据变化与范围切换仍正常更新。这只减少展示层的重复构造，不改变五秒轮询、历史／容量响应范围或授权新鲜度，不能据此宣称减少了网络下载。

容量加载错误在状态中保留完整的类型化 API 错误及来源链，界面再投影为用户可见反馈，不在状态接收时先抹去解码或请求来源。根 Web 回归覆盖等值加载翻转与错误来源；真实浏览器的范围查询场景另检查 SVG 节点身份，源码接线不等于浏览器验收通过。

## 文件管理的磁盘层级与观测状态

文件根目录继续消费真实 `/api/file-manager/disks` 的完整登记盘列表，保留服务端顺序、目录名称、稳定槽位和正整数层级，不再丢弃 `level`。一级标为主盘，二级及以上按返回层级标为备份盘；不补造未返回的上游盘，不从名称或槽位推算层级。只读目录模式与在线观测分列，离线备份盘仍保留行；可用容量为零与未知继续区分。非法层级、可写备份盘和“在线但身份观测失败”的矛盾响应在解析边界整体拒绝，保留具体解码来源。

“观测状态”区分普通离线、身份观测失败、在线但容量不可用，以及不可访问的容量观测失败；身份读取失败不宣称物理盘已离线。刷新中或失败后保留的旧行有非当前状态提示。按钮仍依照服务端返回的 `online` 控制打开，目录模式不是当前写入授权，原会话、存储状态、目录及服务端写入检查均不改变。

已有 Web 备份命名空间读取保持原样，列表行不拼接递归备份路径，也不引入新的发布证明或共享历史 provider。SMB 的根目录枚举、路径解析和已打开句柄校验仍分别限定一级盘。本次只改变 Web 标签和边界解析，不改 SMB、后端路由或权限。验证范围见[层级与状态显示记录](../validation/file-disk-levels-main-20261106.md)。

## SMB 账户设置

账户页区分 Web 密码与独立的 SMB 账号、密码。SMB 账号在服务端预置名单中真实选择，输入当前 Web 管理密码后保存持久绑定，并撤销旧代 ZXS SMB RPC 连接；不创建或重命名系统账户。有效账号可输入当前 SMB 密码、新密码及确认值进行真实改密。输入在提交时清空，不保存到浏览器状态或本地存储；刷新、重复点击、未保存账号选择、会话切换和未知结果均有隔离。账号保存结果未知须刷新读回绑定；刷新不会清除改密未知围栏，须先在客户端核实密码再解锁。改密成功提示更新客户端保存凭据，并说明已建立 SMB 连接不一定立即失效。完整边界见 [SMB 账户与密码](smb.md#smb-account-settings)。

没有账户时显示六行首次账户设置，提示仅为“请设置账户名和密码”，完成后切换到六行登录；两者不同时展示。首次建账无授权密钥，已有或损坏账户不能重建；未知结果仍禁止重复提交，必须通过状态检查或真实登录解决。目录发现仅限持久根（默认 `/zxs/data/disks`）内部，管理员可保存其他发现根；选择与激活同时绑定该根身份。

目录仓库面板新增“检查整理范围”，明确确认后才触发整个外层仓库的实体布局整理，不在浏览或初始化时自动执行。范围说明包括执行时独立 main 的未提交保存状态，成功区分不可用副本，错误保留未知结果提示并要求刷新后再检查。旧页面回包不覆盖新页面，旧会话不释放新会话的写入门禁；离开页面不撤销已准入后台任务。此入口不包含正文完整性巡检或真实设备断电验收。

逐级备份编辑器读取必需的 `effective_mode`：目录重开或重新读取时，经过验证的文件与目录策略保持为文件与目录模式；其他来源明确显示仓库默认、自定义、保留或未验证，不把前缀形状当模式依据。继承此策略的单文件仍只建立独立文件规则。有效模式不是已捕获证明，新空目录仍须显式保存；切换保存模式不修改只读有效模式，旧会话/旧草稿响应不能覆盖新选择。
