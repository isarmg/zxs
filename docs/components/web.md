# ZXS Web 界面

`src/web/` 是 Rust/WASM CSR 产品界面，`src/interface/` 将共享组件、浏览器生命周期和 CSR 基础原语直接合为同一包；`src/macros/` 提供过程宏编译目标。所有组件共用根工作区与锁文件，第三方基础实现位于 `src/foundation/`。来源与许可统一见 [compliance](../../compliance/README.md)。

浏览器通过同源 `/api/` 完成身份验证、文件与版本操作；SMB 是独立的 Samba 集成路径。构建与运行均不依赖兄弟项目目录。

## UTC 时间约定

界面直接显示服务端提供的 UTC 时间，不按浏览器语言、本地时区或用户位置换算。文件历史节点与操作记录统一使用 `YYYY-MM-DDTHH:mm:ssZ`，相同格式可直接排序；节点父子关系仍优先于时间。监测及健康检查的 UTC 字符串原样显示。监测图表仅为横轴坐标解析明确的 UTC 时间，不另设本地时间表示。持久化时间事实、会话有效期和单调时钟不因界面展示而改写。

## 页面与操作

默认进入文件页面，首先显示 P01、B01、C01 等独立硬盘目录。进入目录后使用面包屑、新建文件夹/重命名/删除工具栏、当前文件夹搜索和文件列表；详情在独立菜单页显示。菜单、工具栏和说明按与列表相同的紧凑文字留白排布。这里浏览的是服务管理的文件命名空间，不展示服务器系统路径。主盘按业务可写状态写入，备份盘只读查看实际持有的内容。

- **有界文件列表**：每页最多 200 项，前后翻页替换当前页，不无限追加条目。搜索和目录优先的名称排序由服务端在分页前全局执行，浏览器不逐页重排或仅搜索已加载条目。搜索输入合并 250ms 内的连续更改；查询或导航立即取消旧读取，并以会话、位置及请求代次拒绝迟到响应。全选只选择本页，翻页、搜索或目录导航清除本页选择；不默认为选中未加载条目。快照失效时提示并返回第一页，失败可显式重试。普通详情刷新通过精确路径和身份请求独立的 `selected_entry`，不能因条目不在本页就推断删除，也不能自动接纳同路径的新对象。原生表格及公共 G4 布局保持不变。投影、生命周期及验证边界见[文件列表分页快照](../architecture/file-list-projections.md)。
- **文件与分支**：文件详情以真实父节点关系展示历史树，箭头从父节点指向子节点；没有来源记录的版本独立显示，不按时间虚构连线。每个节点只含日期、备注、操作三行，可写视图的操作为“编辑备注／编辑标签／创建分支”，只读副本仅显示只读标记；当前标识与日期同行。分叉、多父关系与跨层连线完整保留；连线为等粗实线，水平／垂直正交布线，转弯为圆角，并按实际节点尺寸绕行；手机仅在树内部横向滚动。创建分支只登记父节点引用，不创建占位文件或复制来源正文，也不增加内容版本，创建后不自动切换。待写入分支在下拉框标出；切换后继承并显示父版本，可查看元数据，也可从当前可见父版本再登记分支。历史树包含真实正文节点与复用正文的路径节点：文件或文件夹改名时新增路径节点，正文版本不增加；后续写入以路径节点为父节点。分支登记本身不增加历史节点，可见的继承正文仍标为“继承的父版本”，不会将父版本改归新分支。首次成功写入后才产生该分支自己的内容版本，零字节写入同样是实际版本。切换保留当前路径，不改变其它文件或目录。文件尚无独立分支时显示主版本。首次写入自动生成的公共文件分支也可通过当前选择器旁的“重命名文件分支”原位改名，使用同样的 128 UTF-8 字节下划线输入，只改标签，不新建文件内容或目录子树。
- **目录分支组合**：目录分支记录目录及子目录中各个共享文件分支的组合，不创建目录私有的文件分支，也不复制正文；切换时恢复已记录组合，不改变目录外文件。修改文件或切换目录内的文件组合，只在当前命名分支下追加不可变子树节点；命名分支 ID 保持稳定，仅显式创建操作增加命名分支。未写入的文件继续显示各自父版本，已写入的文件显示各自的本分支版本，两者可以同时出现在同一目录列表。目录选择器使用真实目录分支记录，不按同名文件分支交集推算。根目录的“当前主分支（SMB 默认）”选择器同时设置 SMB 默认组合，稳定的命名空间不会因此更换。没有目录记录时只显示主版本，不虚构可选 ID；空目录也可登记组合。当前目录分支可通过“重命名分支”原位修改名称，128 字节限制、Enter 保存、空值／Esc／失焦取消，不使用弹窗。
- **批量文件操作**：文件列表支持勾选多个文件或文件夹，然后在页面内移动、复制、删除或逐项改名。源目录分支逐项勾选，移动与复制逐条指定“源分支 → 目标分支”，不推断所有两两组合；可添加映射以接收多个目标分支。目标目录读取和审阅不切换 SMB 默认入口。所有条目携带稳定身份及捕获的依据子树，同一批原子发布；某个选中分支缺少条目、名称无效或服务端冲突时保留输入，整批不会静默跳过。尚无目录分支记录的范围提供显式登记按钮，普通读取不写元数据。未选分支、历史版本及真实移动后的旧逻辑引用由核心保持。
- **文件分支合并**：在页面内选择两个以上可写文件分支，捕获各自当前节点；结果可采用本文件任一历史节点，并且必须明确选择保留的参与分支。复用参与分支头时不增加节点，其他结果新增复用正文与标签的合并节点。被消耗名称保留为不可写别名；完整来源另外列出，树不为展示来源制造环或虚构正文。目录分支合并待确认，暂不提供操作。
- **节点标签**：每个历史节点展示自己的标签。可勾选多个节点，选择关联的可写分支后批量添加或移除标签；标签片及输入均在页面内，最多16个标签、每个128个UTF-8字节。修改新增继承正文的元数据子节点，原节点不变；编辑历史节点只推进仍指向它的引用，不回退较新正文。没有标签变化时不请求写入。
- **备份设置**：文件、文件夹及当前目录都可读取保护策略；唯一管理员可在会话有效且存储可写时编辑，不再返回 `can_manage` 权限投影；备份盘、只读别名和其他业务限制仍有效。总份数包含主盘，每个目标盘各有相对逻辑前缀，前缀最多768个UTF-8字节。同一范围包含多条历史主盘路径时，读取完整 `backup_routes`，按所选份数收集每条链所需备份槽，份数上限取最短链；只接受当前 `backup_routes`、明确的 `max_copies` 和对象形状 `backup_paths`，缺失或旧格式失败关闭，不从旧路线字段或数组别名推断。保存始终包含读取时的范围稳定身份与自身策略代数；继承上级规则时自身代数为0。单文件追加配置时绑定的文件名，目录追加相对所选目录的路径；主盘改名或移动不自动改变绑定的备份位置。备份盘文件页显示这些逻辑前缀，`path` 仅用于备份浏览，显式 `repository_path` 仅用于读取真实主目录上下文；主目录引用已删除时不构造假路径，直接按稳定文件历史读取。备份详情固定其实际存储的节点及正文版本，隐藏修改控件，历史返回的较新主盘节点不覆盖当前副本。冲突保留输入，结果未知时查询原操作。
- **元数据保存**：新建文件夹、改名、删除、分支、合并、标签、备注与备份配置通过服务端事务发布。文件页与技术管理页共用当前 HTTP 回执校验，只有原操作 ID 匹配、字段完整且发布证据一致的直接回执才能确认结果；不接受旧 `operation` 包裹或仅有 `state` 的成功对象。冲突保留草稿；空值、缺字段、矛盾回执及其它未知结果保留草稿、原操作 ID 和写入围栏，继续查询原操作，不把 HTTP 2xx 或网络失败显示为保存成功。
- **备注**：文件备注、正文版本备注与路径节点备注分别保存，每项最多 128 UTF-8 字节，禁止换行与控制字符。历史节点第三行点击编辑备注后，第二行原位切换为下划线输入；Enter 保存、空值清除、输入法组合期间不提交，Esc 或失焦取消。新建目录、改名和分支采用同一原位交互；文件与目录名称统一遵循当前 `PortableName`／`PortablePath` 规则，不套用备注的 128 字节限制，完整目标路径仍须符合长度与深度预算。分支名称保持 128 UTF-8 字节限制。已验证备注完整显示，不静默截断；展示层不承诺旧格式备注可被引擎读取。删除在页面内审阅条目及分支后提交。路径节点空备注显示“改名 旧路径 → 新路径”；从路径节点创建分支保留正文版本与来源节点引用。
- **状态**：管理员查看真实 CPU 使用率、CPU 功耗、内存、各盘容量与功耗，每 5 秒刷新。带图标的卡片顶部是实时值，下方是真实历史折线；范围为 1min/30min/1h/24h/1month，最后一项代表最近 30 天。所有卡片为 3:2，桌面固定四列，末行仍保持单列宽度，手机每行一张。后台每 5 秒独立采样，分钟历史缓存保留 31 天，重启恢复。缺失采样断线，缺失传感器显示不可用；功耗不根据使用率或 TDP 推算。目录模拟盘容量可能相同且没有独立功耗，不能作为独立物理盘相加。数据来源和缓存边界见[监测实现](server/src/telemetry.md)。
- **历史记录**：展示最近已提交的文件活动记录及时间、路径和主体，可以按硬盘筛选；这是近期活动概览，不是完整的逐路径取证审计。删除记录来自已提交的命名空间事实，逐次记录删除时的逻辑路径和时间；删除单个别名、删除后复用路径及同次操作重复删除同一路径均保留独立记录，普通改名与仅大小写改名不记为删除。删除活动不绑定正文身份，也不延长正文保留。文件自身的版本、分支和备注在文件详情中查看。文件操作历史与状态页的监测历史分别保存。
- **账户与显示**：登录、退出、HttpOnly Cookie 会话恢复、CSRF、自助改密、错误反馈、主题及中英文切换。系统只有一个管理员，用户名在初始化时自选，之后只读；没有其他账户、角色、禁用或仓库 ACL 表单。改密成功后全部会话撤销，必须重新登录。公共及业务文案统一调用语言接口，切换语言通过 `lang` 参数重新加载并恢复会话。

Web 不提供文件上传、下载、正文预览、“写入当前分支”或传输任务页面；文件浏览、元数据编辑、版本树、账户、状态和历史保留。文件正文通过 SMB 或受控 HTTP API 读写，这些协议及接口保持不变。项目不提供原生 App、WebView 宿主或 App 安装包。主页面不展示整树合并、清除或拆分等技术管理表单；含独立文件分支时，未适配的旧整树高级操作由核心明确拒绝，不隐式改变文件分支语义。

## 真实文件容器

新版本正文是独立普通文件，位于：

```text
histories/<history-id>/file-containers/<file-id>/<当前文件名>/versions/
    v000001_20261018T133000Z_ab12cd34.txt
```

稳定外层 `file-id` 保持不变，内层目录随业务改名真实重命名。内部版本名记录文件内顺序、UTC 时间、内容散列短前缀和保存时的扩展名；改名不会重写旧版本文件名或不可变证明。版本说明、校验和及发布证明仍在独立的 `histories/<history-id>/versions/<version-id>/`。

当前名称、文件备注、版本备注与选中分支由已发布 State 持久恢复，`container.json` 是供离线浏览的可重建缓存，不代替证明。当前版本记录必须包含 `storage_name` 和 `created_at`，不保留缺失字段的旧格式读取或隐式全盘迁移。准备阶段与独立历史包使用的 `content/<creation_name>` 是当前中间布局，不是旧格式兼容入口。详细规则见[存储布局](../08-full-storage-and-disk-format.md#s08-02)。

公共组件只通过 Signal/Callback 接收状态与动作，不导入存储业务或旧管理员接口。自定义 `Select` 实际使用原选择器触发器、箭头和顶层弹层样式，Rust 实现方向键、输入跳转、Enter/空格、Escape/Tab、焦点、禁用项及外点关闭，不再依赖原生菜单外观。登录标签、输入和按钮统一字号与字重，窄屏和大字时由内容撑高。

新增页面先组合共享布局角色，不增加页面级尺寸覆盖：`.zxs-stack` 和 `.zxs-flow` 排列内容，默认不另加外部间距；`.zxs-row` 管理字盒留白，`.zxs-frame` 管理灰色边框与 G4 表面。透明包装仅在其边界紧贴可见框时使用 `.zxs-surface-start/end` 或 `.zxs-surface`，由公共规则分开直接接触的框；中间已有标签或说明行时不重复加距。普通输入保持 44px；搜索、账户和下拉框显式采用 `.zxs-input--compact`，原位输入再组合 `.zxs-input--underline`。登录规则只在 `.authentication-shell` 内生效。完整用法见[公共样式](web/public/styles.md)。

请求路径与备注校验复用 `storage-contract`：浏览器使用严格的同源 `/api/` 路径边界，备注使用同一 128 字节单行规则。目录读取和历史读取保留请求代次隔离；元数据反馈、改密反馈也必须属于原有有效会话，登出或重新登录后的旧响应不能改写新会话。

退出登录开始后即停止接纳新的元数据写入；页面控件与动作入口共用会话及写入准入检查，包含批量操作、合并、标签和备份提交。退出请求失败时保留撤销所需凭据供显式重试，不把失败当作已退出，也不因此恢复新业务操作。恢复会话期间同样不接纳这些操作；已开始的服务端事务仍须按原操作 ID 核对，停止 UI 后续处理不代表服务器回滚。

轮廓使用 `data-zxs-contour-*` / `--zxs-contour-*`，主题和语言偏好键为 `zxs-theme` / `zxs-language`。产品逻辑与轮廓为 Rust；WASM 绑定和 WASM 加载前的通用失败处理由 Rust 构建工具生成，不维护自写业务 JS/TS。

本界面复用项目所有者提供的页面与组件源码中的公共页面、明暗令牌与连续轮廓；文件浏览源码提供图标、工具栏及标签片的可访问按压选择交互，当前目录排序已移到服务端分页前统一执行，标签操作在此改为节点级原子请求；主机管理源码提供格式化与状态展示，主机采样源码提供最小采样路径并在此独立定制。这些说明保留代码来源关系，不要求读者访问原作者的私有目录，也不是运行时或构建输入。第三方许可、版权和来源统一见 `compliance/`。

## 构建与验证边界

使用根工具链指定的 Rust、`wasm32-unknown-unknown` 标准库及与锁文件一致的 wasm-bindgen CLI。第三方 Rust 依赖与 CLI 源码来自本仓库，首次正式构建也离线执行：

```sh
ZXS_WEB_BINDGEN="$(bash .github/scripts/rust-build-tool.sh wasm-bindgen)"
export ZXS_WEB_BINDGEN
cargo run --locked --offline -p web-build -- build --product-root .
cargo run --locked --offline -p web-build -- check --product-root .
cargo test --locked --offline -p web-app -p web-interface -p view-macros
```

`ZXS_WEB_BINDGEN` 指定 CLI 路径，`ZXS_WEB_TARGET_DIR` 指定浏览器 target 目录。默认输出 `build/web`，包含 WASM、生成绑定与通用启动模块、CSS、字体、确定性 gzip 和 `build-manifest.json`。服务使用 `--web-dir /absolute/path/build/web` 提供资源；运行标记为 `data-zxs-runtime="web-interface"` 与 `data-zxs-ready="true"`，需验证 WASM MIME、gzip、ETag、nosniff 与 CSP。

构建成功不能替代真实浏览器、实际 Samba、物理盘故障或发行验收；开发目录模拟盘不构成物理冗余证据。浏览器验收应检查会话恢复、分支继承/首次写入、元数据冲突与未知结果、窄屏布局和公共样式。

文件列表浏览器回归使用两类证据：真实服务的文件行场景检查勾选焦点和查询重置，明确标注的 205 项合成分页响应检查真实 WASM／DOM 中的页替换、行数上限、快照重启、中止信号及迟到响应隔离。合成场景不证明引擎规模性能；原生测试或构建成功也不表示浏览器场景已经通过。实际浏览器不能启动时必须保留环境阻塞结论，等待具备权限的浏览器执行环境验证。
