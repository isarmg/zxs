# 磁盘向导的普通目录转换

`directory_conversion` 是 `storage-engine` 的集成能力，不是独立程序。发现目录不调用转换，也不依据目录名称、磁盘角色或一份 `disk.json` 自动接纳外来盘。

## 转换范围

普通目录转换保留可表示的相对名称、完整文件字节和空目录。权限、所有者、时间戳、ACL、扩展属性、硬链接关系不在该范围内。向导必须先展示源、独立目标、文件/目录数量和空间估算，明确确认这个范围，再执行。源目录和目标不能重叠，也不能与当前系统根或数据盘根重叠。

普通来源只能转换为启用的一级磁盘，且没有上游。新盘转换先由管理层按已确认的接纳计划初始化另一个空目标，再将相同源清单绑定到这个新盘，直接导入空的盘根命名空间。不在原普通目录内写 ZXS 元数据，不清空或覆盖源。将内容复制到已有一级盘的新子目录是另一个导入用途，不能称为已将源盘转换成新磁盘。

ZXS 数据、损坏或部分缺失的 ZXS 证据不能进入普通目录转换；同一分类检查覆盖选中根与所有嵌套目录，并在提交前清单复验时再次执行。普通 `.git/objects`、没有 ZXS 保留组合的 metadata/histories 目录及明确普通 JSON 文档不被单凭名称拒绝。完整历史、版本与分支迁移需要独立的已验证来源闭包和正式接纳协议，不能用当前视图复制代替。当前模块没有实现跨系统历史迁移、二级/三级角色转换或原地改写旧身份。

## 只读计划与确认

- `PreparedOrdinaryDirectory::inspect(File, &Path)` 不需要已激活的 `Engine`，持有经过检查的目录描述符和清单。独立预览限制为最多 100,000 项、1 TiB 总量和 1 TiB 单文件；绑定后仍执行当前主机真实额度。
- `prepare_new_disk_import(self, &Engine, slot)` 要求目标是当前登记且启用、没有上游的一级盘，盘根命名空间不存在或为空。管理层另外核验这个槽位和物理身份正是同一工作流刚接纳的新盘；引擎 API 本身不授予接纳权限。
- `Engine::prepare_disk_directory_import` 在已有一级盘的不存在子树下导入。`prepare_directory_import` 只接受对应盘根的主命名空间，不接受任意私有分支。
- `DirectoryConversionDigest` 是独立的审阅承诺类型。它绑定来源清单、目标、登记身份、当前状态序列和分支基线，不能当正文摘要或接纳证明。
- `DirectoryConversionConfirmation::contents_only` 只能由已鉴权调用方在用户确认后构造。管理层需要把源审阅与新目标接纳计划绑定到相同主体和确认流程；计划不是授权。

`content_bytes` 是文件正文总量。导入的 `temporary_bytes` 是额外的完整工作区正文量，二者不含元数据、已有占用、配置的其他副本和运行期变化，不能当可用空间证明。提交继续使用原有容量、发布及备份规则；不足空间时保留源和已接受的暂存证据，不删数据来腾空间。

源以只读方式逐项检查。目录描述符限制遍历在同一挂载，拒绝软链接、硬链接、特殊文件、非法 UTF-8、名称规范化冲突和不可表示路径。来源名称重新打开后必须仍指向同一根。每个文件在复制前后比较设备/inode、大小、mtime、ctime、模式；发布前重新扫描整个清单。预览不会冻结外部文件系统，操作期间应停止源写入；检测到变化即失败，不声称提供并发写入下的文件系统快照。

有歧义的 `disk.json`、身份字段、保留元数据目录及 `histories/history_*` 布局均失败关闭。普通的非身份 JSON 文档可以保留为普通文件；无法确定属于普通数据时不做降级推断。

## 发布、进度和恢复

一次导入使用一个原生工作区，所有文件按既有上传路径完整写入，再调用一次 `commit_workspace`。文件版本和当前目录组合遵循原生保存语义；本模块不额外自动创建显式目录历史提交。

`execute_with_progress` 接受持久进度回调，并依次通知原操作 ID、即将创建盘根使用的操作 ID、工作区持久化前分配的稳定 ID、已创建但尚未暂存内容的同一工作区 ID，以及发布前的完整 `CommitRequest`。回调失败立即停止。`DirectoryImportFailure` 同样暴露这些结构化引用和原始原因，不要求解析错误文本。

管理层应在返回回调前持久化这些引用，先记执行意图，再开始写入。重启时用保留的完整请求调用 `Engine::native_workspace_commit_completed` 验证原生收据，不能只看到同名操作就宣称完成。不确定、未完成或缺少证据的工作流必须停在恢复状态，不能分配新操作/工作区盲重交。工作区 ID 在命名空间准入记录及工作区持久化前先写入意图，消除创建成功但没有恢复 ID 的窗口。预记成功不代表创建完成，重启找不到该工作区时仍须核对流程状态，不能自动换 ID 重试；当前模块没有自动续传或自动回滚。

独立根创建可能已经成功，而内容尚未发布。该状态是可见的部分完成，不是整体成功，也不会自动删除新盘或工作区。任何后续清理应走相应受授权的原生恢复入口。

## 明确停止并保留材料

`DirectoryImportStopRequest` 只从已鉴权工作流的持久记录构造，绑定原目标登记、导入/盘根/工作区身份、完整原生请求（若已产生），以及事先持久化的独立停止操作 ID。停止不取消尚未完成的磁盘接纳共识。

`stop_directory_import` 先要求无未决写入和活动准备所有者。原导入已精确发布时返回 `Published`，不把成功改成取消；否则验证目标身份、盘根创建收据和工作区归属，仅调用原生 `abort_workspace` 关闭已存在的工作区，保留全部暂存字节。只有预记身份而不存在的工作区绝不重建。关闭成功后，再通过原生发布写入 `directory.import.stop` 永久收据；两步之间中断时使用同一停止请求继续，不重新分配身份，也不再次递增已关闭工作区的围栏。

`directory_import_stop_result` 只核对永久发布、请求摘要和主体，允许目标后来合法退出后仍查询原收据。后台只有取得精确 `Stopped` 收据才能结束恢复状态并允许新的独立转换；单独的本地状态缓存不是证明。界面应明确说明保留已接纳盘、盘根和暂存数据，不等于转换成功，不会删除源。已停止的导入操作 ID 不能用于重新导入，也不能通过直接原生工作区提交或其他业务操作复用。围栏位于公共新操作准备入口；当前实现扫描已发布停止收据，每次新业务操作增加 O(M) 检查，M 为保留操作数，没有引入未经恢复校验的缓存。

## 当前视图导出

`Engine::prepare_directory_export` 可显式选择当前命名空间或一个已验证提交的视图。它不是全历史导出。所有源版本通过现有内容证明读取；预检完成前不创建输出。目标父目录必须是当前用户持有的私有目录，最终目标名必须不存在。

执行时在目标父目录的独占暂存子目录内复制，按预期长度和正文哈希验证，并沿用原生持久化写入。最终以 `RENAME_NOREPLACE` 发布，不覆盖竞争出现的名称。失败保留暂存目录，错误指出恢复位置；若重命名后的父目录同步失败，明确报告持久性未知，不能直接重试。导出不写源系统或盘内证明。

## 成本与验证

N 项清单使用 O(N) 内存，规范化键集合维护成本 O(N log N)。预览和绑定/执行复验均扫描有界清单；正文完整复制为 O(B) 字节，导出预检还会完整验证源副本。导入保留原生逐文件暂存和工作区发布的 fsync 屏障，导出保留文件/目录同步和最终父目录同步，没有合并或减少持久化屏障。

回归位于 `test/engine/unit/directory_conversion/tests.rs`，覆盖空源、Unicode/空目录/二进制往返、来源与目标变化、非覆盖、一级限制、损坏ZXS拒绝、非法名称与文件类型、进度持久化失败、精确原生收据绑定。执行：

    cargo test --locked --offline -p storage-engine --lib directory_conversion::tests -- --test-threads=1

这些测试仅使用临时构造数据，不转换真实用户数据。跨挂载与进程杀死/真实断电场景需要专门环境验证；普通单元测试不代表完成这些验证。
